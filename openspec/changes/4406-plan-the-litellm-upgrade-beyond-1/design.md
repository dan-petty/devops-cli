# Design

## Decisions

- **Put the upgrade plan in `k8s/llm/gateway/UPGRADE.md`.**: It sits beside `k8s/llm/gateway/config.yaml` and `k8s/llm/gateway/deployment.yaml`, the two files that the bump changes, and one pull request adds it.
- **Name the newest stable release that loads the config as the target.**: It carries the most fixes, and the config load and the smoke steps decide whether the bump can land; no minimum release age applies, per the owner direction of 2026-11-11.
- **Load the config with `Router` of the target wheel in a new empty directory with `python -I`.**: It runs the real `model_list` and `router_settings` against the target version with no cluster, and it leaves the checkout clean.
- **Take v1.103.11 as the running version and the rollback target.**: `k8s/llm/gateway/deployment.yaml:46:image: ghcr.io/berriai/litellm:v1.103.11` is the staged pin, and the v1.103.10 of the issue body is one patch behind the tree.
- **State the update policy in the page: the release-age rule, the pin form of the image, and whether the target meets the rule.**: `CONTRIBUTING.md:35:A dependency, an image, a chart or a tool has no minimum release age.` gives the rule, and the acceptance criterion of the issue asks for the policy, the pin and the verdict on the target.
- **State the pin of the gateway image as a tag with no digest, and name the Renovate rule that writes it.**: `k8s/llm/gateway/deployment.yaml:46:image: ghcr.io/berriai/litellm:v1.103.11` holds a tag and no `@sha256` digest, and the rule at `.github/renovate.json:244: "matchPackageNames": ["ghcr.io/berriai/litellm"],` sets no `pinDigests`, so the plan states the form that the tree holds instead of a digest that no file pins.
- **State 12 model groups and 7 fallback rules, as the staged config holds them.**: `k8s/llm/gateway/config.yaml:338:id that /v1/models returns, after the 12 model groups, and a caller does not name it (#5302).` gives the 12 groups, and the `fallbacks:` block at `k8s/llm/gateway/config.yaml:375: fallbacks:` holds 7 rules, so the page corrects the 6 of the issue body instead of copying it.
- **State the `litellm-proxy-extras` migrations of the range in their own section.**: `prisma migrate deploy` runs before port 4000, so a migration of that package decides whether the new pod starts; the earlier bump recorded such a change at `openspec/changes/archive/2026-11-10-4370-bump-the-litellm-gateway-to-v1/proposal.md:40:- Database: `litellm-proxy-extras` goes from 0.4.100 to 0.4.100.post1. It adds no migration.`
- **Link the documented smoke calls of `k8s/README.md` and add only the call for `deepseek-v4.1-flash`.**: `k8s/README.md:186:#### Smoke check after a gateway upgrade` already holds four group calls, the structured call and the key table, so a copy in the page would drift from the section, and the undated DeepSeek group is the one group that the section lacks.
- **Link the page from the LLM Gateway section of `k8s/README.md`.**: `tests/invariants/test_agents_md.py:446:def test_every_hand_written_and_generated_document_is_within_two_links_of_agents_md() -> None:` requires a route from the agent router, and `AGENTS.md:39:| change a manifest, the cluster or OpenTofu | [k8s](k8s/README.md), [cluster](docs/CLUSTER.md), [tf](tf/README.md) |` puts `k8s/README.md` one link away.
- **Record the risk list from the features that the repository's own config uses, each with its check.**: Each entry names a place in the gateway config and the test or live step that proves it, so the bump verifies what this project relies on instead of the whole changelog.
- **Keep the change to documents only and edit no manifest.**: The bump is a separate item, and a plan changes no behavior that a consumer observes, so it carries no spec delta and no group changes `k8s/llm/gateway/config.yaml` or `k8s/llm/gateway/deployment.yaml`.

## Rejected alternatives

- **Put the plan in `docs/litellm-upgrade.md`.**: The probe says that `docs/litellm-upgrade.md` is no file of the staging commit, and the page would sit away from the manifests that the bump changes.
- **Keep the plan in the issue body only.**: A pull request delivers a file of the repository, and a comment on an issue delivers no change.
- **Name the next minor only.**: It leaves four minors of fixes behind, and the gateway config relies on the cost map and the router settings that the later releases change.
- **Add a test module in CI that loads the config with `Router`.**: CI must test the version that the cluster runs, which is `k8s/llm/gateway/deployment.yaml:46:image: ghcr.io/berriai/litellm:v1.103.11`, and no test asserts a plan document.
- **Wait for a release age of two weeks before the bump.**: `CONTRIBUTING.md:35:A dependency, an image, a chart or a tool has no minimum release age.` states the owner rule of 2026-11-11 that replaced it.
- **Repeat the four documented smoke calls and the key table in the plan page.**: `k8s/README.md:186:#### Smoke check after a gateway upgrade` holds them, so the plan links the section and adds only the missing call.
- **Pin the gateway image by digest in this change.**: `k8s/llm/gateway/deployment.yaml:46:image: ghcr.io/berriai/litellm:v1.103.11` holds a tag and no `@sha256` digest, and `.github/renovate.json` sets no `pinDigests` for the package, so the page states the tag pin that the tree holds and the bump stays a separate item.
- **Roll back to v1.103.10.**: `k8s/llm/gateway/deployment.yaml:46:image: ghcr.io/berriai/litellm:v1.103.11` is the running tag, so v1.103.10 is no rollback of the staged tree.
- **Change the gateway config or the deployment image in this pull request.**: The issue says that the bump itself is a separate fix issue, and `k8s/llm/gateway/config.yaml` and `k8s/llm/gateway/deployment.yaml` are manifests of the cluster, so this plan only writes the page that the bump follows.

## Security

The page crosses no trust boundary: it holds public image tags, repository paths, environment variable names, the placeholders `<node>:<node-port>` and commands, and no key value, private address or internal host name. A person confirms before the merge that each smoke step sends only the gateway key and names only the provider key variable, that the update policy states the tag pin that `k8s/llm/gateway/deployment.yaml` holds and claims no digest, and that the page holds no secret. `uv run devops scan secrets k8s/llm/gateway/UPGRADE.md` fails when a key value lands in the page, and `uv run devops ci test tests/invariants/test_agents_md.py` fails when the page is not routed from the agent router.
