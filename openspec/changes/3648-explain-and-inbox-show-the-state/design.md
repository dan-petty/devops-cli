# Design

## Decisions

- **Record the action left in `implement.left_action` in the marks of `stop`.**: Only the stop knows the action left, because `left_action` returns `wait` once the job has taken the default action of the class, and `stop` computes that value already at line 1981.
- **Count the attempts of the stopped step from the `attempt` events of `implement.trace` whose step equals the recorded `implement.stopped`.**: The trace labels each event with the step that runs, `recorded_rows` of `src/devops_cli/roadmap/follow.py` groups them by that step, and the events of the last step survive the bound, so the record needs no second count key.
- **Print the class text that `implement.failure` holds, as it stands, and look up no table.**: The sample value `not_ticked` is no member of the failure classes, so a lookup would stop the report of an item that the job must still explain.
- **Treat a stop with no `implement.failure` and no `implement.left_action` as a stop whose record holds neither, and print that.**: A stop from an earlier runner image holds neither key, and naming a class or an action that the record does not hold would misstate the item.
- **Count no attempt when `implement.trace` cannot be decoded, and print the class and the action left anyway.**: `_trace_of` of `src/devops_cli/roadmap/explain.py` raises on a corrupt trace, and a corrupt trace of one item must not stop the report or the whole inbox.
- **Put the class and the attempt count in `subject` and the action left in `clear` of `InboxLine`.**: `src/devops_cli/roadmap/inbox.py:512:def _render_line(line: InboxLine) -> str:` prints the two fields, so the line keeps its shape and the tests of the line shape stay as they are.
- **Read the state of a stop in one new module, `src/devops_cli/roadmap/stop_state.py`.**: `src/devops_cli/roadmap/follow.py:def follow_command` is the same shape for the same two callers, so the class, the attempts and the action left are read once for the report and the inbox.
- **Clear `implement.left_action` on the retry path and on each clear rule of the Service.**: Those two paths remove `implement.stopped` and `implement.failure`, so a value that names a stop that is gone cannot stay behind.
- **Print the state of a stop in the default report of `render_explanation`, not behind `--trace`.**: The trace holds a bound and drops its oldest events, and the default report is what a person reads for a stopped item.
- **Fill the stop state on the open path of `explain_item` only, and leave its early return for a closed item as it is.**: A closed item is no longer stopped, and its report keeps the refusal it prints today, so the new section adds no line to an item that the jobs no longer take.
- **Prove the request count of the inbox at the `gh` process edge over `GitHubFake`, with a blocked item that holds a stop against a second one-item repository whose item has no stop.**: `tests/support/fakes/roadmap_store.py:646:def comments_on(self, number: int) -> list[IssueComment]:` returns the comments and `tests/support/fakes/roadmap_store.py:898:def _read(self, issue: IssueRecord) -> IssueRecord:` appends nothing to `reads`, so a case over that store cannot fail for a read of a stop; `tests/support/fakes/github_repository.py:287:self.calls.append(args)` records every request at the `gh` edge, and `src/devops_cli/roadmap/stores/github_store.py:780:found = self._read_or_none(issue_args(self._repo, number), _ISSUE, f"issue #{number}")` shows that a read of one item is one request there, so the control item makes the same reads and any read of the stop adds a request that fails the case.

## Rejected alternatives

- **Read the default action of the failure class at read time instead of recording it.**: `src/devops_cli/roadmap/failure.py:363:return FailureAction.WAIT if taken is default else default` shows that the default names an action the job took, not the action left.
- **Read the action left from the `attempt` event of the trace.**: `render_trace` of `src/devops_cli/roadmap/explain.py` prints the events of the trace within its bound, so an old stop would show no attempt event and no action.
- **Add a field for the class and the action to `InboxLine`.**: `src/devops_cli/roadmap/inbox.py:512:def _render_line(line: InboxLine) -> str:` prints `subject` and `clear`, and each test that holds the shape of a line would change for no new information.
- **Show the state of a stop only under `explain --trace`.**: The issue states that the trace holds a limit and is no summary, and the default report of `src/devops_cli/roadmap/explain.py:def render_explanation` is what a person reads.
- **Name `ci_infra` for a stop whose record holds no class.**: `classify_failure` of `src/devops_cli/roadmap/failure.py` gives `ci_infra` to a failure that it reads, and a stop with no recorded class was never classified, so the line says that the record holds no class.
- **Prove that the inbox makes no new request with the static plan of `inbox_requests`.**: `tests/roadmap/test_roadmap_inbox_requests.py:50:reads, writes = inbox_requests(REPO)` builds the same plan from `src/devops_cli/roadmap/request_plan.py` whatever the inbox code does, so the case passes for a line that reads the item and cannot fail.
- **Prove the request count over the in-memory store of `tests/support/fakes/roadmap_store.py`, by comparing its `reads`.**: `tests/support/fakes/roadmap_store.py:646:def comments_on(self, number: int) -> list[IssueComment]:` appends nothing to `reads` and `tests/support/fakes/roadmap_store.py:898:def _read(self, issue: IssueRecord) -> IssueRecord:` records no read, so the comparison cannot fail for a read of a comment or a second listing.
- **Compare two runs that both hold a stopped item, as the first shape of the request case did.**: Both runs hold `implement.stopped`, so a read that the new line sends for a stop is sent in both and the two request lists stay equal; only an item with no stop tells a stop read apart.
