# Design

## Decisions

- **Reuse the publisher at `src/devops_cli/github/pr_evidence.py:96:def publish_pr_evidence(` in the implement job.**: It already builds the head commit, the check table, the links and the skipped runs as one updatable comment, and the evidence command calls it.
- **Publish the evidence in `_ready`, after the readiness answer and before the ready mark.**: It is the one transition point of the item, and it already holds the session, the pull status and the head at `src/devops_cli/roadmap/implement/implement_run.py:2055:head = status.head_sha or self._head()`.
- **Stop the item with the job's own stop class at `src/devops_cli/roadmap/implement/implement_run.py:302:class _StopError(Exception):` when the publisher raises a `GitHubOperationError` at `src/devops_cli/exceptions/git.py:86:class GitHubOperationError(DevOpsCLIError, RuntimeError):`, whose body holds `error_code = "GITHUB_OPERATION_FAILED"`.**: The evidence is a condition of the ready transition: the item is Blocked, `gh pr ready` never runs, and a retry writes the evidence.
- **Give `publish_pr_evidence` an optional keyword-only `head` and pass the head that the job already read.**: The test world answers the pull read with no head at `tests/support/roadmap_implement.py:118:"head": {"ref": BRANCH, "sha": ""},`, and many tests override that status before a ready finish, so an optional head keeps them as they are.
- **Keep the default of `head` as `None`, and name the head commit in the docstring of the command at `src/devops_cli/commands/pr.py:479:"""Write the check results of the head commit of a pull request as its one evidence comment.`.**: The command passes no head at `src/devops_cli/commands/pr.py:495:publish_pr_evidence(`, so its output and its requests stay the same, and the file that calls the publisher records the new argument.
- **Hold one evidence comment of the world's login in the test world, and list it ahead of the comments that a test gives.**: The publisher then changes that one comment, so the pull request holds one evidence comment and the one-comment rule is exercised, and the tests that unpack one posted comment stay as they are.
- **Record the requests that the API had already received at each `gh pr ready`, in a new list of the pull fake.**: The ready call and the evidence write reach two different fakes, so a shared record at the ready call is the only place that shows which of them came first; the test then fails when the evidence is written after the ready mark.
- **Modify the existing requirement `A pull request that passes its checks is marked ready` instead of adding a second one.**: The evidence condition has the same trigger as that requirement, which already names the ready mark at `src/devops_cli/roadmap/implement/implement_run.py:2097:mark_ready(self.repo, pull, draft=draft)`, so a second requirement with that trigger would leave two rules for one step.
- **Put the request-count update in the same group as the code, and run both test modules in its verify.**: The counts read the requests of the same run, so the group that moves them shows them passing, and a group that only repairs a broken test is no group.
- **Add no spec delta to `pull-request-evidence`.**: The evidence command keeps its behavior and passes no head, so only the ready step of the implement job changes, which the delta of `roadmap-implement-job/pull-request` records.

## Rejected alternatives

- **Build a second evidence renderer in the implement job.**: `src/devops_cli/github/pr_evidence.py:96:def publish_pr_evidence(` builds the head commit, the check table, the links and the skipped runs as one updatable comment already.
- **Run `devops pr evidence` as a subprocess from the job.**: The command is a thin caller of the same function at `src/devops_cli/commands/pr.py:495:publish_pr_evidence(`, and the job runs every `gh` and GitHub call in its own process, so a subprocess adds a shell call and command parsing where an in-process call exists.
- **Publish the evidence inside the check step after the watch.**: The repair loop of that step can push a new head after the watch, so evidence written there can name a head that a repair replaced; the ready step reads the final head at `src/devops_cli/roadmap/implement/implement_run.py:2055:head = status.head_sha or self._head()`.
- **Publish the evidence in the run before the ready step.**: It separates the evidence from the readiness decision and reads the pull status a second time, while the ready step holds it at `src/devops_cli/roadmap/implement/implement_run.py:2055:head = status.head_sha or self._head()`.
- **Log the failure of the publisher and mark the pull request ready anyway.**: The pull request would leave draft with no evidence comment, which is the defect that #4129 names.
- **Add a second requirement for the evidence with the same trigger as the ready requirement.**: The base requirement already holds that trigger and the ready mark at `src/devops_cli/roadmap/implement/implement_run.py:2097:mark_ready(self.repo, pull, draft=draft)`, so the condition belongs in that requirement.
- **Assert the order with the ready call list alone, as the first draft did.**: `tests/support/roadmap_implement.py:511:self.ready_calls.append(call.argv[1:])` holds only the argv of the ready call, so that assertion passes whether the evidence is written before or after the ready mark.
- **Let the publisher read the head from the pull request in every test world.**: The world answers it with no head at `tests/support/roadmap_implement.py:118:"head": {"ref": BRANCH, "sha": ""},`, and the tests that override the status before a ready finish would each need a head, for no gain in the real system.
- **Let the job post a new evidence comment on each run.**: The pull request would hold two evidence comments, and every test that unpacks the one posted comment of its run would need an edit.
- **Give `publish_pr_evidence` a required head and make the command read the pull status first.**: The command would make one more request for a head that the publisher reads at `src/devops_cli/github/pr_evidence.py:105:pull = client.get_pull(repo, number)`, with no change of its output.
