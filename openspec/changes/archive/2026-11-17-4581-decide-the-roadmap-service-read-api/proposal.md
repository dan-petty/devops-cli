# Proposal

## Why

The roadmap Service has no API, and the owner asked on 2026-11-11 for read endpoints of the Service state. Three choices need a record: where the API lives, who can reach it, and which writes it does not have. ADR 0021 moves the state into Valkey and the work into pods, and ADR 0022 names each repository's objects and keys, so the record must link to both (#4581).

## What Changes

- A new architecture decision record, `docs/adr/0029-the-roadmap-service-serves-a-read-only-api.md`, that records the placement, the route list with the data source of each route, the in-cluster exposure, the token rule, the Grafana exposure fact, and each write that the API does not have with the open tool that covers it.
- The index of `docs/adr/README.md` gains the row of the record.
- The change writes no code and alters no behavior a consumer observes, so it carries no spec delta and sets `skip_specs: true`.
- The change fits one pull request.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. The record is documentation, so the change carries no spec delta.

## Impact

- Documents: `docs/adr/0029-the-roadmap-service-serves-a-read-only-api.md` (new), `docs/adr/README.md`

## Feasibility

- The premise holds in the code at the staging commit. The Service turns OpenAPI off and serves the webhook routes, the probes and `/metrics` (`src/devops_cli/server/`), and it holds no read route of its state.
- The two records that the new record links to exist: `docs/adr/0021-the-roadmap-service-is-a-webhook-router-cluster-pods-run-the-roadmap-jobs-and-valkey-holds-their-shared-state.md` (the move) and `docs/adr/0022-one-repository-reference-names-the-objects-labels-and-keys-of-each-repository.md` (the naming record).
- The form rules are those of `docs/adr/README.md`, checked by `tests/invariants/test_adr_records.py`, and the index is generated by `uv run devops docs generate`.
- The check is `uv run devops ci docs`, which regenerates the index and validates the documents.
- The second check is `uv run devops ci test tests/invariants/test_adr_records.py`, which checks the form of the record.
- The third check is `uv run devops openspec check`, which validates the change.

## Existing Tool Considered

FastAPI, the framework of the Service, generates the OpenAPI document for the routes that the follow-up work adds, and the record names it. The record itself needs no tool: MADR 4 is the form, and the repository already holds the records and their check (`src/devops_cli/docs/adr_records.py`). The writes need no new tool: the argo CLI, GitHub labels and GitOps cover them, and the record names each one. The written cost is about 4,000 tokens and about 1 hour.

## Dependencies

- ADR 0021 (the move to jobs and Valkey), in `docs/adr/`, done.
- ADR 0022 (one `RepoRef` names each repository's objects and keys), in `docs/adr/`, done.
- Owner decision 2026-11-11: the API serves read-only routes for the dashboard (Grafana, the start page widgets and the CLI read) and the webhook routes, and no write routes.
