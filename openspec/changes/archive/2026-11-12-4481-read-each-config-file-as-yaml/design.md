# Design

## Decisions

- **The reader changes, not the writer and not the types.** The writer `round_trip.edit` writes YAML 1.2 with ruamel.yaml. Each reader of a config file now reads YAML 1.2 with the same library, so each string that a save writes loads as the same string. This fixes all string settings, not only the two mode fields.
- **One reader, `parse_config_yaml`, in `config/yaml_errors.py`.** It calls `YAML(typ="safe", pure=True).load(text)`. `pure=True` keeps the Python parser of YAML 1.2 when ruamel.yaml.clib is installed. A new `YAML` object for each call keeps the reader free of shared state between threads.
- **The import of ruamel.yaml stays inside the functions.** `parse_config_yaml`, `load_yaml` and `yaml_load_errors` import ruamel.yaml when they run. A command that reads no config file, such as `devops config --help`, does not import the 29 modules of ruamel.yaml. `config/write_history.py` imports `round_trip`, which already imports ruamel.yaml.
- **`load_yaml` catches the errors of ruamel.yaml.** `yaml_load_errors()` gives the `YAMLError` of ruamel.yaml and the errors of a value that the loader cannot build (`ValueError`, `LookupError`, `AttributeError`, `RecursionError`). `load_yaml` catches them for each parse, the round trip included, so its `errors` parameter goes. The rule of #1468 stays: the error names the file, the type of the error, and its line and column, and quotes no text of the file. The text of the file stays in the frame of the parse, which is not in the traceback of the error.
- **The mode types stay as they are.** `JevMode`, `DecisionMode` and the refusal of a bool of #4438 do not change. A bare `true` is a bool in YAML 1.2, so the scenario "The old bool is refused" of `roadmap-intake-jev` stays true.
- **The ConfigMap render reads only its config as YAML 1.2.** Kubernetes reads the manifest of the template, and its parser reads YAML 1.1, so the render reads the manifest with PyYAML. The config in the manifest is a devops-cli config file, so the render reads it with `parse_config_yaml`. The render writes the config with PyYAML, which quotes each word that YAML 1.1 reads as a bool or a number, such as `'off'`. The YAML 1.2 reader of the Service reads the same string. The render validates the settings of the YAML 1.2 read of the text that it writes, so it never writes a config that the Service cannot load.
- **The SSH key prefix reads the project config file as YAML 1.2.** `crypto/ssh_keys.py` reads `ssh.key_prefix` from a project config file without the settings load. It reads the same files, so it uses the same reader. It catches the errors that the settings load catches (`yaml_load_errors()`) and an `OSError`, so a tagged value that the loader cannot build gives no prefix and does not stop the command. The `try` block holds only the read and the parse.
- **A duplicate key stops the load.** The safe loader of ruamel.yaml refuses a key that a mapping holds two times, as YAML 1.2 requires. PyYAML kept the last value with no message. The error names the file, the line and the column, so a person can remove the duplicate.

## Rejected alternatives

- **A `BeforeValidator` on `JevMode` and `DecisionMode` that maps a bool to a mode.** The closed plan pull request #4599 proposed it. It fixes 2 of about 100 string settings: `devops config set search.language no` still writes `no` and stops each later load. It also makes `jev: true` and `jev: yes` load as `on`, the live mode, against #4438 and ADR 0019.
- **Quote the values in `round_trip.edit`.** Quotes cover only a file that the writer writes. A file that a person types, and the config of a ConfigMap, stay exposed.
- **A PyYAML loader subclass with the booleans of YAML 1.2.** It patches PyYAML and keeps two YAML versions in one process. Each other YAML 1.1 form, such as `12:30` as 750, still changes type. The import cost of ruamel.yaml (29 modules, only for a command that reads a config file) does not justify it.
- **Import ruamel.yaml at the top of `yaml_errors.py`.** The settings module imports `yaml_errors`. So each start that imports the settings module, such as `devops config --help`, would import the 29 modules of ruamel.yaml, also when it reads no config file. `python -X importtime` shows that `devops config --help` imports `devops_cli.config.settings` and does not import `ruamel.yaml`.
- **Write the config of the ConfigMap with ruamel.yaml too.** A prototype on the repository template wrote a different text: it folds the long telemetry URL at 80 columns and writes `jev: off` bare. The PyYAML writer quotes each word that YAML 1.1 reads as a bool or a number, so the YAML 1.2 reader reads the same value for each setting of the template.
