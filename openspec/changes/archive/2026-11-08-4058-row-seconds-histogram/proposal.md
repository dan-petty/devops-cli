# Proposal

## Why

No metric gives the seconds of one row of the roadmap Service. The counter `devops_cli_service_job_seconds_total` has the labels `repo` and `lane` and counts one lane round, so a slow row hides in the total of its lane. The 5 minute rule of AGENTS.md cannot be checked for one row (#4058).

## What Changes

- Declare the histogram `devops_cli_roadmap_row_seconds` (unit `s`) in `src/devops_cli/telemetry/instruments.py` with the labels `repo`, `row` and `result`, and add it to `INSTRUMENTS`.
- In `_execute_due_rows` (`src/devops_cli/roadmap/run.py`), time each `row.runner(...)` call with the clock seam `devops_cli.core.clock.monotonic` and send the seconds through `emit()` once the result is known. The result uses the values of `_count_job`: `success`, `error` and `stopped`.
- A row that is not due, a row that the ledger suspends and a row that a clone failure keeps from running add no sample. The clone failure never reaches the runner, so no time passed in the row.
- A run with no lane (the command line) adds the sample too. The instrument has no label `lane`, and `emit()` works in a short-lived process.
- A scoped update of a webhook (`run_scoped_update`) is not a row of a round and adds no sample. The issue names `_execute_due_rows` only.
- Regenerate `docs/TELEMETRY.md` with `uv run devops docs generate`, which lists the series and the series count.
- Series count: one repository adds at most 11 rows x 3 results = 33 series. The histogram is exponential, and Prometheus 3 stores it as one native histogram for each series with no `_bucket`, `_sum` and `_count` series (`docs/TELEMETRY.md`, instruments section). So the buckets add no series. The issue text "times the histogram buckets" does not hold for this path.
- The change adds no Settings key and removes, renames or tightens none. The example ConfigMap and the live ConfigMap load as before, so the rollout rule for a setting does not apply.
- The change adds no promtool test and no alert rule. The issue asks for none.
- The change carries a spec delta, because a metric of the Service is observable behavior.
- The change fits one pull request.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `metric-instruments`: The row seconds histogram is declared, documented and sent for each row that ran

## Impact

- Code: `src/devops_cli/telemetry/instruments.py`, `src/devops_cli/roadmap/run.py`
- Documents: `docs/TELEMETRY.md` (generated)
- Tests: `tests/telemetry/test_roadmap_row_seconds.py`

## Feasibility

- Code read at origin/main `f16535fa`, no run of the Service: `_execute_due_rows` in `src/devops_cli/roadmap/run.py` calls `row.runner(...)` one time for each row inside `request_scope(row=row.name)`. The skip `if not is_due or failures.suspended(...): continue` comes before it, so a timer around the runner adds no sample for a row that is not due or that the ledger suspends. The clone-failure branch counts a job and `continue`s before the runner, so it adds no sample either.
- `_count_job` takes its result from `_failed_result(exc)` (`error` or `stopped`) and `CONST_SERVICE_JOB_RESULT_SUCCESS`: 3 results.
- The set of rows, counted from `DEFAULT_DUE_TABLE` in `src/devops_cli/roadmap/run.py` by `tests/telemetry/test_roadmap_row_seconds.py::test_the_row_seconds_series_of_a_repository_are_bounded_by_the_rows_and_results`: status lane 6 rows (metrics, implement, stage_ready, release_comments, github_status, cloudflare_status), triage lane 1 (intake), model lane 4 (refine, retitle, stage, alternatives). 11 x 3 = 33 series for one repository.
- `src/devops_cli/telemetry/instruments.py` has `InstrumentKind.HISTOGRAM` and `emit()`. `docs/TELEMETRY.md` says that Prometheus 3 stores an exponential histogram as one native histogram under the instrument name, so the series count is 33 and not 33 times the buckets.
- The label `row` is the right name: `src/devops_cli/roadmap/tool_metrics.py` uses `row` and records that the collector sets `job` from the resource, and the rule "No instrument attribute is named job or instance" of `metric-instruments` forbids `job`.
- `docs/TELEMETRY.md` is generated by `generate_telemetry_docs` in `src/devops_cli/docs/generator.py` from `INSTRUMENTS`, so the document needs no hand edit.
- The file `svc_issues/c11a1.md` that the task names as basis is not in the repository. The body of #4058 holds the basis, and this change reads it.
- First check against the real system: `uv run devops ci test tests/telemetry/test_roadmap_row_seconds.py` passes, and `grep -q 'devops_cli_roadmap_row_seconds' docs/TELEMETRY.md` exits 0.
- Precondition: the calls need a checkout of the repository. They need no network and no cluster.

## Existing Tool Considered

The OpenTelemetry histogram that `emit()` in `src/devops_cli/telemetry/instruments.py` already sends, and the clock seam `devops_cli.core.clock`. No new library and no new helper: the change adds one `Instrument` and one timed call in `_execute_due_rows`. It deletes no internal code.
