# Design

## Decisions

- **The collector deletes `host.name`, before `deltatocumulative`.** The tracer of #4697 already sends no `host.name`. An old build still sends it, and a process can run an old build for a long time: a global install, a long-lived MCP server, a worktree on an old branch or a Job from an old image. Only the collector sees the metrics of every build, so the rule goes there. It runs after `memory_limiter`, so a full collector drops data before it does work, and before `deltatocumulative`, because that processor keys the stream.
- **The rule applies only where `telemetry.sdk.name` is `devops-cli-otel`.** The cause is in devops-cli builds. The collector is shared, and the Resource of another SDK stays as that SDK sends it. The test reads the SDK name from a metric that the tracer exports, so a rename in the tracer fails the test.
- **`error_mode: ignore`.** `delete_key` of a missing key is no error. If a statement fails, the processor logs the error and sends the batch on unchanged. A dropped batch loses counts of every workload, and an unchanged batch splits one series at most, which the alert then shows.
- **The alert names classes of labels, not only `host_name`.** With the collector rule, two devops-cli builds can no longer differ in `host_name`. The description tells the reader to compare the labels of the two `target_info` series: a different `telemetry_sdk_*` label is a second SDK, another different label is a devops-cli build with another metric Resource, and a `host_name` label shows metrics that did not go through the collector rule. The alert clears 15 minutes after the old writer stops, because the rule reads `last_over_time(...[15m])`.
- **The runbook action goes into the "Fires when" cell.** The rows of `GatewayDatabaseDown`, `GatewayDatabaseConnectionsNearMax` and `GatewayDatabaseNearClaim` already do this. The rows of `ResearchCriticalFindings`, `ClaudeSpendDailyHigh` and `HostedSpendDailyHigh` get the same fix, because the new table test covers every row.
- **The README test parses the table with markdown-it-py.** The GFM table rule keeps the cells that the header has and drops the rest. A row renders every cell when its source line ends with its last rendered cell. So the test needs no split of its own.
- **The promtool cases pin each part of the rule.** The firing case has no alert at 29 minutes and an alert at 30 minutes, which pins `for: 30m`. The pod-change case stays quiet at 34 minutes, the last minute at which the 15 minute lookback still holds the old series. A job outside `devops-cli.*|roadmap-service` stays quiet with two series. Two writers that each send once in 15 minutes fire, and with a shorter lookback they would not.
- **Job pods that run at the same time share one stream.** This is the design of #4697. The collector can drop a delta of one pod that starts before the stream or is older than its last point. `docs/TELEMETRY.md` says this and names the metric `otelcol_deltatocumulative_datapoints{error!=""}`.

## Rejected alternatives

- **Change only the alert text.** The text does not stop the wrong counts: Prometheus showed two `target_info` series of one job and instance for the workstation, two runner pods and roadmap-service while an old build ran next to a new one.
- **Delete `host.name` for every SDK.** All OTLP metrics today come from `devops-cli-otel` (7 days of `target_info`), so the result is the same now. But the collector also receives the data of other services, and the reason for the rule is specific to devops-cli builds.
- **Keep only the allowlist of the tracer in the collector (`keep_matching_keys`).** That is a second copy of `_METRIC_RESOURCE_KEYS` to keep in step. In the live data the old and new series differ in `host_name` only.
- **Add a fifth "Do this" column to the Alerting table.** That changes all 46 rows, and most rows have no action.
- **A test that runs the OTTL statement.** No collector binary is on the devcontainer or the GitHub runner, and the project adds no package to a runner. The test pins the statement, its place in the pipeline and the SDK name that the tracer sends. The upstream documents of contrib v0.163.0 confirm the function and the context.
