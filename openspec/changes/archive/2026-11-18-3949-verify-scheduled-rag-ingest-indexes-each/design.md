# Design

## Decisions

- **Call `run_ingest_pass` offline with three fixture remotes and an injected indexer, `src/devops_cli/ai/rag/indexer.py:639:class WorkspaceIndexer:`, over `FakeQdrantClient`.**: `devops ai rag ingest` calls the pass (`src/devops_cli/commands/rag.py:846:results = run_ingest_pass(`), so the test covers the pass the schedule runs, with deterministic data and no cluster. ADR 0005 replaces the `devops ai ingest` subcommands and keeps `devops ai rag ingest`.
- **Count points by the `project_name` payload key with `count_points`, and pass the expected repository list to the coverage assertion.**: The indexer writes that key on each point (`src/devops_cli/ai/rag/indexer.py:332:"project_name": chunk.project_name,`), so one count per repository gives the coverage result. The expected list lets the assertion name a repository that the counts omit, not only one whose count is 0.
- **Name the code collection for the test run with `_run_collection`, pass it to the injected indexer, and delete it in a `finally`.**: The issue asks for an isolated collection and its cleanup. The indexer takes the name (`src/devops_cli/ai/rag/indexer.py:647:code_collection: str = DEFAULT_RAG_COLLECTION,`) and the fake client deletes and lists collections (`tests/support/fakes/qdrant.py:138:def delete_collection(self, name: str) -> bool:`), so no product change is needed.
- **Give each of the two runs its own `data_dir=` for the pass and its own `cache_dir=` for the indexer.**: The intact check reads the counts file of the earlier run (`src/devops_cli/ai/rag/indexer.py:713:if project in counts:` and `src/devops_cli/ai/rag/indexer.py:716:prev_count = proj_counts.get(coll, 0)`), so a fresh collection looks intact and `src/devops_cli/ai/rag/ingest.py:278:if recorded_head == head and intact:` skips the repository. A per-run directory makes each run a first run, so both runs index and give the same counts.
- **Build the three fixture repositories with the existing `_make_bare_remote` helper.**: The helper makes a bare git remote under `tmp_path` (`tests/ai/rag/test_rag_ingest.py:55:def _make_bare_remote(`), so the run is offline and a missing repository is easy to inject.
- **Add the coverage assertion and the three tests to `tests/ai/rag/test_rag_ingest.py`.**: The module already holds the ingest pass tests, `FixedVectorEngine` and the fixture helpers, so a new module would duplicate them or import from another test module.
- **Leave `run_ingest_pass` and the injected indexer unchanged.**: A scheduled run must fill the collection that search reads, `devops_code` (`src/devops_cli/config/defaults.py:245:DEFAULT_RAG_COLLECTION = "devops_code"`), so a product change that wrote a run-named collection would leave search empty; only the test isolates its collection.

## Rejected alternatives

- **Create a Workflow from the CronWorkflow and wait for it.**: The controller watches only namespace `argo-workflows` (`k8s/argo-workflows/values.yaml:26:singleNamespace: true`), and the runner pod has no cluster token and no container engine, so the CronWorkflow in `devops` does not run.
- **Wait for the next scheduled run and check the live index.**: `k8s/devops/cronworkflow-rag-ingest.yaml:10:schedule: "*/3 * * * *"` shows a 3-minute schedule, a real wait is slow and flaky, and the controller does not watch namespace `devops`.
- **Run one lookup per repository through the CLI.**: A lookup returns the best matches, so a repository with no document and a repository whose document ranks low look the same, and neither names the repository that has no point.
- **Read the files that the docs ingestor writes.**: `docs/adr/0005-review-findings-come-from-tools-not-models.md:12:The docs ingestor writes files nothing reads.` so a check of those files shows nothing about the index.
- **Use the live repositories of the GitHub installation.**: It needs the network and its result changes between runs, and the runner's installation token names one repository, so one run would not cover three.
- **Change the product so a scheduled run writes a run-named collection.**: Search and the retriever read the collection that `DEFAULT_RAG_COLLECTION` names (`src/devops_cli/config/defaults.py:245:DEFAULT_RAG_COLLECTION = "devops_code"`), so a run-named collection in the product would leave search with nothing.
- **Keep the default `devops_code` collection in the test and skip the cleanup.**: The issue asks that the test write to a collection named for the test run and delete it after the run, and `tests/support/fakes/qdrant.py:138:def delete_collection(self, name: str) -> bool:` makes the cleanup assertable.
- **Reuse one data directory for both runs of the two-run test and let the second run skip.**: The second run would then skip every repository, because `src/devops_cli/ai/rag/indexer.py:716:prev_count = proj_counts.get(coll, 0)` records no count for its fresh collection and `src/devops_cli/ai/rag/ingest.py:278:if recorded_head == head and intact:` skips, so its collection would stay empty and the counts would differ.
