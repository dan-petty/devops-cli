# Design

## Decisions

- **Read `[review] tag_pattern` from `.devops/roadmap.toml` with default `CONST_ROADMAP_REVIEW_TAG_PATTERN = "v*"`.**: `src/devops_cli/roadmap/project_profile.py:78` already uses `CONST_ROADMAP_IMPLEMENT_STEPS_FILE` (`.devops/roadmap.toml`) as the repository roadmap declaration file; keeping the default constant beside `CONST_ROADMAP_IMPLEMENT_STEPS_FILE` in `src/devops_cli/config/constants.py` avoids duplicated constants. Validate `tag_pattern` in `_Review` to reject empty values, whitespace, or leading `-` so git refspecs stay safe.
- **Add `review: _Review = _Review()` to `_Declaration` in `src/devops_cli/roadmap/project_profile.py`.**: `_Declaration` configures `ConfigDict(extra="forbid", frozen=True)`, so adding `[review]` to `.devops/roadmap.toml` would otherwise raise `ConfigurationError` in `resolve_profile` during implement jobs.
- **Refuse an empty tag list on a version window inside `resolve_window`.**: `src/devops_cli/roadmap/project_review/window.py:209` receives `tags: Sequence[Tag]` from `read_tags(checkout, pattern)`; checking `not tags` under `case VersionRequest():` fails immediately with a message naming `tag_pattern` and the configured pattern without calling `_tag_commit`, while period and week windows with zero tags continue to succeed.
- **Check `rows and not read` in `complexity_fact` to mark `lizard.complexity` as `skipped`.**: `src/devops_cli/roadmap/project_review/facts.py:223` already filters `rows` via `lizard_languages.get_reader_for(row.path) is not None`. Returning `skipped` only when `rows` is non-empty and `read` is empty keeps empty windows (`rows == []`) as `ok` `[]` while giving churn-only `git.hotspots` with a printed skip reason on Shell-only windows.
- **Parse `CHANGELOG.md` headings and bullet items with `commonmark_parser()` in `functional.py`.**: `src/devops_cli/roadmap/markdown.py:15` provides the shared cached CommonMark parser required across roadmap Markdown readers (`tests/roadmap/test_roadmap_markdown.py`). Walking tokens from the first `h2` until the next `h2` and collecting top-level list items under `h3` headings `Features` and `Bug Fixes` avoids hand-rolled regex parsing.
- **Add `listing.merged_titles` to `catalog.yaml` and insert `functional.change` after `lizard.complexity` in `run_review`.**: `_ONE_READ` in `src/devops_cli/roadmap/project_review/dispatch.py:106` shares a single `listing` read across all listing facts, so `listing.merged_titles` costs zero extra GitHub requests and returns `[]` when empty (`status = ok`, `n = 0`). Placing `functional.change` between `review_facts` and `result.facts` only when no `openspec.*` fact has `status == FactStatus.OK` preserves `tests/fixtures/git/review_window.json` unchanged.
- **Add `planned_sections(catalog, settings)` for `--dry-run` with no window option.**: Handling `(dry_run or is_dry_run()) and not any((version, since, until, week, last))` in `src/devops_cli/commands/roadmap_review.py` before `parse_window` and `find_repo_root` lists every `service.repos` entry with section titles, fact IDs, unset `setting:` reasons (`_setting`), and other `_condition` texts without starting subprocesses or HTTP requests.

## Rejected alternatives

- **Read `planning.system` and `languages` from `resolve_profile`.**: `src/devops_cli/roadmap/project_profile.py:60` holds only `preset: ToolchainPreset` (`extra="forbid"`) with no language or planning system fields.
- **Call `resolve_profile` via `git show` from `run_review`.**: `src/devops_cli/roadmap/project_profile.py:79` executes extra `ls-tree`/`show` git commands that would break `tests/fixtures/git/review_window.json` (`25` exchanges, where the only tag read is `refs/tags/v*`).
- **Probe each file with a new language detector instead of `lizard_languages.get_reader_for`.**: `src/devops_cli/roadmap/project_review/facts.py:223` already asks lizard directly for a language reader per hotspot path.
- **Add a second GitHub REST read in `functional.py` for merged PR titles.**: `src/devops_cli/roadmap/project_review/dispatch.py:106` shares one `listing` read across all `listing.*` facts, so reading inside `listing.merged_titles` reuses the single listing pass.
- **Add a separate requirement beside `A dry run of the review starts no program`.**: `openspec/specs/roadmap-project-review/spec.md:56` already defines `devops roadmap review run --dry-run`; extending it with `MODIFIED` keeps dry-run behavior in one requirement.
- **Route private repository summaries to tracker issues in this change.**: `src/devops_cli/roadmap/project_review/review.py:74` returns `ReviewData` only and publishes no external summary; tracker-issue routing is tracked separately in `#7042`.

## Unchanged references

- `tests/fixtures/git/review_window.json`: Default `tag_pattern` (`v*`) produces the exact same `for-each-ref` arguments (`refs/tags/v*`), and the transcript records `review_facts` rather than `run_review`, so the recorded git fixture stays unchanged.
