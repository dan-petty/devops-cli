# Design

## Decisions

- **Upstream charts at pinned versions.** Argo CD installs chart `jetstack/cert-manager` v1.21.3 and chart `cloudnative-pg/plugin-barman-cloud` 0.8.1, as it does for every other chart. deploy-stack installs the same versions, so a cluster without Argo CD gets the same objects.
- **cert-manager values.** `crds.enabled` and `crds.keep` let the chart own the CRDs and keep them, because a deleted CRD deletes every `Certificate` and `Issuer`. `global.leaderElection.namespace: cert-manager` keeps the lease in the namespace of the release, so the chart writes no Role in `kube-system`. The chart's own NetworkPolicies stay off; this repository keeps each perimeter in git. No `ClusterIssuer` is set: the plugin chart brings its own self-signed `Issuer`.
- **Order.** The plugin chart renders a cert-manager `Issuer` and two `Certificate` objects, and the cert-manager webhook must answer before the API server admits them. deploy-stack installs `cloudnative-pg`, then `cert-manager`, then `plugin-barman-cloud`. The cert-manager start-up check Job holds `--wait` until the webhook answers. In Argo CD, Application `plugin-barman-cloud` is in sync wave 1 and has `SkipDryRunOnMissingResource=true`; its retry policy covers the time until the webhook is ready.
- **Perimeters.** The cert-manager namespace gets a default-deny perimeter: only the metrics scrape of `monitoring` on 9402 comes in, and only CoreDNS and the API server (443 and 6443 through an ipBlock that excludes the metadata address) go out. The issuers are self-signed, so no pod calls an ACME server. A second policy admits TCP 10250 to the webhook pods alone from any peer: the API server calls the webhook from the host network of the control-plane node, and kube-router matches no selector against that address. In `cnpg-system`, a policy selects only the plugin pod: the operator comes in on 9090, and CoreDNS and the API server go out. The operator keeps no policy, as before. The instance pods talk to the plugin sidecar in their own pod, so they need no rule. The sidecar sends the backups, so the perimeter of each database namespace gets its object-store egress with that database's backup item.
- **Where the policies live.** The root kustomization (`k8s/kustomization.yaml`) applies `cert-manager/` and `cnpg-system/`. Application `base` syncs it with Argo CD, and deploy-stack applies it on every stack, so the policies exist before the charts and the k8s gate check finds a path for each policy.
- **Metrics.** The cert-manager pods already carry `prometheus.io/*` annotations, so Alloy's annotation autodiscovery scrapes them, and the monitoring perimeter lets the scrape out on 9402. The plugin pod exposes no metrics port; its backup metrics come from the instance manager of each database.

## Rejected alternatives

- **The in-tree `barmanObjectStore`.** CloudNativePG 1.32.0 removes it (release-1.30 docs, `docs/src/appendixes/backup_barmanobjectstore.md`), so a backup set up on it must move again.
- **plugin-barman-cloud v0.16.0 (chart 0.9.0).** Published on 2026-11-09, so it is younger than 14 days.
- **A `pg_dump` CronJob.** It has no WAL archive and no point-in-time recovery, which #3741 needs.
- **A namespace-wide perimeter in `cnpg-system`.** It would also restrict the CloudNativePG operator, whose webhook and instance traffic this item does not change. A policy on the plugin pod alone changes nothing for the operator.
- **A named peer for the webhook rule.** The API server connects from a node address. kube-router matches an ingress ipBlock against pod addresses only (`k8s/monitoring/networkpolicy.yaml`), so no peer can name the API server; a rule with no peer on one port of the webhook pods is the narrow form. The cert-manager chart's own webhook policy also has no peer on its ingress rule.
- **The cert-manager chart's NetworkPolicies.** In chart v1.21.3 they are off by default. When on, their ingress rules have no peer on the metrics and health ports of every pod, and their egress rules let every pod reach any address on 80, 443, 53 and 6443. The perimeters in git are narrower and stay in one place with the other perimeters.
