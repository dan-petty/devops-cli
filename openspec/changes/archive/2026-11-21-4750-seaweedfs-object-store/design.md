# Design

## Decisions

- **Store and operator.** SeaweedFS with the SeaweedFS operator, both Apache-2.0. One `Seaweed` CR `seaweedfs` in namespace `object-store` gives every workload; the change writes no StatefulSet, Deployment or Service. ADR 0034 records the choice (0030 and 0031 exist, and 0032 and 0033 are reserved).
- **Versions.** The version rule of the owner (2026-11-11): no minimum release age; pin the newest SeaweedFS release that the newest operator supports, never below 4.53 and never 4.48 to 4.51. On 2026-11-21 that is SeaweedFS 4.54 (operator 1.0.45 builds against its commit `5ef99c1d8dbb`) with chart 0.1.48 (`appVersion` 1.0.45). `spec.image` pins `chrislusf/seaweedfs:4.54` by digest, and no component sets its own `version`, so one field names the release of every pod. The operator image is the `appVersion` of the chart, and the values set no tag.
- **Stack `infra`.** `CONST_K8S_STACKS` has no `storage` stack, so the chart, its repository, the post-Helm path `object-store` and the two Secret rows belong to `infra`. `deploy-stack --stack infra` installs the chart after cert-manager, because the chart issues its webhook certificate with cert-manager, and applies `k8s/object-store` after the charts, because the CR needs the CRD of the chart.
- **Argo CD.** Project `homelab`. `seaweedfs-operator` has sync-wave `-1` and `ServerSideApply=true`, because the CRD file is larger than the annotation limit of a client-side apply. `object-store` has sync-wave `0` and `SkipDryRunOnMissingResource=true`, as Application `mattermost` has for its CR, so the first sync waits for the CRD with its retries. The CR has `Prune=false,Delete=false`, and the data safety check of the `k8s` row covers the kind `Seaweed`.
- **Webhook certificate.** `webhook.certManager.enabled: true`: the chart renders a self-signed Issuer and a Certificate, and the cainjector of cert-manager writes the CA bundle. The rendered webhook configurations hold no `caBundle`, so the Argo CD diff does not see the field. This replaces the certgen hook Jobs of the chart.
- **Operator scope.** `watchNamespaces: [object-store]` gives the operator a Role in `object-store` and a small ClusterRole for the cluster-scoped reads, in place of a ClusterRole over every namespace.
- **Masters.** 3 masters, `defaultReplication` `001`, `volumeSizeLimitMB` 1000, `[master.volume_growth] copy_2 = 2`, `-telemetry=false`, and a 1Gi `fast-nvme` claim for the Raft state of each. SeaweedFS 4.54 freezes volume growth when a volume server reports another topology id (`freeze_on_topology_mismatch`, default true), and a master with no volume mints a new id at each restart, so a reboot of the cluster would stop all new volumes until a person runs `volume.growth.resume`.
- **Volume servers.** 3 replicas on 300Gi `fast-nvme` claims, `maxVolumeCounts` 300, `minFreeSpacePercent` 10, a required hostname anti-affinity among the volume pods, and the required control-plane exclusion of the placement rule. Replication `001` keeps the second copy of each volume on another volume server, which is another node.
- **Filers.** 2 filers, each with its own leveldb2 store on a 10Gi `fast-nvme` claim; the filers sync their metadata with each other. No S3 in the filer: the operator marks it deprecated.
- **S3 gateway.** The standalone `spec.s3`, 2 replicas on 8333, `iam: false`, and `-port.iceberg=0 -port.lance=0`. `iam: false` keeps the IAM API, STS and OIDC off (SeaweedFS 4.54 starts them only for `-iam` or `-iam.config`), and it closes the S3 Tables bypass of GHSA-25hp-4mw7-9c75, which needs the IAM subsystem. `configSecret` names key `s3.json` of Secret `seaweedfs-s3`, an identities file with no identity: with a config file, SeaweedFS 4.54 refuses each request until an identity exists, and it merges the identities that the admin UI keeps in the filer. With no config file it would allow every request.
- **Admin and worker.** 1 admin with `credentialsSecret` `seaweedfs-admin` (`adminUser`, `adminPassword`); the operator binds the admin to all addresses only when `adminPassword` is there, which closes GHSA-m3m8-mrgq-hf9h. 1 worker with `jobType` `vacuum,volume_balance,admin_script,s3_lifecycle`, with no erasure coding.
- **JWT signing.** `securityConfig.jwtSigning.volumeWrite` and `filerWrite` are true. The operator mints each key and keeps it in Secret `seaweedfs-security-config`, which the CR owns, so `CLUSTER_SECRETS` holds no JWT row.
- **Secrets.** `object-store/seaweedfs-admin`: `adminUser` is the literal `admin`, and `adminPassword` is the keyring-only key `seaweedfs_admin_password`, made with `token_urlsafe(32)` when the keyring lacks it. `object-store/seaweedfs-s3`: `s3.json` is the literal `{"identities": []}`. Both have stack `infra` and restart their workload.
- **Perimeter.** `object-store-perimeter` selects every pod of the namespace for ingress and egress. Ingress: the pods of the namespace on the HTTP and gRPC ports of the master (9333, 19333), the volume servers (8444, 18444), the filers (8888, 18888), the S3 gateway (8333, 18333) and the admin HTTP port (23646); the worker pods on 33646; each namespace with the label `backup-client: "true"` on 8333; namespace `monitoring` on the metrics port 9327. Egress: CoreDNS and the pods of the namespace. `monitoring-default-perimeter` limits the egress of every pod of `monitoring`, so it gets an egress rule to namespace `object-store` on 9327, as the cert-manager scrape has one to 9402. `object-store-operator` selects the operator pod: ingress on the webhook port 9443 with no peer, as `cert-manager-webhook` does, and egress to the Kubernetes API on 6443 with the metadata address excluded, as the Argo Workflows perimeter does: the `kubernetes` Service resolves to the node address on 6443. No rule names a client namespace: a namespace selector on the label selects the clients.
- **Workload security.** Each component sets `runAsNonRoot`, `runAsUser` and `runAsGroup` 1000 (user `seaweed` of the image), `fsGroup` 1000, `seccompProfile` `RuntimeDefault`, `allowPrivilegeEscalation: false` and `capabilities.drop: [ALL]`. The chart sets the same form on the operator.
- **Budgets and requests.** One PodDisruptionBudget for each component and the operator, each with `maxUnavailable: 1` and `unhealthyPodEvictionPolicy: AlwaysAllow`. The requests add up to 900m CPU and 2752Mi of memory, under the 1 CPU and 3Gi of the namespace.
- **Metrics.** Each component sets `metricsPort` 9327, and `spec.serviceMonitor.enabled` makes the operator write one ServiceMonitor for each component, which Alloy scrapes (`prometheusOperatorObjects`). The operator owns the pod templates, so pod annotations would not stay.
- **No Ingress.** No component sets `ingress`, and the CR sets no `hostSuffix`. A port-forward reaches the admin UI.
- **Alerts and dashboard.** The `seaweedfs` group in `serverFiles.alerting_rules.yml` of `k8s/monitoring/prometheus-values.yaml`, with a row for each alert in the README alert table (rule SRE3). The dashboard is `other/metrics/grafana_seaweedfs_k8s.json` of tag 4.54 in `k8s/monitoring/dashboards/seaweedfs.json` in a ConfigMap of its own, with the changes that `devops grafana dashboards lint` needs: a uid, a data source object on each panel, no empty query, and the two S3 bucket panels moved under the last panel. The chart's own dashboard ConfigMap is off: the sidecar does not read namespace `object-store`.
- **Checks.** `tests/gate/k8s_checks/object_store.py` reads the renders that the `k8s` row shares. Each rule is a function that returns its problems; one check applies it to the committed render, and one applies it to a small fixture that breaks the rule and asserts that the problem names the object, as `job_admission_policy.py` does.
- **Build test.** `k8s/object-store/build-test/` is a kustomization that no Application lists. It makes namespace `object-store-build-test` with the label `backup-client: "true"` and two Jobs: boto3 (4 parallel 150 MB multipart uploads) and minio-go (one streaming upload of unknown size), both through Service `seaweedfs-s3`. The README gives the steps around it: the bucket `build-test`, made in the admin UI because SeaweedFS authorizes a bucket create as `Admin`, a temporary S3 identity with Read, Write, List and Tagging, the cross-gateway check and the volume pod check with the `curl` of the SeaweedFS image in the gateway pods, and the 33646 check with the `nc` of the image in a filer pod and the worker pod.
- **Catalog.** `k8s/catalog.toml` gets the service `object-store` (rule SRE1): Applications `object-store` and `seaweedfs-operator`, tier 2 (the backups of #3741 serve a tier 1 service), data class `owned`.

## Rejected alternatives

- **A hand-written ServiceMonitor in `k8s/object-store/`.** The operator writes one for each component from `serviceMonitor.enabled` and `metricsPort` (operator 1.0.45 `controller_servicemonitor.go`), with the selectors and ports of its own Services, and its ClusterRole grants `servicemonitors`. A copy would repeat them.
- **`CLUSTER_SECRETS` rows for the JWT keys.** Operator 1.0.45 `ensureSecuritySecret` mints and keeps the keys in Secret `seaweedfs-security-config`, with the CR as its controller, and rewrites that Secret at each reconcile. A pushed copy would fight the operator.
- **An S3 gateway with no config file.** SeaweedFS 4.54 `auth_credentials.go:419-427` then allows every request to each pod that the perimeter admits.
- **The certgen hook Jobs of the chart.** They run as Argo CD hooks at each sync and pull `registry.k8s.io/ingress-nginx/kube-webhook-certgen`; cert-manager already runs in the cluster.
- **The dashboard ConfigMap of the chart.** It goes into namespace `object-store`, where the sidecar does not look, and it uses the old `rows` schema. The main dashboard of the tag is 407233 bytes, more than one ConfigMap holds.
- **Masters with no claim.** A restart of all three masters would freeze volume growth (`freeze_on_topology_mismatch`).
- **A new AppProject or stack `storage`.** The workload Applications use `homelab`, and `deploy-stack` pushes only the rows of a stack in `CONST_K8S_STACKS`.
- **A client namespace by name in the perimeter.** The rule would name a service in the store policy; the label `backup-client: "true"` lets each client namespace opt in.
- **A committed shell or Python script for the build test.** The repository holds no shell script and no Python outside `src/` and `tests/`, and minio-go needs Go. The Jobs run the two clients in their own images, and the README holds the `kubectl` steps.
- **A ResourceQuota for the request sum.** A rolling update starts a new pod before the old one stops, so a quota at the sum would block the rollout. The `k8s` row adds up the requests instead.
