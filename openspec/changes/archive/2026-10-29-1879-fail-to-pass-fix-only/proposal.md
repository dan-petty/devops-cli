# Proposal

## Why

Issue #1879: the fail-to-pass check ran on every pull request into `main`, and it carried an escape: the line `Fail-to-pass: not applicable: <reason>` in the pull request body. The owner rule of 2026-10-20 is: a check that does not apply is not run there, and the project builds no escape to make a check pass. Only a fix must show a test that fails on its base (rule 4 of AGENTS.md), and only a change to the code under `src/` can make a test fail on base.

## What Changes

- `.github/workflows/fail-to-pass.yml` starts only for a pull request that changes `src/**` outside `src/devops_cli/ai/knowledge_base/**` (an `on.pull_request.paths` filter). Its job runs only for a title that starts with `fix(`, `fix:` or `fix!` (a job `if:`). The `labeled` trigger goes, because no label decides the job.
- The `self-check` job, which replayed two pinned commits and matched a fixed line of output, is deleted. The live tests that replay a real fix in a `tmp_path` git repository with a real nested pytest run do that work (`test_a_new_module_s_test_that_cannot_import_on_base_leaves_the_other_tests_counted` and `test_a_test_that_runs_git_ls_files_passes_on_base_in_the_replay`).
- The release-please case of the concurrency group is deleted: the release pull request changes no file under `src/`, so the path filter never starts the workflow for it.
- `devops ci fail-to-pass` reads no title, label or body. The options `--title`, `--labels` and `--body` and the variables `PR_TITLE`, `PR_LABELS` and `PR_BODY` go. Each run enforces the replay: at least one changed test fails on base.
- Deleted from `ci/fail_to_pass.py`: `extract_escape_reason`, `parse_pr_labels`, `_parse_json_labels`, `_is_enforced_defect`, and the report's `is_defect` and `escape_reason` fields. `CONST_FAIL_TO_PASS_ESCAPE_PATTERN`, three help strings and the `fail_to_pass_not_applicable` message go.
- A replay that cannot run on base fails and tells the author to merge the change to the test harness or the dependencies first, in a pull request that is not a fix.
- `CONTRIBUTING.md` states when the check runs and drops the escape line. Renovate's `prBodyNotes` with the escape line goes: a base image update changes only the `Dockerfile`, so the path filter skips it.
- The check's trigger, its command options and its report text are behavior that a contributor sees, so the change carries a spec delta: the new capability `ci-fail-to-pass`.
- This change fits one pull request.

## Feasibility

- **Workflow on `origin/main` (2026-10-29):** it ran on `opened`, `synchronize`, `reopened`, `edited` and `labeled` for every pull request into `main`. It passed `PR_TITLE`, `PR_LABELS` and `PR_BODY` to the replay. Its `self-check` job replayed `5768cd9` against `36b2bee` and matched `16 failed and 24 passed in tests/test_ai_fixer.py`.
- **Required checks:** the ruleset `main branch` (read with `devops gh api repos/{owner}/{repo}/rulesets/<id>`) requires only `Static Analysis`, `Tests & Coverage` and `Semantic PR title`, with `strict_required_status_checks_policy: false`. `Fail-to-Pass Check` is not required, as ADR 0012 records.
- **GitHub documentation, "Troubleshooting required status checks":** a job skipped by a conditional "reports Success". When a workflow is skipped by path filtering, "Associated checks stay in a 'Pending' state and block merging". So a path filter is safe only for a check that is not required, which holds here. If a person ever makes `Fail-to-Pass Check` required, the path scope must move into the job's `if:`.
- **GitHub documentation, "Workflow syntax":** "If you define a path with the `!` character, you must also define at least one path without the `!` character". The last pattern that matches decides.
- **GitHub documentation, "Expressions":** `startsWith( searchString, searchValue )` "is not case sensitive", as `CONST_DEFECT_TITLE_PATTERN` (`re.IGNORECASE` in `github/defect_classifier.py`) is not. A test holds the job condition equal to that pattern on fix titles, other types, upper case and `fixup:`.
- **Release pull request:** the last `chore(main): release` commit changed `.release-please-manifest.json`, `CHANGELOG.md`, `pyproject.toml` and `uv.lock` only. None matches the path filter.
- **Path choice (issue decision B):** `src/**` without the knowledge base skips the test-only fixes #1896 and #1897 and the dependency fix #1900, and keeps the replay of #1901, whose 18 tests failed on base.
- **Self-check replacement:** the two live replay tests took 4.6 s and 4.1 s at a load average of 21 on 16 CPUs. They already ran in the suite, so the gate gains no time.
- **Criterion "git grep finds no `PR_BODY`":** two mentions stay and neither reads a body. `test_no_title_label_or_body_changes_the_result` sets `PR_BODY` to an escape line and shows that the result does not change, and a docstring in `tests/test_pr_cmd.py` names the squash setting `PR_BODY`.

## Existing Tool Considered

GitHub Actions' own `on.pull_request.paths` filter and job-level `if:` with `startsWith` scope the check. The change builds nothing. It deletes the escape parser, the label parser, the title and label classification of the replay, the three command options, and the `self-check` job.
