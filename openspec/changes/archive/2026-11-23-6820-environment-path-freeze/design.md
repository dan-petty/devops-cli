# Design

## Decisions
1. **The check is a module of the `k8s` row.** `tests/gate/k8s_checks/environment_freeze.py` holds `check_the_branch_changes_no_environment_path`. The runner of the row imports each module of `tests/gate/k8s_checks`, so the check needs no new row, no new subcommand and no change under `src/`. `Static Analysis` runs the row, and the scoped checks of an agent (`--only ...,k8s,...`) run it before a push. Reason: the check is about the committed Kubernetes files, and step 17 deletes one module and its test.
2. **The changed paths come from git.** The check runs `git diff --name-only --no-renames -z origin/main...HEAD` in the checkout: the net change of the branch from its merge base with `origin/main`. `--no-renames` gives both paths of a move, so a move out of the environment counts as a change. `-z` gives each path with no quotes. A commit that adds a file and a later commit that removes it give no path. Reason: the squash merge applies the net change, and a pull request shows the same diff.
3. **Python decides each path.** `is_environment_path` is true for a path under `k8s` that is under neither product folder and that does not end in `.md`. The two product folders are the excludes of the pathspec of step 10. A new file under `k8s` is an environment path too, because the rule is by folder and not by a list. Reason: a test gives the output of git to `outcome` and starts no git ([docs/TESTING.md](../../../docs/TESTING.md)), so the rule must be in Python.
4. **A Markdown file is not refused.** Steps 12 and 15 of the runbook change `k8s/README.md` in devops-cli, and the `docs` row can ask for a change of a document under `k8s`. A document deploys nothing, so no author thinks that it deploys.
5. **A git failure fails the check.** When git exits with another status than 0, for example when `origin/main` is not in the checkout, the check fails with the exit status, at most 256 characters of the error of git, and the fix: fetch `origin/main` with its history. Reason: a check that cannot read the change must not pass.
6. **The message names homelab.** Each finding gives the path. The last line says that Argo CD reads the environment from dan-petty/homelab since step 11, that the change goes to a homelab pull request, and that step 17 deletes the files and the check.
7. **Renovate turns off the dependencies of the environment paths.** One package rule with `matchFileNames: ["k8s/**", "!k8s/devops/**", "!k8s/overlays/homelab/devops/**"]` and `enabled: false`. Renovate still reads the files, so the managers and their file patterns stay as they are, and step 17 deletes one rule.

## Rejected alternatives
- **A new row of `devops ci`.** Rejected: it needs a change of `src/devops_cli/commands/ci.py`, a message, a subcommand and the generated documents, and step 17 must delete all of them. The scoped checks of an agent do not name a new row, so an agent sees the refusal only in CI.
- **A git pathspec in the git command.** Rejected: the rule is then in git, and a test cannot prove that `k8s/devops` passes without a start of git.
- **`ignorePaths` in `.github/renovate.json`.** Rejected: Renovate 44.239.2 does not merge `ignorePaths`, so the repository value replaces the eight paths that `:ignoreModulesAndTests` of `config:recommended` gives, `**/tests/**` included. Its patterns take no negation, and a substring such as `k8s/monitoring` also matches `k8s/devops/monitoring/`.
- **A branch ruleset that restricts file paths.** Rejected: only a person changes the repository settings, and the ruleset gives no message that names the homelab repository.
- **Refuse each path of the metadata file of homelab.** Rejected: devops-cli has no copy of the list, and a new environment file is not on it (step 10 of the runbook).
