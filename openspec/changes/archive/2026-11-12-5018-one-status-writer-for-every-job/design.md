# Design

## Decisions

- **The writer derives every Status.** `StatusFacts` gets `needs_refine`, `pull_ready` and `pull_open`, so each caller gives facts and no caller names a Status. The order is New, In Review, In Progress, Blocked, Planned, Ready. A return outranks every other fact, because the item goes back to refine. A pull request that is ready for review outranks a Job that still runs, because the runner Job marks the pull request ready before it ends. An open pull request outranks a stop, because `devops pr create` on an item with a stop of the implement job is the fix of the stop.
- **Only the label decides the write.** The writer compares the derived Status with the label of the item that its caller read, as the issue asks. When they are equal, it writes only the marks and the body that its caller gives, with `set_marks`, and reads nothing. A record that differs from an equal label stays as it is.
- **The read-back checks the label.** After a write, the writer reads the issue with `store.issue` and compares its Status label with the written Status. It reads the issue and not the Item, because intake writes New on a candidate before the Priority that makes it an Item. A difference raises `RoadmapStatusLostError`, a `GitHubOperationError`, so each caller reports it as it reports a failed write: the sweep adds a failure for the item and goes on, `devops pr` prints the error and exits 1. The writer does not write again, because the facts came from the issue before the other write; the next round derives the Status from the issue as it is. The check of the job record waits for the record read-back of #4555.
- **The guards stay with the callers.** The sweep writes only an item that it owns (`owns_status`), `devops pr` replaces only the Statuses of `_REPLACES`, and a stop is cleared only by its rules. The writer holds no guard, so each caller keeps its own rule.
- **The import cycle.** `status_sync.py` imports only leaf modules at the top. `PlannedChanges` and `StageFailure` are imports for type checks, and `sync_statuses` imports `write_each` when it runs.
- **The structural test reads the source.** It walks the syntax tree of each module of `src/devops_cli` and names a call of `set_field` that names `ItemField.STATUS`, and a label write of a `status/` literal, outside `roadmap/status_sync.py` and `roadmap/stores/`. It sits in `tests/invariants/test_architectural_invariants.py`, next to the git seam test of the same form.

## Rejected alternatives

- **A Status argument next to the facts.** `write_status(store, item, status)` for New and In Review, and facts only for the sweep. Rejected: then two rules name a Status again, which is the problem of the issue.
- **Compare the label and the record before a write.** A write when the record differs from an equal label would set `Status: New` in the record of an item that a person labeled New, and `repair.py` reads that record as "a job set New" (`_job_set_new`). Rejected: it changes what repair finds, and the issue asks for no write when the label is equal.
- **Write again after a lost write.** Rejected: the second write would use the facts read before the other writer, so it could revert a newer change (ADR 0002).
- **Move `StageFailure` and `write_each` out of `stage.py`.** It breaks the import cycle at its source, but it changes five more modules that import them. Rejected for this change: the imports for type checks and the import inside `sync_statuses` break the cycle with no change of the other modules.
- **Read the label back with `store.item`.** Rejected: `item` gives None for an issue with no Priority, so each intake placement failed with a lost write (123 failed tests in `tests/roadmap`, most of them intake).
- **Write the intake Status after the Priority.** Rejected: a run that stops between the two writes leaves an Item with no Status, and intake reads only candidates again, so no run would write it.
- **Catch a generic field loop in the structural test.** A check that fails on each `set_field` whose field is a variable would also fail the dry-run planners, which pass field names as text. Rejected: intake, the one generic writer, now sends the Status through `write_status` by hand.
