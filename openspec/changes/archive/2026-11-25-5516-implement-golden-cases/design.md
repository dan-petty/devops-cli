# Design

## Decisions

- **Proportional scope allocation with full scope floor**: Compute Conventional Commit scope counts from merged delivery commits on `origin/main` over the last 90 days (commits with complete three-file archived OpenSpec change folders, excluding automated changelog/planning/dependency commits). Every scope with valid OpenSpec task groups receives at least one fixture, and remaining slots are distributed in proportion to 90-day delivery volume (`81` total cases across `49` scopes: `14` existing baseline fixtures plus `67` new cases). Each new fixture keeps real GitHub issue text, real merged OpenSpec `proposal.md`, `design.md` and unticked `tasks.md`, the parent SHA before the delivery commit as `base`, modified files named by the selected group's code spans as `changes`, and pytest/CI check commands as `tests_pass`.
- **Single gate row `roadmap-eval-commits`**: Rename `roadmap-stage-eval-commits` (`tests/gate/roadmap_stage_eval_commits.py`, `tests/invariants/test_roadmap_stage_eval_commits_check.py`) to `roadmap-eval-commits` (`tests/gate/roadmap_eval_commits.py`, `tests/invariants/test_roadmap_eval_commits_check.py`) and have it load both `tests/fixtures/roadmap_eval/stage` (`StageCase.base_commit`, allowing `NO_COMMIT` only with an explicit note) and `tests/fixtures/roadmap_eval/implement` (`LoadedCase.case.base`, requiring a full 40-character SHA that resolves via `git cat-file -e <sha>^{commit}`). Regenerate `docs/` and update the MCP listing snapshot for the renamed CI row.
- **Raised size bound and scope invariant**: Raise `MAX_BYTES` in `tests/invariants/test_roadmap_eval_fixtures.py` from `300_000` to `1_000_000` and replace the 10-case threshold with a 40-case threshold plus a scope-distribution test (`test_the_scope_counts_match_the_delivery_mix`) that parses each fixture's Conventional Commit scope from `case.title`, prints `<scope>: <count>`, and asserts exact agreement with the recorded 90-day distribution and total case count.

## Rejected alternatives

- **Equal fixture count per scope**: Overweights single-commit scopes at the expense of high-volume scopes (`roadmap`: 615/1576, `k8s`: 177/1576, `ai`: 113/1576) and either skews the E2/E3 pipeline evaluation or exceeds the byte budget across 49 scopes.
- **Random selection from all history**: Fails to reflect the current 90-day delivery distribution of OpenSpec-planned work (and older commits predating `openspec/changes/archive` lack structured `plan/` files required by `tests/fixtures/roadmap_eval/implement/2152-numeric-host-doubles/case.json`).
- **Second gate row for implement commits**: Adding `roadmap-implement-eval-commits` alongside `roadmap-stage-eval-commits` would duplicate the shallow-clone guard (`git rev-parse --is-shallow-repository`), `git cat-file -e` runner, and `static` job `fetch-depth: 0` rationale documented in `docs/TESTING.md:76` and `.github/workflows/ci.yml:57`.
- **Keeping `MAX_BYTES = 300_000`**: The existing 14 fixtures already occupy `276_058` bytes (`tests/invariants/test_roadmap_eval_fixtures.py:15`), and `load_cases` reads one root folder (`src/devops_cli/roadmap/implement/implement_eval.py:214`), so reaching 40+ full-text fixtures requires raising the bound to `1_000_000` bytes rather than truncating real issue bodies/plans or splitting the root directory.
