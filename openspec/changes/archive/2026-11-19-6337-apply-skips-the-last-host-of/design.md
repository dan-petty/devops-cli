# Design

## Decisions

- **Choose the separator inside `host_pattern` from the limit itself: a comma when the limit holds a comma, a colon when it holds none, where `src/devops_cli/infra/plan.py:168:return f"{pattern}:!{offline_group}" if offline_group else pattern` holds the colon of today.**: Ansible splits a pattern that holds a comma on the commas only, so a comma limit needs the exclusion as its own comma term, and a limit with no comma keeps the colon form that the living requirement `No host of the offline group is in the limit` and the dry-run snapshots hold.
- **Build the shown pattern of the plan dry run and of the apply dry run with `host_pattern`, where `src/devops_cli/infra/infra_plans.py:182:pattern=f"{limit or 'all'}:!<offline group>",` and `src/devops_cli/infra/infra_plans.py:281:argv=runner(f"{','.join(together)}:!<offline group>", check_mode=False),` hold the literals of today.**: The dry-run text then shows the separator that the run sends, and one rule holds it for the plan, the together run and both dry runs.
- **Keep the colon of the single-host steps, as `src/devops_cli/infra/infra_plans.py:320:pattern = f"{host}:!<offline group>"` shows for the fresh check and the run of one disruptive host.**: A single host name holds no comma, so the colon is the separator that Ansible reads for that pattern, and the dry-run text of one host keeps its snapshot.
- **Keep the call sites in `src/devops_cli/infra/apply.py:555:outcome = context.run.run(host_pattern(names, context.offline_group), check_mode=False)` and the field `src/devops_cli/models/infra.py:238:host_pattern: str = Field(` as they are.**: They pass the limit to the helper or hold its answer; only the separator inside the helper changes, so no caller and no record field changes.
- **Read the hosts of a run from its limit in the fake with each `!` term dropped, where `tests/support/infra.py:296:return tuple(pattern.split(":", 1)[0].split(","))` holds the read of the colon form today.**: The together run of two or more hosts sends the exclusion as its own comma term, and the fake would otherwise read `!offline` as a host of the run in `tests/support/infra.py:343:steps.append(f"{kind} {','.join(limit_hosts(call))}")`.
- **Keep `tests/commands/__snapshots__/test_infra_plan.ambr`, `tests/commands/__snapshots__/test_infra_apply.ambr` and `tests/commands/__snapshots__/test_infra_status.ambr` as they are.**: Each shows the pattern of one host or of no host term, where the limit holds no comma, so `--limit 'node-3.example.com:!<offline group>'` and `--limit '!<offline group>'` stay the same text.
- **Replace the requirement `No host of the offline group is in the limit` of `openspec/specs/infra-plan/spec.md` with text that names both separators, and add the requirement `Each host of the together run is one term of the limit` to `infra-apply`.**: The living text names the colon only, which contradicts the comma term of a comma limit, and the archive writes the living spec from the spec delta.
- **Test the together run through the command layer with the fake runner, in `tests/commands/test_infra_apply.py:208:def test_the_hosts_with_no_disruptive_class_run_together_with_no_drain(`.**: The together run needs a plan record, a cluster and a runner, and the Lab of that module plans first and keeps each `ansible-runner` call, so a test reads the `--limit` that the run got.

## Rejected alternatives

- **Always append the offline exclusion with a colon.**: `src/devops_cli/infra/plan.py:168:return f"{pattern}:!{offline_group}" if offline_group else pattern` is the defect: Ansible reads the term `<last host>:!offline` of a comma limit as no host, as the issue reports for the apply `bc18ea1590e2472bb1b59929494e08c3`.
- **Always append the offline exclusion with a comma.**: It changes the pattern of a limit with no comma, which `tests/commands/test_infra_plan.py:197:assert (plan["status"], plan["error"], plan["host_pattern"]) == ("failed", None, "all:!offline")` and the base scenario `node-5.example.com:!offline` of the requirement `No host of the offline group is in the limit` hold.
- **Change only the together run and leave the dry-run texts with their literal colon.**: `src/devops_cli/infra/infra_plans.py:281:argv=runner(f"{','.join(together)}:!<offline group>", check_mode=False),` would show a pattern that no run sends, and `src/devops_cli/infra/plan.py:592:pattern = host_pattern(request.limit, ansible.offline_group)` shows the plan command on the same helper.

## Unchanged references

- `tests/commands/__snapshots__/test_infra_apply.ambr` (snapshot file): it shows the pattern of one together host, where the limit holds no comma and the separator stays a colon.
- `tests/commands/__snapshots__/test_infra_plan.ambr` (snapshot file): it shows the pattern of one limit host, where the limit holds no comma and the separator stays a colon.
- `tests/commands/__snapshots__/test_infra_status.ambr` (snapshot file): it shows the `--limit` of the SSH check, which holds no host term and no comma.
