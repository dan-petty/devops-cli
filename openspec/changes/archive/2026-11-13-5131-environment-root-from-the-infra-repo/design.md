# Design

## Decisions

- **One resolver, one tree object.** `resolve_environment` returns an `EnvironmentTree`: the root, the repository that holds it, and a property for each path that devops reads (`application_dirs`, `root_application`, `dashboards`, `gateway_config`, `ollama_profiles`, `gpu_thresholds`, `tier_templates`, `llm_services`). The layout of a tree is one contract of the product, in one module. A command reads no path of the tree by a constant.
- **The order of the sources.** `--k8s-dir` wins. Then the profile of the repository of the current folder, because a person or a CI job that works in an infra repo means that repo. Then the infra repos of the settings, because a person in a checkout of devops-cli after the switch means the infra repo. Two infra repos that give a tree are an error, not a choice: the command cannot know which cluster the person means. The reads are local files only (a walk to `.git` and `tomllib`), so a dry run reads them too.
- **devops-cli declares its own tree.** `.devops/project.toml` declares `[kubernetes] dir = "k8s"`. Each command reads the same files as before in a checkout of devops-cli, and the CI job `image-pins` needs no option. The switch of #5134 removes the line, and every command then reads the tree of the infra repo with no code change.
- **A relative option stays relative.** `tree_at` keeps a root as the option gives it, so `--k8s-dir k8s` prints `k8s/llm/gateway` as before. A root from a profile is absolute. The repository that holds the tree is the nearest folder with `.git` at or above the root, else the parent of the root, so a copy of `k8s/` outside a repository reads its Application paths (`k8s/devops`) as the checkout does.
- **The product base apart from the tree.** The 28 product manifests and the two Argo Workflows files of the `devops` stack move to `PRODUCT_MANIFESTS_BY_STACK` and `PRODUCT_POST_HELM_BY_STACK`, with paths relative to `k8s/devops`. The alert rules of `prometheus` (#5292) are the `product_values` of its release, after its environment values, in the order of the Application. The ConfigMap template is read from the product base. The two `agents` manifests are environment files and stay in `MANIFESTS_BY_STACK["devops"]`, after the product files, in the order of before.
- **Fetch of another repository.** `SourceTrees` maps the origin to the checkout and fetches any other `https` repository once for each revision, under a lock, because `image-pins` renders Applications in threads. The commands are those of `render_at_revision`. A URL that is not `https` (`file://`, `ext::`, `ssh`) is refused before git runs: such a URL can read the host or run a command. A dry run records the fetch commands and renders no path source of another repository.
- **The default dashboard folders.** `devops grafana dashboards sync` and `lint` read `monitoring/dashboards` of the tree, then `dashboards` of the product base. An infra repo holds no product base, so the product folder is read only when the current repository holds it; in a checkout of devops-cli the two folders are linted together, so a uid that both share is still an error (#5292).
- **Names of live objects are settings with the live names as defaults.** A sync finds a Cloudflare policy by name, and the doctor reads an Application by name, so other defaults would make new objects or fail on the homelab. The owner can set other names in `config.yaml`.
- **The gate keeps its placeholder rule.** `CONST_K8S_ARGOCD_HOMELAB_APPLICATIONS` stays until #5134 step 5c, so a fetched product base is checked with the same host-field rule as the local one.

## Rejected alternatives

- **A `k8s_dir` key in `infra.repos[]`.** `InfraRepoConfig` has `extra="forbid"` (`settings.py:1584`), and its description says that the facts of a repository are in its profile (#5121). The profile already has `kubernetes.dir`.
- **Settings for each relative path of the tree** (`llm/gateway/config.yaml` and the others). The paths are the layout of a tree, which an infra repo copies as it is (#5134 copies `k8s/` to the same paths). A setting for each path adds keys that no person changes, and the root already moves with `kubernetes.dir`.
- **A Kustomize remote base in place of a fetch** for `image-pins`. A remote base renders the whole base, but `image-pins` must also read a value file of a ref source for `helm template`, which no remote base gives, and it must name the Application of each image.
- **The fetch through `render_at_revision`.** It takes the runner of `cluster_runtime` and renders at once. Since #5294 it also gives git the GitHub credential of the session for a private repository on github.com. `image-pins` and the gate read public sources, so the source module keeps its own three git commands with no credential of its own.
- **Absolute paths for every root.** The dry run of `deploy-stack --k8s-dir k8s` printed relative paths before, and tests and documents read them. The option keeps the form the person gave.
- **The Application `cluster` of the Argo CD check of `deploy-stack`.** `_is_cluster_argo_managed` and its messages name `cluster`. The issue does not list it, and #5134 keeps the name, so it stays.
