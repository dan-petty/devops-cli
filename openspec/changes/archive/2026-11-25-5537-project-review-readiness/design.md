# Design

## Decisions
- **Row-check map home (`src/devops_cli/roadmap/project_review/readiness.py`)**: Keep the 91-row `READINESS_ROWS` tuple and check dispatch next to `catalog.py`, producing `Fact` entries inside `RepoReadiness` models stored on `ReviewData.readiness`. Tests parse `docs/guidelines/production-readiness.md` directly and assert exact agreement on ID, Scope, Level, scorecard checks, kube-linter checks, commands, and `manual` flags, plus zero `#<digits>` issue numbers and zero gap fields. [sources: docs/guidelines/production-readiness.md, src/devops_cli/roadmap/project_review/data.py:60]
- **Scorecard first, GitHub API fallback for private repos**: Check repository visibility via `read_github(session, f"repos/{repo}", ..., paginate=False)` (`PagedSession`), invoke `scorecard --repo=github.com/<repo> --format json`, and on failure when `private=True` evaluate repository practice rows via `read_github` contents/repository/branches/releases/workflows queries with `source="github"`. Private repositories still stay omitted from shared `ReviewData.readiness` (`private=True` excluded by `collect_readiness` shared output), while per-repository evaluation returns their full rows. [sources: src/devops_cli/roadmap/project_review/readers.py:179, tests/support/fakes/github.py:193]
- **Command and manual checks**: `devops` commands execute via `run_subprocess` and interpret JSON stdout (`state`, `ok`, `passed`, `failing`) or exit code as fallback, setting `source` to the executed command; `manual` rows and unread check kinds (`catalog`, `settings`, `promql`, `kube-linter`, etc.) return `not readable` with zero subprocess or HTTP calls. [sources: docs/guidelines/production-readiness.md, src/devops_cli/core/process.py]
- **`--ref <branch>` and `--dry-run`**: Add optional `--ref` to `devops roadmap review run`. When `--ref` is provided without a window (`--version`/`--last`/etc.), run the readiness report at that ref; when combined with a window, pass `--ref` into readiness collection. `--dry-run` prints planned Scorecard, GitHub, and command reads with zero requests and zero subprocesses. [sources: src/devops_cli/commands/roadmap_review.py:52, src/devops_cli/roadmap/project_review/review.py:55]

## Rejected alternatives
- **Hardcoding `service.repos` or gap issue numbers in `readiness.py`**: Rejected because gap state lives on GitHub sub-issues and repositories come dynamically from live `settings.service.repos` and `settings.infra.repos`. [sources: docs/guidelines/production-readiness.md, src/devops_cli/config/settings.py:2438]
- **Generating `readiness.py` from `docs/guidelines/production-readiness.md`**: Rejected because row check specs carry executable check descriptors while the test suite enforces bidirectional sync directly against the Markdown table. [sources: docs/guidelines/production-readiness.md]
- **Merging per-row readiness facts directly into `ReviewData.facts`**: Rejected because existing review consumers and tests assert exact catalog-only IDs in `ReviewData.facts`; adding `ReviewData.readiness` keeps `Fact` schema reuse while preserving backward compatibility. [sources: tests/commands/test_roadmap_review.py:143, src/devops_cli/roadmap/project_review/data.py:123]
