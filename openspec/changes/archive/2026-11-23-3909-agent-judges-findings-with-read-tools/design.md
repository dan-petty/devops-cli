# Design

## Decisions

- **The judge runs on pydantic-ai through the project's `build_agent` factory and the toolset helper `create_function_toolset` of `src/devops_cli/ai/toolsets/__init__.py`.**: ADR 0028 chooses pydantic-ai as the open agent framework of the project, the pins give the typed output and the test models, and every other agent of the project is built by that one factory.
- **The judgment prompt is the module constant `JUDGE_INSTRUCTIONS`, passed to `build_agent` as `instructions`.**: `src/devops_cli/ai/client/factory.py:257:instructions: str | Sequence[str] | None = None,` shows that the factory puts the text on the Agent, and a module constant lets a test read the prompt that the live run uses.
- **The agent registers exactly four read-only tools: a store lookup, a repository search, the component list and an exact or regular-expression match over stored text.**: ADR 0028 names ripgrep or Python `re` for the exact and regular-expression match and Qdrant for the index, and each answer names a record id or a path, so the citation check can verify what the model read.
- **The citation check is a plain function after the agent returns, and the agent holds no field and no tool that files a candidate.**: ADR 0005 gives model output no field that changes state, and a test checks the drop and the count in code.
- **The judge reads through the narrow `ReadOnlyCorpus` protocol that `src/devops_cli/research/judge.py` defines, and not through a Qdrant client.**: A test doubles the corpus and reaches no network, and the caller that holds the research index satisfies the protocol at the call site.
- **The judge lives in `src/devops_cli/research/judge.py`, beside the sweep and its models.**: It judges the records of the research sweep and reads the component list of `src/devops_cli/research/models.py`.
- **A narrow instruction-override detector joins `scan_injection_line`, and its pattern needs a second-person possessive, so it matches "ignore your rules" and "disregard your instructions".**: The issue's test phrase is plain English that the four existing detectors pass, and the second-person form leaves the existing INJ002 case at its one finding.
- **A record that the scanner flags is withheld from the model and named in the report.**: A warning inside the prompt does not stop the instruction, and a person can tell a flagged advisory from a missing one only when the report names it.
- **affects_us holds yes, no or unknown, and a record with thin evidence gets unknown.**: The evaluation gate fails on a false no, so the judge needs a way to say that it cannot tell.
- **The per-sweep record limit and the daily token limit are settings of the research job, counted by the judge.**: A test sets a low limit and checks the stop with no outside service, and each stop names its setting and its value.
- **The two limits are fields of a new `research` section of the class `src/devops_cli/config/settings.py:2372:class Settings(BaseSettings):`, beside `src/devops_cli/config/settings.py:2422:roadmap: RoadmapConfig = RoadmapConfig()`, and each field carries `Variable()`.**: `src/devops_cli/config/settings.py:2096:hours: Annotated[int, Variable()] = Field(` is the marker on a nested field, and `src/devops_cli/commands/config.py:147:for key in sorted(setting_variables().keys() | secret_keys())` shows that `devops config show` reads that map.
- **The two new variables join `_VARIABLES_OF_LATER_SETTINGS` in `tests/security/test_config_declarations.py`, and the settings documents are regenerated rather than edited.**: That file holds the census of declared variables, and `docs/ENV_VARS.md` and `docs/CONFIGURATION.md` are output of `uv run devops docs generate`, which `uv run devops ci docs` checks.
- **The rate function is named `judge_agreement_rate`, and `src/devops_cli/ai/run_store.py` stays unchanged.**: The name states that the rate scores the judge, and no function of the shorter name exists to reuse.
- **The 20 labeled findings are a checked-in constant, and the default test runs `judge_records` over them with a `FunctionModel`, while a separate live module prints the rate of the gateway model.**: The default test then covers the record loop, the citation check and the gate together with no model token, and the live run gives the rate for the pull request comment.
- **The group that withholds a flagged record comes before the group that adds the two limits, and it defines `JudgeReport` and `judge_records`.**: The limits change the signature and the stop of the record loop, so the loop must exist first or the later group could not run as ordered.

## Rejected alternatives

- **Match the bare phrase "ignore previous instructions" in the new detector.**: `tests/security/test_prompt_injection.py:47:hidden = "Ignore previous instructions` is the text of that case and `tests/security/test_prompt_injection.py:49:assert len(findings) == 1` counts its findings, so a second match would break the existing INJ002 case.
- **Hand-edit `docs/ENV_VARS.md` with the two new settings.**: `docs/CONFIGURATION.md` and `docs/ENV_VARS.md` are generated documents, and `uv run devops ci docs` runs `devops docs check`, which refuses a document that is not the generator's output.
- **Declare the two settings with no environment-variable marker on the field.**: The declaration census would still pass, because `env.setting_variables()` and the fixed set would both stay as they are; the limits would then be absent from `devops config show`, which prints only `setting_variables().keys()`, and from the generated `docs/ENV_VARS.md`.
- **Build the agent with no instructions and rely on the output schema to steer the model.**: The six fields of `JudgeFinding` state no rule about which verdict to give or which citation to attach, and a plan that claims a judgment prompt must give the text a test can read.
- **Let the evaluation test feed hand-built judged values to the gate functions.**: The test would then pass whatever the judge answers, and group 7 now runs `judge_records` over the 20 records with a `FunctionModel` and asserts the gate on that run.
- **One generic search tool for the agent.**: It cannot name the record that it read, so the citation check cannot verify the answer against the store.
- **A tool of the agent that files the intake candidate.**: ADR 0005 says that model output has no field that can create, move, re-rate or change the state of a finding, and the agent can skip a tool call.
- **A pydantic validator on the output model that checks the citations.**: It needs the store inside the model process, and the model then sees the check and can retry around it.
- **Warn the model about the instruction in the prompt instead of withholding the record.**: The issue's test requires no tool call and no output field for that record, and a warning in the prompt does not stop the instruction.
- **A boolean affects_us field.**: The evaluation gate fails on a false no, and thin evidence needs a way to say that the judge cannot tell.
- **A confidence score instead of the three-valued field.**: The gate counts labels and not scores, and a score adds a threshold to tune.
- **Use the budget store of #3066 for the two limits.**: #3066 is open and bounds the model use of a repository and of a day for the Service; this change needs one record count and one token count for its own run.
- **Run the labeled evaluation in every CI job.**: It spends model tokens on each push, and ADR 0004 keeps the model token costs bounded, so the live run is a manual process.
