# Design

## Decisions
- **One rule for the body.** `spend_limit_error(status, body)` in `ai/client/models.py` decides for each 401 or 403 reply. It reads only the error text of the body: the body when it is a string (a JSON text is parsed first), else its `message`, else its `error`, read the same way. The reader of the error text is the one that `body_error_text` of `agent_run.py` uses; it moves to `models.py` as `provider_error_text`, with no change, and `body_error_text` calls it. It reads no other value, so a value that the model wrote in another field does not decide the class. The rule matches `Key limit exceeded` with no regard to case. It puts no text of the body in the error.
- **A subclass of `AICredentialsError`.** A spent key stops each model call until a person acts, as a refused key does. Each stop site (`stage`, `refine`, `implement`, `alternatives`, the eval runs) catches `AICredentialsError` and stops the run. A subclass keeps that stop with no change at those sites, and a caller that must tell the two apart reads the type.
- **Each 401/403 site uses the rule.** `model_call_error`, the three branches of `LLMClient` and `fetch_model_info` call the rule before they build their credentials error. Each site keeps its own credentials text for any other body. `fetch_model_info` reads `/model/info`, which the gateway answers without a call to the provider; the rule there costs one call and keeps one rule for every 401/403.
- **The class `spend_limit`.** Its default action is `wait`, because only a person can raise the limit or change the key. Its wait is 1 hour, as for `provider`: a probe costs one refused call, and a raised limit lets the next probe work. It is not a split class of the stage Job, so it does not send an item back to refine.
- **The text rule follows the message.** The log of a stage or implement Job holds the error text, and the Service classifies that log with `classify_failure`. The rule is made from `ERRORS.ai.provider_key_spend_limit` with `_text_around`, as the rule for a refused command is, so it cannot drift from the message. It is the first rule of the text, because the provider says the cause, which is the most sure cause that a text can give, and a Job log can also hold an earlier timeout or provider line.
- **The alert reads the class of the existing series.** `RoadmapProviderKeySpendLimit` reads `devops_cli_service_stage_jobs_total{result="failed"}`, `devops_cli_service_implement_failures_total` and `devops_cli_service_job_suspended`, each with `class="spend_limit"`. The Service primes the two counters for each class, so `increase()` counts the first failure. A row of the Service has no class on `devops_cli_service_jobs_total`, so its signal is the suspended gauge, which is 1 after `service.max_failed_rounds` failed rounds. The alert is critical with no wait, as `RoadmapServiceIdentityRefused` is: the provider said the cause, and every model call fails until a person acts.

## Rejected alternatives
- **Wait for pydantic-ai.** pydantic-ai 2.71.0 gives `ModelAuthenticationError` for each 401 and 403 (`_model_errors.http_status_category`), and reads quota codes only for OpenAI-compatible bodies (`_QUOTA_CODES`). `LLMClient` does not use pydantic-ai. So pydantic-ai alone cannot class an OpenRouter key limit in either path.
- **Map `ModelQuotaExceededError` to the spend-limit error too.** pydantic-ai gives it for a 402 and for an OpenAI quota code that comes with a 429. No live failure showed it, and a 429 now gets the wait of `provider`. The issue names the 403 only, so this change keeps the 402 and the 429 as they are.
- **A new `result` value on `devops_cli_service_jobs_total`.** It would change the meaning of `RoadmapServiceJobsFailing` and of the success rates of the project review, which read `result`. The issue asks for a second signal, not a new meaning of the first.
- **A new counter for spent keys.** The existing Job outcome series already carry a `class` label, so a new metric would count the same event twice.
- **Match the raw OpenRouter text in a Job log.** A log of an implement Job can hold that text in a test or a plan of this change, and the cause rules come before the check rules. The rule reads the text of our own error only.
