# Design

## Decisions

- **The gate reads `recorded_check`, which needs the job-record key and the block of the job in the body, not the key alone.**: `src/devops_cli/roadmap/refine/refine.py:def recorded_check` already gives that rule to the request of the round, so a person who deletes the block deletes the check for both.
- **The exempt class is the verdict `not-applicable` plus a repository whose alternatives check is off.**: The alternatives job gives `not-applicable` to each skip class with no model call, so a second refine-only list would drift from it.
- **A new `NextStep.ALTERNATIVES` value carries the wait.**: `refine.next_step` is what a later round reads to end a wait, and the alternatives block is left out of the body hash, so a body change alone cannot end this one.
- **The new step gets the key `alternatives` in each of the three maps that a step value indexes.**: `src/devops_cli/roadmap/refine/refine.py:1450:template = texts.refine_step_comments[step.value]` writes the comment, `src/devops_cli/roadmap/refine/refine.py:2318:return texts.refine_left_waits[waits.step.value].format(details=shown).strip()` writes the left line, and `src/devops_cli/roadmap/refine/refine.py:3480:return [texts.refine_step_headings[step.value], *lines] if lines else []` writes the report heading, so one missing key raises a `KeyError` in the round.
- **The wait ends on `recorded_check` of the item and reads no comment.**: The check writes a block that `body_hashes` leaves out, so the recorded hash cannot see it, and a comment read would cost a request for a wait that no person ends.
- **The person-set Ready guard uses `owns_status` of `src/devops_cli/roadmap/status_sync.py`.**: `owns_status` is the rule that says a job last wrote the label, and the transitions table gives a label that a person set the final say.
- **The gate runs before the review of a Ready proposal for an item that a bot opened.**: The review costs a model call, and a proposal cannot be Ready while the alternatives verdict is absent.
- **The gate keeps `covers` as the only verdict that asks a person.**: `src/devops_cli/roadmap/refine/refine.py:def covers_question` asks a person for `covers` alone today, and the issue keeps that question as it is.
- **The last group verifies with the whole `uv run devops ci`, not the docs row alone.**: The fourth acceptance criterion names the whole gate, and `uv run devops ci` runs its docs row too, so one step delivers the document change and the criterion.
- **A public-repository refine test that expects Ready gets a recorded check, and a test about another rule seeds a private store.**: The default providers make web search on for a public repository, so the gate applies to those tests, and a private store is exempt exactly as the gate is written.
- **The task of the person-set guard cites the symbol `src/devops_cli/roadmap/refine/refine.py:def _apply_refined` and no constant name.**: `src/devops_cli/roadmap/stage/stage_registry.py:126:if any(entry.token in text for text in texts) or any(entry.token in path for path in paths):` makes the registry gate match a token in a task text, and the plan adds no constant.

## Rejected alternatives

- **Ask a person for a `partly` verdict too, as the body's proposed design reads.**: `src/devops_cli/roadmap/refine/refine.py:657:if check is None or check.verdict is not Verdict.COVERS or not check.tool:` asks a person for `covers` alone, `docs/CLUSTER.md` says that a `covers` verdict makes refine ask, and the existing covers tests treat `partly` as no question; a new question would hold each `partly` item in New and is outside the four acceptance criteria.
- **Make the alternatives row set Ready itself.**: `openspec/specs/roadmap-alternatives/spec.md` says the check changes no label, and `src/devops_cli/roadmap/status_sync.py:def write_status` names refine among the writers of the Status.
- **Treat a missing verdict as a job failure with the next step `retry`.**: A failure counts against the tries on one body and stops at the limit (`src/devops_cli/roadmap/refine/refine.py:class JobCheck`), and no text of the item brings a verdict; the item would end in `failed`.
- **Add a refine-only exempt-class list for the item types that need no tool.**: `src/devops_cli/roadmap/alternatives.py:166:_SKIP_COMMIT_TYPES: tuple[str, ...] = ("test", "docs", "refactor", "chore", "ci", "perf")` already names them, and the job gives each one `not-applicable`, so a second list would drift.
- **Read the job-record key alone as the verdict.**: `src/devops_cli/roadmap/refine/refine.py:def recorded_check` returns None when the block is missing, so the key alone would pass a check that a person deleted from the body.
- **Verify the last group with `uv run devops ci docs` alone.**: The acceptance criterion `uv run devops ci` passes. names the whole gate, so a docs-only verify leaves that criterion with no step that runs it.
- **Add a task for `tests/roadmap/test_roadmap_limit_classes.py` because a task text held a constant name.**: `tests/roadmap/test_roadmap_limit_classes.py:47:("prefix", "CONST_ROADMAP_", "tests/roadmap/test_roadmap_limit_classes.py"),` counts the constants that `src/devops_cli/config/constants.py` declares, and the plan declares none, so a task for that table would check a change that the plan does not make.
- **Rely on the comment text and the left line alone for the new step, with no heading entry.**: `src/devops_cli/roadmap/refine/refine.py:3480:return [texts.refine_step_headings[step.value], *lines] if lines else []` runs for every item on the step, so the round would raise a `KeyError` and `devops roadmap refine` would print no report.
