# Design

## Decisions
- **Each git child gets the token.** The parser of the git arguments decided which git child got the token, so that no program that the agent wrote into a configuration file, a hook or an attribute file saw it. The agent now runs in a container with no token (#3700), so the process runner gives each gh and git child `GH_TOKEN`, as it did before #5266. The lookup and the mint stay: a person's git child looks up the token on first use, and the App mints its installation token and renews it before it expires.
- **A gh child reads `GH_TOKEN`.** The private folder kept the token out of the environment of a `--jq` filter. The filter is the code of the caller, and no program of the agent runs in a container that holds a token. gh reads `GH_TOKEN` before any stored login.
- **The own session stays.** A child that gets the token still starts in a session of its own, and a timeout kills its process group. This is not a sweep of the processes of the job: it ends the helpers of the one child that ran out of time. Each git child that gets the token now runs in its own session, so the SIGINT of a Ctrl+C does not reach it from the terminal. The process runner sends that SIGINT to the group and waits 0.25 s, as `subprocess.run` waits after a Ctrl+C, and only then kills the group. Without the SIGINT, a killed `git commit -a` left `.git/index.lock`, and a killed `git worktree add` left a locked worktree.
- **git keeps a failed lookup.** Each git child of a person looks up the token, and #6671 keeps no failed lookup. In a process with no login, such as `agent`, CI with no `GH_TOKEN` or a workstation with no login, each git call would start `gh auth token` first: about 0.24 s a call, and twice 5 s when gh hangs. So the git children keep a failed lookup for the life of the process. A gh call still looks again, as #6671 asks, and a token that it finds reaches the next git child.
- **The withdraw of the review step is a plain push.** It runs `git ls-remote --heads origin <ref>` and, when the branch is there, `git push --quiet --force-with-lease=<ref>:<lease> origin :<ref>` in the clone of the plan, which no agent wrote (`clone_git.git`). The lease keeps the push of another writer, and a branch that is gone gets no push, as before.
- **`deny_environment_reads` stays.** It is not in the list of #6691, and the agent phase still runs code of the pull request as a child of its own process.
- **The `envFrom` branch of the policy goes with the one-container branch.** Only a runner Job of one container from before #6518 had `envFrom`. Without the first branch, the policy refuses an `UPDATE` of such a Job by its shape, so the second branch admits nothing, and its comment, that the Service still patches such a Job, is wrong.
- **`git_config` stays.** The failure taxonomy keeps the class for the records of earlier Jobs, as it does since #3702. No stop site gives it.
- **`psutil` goes.** Only `end_leftover_processes` read it, so `deptry` would report it as an unused dependency. pytest-xdist counts the workers with `os.sched_getaffinity` when psutil is not there, and `PYTEST_XDIST_AUTO_NUM_WORKERS` still sets the count of a runner Job.

## Rejected alternatives
- **Keep the git parser as a filter of the lookup.** A local git call would then start no lookup and no mint. The owner decision lists the parser for deletion, and the cost is one lookup for each process, which the process keeps.
- **Keep the sweeps as hygiene.** The docstrings and the specs of the sweeps name the token as their one reason. The processes of `agent` end when its container ends, and `prepare` and `publish` run no program of the pull request.
- **Delete `--phase all` too.** It is not in the list of #6691. It runs only where `require_runner` passes, and the runner Job gives each container its own `--phase`.
- **Delete the one-container paths of `build_job`, `log_tail` and `phase_containers`.** The stage, planner and default templates have one container, so these paths stay. The ended runner Jobs of one container stay readable until their TTL deletes them.
