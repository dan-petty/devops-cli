# Design

## Decisions

1. **The generator imports every module of devops-cli, and no list of modules exists.** `DocGenerator.catalog_module_names` takes the `.py` files of the directory of the `devops_cli` package with `Path.rglob`. It gives each file its dotted name with `module_name` of `devops_cli.core.import_graph`. `DocGenerator._import_all_exception_modules` imports each name with `importlib.import_module`. Then `DevOpsCLIError.__subclasses__` holds each error class, through any chain of bases and any import name. Reason: the hand list is the cause of #6815. A file list has no entry that a person can forget.
2. **The names come from the files, not from `pkgutil.walk_packages`.** Reason: `walk_packages` skips a directory with no `__init__.py`. The probe of the proposal shows that it skips the 6 modules of `devops_cli.docker`. An error class there would then be missing from the catalog, and no check would fail. The file list holds all 964 modules.
3. **The cost is about 2.3 s for each `devops docs generate`.** When the catalog runs, 565 modules are in memory, and the other 399 are new imports. The median of six runs of the command is 5.95 s on the base and 8.24 s with the change, on one workstation. The output files are the same. No module fails to import, and the imports happen in the function, so the `startup-imports` row of `devops ci` does not change. An import that fails still stops the docs stage with the name of the module. The catalog tests do the same imports: in a fresh worker, `tests/docs/test_exceptions.py` takes about 2.3 s, against 0.3 s on the base. `tests/module_durations.json` keeps 0.2 s for the module until `devops ci durations` writes the record again from the runs of `main`. A value that a person writes is not a measurement. The difference of 2 s is 0.3 % of the 660 s that the record gives each shard.
4. **The guard test runs the import step in the test process and checks `sys.modules`.** The test reads the `.py` files of `src/devops_cli` and calculates their dotted names with no help from the generator. Then it runs the import step of the catalog and expects each name in `sys.modules`. A module that an earlier test of the worker loaded can only hide a missing module. It cannot add a false failure. A check of the error classes alone passes on ec5b16bdc, because the list names each module with an error class today. On the base, the import step loads only the listed modules, so the test fails with the names of the others. The test starts no process.
5. **A new capability, `docs-error-catalog`, holds the rule.** No base spec holds a rule of `docs/ERRORS.md`. `docs-cli-reference` holds the rules of `docs/CLI_REFERENCE.md`, and `command-error-exit` holds the rules of how a command reports an error.

## Rejected alternatives

- **Keep `CONST_DOMAIN_EXCEPTION_MODULES` and add a test that fails when a module with an error class is not in it.** Rejected: the test must import every module too, so it costs the same time in the test run. A person still edits the list for each new module, and the list is the cause of #6815.
- **Find the error classes with an `ast` scan for `class X(DevOpsCLIError)`.** Rejected: a class whose base is another error class, from another module or under another name, needs name resolution that the scan must build again. That is a parser of our own, and the import of the modules gives the answer with the standard library.
- **Import the modules that `pkgutil.walk_packages` gives.** Rejected: it skips the namespace package `devops_cli.docker` (decision 2).
- **Run the import step in a fresh interpreter, and check `sys.modules` after it.** Rejected: the child imports each module of the package again and took 10 s to 15 s under the load of a test run. The import step in the test process takes about 2 s (decision 3).
- **Patch `importlib.import_module` and record the names that the import step asks for.** Rejected: `docs/TESTING.md` lets a test double only an edge, and the import system is not an edge. A function that gives the names needs no double.
- **Move every error class into `devops_cli.exceptions`.** Rejected: 21 classes of 16 modules would move, with the imports of their callers. That is a refactor of its own, and a new module could still define an error class elsewhere with no failed check.
