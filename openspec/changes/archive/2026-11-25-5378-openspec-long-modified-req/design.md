# Design

## Decisions
- **Reuse `stage_change.requirement_length_problem` directly**: Export `requirement_length_problem(name: str, text: str) -> str | None` from `src/devops_cli/roadmap/stage/stage_change.py` (using existing `_js_length`, `REQUIREMENT_MAX_CHARS`, and `MESSAGES.roadmap.stage_problem_requirement_long`) and import both `REQUIREMENT_MAX_CHARS` and `requirement_length_problem` in `src/devops_cli/openspec/gate.py`. Both modules reference identical objects with one copy of the limit, UTF-16 count, and wording.
- **Defer `devops_cli.openspec.gate` imports in `src/devops_cli/commands/openspec.py`**: Move `check_openspec`, `plan_check`, and `version_finding` imports from module scope (`src/devops_cli/commands/openspec.py:18`) into `check` and `regenerate`. Importing `stage_change` at module load in `gate.py` causes `devops openspec --help` to import `pydantic_ai`, which fails `tests/gate/startup_imports.py:252` (`help_problems`). Keeping module-level re-exports in `gate.py` lets `devops_cli.openspec.gate` expose the shared objects while `devops openspec --help` loads zero heavy modules.
- **Share one `openspec show` pass per active change before validation**: Add `change_deltas(tool, root, changes)` and `overlapping_deltas(deltas)` in `src/devops_cli/openspec/overlap.py`. `check_openspec` reads active change deltas once before `_validation_findings`, computes `GateCheck.REQUIREMENT_LENGTH` findings before CLI validation, and passes the loaded deltas to `_overlap_findings` at its existing step 5 slot. If `show` raises `ToolExecutionError`, `check_openspec` captures the error cleanly and reports `[GateFinding(GateCheck.OVERLAP, str(unreadable))]`, preserving `tests/openspec/test_openspec_tool.py:62-78`.
- **Preserve `plan_check()` command order on empty trees**: Keep `show_args(CHANGE_PLACEHOLDER)` at the end of `plan_check()` in `src/devops_cli/openspec/gate.py:281-285` because on empty trees (`changes == []`) zero `show` commands execute, preserving the contract asserted by `tests/openspec/test_openspec_gate.py:73-107`.
- **Plan vs infra classification**: `GateCheck.REQUIREMENT_LENGTH` is intentionally excluded from `_CI_INFRA_CHECKS` (`src/devops_cli/roadmap/stage/stage_job_phases.py:781-783`), so long-requirement findings classify as plan issues rather than CI infrastructure failures.

## Rejected alternatives
- **Copy `REQUIREMENT_MAX_CHARS` or `_js_length` into `src/devops_cli/openspec/gate.py`**: Rejected because `#5378` explicitly forbids a second copy, and two copies risk drifting from `stage_change.py:140,947`.
- **Move `REQUIREMENT_MAX_CHARS` and `_js_length` into a new standalone module**: Rejected because it modifies stage import graphs (`stage_change.py`) and moves a helper already tested under `tests/roadmap/stage/test_roadmap_stage_requirement_length.py`.
- **Leave `from devops_cli.openspec.gate import ...` at top level of `src/devops_cli/commands/openspec.py`**: Rejected because importing `stage_change` pulls `pydantic_ai` into `sys.modules` (verified via `-c "import devops_cli.commands.openspec, devops_cli.roadmap.stage.stage_change"` showing `heavy: ['pydantic_ai']`), violating `tests/gate/startup_imports.py:252`.
- **Run `_requirement_length_findings` after `_validation_findings` or call `openspec show` twice**: Rejected because OpenSpec CLI validation emits warnings naming `requirements[N]` instead of requirement titles (`issue #5378`), and calling `show` twice per active change duplicates subprocess work.
- **Catch `ToolExecutionError` separately inside both length and overlap checks**: Rejected because `tests/openspec/test_openspec_tool.py:72-78` asserts a single `GateCheck.OVERLAP` finding when `openspec show` fails.
