# Design

## Decisions
1. **The in-namespace egress has the ports of the in-namespace ingress.** Egress rule 2 of `object-store-perimeter` keeps the peer `podSelector: {}` and gets the 9 ports of ingress rule 1: 9333, 19333, 8444, 18444, 8888, 18888, 8333, 18333 and 23646. Reason: the egress of each source is then as narrow as the ingress of its destinations, in ports and in peers, so the rule holds under this controller and under the standard rule. The list removes TCP 33646 and TCP 9327 from the in-namespace egress. The live connections and the operator source use only ports of the list (proposal, Feasibility).
2. **The worker gets its own egress policy.** `object-store-worker` selects the pods with `app.kubernetes.io/name: seaweedfs` and `app.kubernetes.io/component: worker`, has the policy type `Egress` only, and lets them send to the pods with `app.kubernetes.io/name: seaweedfs` and `app.kubernetes.io/component: admin` on TCP 33646. Reason: the perimeter selects every pod of the namespace, so a rule to 33646 in it applies to every pod. The selectors are the selectors of ingress rule 2, so the two rules name the same pods.
3. **The rule reads the egress rules and fails closed.** A new helper `egress_senders` gives each pod of the model in namespace `object-store` that an egress rule lets send to a target pod on a TCP port, with the names of the policies. A rule with no `to` sends to every pod, an `ipBlock` peer reaches the pod, and `_port_matches` counts a rule with no `ports`, a port entry with no port and a named port as the port. `admin_port_problems` reports each sender that is not the worker, and a worker that `egress_blockers` stops. `egress_blockers` and `egress_senders` share one helper that finds the policies that select a pod for egress.
4. **The rule reads the policies of the store only.** The pods of other namespaces send by the egress rules of their own namespaces. Their in-namespace egress shape is the work of #6708.
5. **No separate rule for the metrics port.** The narrowed egress also stops the in-namespace path to TCP 9327. #6708 adds a row that refuses an in-namespace egress rule with no ports in a namespace whose ingress rules limit a port or a peer, and that row covers 9327 here.
6. **No Status History line in ADR 0034.** Its text says that the perimeter answers GHSA-3qr2-qw48-cj6q and that only the worker reaches the admin gRPC port. That is true after the merge. `docs/adr/README.md` adds a line only when a pull request makes a fact of a record wrong.
7. **Spec delta.** One MODIFIED requirement in `object-store`: "Only the worker reaches the admin gRPC port" gets the egress side and three scenarios of the new fixture checks.

## Rejected alternatives
- **An egress rule for each pair of components.** Rejected: the 14 live pairs and the on-demand data paths need about 10 rules, and each new path of a SeaweedFS release needs a new rule. The ingress rule already names the ports of the namespace in one list, and the issue asks for the same list on the egress side.
- **An exception for 33646 in the in-namespace egress rule.** Rejected: a NetworkPolicy rule only allows traffic. It has no deny and no `except` for a pod selector, so the rule must list the ports that it allows.
- **An open policy analyzer in the `k8s` row.** Rejected: `netpol-analyzer` and Cyclonus apply the standard rule, so they find no problem in the old perimeter (proposal, Existing Tool Considered).
- **A change to the network policy controller.** Rejected for this item: the controller is part of k3s and is not in this repository. #6708 reports the behavior upstream.
