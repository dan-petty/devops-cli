# Design

## Decisions

- **A block that no close ends ends at the job blocks at its end.**: A fenced code block or an HTML block of kinds 1 to 5 with no close runs to the end of the body. GitHub then shows each later line as code, the job blocks too. So such a block is open by accident. The jobs write their blocks at the end of the body. So the block ends for a read at the first line from which the lines that CommonMark reads on their own as job block markers are whole blocks of the jobs. Before #6720, the plain text search replaced the old block in place. The read of #6627 leaves two start markers (Feasibility).
- **A job has one block at most at the end of the open block.**: A person can quote a block of a job in the open block above the real block. The real block is the last one, so the quote stays in the open block. A job whose start marker a read finds before the open block has no block in it. So no write replaces a quote of a person. The review of the first head (`4bb03ab41`) found that its rule, the first marker line, took such a quote as the block, and that the write lost a line of the person.
- **A lone marker line in an open block is a quote.**: A start marker with no end marker after it, or an end marker with no start marker, is no block. The write then closes the open block at the end of the body and adds its block, as on the base. The alternatives check does not stop. The first head stopped it, and its refine write made the quoted marker a live bound.
- **The end marker of a section ends a block that a person opens in the section.**: The start marker comes before the open block, so the end marker is the first line of the job blocks. The section then holds the close, and refine reads a section that a person changed.
- **The blocks of all jobs count, not only the block of the reader.**: Each reader must see the same blocks. With only its own markers, the alternatives write would close the fence after a refine section that comes first. That section would then be a quote in a closed fence, and refine would write a second one.
- **The parser tells whether a block is open.**: `_open_block` parses the last block with the probe marker after a blank line, as `close_open_block` does. When the probe is part of that block, the block is open. A rule of our own for the end of each block kind would copy CommonMark.
- **A body has at most one part more than there are job block markers.**: Each new part starts at a marker that bounds a block. That marker ends no other open block. One job can end two open blocks. Its start marker ends a block above its block, and its end marker ends a block in its block. So a reader parses the body at most five times, not once for each open block. The review of the second head found a defect in a cap of one part for each job. That cap lost the last marker of a body with three open blocks. On a body of 65536 characters with 1598 marker lines in an open fence, `block_marker_spans` took 10.76 s with the rule of the first head. It took 0.12 s with this rule and 0.01 s on the base. On a body of 64982 characters with three open blocks, it took 0.09 s. The parse of each marker line is the rest of the time.
- **`extract_section_and_outside` cuts the body with the closes in place (`close_blocks_before_markers`).**: The refine write and the repair pass keep the outside text. So they write the close before the job block and keep the next block readable. A body with no open block above a marker does not change, so no recorded hash changes.
- **A marker that ends a declaration bounds a block.**: CommonMark ends a declaration such as `<!DOCTYPE` at the first line that holds `>`. A marker line holds `>`, so it ends a declaration that a person leaves open above it. `block_marker_of` reads the end text of each kind of HTML block from `_HTML_BLOCK_CLOSES`, the table that `close_open_block` uses. So one table holds the end of each kind, and no reader tests a comment on its own. The base read such a marker as text, so a read did not find the block. The 836 open issues of 2026-11-22 hold no line that starts with `<!` and a letter. So no read of a live item changes.
- **`block_marker_of` is the one token test.**: `_marker_span` and `_ends_section` both call it, so a comment that a person leaves open above a job block ends a section too.
- **`body_dependencies` parses the body with the closes in place.**: It reads the Dependencies part of the refine section, so it must find that section where the other readers find it.
- **A marker in a block that a close ends stays a quote.**: A person who quotes a job block in code closes the fence. The tests of #6627 for a quoted pair stay green.
- **The body parser of `body_hash` reads only the blocks (`disable("inline")`).**: The rule reads only `html_block` and `fence` tokens, as the record parser of `src/devops_cli/roadmap/stores/store.py` does. The probe of an open block adds a parse, and the parse without inline rules costs about half the time.
- **`CONST_ROADMAP_REFINE_RULES_SINCE` does not move.**: The change can change the blockers that `body_dependencies` reads, and `docs/roadmap/refine.md` asks for a later time for such a change. A later time gives each item that waits on a person one more model round. A scratch run read the 836 open issues of 2026-11-22 with the base and with this change, with and without the record block. It found no difference in any read: the blocks, the hashes, the text of a person, the blockers, the questions and the writes. So no item gets another next step, and a new round would cost model calls for no change.
- **A whole block of a job that a person quotes at the end of an open block reads as the block of the job.**: The body cannot tell it from a block of the job that a person opened a block above. The record block cannot tell either: the open block hides it from `split_record`, and a read that finds it takes it out of the body. Refine finds a section that it has no record of and waits for a person, so it writes nothing. The alternatives check replaces the block. The census of the review found no open issue with a job block marker line that is not a bound.
- **The refine round test of a block above the section asserts the wait for a person.**: The record block is the last block of the body, so the open block of a person holds it too, and `split_record` then reads no record. Refine then finds a section that it has no record of, and waits for a person. So the test asserts no model call and no write in each round, and it fails when a round reads the record. A run with a `with_record` that closes the open block only at the end of the body gave two sections. A run with a `with_record` that first calls `close_blocks_before_markers` gave one. The record is the work of #6729, and this change does not touch `src/devops_cli/roadmap/stores/store.py`. Until then, the unit tests of `tests/roadmap/test_roadmap_body_hash.py` and a refine write above the block of another job prove the cut.
- **This decision replaces the rejected alternative "Close the open block before the first marker line in it" of #6627, for a block that no close ends.**: #6736 expects one block after each write. A block in a closed fence is still a quote.

## Rejected alternatives

- **Read a marker in an open block as an unpaired marker and write no block (option b of the review of PR #6720).**: Refine has no such stop. The item then gets no result from a job until a person closes the block.
- **Read each whole-line marker in any code block or HTML block as a bound.**: A quoted pair in a closed fence would then lose its text. `test_a_marker_in_a_code_span_a_code_block_or_a_paragraph_is_no_block` forbids it.
- **Keep the close at the end of the outside text.**: The premise script shows two start markers after each round.
- **Close the open block only in each writer, and keep `extract_section_and_outside` a plain cut.**: Each writer must then repeat the call. The repair pass would write an alternatives block back into the open block.
- **Use the recorded section hash to accept a marker in an open block.**: The alternatives job records no hash of its block, and the readers take no item.
- **End the open block at its first job block marker line (the first head).**: A quote of a person in the open block then became a block. A write replaced the quote, or made a lone quoted marker a live bound. Each reader also parsed the rest of the body again for each open block.
- **Ask for the record block after the job blocks.**: It tells a quote from a block only while `split_record` cannot read a record in an open block. When a read finds that record, it takes it out of the body, and the rule then stops.
