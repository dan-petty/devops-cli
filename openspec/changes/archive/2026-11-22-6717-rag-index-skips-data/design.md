# Design

## Decisions
1. **The working tree's `.gitattributes` decide, and only `linguist-vendored` leaves a file out.** `collect_files` walks the directory as before, then asks git once for the attribute `linguist-vendored` of all the files that it kept. A file with the value `set` or `true` is left out. `-linguist-vendored` (`unset`) and `linguist-vendored=false` keep a file. A file marked `linguist-generated` stays. Reason: `set` and `true` are the values that GitHub Linguist reads as true, and the project review already reads them so (`src/devops_cli/roadmap/project_review/git_read.py`). A vendored file is the data of a third party. A generated file of this repository is tool output, but the command reference (`docs/commands/*.md`, `docs/CLI_REFERENCE.md`) is one of the most useful documents for a search, and `_is_lockfile` already leaves out the lock files by name.
2. **One git call for a walk.** `paths_with_attributes(repo_dir, paths, attributes)` in `src/devops_cli/git/operations.py` sends the paths on standard input to `git -C <repo_dir> check-attr -z --stdin <attributes>`, through `run_subprocess` as a local read. The paths are relative to the root of the walk, and `-C` makes git resolve them from there. A path with a space or a newline stays whole in the `-z` form. A git that exits with a status other than 0 raises `GitOperationError`, so a broken repository stops the run and does not index files that it should leave out. Reason: a per-file call costs one process start per file, and the indexer reads 12636 files of this repository.
3. **No attributes outside a work tree.** `collect_files` asks git for attributes only when `git_show_toplevel` finds a work tree that holds the root. Reason: git exits 128 outside a work tree, and a directory with no repository has no `.gitattributes` that git reads. The knowledge base of an installed package is such a directory.
4. **Sort a failed batch by the HTTP status of the reply.** `EmbeddingsError` gets `status`. `_reply_vectors` sets it from the reply. `_embedding_error` keeps it when each endpoint that was asked gave the same status, and else sets None. `is_input_refused_error` accepts the statuses 400, 413 and 422 (`http.HTTPStatus`). Reason: the error text of a gateway or a node is not a contract, and the status is. A reply with one of these statuses refuses the input of one request, such as a text that is too long, and a request with other texts can succeed.
5. **Retry a transient failure once.** The upsert loop calls `embed_texts` through `tenacity.Retrying` with `stop_after_attempt(_BATCH_ATTEMPTS)` (2), `retry_if_exception(_is_retryable)` (a transient error that is not a refused input), `wait_exponential_jitter(initial=_BATCH_RETRY_WAIT_SECONDS, max=_BATCH_RETRY_MAX_WAIT_SECONDS)` (10 s and 60 s) and `sleep=clock.sleep`. Reason: the second attempt splits the batch at the size that the AIMD rule lowered after the timeout. The embedder already tries each HTTP request 3 times with a batch timeout of up to 120 s, so one batch attempt can take 6 min. Two attempts bound one failed batch to about 12 min.
6. **Skip, record, and fail at the end.** A batch that fails both attempts with a transient error is skipped. A batch whose reply refuses its input is skipped after one attempt, because a new attempt sends the same texts and gets the same reply. Its files go into a list of the run, and each of them is marked `CONST_RAG_INCOMPLETE_FILE_MARKER` in the index cache, so the next run without `--force` embeds the file again. The loop goes on with the next batch, and the docs collection after the code collection, until the run stops (decision 10). After the cache and the counts are saved, `index_workspace` raises `EmbeddingsError` with `exit_code=CONST_EXIT_FAILURE`, the first error, the count of files and the sorted list of files. `details` holds `skipped_files` and `first_error`. Reason: drift and the ingest pass record a synced state only when `index_workspace` returns, so they record none for an index with gaps. The CLI already prints an `EmbeddingsError` and exits with its status.
7. **A permanent error ends the run at once.** Any other error raises the existing `batch_failed` error at once, with no retry: a refused key (401, 403), an unserved model (404) or a malformed reply. Reason: no later batch can succeed after such an error, and the investigator turns RAG off for the run on the same rule.
8. **A second refused batch before an embedded batch ends the run.** The LiteLLM proxy of the gateway answers a model name that no deployment serves with HTTP 400 (`ProxyModelNotFoundError`), and its body holds only message text. So one 400 cannot tell a bad input from an unknown model. The run counts the batches that got vectors and the refused batches. A refused batch after an embedded batch is skipped. The first refused batch of a run is skipped too. A second refused batch while no batch got vectors raises the `batch_failed` error. Reason: two refused inputs and no accepted one point to the model, not to the input. An unknown model then costs two fast requests, not one request for each batch of the workspace.
9. **Mark the tiktoken fixtures vendored.** `.gitattributes` gets `tests/fixtures/tiktoken/*.tiktoken linguist-vendored`. Reason: they are the vocabularies of tiktoken, and nobody edits them.
10. **Stop the run when the endpoint is not available.** A pybreaker `CircuitBreaker` of each run (`fail_max=_FAILED_BATCHES_IN_A_ROW`, 3) wraps the two attempts of a batch. It counts a batch that fails both attempts with a transient error. Its `exclude` takes a refused input as an answer, which sets the count back to 0, as a batch with vectors does. The run stops when the breaker opens, or when such a batch comes before any batch of the run got vectors. It marks the batch incomplete, and raises `EmbeddingsError` with `ERRORS.rag.endpoint_down`, exit status 1, the last error and the files of the skipped batches. It sends no request for the later batches. Reason: an endpoint that is down or hangs fails each later batch. With no stop, each batch gets its retry and its wait. The 324 batches of this repository then wait more than 55 min, and the ingest pass goes on to the next repository. One failed batch can take about 12 min, so 3 batches in a row bound an outage in a run to about 36 min. The investigator pauses lookups after the same count of transient failures (`CONST_RAG_CIRCUIT_BREAKER_FAILURES`).

## Rejected alternatives
- **A check-attr call for each file in `_is_indexable_file`.** Rejected: `is_ignored_by_git` moved off a per-file `git check-ignore` because the process start cost 39.5 ms for each tracked file (`src/devops_cli/core/repo.py`). The same cost applies to `check-attr`.
- **Reuse `generated_paths` of the project review.** Rejected: it reads the attributes of a commit (`--source=<head>`) and only `linguist-generated`, through the git runner of the review, which its dry run lists. The indexer reads the working tree.
- **Leave out `linguist-generated` files too.** Rejected: the issue aim is a full index of the repository without data that has no meaning for a search. The generated command reference is one of the most useful documents for RAG. The lock files are already left out by name. `tests/module_durations.json` is small.
- **Sort a failed batch by the text of the error.** Rejected: the text of a gateway or a node can change in any release, and the status is part of the HTTP contract.
- **Skip each batch whose reply is HTTP 400.** Rejected: with an unknown model behind the LiteLLM proxy, the run sends one request for each batch of the workspace, and each one fails.
- **Embed a probe text before the first batch.** Rejected: the embedder cache can answer the probe with no request, so it does not prove that the endpoint serves the model now, and each run sends one more request.
- **No batch-level retry, because the embedder retries each request.** Rejected: the request retry sends the same sub-batch again within seconds, while a new batch attempt splits the texts at the size that the AIMD rule lowered.
- **Three batch attempts.** Rejected: with the request retries, one failed batch could hold the run for about 18 min.
- **Skip a batch after a permanent error too.** Rejected: an unserved model then sends one request for each batch of the workspace (about 1300 for 41385 chunks), and each one fails.
- **The pybreaker circuit breaker in place of the retry.** Rejected: a breaker stops calls after failures, and does not try a batch again. The issue asks for a retry, then a skip. The run uses the breaker only to stop after failed batches in a row (decision 10).
- **Stop at the first transient skip.** Rejected: one batch that times out, such as the tiktoken batch of #6717, then stops the run before the docs phase again.
- **Count all the transient skips of a run, not the skips in a row.** Rejected: a long run with a few failures far apart then stops, while the endpoint answers the batches between them.
- **Return the skipped files in the result instead of an error.** Rejected: drift and the ingest pass would record a synced state for an index with gaps, and the MCP tool and the CLI would report success.
