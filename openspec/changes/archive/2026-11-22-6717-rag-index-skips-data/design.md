# Design

## Decisions
1. **The working tree's `.gitattributes` decide.** `collect_files` walks the directory as before, then asks git once for the attributes `linguist-generated` and `linguist-vendored` of all the files that it kept. A file with the value `set` or `true` for one of them is left out. `-linguist-generated` (`unset`) and `linguist-generated=false` keep a file. Reason: these are the values that GitHub Linguist reads as true, and the project review already reads `set` and `true` as generated (`src/devops_cli/roadmap/project_review/git_read.py`).
2. **One git call for a walk.** `paths_with_attributes(repo_dir, paths, attributes)` in `src/devops_cli/git/operations.py` sends the paths on standard input to `git -C <repo_dir> check-attr -z --stdin <attributes>`, through `run_subprocess` as a local read. The paths are relative to the root of the walk, and `-C` makes git resolve them from there. A path with a space or a newline stays whole in the `-z` form. A git that exits with a status other than 0 raises `GitOperationError`, so a broken repository stops the run and does not index files that it should leave out. Reason: a per-file call costs one process start per file, and the indexer reads 12636 files of this repository.
3. **No attributes outside a work tree.** `collect_files` asks git for attributes only when `git_show_toplevel` finds a work tree that holds the root. Reason: git exits 128 outside a work tree, and a directory with no repository has no `.gitattributes` that git reads. The knowledge base of an installed package is such a directory.
4. **Retry a transient failure once.** The upsert loop calls `embed_texts` through `tenacity.Retrying` with `stop_after_attempt(_BATCH_ATTEMPTS)` (2), `retry_if_exception(is_transient_embedding_error)`, `wait_exponential_jitter(initial=_BATCH_RETRY_WAIT_SECONDS, max=_BATCH_RETRY_MAX_WAIT_SECONDS)` (10 s and 60 s) and `sleep=clock.sleep`. Reason: the second attempt splits the batch at the size that the AIMD rule lowered after the timeout. The embedder already tries each HTTP request 3 times with a batch timeout of up to 120 s, so one batch attempt can take 6 min. Two attempts bound one failed batch to about 12 min.
5. **Skip, record, and fail at the end.** A batch that fails both attempts is skipped. Its files go into a list of the run, and each of them is marked `CONST_RAG_INCOMPLETE_FILE_MARKER` in the index cache, so the next run without `--force` embeds the file again. The loop goes on with the next batch, and the docs collection after the code collection. After the cache and the counts are saved, `index_workspace` raises `EmbeddingsError` with `exit_code=CONST_EXIT_FAILURE`, the first error, the count of files and the sorted list of files. `details` holds `skipped_files` and `first_error`. Reason: drift and the ingest pass record a synced state only when `index_workspace` returns, so they record none for an index with gaps. The CLI already prints an `EmbeddingsError` and exits with its status.
6. **A permanent error ends the run at once.** An error that `is_transient_embedding_error` does not accept raises the existing `batch_failed` error at once, with no retry. Reason: the embedder marks an unknown or unserved model, a refused request (4xx other than 408 and 429) and a malformed reply as permanent. No later batch can succeed after such an error, and the investigator turns RAG off for the run on the same rule.
7. **Mark the tiktoken fixtures vendored.** `.gitattributes` gets `tests/fixtures/tiktoken/*.tiktoken linguist-vendored`. Reason: they are the vocabularies of tiktoken, and nobody edits them.

## Rejected alternatives
- **A check-attr call for each file in `_is_indexable_file`.** Rejected: `is_ignored_by_git` moved off a per-file `git check-ignore` because the process start cost 39.5 ms for each tracked file (`src/devops_cli/core/repo.py`). The same cost applies to `check-attr`.
- **Reuse `generated_paths` of the project review.** Rejected: it reads the attributes of a commit (`--source=<head>`) and only `linguist-generated`, through the git runner of the review, which its dry run lists. The indexer reads the working tree.
- **Leave out only `linguist-vendored` files.** Rejected: the issue asks for both attributes, and the `linguist-generated` files of this repository are tool output: the command pages repeat the help text that the code collection holds, and `tests/module_durations.json` is data.
- **No batch-level retry, because the embedder retries each request.** Rejected: the request retry sends the same sub-batch again within seconds, while a new batch attempt splits the texts at the size that the AIMD rule lowered.
- **Three batch attempts.** Rejected: with the request retries, one failed batch could hold the run for about 18 min.
- **Skip a batch after a permanent error too.** Rejected: an unserved model then sends one request for each batch of the workspace (about 1300 for 41385 chunks), and each one fails.
- **The pybreaker circuit breaker of the investigator.** Rejected: a breaker stops calls after failures, and does not try a batch again. The issue asks for a retry, then a skip.
- **Return the skipped files in the result instead of an error.** Rejected: drift and the ingest pass would record a synced state for an index with gaps, and the MCP tool and the CLI would report success.
