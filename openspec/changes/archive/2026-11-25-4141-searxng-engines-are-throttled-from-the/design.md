# Design

## Decisions

- **Remove stackoverflow, askubuntu and superuser from keep_only and keep the six other engines.**: The log of 2026-11-08 records the three suspended for too many requests and answering HTTP 400 from api.stackexchange.com with no key in the request, so a query spends one request on each of them. The issue states that the cause of the 400 is not proven, and this decision names none.
- **Keep duckduckgo in the settings and leave its removal to the measure under #4201.**: The issue puts the removal of duckduckgo after the measure, because the chain already has the ddgs provider, which sends the same request from the same egress address. The log of 2026-11-08 records the 1 hit of the general row while duckduckgo answered a CAPTCHA, so the log names no engine for that hit, and this plan claims none. `docs/CLUSTER.md:260:A request that names no category asks only the` names duckduckgo and wikipedia as the two general engines that the settings keep.
- **Add the three names to OFF_ENGINES so devops k8s searxng-check fails a reply that names one.**: The check fails today on a reply that names the three and passes after the settings rollout, so the change delivers a command that fails today, and its offline cases prove the refusal with no cluster.
- **Prove the engine set with a behavior test over the OFF_ENGINES constant and with the live check, and add no test that reads the ConfigMap.**: `docs/TESTING.md:61:A test checks the source code of the project.` refuses a test that asserts a value of a config file, and `tests/invariants/test_k8s_searxng.py:5:No test asserts a value of the manifests (#6060).` states the same rule.
- **Map the acceptance criterion that names the ConfigMap test and the general run to group 2, and keep the failing test in group 1.**: Group 1 makes `tests/k8s/test_searxng_check.py` fail on the base, and group 2 changes keep_only, the data that the criterion names, and ends with the live `uv run devops k8s searxng-check` run of the json-general row, whose failure on a reply with no hit is the work of `src/devops_cli/k8s/searxng_check.py:def reply_problems`.
- **Record the engine list in docs/CLUSTER.md and not in k8s/README.md.**: The engine bullet is `docs/CLUSTER.md:260:keeps nine engines that need no key`, and `k8s/README.md` holds no engine list. The open pull request #6555 changes `k8s/README.md`, and this change edits none of that file.
- **Modify the base requirement `The settings keep only keyless engines` of `openspec/specs/searxng-service/spec.md` in the spec delta of this change.**: A task group never writes `openspec/specs/`, and `openspec archive` writes the living spec from the delta. The requirement names the nine engines today, so an unmodified requirement would contradict the six-engine ConfigMap after the archive.
- **Modify the requirement `Engines that stay off` of `k8s-searxng-check` together with the tuple.**: `read_spec` returned that requirement with the seven names, so an unmodified requirement would contradict the ten-name tuple in the living spec after the archive.
- **Leave `tests/fixtures/searxng/search_reply.json` unchanged.**: It is a saved reply of the pinned image that the provider tests read, and it names the three engines only as unresponsive engines of a reply of 2026-11-08. No code compares it with OFF_ENGINES, and the command tests fake their own replies.
- **Name the one file of group 2 in a plain code span of its task text, and list only the files that its steps edit.**: A group whose task text names no file of the staged commit packs nothing for its step. `k8s/devops/searxng/configmap.yaml` is the one file that group 2 edits, and `tests/commands/k8s/test_k8s_devops_stack.py` is not in its changes, because no step of the group edits it.
- **Keep one attempt for each provider in the search chain and add no retry, no wait and no rate limit.**: #4094 decided against a retry, and `src/devops_cli/ai/web_search.py:5:passes the search on at once, with no retry and no wait` states that a failed provider passes the search on at once. This change touches no provider and adds no wait.
- **Add no Stack Exchange API key and no per-engine suspension value.**: The key is a Secret that a person creates, and `k8s/devops/searxng/configmap.yaml:3:The file keeps only the engines that need no key.` shows that the settings hold no engine key. The suspension waits on the measure under #4201.
- **Read the existing metric devops_cli_web_searches_total for the measure and add no instrument.**: `src/devops_cli/telemetry/instruments.py:258:WEB_SEARCHES_TOTAL = Instrument(` already counts each attempt by its backend and its result, so this change adds no metric and no label.
- **Map the four Covers items and the four Lacks items of the alternatives block to a group or to a person.**: The check reads each top-level item of the issue as an acceptance criterion. The three items about the engine set and the keyless path are delivered by group 2, which edits `k8s/devops/searxng/configmap.yaml`, and the five items about the measure, the suspension, the engine key and the egress flag need the 3-day measure, a person's Secret or a query from another address, which #4201 holds.

## Rejected alternatives

- **Keep the three Stack Exchange engines and add a Stack Exchange API key.**: The key is a Secret that a person creates, and `k8s/devops/searxng/configmap.yaml:3:The file keeps only the engines that need no key.` shows that the settings file holds none, so the change would wait on a person while the three keep answering 400.
- **Keep the three Stack Exchange engines unchanged.**: The log of 2026-11-08 records the three suspended for too many requests and answering HTTP 400 from api.stackexchange.com with no key, so a query spends one request on each. The plan names no cause for the 400 and does not claim that the three never answer.
- **Remove duckduckgo from the settings as well.**: The issue puts that removal after the measure, in step 2 and option 1 of step 3, because the ddgs provider sends the same DuckDuckGo request from the same egress address, so a removal moves the load and does not cut it. The log of 2026-11-08 records the 1 hit of the general row while duckduckgo answered a CAPTCHA, so the log does not show what the removal would cost.
- **Set a suspension time for the duckduckgo CAPTCHA in the settings.**: The issue records `suspended_time=0` for the duckduckgo CAPTCHA, so a suspension value does not apply to it today, and the issue says the effect must be checked against the pinned image. The measure under #4201 holds it.
- **Add a second key-free general engine so the general row answers without duckduckgo.**: No input shows that the pinned image ships a key-free general engine that answers from the cluster address, so the plan adds no name it cannot verify.
- **Extend `tests/invariants/test_k8s_searxng.py` with a test over the rendered ConfigMap and its engine list, as the refine block chose.**: `docs/TESTING.md:61:A test checks the source code of the project.` refuses a test that asserts a value of a config file, and `tests/invariants/test_k8s_searxng.py:5:No test asserts a value of the manifests (#6060).` states the same rule.
- **Prove the engine set with `uv run devops k8s searxng-check` alone.**: It needs a checkout, a client of the Kubernetes API and a network, and the runner pod holds no Kubernetes token, so the offline cases of the check are what the runner proves.
- **Add a retry with a backoff to the provider chain.**: #4094 decided against it, and `src/devops_cli/ai/web_search.py:5:passes the search on at once, with no retry and no wait` states that a failed provider passes the search on with no retry and no wait, so a retry would add a second attempt and hide the throttle.
- **Name the HTTP 400 of api.stackexchange.com as a proven cause of the throttle.**: The issue states "The reply body is not in the log, so the cause of the 400 is not proven.", so the plan removes the three for the recorded 400 and the suspension and names no cause.
- **Attribute the 1 hit of the general row on 2026-11-08 to duckduckgo.**: The issue records that run as "got 1 hit for the plain `general` category while DuckDuckGo was CAPTCHA-blocked", so duckduckgo gave no hit of that row and the log names no engine for it.

## Unchanged references

- `openspec/specs/searxng-service/spec.md` (spec requirement): The spec delta of this change replaces the requirement `The settings keep only keyless engines`, and `openspec archive` writes the living spec; no task group edits the file.
- `tests/fixtures/searxng/search_reply.json` (saved live reply): It is a saved reply of the pinned image that the provider tests read, and it names the three engines only as unresponsive engines of a reply of 2026-11-08; no code compares it with OFF_ENGINES.
- `openspec/changes/archive/2026-11-08-3929-searxng-check-command/tasks.md` (archived change record): It is the record of a merged change under `openspec/changes/archive/`, and the archive keeps the text of the plan that it delivered.

## Security

The change edits the `searxng-settings` ConfigMap under `k8s/`, so it crosses the cluster trust boundary at the pod's egress: the `searxng` pod keeps its NetworkPolicy and stops reaching api.stackexchange.com, and the settings file keeps no key. A person must confirm that the pod still reaches public TCP 443 only, that no Stack Exchange API key enters the ConfigMap, and that the rollout of the ConfigMap reaches the pod before the live check runs. `uv run devops ci --check --only k8s` fails if the ConfigMap stops rendering, `uv run devops ci test tests/k8s/test_searxng_check.py` fails if a Stack Exchange name leaves the tuple, and `uv run devops k8s searxng-check` fails if an engine that must stay off appears in a reply.
