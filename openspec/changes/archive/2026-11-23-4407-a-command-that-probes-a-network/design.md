# Design

## Decisions

- **Keep the retry loop in `probe_http_from_pod`, beside the pod lifecycle.**: The pod must stay alive across the attempts, and `src/devops_cli/k8s/service_probe.py:267:def probe_from_pod(` already starts, probes and deletes one pod, so the loop reuses `_start_pod`, `_delete_pod` and the clock seam instead of a second pod path.
- **Retry while the pod's curl exits 7 and end the retry at the `--wait` deadline with `PodHttpResult(curl_exit=7)`; the `--timeout` deadline is a separate bound that raises a timeout.**: The Done-when section of the issue needs a blocked result from a label that the policy drops, so the retry ends at `--wait` with the exit code and exit 0, and `--timeout` stays the bound for a probe that never answers; `src/devops_cli/k8s/service_probe.py:65:_KUBECTL_TIMEOUT_SECONDS = 30` bounds each kubectl call, so the retry sleeps `DEFAULT_PROBE_RETRY_SECONDS` between attempts and stays inside it.
- **Make `image` a required keyword argument of `_pod_overrides`, `_run_argv` and `_start_pod`, so `probe_from_pod` passes `PROBE_IMAGE` and `probe_http_from_pod` passes `CURL_IMAGE`.**: A default of `PROBE_IMAGE` would leave the probe pod on busybox, which has no curl, so each caller names its image; `src/devops_cli/k8s/service_probe.py:124:def _pod_overrides(name: str) -> dict[str, object]:` has no caller outside its module, so the two service checks keep the busybox pod.
- **Read the digest of the curl tag once with `tag_digest` and write it into `CURL_IMAGE`.**: The pinned image needs a digest, and `src/devops_cli/docker/registry.py:102:def tag_digest(reference: str, client: httpx2.Client, *, timeout: float) -> str:` is the project's reader of a tag digest; a guessed digest would fail the live check.
- **Render the request plan and stop with `--dry-run`, and give each exec of that plan its curl command line, the URL and a placeholder for the headers.**: The operator sees the exact pod and request, nothing touches the cluster, and the command matches the dry run of `src/devops_cli/commands/k8s/searxng_check.py:100:@dry_run_class("request-plan")`, whose plan comes from the module beside it.
- **Write the header values as curl config lines to the standard input of the exec call.**: The value stays out of every argv and out of the output, and `src/devops_cli/core/process.py:1040:input: str | None = None` with `tests/support/fakes/process.py:39:stdin: str | bytes | None = None` lets a test assert it.
- **Print `status=<code>` or `curl_exit=<code>` and exit 0 on a measurement.**: A blocked path is a valid result of a policy check, so a script reads the printed value, and a non-zero exit stays for a command that did not measure.
- **Give the wait, timeout and retry bounds the new names `DEFAULT_PROBE_WAIT_SECONDS` (20), `DEFAULT_PROBE_TIMEOUT_SECONDS` (60) and `DEFAULT_PROBE_RETRY_SECONDS` (2), and let curl take the staged `DEFAULT_PROBE_CONNECT_SECONDS` of 3 for its connect and total bounds.**: The staged tree already defines that bound at `src/devops_cli/config/defaults.py:714:DEFAULT_PROBE_CONNECT_SECONDS: int = 3`, so no new name is given to it; the three other bounds are new and get one name each.
- **Put the command test at `tests/commands/k8s/test_k8s_probe.py`.**: The command module sits in `src/devops_cli/commands/k8s/`, and that folder holds `tests/commands/k8s/test_k8s_searxng_check.py:145:def _check(cli: Callable[..., Any], *args: str) -> Any:`, so the test mirrors the package of the code it tests.

## Rejected alternatives

- **A fixed sleep of 20 seconds before the request.**: It wastes the 20 seconds when the path is ready at once and fails when programming takes longer, while `src/devops_cli/k8s/service_probe.py:194:def _connects(name: str, namespace: str, target: PodTarget, context: str | None) -> bool:` already parses the remote exit code, so the retry costs one loop.
- **curl --retry-connrefused inside one exec call.**: `src/devops_cli/k8s/service_probe.py:65:_KUBECTL_TIMEOUT_SECONDS = 30` bounds each kubectl call, so one exec could not outlast the 20 second wait, and it could not report the attempts.
- **A new pod for each attempt.**: `src/devops_cli/k8s/service_probe.py:267:def probe_from_pod(` starts the pod once and execs each target into it, and a pod per attempt would spend one `kubectl run` and one delete per try.
- **A default of `PROBE_IMAGE` for the image of the probe pod.**: `src/devops_cli/k8s/service_probe.py:62:PROBE_IMAGE = (` names busybox, which has no curl, so a default would leave the probe pod unable to give a status or an exit code; a required argument makes each caller name its image.
- **busybox with nc, the current `PROBE_IMAGE`.**: `src/devops_cli/k8s/service_probe.py:62:PROBE_IMAGE = (` names busybox, whose nc applet exits 0 or 1 with no HTTP status, so a blocked path and a refused connection give the same result.
- **registry.k8s.io/e2e-test-images/agnhost.**: It reports reachability only, while the probe must tell a status such as 401 from curl exit 7, and `src/devops_cli/k8s/service_probe.py:124:def _pod_overrides(name: str) -> dict[str, object]:` carries one image.
- **The devops-cli image as the probe image.**: A pod start waits `src/devops_cli/config/defaults.py:713:DEFAULT_PROBE_POD_START_SECONDS: int = 120`, and the image of the whole CLI spends that budget on a pull of tools that the probe does not use.
- **Create the pod and skip the request with `--dry-run`.**: `src/devops_cli/k8s/service_probe.py:306:def plan_probe_from_pod(` renders the pod call with no cluster call, and a created pod would stay behind for a check that must be safe.
- **Put the header value in the exec argv.**: The value would show in the process list of the pod and in the kubectl call, and `src/devops_cli/k8s/service_probe.py:124:def _pod_overrides(name: str) -> dict[str, object]:` shows that the pod spec travels in the `--overrides` argv; `openspec/specs/k8s-crawl4ai-check/spec.md` forbids a token on a command line.
- **Pass the header value as an environment variable of the pod.**: `src/devops_cli/k8s/service_probe.py:124:def _pod_overrides(name: str) -> dict[str, object]:` shows that the pod spec travels in the `--overrides` argv of `kubectl run`, so the value would land in an argv and in the pod object.
- **Exit non-zero on a blocked path.**: A blocked path is a measurement and not a fault: the caller reads `curl_exit=7`, and `src/devops_cli/commands/k8s/searxng_check.py:def k8s_searxng_check` raises for a failed check only.

## Security

The probe pod carries the label of a workload, so the cluster's network policy admits it, and a header value crosses from the operator into the pod. The value travels on the standard input of the exec call, never in an argv, a pod object or the output. A person confirms the namespace, the label, the URL and that `--image` names a digest before the command runs against a cluster. `tests/commands/k8s/test_k8s_probe.py` fails if a header value reaches an argv or the output, and `tests/k8s/test_service_probe.py` fails if the pod spec loses a field of the restricted level.
