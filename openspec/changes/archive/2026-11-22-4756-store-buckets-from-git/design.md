# Design

## Decisions

- **Scope of the item.** This change makes the four platform buckets of the devops-cli workloads, with their quotas, their anonymous read and their lifecycle rules. The tenant backup buckets (`backups-*`), the writer identities and keys, and the read-only identity `cloud-backup` come from the tenant chart of `dan-petty/infra#14`, which is a separate issue: one generic CR form for each tenant namespace, with a key pair from an ESO `Password` generator. The 90-day rule for the version-review HTML waits for #4733 to name its bucket and prefix: a rule on a guessed prefix expires nothing, or other objects.
- **Scope and namespace of each CR.** Every CRD of the operator is Namespaced. The coordinator decision of 2026-11-22 (least privilege) in #4756 puts the four platform buckets and their lifecycle policies in namespace `object-store`, beside the `Seaweed` CR, and keeps the operator on that one namespace:

  | Kind | Count | Namespace | Why |
  | :--- | :--- | :--- | :--- |
  | `Bucket` `reports`, `reports-private`, `cache`, `argo-artifacts` | 4 | `object-store` | The namespace of the `Seaweed` CR and the only namespace that the operator watches |
  | `BucketLifecyclePolicy` | 4 | `object-store` | Its `bucketRef` names a `Bucket` of its own namespace, and it takes the cluster from that bucket |

- **Buckets.** Each `Bucket` sets `clusterRef` (`seaweedfs`, with no namespace, so the operator takes the namespace of the bucket), `quota.size` with `enforce: true`, and `reclaimPolicy: Retain`. `local-path` does not enforce the size of a claim, so the quotas are the limits. `seaweedRef` is the same reference under the name that the other CRDs use; the CRD requires exactly one of the two (`api/v1/bucket_types.go`), and the item names `clusterRef`.
- **No grant.** A reference in the same namespace needs no `ResourceReferenceGrant`: the operator always permits it (`referenceGrantPermits` in `internal/controller/referencegrant.go` at tag `seaweedfs-operator-0.1.48`). The render holds no grant, so no CR of another namespace can name the store.
- **Anonymous read.** `anonymousRead: true` only on `reports` and `reports-private`. The operator grants the reserved identity `anonymous` the action `Read` on the bucket in the IAM store of the filer (`internal/controller/swadmin/iam_client.go`, `SetBucketAccess`), which allows GET and not List. No `access` entry names `anonymous`. The S3 gateway adds the identities of the filer to its identities file of no identity (`weed/s3api/auth_credentials.go` at SeaweedFS 4.54), so it allows the anonymous GET of these two buckets and refuses an unsigned List, an unsigned ListBuckets and each other unsigned request. At each reconcile, the operator sets the actions of each identity that the CR grants, and revokes only the users of its annotation of applied grants (`readAppliedAccessAnnotation` in `internal/controller/bucket_controller.go` of operator 1.0.45). Thus a grant that a person adds, for example `Read` of `anonymous` on `cache`, stays until a person removes it.
- **Lifecycle.** One `BucketLifecyclePolicy` for each bucket, named as the bucket. Each has the rule `abort-incomplete-multipart` (`abortIncompleteMultipartUpload.daysAfterInitiation: 1`, no prefix). `reports-private` adds `studies` (prefix `studies/`, 90 days); `cache` and `argo-artifacts` add `expire` (7 days). No bucket named `backups-*` may have an expiration rule. The CRD has no expiration date: `expiration.days` has a minimum of 1.
- **Keys.** This change adds no `S3Identity`, `S3Policy`, `S3PolicyBinding` or `S3Credentials`, and no row to `CLUSTER_SECRETS`. The S3 gateway keeps its identities file with no identity, so it refuses each signed request until the tenant chart adds an identity; only the anonymous GET of the report buckets works.
- **Watch scope.** `watchNamespaces: [object-store]`, as #4750 set it. The operator reads its CRs only through the cache of the watched namespaces (`cmd/main.go`, `Cache.DefaultNamespaces`), and the chart renders its manager Role and binding in each watched namespace (`deploy/helm/templates/rbac/role.yaml`). That Role can create, read, change and delete the Secrets, ConfigMaps and Services of the namespace. With one watched namespace, the render of chart 0.1.48 has each Role and RoleBinding in `object-store`, and one ClusterRoleBinding to ClusterRole `seaweedfs-operator-manager-role`, which only reads namespaces and storage classes.
- **Kustomization.** `k8s/object-store/kustomization.yaml` keeps its `namespace: object-store` transformer and lists `buckets.yaml`, so each CR of the file gets the namespace of the store.
- **Argo CD.** Application `object-store` of #4750 applies the new file at sync-wave `0` after the operator, with automated sync, `prune`, `selfHeal`, 5 retries and `SkipDryRunOnMissingResource=true`. The project `homelab` already lists `object-store` as a destination, so the project needs no change. A changed CR goes back to git at the next sync, and the operator restores a changed quota, lifecycle rule or grant that it applied at its next reconcile. It does not remove a grant that a person adds, and it does not change a value that no CR sets, such as the versioning (`Off` is a no-op) or the owner (it removes an owner only when `status.ownerIdentity` is set).
- **Network.** No NetworkPolicy changes. The operator reaches the API server through `object-store-operator-egress`, and the filer gRPC port 18888 and the master gRPC port 19333 through `object-store-perimeter-egress` and `object-store-perimeter-ingress`. This change adds no S3 client, so no namespace gets the label `backup-client: "true"`.
- **Checks.** `tests/gate/k8s_checks/object_store_buckets.py` reads the shared render of `k8s/object-store`. Each rule is a function that returns its problems; one check applies it to the committed render, and one applies it to a fixture that breaks the rule and asserts that the problem names the object, as `object_store.py` does. The bucket rule checks each `Bucket` CR and refuses two CRs with the same bucket name, so a second CR with `reclaimPolicy: Delete` cannot hide behind the committed one. The watch rule holds `watchNamespaces` to `[object-store]`, and the kind rule refuses a `ResourceReferenceGrant` and an object outside `object-store`. A unit test of `tests/k8s/test_cluster_secret_plan.py` holds the table to no row of a store key.

## Rejected alternatives

- **Each bucket in the namespace of its writer (`devops`, `argo-workflows`), with a `ResourceReferenceGrant` in `object-store`.** The first plan of this change and the refined design of #4756 chose it. The coordinator decision of 2026-11-22 replaced it: operator 1.0.45 sees a Bucket only in a namespace that it watches, and the chart gives each watched namespace the manager Role of the operator, which can read and change every Secret there. Watching `devops` and `argo-workflows` gives the operator the Secrets of those namespaces, the GitHub App keys of the roadmap Service among them. `helm template` of chart 0.1.48 with that watch list renders `seaweedfs-operator-manager-role` and its RoleBinding in `devops` and in `argo-workflows`. The tenant buckets of service repositories still come from the tenant chart of `dan-petty/infra`, in the namespace of each tenant.
- **ClusterSecret rows for the writer keys, pushed by `devops k8s push-secrets`.** The owner refused it: the key pair would live in the workstation keyring. The tenant chart makes each pair with an ESO `Password` generator.
- **Hand-written writer CRs in `k8s/object-store/`.** The per-tenant form belongs in the tenant chart that the tenant namespaces read, and a copy here would drift from it.
- **An empty `watchNamespaces`.** The chart then renders the manager rules as a ClusterRole over every namespace (`deploy/helm/templates/rbac/role.yaml`, else branch), with write access to the Secrets and the workloads of each namespace.
- **Cluster-scoped CRs.** The `Bucket` CRD is Namespaced, so the API server refuses a cluster-scoped object.
- **`Bucket.spec.access` for a writer.** No writer identity exists in this change, and the tenant chart grants access with `S3Policy` and `S3PolicyBinding`.
