# Design

## Decisions

- **Write each GitHub read under `work/github/` (`src/devops_cli/roadmap/stage/stage_github_snapshot.py`)**: Write `work/github/issues/<number>.json`, `work/github/pulls.json`, `work/github/pull-files/<number>.json`, `work/github/issue-index.jsonl`, and `work/github/errors.json` directly in `work/github/` during `_Prepare.hand_on` (`src/devops_cli/roadmap/stage/stage_job_phases.py:430`), and pass `"github"` in `_request` alongside `"issue_listing"`.
- **Add `PullRequestFilePatch` instead of adding `patch` to `PullRequestFile` (`src/devops_cli/github/client.py:190`)**: Recorded fixture `tests/fixtures/github/hello_world_pull_request.json` contains `"patch"` keys on `branch_comparison` files, and `tests/github/test_github_client.py:169` compares `get_compare_files(...).files` against `PullRequestFile(filename=..., status=..., additions=..., changes=...)` without `patch`. Keeping `PullRequestFile` unchanged and introducing `PullRequestFilePatch` for `GitHubClient.get_pull_files` preserves existing compare tests.
- **Stop open-issue pagination at 1000 issues and cap JSONL size at 1 MiB**: `GitHubClient.list_open_issues` stops consuming `self._session.paginate` as soon as `limit` (`CONST_ROADMAP_STAGE_GITHUB_INDEX_MAX_ISSUES = 1000`) non-PR issues are collected. Each JSONL line stores `{"ref": f"#{number}", "number": number, "title": ..., "labels": [...], "body": ...}` with masked body cut to `CONST_ROADMAP_STAGE_GITHUB_INDEX_BODY_CHARS = 500`, stopping before exceeding `CONST_ROADMAP_PHASE_JSON_MAX_BYTES` (`1048576` bytes). Putting `"ref": f"#{number}"` first ensures `grep -i <word> work/github/issue-index.jsonl` outputs `#<number>` directly.
- **Extract `#<number>` references and pull-file candidates without false errors**: Match `(?<![\w/#])#(\d+)\b` (same boundary rule as `src/devops_cli/roadmap/refine/refine.py:2591`) on `item.body`. Fetch each referenced `#<number>` via `get_issue` (plus last comments and closing pull when closed); only request `get_pull_files` for explicitly named PRs (`named_pull_requests`) or referenced `#<number>` whose `IssueView.is_pull_request` is `True`. Catch `GitHubOperationError` per read, omit the failed target file, record the failure in `work/github/errors.json`, and continue.
- **Instruct stock `Coder` via `src/devops_cli/ai/tasks/roadmap_stage_coder.md`**: Name `work/github/issues/`, `work/github/pulls.json`, `work/github/pull-files/`, and `work/github/issue-index.jsonl` with shell inspection and `grep -i <word> work/github/issue-index.jsonl` while preserving all existing rules checked by `tests/roadmap/stage/test_roadmap_stage_prompt_rules.py`.

## Rejected alternatives

- **Add `read_issue` and `find_issues` custom tools to `--phase agent`**: Rejected because `openspec/specs/roadmap-stage/phases/spec.md:60` and `tests/roadmap/stage/test_roadmap_stage_agent.py:104` require `script.tools_offered == stock.tools_offered` (`Coder(repo_context=False, sub_agents=False)`).
- **Modify `PullRequestFile` in `src/devops_cli/github/client.py:190`**: Rejected because `tests/fixtures/github/hello_world_pull_request.json` holds `"patch"` keys and would break `PullRequestFile` equality assertions in `tests/github/test_github_client.py:169`.
- **Reuse `work/issues.json` (`ListingIssues` at `src/devops_cli/roadmap/stage/stage_job_phases.py:246`) for open-issue search**: Rejected because `work/issues.json` only holds the target item and active change issues under `openspec/changes/`, omitting general open repository issues (up to 1000 records).
- **Abort `prepare` when a referenced `#<number>` or optional snapshot read raises `GitHubOperationError`**: Rejected because a single missing reference or transient read error must be recorded in `work/github/errors.json` without blocking planning for the item.
