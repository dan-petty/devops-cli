# Design

## Decisions

- **The run ends at the draft.** After `_pull_request`, `_require_complete` asks `draft_readiness` with no check runs, as `_ready` did: a refusal stops the item at the step `ready`. Then `_end_drafted` writes the marks that `_ready` wrote (the last commit, the pull request, the spend, the trace, the repair rounds, and no base and no phase marks), with `implement.result` equal to `drafted`, and sets Status In Review, as #3702 asks for the end of `publish`. The comment on the item names the draft and the spend.
- **The grade follows the forge outcome at read time.** The implement line is `drafted`, the record of the hand-off, and the line counts it as a success. `devops roadmap eval grades` scores each `drafted` line by the delivery of its item: merged, or open and out of draft, is a success; closed with no merge is a failure; a draft keeps the line out of the attempts (`drafts_pending`). The search of the bot pull requests reads `updated:>=` with the head branch, the state, the draft flag and the creation time, so a delivery opened before the window gives its outcome; the verdicts count only the pull requests opened in the window. No second writer and no pending mark are needed. The versions and the trend count the lines as written, and so does the dashboard.
- **No delivery draft waits with no actor.** A failed check that no fix-checks unit repairs (a name that gives a class outside `FIX_CHECK_CLASSES`), a cancelled check and a conflict with the base reach no unit. The watch row stops the item of such a draft through the stop flow of the Job (the due step `stop` replaces the dead `comment_ci_infra`): one stop comment, Status Blocked, `implement.stopped` at `pull request`, the class `ci_infra` or `conflict`. A check that GitHub could not read stops nothing. The row writes the judged head of the ready path only after the path returns a report.
- **One predicate for the ready path.** `takes_ready_path` of `fix_checks.py` holds the rule for the watch row and for the step: `fix_checks.result` equal to `repaired`, or `implement.result` equal to `drafted`. The draft of a stopped Job stays a draft, as before.
- **The step keeps no work in progress.** The step records the commit where it started (`start`) and resets to it when it does not end done. The exit checks judge everything since `start`. The rename restore of a stray file (#3488) moves from `implement_wip.py` into `implement_step.py`, because the exit checks still use it.
- **The group commit stages what a check changed.** The `wip:` commits staged the checkout after the verification commands ran. With no keeper, `_commit_group` runs `git add -u` before the commit, so a tracked file that an exit check rewrote, such as the `uv.lock` of a stale lock (#6557), leaves the checkout clean. A new file stays out.
- **The scoped-check repair stays.** `_fix` serves `_scoped_rounds`, the repair of a failed scoped check before the push, which needs no GitHub call. Only its caller in the watch loop (`_repair_after_push`) goes. #6527 decides the scoped repair of the stock `Coder`.
- **The checkpoints stay.** A checkpoint pushes each group that passed between the steps. Part C of #3702 removes all pushes from the agent phase.
- **The stall keeps its value.** `deadline_stall_seconds` stays 4200: the change removes the watch, and the longest silent wait is now a command of 1800 s. #5029 owns a lower value.

## Check classes that lose the repair of the Job

Before, the Job repaired a failed check of any class whose log named a path of the repair scope (`_repair_after_push`), and stopped the item for a cancelled check or a conflict. The watch row starts a fix-checks Job only when the name of the failed check gives a class of `FIX_CHECK_CLASSES` (`fix_checks_check` of `steps/watch.py`). `_CHECK_NAMES` of `failure.py` gives no name the class `plan_defect`, so in practice only `test`, `lint` and `types` get a repair. These checks of this repository give `ci_infra` and lose the repair: `Fail-to-Pass Check`, `Plan Check`, `Semantic PR title`, `Design Tokens`, `Docs Site Build`, `Trivy`, `zizmor`, `CodeQL` and `Analyze`, and the image checks. For such a check, a cancelled check and a conflict, the watch row now stops the item, as the Job did, and a person or a clear rule takes it. Only mode `on` of `roadmap.fix_checks.mode` repairs or marks a draft ready; modes `off` and `plan` leave the draft a draft.

## Rejected alternatives

- **Write the implement line at the ready mark or the merge.** Rejected: it adds a writer of the result line and a pending mark, and it loses each attempt whose draft never moves. The report reads the forge state instead (see Decisions).
- **A new baseline: `drafted` is the success.** Rejected by the owner (#3702, comment 7049207841): the grade follows the forge outcome.
- **Re-run a cancelled check, or wait for a person with no stop.** Rejected: a re-run is a new retry, and a wait with no stop leaves the item In Review with no actor.
- **Keep the `wip:` commits and drop only their push.** Rejected: the owner decision names `implement_wip.py`, and in the split of #3702 the agent phase hands one patch to `publish`, so a commit that no push sends keeps nothing.
- **Delete `_fix` with the watch loop.** Rejected: it removes the repair of a failed scoped check before the push, which no criterion asks for.
