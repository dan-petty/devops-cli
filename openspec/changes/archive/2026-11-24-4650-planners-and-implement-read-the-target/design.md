# Design

## Decisions

- **One section builder `rules_section` in `src/devops_cli/roadmap/step_rules.py` takes the rules text and the heading and cuts it to the cap, and both callers use it.**: The implement step and the stage measure already share `rules_sections`, so one builder keeps the cap and the heading equal for the planner and the step, and `src/devops_cli/roadmap/step_rules.py:141:agents.read_text(encoding="utf-8").strip(), CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS` stays the one place of the cut.
- **Read the `AGENTS.md` of the item's `sha` through `_read_git_file`.**: `src/devops_cli/roadmap/refine/refine.py:1060:ctx = _read_git_file(source, sha, "CONTEXT.md")` reads CONTEXT.md at the sha, so the whole context describes one revision and an earlier step cannot change the rules of the plan.
- **Add the rules section first, before `CONTEXT.md` and the ADRs.**: `src/devops_cli/roadmap/refine/refine.py:1098:truncated = truncate_to_token_limit(raw_text, max_tokens=max_tokens)` cuts the end of the text first, so the rules survive a small budget.
- **Cut each rules section with `CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS`, 8000 tokens.**: The implement step already cuts the same file with this constant at `src/devops_cli/roadmap/step_rules.py:141:agents.read_text(encoding="utf-8").strip(), CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS`, and one cap keeps the planner and the step equal.
- **Render the generic rules with `generate_agents_md(parse_project_metadata(source))` when the checkout holds no `AGENTS.md`.**: #4641 delivered that renderer and its manifest detection, and `src/devops_cli/templates/AGENTS.md.j2:17:{% if python %} A fix pull request shows that its new tests fail on the base with `devops ci fail-to-pass --base <ref>`.{% endif %}` writes no Python sentence for a checkout with no Python manifest.
- **Import `parse_project_metadata` and `generate_agents_md` inside `generic_rules`, not at the top of `step_rules.py`.**: `src/devops_cli/roadmap/implement/implement_step.py:468:*rules_sections(source, chosen),` loads `step_rules` for every command that loads the implement step, so a top-level import of the generator would load the template stack there too and tie `devops_cli.roadmap` to `devops_cli.ai`.
- **Detect the toolchain of the generic rules from the checkout, not from the item's commit.**: `src/devops_cli/ai/instruction_generator.py:177:resolved_path = repo_path.resolve()` is the first line of `parse_project_metadata`, which resolves the folder it is given and takes no sha, and the section is the generic rules, so it names no rule of the target's own file.
- **Give the generic rules to both `rules_sections` and `collect_context`.**: `src/devops_cli/roadmap/step_rules.py:139:return []` leaves the planner and the implement step with no rules for a repository without the file, and both need the same rules.
- **Keep the target `AGENTS.md` of 44,535 characters and cut it at the cap.**: Owner decision 7 of #4627 keeps an existing `AGENTS.md` and leaves a shortening to the owner, and `src/devops_cli/config/constants.py:3730:CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS: Final[int] = 8000` holds the section.
- **Count the generic rules in the stage measure, and change no caller of `rules_sections`.**: `src/devops_cli/roadmap/stage/stage_change.py:def measure_groups` counts the sections of `rules_sections`, so the measure and the message stay equal and the implement step needs no change.
- **Regenerate the step message snapshot in a group of its own, after the fallback lands.**: `tests/roadmap/implement/test_roadmap_implement_step.py:175:assert inputs.message == snapshot` compares the whole message of a checkout with no `AGENTS.md`, and `.pre-commit-config.yaml:25:snapshot, which is regenerated, never edited (docs/TESTING.md)` makes the regeneration the fix.
- **Leave the ADR selection as it is.**: The issue states that ADR selection by relevance is a different item, and `src/devops_cli/roadmap/refine/refine.py:1068:for adr_path in [p for p in adr_items if p][:5]:` keeps the five files in name order in this change.
- **Run the stage eval replay in a group of its own, and state the score before and after in the pull request body.**: `src/devops_cli/commands/roadmap_eval_stage.py:254:replay: Annotated[bool, typer.Option("--replay", help=HELP.roadmap.eval_stage_replay)] = False,` replays the recorded cases through the gates with no model call, so the same command gives the before score and the after score and the third criterion needs no person.

## Rejected alternatives

- **Pass a synthetic task group from refine to `rules_sections`.**: Refine holds no task group, and a synthetic one couples the context to the shape of a group: `src/devops_cli/roadmap/step_rules.py:129:return [route for route in ROUTES if _matches(route, paths)]` reads only the named paths of a group.
- **Copy the `AGENTS.md` read and the cap into `refine.py`.**: `src/devops_cli/roadmap/step_rules.py:141:agents.read_text(encoding="utf-8").strip(), CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS` holds the cap of the step, and a second copy in refine.py drifts from it.
- **Import the instruction generator at the top of `step_rules.py`.**: `src/devops_cli/roadmap/implement/implement_step.py:468:*rules_sections(source, chosen),` loads `step_rules` on every command that loads the implement step, so the template stack would load there too.
- **Read the working-tree `AGENTS.md` in the refine context.**: `src/devops_cli/roadmap/refine/refine.py:1060:ctx = _read_git_file(source, sha, "CONTEXT.md")` reads CONTEXT.md at the sha, so a working-tree read would mix two revisions in one context.
- **Read both the `AGENTS.md` at the sha and the working-tree file.**: `src/devops_cli/roadmap/refine/refine.py:1098:truncated = truncate_to_token_limit(raw_text, max_tokens=max_tokens)` caps the whole context, so two copies of the rules spend the budget twice.
- **Put the rules section last, after `CONTEXT.md` and the ADRs.**: `src/devops_cli/roadmap/refine/refine.py:1098:truncated = truncate_to_token_limit(raw_text, max_tokens=max_tokens)` cuts the end of the text first, so a small budget would remove the rules.
- **Add no cap to the rules section.**: The target file holds 44,535 characters, about 11,000 tokens, against `src/devops_cli/config/constants.py:3730:CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS: Final[int] = 8000`.
- **Add a refine-only cap constant.**: `src/devops_cli/config/constants.py:3730:CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS: Final[int] = 8000` is the one cap of a rules section, and a second constant would let the planner and the step read different text.
- **Shorten the target `AGENTS.md` in this change.**: Owner decision 7 of #4627 keeps an existing `AGENTS.md` and leaves a shortening to the owner's hand, and `src/devops_cli/config/constants.py:3730:CONST_ROADMAP_IMPLEMENT_FILE_MAX_TOKENS: Final[int] = 8000` is the only change to it.
- **Give the generic rules to the implement step only.**: `src/devops_cli/roadmap/refine/refine.py:1068:for adr_path in [p for p in adr_items if p][:5]:` is the whole of the planner's repository rules today, so the planner would still read no rules of the target.
- **Keep the empty list and file a separate item for the fallback.**: `src/devops_cli/roadmap/step_rules.py:139:return []` is the fallback that leaves a repository without the file with no rules, and #4641 is closed with its renderer delivered in v0.114.0.
- **Select the ADRs by relevance in this change.**: `src/devops_cli/roadmap/refine/refine.py:1068:for adr_path in [p for p in adr_items if p][:5]:` is the selection that the issue leaves to a different item, so this change keeps it unchanged.
- **Park the stage eval replay score on a person.**: `src/devops_cli/commands/roadmap_eval_stage.py:254:replay: Annotated[bool, typer.Option("--replay", help=HELP.roadmap.eval_stage_replay)] = False,` replays the recorded cases with no model call, so a group runs it before and after the change and states both numbers in the pull request body.
- **Edit the implement step snapshot by hand to add the generic section.**: `.pre-commit-config.yaml:25:snapshot, which is regenerated, never edited (docs/TESTING.md)` makes the regeneration the only fix, and a hand edit drifts from the message at the next change.

## Unchanged references

- `src/devops_cli/roadmap/implement/implement_step.py` (import): It imports and calls rules_sections, so the generic section reaches the step message with no change to this file.
- `src/devops_cli/roadmap/stage/stage_change.py` (import): Its measure counts the sections of rules_sections, so the measure follows the fallback with no change to this file.
