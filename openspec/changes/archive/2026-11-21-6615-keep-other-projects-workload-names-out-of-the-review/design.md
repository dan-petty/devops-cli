# Design

## Decisions

1. **A namespace matcher in the query, from a setting.** Each fact that groups by `namespace` or `pod` gets the matcher `namespace=~"{namespaces}"` in each selector whose metric has a `namespace` label, and keeps `namespace` and `pod` in its `by` and `on` clauses. Prometheus then gives no series of another project, so the dispatcher never reads a foreign name, and each fact keeps one row for each workload of the project. The selectors of node metrics (`kube_node_status_allocatable`, `kube_node_status_condition`) have no `namespace` label and do not change.
   - `prometheus.working_set_over_limit`, `prometheus.cpu_throttling`, `prometheus.restarting_containers`, `prometheus.valkey_memory`, `prometheus.valkey_no_maxmemory` and `prometheus.database_memory` get the matcher. Their definitions name the project namespaces.
   - `loki.error_lines_top` reads `namespace=~"{namespaces}"` in place of the fixed `namespace=~"devops|llm"`, so one setting scopes all facts, and the guard of decision 5 agrees with the query.
   - `prometheus.requests_over_allocatable` stays the share of the cluster: the requests of the running pods of all namespaces over the allocatable resources of the Ready nodes (SRE Q14, Kubernetes Q11 for the cluster). Its rows hold only `resource`, so it names no workload. Its join reads the pod UID (`on (uid)`, `max by (uid)`) in place of `on (pod, namespace)`, so the loader rule of decision 4 does not refuse it. The UID is unique for each pod, so the join gives the same pods. On 2026-11-21 a read-only query at 12:00Z gave the same two values for the two joins, and each of the 318 request series held `uid`.
2. **The setting `roadmap.project_review.namespaces`.** One list of names serves all facts, and the config of each checkout can give its own list. The model is `RoadmapProjectReviewConfig` in `src/devops_cli/config/settings.py`, as the field `project_review` of `RoadmapConfig`. `roadmap.review` is the setting of the step review (#5969), so the project review gets its own name.
   - The default is `DEFAULT_ROADMAP_PROJECT_REVIEW_NAMESPACES` in `src/devops_cli/config/defaults.py`: the 14 namespaces that `k8s/namespaces.yaml` defines (`git grep -l "kind: Namespace" k8s/`). The `namespace:` of the kustomizations (`cloudflared`, `monitoring`) are already in that file. The comment above the constant names this source. These names are already public in `k8s/` of this repository, so AGENTS.md rule 10 holds.
   - `kube-system` and `default` are not in the default list, because workloads from outside this repository run there. Thus the review does not measure Traefik (`kube-system`, part of k3s) or gpu-feature-discovery (`default`). #6628 moves gpu-feature-discovery out of `default` (see #6628).
   - An empty list is a config error, not "all namespaces": the field has `min_length=1`. Each name must match `CONST_K8S_LABEL_RE` (RFC 1123 label), so a name holds only `a-z`, `0-9` and `-`. Such a name cannot change the regular expression of the matcher or end its PromQL string.
3. **The placeholder `{namespaces}`.** `PLACEHOLDERS` of `catalog.py` and the placeholder pattern of `catalog.schema.json` get `namespaces`. `window_placeholders(window, repo, namespaces)` gives the names joined with `|`. `read_catalog` in `dispatch.py` passes `context.settings.roadmap.project_review.namespaces`. `_plan_values` in `review.py` fills the same value from `load_settings()`, so `--dry-run` prints the filled queries. A settings load reads files only, so the dry run still sends 0 requests and starts no program.
4. **The loader rule `unscoped_workload_metric`.** It sits beside `unscoped_service_metric` in `catalog.py`, and `_cross_checked` calls it for each fact of the shape `rows`. When a `by (…)` or `on (…)` clause of the query names `namespace` or `pod`, it returns the field, `query` or `base`, that holds no positive namespace matcher (`namespace="…"` or `namespace=~"…"`) and the first such label, else None. The refusal message `review_catalog_unscoped_workload` names the fact, the field and the label. The rule reads the query text, as `unscoped_service_metric` and the schema rule for `by (node)` do. It is the acceptance criterion of #6615, and it reads only the clauses that #6615 names.
   - The rule reads `base` too. The probe of the base tells whether an empty answer is "none". A base of all namespaces makes an empty answer of the project `ok` with no rows when only another project has a series. So the six scoped facts get `namespace=~"{namespaces}"` in their `base` as well.
   - A negative matcher (`namespace!="…"`, `namespace!~"…"`) does not scope a query: it still reads every other namespace, so the rule refuses it.
   - A `scalar` fact is one number with no label, so it names no workload, and the rule does not apply to it.
   - The rule accepts each positive matcher, also a fixed one such as `namespace="devops"` of `prometheus.restarts`.
5. **The guard on the rows.** The loader rule reads only `by (…)` and `on (…)`. A query with no aggregation, `without (…)`, `topk`, `sort` or `label_replace` can keep every label of a series and pass the rule. So the dispatcher also reads the labels of each series of a `rows` fact of Prometheus and Loki, before it makes the rows. Each namespace label of a series must hold a namespace of the setting, and a series that holds a workload label must hold `namespace`. Else the fact gets `error` and a null value, and the review keeps no row of it. The reason `review_foreign_workload` names the fact and the label, never a label value.
   - The table `_NAMESPACE_LABELS` of `dispatch.py` holds `namespace`, `exported_namespace` (the namespace of a target that a scrape keeps) and `dest_namespace` (the destination of an Argo CD application).
   - The table `_WORKLOAD_LABELS` holds the labels by which the catalog facts group (`pod`, `container`), the workload labels of kube-state-metrics (`deployment`, `statefulset`, `daemonset`, `replicaset`, `job_name`, `cronjob`, `created_by_name`, `owner_name`), `exported_pod`, `exported_container`, `service` (Traefik and kube-state-metrics) and `persistentvolumeclaim`. A Traefik `service` series has no `namespace`, so a `rows` fact by the Traefik `service` gives `error`.
   - The guard checks only the labels of these two tables. It does not check another label, for example a label that `label_replace` writes or the application `name` of Argo CD. A fact must not group by such a label.
   - A series with no such label passes, for example a row by `resource` only.
   - `prometheus.restarts`, `prometheus.oom_kills_devops` and `prometheus.argo_workflows_memory` group by `container` in one fixed namespace. They now also group by `namespace`, so each row holds its namespace and the guard can check it.
   - The guard reads the answer only, so the dry run still sends 0 requests.
6. **The header rule of `catalog.yaml`.** It adds `{namespaces}` to the list of placeholders, and adds: a query gives no name of a workload outside the project namespaces, so a `rows` fact that groups or joins by `namespace` or `pod` holds the matcher `namespace=~"{namespaces}"` in its query and in its base, and a row that names a workload outside the setting makes the fact `error`.
7. **The probe does not change.** The probe is `group(last_over_time(<base>[<range>]))` with no `by` clause, so its answer has no label and names no workload. #6612 changes the base metric names, the probe, the runner pair, the path condition, `prometheus.oldest_pending_update` and `prometheus.stage_sli`, and this change does not touch them.
8. **The proof is offline.** The spec scenarios use fixture catalogs, the shipped catalog loaded by the loader, the settings model, fixture answers of Prometheus and Loki, and the fakes of the dry run. The 7-day read-only review after the release is the live check, in the pull request body. No test reads live data.

## Rejected alternatives

- **Remove `namespace` and `pod` from the `by` clauses.** It hides the names, but each fact still counts the workloads of other projects, so the values stay wrong for the project. The refine design of #6615 rejected it for this reason.
- **Filter the rows after the read, as the only control.** The dispatcher has already read the foreign names, and a fact with a threshold (`> 0.8`) has already compared foreign series. The leak and the wrong count stay. The matcher in the query stays the first control. The guard of decision 5 is a second control: it does not drop a row and keep the others, it gives `error` for the whole fact.
- **The project share of `prometheus.requests_over_allocatable`.** The requests of the project namespaces over the allocatable resources of all Ready nodes is not the question Q11 asks: are the nodes overcommitted. Its rows never named a workload.
- **Hard-code the namespaces in each fact.** Seven copies of one value, and a review of another repository gives the namespaces of devops-cli with no way to change them.
- **Read the namespaces from the manifests at review time.** The review then needs a checkout with `k8s/` and a manifest parser, and a repository with no manifests gives no value. The setting with a default from the manifests gives the same names with no read.
- **An empty list means all namespaces.** A setting that is empty by mistake would publish the names of other projects again. The load refuses it.
- **Put `kube-system` and `default` in the default list.** Workloads from outside this repository run there, so the review would name them.
- **Require the placeholder `{namespaces}` itself.** `prometheus.restarts`, `prometheus.oom_kills_devops` and `prometheus.argo_workflows_memory` hold a fixed matcher of one project namespace. A positive matcher is enough for the rule, and the guard of decision 5 checks the namespace of each row.
- **A PromQL syntax tree (promql-parser 0.12.0).** The repository messense/py-promql-parser has an MIT license, and the PyPI release 0.12.0 has no license field. The change does not adopt it: the guard reads the labels of the answer and needs no parse, and the loader rule reads only the clauses that #6615 names. It also cannot parse the LogQL query of `loki.error_lines_top`. The auto mode classifier refused a local probe of its API, so the change did not run it.
- **cloudflare/pint.** It lints the `expr` of Prometheus rule files and is a Go program. It does not read the catalog form, and a run of pint at each catalog load adds a second runtime for one check.
