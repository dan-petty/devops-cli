# Design

## Decisions

- **Use the structured reply's own validation error for a schema rejection and the project form check for an empty part that the schema allows.**: The repository already uses the structured reply library, which names the field path of a rejection, and the project form check is the code that sees an empty part: `src/devops_cli/roadmap/refine/refine.py:1454:return all(part.strip() for part in criterion.model_dump().values())`.
- **Name a failed part as a path in the record and as a dotted name on the result line.**: The result line holds a name only, as `src/devops_cli/roadmap/job_result.py:304:fields += [f"{_name(key)}={_name(value)}" for key, value in (names or {}).items()]` shows, and the record holds text that a person and the model read.
- **Build the failure text and the result-line names from a new `form_check_details`, and keep the three members that the failure class at `src/devops_cli/roadmap/refine/refine.py:427:class JobFailure:` defines.**: The form check already reads each part of a criterion, as `src/devops_cli/roadmap/refine/refine.py:1454:return all(part.strip() for part in criterion.model_dump().values())` shows, and the class holds `src/devops_cli/roadmap/refine/refine.py:435:findings: tuple[str, ...] = ()` beside the error, so `_log_attempt` reads the proposal of the item and the result line needs no second copy of the parts in the record.
- **Carry the earlier failure to the next request through the findings list of `_judge_findings`.**: That list is the one path that the next request already carries, as `src/devops_cli/roadmap/refine/refine.py:def _judge_findings` and the prompt key show, so the review findings and the earlier failure reach the model together.
- **Write the class form_check for any failure that holds a form check, not only for a failure that holds form checks alone.**: The issue asks for a class that is not `none`, and a failure that holds a form check beside an open question is still a form check failure: the round writes `none` today through `src/devops_cli/roadmap/refine/refine.py:4067:outcome, failure = result.next_step.value, None`.
- **Add the class value form_check with the action retry, and let the fault-case census name it as the one class that the fault suite cannot drive.**: The one table gives each class one action, as `src/devops_cli/roadmap/failure.py:130:ACTION_BY_CLASS: Final[Mapping[FailureClass, FailureAction]] = MappingProxyType(` shows, and the fault suite runs the implement job, which never records this class.
- **Remove the two character caps.**: The owner rule of 2026-11-17 forbids a hard cap that drops a failure reason of an earlier try, and the staged values are `src/devops_cli/config/constants.py:3486:CONST_ROADMAP_REFINE_FAILURE_MAX_CHARS: Final[int] = 300` and `src/devops_cli/config/constants.py:3490:CONST_ROADMAP_REFINE_JUDGE_FINDINGS_MAX_CHARS: Final[int] = 2000`.
- **Pass the class and the failed parts to the result line from the refine round.**: The grade reads the result line, and `src/devops_cli/roadmap/job_result.py:299:f"class={failure.value if failure else _NONE}",` shows that the line writes the class that the round passes.
- **Keep the review findings list and add the earlier failure to it, with no second request key.**: The store key and the request key already carry the review findings, and one list feeds the model, so a second key would change the prompt for one string.
- **Prove the record detail and the next request with one test that builds a reply whose first criterion has an empty then.**: `tests/roadmap/refine/test_roadmap_refine_job_failure.py:53:_WHOLE = RefinementProposal(` lets the module build that reply from the whole one, and one test then shows both halves of the fourth expected behavior of the issue.
- **Record each proposal prompt in the fake client of the job-failure test module.**: `tests/roadmap/refine/test_roadmap_refine_job_failure.py:87:def chat_structured(self, system: str, prompt: str, schema: type[Any], **_: Any) -> Any:` receives the prompt of each request, so the test reads what the model got without a second fake.

## Rejected alternatives

- **A custom string scan of the proposal.**: It repeats the schema and misses a nested field, and the form check already reads each part: `src/devops_cli/roadmap/refine/refine.py:1454:return all(part.strip() for part in criterion.model_dump().values())`.
- **A second JSON Schema validator.**: It adds a schema that the model does not read and gives no field path to the next round.
- **A new request key for the earlier failure.**: It changes the prompt and the request for one string, and the findings list already reaches the model through `src/devops_cli/roadmap/refine/refine.py:def _judge_findings`.
- **A comment on the item that holds the failure.**: A job failure writes no comment, and the record is the source that a later round reads.
- **Record the class none for a form check.**: The class `none` hides the cause: `src/devops_cli/roadmap/job_result.py:299:f"class={failure.value if failure else _NONE}",`.
- **Reuse an existing model class such as provider or parser.**: A form check is no model or network failure, so an existing class names the wrong cause: `src/devops_cli/roadmap/failure.py:70:PROVIDER = "provider"`.
- **Add a form-check fault case to the fault suite instead of narrowing the census.**: The matrix asserts the class of the implement job, and only the refine round records this class, so no implement fault can produce it.
- **Raise the two caps.**: A larger cap still drops a long failure and still breaks the owner rule of 2026-11-17.
- **Cap only the result line.**: The result line is the evidence that the grade and a person read, so a cap hides the same detail.
- **Log the detail with the application logger.**: The grade reads the result line, not the application log.
