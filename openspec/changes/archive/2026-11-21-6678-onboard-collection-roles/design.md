# Design

## Decisions
1. **ansible-doc gives the roles of a collection.** `read_collection_roles` in `src/devops_cli/infra/ansible_facts.py` runs `ansible-doc -t role -l -j` of the tool environment in the export through `run_subprocess`, and returns, sorted, each key of the JSON mapping whose value has the key `collection`. Project code reads no file of a collection. Reason: the issue, and ansible-core 2.22.0 marks each role of a collection with that key and no role of `roles_path`.
2. **The role folders stay with `find_roles`.** The row lists the roles of `find_roles`, then the roles of the collections. Reason: `ansible-doc` lists only a role with an argument spec, and none of the 5 roles of `tests/fixtures/infra/homelab_shape` has one (its listing with no collection is `{}`). `find_roles` finds each role folder.
3. **The listing sees only the install.** The listing runs with `ANSIBLE_COLLECTIONS_PATH=<folder of the install>` and `ANSIBLE_COLLECTIONS_SCAN_SYS_PATH=False`, and with `ANSIBLE_CONFIG` of the repo's `ansible.cfg`, as the install has it. Reason: the process runner gives the child no `ANSIBLE_` variable of the person, and the environment variable wins over a `collections_path` of `ansible.cfg`. Without the sys path setting, a probe with the `ansible` 2.21.4 package listed 108 roles, most from the collections of that package, in place of 2.
4. **A temporary folder for the install.** Onboarding installs into a new `tempfile.TemporaryDirectory` (mode 0700) and removes it after the listing. It does not use the kept install of plan under `<data dir>/infra/collections/<sha256>`. Reason: the issue asks for a temporary path, and onboarding then writes no file outside its private temporary folders unless a person gives `--confirm`.
5. **One install helper.** `REQUIREMENTS_FILE`, `galaxy_argv` and `config_env` (before: `_config_env`) move from `plan.py` to `ansible_facts.py`, with the new `install_requirements(tool, project, target)`. It runs the install of `plan.py` (same command, environment, timeout and error) into a folder that the caller gives. `install_collections` of `plan.py` keeps its kept install and its staging folder, and calls it. Reason: `plan.py` imports `OnboardTarget` from `onboard.py`, so `onboard.py` cannot import `plan.py`. `ansible_facts.py` already holds the tool environment and the other reads of Ansible output.
6. **No ansible-doc, no install.** Before the install, onboarding checks the `ansible-doc` of the tool environment (`tool.argv("ansible-doc")[0]`) with `check_binary`. When no tool environment is installed, or the folder of `ansible-runner` holds no `ansible-doc`, it starts no install, and the row says why in its reason. Reason: the issue. An install with no listing has no use, and the tool environment starts each command from the folder of `ansible-runner` (requirement "The Ansible environment is the ansible-runner on PATH").
7. **A failed read keeps the role folders.** A failed install or listing gives its `InfraReadError` message to the reason of the row, as `_attempt` does for the config and the inventory. The state comes from the roles that the row lists: `present` with one role or more, else `missing` with the step. Reason: the role folders still read, so the row is not `not readable`.
8. **Only `collections/requirements.yml`.** The install reads `REQUIREMENTS_FILE`, the file that plan and apply install. Reason: the roles row then shows the roles that a plan runs.
9. **The step names a collection.** The step of the roles row also names a role of a pinned collection with an argument spec. Reason: a repo whose roles are all in collections gets a step it can follow.
10. **Tests double the process edge.** `answer_infra_reads` in `tests/support/infra.py` answers the install by a copy of each collection that the requirements file names and that `tests/fixtures/infra/collections/<namespace>/<name>/` holds, into `<folder>/ansible_collections/`, as an install puts it. It answers `ansible-doc -t role -l -j` with the recorded listing `tests/fixtures/infra/ansible_roles.json` when `ANSIBLE_COLLECTIONS_PATH` holds the fixture collection `example.infra`, and with `{}`, the recorded listing of the homelab shape, when it does not. The tests start no real Ansible (docs/TESTING.md), so they run the same in the devcontainer and on the CI runner.

## Rejected alternatives
- **Walk the `roles` folder of each installed collection.** Rejected: the issue says to use the listing of ansible-core and walk no collection folder in project code.
- **Use the kept install of plan (`install_collections`).** Rejected: the issue asks for a temporary path, and the kept install is the store of plan and apply under the data folder.
- **Take every role from `ansible-doc`, also the role folders.** Rejected: `ansible-doc` lists no role without an argument spec, so the 5 roles of the homelab shape would leave the row (its listing is `{}`).
- **Import `plan.py` in the function body of `onboard.py`.** Rejected: a late import hides the cycle `plan.py` → `onboard.py` and keeps the install helper in a module of one command.
- **Keep the scan of the Python environment of the tool.** Rejected: the probe listed 108 roles from the collections of the `ansible` package in place of 2.
