# Design

## Decisions

- **Rank each value with one fixed table for each rule type, and keep the live value of a parameter that the table does not rank.**: The GitHub value names do not order the values, so the table gives the order of each rule; an unranked parameter keeps the live value, so a new GitHub parameter is never lowered.
- **Rank each boolean parameter with its own direction, so `do_not_enforce_on_create` ranks false above true.**: The baseline holds `tests/support/github_repository.py:101:do_not_enforce_on_create` as true, and that true value enforces fewer checks when a branch is created, so one rule of true over false would keep a weaker live value.
- **Apply one comparison to each rule, the required checks rule included, and then run `_with_required_checks`, which keeps its win for each parameter that the repository file sets and for each check entry that the file names.**: The comparison keeps the live checks and the stricter live parameters, and the win of the repository file stays as the base requirement and its confirmed-run scenario state, so the new text contradicts neither the code nor the base spec.
- **Keep the stricter live value, write one warning line that names the rule and the parameter, and exit 0.**: The row still applies the baseline, and the owner keeps the choice to lower the setting.
- **Merge the baseline and the live ruleset as a union with the stricter value on each shared parameter, and add each baseline rule and parameter.**: It adds each baseline rule and required check, raises a weaker live rule, and never lowers a strict one.
- **Give the kept-setting lines as a new `warnings` field of the row record, added after `src/devops_cli/github/onboard/model.py:85:changes: tuple[str, ...] = ()`, and render each line in `src/devops_cli/github/onboard/run.py:265:def _row_lines(row: Row) -> list[str]:`.**: The row has nothing to write, so it stays `present`, the drift check counts no drift, and the line still names the setting in the output.
- **Name the rendered settings file of the target repository by the constant that reads it, not by its path, in the tests of row 10.**: `search_code` for that path listed no file of the staged tree, and `src/devops_cli/github/onboard/baseline.py:39:SETTINGS_FILE: Final[str] = "github/repository.yaml"` holds the one copy of the name; the test helper `tests/github/onboard/test_onboard_rows.py:790:def _declare_checks(harness: OnboardHarness, checks: list[str], **parameters: Any) -> None:` writes the file into the commit of `main`.
- **Build the code fix now and leave the live run on dan-petty/devops-cli with its owner.**: The owner decision of 2026-11-23 on #6784 and its comment of 2026-11-26 hold the live run until #6876, and this change needs no live write; its tests run offline against a fake GitHub.

## Rejected alternatives

- **Let the merge also override a parameter of the required checks rule that the repository file sets.**: `src/devops_cli/github/onboard/settings_rows.py:670:parameters.update(own_parameters)` shows that the file wins each parameter that it sets, and the base requirement `The ruleset requires the reported and the declared checks` holds a confirmed-run scenario that asserts the strict policy of the file; the added requirement states that win instead.
- **Compare the two values as text.**: The value order of `security_alerts_threshold` in the [REST API](https://docs.github.com/en/rest/repos/rules) is `none`, `critical`, `high_or_higher`, `medium_or_higher`, `all`, which is not alphabetical, so a text comparison keeps `high_or_higher` over `medium_or_higher`; the issue evidence of 2026-11-26 records that exact lowering.
- **Keep the whole live ruleset when it differs from the baseline.**: It also keeps a live value that is weaker than the baseline, so the baseline never raises it; `src/devops_cli/github/onboard/settings_rows.py:672:for entry in [*_check_entries(own), *baseline_checks, *_check_entries(live)]:` shows that the baseline checks already reach a live ruleset today.
- **Stop the run with a nonzero exit when a live setting is stricter than the baseline.**: `docs/adr/0035-the-onboard-command-owns-the-repository-settings.md:43:- Each row reads the live value, compares it with the baseline and writes only a difference.` holds the contract of the row, and a stop would block rows 11 to 16 of the same run.
- **Write the baseline value and warn of the change.**: It still lowers the live threshold, which rule 5 of `AGENTS.md` forbids; `src/devops_cli/github/onboard/settings_rows.py:714:writer.rest("ruleset-update", f"/repos/{ctx.repo}/rulesets/{match['id']}", desired)` is that write today.
- **Let the live ruleset win on each difference.**: `src/devops_cli/github/onboard/settings_rows.py:694:for ruleset in baseline.settings.get("rulesets") or []:` shows that the row writes each baseline ruleset, so a live value that wins on each difference never applies a new baseline rule.
- **Let the baseline win on each difference.**: It lowers each stricter live rule, which is the defect; the issue evidence of 2026-11-26 lists the `code_coverage` rule removed by that write.
- **Keep every live parameter of the required checks rule, also one that is weaker than the baseline.**: It contradicts the added requirement `Row 10 keeps each live rule and stricter threshold` and `tests/support/github_repository.py:103:strict_required_status_checks_policy": False,`, so a live false would survive a baseline true; the added requirement now uses the same rank table for that rule.
- **Wait for #6876 before any code change.**: The issue asks for a test that fails on the base (#7326), and the merge lives at `src/devops_cli/github/onboard/settings_rows.py:680:def ruleset_row(` of this repository; no live write is part of the change.
