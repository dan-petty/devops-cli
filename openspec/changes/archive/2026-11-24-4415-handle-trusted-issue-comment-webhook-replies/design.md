# Design

## Decisions

- **Give the comment event its own constant, `CONST_ROADMAP_COMMENT_WEBHOOK_EVENTS`, and union it into `CONST_ROADMAP_WEBHOOK_EVENTS`, leaving `CONST_ROADMAP_INTAKE_BATCH_KEYS` unchanged.**: The event set is derived at `src/devops_cli/config/constants.py:4026:CONST_ROADMAP_WEBHOOK_EVENTS: Final[frozenset[str]] = frozenset(`, and an intake key would make the intake row due for a comment.
- **Modify the base requirement of the event set with the five events, and keep both of its scenarios.**: The living spec says the set holds the four events, so an added requirement would contradict it after the archive; `read_spec` gave that text and its two scenarios.
- **Add the comment fields and the pull request marker to the typed payload.**: The refusal needs the action, the sender, the association and the marker, and the routing needs the body and its time, and the model is validated once after the signature check at `src/devops_cli/server/routes/webhooks.py:258:payload_model=GitHubWebhookPayload,`.
- **Refuse a comment on a pull request by the marker of the payload.**: The marker arrives in the payload, so the refusal makes no request at `src/devops_cli/server/routes/webhooks.py:158:refusal: Callable[[GitHubWebhookPayload], str | None] = _takes_every_payload`.
- **Tell a comment delivery by the `comment` field of the payload, because the refusal receives no event name.**: The hook is `Callable[[GitHubWebhookPayload], str | None]`, so the field is the only fact that the refusal sees; an `issues` payload holds no comment.
- **Trust only an `author_association` in `CONST_ROADMAP_TRUSTED_AUTHORS`, and refuse the Service bot and a login that ends with `[bot]`.**: It is the rule of `src/devops_cli/roadmap/trust.py:64:def is_person_comment(comment: IssueComment, actor: str | None) -> bool:`, which no bot and no outside account passes.
- **Answer the action, bot and pull request refusals with `CONST_SERVICE_STATUS_COMMENT_REFUSED`, and an untrusted author with `CONST_SERVICE_STATUS_UNTRUSTED_COMMENT`, which the route counts as `ignored`.**: The route maps only the own-write status and counts every other refusal as ignored, at `src/devops_cli/server/routes/webhooks.py:568:return _acknowledged(first, _REFUSAL_OUTCOMES.get(first, CONST_SERVICE_OUTCOME_IGNORED))`.
- **Choose the scoped row in `scoped_update_of`: the `implement` row for the retry command, the `refine` row otherwise, and use it in both `deliver` and `run_scoped_update`.**: The two rows sit on different lanes, and the table is keyed by event and action alone at `src/devops_cli/roadmap/run.py:1365:update = SCOPED_UPDATES.get((delivery.event, delivery.action))`, so one key cannot hold both.
- **Run the row's own decision code for the one item on the checkout of its lane, and write no due mark.**: `plan_refine` takes one item at `src/devops_cli/roadmap/refine/refine.py:3978:item_number: int | None = None`, and a scoped update writes no job's last success at `src/devops_cli/roadmap/run.py:1361:and writes no job's last success: the reconciling poll still judges every change made since`.
- **Let the implement row clear the stop with its own retry rule.**: The stop rule reads the trusted comment at `src/devops_cli/roadmap/stop_clear.py:349:retry = retry_asked_on(store, item)`, so the route writes no GitHub state.
- **Read the retry command from one function, `comment_asks_retry`, in both the route and `retry_asked`.**: The stop rule compares each body with `src/devops_cli/config/constants.py:3820:CONST_ROADMAP_IMPLEMENT_RETRY_COMMENT: Final[str] = "implement: retry"` at `src/devops_cli/roadmap/implement/implement.py:271:and comment.body.strip().casefold() == CONST_ROADMAP_IMPLEMENT_RETRY_COMMENT`, so the command has one text.
- **Change step 8 and step 11 of `docs/CLUSTER.md`, where the staged tree holds the onboarding, and leave `k8s/README.md` alone.**: `search_code` for `Add each repo's webhook` gave one hit, `docs/CLUSTER.md:47:8. Add each repo's webhook:`, so the event list and the constant stay equal.
- **Update the no-subscriber and counter cases of `tests/server/test_server_service.py` in the group that adds the event, and not in a later group.**: The subscription is what makes the two cases false, so the same step must change them: `tests/server/test_server_service.py:1879:("issue_comment", _event_payload("created")),` and `tests/server/test_server_service.py:2414:("github", "other", "no_subscriber"): 3.0,` fail on that step alone.

## Rejected alternatives

- **Add `issue_comment` to `CONST_ROADMAP_INTAKE_BATCH_KEYS`.**: The intake keys make the intake row due at `src/devops_cli/config/constants.py:3999:CONST_ROADMAP_INTAKE_BATCH_KEYS: Final[tuple[tuple[str, str, str], ...]] = (`, so a comment would run a whole intake round.
- **Replace the event set with an explicit list of events.**: `src/devops_cli/config/constants.py:4026:CONST_ROADMAP_WEBHOOK_EVENTS: Final[frozenset[str]] = frozenset(` derives the set from the intake keys and the watch events, so an explicit list would drift from them.
- **Add a new requirement for the comment event beside the base requirement of the event set.**: `read_spec` gave `The event set of the roadmap consumer, CONST_ROADMAP_WEBHOOK_EVENTS, SHALL hold issues, pull_request, pull_request_review and check_suite`, so the added requirement would contradict the living spec after the archive.
- **Add only the body of the comment to the payload.**: `src/devops_cli/roadmap/trust.py:64:def is_person_comment(comment: IssueComment, actor: str | None) -> bool:` decides trust from the association and the login, which the body alone does not give.
- **Parse the raw payload in the route instead of the typed model.**: `src/devops_cli/server/routes/webhooks.py:258:payload_model=GitHubWebhookPayload,` validates the body once, after the signature check.
- **Look up the issue to tell an issue comment from a pull request comment.**: The refusal runs before any request at `src/devops_cli/server/routes/webhooks.py:158:refusal: Callable[[GitHubWebhookPayload], str | None] = _takes_every_payload`, so a lookup would spend the request the refusal must save.
- **Trust every comment, or trust the sender login alone.**: `src/devops_cli/config/constants.py:4307:CONST_ROADMAP_TRUSTED_AUTHORS: Final[frozenset[str]] = frozenset(` holds 3 associations with write access, and the repository is public.
- **Set a refine or stage due mark from the route.**: `src/devops_cli/config/constants.py:3994:CONST_ROADMAP_REFINE_DUE_STAMP: Final[str] = "refine_due"` only makes the row due at the next sweep, which is the latency this change removes.
- **Queue a whole-round trigger on the lane of the row.**: `src/devops_cli/server/routes/webhooks.py:332:service_manager.enqueue_trigger(` runs every due row of the lane, which ADR 0009 rejected for a comment.
- **Clear the stop inside the webhook route.**: `src/devops_cli/roadmap/stop_clear.py:358:status = write_status(store, current, facts, marks=_marks(decided, current, now)).status` keeps the one Status writer in the row.
- **Run `clear_stops` for every Blocked item when a comment arrives.**: The idle cost is the comment listing of each Blocked item at `src/devops_cli/roadmap/stop_clear.py:50:**Cost.** A Blocked stop that no rule clears costs one request in the first round of a process:`.
- **Pass the comment timestamp to the failure ledger from the route.**: `src/devops_cli/roadmap/run.py:1361:and writes no job's last success: the reconciling poll still judges every change made since` shows that a scoped update leaves the next round to read the comment.
- **Keep the `issue_comment` case in the no-subscriber table and mark the delivery refused by the subscription itself.**: The subscription is the consumer's `events` set at `src/devops_cli/server/routes/webhooks.py:344:events=CONST_ROADMAP_WEBHOOK_EVENTS,`, which admits a delivery before any refusal runs, so the case would answer `accepted` and not `no_subscriber`.

## Security

A GitHub webhook body is untrusted input into the Service. This change parses the comment of an `issue_comment` delivery and refuses every delivery that is not a created comment of a trusted author, before any GitHub request, so no text of an outside account reaches a roadmap job. A person must confirm that each repository hook sends `issue_comment` and that `CONST_ROADMAP_TRUSTED_AUTHORS` holds only associations with write access. `tests/server/routes/test_roadmap_consumer_comment_events.py` fails when a bot, an untrusted author, an edited action or a pull request comment reaches `deliver` or spends a request.
