# Design

## Decisions

- **Declare the `pull_request` `closed` key in `CONST_ROADMAP_STAGE_BATCH_KEYS`, the constant that the `stage` and the `implement` rows already name.**: One constant serves both rows (`src/devops_cli/roadmap/run.py:1108:batch_keys=CONST_ROADMAP_STAGE_BATCH_KEYS,`), so the two rows cannot drift, and `src/devops_cli/roadmap/run.py:1456:return any(key in batch_counts for key in row.batch_keys)` already reads the keys, so the due logic needs no change.
- **Wake the other lanes from `scoped_update_wakes_lanes` for a `pull_request` `closed` delivery, and keep the router unchanged.**: `src/devops_cli/roadmap/run.py:1307:("pull_request", "closed"),` makes the action scoped, so `src/devops_cli/server/routes/webhooks.py:329:if service_manager.enqueue_scoped(repo, lane, run_scoped):` returns before the whole-round trigger; that file therefore stays as it is, because `src/devops_cli/server/routes/webhooks.py:317:if scoped_update_wakes_lanes(delivery, outcome):` already calls the widened predicate.
- **The `implement` row handles a merged plan pull request on its own lane.**: Its round owns the status sync and the Job create: `src/devops_cli/roadmap/implement/implement_submit.py:725:swept = sync_statuses(store, repo=repo, planned=planned).failed`, and it lists the running Jobs of the item at `src/devops_cli/roadmap/implement/implement_submit.py:721:held = {job.name: job for job in api.list_jobs({CONST_ROADMAP_IMPLEMENT_JOB_LABEL: label})}` before it submits one.
- **The `stage` row handles an unmerged closed plan pull request, because its round holds the clone that the branch delete needs.**: The round reads the rejections at `src/devops_cli/roadmap/stage/stage.py:3383:rejections = _rejections(store, repo, source, heads, planned, item_number)` and writes them at `src/devops_cli/roadmap/stage/stage.py:4222:def _reject_plan(`, with the comment rules at `src/devops_cli/roadmap/stage/stage_rejected.py:132:def comment_text(pull: int, reason: IssueComment | None) -> str:` and the trusted reason at `src/devops_cli/roadmap/stage/stage_rejected.py:103:def reason_comment(`.
- **Read the merge state, the reason and the branch from GitHub in each round, and add no payload field for them.**: `src/devops_cli/models/webhooks.py:43:class WebhookPullRequest(BaseModel):` holds `src/devops_cli/models/webhooks.py:48:number: int | None = None` alone, and `src/devops_cli/models/webhooks.py:80:if self.pull_request is not None and self.pull_request.number is not None:` already gives the consumer its subject, so a merge field would be read by no code.
- **Keep the reconciling polls, and let the delivery only cut the delay.**: GitHub never sends a failed delivery again, so the sweep stays the source of truth (docs/adr/0017-each-subscribed-webhook-event-runs-the-update-scoped-to-it.md) and the interval of each row remains the fallback.
- **Write the flow into step 8 of `docs/CLUSTER.md`, which holds the batch keys of each row, and into the `all` stack row of `k8s/README.md`, which criterion 4 names.**: `docs/CLUSTER.md:47:A label change or a close makes` holds the sentence that names the rows each webhook key makes due, and `k8s/README.md:23:All components from the stacks above, and the` sends the reader of the `all` stack to `docs/CLUSTER.md`, so the event flow gets one short statement there as criterion 4 asks.
- **Keep the event-to-lane routing table of #5555 out of this change, and express the wake as one more case of the existing predicate.**: `find_issues` lists "#5555 open feat(service): webhook events wake the lanes of their jobs", and its routing table does not exist at this commit: `src/devops_cli/server/routes/webhooks.py:303:scoped = SCOPED_UPDATES.get((event, action))` is the only routing that a delivery reads, so this change adds a case to `scoped_update_wakes_lanes` and leaves the table to #5555.

## Rejected alternatives

- **A new status-lane handler that fetches a clone, calls `sync_statuses` and calls `run_implement_round`.**: The `implement` row already owns that work on a clone of its own: `src/devops_cli/roadmap/implement/implement_submit.py:725:swept = sync_statuses(store, repo=repo, planned=planned).failed`.
- **A scoped update that calls the rejection code of the stage row for an unmerged plan.**: `src/devops_cli/roadmap/run.py:1317:SCOPED_UPDATES: Mapping[tuple[str, str], ScopedUpdate] = MappingProxyType(` holds one update for each event and action, `src/devops_cli/roadmap/run.py:1320:**{key: _SCOPED_WATCH for key in _SCOPED_WATCH_ACTIONS},` maps the closed action to the watch row, and the stage round already reads the rejections at `src/devops_cli/roadmap/stage/stage.py:3383:rejections = _rejections(store, repo, source, heads, planned, item_number)`.
- **Only the watch row's status sync, with no implement round.**: The watch row writes the label but submits no Job, and the Job comes from the implement round at `src/devops_cli/roadmap/implement/implement_submit.py:721:held = {job.name: job for job in api.list_jobs({CONST_ROADMAP_IMPLEMENT_JOB_LABEL: label})}`.
- **Remove `("pull_request", "closed")` from the scoped watch actions, so the delivery becomes a whole-round hint that makes every lane due.**: `src/devops_cli/roadmap/run.py:1315:_SCOPED_WATCH = ScopedUpdate(job="watch", runner=_watch_one)` serves the base requirement that a pull request delivery runs the watch row scoped to its pull requests, and every lane would then run a round for one delivery.
- **A new payload model with `state`, `merged` and `closed_at`, or flat pull request fields on the payload.**: `src/devops_cli/models/webhooks.py:43:class WebhookPullRequest(BaseModel):` holds `src/devops_cli/models/webhooks.py:48:number: int | None = None` alone, and `src/devops_cli/models/webhooks.py:80:if self.pull_request is not None and self.pull_request.number is not None:` already gives the consumer its subject, so the added fields would be read by no code.
- **Remove the polling intervals now that a delivery makes the rows due.**: docs/adr/0017-each-subscribed-webhook-event-runs-the-update-scoped-to-it.md keeps the poll as the reconciler, and GitHub never retries a failed delivery, so a lost delivery would delay an item until a person acts.
- **Document the flow in `docs/ROADMAP_WORKFLOW.md` alone, which holds the workflow of one item.**: `docs/CLUSTER.md:47:A label change or a close makes` holds the batch keys of each row, which is the setting that this change moves.
- **Route the closed delivery to the lanes through the event-to-lane routing table of #5555.**: `find_issues` lists "#5555 open feat(service): webhook events wake the lanes of their jobs", and `src/devops_cli/server/routes/webhooks.py:303:scoped = SCOPED_UPDATES.get((event, action))` is the only routing that a delivery reads at this commit, so the table does not exist yet.

## Unchanged references

- `src/devops_cli/server/routes/webhooks.py` (call): It already calls scoped_update_wakes_lanes and enqueues the trigger on each woken lane, so the widened predicate needs no edit here.

## Security

Nothing new crosses a trust boundary: the change adds no route, no secret and no address, and the new batch key only makes two existing rows due for an event that `CONST_ROADMAP_WEBHOOK_EVENTS` already holds. The router checks the HMAC signature of each delivery and refuses the App bot's own writes at `src/devops_cli/server/routes/webhooks.py:270:def roadmap_consumer(service_manager: ServiceManager) -> WebhookConsumer:`. A person confirms that each managed repository's hook still sends `pull_request` and that the new text of `k8s/README.md` names no secret, no host name and no address. `tests/roadmap/test_roadmap_run_webhook_keys.py` fails if a row becomes due for a key it does not declare, and `tests/server/test_server_service.py` fails if a consumer event leaves `CONST_ROADMAP_WEBHOOK_EVENTS`.
