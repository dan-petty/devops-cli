# Design

## Decisions

- **Each of the four gate modules that print their own problem lines writes one problem as one physical line on standard error, with its own prefix, and exits 1 when it writes one.**: `tests/gate/ruff_config.py:192:print(f"ruff configuration: {line}", file=sys.stderr)` and `tests/gate/construct_gate.py:474:print(f"construct gate: {line}", file=sys.stderr)` already print one prefixed line per problem, so the contract needs a change only to `tests/gate/startup_imports.py:569:print(f"startup imports: {line}", file=sys.stderr)` and `tests/gate/swallowed_failures.py:379:print(line, file=sys.stderr)`.
- **The row of a changed top-level gate module is the row whose `cmd` or `also_cmds` hold `CONST_GATE_ROW_SCRIPT` with that module name.**: `src/devops_cli/commands/ci.py:894:def _python_check_cmd(module: str) -> list[str]:` builds that command from the module name and `src/devops_cli/commands/ci.py:917:also_cmds=[_python_check_cmd("ruff_config")],` shows the `also_cmds` form, so no table of module to row is kept.
- **The base run of a changed top-level gate module uses a detached worktree of the merge base with no head tests overlaid, and the head run uses a worktree of the head, in folders named `gate_base` and `gate_head`.**: `src/devops_cli/ci/fail_to_pass.py:545:_archive_to_dir(root, tests_archive_args(head), dest.parent / "tests.tar", dest)` overlays the head's `tests/` on the merge-base worktree, which would run the head's copy of the module on both trees, while `src/devops_cli/ci/fail_to_pass.py:def _plain_base_tree` gives the base's own copy. The two names keep the module runs apart from the test replay's `plain_base` and `head` worktrees.
- **Both early returns of `run_fail_to_pass` count a module directly under `tests/gate/`: the `needs_proof` return and the no-tests return.**: `src/devops_cli/ci/fail_to_pass.py:1027:if not changed.source_files and not changed.gate_checks:` returns `src/devops_cli/ci/fail_to_pass.py:1033:needs_proof=False,`, and `src/devops_cli/ci/fail_to_pass.py:1036:if not changed.test_files and not changed.gate_checks:` returns a report with no outcomes, so a change of only `tests/gate/ruff_config.py` would otherwise pass with no replay or stop with the no-tests sentence.
- **The report fields of the module replay arrive in the order of the groups: the `changed_gate_modules` field in the group that makes the module need a proof, the `gate_modules` field and the count in `satisfied` in the group that replays the module, and the messages, the plan requests and the test updates in the group that formats the report.**: A test of a report field fails until the group that adds the field lands, so each group's verify holds only with the groups before it, and each step stays within its budget.
- **The group that adds the module runs to `plan_fail_to_pass` and widens the messages updates the cases of `tests/ci/test_fail_to_pass.py` that assert the plan line by line and the old texts, in the same group.**: `tests/ci/test_fail_to_pass.py:1499:assert lines[7] == "git worktree add --quiet --detach '<temp-dir>/tree' '<merge-base>'"`, `tests/ci/test_fail_to_pass.py:1504:assert lines[10:] == [` and `tests/ci/test_fail_to_pass.py:1587:("tests/test_x.py", ("a changed gate check exists", "a module of tests/gate/")),` fix the order and the conditions of the plan, and `tests/ci/test_fail_to_pass.py:762:The fix changes no tests/**/test_*.py file and adds or changes no case of` and `tests/ci/test_fail_to_pass.py:2081:it only deletes checks of tests/gate/*_checks/` fix the texts of the messages, so the group's verify fails unless it changes them.
- **A changed top-level gate module that no row runs makes the command exit 1 and name the module.**: The widened filter matches `tests/gate/**`, so a module such as `tests/gate/runner.py` reaches the command, and a silent pass would cite no proof.
- **The replay runs the `main` of the changed module once per tree, with the `src/` of that tree first on the import path.**: `src/devops_cli/ci/fail_to_pass.py:603:return [sys.executable, "-c", CONST_FAIL_TO_PASS_GATE_ROW_SCRIPT.format(module=row)]` builds that argv, and `CONST_FAIL_TO_PASS_GATE_ROW_SCRIPT` puts the `src/` of the tree first, as `src/devops_cli/ci/fail_to_pass.py:def gate_row_argv` does for a gate row.
- **The row lookup imports `get_check_specs` inside the call that needs it.**: `src/devops_cli/commands/ci.py:def get_check_specs` sits in a heavy module, and a module-level import would join the import graph of every module that imports `src/devops_cli/ci/fail_to_pass.py:def run_fail_to_pass`, which the `startup-imports` row budgets.
- **The path filter of `.github/workflows/fail-to-pass.yml` widens to `tests/gate/**` and drops `tests/gate/*_checks/**`.**: `.github/workflows/fail-to-pass.yml:19:- "tests/gate/*_checks/**"` matches no module directly under `tests/gate/`, and `tests/gate/**` covers the check packages too.
- **The living spec `openspec/specs/ci-fail-to-pass/spec.md` changes only through the spec delta of this change, which `openspec archive` writes.**: No group writes a living spec, and the requirements that name `tests/gate/*_checks/` would otherwise contradict the replay of a changed top-level gate module after the archive.
- **The help of `devops ci fail-to-pass`, the generated command documents and the Fail-to-Pass Evidence item of `CONTRIBUTING.md` change with the behavior.**: `src/devops_cli/lang/en/help.py:1122:A changed module under tests/gate/*_checks/ runs its gate row on ` and the Fail-to-Pass Evidence item of `CONTRIBUTING.md` still describe the old filter, and `docs/commands/ci.md` is generated from that help.

## Rejected alternatives

- **A JSON mode on each gate module.**: It changes the output that `uv run devops ci --check --only swallowed-failures` prints today, needs a parser for each module, and is a larger change than one line per problem (`tests/gate/swallowed_failures.py:379:print(line, file=sys.stderr)`).
- **Compare the whole standard-error text of the base run with the whole text of the head run.**: `tests/gate/swallowed_failures.py:361:*([format_over_ceiling_error(over)] if over else []),` shows one problem as a multi-line block, so a new problem can hide in a block that also holds a base problem.
- **A static table from module to row.**: It duplicates the row table of `src/devops_cli/commands/ci.py:def get_check_specs` and goes stale when a row is renamed.
- **Run `pytest` on a changed top-level gate module.**: `tests/gate/runner.py:def _checks` selects functions named `check_`, and `tests/gate/ruff_config.py:def main` shows the four modules hold only a `main`, so pytest collects no case of them.
- **Run the whole row command of `lint` or `constructs` on each tree, including its other commands.**: `src/devops_cli/commands/ci.py:917:also_cmds=[_python_check_cmd("ruff_config")],` shows the module is one command of the row, so the other commands would run on both trees and add cost and noise to a replay that proves the module.
- **Widen only the `needs_proof` guard and leave the no-tests guard as it is.**: `src/devops_cli/ci/fail_to_pass.py:1036:if not changed.test_files and not changed.gate_checks:` returns a report before any module run, so a change of only `tests/gate/ruff_config.py` would exit 1 with the no-tests sentence and name no module.
- **Run both the base and the head module in the current tree.**: The head source would answer for the base and hide the base problem, which is why `src/devops_cli/ci/fail_to_pass.py:def _plain_base_tree` checks out the merge base with no head tests overlaid.
- **Add the module runs to the plan and leave the existing dry-run and report cases of `tests/ci/test_fail_to_pass.py` as they are.**: `tests/ci/test_fail_to_pass.py:1499:assert lines[7] == "git worktree add --quiet --detach '<temp-dir>/tree' '<merge-base>'"` and `tests/ci/test_fail_to_pass.py:2081:it only deletes checks of tests/gate/*_checks/` fail as soon as the plan holds another request or the text of the message widens, so the group's verify would fail.
