# Design

## Decisions

- **The findings of the last plan comment.** The issue and the owner direction of 2026-11-12 ask for the open findings that the stage comment lists. The step reads the open findings section of the newest comment of the stage job or of the step that names the pull request (`comment_open_findings`), the section that `open_findings_section` writes. A test reads the real comment of the plan of #2530 and reads back each line that `finding_line` writes, so the reader and the writer stay one format. Only a comment of a trusted author counts (`trusted_replies`), because the findings go to the planner. The verification pass then reviews only the revision, so an attempt costs one review less.
- **The review of the head is the fallback.** When no comment lists an open finding, the step reviews the plan of the head at the latest default branch. A review that finds no open finding is the "later stage round" of `docs/roadmap/stage.md`, so the step removes the label and writes no commit.
- **Better means fewer open findings.** The step compares the open findings of the last review of the revision with the open findings before the repair. A revision with fewer open findings is pushed. A revision with the same count or more is not pushed, and the step records the attempt.
- **One repair with every open finding, then the normal rounds.** The first repair gets each open finding of the head, whatever its type, as the issue asks. Then `_verified` reviews the revision and returns it to the planner for a finding of `RETURN_TYPES`, as a stage round does. A change of `RETURN_TYPES` or of the repair rounds in `stage_verify.py` applies to this step with no edit.
- **The seam is a planner method.** `_Planner.revise` calls `_request`, `_gated`, `_review`, `_repaired` and `_verified`, and `revise_plan` builds the planner as `plan_stage` does. `_gated` judges the head plan as a kept plan (#4950): a head plan that the checks refuse gets a new first reply and uses no return. The per-item state of the planner is reset by one method, `_start_item`, which `plan` and `revise` both call. The step module holds the selection, the git writes and the GitHub writes.
- **One commit on the latest default branch.** The step writes the change folder in a detached worktree at `origin/<default>`, makes one commit with the stage title and `Plans #<n>.`, fetches the default branch again and rebases the commit, and pushes `HEAD` to the branch with `--force-with-lease=refs/heads/<branch>:<head>`. The branch then holds the latest default branch and one commit, as a stage branch does. The lease refuses the push when a person pushed after the read.
- **The change folder keeps its name.** The step takes the type and the slug from the branch of the pull request, not from the title of the item, so a retitled item keeps its branch and its change folder.
- **Attempt marks first.** The step writes `fix_plan.key`, `fix_plan.attempts` and `fix_plan.at` before the model call, as the stage job writes `stage.pending` before its push (#4051). A stop of the Service in the attempt counts the attempt, so a crash loop cannot spend tokens without limit.
- **Own comment and own keys.** ADR 0021 section 8 rule 1 lets a row write only its own keys and its own marked comments. So the step posts its own comment on the issue, after the stage comment, and does not edit the stage comment. The store refuses a repeat of the comment (#4793).
- **Mode starts in `plan`.** ADR 0021 section 8 rule 5. Mode `plan` runs the selection and logs the pull request that an attempt would take, with no model call and no write. The command by hand acts with `--confirm` in every mode, because a person chose it.
- **Bounds.** 1 plan for each round, 2 attempts for each head, 6 hours between attempts of one item, and 3 revisions for each pull request, which ADR 0021 gives the fix units ("at most 3 heads for each pull request"). Each attempt has the model limits of one stage item. The drain guard stops a new attempt.
- **Interval.** The row is due every 53 minutes and on a first run. With 1 plan for each round and 6 hours between the attempts of one item, 53 minutes takes 6 plans in less than 6 hours.

## Rejected alternatives

- **Always review the head again.** It costs one more review call for each attempt, and the review of a model can name other findings than the ones that set the label. The owner direction asks for the findings of the comment. The review stays as the fallback for a plan whose comment lists no open finding.
- **Run `_verified` alone on the head plan.** Before #5059 it returned the plan to the planner only for a finding of `RETURN_TYPES`, so a plan with only `criterion_dropped` findings, such as the plan of #2530, got no repair. It also gives no count of the open findings of the head, so the step could not tell a better revision.
- **Edit the stage comment.** ADR 0021 section 8 rule 1 forbids a row to write the marked comment of another job, and the store has no edit of a comment of an item.
- **A rebase of the branch and a new commit on top.** The branch then holds two commits of one plan, and a conflict of the rebase stops the attempt. One commit on the latest default branch has the form that the stage job writes and cannot conflict.
- **Start the row in mode `on`.** ADR 0021 section 8 rule 5 starts each new row in mode `plan`, and #5056 keeps that rule for each row that replaces no live row. `fix_plan` replaces no row.
- **A new planner or verifier for the step.** AGENTS.md rule 3, and the issue: the step reuses the stage code.
