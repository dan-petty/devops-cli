# Design

## Decisions

- **The image.** `ghcr.io/renovatebot/renovate:44.239.1@sha256:7dba1a3b…656b`, the index digest from a registry read on 2026-11-16. 44.239.1 is the newest release that is at least 3 days old. The default image, not the full image: `binarySource: install` installs the tools that a repository asks for.
- **Two init containers.** `seed` runs first, then `token`, so the token is minted as late as possible. The Job deadline (3000 s) counts from the start of the Job, and the token (3600 s) from its mint, so the token outlives the pod.
- **The seed copy.** The issue named emptyDir volumes on `/tmp`, `/opt/containerbase`, `/var/lib/containerbase` and the home folder. The image layers show that a plain emptyDir hides build files: `/opt/containerbase` holds the tool folders, the containerbase database and the CA link that `prepare-tool all` and `install-tool` wrote, and `/home/ubuntu` holds the cache links and `bin/`. So `seed` copies both folders (`cp -a --no-preserve=ownership --parents`) into one emptyDir, and Renovate mounts the two copies with `subPath`. This is the usual Kubernetes pattern for a writable image folder under a read-only root. `/var/lib/containerbase` gets no volume: root owns it with mode 0755, so user 12021 never writes it, and an emptyDir would hide the markers of the prepared tools and the CA bundle. `/tmp` is a plain emptyDir: the entrypoint runs `containerbase-cli init tool all` when `/tmp/containerbase` is missing.
- **The user.** User and group 12021. The image user `ubuntu` has primary group 0, but each file of the image that Renovate reads is readable by other users (the layers were listed), and a group above 10000 keeps Trivy KSV-0021 quiet. The token init container runs as the same user, so the token file (mode 0600) is the Renovate user's. `fsGroup` does not change the owner of a file.
- **The token.** The volume `token` is a memory emptyDir of 1 MiB. `config.js` reads the file as it is (no newline). The key `'token'` is quoted, as in `config.json`: Trivy KSV-0109 reads an unquoted `token:` line of a ConfigMap as a stored secret, and the line holds a file read.
- **Optional keys.** The three keys of `devops/renovate` are optional, and the row is in `OPTIONAL_FEATURE_SECRETS`. With required keys, every push of stack `devops` (also each `deploy-stack --stack devops`) failed on a workstation with no Renovate settings: the push tests showed it. The `envFrom` of `token` is optional, so with no Secret the container starts, names the settings that are not set and exits 1, and the Job ends at once instead of at its deadline.
- **The config files.** `config.json` holds the settings, so a Python test reads them; `config.js` adds the token. Renovate loads a `.js` file with `import()`, and a file with no `package.json` near it is CommonJS.
- **Onboarding waits for #4913.** `onboarding: false` with `requireConfig: required` makes Renovate skip a repository that has no config, with no onboarding pull request. On 2026-11-16 only devops-cli has one (`.github/renovate.json`). `onboardingConfig` already extends the shared preset of #4896, so #4913 changes one value.
- **The allowed commands.** One anchored regex for each `postUpgradeTasks` command of `.github/renovate.json`. A test fails when a command has no regex or a regex matches no command, so #4902 adds its regex with its command.
- **Telemetry and logs.** `OTEL_EXPORTER_OTLP_ENDPOINT` names the cluster collector (Renovate sends OTLP/HTTP spans with the service name `renovate`). `LOG_FORMAT=json` gives one object per line, for the measurements of #4909.
- **The perimeter.** `renovate-perimeter`, in the form of `crawl4ai-perimeter` and `searxng-perimeter`: no ingress, and egress to CoreDNS, the collector on 4318 and public TCP 443 with the except list of `devops-default-perimeter`. The issue named it `renovate-egress`; the policy also denies ingress, so it takes the name of its two siblings.
- **The documents.** The issue asked for the Renovate section in `k8s/README.md` in the SearXNG form. The SearXNG section, with its license bullet, is in `docs/CLUSTER.md`, which tells the services of namespace `devops`. So the Renovate section is there, and `k8s/README.md` gets the Secret rows, the Secret note with a link, and the folder line.
- **The deploy path.** `deploy-stack --stack devops` applies the four files, as for SearXNG. Two clusters that run Renovate as the same App push to the same branches, so the documents say to push `devops/renovate` to one cluster only.
- **Resources.** First values, which #4909 measures: Renovate asks for 500m and 1 GiB, with limits of 2 CPU and 4 GiB; emptyDir limits of 4 GiB (`/tmp`) and 6 GiB (tools and home).

## Rejected alternatives

- **`readOnlyRootFilesystem: false`.** Trivy KSV-0014 is HIGH, and the acceptance criteria allow no HIGH finding.
- **A plain emptyDir on `/opt/containerbase` and `/var/lib/containerbase`.** It hides the build files, as above.
- **`autodiscoverFilter` limited to devops-cli.** It also works, but #4913 would have to change the scope and the onboarding together. `onboarding: false` keeps the scope on the App installation, as #4893 decided.
- **A shell in the Renovate container to read the token into `RENOVATE_TOKEN`.** It puts the token in the process environment and overrides the image entrypoint.
- **Suspend the CronJob in the product base and turn it on in the homelab overlay.** It stops a second cluster from running Renovate, but it adds a CronJob patch that the manifest readers do not see. The Service App has the same exposure today, and a document line covers it.
