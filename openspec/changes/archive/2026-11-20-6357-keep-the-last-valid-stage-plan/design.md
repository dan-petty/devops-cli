# Design

## Decisions

- **Handle the schema failure in one method, `_ask_return`, for each request that carries an earlier plan: the reply to a gate return in `_returned` and the revision of a repair round in `_repaired`.**: The stage log of 2026-11-18 to 2026-11-20 (Loki, `{container="stage"} |= "roadmap job result" |= "class=parser"`) has 21 parser failures. 6 are first replies (`plan_calls=1 gate_returns=0`). 9 are replies to a gate return with no review round (`verify_rounds=0`, `gate_returns` 1 to 6), such as #6327 with `plan_calls=2 gate_returns=1`. 6 come after a review round. The examples of the issue (#4012 with 4 gate returns, #4075 with 3, #6327 with 1) are replies to a gate return, so a fix in the repair round alone leaves most of the failures.
- **Keep the earlier plan in the caller's value: the refused reply `outcome.reply` for a gate return, and `change.proposal` for a repair round.**: `_ask_plan` returns only a reply that the schema accepts, so a failed reply raises before the plan that the caller holds changes.
- **Reuse `roadmap.stage.gate_returns` for the schema return, and pass the count that a revision used into `_returned` as the keyword argument `used`.**: The setting already counts the returns of the planner loop, and the issue requires the schema return to count in the same budget. So the bound of planner calls in the docstring of `plan` stays.
- **Compare the findings of a reply only with a reply that the checks refused in the same call of `_returned` (`returns > used`).**: A schema return of the revision follows no judged reply. Without this rule, the first judged revision is compared with an older refused reply of the item, in the log of `log_gate_findings` and in the decision of `gate_extension`.
- **Keep one output retry for a first plan ask and end it with the class `parser`.**: No earlier plan exists to return, and the replies spec sets one output retry for a reply that breaks the schema.
- **Re-raise the schema error when the gate returns are spent.**: `src/devops_cli/ai/client/models.py:115:class StructuredOutputValidationError(AIClientError):` gives the class `parser` through the failure taxonomy, which the issue requires for the exhausted case.
- **Carry the problem of the request and `violation_summary` of the failed reply as the problem of the return (`stage_schema_return`).**: `violation_summary` gives the count and up to three violation lines with location and type. The violations alone would drop the findings of the checks or of the review, which the planner must still fix, and they name fields of a reply that the planner does not see in `previous`.
- **Build the retry test on `checking_replies()` and the violation test on a queued schema error that carries the violation texts.**: `tests/support/fakes/model.py:350:def chat_structured(` raises at once and fills no violation texts, while `tests/support/fakes/model.py:383:def checking_replies(self) -> ModelFakeReplies:` runs the real retry of one ask, so each test shows what it claims.
- **State the rule in the stage item of `docs/CLUSTER.md`, beside the sentence that already gives the gate returns of a refused reply, and in the paragraph of the returns in `docs/roadmap/stage.md`.**: Both give `roadmap.stage.gate_returns`, and `docs/roadmap/stage.md` says how a refused reply after the last return fails the item.
- **Keep the new first reply after a refused kept plan as a first reply.**: `docs/roadmap/stage.md` calls it a new first reply that uses no return, and the kept plan stays in its file for the next attempt, so a schema failure there loses no work.

## Rejected alternatives

- **Add a second output retry for a first plan ask.**: No earlier plan exists to preserve, and a second retry hides a schema defect at one more model call per item.
- **Treat a first reply with no plan as a gate return.**: A gate return needs a plan to revise, and no plan exists before the first reply.
- **Add a separate setting for schema returns.**: It adds a second budget for the same planner loop and a new configuration key where `roadmap.stage.gate_returns` already counts returns.
- **End the item at once on a revision schema failure, as today.**: That loses the last schema-valid plan, which is the defect of #6357.
- **Handle only the revision of a repair round.**: The stage log shows that 9 of the 15 parser failures with an earlier plan are replies to a gate return, which this leaves as they are.
- **Send only the violations as the problem of the return.**: The planner then loses the findings that it must fix, and reads violations of a reply that is not in the request.
- **Keep the last plan in a module-level cache.**: It adds shared state to a job that runs one item at a time, and `change.proposal` already holds the value.
- **Reread the last plan from the plan record file.**: It adds file I/O and a second source of truth for a value that the caller holds in `change.proposal`.
- **Drive the retry test with two queued schema errors on the plain fake.**: `tests/support/fakes/model.py:350:def chat_structured(` raises at once, so two errors are two asks and two gate returns, and its error holds no violation texts; `tests/support/fakes/model.py:383:def checking_replies(self) -> ModelFakeReplies:` runs the real retry of one ask.
