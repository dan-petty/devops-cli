# Design

## Decisions

- **The unit is the new tokens of a reply.** `new_tokens(usage) = input_tokens - cache_read_tokens + output_tokens`. These are the tokens that the provider bills at the full input or output price. A cache write is input that the cache did not serve, so it counts. The function takes any object with the three counts (`TokenCounts`): a pydantic-ai `RequestUsage` and a `StepOutcome`.
- **The step and the item count in the same unit.** `limit_hooks` adds the new tokens of each reply to the step. `JobRun._item_spend` adds the new tokens of the outcomes of this Job to the `new_tokens` of the record `implement.spend`. The ceiling is in the same unit as the step budget.
- **The record names the unit of its count.** The outcome, the tier spend and the record hold `cache_read_tokens` next to `input_tokens` and `output_tokens`. The record also holds `new_tokens`, the count of the item budget in its unit, and the next Job adds its own new tokens to it. A record that an older version wrote has no `new_tokens`, so its Jobs count 0 by the rule of #4070 that a missing key takes its empty value. Its input tokens hold cache reads in an unknown share: as new tokens, the input of the old Jobs, about 98% cache reads, would use most of the item budget of a continuation, or all of it. A record with no unit cannot carry its unknown share forward either, because the next Job would write a sum that mixes the two units.
- **The defaults keep their values.** The default ladder is the local `devops-coder` group, and a local route reports no cache reads, so it counts each input token in both units. A runner Job request on the local route gave 39274 input tokens and 201 output tokens: 8000000 is about 200 such requests, as before. On the cached hosted route a request gave about 1930 new tokens, so 8000000 is about 4100 requests, and the 90 minutes of `step_time_limit_seconds` (about 540 requests at 10 seconds each) stop the step first. The cost of such a step is about USD 0.2. The ceiling stays twice the budget (#4505), and the item budget stays 20000000.
- **The test model reports cache reads.** `ModelScript(cached=n)` gives each streamed reply n more input tokens, all of them cache reads, so a test runs a real step on a reply that the cache served. The `FunctionModel` of pydantic-ai estimates the usage of a stream and takes no usage from the script.

## Rejected alternatives

- **A budget in USD.** The project prices the gateway group itself (#4454): genai-prices 0.1.13 does not know `deepseek-v4.1-flash-1017`, so `UsageLimits.cost_limit` and `SpendLimits` cannot price it alone. A local tier costs USD 0, and a model with no price gives USD 0 with a warning, so the budget never stops such a step. The day and item budgets in USD are #3066.
- **The uncached input tokens only.** The output tokens cost 3 times the input price (0.2352 against 0.0784 USD for each million tokens), and a count without them does not bound the output.
- **The number of requests.** It does not change with the size of the context or with the cached share. A provider that caches nothing costs 30 times more for each request.
- **The raw input tokens, as before.** 98.6% of them were cache reads at 3% of the input price, so the budget stopped steps that made progress after USD 0.034 to 0.052.
- **Defaults from the cached route (1000000 and 2500000).** They fit only the cached hosted route. A local step on the default ladder then stops after about 25 requests, where it made about 200.
- **A budget for each tier or kind of route.** It adds settings and a choice of budget for each request, and a step that moves from a local tier to a hosted tier needs a rule for the count that it already has. The kind of a tier does not say whether its route reports cache reads: the hosted `claude-sonnet-5-5` reports none. With the old values, the time limit bounds a cached step, and the count bounds a step on a route with no cache reads, as before.
- **The cached reads at their price ratio (a weighted sum).** It needs the price of each tier at the time of the count, as a USD budget does. The time limits bound the number of requests, and so the cache reads.
