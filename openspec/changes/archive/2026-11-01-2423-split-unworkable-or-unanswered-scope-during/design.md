# Design

## Decisions

- **`deferred` is a new reply key. `split_offs` and `fits_one_pr` stay.** `split_offs` lines are plain text with no title or body, and `fits_one_pr: false` makes `check_ready` return false (`refine.py:957`), the opposite of this issue. `NextStep.SPLIT` asks a person to split an item that is too big for one pull request. A deferred part is a part that cannot be built or decided now. The two cases have different results, so they have two keys. Each deferred part is `DeferredPart(title, body)`, with `extra="forbid"` like the other reply models, and at most `_MAX_DEFERRED_PARTS` (3) of them. The cap bounds the model calls of one item: intake makes one embedding call and one proposal call for each part.
- **The model removes the part. Code does not check that it did.** The prompt tells the model to leave the part out of `acceptance_criteria`, `key_questions`, `suspected_block` and `dependencies`. The proposal that remains must pass `check_ready` as it is. Code adds no text match for this, because a part is a judgement. A proposal that still holds an open question or a block stays New, as it does today, and files nothing.
- **Refine files the parts only when the item is Ready.** A part moves out only if the rest of the item moves forward. An item that stays New files no issue, so a round that makes no progress makes no new item.
- **Plan and apply stay apart.** `refine_one_item` calls `plan_intake` once for each part (a `NewCandidate` with no `source`). `apply_refine` calls `apply_intake` for the plans, and writes the body, the status and the comment only after every part is filed. `intake_candidate` is these two calls, so refine reuses intake and builds no second path. The intake model comes from a new keyword `intake_model` of `plan_refine` and `refine_one_item`, which defaults to `build_intake_model()` and is built only when a part exists. A test passes its own model through this keyword, like `investigator`.
- **The link is a body line, a sentence in the Ready comment and a record key.** The new body starts with `Split from #<issue>.`. Refine adds `Moved to new items: #a, #b.` to the Ready comment, so the comment cap (2 in 24 hours) is not affected. The job record key `refine.deferred` holds the numbers, comma separated, in the order filed.
- **A part is filed once.** The request to the model gains `deferred_issues`: the number and title of each issue in `refine.deferred`. The prompt tells the model not to defer them again. As a deterministic backstop, refine drops a part whose title, with the white space joined, is the title of a recorded issue. A round that files only some parts records those numbers, leaves the body and status as they are, and logs a warning. The next round sees the recorded parts and files the rest.
- **A part that intake cannot place keeps the item New.** When the intake decision for a part is `Outcome.SKIP`, or `plan_intake` raises `SecurityError` for the text, the item is not Ready. The next step is `NextStep.PERSON` and the detail names the part. Refine writes the section and the comment as it does for any item that waits. Nothing is filed. A `ConfigurationError` (no `.github/labels.yml`) and `ModelGatewayUnreachableError` stop the plan phase, which writes nothing, as intake does.
- **Model text is sanitized.** The title and the body go into a public issue. Refine passes them through `sanitize_text`, as it does for the section and the comments, before it builds the `NewCandidate`.

## Rejected alternatives

- **Link the new issue as a sub-issue of the original (`NewCandidate.source`).** Intake then calls `store.add_sub_issue` (`intake.py:1272`). The original has `sub_issues > 0`, so the stage job calls it a tracker and leaves it out (`stage.py:351`, pinned by `test_a_tracker_is_left_out_under_the_wide_default_filter`). The workable scope would never get a plan. This is the reason refine passes no `source`. The cost is that intake compares the part with the original in its check for duplicates. The verdict is a flag and never an action (`intake.py` module text), so a wrong flag costs one comment line.
- **Reuse `split_offs` for the parts.** A split asks a person to act and sets `needs_split`. See the first decision.
- **File the parts at plan time.** `plan_refine` writes nothing, and the dry-run rule says a plan makes no write. Filing at plan time would also file for an item that `apply_refine` skips when the body changed.
- **Let the model call intake as a tool.** The model stays read-only. A tool would add a second write path and move pacing out of the store.
- **Call `intake_candidate(confirm=True)` in `refine_one_item`.** This files before apply and breaks the plan and apply split above.
- **Send the whole item to a person.** This is the behavior that #2423 reports.
