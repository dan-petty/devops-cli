# Design

## Decisions
- **The judge is one function behind a Protocol.** `ShortlistJudge.judge(case) -> Judgement` takes a `ShortlistCase` (the anchor, the members, their texts and the tool evidence) and returns the group fields and one `MemberVerdict` for each member: the action, the reason and the citations. The run in `consolidate.py` never sees how the verdicts were made. `GatewayShortlistJudge` does the proposal call and the refutation call. A judge that asks another model, such as a decision model with one question for each member, replaces it and keeps the rules in code. This change builds no second judge.
- **The model only flags.** The plan is a local file. A verdict never closes, drops, relabels or moves an item (the rule of intake for duplicates). The plan holds actions for a later apply (#3743), which a person confirms.
- **Code owns the rules.** After the judge answers, `settle` cuts the answer down in this order: an anchor outside the shortlist ends the group; members outside the shortlist go; a started item goes from the members; an item with a milestone gets `link` in place of `merge`, `child` or `close-when-anchor-merges`; an action that the shape does not allow becomes `link`; a group with no non-link action gets the shape `link-only`; a cited `#N` or `path:line` that does not exist is dropped and recorded. The same rules run again on a judgement that is read from the plan file, so a changed board never meets an old verdict.
- **Rules that need no model run first.** The started items and the members reopened after a close as a duplicate of the anchor leave the shortlist before the judge sees it, so the model reads no token for them. A shortlist whose members all link to the anchor already is not judged.
- **A group id is the hash of its membership.** `g<anchor>-<8 hex of sha256 over the sorted member numbers>`. A decline stores the id in the job record of the anchor (`consolidate.declined`, ids joined by commas). A change of members gives a new id, so the group returns with no extra rule.
- **The plan file is the record of the model output.** Each judged shortlist is saved to `<date>.progress.json` as soon as it is done, with the hash of its case. The final plan `<date>.json` is written when every shortlist is done, and the progress file is removed. A gateway that does not answer ends the run with the final plan unwritten, and the progress file keeps the shortlists that were done. A rerun reads the progress file and the last plan, and makes no call for a case with the same hash. A group that an earlier plan also holds is marked `carried`, so a second run over an unchanged board proposes nothing new.
- **A case hash.** The hash covers the texts of a person of the anchor and the members, their titles and the tool evidence, and the version of the prompts.
- **Pending closes.** `close-when-anchor-merges` actions of the earlier plan stay as `pending_closes` while the anchor is open; the plan drops one when the anchor is closed as completed or not planned, or when the member is closed.
- **A failure uses the taxonomy.** An unusable reply (`StructuredOutputValidationError`) gives `FailureClass.PARSER` with `StepName.JUDGE` for that shortlist; the run goes on. A gateway that does not answer raises `ModelGatewayUnreachableError` and ends the run.
- **A limit.** `--limit` caps the shortlists judged by one run, the strongest evidence first, with a default of `DEFAULT_ROADMAP_CONSOLIDATE_JUDGED`. The plan counts the unjudged rest. It is a cost bound for the first runs on a full board.
- **Where the files are.** `consolidate.py` holds the plan, the rules and the run. `consolidate_judge.py` holds the seam, the reply schemas and the model judge. The embedder and the client are built in `consolidate_judge.py` from the AI settings (`ai.for_task("embedding")` and `ai.for_task("analysis")`).

## Rejected alternatives
- **A new task key `consolidate`.** The issue forbids it, and the `analysis` task serves refine in the same way.
- **Write the verdicts to GitHub as comments.** The issue requires a local plan, and apply is #3743.
- **A local database for declines.** ADR 0002 makes the job record the place for job state, and it needs no second store.
- **A board field for status and milestone.** ADR 0016: no roadmap job reads a board.
- **Free-text evidence parsed with a regular expression.** The reply schema holds the citation as fields (`issue`, or `path` and `line`), so no parser runs on model text.
- **A second judge in this change (Jev).** The owner decided to build the issue as written and to measure Jev after it merges. The seam is the only preparation.
- **Write the final plan after each shortlist.** It would leave a plan on disk after a failed run. The issue requires that a gateway failure writes no plan.
