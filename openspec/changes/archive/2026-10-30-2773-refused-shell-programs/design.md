# Design

## Decisions

- **One table of habits, in `config/commands.py`.** `IMPLEMENT_SHELL_REPLACEMENTS` maps a program that the model asks for to the text of its replacement. Both the refusal and the prompt use it. The values are markdown that reads after "Instead of `<program>`:", for example "`uv run python`" or "the tool `read_file`". The first sentence of a value is the replacement. The value of `python` and `python3` adds that `python -m pip` is not allowed, as `uv run python -m pip` passes the shell. The table holds `python`, `python3`, `pytest`, `pip`, `pip3`, `cat`, `head`, `tail`, `ls`, `find`, `grep`, `rg` and `cd`. A program that the table lacks gets the list of allowed programs instead.
- **The hint is a `Hooks` capability in its own module.** `implement_shell_refusal.py` holds `shell_refusal_hooks()`. Its `wrap_tool_execute` calls the handler. When the handler raises a `ToolRetryError` for a shell command and a `PermissionError` is in the cause chain, the hook raises `ModelRetry` with the original text, a space and the hint. The hook reads no part of the original text: it cuts it to `CONST_ROADMAP_IMPLEMENT_ERROR_CHARS` and passes it on, as the shell echoes the first word of the command with no limit. Every other error passes through unchanged. The log of #2758 stays a log; it does not change the text that the model reads.
- **The hint depends on the first word.** A word in the table gets its replacement. A word in `IMPLEMENT_SHELL_PROGRAMS` was refused for an operator or for an interactive command, so it gets the rule of one command in each call and no `cd`. Any other word gets the list of allowed programs and the `uv run` form. The first word is read with `shlex`, as the shell of the harness reads it. A command that `shlex` cannot read gets the list of allowed programs.
- **The log and the hint share two public functions.** `command_word(args)` gives the first word of the `command` argument, or `None` when the call has no command or the command has no word. `is_policy_refusal(error)` walks the `__cause__` chain for a `PermissionError`. Both were private in `implement_tool_log.py`; the new module needs them. A third function, `logged_program(word)`, turns the word into what the log shows.
- **Only a known program is logged.** `logged_program` returns the word when it is a program of `IMPLEMENT_ALLOWED_PROGRAMS` or a key of `IMPLEMENT_SHELL_REPLACEMENTS`. Any other word gives "other". The model can read a password or a token from a file and run it as a command, and the log and the stop comment on GitHub must not show it. The set is fixed in the code, so the count of programs in the reason stays small by design.
- **The counts are a `Counter` by program.** `ToolCallLog.refused` becomes a `Counter[str]`. `ToolCallLog.refused_text()` gives the text for the reason: the programs from the most refused to the least, as "python 4, cd 2". It shows `CONST_ROADMAP_IMPLEMENT_REFUSED_PROGRAMS` programs at most. The rest join the count of "other". With no refusal the text is "0", as before. `ToolCallLog.hooks()` stays the only way to add the log to an agent.
- **The prompt table is static text, pinned by a test.** The prompt loader reads a file and has no template. A test checks that the line of allowed programs lists `IMPLEMENT_SHELL_PROGRAMS` in order, that the table has one row for each entry of `IMPLEMENT_SHELL_REPLACEMENTS` and none other, that each row has the program and the replacement of the table, and that each replacement names an allowed program or a tool that the agent has. The test fails when the prompt, the table and the allowlist disagree.
- **The agent takes the hint capability after the log.** `build_agent` lists `LocalWorkspace`, the tuned `Coder`, the hint capability and then the log. The log is outermost, so it sees the error after the hint. The hint keeps the cause chain (`raise ... from`), so the log still counts the call as refused.

## Rejected alternatives

- **Set the text in `Shell`.** `Shell` and `ShellToolset` have no setting for it (see Feasibility in the proposal).
- **A subclass of `ShellToolset` that overrides `_check_command`.** The method is private, and `Shell._make_toolset` builds the class itself. A subclass needs a subclass of `Shell` too, and breaks on a rename in the library. `Hooks` is a public seam.
- **Change the text in the log hook.** The log would then be a log and a rewriter. Two reasons to change, one class. Rejected.
- **Allow `python`, `pytest` or `cat` in the shell.** The issue asks to keep what is allowed. `uv run python` gives the same result inside the lockfile environment, and the file tools cover `cat`, `ls`, `grep` and `find`.
- **Write the program of every refused command to the log, or every bare word.** A command can start with an assignment that holds a secret, a path, an escape sequence, or a short password that the model read. Only a known program keeps the log safe and still shows `python` or `cd`.
- **Raise `CONST_ROADMAP_IMPLEMENT_TOOL_RETRIES`.** It hides the loop and costs more requests. The hint should end the loop at its cause.
- **Render the prompt table from the constant.** The prompt loader has no template, and a template engine for one table is more code than a test that compares two texts.
