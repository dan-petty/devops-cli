# Design

## Decisions

- **Add `pull_request`, `pull_request_review` and `check_suite` to the event set at `src/devops_cli/config/constants.py:4006:CONST_ROADMAP_WEBHOOK_EVENTS: Final[frozenset[str]] = frozenset(`, and name the routed actions in the table at `src/devops_cli/roadmap/run.py:1271:SCOPED_UPDATES: Mapping[tuple[str, str], ScopedUpdate] = MappingProxyType(`.**: The owner decision D8 of 2026-11-13 names those events, and `devops repos onboard` requires the one event set of each repository hook, so the hook events and the routed actions never drift apart.
- **Run the watch row scoped to the delivered pull request numbers, in place of a scoped `stage_ready` pass.**: The owner decision D8 replaces the scoped `stage_ready` with a scoped sweep, and the status lane holds the row `watch` at `src/devops_cli/roadmap/run.py:1092:name="watch",`.
- **Add minimal frozen pydantic models for `pull_request` and `check_suite` beside the payload model at `src/devops_cli/models/webhooks.py:43:class GitHubWebhookPayload(BaseModel):`.**: They follow that model and read only the numbers that routing needs, and ADR 0009 keeps one parse in the router.
- **Read a check suite's numbers from `check_suite.pull_requests[].number`.**: The stage record holds a pull request number at `src/devops_cli/roadmap/watch_row.py:763:rec = item.job_record.get(StageRecordKey.PR)`, so the payload matches the record with no extra request.
- **Carry the numbers of a delivery in one optional tuple, `pull_numbers`, on the record at `src/devops_cli/roadmap/run.py:668:class WebhookDelivery:`.**: A check suite names several pull requests, and one round for the delivery keeps one ledger write and one request scope.
- **Read a delivered number over REST only when the store records it as the `stage.pr` of an open item or the watch ledger holds it.**: That is the zero-request case of the issue: a number that neither source names sends no `GET pulls` request and no check-runs request.
- **Keep the poll of the watch row at `src/devops_cli/roadmap/run.py:1093:interval=timedelta(minutes=DEFAULT_ROADMAP_WATCH_INTERVAL_MINUTES),` and write no last success from a scoped update.**: ADR 0003 makes the poll the reconciling path, so a lost delivery costs one interval and never hides a change.
- **Trigger on every completed check suite conclusion and on every label change of a staged pull request.**: The watch row reads the check runs and the `plan/needs-fix` label itself, so the router carries no policy of the checks.
- **Keep `CONST_ROADMAP_INTAKE_BATCH_KEYS` as the `issues` keys at `src/devops_cli/config/constants.py:3985:("webhook", "issues", "opened"),`, and route the new events to the watch row only.**: Intake decides issues only, so a pull request or check suite delivery must run no intake round.
- **Keep `issue_comment` out of the consumer event set, although the owner decision has the App subscribe to it.**: ADR 0009 dropped the event after #1361 measured 940 triggers in one hour, and the App subscription is a person's step.

## Rejected alternatives

- **Add the new events to `CONST_ROADMAP_INTAKE_BATCH_KEYS` so the event set picks them up.**: `src/devops_cli/config/constants.py:3985:("webhook", "issues", "opened"),` is an intake key, and intake decides one issue only.
- **Revive a scoped `stage_ready` pass for the delivered pull request.**: `src/devops_cli/roadmap/run.py:1092:name="watch",` is the readiness row of the status lane, and `tests/roadmap/test_roadmap_limit_classes.py:87:# Replaced by DEFAULT_ROADMAP_WATCH_INTERVAL_MINUTES (#5024)` records the retirement of the stage-ready interval.
- **Parse the new payloads with gidgethub or githubkit.**: `src/devops_cli/server/routes/webhooks.py:258:payload_model=GitHubWebhookPayload,` is the typed model of the router, and ADR 0009 keeps one parse in the router.
- **Match a check suite to an item by `check_suite.head_sha`.**: `src/devops_cli/roadmap/watch_row.py:763:rec = item.job_record.get(StageRecordKey.PR)` shows that the record holds a pull request number, so a head commit would need another read.
- **Run the whole watch round for each delivery.**: `src/devops_cli/roadmap/watch_row.py:893:graphql_nodes = _read_open_pulls_graphql(owner, name)` is one GraphQL request for every open pull request of the repository, and a scoped round sends none.
- **Write a job's last success from the scoped update so the poll skips the handled change.**: `src/devops_cli/roadmap/run.py:1312:and writes no job's last success: the reconciling poll still judges every change made since` is the contract of the scoped update.
- **Add `issue_comment` to the consumer event set because the App subscribes to it.**: ADR 0009 dropped the event after #1361 measured 940 triggers in one hour, and one delivery of it would make a whole round due on each lane.
- **Add only `check_suite`, as the first draft of the issue proposed.**: The owner decision D8 names `pull_request` and `pull_request_review` too, and `src/devops_cli/roadmap/watch_row.py:856:def watch_round(` settles a new head and a review on the same round.
- **Trigger only on a successful check suite conclusion.**: The row is idempotent and reads the check runs before it marks a draft ready, so a failed conclusion needs the same read at `src/devops_cli/roadmap/watch_row.py:893:graphql_nodes = _read_open_pulls_graphql(owner, name)`.
- **Add every `pull_request` action to the scoped table.**: `src/devops_cli/roadmap/run.py:1271:SCOPED_UPDATES: Mapping[tuple[str, str], ScopedUpdate] = MappingProxyType(` holds an exact event and action key, and an action that changes no draft and no check sends no request.
- **Add a second event set for the pull request events.**: `src/devops_cli/server/routes/webhooks.py:338:events=CONST_ROADMAP_WEBHOOK_EVENTS,` is the one set that the consumer and `devops repos onboard` read.
