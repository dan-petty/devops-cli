# Design

## Decisions

- **Keep the record at item-label-times.json in the directory of the repository that holds schedule.json.**: docs/CLUSTER.md:42:`so each file has one writer` records that each state file of a repository has one writer, that directory survives a restart, and the metrics row of a repository runs in one lane, so no two writers share the file.
- **Write the file with `write_json_file` of `src/devops_cli/output/file_writer.py` and one error log line, and add no member to `StateRecord` and no series to `devops_cli_service_state_unkept`.**: The base requirement of `roadmap-service-limits` pins that gauge to the label `record` set to `budget`, `halt` or `ledger`, and this file is a derived cache of the row and no record of a Service decision.
- **Version each entry by the Item's `updated_at` and keep the label times under it.**: The issue names updated_at, and tests/support/fakes/roadmap_store.py:965:`update = changes | {"updated_at": self._roadmap.clock()}` shows that the store moves it on every write, so a label change gives a new version.
- **Cap the label-event reads of one round at `_MAX_ITEM_AGE_READS_PER_ROUND = 20` and read an Item whose `updated_at` moved before an Item that the file does not hold.**: A cold round then costs 20 event reads beside the 5 reads of `METRICS_ROW_GITHUB_REQUEST_BUDGET`, near the level before #3601, and the remaining Items are read in later rounds rather than in one burst.
- **Keep the entry of an open Item that the cap did not read, at the older `updated_at` that the file holds, and drop only the entries of Items that left the open list.**: A dropped entry would make the next round treat a deferred Item as never read and read a new Item before it, so the deferred-first rule and the cap of one round would both fail.
- **Delete the process dict and `reset_item_age_cache`, and drop its entry from the reset map of `tests/conftest.py`.**: Two copies disagree after a failed write, and the per-process copy is what the issue names as the defect.
- **Give the record path to the collection as the keyword `label_times_record`, through `_read_item_ages`, and let a round with no path keep no times.**: The collection is also the target of tests and of a command with no Service volume, so the path comes from the row that knows its repository, and `_read_item_ages` is the only function between the collection and the age code.
- **Name the `repo_dir` keyword of `_run_metrics_adapter` instead of adding a new argument to the due table.**: src/devops_cli/roadmap/run.py:1924:`repo_dir=schedule_path.parent,` shows that the due table already gives every row runner the state directory of its repository.
- **Move the request-budget test onto the record file in the same step that deletes the process dict.**: tests/github/test_github_metrics_request_budget.py:48:`def _warm_ages(github: GitHubFake) -> None:` fills the cache that the step deletes, so the step would leave a failing test behind; the warm helper and the record path land together.
- **Measure one new pod with an offline test of the request counter over 30 open Items, and state the number in the pull request body.**: The counter `devops_cli_github_requests_total` and the fake GitHub of `tests/github/test_github_metrics_request_budget.py` give the count of one cold round with no cluster, and the pull request body is the only text of the change that a person reads before the merge.
- **Deliver the live criterion as a task group whose process runs the two rollouts, and leave the two production readings of #3996 to that item.**: A criterion with no task is dropped, so group 6 states the query and the band in `docs/CLUSTER.md` and its process reads the row after each rollout; #3996 stays the open item that records the same readings after the merge.
- **Rename and modify the requirement of `project-metrics-dashboard` onto `updated_at`, and move the cap into its own added requirement.**: The requirement that the row reads the label events when the labels change is replaced by the updated_at version, and a requirement text of 500 characters or less keeps the skip rule apart from the cap of one round.
- **Name the counter and its registry place in the live-check group, and change no instrument.**: tests/telemetry/test_telemetry_instruments.py:81:`("prefix", "devops_cli_", "src/devops_cli/telemetry/instruments.py"),` declares the prefix `devops_cli_` in that file, and the plan only reads the counter, so the registry count and its test stay as they are.

## Rejected alternatives

- **Write the record as one shared file at the top of the state directory, beside service-budget.json.**: Every repository's metrics row would write that file, and docs/CLUSTER.md:42:`so each file has one writer` records that a state file has one writer; the per-repository directory already holds schedule.json.
- **Keep the process dict and add the record as a second copy beside it.**: The file write can fail, so the two copies then disagree and the next pod reads the older one; the issue names the per-process copy as the defect.
- **Write the record through `keep_state_record` with a new member `item_label_times` of `StateRecord`.**: The base requirement of `roadmap-service-limits` reads `devops_cli_service_state_unkept` SHALL be 1, with the label `record` set to `budget`, `halt` or `ledger`, so a fourth value contradicts the living spec.
- **Delete the process dict in one group and move the request-budget test to the record file in a later group.**: tests/github/test_github_metrics_request_budget.py:48:`def _warm_ages(github: GitHubFake) -> None:` fills that cache, so the budget test fails at the step that deletes it; both changes go into group 2.
- **Write only the entries that the round read, so an Item that the cap defers loses its entry.**: The next round would then see no entry for it and read it after an Item that was never read, so the deferred-first rule of the requirement fails.
- **Cap the round at 100 Items instead of 20.**: 100 label-event reads in a cold round is 5 percent of the 2000-request budget of the Service at once, and the observed level before #3601 was 222 to 305 requests an hour, so 100 reads does not hold the row near that level.
- **Version each entry by the Item's status and owner values, as the process dict does.**: The acceptance criterion names updated_at, and tests/support/fakes/roadmap_store.py:965:`update = changes | {"updated_at": self._roadmap.clock()}` shows that a write moves it, so the two values add nothing that updated_at does not give.
- **Keep the cap inside the requirement that the row reads the label events when its updated_at moves.**: The combined text is 556 characters and the most a requirement text holds is 500, so the cap moves into the added requirement `The row reads the label events of at most 20 Items in one round`.

## Unchanged references

- `openspec/changes/archive/2026-11-05-2919-stuck-item-age-metrics-and-one/tasks.md` (archive record): An archived change records what that change did at its commit, and the archive stays as it is.
- `src/devops_cli/telemetry/instruments.py` (registry place of the devops_cli_ prefix): The change adds no series, no label and no query; it only reads the existing counter, so the instruments table and the registry count stay as they are.
