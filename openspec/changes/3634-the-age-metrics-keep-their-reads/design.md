# Design

## Decisions

- **Keep the record at item-label-times.json in the state directory of the repository that holds schedule.json.**: docs/CLUSTER.md:42:`so each file has one writer` records that each state file of a repository has one writer, the directory survives a restart, and the metrics row of a repository runs in one lane, one round at a time.
- **Write the record with `write_json_file` of `src/devops_cli/output/file_writer.py` and one error log line, and add no member to `StateRecord` and no series to `devops_cli_service_state_unkept`.**: The base requirement of `roadmap-service-limits` pins that gauge to the label `record` set to `budget`, `halt` or `ledger`, and this file is a derived cache of the row and no record of a Service decision.
- **Version each entry by the Item's `updated_at` and keep the label times under it.**: tests/support/fakes/roadmap_store.py:965:`update = changes | {"updated_at": self._roadmap.clock()}` shows that the store moves `updated_at` on every write, so a label change gives a new version and the field is the version the issue names.
- **Cap the label-event reads of one round at `_MAX_ITEM_AGE_READS_PER_ROUND = 20` and read an Item whose `updated_at` moved before an Item that the record does not hold.**: A cold round then costs 20 event reads beside the 5 reads of `METRICS_ROW_GITHUB_REQUEST_BUDGET` at `src/devops_cli/github/metrics.py:88`, which is 25 requests, near the level before #3601, and the remaining Items are read in later rounds rather than in one burst.
- **Keep the entry of an open Item that the cap did not read, at the older `updated_at` that the record holds, and drop only the entries of Items that left the open list.**: A dropped entry would make the next round treat a deferred Item as never read and read a new Item before it, so the deferred-first rule and the cap of one round would both fail.
- **Delete the process dict and `reset_item_age_cache`, and drop its entry from the reset map of `tests/conftest.py`.**: Two copies disagree after a failed write, and the per-process copy is what the issue names as the defect; tests/conftest.py:120:`"reset_item_age_cache",` names the entry that goes.
- **Give the record path to the collection as the keyword `label_times_record`, through `_read_item_ages`, and let a round with no path read every Item's label events.**: `_read_item_ages` at `src/devops_cli/github/metrics.py:661` is the only function between the collection and the age code, and `callers` of `collect_project_metrics_report` answered src/devops_cli/commands/gh.py:2220, a command with no record file and no later round.
- **Name the `repo_dir` keyword of `_run_metrics_adapter` instead of adding a new argument to the due table.**: src/devops_cli/roadmap/run.py:1924:`repo_dir=schedule_path.parent,` shows that the due table already gives every row runner the state directory of its repository.
- **Move the request-budget test onto the record file in the same step that deletes the process dict.**: tests/github/test_github_metrics_request_budget.py:48:`def _warm_ages(github: GitHubFake) -> None:` fills the cache that the step deletes, so the step would leave a failing test behind; the warm helper and the record path land together.
- **Measure one new pod with an offline test of the request counter over 30 open Items, and state the number in the pull request body.**: The counter and the fake GitHub of `tests/github/test_github_metrics_request_budget.py` give the count of one cold round with no cluster, and the probe answers that `design.md` is no file at the root of the staging commit, so the pull request body is the text that states the number.
- **Deliver the live criterion as a task group whose process runs the two rollouts and reads the counter after each.**: A criterion with no task is dropped, so group 6 states the query and the band in `docs/CLUSTER.md` item 12 and its process reads the row after each rollout; the rollouts need the cluster, which the runner pod does not reach.
- **Rename and modify the requirement of `project-metrics-dashboard` onto `updated_at`, and move the cap into its own added requirement.**: The requirement that the row reads the label events when the labels change is replaced by the updated_at version, and the cap of one round gets its own scenarios, so a reader sees each rule once.
- **Name the counter and its registry place in the live-check group, and change no instrument.**: tests/telemetry/test_telemetry_instruments.py:81:`("prefix", "devops_cli_", "src/devops_cli/telemetry/instruments.py"),` declares the prefix `devops_cli_` in that file, and the plan only reads the existing counter, so the registry count and its test stay as they are.

## Rejected alternatives

- **Write the record as one shared file at the top of the state directory, beside service-budget.json.**: Every repository's metrics row would write that file, and docs/CLUSTER.md:42:`so each file has one writer` records that a state file has one writer; the per-repository directory already holds schedule.json.
- **Keep the process dict and add the record as a second copy beside it.**: The file write can fail, so the two copies then disagree and the next pod reads the older one; the issue names the per-process copy as the defect.
- **Write the record through `keep_state_record` with a new member `item_label_times` of `StateRecord`.**: The base requirement of `roadmap-service-limits` reads that `devops_cli_service_state_unkept` SHALL be 1, with the label `record` set to `budget`, `halt` or `ledger`, so a fourth value contradicts the living spec.
- **Delete the process dict in one group and move the request-budget test to the record file in a later group.**: tests/github/test_github_metrics_request_budget.py:48:`def _warm_ages(github: GitHubFake) -> None:` fills that cache, so the budget test fails at the step that deletes it; both changes go into group 2.
- **Write only the entries that the round read, so an Item that the cap defers loses its entry.**: The next round would then see no entry for it and read it after an Item that was never read, so the deferred-first rule of the added requirement fails.
- **Cap the round at 100 Items instead of 20.**: 100 label-event reads in a cold round is 5 percent of the 2000-request budget of the Service at once, and the observed level before #3601 was 222 to 305 requests an hour, so 100 reads does not hold the row near that level.
- **Apply the cap to every round, also `devops gh metrics` with no record file.**: `callers` of `collect_project_metrics_report` answered src/devops_cli/commands/gh.py:2220, so that command has no record and no later round, and a cap would drop the age of every Item after the 20th with no way to read it again.
- **Version each entry by the Item's status and owner values, as the process dict does.**: The acceptance criterion names `updated_at`, and tests/support/fakes/roadmap_store.py:965:`update = changes | {"updated_at": self._roadmap.clock()}` shows that a write moves it, so the two values add nothing that `updated_at` does not give.

## Unchanged references

- `src/devops_cli/telemetry/instruments.py` (registry place of the devops_cli_ prefix): The change adds no series, no label and no query; it only reads the existing counter, so the instruments table and the registry count stay as they are.
- `openspec/changes/archive/2026-11-05-2919-stuck-item-age-metrics-and-one/tasks.md` (archive record): An archived change records what that change did at its commit, and the archive stays as it is.
