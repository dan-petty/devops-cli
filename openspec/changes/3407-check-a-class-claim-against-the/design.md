# Design

## Decisions

- **Put the class-claim rule in the `paths` gate of `check_proposal`, beside `model_problems`.**: The golden case records the defect under that gate, the stage job and the replay run the same gate, and `model_problems` already refuses a claim about the staged source there.
- **Read a class with a new `class_sources` that greps `^class <name>` and confirms the definition with `ast`, and not with `_grep_class_paths`.**: `_grep_class_paths` greps `^class <name>(`, which matches only a class that declares a base, and the class of the issue declares none, so that helper returns no source for it.
- **Take the source of the class with `ast` and compare a whitespace-squashed quote of at least three characters with the squashed class source.**: A plan line folds a multi-line quote to one line, and a two-character quote matches almost any source, so the rule keeps the bound of the citation rule.
- **Treat a code span that starts with the name of a class, as the bare name or the name and a dotted member, as the claim, and no other span as a claim.**: A path citation or a task text that holds a class name makes no design claim, and a wider rule would refuse valid plans.
- **Give the class sources to `check_gates` and `check_proposal` as an optional keyword that defaults to None.**: A caller that gives no mapping judges no class claim, as a caller that gives no staged text reader judges no citation, and the stage job and the replay give the mapping.
- **Record the class sources in the facts of a replay case.**: The replay reads no git, so a case must hold the class text that the staged commit held.
- **Record the defect of the golden case as the type `false_premise` with the gate `paths` and a message, and add no member to the type of a defect.**: `false_premise` already names a false claim, the replay accepts a defect whose gate is a gate that finds it when the defect holds a message, and a new member would add a row to every score of the replay.
- **Give the new case the two null commits and a note that says the case reads no commit.**: The `roadmap-stage-eval-commits` row refuses a case whose base commit is `NO_COMMIT` with no note that says it reads no commit, and the change of the case never merged, so it reads no commit.
- **Add the test module `tests/roadmap/stage/test_roadmap_stage_class_claim.py`, and run the existing `tests/roadmap/stage/test_roadmap_stage_apply.py` for the writes of the stage job.**: The issue cites `tests/roadmap/test_roadmap_stage_plan.py`, which commit bff2f14f moved, the mirror folder keeps the cases of the new rule together, and the stage job's writes already have their own test module.
- **Keep the planner prompt unchanged.**: The refusal names the class and the plan section, so the planner adds the quote from the refusal, and a prompt change would need a live score run that no replay measures.
- **State a non-goal: the rule judges no class that `src/` does not define, and no plan text other than the decisions, the rejected alternatives and the feasibility lines.**: A class of the standard library is no internal class, and a what-changes item or a task names a class without making a design claim.

## Rejected alternatives

- **Reuse `_grep_class_paths` unchanged for the new reader.**: `src/devops_cli/roadmap/stage/stage_models.py:131:args = ["grep", "-n", f"^class {name}(", sha, "--", "src/"]` matches only a definition line with a base, and `src/devops_cli/roadmap/stage/stage_paths.py:117:class StagedTree:` declares none, so the reader would return no source for the class of the issue.
- **Compare each quote with the working tree instead of the staged commit.**: `src/devops_cli/roadmap/stage/stage.py:2245:read_text=partial(_read_staged_file, self._source, self._sha),` shows that the citation rule reads the staged commit, and the plan is judged at that commit, so a working tree can hold other text.
- **Scan every plan text for a class name.**: The issue names the decisions, the rejected alternatives and the feasibility lines, and a what-changes item or a task names a class without making a design claim about it.
- **Leave the rule to the model verification pass.**: The issue records that the pass keeps the draft and does not return the plan to the planner, and the replay makes no model call, so no gate would refuse the claim.
- **Find a class in the source text with a regular expression.**: A regex matches a comment, a string or a local name; `src/devops_cli/roadmap/stage/stage_models.py:def parse_module_models` uses `ast` to find the classes of a module, and the new reader does the same.
- **Record the false claim with the gate `none` and leave it to the review.**: `src/devops_cli/roadmap/stage/stage_eval_gates.py:425:if defect.gate is GateName.NONE:` gives the status unjudged, so the case would prove nothing about the rule.
- **Add a member to the type of a defect for the class claim.**: The count test of the golden set makes every type of defect need a case, and a new member adds a row to every score of the replay, while `false_premise` already names a false claim.
- **Keep the test path that the issue names.**: The probe reports that `tests/roadmap/test_roadmap_stage_plan.py` is no file of the commit and names `tests/roadmap/stage/test_roadmap_stage_plan.py`, so the old path would break the plan check.
- **Give the new case the null commits with no note that it reads no commit.**: `tests/gate/roadmap_stage_eval_commits.py:48:if not any(_READS_NO_COMMIT in note for note in case.notes):` refuses such a case, so the `roadmap-stage-eval-commits` row would fail.
