# Design

## Decisions

- **The audit reuses the stage reader and adds `Declaration` and `declarations_in` to `src/devops_cli/roadmap/stage/stage_registry.py`; `counts_in` returns the entries of `declarations_in`.**: One `ast` reader then serves the stage plan and the audit, and the two agree on what a declaration is; a second parser would drift from it, and `counts_in` keeps the answer that its existing test asserts.
- **The refusal covers every test module: a `len(<NAME>) == <int>` assertion and a tuple of upper-case constant names compared with a tuple of plain integers that no declared entry of that module covers, with its `path:line`, and exit 1.**: The design requires exit 1 for a ratchet assertion in a module that declares nothing, and `tests/commands/test_cli_startup_imports.py` is exactly that case, so a refusal limited to declaring modules would miss the new ratchet test that the issue names.
- **An entry covers a name when its token equals the name, or when its kind is `prefix` and the name starts with the token.**: The declarations hold `prefix` tokens such as `CONST_ROADMAP_` and `DEFAULT_ROADMAP_`, and a prefix entry is the declaration that a family of constants exists.
- **The subcommand is a flat `@app.command("registries")` of the `roadmap` group, with `--format`/`-f` and `--json`/`-j` resolved by `resolve_format`.**: `src/devops_cli/commands/roadmap.py:def inbox_cmd` and the other listing commands are flat entries, and the report commands such as `devops roadmap eval grades` already resolve a format.
- **`--path` chooses the checkout whose `tests` folder the audit reads, and the default is the repository root of the current folder.**: A test points the audit at a temporary tree, and a person can audit another checkout without changing the working folder.
- **The plan runs `uv run devops docs generate` and passes no `--sync-readme`.**: `src/devops_cli/commands/docs.py:def generate` declares `--output-dir`, `--format` and `--check` only, and the option is deleted.
- **The exit-0 case, the JSON output and the exit-1 case are tested on temporary trees, and the repository test asserts the rows only.**: This checkout holds a ratchet assertion with no declaration at `tests/commands/test_cli_startup_imports.py:def test_the_four_limits_keep_their_values`, so the command reports it and exits 1 here; a temporary tree is the only stable place to assert exit 0.
- **`tests/roadmap/test_roadmap_dry_runs.py`, `tests/roadmap/test_roadmap_limit_classes.py`, `tests/support/fakes/roadmap_store.py` and `tests/telemetry/test_telemetry_instruments.py` stay unchanged.**: Each declaration holds literal triples, and the plan changes no declaration that the stage plan already reads.
- **`tests/roadmap/stage/test_roadmap_stage_plan.py` and `tests/roadmap/stage/test_roadmap_stage_split_gates.py` stay unchanged.**: Each holds the name `REGISTRY_COUNTS` in a string literal that builds a test module, and a string literal is no module-level declaration.
- **`tests/ai/mcp/test_ai_benchmark_mcp_tool.py` and `tests/commands/test_all_commands_help_dryrun.py` stay unchanged; groups 2 and 3 read them.**: The first imports the catalog `src/devops_cli/lang/en/help.py` and asserts the published parameters of the `ai_benchmark` tool, and the second invokes each command with `--help` and `--dry-run`; the new help texts and the new subcommand keep their rows true, so neither test needs an edit.
- **The subcommand raises `typer.Exit(1)` on a finding, as `src/devops_cli/commands/roadmap.py:def _exit_on_failure` does for a failed roadmap read.**: A check can gate on exit 1, and the roadmap group already reports a failure that way.

## Rejected alternatives

- **Refuse only in a test module that already declares `REGISTRY_COUNTS`, and let a module that declares nothing pass with exit 0.**: The design requires exit 1 for a `len(TABLE) == 3` assertion in a module that declares nothing, and `tests/commands/test_cli_startup_imports.py` is the case that the issue names; that scope would not catch the new ratchet test that the audit exists for.
- **Use `ast-grep` alone for the audit.**: It finds a Python pattern and prints `path:line`, but it cannot split an entry into kind, token and target path, compare an assertion with the declarations of its own module, count the valid entries or set the exit code.
- **Run `uv run devops docs generate --sync-readme` as the issue block says.**: `src/devops_cli/commands/docs.py:def generate` declares `--output-dir`, `--format` and `--check` and no such option.
- **Put the whole scan in `src/devops_cli/commands/roadmap.py` and test it only through the command.**: The scan needs unit tests without the command layer, and `tests/roadmap/` mirrors `src/devops_cli/roadmap/` as `tests/commands/` mirrors `src/devops_cli/commands/`.
- **Add a nested `audit` group under `roadmap` for this one command.**: `src/devops_cli/commands/roadmap.py:def inbox_cmd` and the other listing commands are flat entries, and a group for one command adds a level to every later audit command.
