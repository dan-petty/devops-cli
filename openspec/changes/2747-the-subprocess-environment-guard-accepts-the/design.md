# Design

## Decisions

- **Refuse `PYTEST_ADDOPTS` as an exact entry.** pytest reads only this key, and no `PYTEST_*` family is dangerous: `PYTEST_CURRENT_TEST` and `PYTEST_XDIST_AUTO_NUM_WORKERS` are in `DEFAULT_ALLOWED_ENV_VARS` and must stay. The probe showed that `--junitxml=<path>` makes pytest write a file at the path.
- **Refuse `npm_config_logs_dir` with the entry `NPM_CONFIG_LOGS[_-]DIR`.** npm reads `npm_config_logs-dir` as the same setting (probe in the proposal), so the entry holds `[_-]`, as `NPM_CONFIG_SCRIPT[_-]SHELL` does. The guard upper-cases the key, so one entry covers each case. No caller sets the key.
- **Keep `npm_config_cache` accepted, and keep the rest of the `npm_config_*` family accepted.** `devops install-tools` sets `npm_config_cache` to a scratch directory on purpose (`src/devops_cli/commands/install_tools.py` line 311). A refusal would stop the npm installer and would break `tests/core/test_subprocess_env_uv_npm.py` and `tests/commands/test_install_tools.py`. A caller names a directory that it controls, as for `GH_CONFIG_DIR` and `KUBECONFIG` (#2672) and `npm_config_userconfig` (#2673). A caller that takes the path from an untrusted source must check it first. The guard comment and `ARCHITECTURE.md` say so.
- **State the limit.** npm writes its debug log below the cache directory when `npm_config_logs_dir` is unset. So the refusal of `npm_config_logs_dir` closes the key that names the log directory. It does not stop a caller that sets `npm_config_cache` from directing log files. The issue allows this: its expected result is a refusal "or the design of the guard names each such key that it accepts and the reason".
- **Put both entries in `CONST_CODE_LOADING_ENV_PATTERNS`, in the block of #2674.** The function `_is_env_override_refused` reads this tuple for a caller override. `DEFAULT_DENIED_ENV_PATTERNS` only filters the ambient environment, and both keys are already filtered there.
- **Put the tests in `tests/core/test_subprocess_env_file_write.py`.** It is the file of the keys that make a child write a file (#2674), in the mirror directory of `src/devops_cli/core/process.py`. Its tuple `REFUSED_FILE_WRITE_KEYS` drives the refusal test, the lower-case test and the ambient test, so one tuple entry per key gives all three.
- **Modify the three requirements of the file-write keys.** The refusal requirement lists the keys. The isolation requirement lists them too. The requirement of similar names gets the two new near-miss keys and names `npm_config_cache`. The requirement "A uv or npm key that names no program or that names a file reaches the child" already pins `npm_config_cache` as accepted and does not change.

## Rejected alternatives

- **Refuse the whole `NPM_CONFIG_*` family (the choice of the refine block).** `fnmatch` of `NPM_CONFIG_*` matches the five keys that `devops install-tools` sets, so the pattern breaks the installer. It also breaks two tests and one requirement that pin them as accepted. It makes the seven exact `NPM_CONFIG_*` entries of #2673 dead, and it reverses the decision of #2673 that the other keys stay accepted. Most members of the family write no file (`npm_config_registry`, `npm_config_loglevel`), so the reason "any member can direct a file write" is not true.
- **Refuse the family and name the five installer keys as accepted, as `CONST_GIT_ACCEPTED_ENV` does for git.** It refuses keys that no probe showed, and it needs the pinned keys `npm_config_git_tag_version` and `NPM_CONFIG_GITHUB` to change. That reverses #2673 and claims keys without a probe, which the issue forbids.
- **Refuse `npm_config_cache` and make `install_npm_tool` pass `--cache` as an argument.** It changes the installer and its test only to satisfy the guard. A caller sets the key to a directory that it controls, and the guard accepts such keys elsewhere.
- **Add the keys to `DEFAULT_DENIED_ENV_PATTERNS`.** That list filters the ambient environment only, where both keys are already absent.
