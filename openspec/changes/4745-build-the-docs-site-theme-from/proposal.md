# Proposal

## Why

The docs site of #4745 does not follow the design spec: its palette, fonts, code colors and favicon do not come from the design tokens, so some text pairs sit below the WCAG 2.2 AA ratio of 4.5:1, the page has no focus style and no scale of breakpoints, and the theme CSS has no caption classes.

## What Changes

- Add `design/sd/dark-docs.json` and its build line in `Makefile`, so the dark token values apply under the Zensical slate scheme.
- Add `docs/assets/css/site/theme.css`, which sets each Zensical theme value from a design token variable and holds no color literal.
- Load Source Serif 4, Source Sans 3 and Source Code Pro through one request of the Google Fonts css2 API with display=swap, set Source Serif 4 on the reading text at 16 px and at 18 px from 40rem, and add the focus-visible rule, the 40rem and 75rem breakpoints, the two caption classes and the syntax roles to the theme CSS.
- Set `extra_css` in the `[project]` table of `zensical.toml`, set `theme.font` to false so that the theme adds no second font request, set `theme.favicon`, and add `docs/assets/favicon.svg` in place of the default icon of the theme.
- Add the docs theme folder to the scan roots of the constructs row and to the files of the `css-color-literal` rule, with a case of the gate module and one row of the violation table.
- Add the layout check of the built site to the Docs Site Build workflow, in both schemes at 400 px and 1280 px. Playwright and axe-playwright-python join the docs dependency group of `pyproject.toml` and `uv.lock`, and the check starts the Google Chrome of the runner image and installs nothing.
- Add the theme cases to `tests/design/test_tokens.py`, `tests/design/test_design_spec.py` and `tests/design/test_contrast.py`, which the Design Tokens job runs, and add no case that reads `zensical.toml`.
- State the merged docs theme rules in `docs/DESIGN.md`, and the scan roots and the layout check in `docs/SDLC.md`.
- The change carries a spec delta: a reader of the docs site observes the palette, the fonts, the code colors, the focus outline, the captions and the favicon.
- The change fits one pull request.

## Existing Tool Considered

Zensical 0.1.3 (MIT, in use since #5183) supplies the palette that follows prefers-color-scheme with a reader toggle, the theme variables, the font and favicon settings, the breakpoints, the focus styles and the code block classes; Playwright 1.65.2 (Apache-2.0) drives the Google Chrome of the runner image in the layout check; axe-core (MPL-2.0), through axe-playwright-python 0.1.9, supplies the WCAG contrast of each text pair with its rule color-contrast, so the check holds no contrast code of its own; Style Dictionary builds the token CSS; the Google Fonts css2 API serves the three Source faces. The token map, the docs dark token file, the caption classes and the ast-grep rule stay custom: about 40k tokens and 2 hours to build, keep and fix.
