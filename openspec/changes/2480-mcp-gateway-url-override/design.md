# Design

## Decisions

- **The MCP tools publish no URL.** `_PATH_PARAM_RESTRICTIONS` in `src/devops_cli/ai/mcp/generator.py` already lets a command publish a subset of its options, and `telemetry profile` uses it. The three gateway commands get an entry each: `provider` for `status` and `routes`, `backend` for `probe-backend`. The tools query the configured gateway (`ai.gateway_url`, or `ai.portkey_url` under Portkey) and the first of `ai.ollama_urls`. Thus a model has no URL to give, and the egress defect has no input. A call that still names `gateway_url` or `backend_url` fails at the argument contract of the MCP server, before any command runs.
- **The commands keep their URL options.** A person types `--gateway-url` and `--backend-url` at the command line. These URLs dial at the configured level, as the `--source` URL of `devops ai cost update-pricing` and the `--servers` URLs of `devops ai benchmark` do (#2422). Without a model between the person and the option, no input needs a stricter level.
- **The key rule is in the router.** `GatewayRouter._key_for(url)` gives the AI API key only when `get_url_origin(url)` equals the origin of the configured gateway URL, the one that `GatewayRouter.gateway_url` names for the provider in use. An origin is the scheme, the host and the port, and `httpx2.URL.origin` normalizes the case of the host and the default port. The path of the URL is not part of the origin, so `--gateway-url http://gateway.example.com:4000/another/path` still gets the key. The router is where the configured gateway and the URL of a caller meet, so the rule sits there and not in `fetch_model_info`, which takes only a URL and a key.
- **A refusal says that the gateway got no key.** When a gateway of another origin answers 401 or 403 and a key is set, the text "requires an API key ... no API key is configured" would mislead. `list_routes` raises an `AICredentialsError` that says the key goes only to the configured gateway and names the origin of the gateway that refused. It gives no URL, because a URL can hold user information.
- **The test file is `tests/test_ai_gateway.py`.** It already tests these commands and tools. The new tests use `scripted_resolver` and `record_connects`, and read the dialled addresses and the bytes on the wire. Three existing tests of the route discovery give the router a configured gateway, because an override that has no configured gateway to match gets no key.
- **`SECURITY.md` gets the rule.** The lesson of the defect is general: a URL from a model is untrusted input, and a credential goes only to the origin that the configuration names. The rule is in the egress principle of `SECURITY.md`.

## Rejected alternatives

- **Keep the MCP options and dial them at the public level.** The `EgressLevel.PUBLIC` docstring names this level for a URL that a model gives. It stops the loopback scan. But the model could still make the tool send a GET request to any public host, and `probe-backend` returns up to 256 characters of the error and the parsed model names. No tool needs the option: each one reports the state of the configured gateway or backend. Removing the option removes the input, and no level code is needed.
- **Give a URL option of the command line the public level too.** The tools were the only path from a model to the option. A public level for a person would also refuse a gateway that the person runs on loopback with `--gateway-url`, while `--source` and `--servers` dial at the configured level for the same person. The level of a person's URL is the policy of #2422, not of this change.
- **Compare the key rule in `_query_model_info` or `fetch_model_info`.** These functions take only a URL, a flag and a key. The rule needs the configured gateway, so they would call `load_settings` in a low-level function, which hides a global read. The other callers (`devops ai gateway tune`, the run store) pass the configured URL.
- **Compare only the host, or test the start of the URL.** `http://gateway.example.com:4000@attacker.example.com:4000/v1` starts with the configured URL and has the host `attacker.example.com`. A different port or scheme is a different service. The origin of httpx2 has these cases right, and the test rows hold each of them.
- **An invariant test that no read-only MCP tool publishes a URL option.** Other MCP tools publish one: `k8s_logs` (`loki_url`), the `valkey_*` tools (`url`), `ai_prewarm` (`url`), `ai_benchmark` (`servers`) and `vault_status` (`vault_addr`). An invariant would need an allow list of these, and an allow list is an escape. #2634 and #2635 hold the `valkey_*` tools and `k8s_logs`, each with a probe.

## Non-goals

- The URL options of the other MCP tools. #2634 covers the `valkey_*` tools, and #2635 covers `k8s_logs`.
- `devops ai gateway tune --gateway-url`, which gives the key to any URL that a person types. It is not an MCP tool.
