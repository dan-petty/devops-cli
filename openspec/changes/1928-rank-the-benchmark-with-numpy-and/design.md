# Design

## Decisions

- **Type pytrec_eval with a stub under typings, as the jq stub types jq, and add no mypy override.**: `pyproject.toml:205:mypy_path = "typings"` puts the stub on mypy's path, and the ceiling for mypy overrides is 1 with the statsmodels entry in it, so a second entry fails test_suppressions_stay_under_their_ceilings, which is the fault that closed pull request #5140.
- **Prove the declaration, the lock entry of each library, a linux x86_64 wheel of each and the stub with a new invariant test, and make that test the verify of the first group.**: The invariant test that holds the override ceiling reads neither the dependency list nor the lock, so a command that runs only it passes on the base commit; a test that reads `pyproject.toml`, `uv.lock` and `typings/pytrec_eval.pyi` fails before the group's work and passes after it, and it holds the wheel criterion of the issue to a command instead of a person's confirmation.
- **Assert a wheel whose file name holds `linux` and `x86_64` for each locked entry, and not a wheel of one architecture per library.**: The issue's criterion is a linux/amd64 wheel for each library, and the amd64 image is the only image that the workflows build, so the check covers numpy and pytrec-eval-terrier alike; `uv.lock:2581:numpy-2.5.4-cp314-cp314-manylinux_2_27_x86_64.manylinux_2_28_x86_64.whl` shows the name shape that the assertion matches.
- **Return the three recalls as percentages from the metrics helper, and round them in the runner as it does now.**: `src/devops_cli/models/benchmark.py:148:recall_at_1: float = Field(default=0.0, ge=0.0, le=100.0)` bounds every recall field of the report to 100, so the helper returns percentages and no caller scales them.
- **Put the ranking and the metrics in a new module, `src/devops_cli/ai/benchmark/retrieval_metrics.py`, and leave the orchestration in `src/devops_cli/ai/benchmark/embedding_runner.py`.**: The new module is testable on a fixed fixture with no engine, and the branch it removes from the evaluation function is what the C901 marker covers.
- **Row-normalize the query and corpus matrices and leave a zero-norm row at zero before the one matrix product.**: `src/devops_cli/ai/vector_similarity.py:20:return float(dot / (norm_a * norm_b))` divides by both norms and line 18 returns 0.0 for a zero norm, so a raw dot product would change the ranking of every non-unit vector.
- **Build one run and one qrels for the whole evaluation, and score a target that is absent from the corpus as zero.**: pytrec_eval averages over the queries of a run, so a pair with no vector still counts as a miss, and zero is the correct value for a query whose relevant chunk is not in the corpus.
- **Add the capability ai-benchmark-ranking instead of a requirement of ai-benchmark.**: The purpose of ai-benchmark is the servers that a run sends requests to; the ranking path, its metrics, the two libraries, their declaration and their typing are a different subject.
- **Map the distribution pytrec-eval-terrier to the module pytrec_eval in a `[tool.deptry]` table of `pyproject.toml`.**: The distribution name differs from the module name, the deps row runs deptry over src at `src/devops_cli/commands/ci.py:919:cmd=["uv", "run", "deptry", "src"],`, and the map keeps the declared distribution and the imported module one dependency.
- **Declare the two libraries and add the stub in the first group, before the module that imports them, and leave the deps row to the Static Analysis gate.**: deptry reports a declared dependency that no module imports, so a step cannot declare the libraries and import them in the same change; the gate runs the deps row on the pull request head, after both groups.
- **cosine_similarity stays where it is, and its importers outside the benchmark stay unchanged.**: The definition at `src/devops_cli/ai/vector_similarity.py:11:def cosine_similarity(vec_a: list[float], vec_b: list[float]) -> float:` still serves `src/devops_cli/roadmap/nearest.py`, and `tests/support/fakes/qdrant.py` keeps its own `_cosine_similarity` helper, which never imported the shared function.
- **Prove the removal with the check of the issue, the search of src and tests for compute_ndcg_at_k, and name the helper in no test.**: The issue's criterion is that `rg compute_ndcg_at_k src tests` returns no match, so a test that names the helper keeps a match in tests and makes that check fail. The group that removes the helper runs `! git grep -n compute_ndcg_at_k -- src tests`, the negative-search form that the implement step runs, over the same tracked files of src and tests.
- **rank_corpus returns the score matrix and the ranked indices, and score_retrieval takes both.**: The margins, the separation and the target scores need the score of each query and chunk pair, and the ranked indices alone do not hold them. The run that score_retrieval gives pytrec_eval holds a score that falls as the rank goes up, because trec_eval breaks a tie of scores by the document identifier and not by the order of the run, so the numpy order of equal scores stays.
- **Change both Service Image smoke probes in one group, and prove them with `tests/commands/test_ci.py`.**: `tests/commands/test_ci.py:1518:ci_run == rel_run,` requires the two run blocks to be identical, so a probe edit in one workflow alone fails that test; the workflow group edits `.github/workflows/ci.yml` and `.github/workflows/release.yml` to the same text and runs the parity test as its verify.

## Rejected alternatives

- **Add a second mypy override for pytrec_eval.*.**: The ceiling is 1 at `tests/invariants/test_architectural_invariants.py:144:"[[tool.mypy.overrides]]": 1,`, and pull request #5140 failed only test_suppressions_stay_under_their_ceilings with 2 > ceiling 1.
- **Assert only a resolved version of pytrec-eval-terrier in the lock and leave its wheel to a person's confirmation.**: The issue's criterion says 'uv.lock holds a resolved version and a linux/amd64 wheel for each', and the amd64 image is the only one that the workflows build, so a missing wheel must fail the invariant test rather than wait for a person.
- **Edit only the ci.yml smoke probe and leave the release probe as it is.**: `tests/commands/test_ci.py:1518:ci_run == rel_run,` compares the two run blocks, so the release probe would carry the old imports and the parity test would fail.
- **Keep the verify of the first group as the run of the architectural invariant tests only.**: That file reads neither `pyproject.toml` nor `uv.lock` nor the stub, so it passes on the base commit and would prove nothing about the declaration, the lock or the stub.
- **Keep the inline recall, MRR and nDCG code in the benchmark module.**: The loop at `src/devops_cli/ai/benchmark/embedding_runner.py:443:for idx, (eval_item, q_vec) in enumerate(zip(pairs, query_vectors, strict=False)):` calls cosine_similarity once per pair at line 449 and keeps the C901 marker, which is the slow path and the suppression that the change removes.
- **Use a raw numpy dot product with no normalization.**: `src/devops_cli/ai/vector_similarity.py:20:return float(dot / (norm_a * norm_b))` divides the dot product by both norms, so the embeddings are not unit length and the ranking would change.
- **Return the recalls as fractions from the metrics helper and scale them in the runner.**: `src/devops_cli/models/benchmark.py:148:recall_at_1: float = Field(default=0.0, ge=0.0, le=100.0)` bounds the report field to 100, and the runner already rounds a percentage, so a fraction would need a second scale step and a second unit to keep straight.
- **Guard the removal with a test that reads the benchmark module and asserts it defines no compute_ndcg_at_k.**: The test name and its assertion keep the helper name in tests, so the issue's search of src and tests finds a match and its criterion fails; the negative search proves the same removal with no match left.
- **Return only the ranked indices from rank_corpus.**: score_retrieval then has no score for the margins, the separation and the target scores, which the report holds.
- **Keep compute_ndcg_at_k as a thin wrapper over the new metrics.**: references compute_ndcg_at_k answered files 4, lines 14, and the change updates all four, so no caller needs the helper.

## Unchanged references

- `src/devops_cli/ai/vector_similarity.py` (import): The definition stays and keeps its zero-norm result.
- `src/devops_cli/roadmap/nearest.py` (import): The roadmap shortlist keeps its cosine_similarity call.
- `tests/support/fakes/qdrant.py` (local helper name): The fake defines its own `_cosine_similarity` at `tests/support/fakes/qdrant.py:25:def _cosine_similarity(vec_a: Sequence[float], vec_b: Sequence[float]) -> float:` and calls it at line 194, so the search hit is that local name and it imports no shared function.

## Security

Two third-party packages enter the release image: numpy, and pytrec-eval-terrier, a compiled Terrier extension that the benchmark now imports. A person must confirm the MIT licence and the absence of an advisory before the pin merges. The linux x86_64 wheel of each library is asserted by tests/invariants/test_declared_dependencies.py against uv.lock, so a lock entry without a wheel fails that test instead of reaching a release. The image job's Trivy scan fails on a HIGH or CRITICAL finding of either package, the smoke probe of both workflows fails when an import breaks, and test_suppressions_stay_under_their_ceilings fails if the change adds a mypy override instead of the stub.
