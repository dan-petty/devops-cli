# Design

## Decisions

- **Detect a new command by reading the command module of the staged commit through `read_text` and looking for its quoted literal.**: `src/devops_cli/commands/pr.py:468:@app.command("evidence", help=HELP.pr.evidence)` shows that a module registers a command by a quoted literal, and `src/devops_cli/roadmap/stage/stage.py:1179:read_text=partial(_read_staged_file, self._source, self._sha),` already gives the reader of the staged commit, so no new input and no import of a command module is needed.
- **Compare a command with the module that a group changes, and not with `_COMMAND_SPECS` of `src/devops_cli/main.py`.**: `src/devops_cli/main.py:38:_COMMAND_SPECS: Final[dict[str, tuple[str, str]]] = {` maps a top-level group to its module and holds no subcommand name, so every subcommand would look new. The stem of a changed path under `src/devops_cli/commands/` names the family, and the word after it in a task text is the candidate command.
- **Report the findings through a new gate name `companions` in `ProposalGate` and `check_gates`.**: A gate name tells a person and the model which rule refused a plan, and `devops roadmap plan-recheck` prints it. `set(found) == set(ProposalGate)` in `tests/roadmap/stage/test_roadmap_stage_gates.py` covers the new member with no edit, and the replay runs all gates as its one `paths` gate.
- **Add `src/devops_cli/roadmap/stage/stage_companions.py` to `STAGE_EVAL_TRIGGER_PATHS`.**: The tuple holds each module that holds a check of `check_proposal`, so a later plan that changes only that module must run the replay too. The rule of `docs/ROADMAP_WORKFLOW.md:315:A pull request that changes the stage prompt` then covers it.
- **Require the two documentation commands as task text in the plan, and not as a generated file in `changes`.**: `docs/CLI_REFERENCE.md` and `docs/commands/*.md` are generated, so a plan that lists them in `changes` writes generated text by hand. The task names `uv run devops docs generate --sync-readme` and `uv run devops ci docs`, and the first reuses `REGENERATE_DOCUMENTS`.
- **Accept the companion work in any group of the plan, and do not require it in one named group.**: A plan may run the generation in the group that adds the command or in a closing documentation group. The rule asks that the work is in the plan, not which group holds it.
- **Plan no MCP requirement.**: `tests/ai/mcp/test_mcp_exposure_table.py:96:assert exposed_paths - all_cli_commands == set()` fails only on an exposure entry that names no command, and its docstring states that a new command needs no entry. A rule that demanded an entry would force work that no check requires.

## Rejected alternatives

- **Require an MCP exposure entry or an exclusion entry for each new command, as the issue asks.**: `tests/ai/mcp/test_mcp_exposure_table.py:96:assert exposed_paths - all_cli_commands == set()` fails only on an exposure entry that names no command, and the probe states The path `tests/ai/mcp/test_mcp.py` is no file of the staging commit. The test and the exclusion tuple that the issue names are gone.
- **Compare the command of a task with `_COMMAND_SPECS` of `src/devops_cli/main.py`.**: `src/devops_cli/main.py:38:_COMMAND_SPECS: Final[dict[str, tuple[str, str]]] = {` maps a top-level group to its module, so the map holds no subcommand name and every subcommand of a task would look new.
- **Treat every group that changes a path under `src/devops_cli/commands/` as a new command.**: `src/devops_cli/roadmap/stage/stage_change.py:819:def _adds_plan_rule(group: StageGroup) -> bool:` shows the shape of a group rule that reads `changes`, and a group that edits a help text of an existing module changes the same path. It would demand a dry-run delta for an edit that adds no command.
- **Add a field to `StageProposal` that lists the new commands.**: `src/devops_cli/roadmap/stage/stage_change.py:1203:def check_proposal(` already reads each task text and the spec deltas, so a new field changes the reply schema and the prompt for a check that the task text answers.
- **Add a new defect type and a new replay gate for a missing companion registration.**: `src/devops_cli/roadmap/stage/stage_eval_gates.py:203:Gate(GateName.PATHS, "#3010", DefectType.MISSING_PATH, _path_gate),` and `src/devops_cli/roadmap/stage/stage_eval_gates.py:171:return check_proposal(` show that the `paths` gate already judges `check_proposal`, so the nine-type schema would change for a rule that gate already judges.
