# Design

## Decisions

- **The specs use the Sloth `prometheus/v1` format, and `src/devops_cli/prometheus/slo_rules.py` renders the rule groups from them.**: `docs/guidelines/sre.md:58:Sloth generates the recording rules and the alerts of each SLO from one spec. No person writes an SLO rule by hand.` gives the format, and the runner image holds no `sloth` program, so the repository renders that format instead of running the binary.
- **The four specs live in `k8s/devops/monitoring/slos/`, and their groups join `k8s/devops/monitoring/prometheus-rules-values.yaml`.**: `tests/gate/k8s_checks/environment_freeze.py:def is_environment_path` admits only the product folders of `k8s`, and `k8s/devops/monitoring/prometheus-rules-values.yaml:10:# server loads this file next to the environment rules. A group name is unique over both files.` shows that the server already loads that file.
- **Each SLO uses the 28-day window, the objective of its row of the SLO table of `k8s/README.md`, and the four alert rows of Table 2 of the SRE guideline, each with the severity of its row and no `for`.**: `docs/guidelines/sre.md:52:The window is 28 days for each SLO.` gives the window, `k8s/README.md:655:| 1 | Roadmap Service |` to the row of SLO 4 gives the objectives, and `docs/guidelines/sre.md:64:| Page | 1 h | 5 min | 2 % | 13.44 |` gives the rows.
- **Each alert holds the 20-event guard inside the rendered expression, and each recorded series carries the `service` and `slo` labels.**: `docs/guidelines/sre.md:54:An SLO with fewer than 20 events in the long window of an alert gives` gives the rule, and the two labels keep the four `slo:sli_error:ratio_rate1h` series apart.
- **Each case file sets `evaluation_interval: 5m` and each case sets `interval: 1m`.**: `tests/prometheus/test_k8s_monitoring_alerting.py:157:MAX_PROMTOOL_ROUNDS = 1_000` bounds a case, and a 3-day case at 5 minutes makes 864 rounds, while 1 minute gives the 5-minute short window five samples.
- **The regeneration equality and the README checks are checks of the `k8s` row, in `tests/gate/k8s_checks/slo_rules.py`, and no test function reads a committed manifest.**: `tests/gate/k8s.py:def main` runs every module of `tests/gate/k8s_checks`, and the `k8s` row of `devops ci` is the row that checks the committed manifests of the tree.
- **The SLO table of `k8s/README.md` gains a `Spec` column, and the four rows of this change lose their objective and error budget.**: `k8s/README.md:651:The rows stay here until the Sloth specs of #4709 hold them.` makes the row a temporary copy, so the spec becomes the one place of each objective and window.
- **The SLO 5 row keeps its objective and gets no spec in this change, so the README check names the four SLO rows of this change only and leaves that row alone.**: This item adds no ingress spec, so moving the SLO 5 objective would leave it with no target at all; `k8s/README.md:659:| 5 | Roadmap Service |` is the row that stays.
- **The renderer tests live in `tests/prometheus/test_k8s_monitoring_alerting.py`, the module that checks the product rule file.**: That module already reads `k8s/devops/monitoring/prometheus-rules-values.yaml` and holds `SERVED_SERIES`, so the render and the rules it produces are tested in one place and no new test module is added.

## Rejected alternatives

- **Put the specs under `k8s/monitoring/slos/` and the groups in `k8s/monitoring/slo-rules-values.yaml`, as the issue says.**: `tests/gate/k8s_checks/environment_freeze.py:def is_environment_path` refuses each non-Markdown file of `k8s` outside the two product folders, so the branch would fail the `k8s` row that `Static Analysis` runs.
- **Run `sloth generate` in the regeneration check, or pin Sloth v0.16.0 in `src/devops_cli/tools_lock/tools.lock`.**: The probe reports that `src/devops_cli/tools_lock/tools.lock` is no file of the staging commit, `search_code sloth` returned no line of `src/`, and the runner image holds no `sloth` program.
- **Add a third values file under `k8s/monitoring/`, name it in `valueFiles` of Application `prometheus`, and add its file name to `rule_files`.**: `k8s/devops/monitoring/prometheus-rules-values.yaml:10:# server loads this file next to the environment rules. A group name is unique over both files.` shows that the server already loads the product file, and `tests/gate/k8s_checks/environment_freeze.py:def is_environment_path` refuses a third file under `k8s/monitoring`.
- **Generate PrometheusRule objects for the four SLOs.**: The server reads its rules from `serverFiles`, as `k8s/devops/monitoring/prometheus-rules-values.yaml:16: devops_cli_alerting_rules.yml:` shows, and no Prometheus operator reconciles a PrometheusRule.
- **Write the rule groups by hand.**: `docs/guidelines/sre.md:58:Sloth generates the recording rules and the alerts of each SLO from one spec. No person writes an SLO rule by hand.`, and a hand-written group gives the equality check nothing to compare.
- **Lower the burn-rate line instead of adding the 20-event guard.**: `docs/guidelines/sre.md:54:An SLO with fewer than 20 events in the long window of an alert gives` gives the event count apart from the page line, and `docs/guidelines/sre.md:64:| Page | 1 h | 5 min | 2 % | 13.44 |` fixes the line.
- **Set the service dashboards to 28 days with the 13.44x and 5.6x lines in this change, as the comment of 2026-11-13 asks.**: `tests/gate/k8s_checks/environment_freeze.py:def is_environment_path` refuses `k8s/monitoring/dashboards/services.toml`, and the environment lives in dan-petty/homelab since step 11 of the switch, so that change belongs to that repository.
- **Keep the four objectives in the README rows and in the specs.**: `k8s/README.md:651:The rows stay here until the Sloth specs of #4709 hold them.` makes the row the temporary copy, and no check compares two copies.
- **Add a subcommand of the `prometheus` group that writes the groups.**: The renderer needs no command: its module program writes the file with `--write`, and `src/devops_cli/prometheus/promql.py:def grouping_labels` already gives the grouping of a query.
- **Keep 30 days and the 14.4x and 6x lines.**: `docs/guidelines/sre.md:52:The window is 28 days for each SLO.` and `docs/guidelines/sre.md:64:| Page | 1 h | 5 min | 2 % | 13.44 |` give the window and its page line.
- **Check every SLO row of `k8s/README.md` for a spec and for a percentage, the SLO 5 row included.**: `k8s/README.md:659:| 5 | Roadmap Service |` is the row of SLO 5, which keeps its objective and gets no spec in this change, so a check over all five rows would fail on the tree that this change merges.

## Security

Nothing crosses a trust boundary: the change adds spec files, a renderer, checks of committed files and tests of the checkout, and it adds four rule groups to a values file that the Prometheus chart already loads. No cluster object, role, policy, ServiceAccount or secret changes, and no rule reads a series that no scrape serves. A person must confirm at the merge that each spec names a service of the catalog data, that each alert keeps its 20-event guard, and that each of the four SLO rows of `k8s/README.md` names its spec. `uv run devops ci test tests/prometheus/test_k8s_monitoring_alerting.py` fails when a rule selects a series outside `SERVED_SERIES` or a case breaks the guard, and `uv run devops ci --check --only k8s` fails when the branch changes an environment path or the four groups differ from the render.
