# Design

## Decisions

- **One gauge, `devops_cli_roadmap_inbox_items`, with the labels `repo` and `kind`.**: Nine counted kinds for each of seven repositories give 63 series, inside the cap, and a new repository needs no code.
- **The counted kinds are `blocked`, `refine`, `split`, `alternatives`, `failed`, `stage_retry`, `claim`, `labels` and `queue`; the kinds `plan`, `implement`, `release`, `draft` and `person` stay out of `COUNTED_KINDS`.**: Each excluded member is a pull request kind that the pull request list already shows, and each further kind adds seven series past the 63-series cap. Every member of the 14 of `InboxKind` is decided: nine counted, five left out.
- **`COUNTED_KINDS` lives in `src/devops_cli/roadmap/inbox_kind.py`, beside the enum.**: That module holds no heavy import, and the command builds `--kind` from it, so `devops roadmap --help` stays light.
- **`inbox_cmd` calls `emit_inbox_counts` after `read_inbox` returns and before it renders the report.**: `read_inbox` stays a pure read, so every test that calls it sends no metric, and one test calls the emitter with a fake repository.
- **The panel goes in `k8s/devops/dashboards/project-metrics.json` at x 12, y 34, w 12 and h 8, and its case goes in `tests/grafana/test_grafana_dashboards.py`.**: The panel "Oldest Item Age by State" sits at x 0 and y 34, and #2919 left the right half of that row free. The grafana module holds the lint case that reads the product dashboards, so one command runs the new case and the lint.
- **`stage_retry` is a kind of its own, does not reuse `InboxKind.FAILED`, and its clearing step is `devops roadmap stage --item <number> --repo <repository> --confirm`.**: `src/devops_cli/roadmap/inbox_kind.py:21:FAILED = "failed"` is the refine try limit, while `src/devops_cli/roadmap/stores/store.py:270:FAILED_CLASS = "stage.failed_class"` is the stage failure. `devops roadmap stage --item` takes the item at once, while `devops roadmap explain` only reads and writes nothing.
- **The panel is hand-written JSON, and no generator is adopted.**: The dashboard lint reads JSON files, and one panel needs no dependency and no generation step.
- **`docs/TELEMETRY.md` is regenerated by `uv run devops docs generate` with no option, and `docs/roadmap/inbox.md` records why the image digest line cannot be built.**: The document is generated from `INSTRUMENTS`, and the `docs` row of `uv run devops ci` refuses a generated document that is not the output of its generator. The digest line needs a client of the cluster, and the Service pod holds no cluster token, so #4832 owns it and the page says why.

## Rejected alternatives

- **Send every kind of `InboxKind` as a series of the gauge.**: Fourteen kinds for seven repositories give 98 series, over the 63-series cap that the constraint line of 2026-11-12 on #2968 records, and the closed plan #4963 was rejected for the 91 series of all kinds.
- **Emit the gauge inside `read_inbox`.**: Every test of the read, including `tests/roadmap/test_roadmap_inbox.py`, would export metrics, and the read would no longer be pure.
- **Reuse `InboxKind.FAILED` for a stage failure.**: `src/devops_cli/roadmap/inbox_kind.py:21:FAILED = "failed"` is the refine try limit, and the stage job writes another key, `src/devops_cli/roadmap/stores/store.py:270:FAILED_CLASS = "stage.failed_class"`.
- **Make `devops roadmap explain` the clearing step of the `stage_retry` line.**: The module docstring of `src/devops_cli/roadmap/inbox.py` says the read writes nothing, and `docs/roadmap/stage.md:119:takes the item at once.` says that `--item` takes the item at once, so the clearing step is `devops roadmap stage --item <number> --repo <repository> --confirm`.
- **Generate the panel with weaveworks/grafanalib.**: `tests/grafana/test_grafana_dashboards.py:180:def test_repository_dashboards_lint_clean(dashboard_file: Path) -> None:` reads the JSON files, and one panel needs no dependency and no generation step.
- **Run `uv run devops docs generate --sync-readme`.**: The option no longer exists (#5198), and the closed plan #4963 failed the paths gate on it. The workflow document gives the command with no option at `docs/ROADMAP_WORKFLOW.md:311:Write the generated documents in the docs directory of the checkout`.
- **Add a fourth dashboard file for the panel.**: The panel "Oldest Item Age by State" of `k8s/devops/dashboards/project-metrics.json` shows that the item panels already live in that file, and the folder keeps its three product dashboards.
- **Build the image digest line in this change.**: The line reads the pin with `devops argo cd apps status devops`, which needs a client of the cluster, and the Service pod holds no cluster token. #4832 is open and owns that line, so the docs group records the reason and the owner.

## Security

The panel JSON crosses from the repository into the monitoring stack: Argo CD applies it and Grafana reads it. The panel holds one PromQL query, one datasource and no secret, no host name and no address. A person must confirm that the panel reads only `devops_cli_roadmap_inbox_items` and keeps the datasource `prometheus`. `tests/grafana/test_grafana_dashboards.py` fails when the dashboard stops passing the lint, and `test_the_inbox_panel_charts_each_counted_kind` fails when the query names another metric.
