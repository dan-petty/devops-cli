# Design

## Decisions

- **Adopt k8up-io/k8up for the Gitea backup.**: The owner adopted the tool in the comment of 2026-11-24, and the alternatives check of 2026-11-18 gives it the verdict covers for the scheduled restic backup, the retention, the check, the metrics and the restore.
- **Back the Gitea claim up to the bucket `backups-gitea` of the in-cluster SeaweedFS S3 gateway.**: The owner set that target on 2026-11-21; the store keeps 2 copies on 2 nodes, so the copy leaves the Gitea node, and the NAS is out.
- **Run the backup daily at 02:00, keep 7 daily and 4 weekly snapshots, prune weekly and run a restic check once a week.**: A daily run bounds the loss of a forge with little change to 24 hours, 4 weekly snapshots keep a month, and the small target keeps the storage bounded.
- **Take the dump with `gitea dump` from the Gitea pod and write only the archive to stdout.**: The Gitea data is a live SQLite database in WAL mode on one claim, so a file copy can be inconsistent and the dump keeps Gitea online.
- **Install the chart in namespace `k8up` with `skipWithoutAnnotation` true, in dan-petty/homelab.**: The flag keeps the backup to the annotated Gitea claim, so no other claim gets a copy it does not need, and the chart is an environment release of the homelab.
- **Warn with `GiteaBackupTooOld` when the last successful backup is older than 93600 seconds, with `for: 0m`.**: 93600 seconds is one daily run plus a 2-hour grace, so the first missed run warns and no second hold delays it.
- **Put the group `gitea-backup` in `k8s/devops/monitoring/prometheus-rules-values.yaml`, the product rule file, and not in `k8s/monitoring/prometheus-values.yaml`.**: `tests/gate/k8s_checks/environment_freeze.py:67:is an environment path, and dan-petty/homelab holds the environment.` is the message of the required `k8s` row for the environment values file, and `k8s/README.md:1304:From this repository, it reads only the product base` shows that Application `prometheus` reads the product file from this repository.
- **Deliver the age series and its alert from this repository, and the k8up release, the Schedule, the PodConfig and the NetworkPolicies from dan-petty/homelab.**: The alert is product content of Application `prometheus`, and the manifests are environment paths that the required `k8s` row refuses in this repository, so the criterion maps to the group that changes the alert and its served series.
- **State the product rule file's rule instead of a census of its groups in the requirement `The product alert rules have their own values file`.**: The census of the base text is already stale: it names 10 groups, and `tests/prometheus/test_k8s_monitoring_alerting.py:134:REPOS_DRIFT_GROUP = "repos-drift"` names a group that the file holds and the text does not.
- **Restore with the S3 method into a scratch namespace and name the folder method as the fallback.**: The S3 method reads the snapshot in place, and the owner's comment of 2026-11-11 names the signature failure of the S3 method as the case that the folder fallback covers.
- **Set the PodConfig to user and group 1000 with fsGroup 1000 and the restricted security context, and allow egress to the S3 gateway on port 8333 and the API server on TCP 443 and 6443 only.**: The gitea namespace enforces restricted, and only the backup pods need the S3 and API egress.
- **Name the in-cluster endpoint and the bucket in git, and keep the S3 key and the restic password in the environment Secret rows of dan-petty/homelab.**: The endpoint and the bucket are in-cluster names, and `src/devops_cli/k8s/cluster_secrets.py:490:cluster_secrets_path = getattr(env, "cluster_secrets", None)` reads the environment file of dan-petty/homelab before any fixture, so no value of this repository reaches the live Secret.
- **Add no row to the Cluster Secrets table of `k8s/README.md`.**: `tests/invariants/test_k8s_manifests.py:135:def test_readme_lists_the_table` requires each product row in that table, and the restic row of the Gitea backup is an environment row of dan-petty/homelab, so a product row would describe a Secret that only this cluster holds.
- **Verify the alert with its promtool case, and the README with the `docs` row.**: Each command runs offline on the merge, the `k8s` row reads no rule values file, and a live restore needs the deployed release, the bucket of dan-petty/homelab#98 and a person.
- **Record the person's restore run as the `process` of group 3, and the measured result in #7022.**: No command of the runner reaches the cluster, so the run is a manual check, and #7022 holds the live backup, the restore and the measured time.

## Rejected alternatives

- **Build the snapshot, retention, restore and metric code in this repository.**: `docs/guidelines/production-readiness.md:242:k8up for a volume` names k8up as the tool of the data item, and rule 3 of `AGENTS.md` puts the open tool before new code.
- **Adopt velero-io/velero for the backup.**: The owner's comment of 2026-11-11 states that Velero file-system backup cannot read the hostPath volumes of this cluster, and reports 19 of 19 PVs as `hostPath`.
- **Back the claim up to the NAS on the local network.**: The owner's comment of 2026-11-21 puts the NAS out of scope and sets the in-cluster bucket `backups-gitea` as the target, which `docs/adr/0034-the-object-store-is-seaweedfs-with-its-operator.md` records as the store of the cluster.
- **Copy the claim to a path on another node.**: A copy on another node is not off the node, and the owner's comment of 2026-11-21 names the store that keeps 2 copies on 2 nodes as the target.
- **Put the rule group in `k8s/monitoring/prometheus-values.yaml`, as the refine block proposes.**: `tests/gate/k8s_checks/environment_freeze.py:67:is an environment path, and dan-petty/homelab holds the environment.` is the message of the required `k8s` row for that file.
- **Put the k8up release and the Schedule under a product folder such as `k8s/overlays/homelab/devops` to pass the freeze row.**: `docs/HOMELAB_REPO_SWITCH.md:284:delete the environment files of the path list, the overlay` deletes that overlay at step 17, and a backup of the forge is no part of the devops product.
- **Add the restic password row to the product cluster-secrets rows and to the Cluster Secrets table of `k8s/README.md`.**: `src/devops_cli/k8s/cluster_secrets.py` holds the product rows in `CLUSTER_SECRETS: tuple[ClusterSecret, ...] = (`, and `tests/invariants/test_k8s_manifests.py:135:def test_readme_lists_the_table` requires each of them in the table of `k8s/README.md`; the restic row of namespace `gitea` is an environment row of dan-petty/homelab, so this repository adds no product row for it.
- **Keep the census of the product groups in the requirement and add `gitea-backup` to it.**: The base text names 10 groups while `tests/prometheus/test_k8s_monitoring_alerting.py:134:REPOS_DRIFT_GROUP = "repos-drift"` shows a product group that the text leaves out, so a census would ship stale text again.
- **Fire the age alert after 48 hours or after 7 days.**: The schedule runs once a day, so 48 hours is 2 missed runs and 7 days is 168 hours of internal work at risk.
- **Add a live restore check to the merge gate.**: `docs/adr/0004-ci-is-the-authoritative-gate.md` makes the CI checks the gate, and the runner pod holds no Kubernetes token, so no check of the gate can run a restore on the cluster.

## Security

The change adds one rule group to a values file under `k8s/` and edits a document, so no credential crosses a trust boundary: the S3 key and the restic password live in the environment Secret rows of dan-petty/homelab, and this repository holds no value. A person must confirm before the merge that the new rule selects only `k8up_jobs_last_successful_timestamp` and that the diff holds no Secret value. `tests/prometheus/test_k8s_monitoring_alerting.py` fails if a rule selects a series outside `SERVED_SERIES`.
