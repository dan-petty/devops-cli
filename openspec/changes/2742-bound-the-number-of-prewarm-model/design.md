# Design

## Decisions

- **The allowed set is `ai.model` plus the models that the servers of the run report.** The servers of the run are the URLs that `resolve_prewarm_urls` returns (`src/devops_cli/ai/endpoints.py:139-149`): the URL of `--url`, else all configured URLs, else the first one. The set has at most 2 plus the number of reported models values, whatever the caller sends. A run with `--model gemma4:26b` is normal use (`tests/ai/mcp/test_ai_prewarm.py:353`), so the name of a model that a server holds stays readable.
- **Ask each server of the run with `list_models(urls=[server])`, one request each.** `_ollama_models` returns the tags of the first server that answers (`src/devops_cli/ai/client/ollama.py:502-530`), so one call over all URLs reads one server, and a model that only the second node holds would show as `other` in some runs. One call for each server gives the union, and a server that fails drops only its own models. The cost is one small `GET /api/tags` for each server of the run, 2 or 3 in a cluster.
- **Add the argument `urls` to `list_models` and `_ollama_models`, with `None` for the old behavior.** The argument replaces `_get_ollama_urls_loop()` as the list of candidates. The round-robin index of chat calls does not move for a listing that names its servers. `devops ai models` (`commands/ai.py:456-458`) keeps calling `list_models()`.
- **Ask only when `ai.provider` is `ollama`.** `preload_models` returns `{}` for every other provider (`ollama.py:104`), while `list_models` makes an authenticated request to `/models` for `copilot`, `openai` and `gateway` (`unified.py:1129-1130`). The guard keeps a no-op command from sending a request with an API key.
- **Read the models inside the existing `with`, after `get_llm_client` and before `preload_models`, and set the span attribute there.** The `with` holds `request_priority_scope(AS_AVAILABLE)`, the same scope that `preload_models` uses (`ollama.py:111`), so the model requests have the priority of the prewarm. The label exists only after the list, so `ai.model` leaves the attributes at span start (`ai.py:821-823`) and `SpanHandle.set_attribute` sets it. The counter reads the same variable, so the two records cannot differ.
- **Catch `AIClientError` and `ConfigurationError` by name, and add no model on either.** The prewarm that follows meets the same server, and reports its failure in the table and the exit code (`render_prewarm_results`, `ai.py:713`). So the error is not lost, and a failed list does not fail a prewarm that could succeed. The issue asks for this fallback to `ai.model`.
- **`bounded_model_label` tests the raw name against the raw names, then applies `bounded_label`.** A server that holds a model name with a symbol keeps the readable label of #2676, and the inner bound of characters and length stays. A model that a server names `other` shares the bucket value, which does no harm.
- **The helper goes beside `bounded_label` in `instruments.py`, and the value `other` in `constants.py` beside the other label constants (`constants.py:950-951`).** `bounded_label` lives in `instruments.py` for the same reason: it is a label rule that other commands can reuse.
- **The new tests join `tests/ai/mcp/test_ai_prewarm.py`, and `ModelFake.list_models` takes `urls` and records each call in `list_models_calls`.** The file already holds the `otlp` collector, the `AI_PREWARMS_TOTAL` points and the 11 test cases that the change makes wrong. `docs/TESTING.md` says a new test joins the file that tests the behavior. A recorded call lets a test show which server the run asked, with no socket.

## Rejected alternatives

- **Bound to `ai.model` alone (2 values).** The refine of the issue rejected it: a person who prewarms another model, which is the use of the command, would see `other`.
- **Call `list_models()` with no argument, as the issue wrote.** The run of the first scratch change showed `['example.org:11434', 'example.com:11434']` for `--url http://example.com:11434` with `example.org` configured. The command asked a server that the person did not name, against "A person types the URL" (`openspec/specs/ai-prewarm/spec.md:9,28`). It also reads one server only (`ollama.py:502-530`).
- **One `list_models(urls=urls)` call over all servers.** It returns the first answering server's tags, not the union (`ollama.py:502-530`).
- **Drop the label with an OpenTelemetry `View` (`attribute_keys`).** `View` (`opentelemetry/sdk/metrics/_internal/view.py:105`) removes `model` from the metric for every run and does not reach the span attribute. The issue asks to keep the model name for the models that exist.
- **Hash the model, or keep a fixed list of names.** The archived design of #2676 rejected both: a person cannot read a hash in a dashboard, and each new model would need an edit of the list.
- **A separate requirement for each of the old three scenarios of the counter label.** The label rule is one rule: the character bound is the inner bound of the value bound. Two requirements for one label would disagree on a model outside the set, which is the defect of the first plan of this change. So the existing requirement is MODIFIED with all its scenarios, and only the span attribute is ADDED.
