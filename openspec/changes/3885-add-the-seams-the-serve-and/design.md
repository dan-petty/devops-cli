# Design

## Decisions

- **Install the server starter through `install_server_starter` and `remove_server_starter`, with a protocol, a real `UvicornStarter` and a `FakeServerStarter`.**: It matches `install_exporter`, gives one fake for the server and the roadmap tests, and the seam is registered in the process-wide reset so no fake reaches a later test.
- **The fake records the start call and, when the call sets `factory`, builds the app from the target and keeps it in `apps`.**: uvicorn builds the app from the factory after it applies the log config, so a fake that builds it too makes the app exist only inside the start; a case that calls the factory itself would assert a warning that appears whatever the command does.
- **Rename the app-build case to `test_serve_service_mode_hands_the_starter_an_app_factory_and_the_json_log_config` and assert the factory flag, the log config, the one app that the fake built and the warning in `caplog`.**: The name then states what the case proves, and a command that built the app itself and passed the app would set no factory and leave `apps` empty, so the case fails.
- **Rewrite all nine `uvicorn.run` patch sites, in `tests/server/test_server.py` and in `tests/roadmap/test_roadmap_run_service.py`, in the group that changes the start of `devops serve`.**: The serve change stops calling `uvicorn.run`, so every case that patches it fails at that step; one group rewrites them together, and the roadmap halt and budget case keeps only its own start patch replaced.
- **The contract test runs the real starter on a loopback port that the test process binds, answers one request and stops the server.**: The testing page's contract suite runs the real implementation of an edge against a real local tool and never a live service, and a loopback port the test binds itself is the one a test may connect to.
- **Publish `LaneSpec` and `lane_specs` in `src/devops_cli/roadmap/run.py`, build the jobs of `service_jobs` from them, and set `app.state.lanes` from them.**: The lane jobs and the metadata then come from one source and cannot drift, and a test reads the table and the clone directory with no patch of `run_due_jobs`.
- **Move the body of the `roadmap run` command into `run_roadmap_command`, which takes the due table, and keep the Typer command as the caller that opens the store.**: The command keeps its exit code and its printed output, and the case drives the real error path with a stub table instead of a patch.
- **Add the two `devops ci` cache cases over `git_fake` alone, and script the checks on it.**: `GitFake` is a `ProcessFake` that answers every other program from its scripted answers, and both `git_fake` and `process_fake` install the process runner, so one case installs one fixture.
- **Lower `_INTERNAL_PATCH_CEILING` by the two patches of a `devops_cli` name that the change removes.**: The living spec of `test-ratchets` says that a fix lowers the ceiling in the same pull request, and the ceiling is `tests/invariants/test_source_tree.py:563:_INTERNAL_PATCH_CEILING = 377` at the staged commit.

## Rejected alternatives

- **Keep patching `uvicorn.run` in each test.**: `tests/server/test_server.py:302:with patch("uvicorn.run") as mock_uvicorn:` and six more sites there, plus `tests/roadmap/test_roadmap_run_service.py:54:with patch("uvicorn.run") as mock_uvicorn:` and line 113, are the patch-shaped tests that ADR 0007 and the testing page forbid.
- **Let the app-build case call the factory that the fake recorded, after the invoke, and assert the missing-secret warning then.**: The review of the plan found it as a contrived test: the warning appears whenever the test calls the factory, whatever the command does, so the case proves nothing about the start; `tests/server/test_server.py:441:with patch("uvicorn.run", side_effect=run) as mock_uvicorn:` read it at the start instead.
- **Leave the halt and budget case of `tests/roadmap/test_roadmap_run_service.py` on `patch("uvicorn.run")` until the lane group.**: `src/devops_cli/commands/serve.py:162:uvicorn.run(` stops being called in the group that changes the start, so that case fails from that step on; the review of the earlier plan found it as a dropped criterion.
- **Pass a starter parameter through the `devops serve` command.**: It leaks a test detail into the command signature and every caller, while `src/devops_cli/telemetry/tracer.py:def install_exporter` already shows the process-wide install hook that this repository uses for an edge.
- **Keep patching `run_due_jobs` in the two roadmap tests.**: `tests/roadmap/test_roadmap_run_service.py:59:with patch("devops_cli.roadmap.run.run_due_jobs") as mock_run:` and `tests/roadmap/test_roadmap_run_due_table.py:420:with patch("devops_cli.roadmap.run.run_due_jobs", side_effect=failing_adapter):` are the two sites that the issue asks to remove.
- **Compare only the config of the real starter in the contract test, and start no server.**: The issue asks for a contract test in which the real starter serves a request on a loopback port and stops, and the testing page names a real local tool for the real side of a contract suite, so a config comparison alone drops the criterion.
- **Add a module-level install hook for the lane jobs instead of app state.**: It adds global state and a reset for no gain, while `src/devops_cli/server/service.py:1179:app.state.jobs = lane_jobs` already shows that the app state is the public place a test reads what the command built.
- **Request both `process_fake` and `git_fake` in one `devops ci` case.**: `tests/support/fakes/git.py:139:set_process_runner(fake)` and `tests/support/fakes/process.py:453:set_process_runner(fake)` install the same seam, so the second fixture replaces the first and the answer that edits the tracked file never runs.
- **Test only an error formatter for the Rich markup case.**: It does not cover the exit code and the output of the command, which `src/devops_cli/commands/roadmap.py:def run_cmd` owns, with `src/devops_cli/commands/roadmap.py:651:print_error(str(exc), safe=True)` and the class `src/devops_cli/exceptions/roadmap.py:class RoadmapRunError`.
- **Defer the two `devops ci` cache cases until #1333 lands.**: `read_issue` for #1333 answered 'closed (completed)', and the async start of a check now goes through the process runner that `git_fake` answers, so the two cases are added now.
