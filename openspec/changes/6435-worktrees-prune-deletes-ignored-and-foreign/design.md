# Design

## Decisions

- **Put the shared scope rule in one public function `scope_refusal(entry, *, managed_root)` in `src/devops_cli/git/worktree_inventory.py`, beside the data counter.**: The module already holds the counter and the prune decision, so one import serves both callers and no new module appears. The reclaim already imports from it.
- **Check the folder first, then the ignored data files.**: The order matches the reclaim, so both callers give one reason for one worktree, and a worktree outside the folder costs no git call.
- **Count only the ignored data files: the files that `.gitignore` hides, but not the regenerable paths.**: A regenerable path is a cache or a build output that a command makes again. The measure of 2026-11-20 (proposal, Feasibility) found 1 to 165 ignored entries in each used worktree, nearly all of them caches (`.venv`, `__pycache__`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`, `.hypothesis`, `dist`, coverage output). A rule that counts every ignored path keeps almost every used worktree, and only `--force` frees the disk (about 1.5 GB for each worktree), while `--force` also removes unmerged work. Each other ignored file is data, for example `.data/agent/**`, `.env*`, `.code-workspace` and `config.yaml`, and keeps the worktree. An empty directory holds no data. The reclaim of #4092 takes the same rule, so it now takes a merged worktree that holds only caches.
- **Count with git's own plumbing: `git -C <worktree> ls-files --others --ignored --exclude-standard -z` with one `:(exclude)` pathspec for each regenerable path.**: Git applies the ignore rules of the worktree (`.gitignore`, `.git/info/exclude`, `core.excludesFile`), as the old `git status --ignored` call did. The call lists each ignored file, also inside an ignored directory such as `.data/`, and lists no empty directory. It took 0.21 to 1.05 s in the measured worktrees, about 1.3 times the 0.12 to 0.69 s of the old call.
- **Name the regenerable paths in one constant, `CONST_WORKTREE_REGENERABLE_PATHSPECS: Final[tuple[str, ...]]` in `src/devops_cli/config/constants.py`, as git exclude pathspecs.**: The caches that a tool names at any depth use the glob magic: `:(exclude,glob)**/__pycache__/**`, `:(exclude,glob)**/.pytest_cache/**`, `:(exclude,glob)**/.ruff_cache/**`, `:(exclude,glob)**/.mypy_cache/**`, `:(exclude,glob)**/.hypothesis/**`, `:(exclude,glob)**/node_modules/**` and `:(exclude,glob)**/.coverage*`. The outputs at the root of the worktree use a plain pathspec, which also matches the files under a directory: `:(exclude).venv`, `:(exclude)dist`, `:(exclude)build`, `:(exclude)htmlcov`, `:(exclude).data/cache`, `:(exclude).data/rag`, and the coverage outputs that `pyproject.toml` writes under `.data/`: `:(exclude).data/htmlcov`, `:(exclude).data/coverage.xml` and `:(exclude).data/coverage.json`. `dist`, `build` and `htmlcov` match only at the root, so a folder of that name under `.data/agent/scratch` stays data.
- **Rename `count_ignored_paths` to `count_ignored_data_files(worktree_dir: Path) -> int | None`, and delete `CONST_GIT_IGNORED_PREFIX`.**: The new name says what the count holds, and the docstring and the reasons say "ignored data file" in the same words. A directory that is gone holds no file, so it counts 0. None means that git failed, so the count is unknown and the worktree stays. `CONST_GIT_IGNORED_PREFIX` parsed the output of `git status --ignored`, and no other code reads it.
- **Give the reasons the folder and the count: `outside the managed folder <folder>`, `holds 1 ignored data file` or `holds 3 ignored data files`, and `ignored data files are unknown (git ls-files failed)`.**: The issue asks the preview to name the folder and the count, and one shared text keeps both callers equal. The singular form follows the existing dirty reason.
- **Rename the three kept reasons from `worktrees_add_kept_outside`, `worktrees_add_kept_ignored` and `worktrees_add_kept_ignored_unknown` to `worktrees_kept_outside`, `worktrees_kept_data` and `worktrees_kept_data_unknown`, and keep `worktrees_add_kept_line`.**: Prune and the reclaim give these reasons, so the `add` prefix would name one caller only. The line message belongs to the renderer of `add` and keeps its name.
- **Ask the scope rule in `_decided_by_local_state` after the main worktree, the current directory and `--force`, and before the lock, the missing directory and the dirty state.**: The order is main, current directory, `--force`, scope (folder, then data files), lock, missing directory, dirty state, merged pull request. The coordinator decided the case of a record whose directory is missing: the reclaim is right to keep it outside the folder. A directory can look missing from this container while another container or tool still uses it, for example through a shared home volume or the folder of another tool. So the folder refusal comes before the missing-directory rule, also for a prunable record. A missing directory holds no file, so its data count is 0, and a missing directory under the managed folder stays removable. `--force` keeps its precedence, as today. The scope comes before the lock and the dirty state because the reclaim asks the scope first, so prune and the reclaim give the same reason for one worktree.
- **Give `_decided_by_local_state`, `_decide`, `plan_prune` and `prune_worktrees` a required keyword-only `managed_root: Path`, and change each caller in the same task group.**: A keyword-only parameter cannot bind a positional argument by mistake, and a required one makes each caller name the folder, so mypy and Python refuse a caller that forgets it. The callers are `worktrees_prune` of `src/devops_cli/commands/repos.py`, `reclaim_merged_worktrees` of `src/devops_cli/git/worktree_add.py` and the direct call of `tests/git/test_repos_worktrees_reclaim.py`.
- **Pass the resolved managed folder from the callers, and leave `managed_folder` in `src/devops_cli/git/worktree_add.py`.**: `worktree_inventory.py` reads no settings, and `worktree_add.py` imports it, so a move would need a settings read in the decision module or an import cycle. Both callers already import `managed_folder`.
- **Keep the scope pass `_split_by_scope` of the reclaim, now with `scope_refusal`, and pass only its in-scope worktrees to prune with `managed_root`.**: The reclaim names each worktree that it keeps for scope, and it never names the main worktree; prune names every worktree. Prune asks the rule again for the in-scope worktrees, which costs one more `git ls-files` for each worktree under the managed folder that holds no data file (0.21 to 1.05 s each in the measure). The reclaim removes the merged ones of these worktrees on its first run, so few stay.
- **Refuse in the dry run as well.**: `plan_prune` asks `_decided_by_local_state`, so the preview lists no read for a worktree that the scope keeps, and it shows the same refusal as a run with `--confirm`.
- **Move the worktrees of the prune tests under the managed folder before the prune decision changes, and run that module in the verification of each group that changes it.**: A prune test that builds its worktree under `tmp_path` would be refused after the change and would test nothing. Moving it first keeps each step green.
- **Test with real temporary repositories and worktrees, as `tests/git/test_repos_worktrees_reclaim_scope.py` does.**: The fake git of `tests/git/test_repos_worktrees.py` answers `ls-files` with no output, so only a real repository shows which files git lists. Each case runs through prune and through the reclaim: only caches (removed), a scratch note (refused, `holds 1 ignored data file`), a `.env.local` (refused), only `.data/cache` (removed), and a missing directory outside the folder (refused).
- **State the scope in the docstring of `worktrees_prune`, in `HELP.repos.worktrees_force` and in section 5 of `CONTRIBUTING.md`, and regenerate `docs/commands/repos.md`.**: The docstring is the help of the command: `docs/commands/repos.md` shows it as the summary of `prune`. The section holds the worktree rules that a contributor reads. The help of `--force` names both worktrees that it keeps: the main worktree and the worktree that holds the current directory.
- **Delete `HELP.repos.worktrees_prune`.**: `git grep -n "worktrees_prune" -- src` finds only its definition at `src/devops_cli/lang/en/help.py:660:` `worktrees_prune: str = (` and the names of other messages, so no code reads it. A second text of the scope that nothing shows would drift from the docstring.

## Rejected alternatives

- **Count every ignored path, as the reclaim of #4092 does.**: The measure found 1 to 165 ignored entries in each used worktree, nearly all of them caches, so the rule keeps almost every used worktree. Only `--force` then frees the disk, and `--force` also removes unmerged worktrees.
- **Keep `git status --porcelain --ignored -z` and filter its output.**: It shows an ignored directory as one entry: `git status --porcelain --ignored -z` in `.data/agent/worktrees/w-6461` printed `!! .data/` and `!! .venv/`. The filter cannot tell `.data/cache` from `.data/agent/scratch`.
- **Walk the worktree in Python and match the `.gitignore` patterns.**: It copies the ignore rules of git, which `git ls-files --exclude-standard` already applies (AGENTS.md rule 3).
- **Reuse an existing list of cache folders.**: `src/devops_cli/config/constants.py:4241:` `CONST_SEMGREP_EXCLUDED_DIRECTORIES: Final[tuple[str, ...]] = (` and the lists of `src/devops_cli/commands/devcontainer.py`, `src/devops_cli/security/prompt_injection.py` and `src/devops_cli/roadmap/stage/stage_removal_references.py` serve scans and volumes. Each holds `.data`, `.git` or `.uv`, and `.data` holds agent data.
- **Count `mutants`, `.data/camp` and `.data/junit.xml` as regenerable.**: A mutation run or a test camp takes hours, and a person can still read its results. The measure found them in 3 of 27 worktrees, and `--force` removes such a worktree.
- **Ask the scope after `_decided_by_local_state`, as the first plan did.**: `src/devops_cli/git/worktree_inventory.py:405:` `if entry.prunable:` returns removable before the scope, so prune would remove the record of a worktree outside the folder whose directory is missing, while the reclaim keeps it.
- **Check the data files before the folder.**: It changes the reason of a worktree outside the folder and adds a git call for it, while the reclaim checks the folder first at `src/devops_cli/git/worktree_add.py:272:` `if not Path(entry.path).resolve().is_relative_to(folder):`.
- **Make `--force` keep the worktrees that the scope refuses.**: The issue states that `--force` stays the way to remove every worktree, and `src/devops_cli/git/worktree_inventory.py:400:` `if force:` returns `forced` before the rules that it skips.
- **Mark a scope refusal on the item of the prune report, so the reclaim reads it from prune and counts once.**: It adds a field to the JSON of `prune` and `add` to save one git call for each in-scope worktree.
- **Make the scope a method on the worktree record.**: The rule needs the managed folder and a git call, which a value object does not hold: `src/devops_cli/git/worktree_inventory.py:60:` `class WorktreeEntry(BaseModel):` holds the fields of a record.
- **Put the scope in a new module `worktree_scope.py`.**: One small function does not justify a module, and the rule belongs beside its only decision, `src/devops_cli/git/worktree_inventory.py:417:` `def _decide(`.
- **Keep the old reason text `outside the managed folder` with no folder.**: The issue asks the preview to name the folder, and `src/devops_cli/git/worktree_add.py:272:` `if not Path(entry.path).resolve().is_relative_to(folder):` already holds it.
- **Edit `docs/CLI_REFERENCE.md` by hand.**: `devops docs generate` writes the command pages from the command tree, and the `docs` row refuses a page that is not the output of its generator.
- **Add a worktree manager library.**: The alternatives check of 2026-11-19 found only gtr and its wrappers, which are archived and decide no scope.

## Unchanged references

- `src/devops_cli/commands/repos.py` (message name): The module holds only `worktrees_add_kept_line` at line 708, and that message keeps its name.
