# Design

## Decisions

- **The level of each caller comes from the table of #2424.** Each URL of the table, except the Loki URL and a direct cluster-service URL, comes from the configuration of the person (`grafana.url`, `prometheus.url`, `argocd.url`). These callers dial at `configured_level(settings.ai)`. Loki and the direct cluster-service URLs stay at the private level, which they have now.
- **The credential functions take an `EgressLevel`.** `mint_argocd_token`, `mint_grafana_token`, `verify_argocd_token` and `verify_grafana_token` take a keyword `level` with no default. Before, they took `allow_private_network: bool = True`, and the sync used that default, so the sync checked the URL as if the flag were set. The caller that has the settings decides the level: `get_or_mint_argocd_token`, `get_or_mint_grafana_auth` and `sync_k8s_credentials` give `configured_level(settings.ai)`. A required level makes a new caller choose it.
- **A refused address is a failed credential step.** Before, the pre-flight refusal came out of the mint or the check as `SSRFBlockedError`, but the sync never got one, because it allowed private addresses. With the configured level, the sync can get a refusal. The mint and the check turn `SSRFBlockedError` into `StackCredentialError` with the cause, as they do for `httpx2.RequestError`. The `stack-credential-sync` spec already counts a request error as a failed check. So the sync reports `failed` with the cause and keeps the stored token, and `get_or_mint_grafana_auth` falls back to the admin password with a warning.
- **The commands report a refusal without a traceback.** The pre-flight refusal printed an error and exited with status 1. The connect raises `SSRFBlockedError` from the request. The Typer apps of `devops grafana`, `devops grafana dashboards`, `devops prometheus` and `devops argo cd apps` get `exit_on=SSRFBlockedError`, which prints the message of the error and exits with its status. That status is 2, the status that `docs/ERRORS.md` gives `SSRF_BLOCKED`. `cd apps list` and `cd apps status` show each error of their request in their table or panel, as before. `dashboards sync` reports the error of each file and goes to the next file, but it lets `SSRFBlockedError` out of that handler: the refusal applies to each file, so the run stops at the first file and `exit_on` reports it.
- **A failed Argo CD token mint ends the command with its cause.** With the admin password and no stored token, `_argocd` mints a token before the request of each `devops argo cd apps` command. The mint makes a refusal a failed credential step (`StackCredentialError`), so the refusal does not come to `exit_on`. `_argocd` reports `StackCredentialError` with `exit_on_error`: the command prints the failed mint with its cause, without a traceback, and exits with status 1. The spec names this status for a refusal in the mint. Before, the error of a failed mint came out of the command with a traceback.
- **The early URL check reads only the URL.** `devops k8s configure-urls --addressing proxy` writes `k8s://` addresses to `argocd.url`, `grafana.url` and `prometheus.url`, and the settings type admits them. These commands cannot dial such an address, and httpx2 would raise `UnsupportedProtocol` from the request with a traceback. The deleted `validate_service_url` refused the scheme first. `_clean_service_base_url` of `k8s/credentials.py` already made this check for the token calls with `urlsplit`, and it names the setting in its `ConfigurationError`. It moves to `devops_cli.http.urls` as `service_base_url`, and the three command groups call it. It makes no lookup. `_argocd` calls it before the token mint, so a `k8s://` address stops the command with the error that names the setting, and the mint does not run.
- **The fleet sync, the GitOps sync and the rollout gate need no early check.** Each one catches the error of one request and reports it in its result: the fleet and the GitOps sync with `except Exception`, the rollout gate with `except (httpx2.HTTPError, ValueError, ...)`. `UnsupportedProtocol` is an `httpx2.HTTPError`, and `SSRFBlockedError` is a `ValueError`.
- **Loki and the direct cluster-service URLs need no scheme check.** httpx2 2.13.1 refuses a scheme other than http and https with `UnsupportedProtocol` before any lookup. The Loki test that expected `SSRFBlockedError` for an `ftp://` URL now expects `UnsupportedProtocol` and no lookup.
- **The timeouts stay the same.** Each moved request keeps its own `timeout=` argument, which overrides the client timeout as before. The credential clients get `timeout=httpx2.Timeout(timeout)`, the bound of their raw clients.
- **Three tests show the defect.** `test_each_caller_dials_at_its_level` gets a row for each caller of the table, with and without the flag, and fails when a caller host name reaches the dial. `test_each_k8s_service_caller_dials_the_address_it_checked` is the reproduction of the issue: each host answers a public address at the first lookup and cloud metadata at each later lookup. `test_loki_and_a_direct_service_url_look_up_their_host_once` counts the lookups of one request.

## Rejected alternatives

- **Give a refusal in the Argo CD token mint status 2.** The mint turns `SSRFBlockedError` into `StackCredentialError`, because the `stack-credential-sync` spec counts a refusal as a failed step. For status 2, `_argocd` must read the cause of the error, or `StackCredentialError` must carry the status of `SSRF_BLOCKED` with its own error code, which `docs/ERRORS.md` does not give it. The message of the failed mint gives the refusal.
- **Send the Argo CD request without a token when the mint fails, as the Grafana commands use the admin password.** The Argo CD requests authenticate only with a bearer token, and the admin password gives a token only through the session call that failed. A request without a token gets an authentication error from Argo CD, which hides the cause of the failed mint.
- **Keep the sync at the private level.** The sync reads `argocd.url` and `grafana.url` from the configuration, as the commands do. The #898 level table gives the session and token checks of `k8s/credentials.py` the configured level, and the issue asks for it. A private address that the commands refuse without the flag must not get a token through the sync.
- **Give the credential functions a default level.** A default of `PRIVATE` keeps the old fail-open default. A default that loads the settings hides a read of the configuration in a function that takes a URL.
- **Check the scheme with `HttpUrlStr` in a `TypeAdapter`.** It also makes no lookup, but its pydantic error does not name the setting, and the token calls already use `_clean_service_base_url` for the same URLs. One check for the same URLs gives one message.
- **Keep `_clean_service_base_url` in `k8s/credentials.py` and import it from the Prometheus commands.** The Prometheus commands have no credentials. `devops_cli.http.urls` holds the other URL helpers.
- **Catch `SSRFBlockedError` in each command and exit with status 1.** That keeps the old status, but it adds an error branch to each command for what `exit_on` already does for every command of an app, and it gives the refusal a status that `docs/ERRORS.md` does not list for it.
- **Send `k8s://` addresses through the API server proxy in these commands.** That is a new feature, not this fix. `service_http.get_json` does it for the callers that read JSON only.

## Non-goals

- `commands/config.py`, which checks the URLs when a person sets them. #1381 keeps the configuration wizard as a pre-flight caller, and part 5 (#2437) changes it to `vet_addresses`.
- `commands/k8s/cluster_context.py:197`, the check of `devops k8s apply`. kubectl dials that URL. Part 5 changes it.
- `_resolve_host_ips` and `_enforce_non_private_ssrf` in `core/validation.py`. Part 5 deletes them.
- The general statement that every HTTP client is checked at the connect. Part 5 writes it when it is true.
