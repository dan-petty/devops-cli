# Design

## Decisions

- **Measure on a local host that is idle, not in CI.** The issue needs a load under 2 before each run. A CI runner is shared, and the 2026-10-27 comparison failed at a load of 10 to 39. The runner script reads `/proc/loadavg` before each run and records it, and the verification of group 2 fails when one row holds a load of 2 or more.
- **Wait for the idle host, and stop when it does not come.** The load of this workstation is 30.65 now (`/proc/loadavg`), because agents run beside each other. Each run waits for a 1-minute load under 2, for at most 30 minutes. After that the work stops and reports the load. A number from a loaded host is never recorded, and nothing lowers the condition.
- **Use the median of three runs, in rounds.** The four configurations run in the order none, lines, branches, ctrace, and this order repeats three times. A slow drift of the host then falls on all four configurations. The median does not follow one outlier run.
- **Take CPU time from the bash `time` keyword.** With `TIMEFORMAT='%U %S %R'` it gives user, system and wall time of the command and of every process it waited for, the xdist workers included. The CPU time is user plus system.
- **Keep the options of the gate for all four configurations.** The "lines" command is the output of `_resolve_pytest_cmd`. The "none" configuration drops `--cov=src` and `--cov-report=term-missing`. The "branches" configuration adds `--cov-branch`. The "ctrace" configuration sets `COVERAGE_CORE=ctrace`. The worker count (`-n logical`), the `worksteal` distribution and `--durations=10` stay the same in all four, since they come from `addopts` and the gate command.
- **Time the serial end on a 13th run that keeps the worker files.** `pytest-cov` combines the files of the workers and deletes them, so a normal run leaves one combined file. A scratch plugin `keep_cov.py` wraps `coverage.Coverage.combine` so that it calls the original with `keep=True`, and the run is the "lines" command with `-p keep_cov`. Then `coverage combine --keep`, `coverage report --show-missing` and `coverage xml` run alone, three times each, on those files.
- **Define "a large share" as 5 % of the wall time of the lines run.** The issue says "large" and gives no number. AGENTS.md makes a check that averages more than 5 minutes a P0 bug, and the guard `devops ci job-time` fails over a mean of 300 s, so 5 % of a run is about 15 s of that budget. The share is `coverage combine` plus `coverage report` (the two steps that the gate pays) over the median wall time of "lines". `coverage xml` runs in the `Changed-Line Coverage` step of CI, so it is stated beside the share and not in it.
- **The extra run is a measure, the change of options is a follow-up.** When the share is 5 % or more, the "lines" command runs three more times with `--cov-report=` (no report) and the saving is stated. A change to `_resolve_pytest_cmd` needs a MODIFIED requirement of `ci-coverage-reports`, new tests and a decision about the term report that people read, so it is its own issue. This change alters no option and no threshold.
- **Put the result in the pull request body and on #2163.** The issue asks for the table in the pull request and for the statement on #2163. No file of the repository holds the numbers, so no tracked file can go stale. The scratch files stay in `.data/agent/scratch/2373/`.
- **No spec delta.** The change alters no command, option, message, manifest or service. The scenarios of a benchmark record cannot be asserted by a test under `tests/` offline, so `.openspec.yaml` sets `skip_specs: true`.

## Rejected alternatives

- **Run the benchmark in a CI job.** Rejected: a runner is shared, so the load cannot be held under 2, and the issue says no recurring job is added.
- **Use the 568 s run of #2356 as the cost of branches.** Rejected: that run changes the core, the contexts and the branches together (`openspec/changes/archive/2026-10-27-2356-coverage-floor-and-test-cost/design.md`, line 80).
- **Use `coverage run` with `patch = subprocess` to get uncombined files.** Rejected: it measures every Python subprocess that the tests start, and the gate does not (`pyproject.toml` has no `patch` key), so the data and the time of the combine step differ from the gate. The plugin keeps the data of the gate command.
- **Time the three commands on the normal combined file.** Rejected: `coverage combine` has nothing to combine in it. `DistMaster.finish` in `pytest_cov/engine.py` combines and deletes the worker files.
- **Use `hyperfine`.** Rejected: it is not installed and in no tools lock (`git grep -n -i hyperfine origin/main -- . ':!openspec'` prints nothing), and bash `time` gives the same numbers for twelve runs.
- **Keep the table in a file of the change folder.** Rejected: the issue asks for the pull request body and a comment on #2163, and a file in the folder would be archived with the change and read by nobody.
- **Change `--cov-report` in this pull request.** Rejected: see "The extra run is a measure". The acceptance criterion 4 holds when no option changes.
