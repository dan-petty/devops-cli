# Proposal

## Why

The implement step reaches the code of its checkout with fewer code-intelligence reads than a person in the devcontainer, and nothing states which tools it has (#3148). Its prompt names its tools in one sentence, its pull request comment names no tool call, the MCP implementation role holds two lookups that send a model-chosen value to an outside service, the local command table states the symbol graph as a write, and `devops roadmap eval implement` cannot score the step with its remote tools off. So the step works with less evidence than a person, one of its tools reaches the network, and a change to its tools cannot state a score before and after.

## What Changes

- The registry `TOOLS` gives `read_file` and `list_files` the implement holder beside the stage holders, and the step takes `IMPLEMENT_LOCAL_TOOL_NAMES` from `tool_names(HOLDER_IMPLEMENT)` in place of a hand-written set.
- The implement prompt holds a table of the tools it offers, built from the registry: each name, its read flag and its purpose.
- `ToolCallLog` counts every call by tool name, and the comment of a Job on its pull request names the tools it called in one line beside the table of the steps, with their counts and no argument, path or file content in that line.
- The implementation role drops `security_intel_network` and `security_intel_package`, and the planning and review roles keep them, so the role holds 15 tools and the two count tests state 28, 15 and 16.
- The `ai ast` row of the local command table has access read and names no `--output`, beside the read row of `ai repomap`.
- `devops roadmap eval implement` accepts `--no-tools`, runs the same selected fixtures with the remote MCP tools of the step off, and records the tool mode in its report beside the model.
- `docs/ROADMAP_WORKFLOW.md` states the tools table, the tool counts of the pull request comment and the two eval modes, and `docs/CLI_REFERENCE.md` and `docs/commands/roadmap.md` are regenerated with the `--no-tools` option.
- The change carries a spec delta for the prompt, the pull request comment, the MCP role table and the eval, because a prompt, a comment, a command option and the tools of a job are observable.
- The change fits one pull request.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `roadmap-implement-step/inputs`: The implement prompt lists the tools of the registry, The prompt lists the local devops commands of the catalog
- `roadmap-implement-job/pull-request`: The pull request comment names the tools of the job
- `mcp-role-server`: The implementation role holds no threat-intelligence lookup
- `roadmap-eval-implement`: The eval compares the tool modes
