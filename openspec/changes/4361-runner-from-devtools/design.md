# Design

## Decisions
- **One `devtools` stage names the image.** `FROM ghcr.io/dan-petty/devtools:<date>@sha256:<digest> AS devtools` is the one reference. `runner-deps` builds FROM it, and the Service and MCP server stages `COPY --link --from=devtools` single programs. Renovate's `dockerfile` manager moves the tag and the digest of that line in the `devtools` group, with `.devcontainer/Dockerfile`.
- **The runner builds its own venv and project.** The venv of the devtools Python and the venv of `python:3.14-slim-trixie` have different interpreters, so `runner-deps` installs the requirements of the `lock` stage again, and `runner-builder` installs the project on it. The runner target then builds no stage of the Service path but `lock`. The requirement files come in as bind mounts, so no layer holds them.
- **The runner smoke test keeps `python -m devops_cli.roadmap.runner_tools`.** The issue asked for a `<tool> --version` line for each tool. The check module already runs the version command of each tool of `RUNNER_TOOLS`, holds no version (#5585) and does not call `devops install-tools`. The requirement "The smoke test of the runner image uses the table" forbids a version command of its own in the workflow, and one list stays one list. The build step that ran it goes, so a change of `src/` does not run it again.
- **The MCP server image is the Service image with kubectl and helm.** It builds on `service-deps` through `mcp-server-deps`, which copies the two programs. So the copy from the devtools image is in a cached stage, and only the `apt-get upgrade` and the project build again. The served tools of the job roles (`src/devops_cli/ai/mcp/roles.py`) run `devops` commands in-process, and these start gh (GitHub reads), kubectl and helm (cluster reads). `k8s audit` starts popeye, which the old image did not hold either.
- **OpenSpec comes from the devtools npm tree.** The tree holds Claude Code, Copilot, the Dev Containers CLI and Style Dictionary next to OpenSpec, 658 MB in all. Stage `openspec` writes a `package.json` with only OpenSpec at the installed version, and `npm prune --offline --ignore-scripts` removes every other package. The Service image gets 23 MB, and the official Node binary runs it, because the Node of sid needs glibc 2.43 and trixie has 2.41.
- **The runner scan reports; the other scans gate.** The owner approved this on 2026-11-19 (dan-petty/devtools#3, #5447). The project venv of the runner is the lock of `uv.lock`, which the osv-scanner audit row of the gate checks. The local scan found no finding in `/app/.venv`.
- **The runner size bound follows the base.** The devtools image is 4.88 GB, and the runner is 6.38 GB, so the bound of 3000000000 bytes cannot hold. The new bound is 7000000000 bytes, about 10% over the measured size, so a jump in the devtools image still fails the job.
- **Ignore entries only where a gate reads them.** The MCP server copies kubectl from the devtools image, so its four entries move to `usr/local/bin/kubectl`. The entries of tofu, promtool, Trivy and actionlint hid findings only in the runner scan, which no longer gates, so they go.
- **The tool table follows the image.** `ToolSource` names `devtools` in place of `apt`, `tools-lock` and `image-pin`. kubectl, kube-linter, osv-scanner, npm, zsh and ps move from `NOT_IN_RUNNER` to `RUNNER_TOOLS`, because a source of the gate needs each one and the image holds it. The other programs that the devtools image holds stay in `NOT_IN_RUNNER`, because no source of the gate runs them in a Job, and their reasons no longer say that the image lacks them.

## Rejected alternatives
- **Two scans of the runner: report-only, and a gate that skips the devtools tools.** The local scan found every finding under `/usr/local/bin` and `/usr/local/lib/devtools`, so a gate with `--skip-dirs` on these two folders would pass today. But it checks only `/app/.venv`, which the audit row already checks from `uv.lock`, and it adds a second scan of a 6 GB image and a `skip-dirs` input to the action. The owner text of the table entry (#5447) names the osv-scanner gate on the lock files as the kept gate.
- **Copy the whole npm tree of the devtools image into the Service image.** It adds 658 MB with Claude Code and Copilot, and the full gate of the Service scan would read their packages.
- **Name the OpenSpec packages in the `Dockerfile`.** OpenSpec 2.1.1 needs 65 packages. A list of them changes with each OpenSpec release, which is the copy that the owner decision forbids.
- **Share one `builder` between the runner and the Service image.** The runner target would then build the Service venv on `python:3.14-slim-trixie` too, about 60 s more on a cold cache, to copy files that `runner-builder` makes in 10 s.
- **Keep `apt-get upgrade` in the runner.** The devtools image is rebuilt each day with `apt-get upgrade` of sid, so a second upgrade adds a layer and time and no update.
