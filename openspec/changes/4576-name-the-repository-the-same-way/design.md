# Design

## Decisions

- **Attach the repository filter to the Service `json` handler, as the trace filter `src/devops_cli/telemetry/logging_bridge.py:class TraceCorrelationFilter` is attached there.**: The handler sees each record it formats, and it is the one writer of the JSON lines of the Service.
- **Hold the current repository in a context variable of the new module `repo_context` under `src/devops_cli/telemetry`, set at the edge and read by a logging filter.**: ADR 0022 parses `owner/name` one time at the edge. One filter then names each record with no change to a call site.
- **Give a record `repo` with the casefolded key whenever a reference is current, replacing any `repo` the record carries, and leave the record unchanged when no reference is current.**: The router's delivery record writes its own `repo` with the GitHub spelling, and only the filter can replace it with the key; a service-level record names no repository, so it gets no empty value.
- **Write the router's delivery record inside `repo_scope` in `src/devops_cli/server/routes/webhooks.py:def conclude`.**: The record is written after the route returns, so the scope has to cover that call, and the filter then names it with the casefolded key of the delivery's repository.
- **Use the OpenTelemetry VCS attributes `vcs.provider.name`, `vcs.owner.name` and `vcs.repository.name` in place of the span attribute `service.repo`.**: An open, maintained convention that Tempo and Grafana read, and ADR 0022 adopts it.
- **Hold `service.repos` in `ServiceManager` as casefolded `RepoRef` keys: the class that begins `class ServiceManager:` builds the workers and primes the counters from that one set, and the class that begins `class RepoRef:` gives the key.**: Every metric label of the Service reads the repository from that set or from the trigger batch, so one casefolded set gives one label value and no second spelling.
- **Give a `RepoWorker` the `RepoRef` values of `service.repos` as a keyword, and set its `repo` label with `RepoRef.metric_value`: the class that begins `class RepoWorker:` takes the keyword, and the class that begins `class RepoRef:` gives the bounded value.**: The keyword stays optional for the tests that build a worker directly, and the label then falls back to `other` for a repository outside `service.repos`.
- **Give the `repo` label of a repository outside `service.repos` the value `other`, the staged constant `OTHER_REPOSITORY`.**: A webhook from an unknown repository cannot grow the label set without limit, and the value stays fixed.
- **Write `annotations: {roadmap.devops-cli/repository: repo}` under `podLogsViaLoki`, with the annotation name as the key and the Loki label as the value.**: The chart maps a Kubernetes annotation name to a Loki label name, and the annotation name holds `/` and `.`, which a Loki label name cannot hold.
- **Keep the router stream labels and write the repository into the JSON body of each router line.**: The router serves many repositories, so a `repo` stream label per repository would multiply the streams of one pod.
- **Prove the values mapping with the `uv run devops ci --check --only charts` render and the router's stream labels with a check of the `k8s` row, and give each `monitoring-collectors` scenario a result that a test asserts.**: No offline command other than the `charts` row renders the Helm values, and a live Loki query or a live `kubectl` read is no result that a test asserts.

## Rejected alternatives

- **Attach the repository filter to the root logger.**: The service log config sets `propagate` to false on the `devops_cli` logger: `src/devops_cli/server/json_logs.py:84:name: {"handlers": ["json"], "level": numeric_level, "propagate": False}`. A record of that logger never reaches the root, so a root filter misses it.
- **Pass the repository to each logging call.**: The JSON formatter already writes the key from the record: `src/devops_cli/server/json_logs.py:14:CONTEXT_LOG_KEYS: Final[tuple[str, ...]] = (` starts the tuple that holds `repo`, so one filter that sets the record attribute needs no call site and covers the records that libraries write.
- **Keep the span attribute `service.repo` and add no VCS attributes.**: `src/devops_cli/server/service.py:684:"service.repo": self.repo,` is the project-specific key that no convention or dashboard reads, while `src/devops_cli/github/repo_ref.py:223:def span_attributes(self) -> dict[str, str]:` already builds the three VCS keys that Tempo and Grafana read.
- **Let the filter leave a `repo` that the record already carries.**: `src/devops_cli/server/routes/webhooks.py:467:"repo": self.repo,` writes the GitHub spelling of the repository, so a filter that leaves it keeps a value that differs from the casefolded key of `RepoRef`, the class that begins `class RepoRef:`, for a repository such as `Example-Org/Repo1`.
- **Bound only the labels of `RepoWorker` (the class that begins `class RepoWorker:`) and the priming, and leave the metric labels of the webhook route.**: `src/devops_cli/server/routes/webhooks.py:639:labels={"repo": payload.repository.full_name, "reason": reason},` writes the payload's spelling, so `count by (repo)` would hold `Example-Org/Repo1` beside `example-org/repo1` for one repository.
- **Casefold `service.repos` in the setting itself.**: `tests/config/test_settings.py:64:assert ServiceConfig(repos=["Owner/Repo", "owner/.github"]).repos == [` asserts that the setting keeps the configured spelling, so the Service casefolds its own copy of the set instead.
- **Add a `repo` stream label to the router pod.**: The router serves every managed repository: `src/devops_cli/server/routes/webhooks.py:763:for repo in sorted(service_manager.managed_repos)`. A stream label per repository would multiply the streams of the one router pod.
- **State the unit-pod and the router scenario as live checks against the cluster, such as `uv run devops k8s logs <unit-pod> --query` and `kubectl -n devops get deployment roadmap-service`.**: `docs/TESTING.md` names `uv run devops ci --check --only k8s` and `uv run devops ci --check --only charts` as the proof of a manifest change, and no offline test asserts the answer of a Loki query or of a `kubectl` read against the cluster, so the result would stay unverified.

## Security

The repository name crosses a trust boundary: the k8s-monitoring chart turns the pod annotation `roadmap.devops-cli/repository` of a unit pod into the Loki stream label `repo`, so a value that is not the casefolded `owner/name` of a repository of `service.repos` reaches the log store as a label of its own. A person must confirm that the annotation comes from `RepoRef.key` alone and holds no item number, no branch and no pod name, and that the router Deployment carries no such annotation, because its one pod serves every repository and a per-repository stream label would multiply its streams. The check that fails when the rule breaks is `check_the_router_deployment_carries_no_repository_annotation` in `tests/gate/k8s_checks/roadmap_service.py`, run by `uv run devops ci --check --only k8s`, together with the mapping assertion of `tests/core/test_third_party_telemetry.py`.
