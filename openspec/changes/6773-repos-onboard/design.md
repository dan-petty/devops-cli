# Design

## Decisions

- **One package.** `src/devops_cli/github/onboard/` holds the rows: `model.py` (the row, its state, the person steps and the report), `routes.py` (the route table and the writer), `baseline.py` (the template ref, the answers and the render), `settings_rows.py` (rows 0 to 6 and 10), `template_pr.py` (rows 9 and 11), `service_rows.py` (rows 7, 8 and 12 to 15, moved from `roadmap/onboard.py`) and `run.py` (the order of the rows, the output and the dry run). `src/devops_cli/commands/repos.py` is a thin adapter.
- **One code path.** Each row reads with GET, compares the live value with the baseline, and gives each difference to the writer. With `--plan`, the writer records the write and the row reads `pending`. With `--confirm`, the writer sends it and the row reads `applied`. The baseline is compared as a subset: a live answer can hold more keys than the baseline, such as the defaults that GitHub adds to a rule, and only a baseline key that differs is a difference.
- **The route table.** `ROUTES` lists each write of the command: its row, method, path form and owner. The writer refuses a write whose route is not in the table. The route-ownership test lists the table and fails when a route writes a setting of another owner: an organization or transfer route of OpenTofu, a status label or a comment of the Service, or a direct write of a template file to the default branch. A second test runs `--confirm` on a new repository and checks that each request of the run matches a route of the table, so the table cannot drift from the code. The dry run prints the table, so it sends no request.
- **States.** `present`, `pending`, `applied`, `waiting`, `skipped`, `not available`, `person`, `refused`, `not readable` and `failed`. The command exits 1 when a row is `pending`, `failed` or `not readable`. The RAG row informs only and does not change the exit code. `waiting` is a template pull request whose checks have not ended: the next run continues there.
- **The baseline.** The template ref is `--template-ref`, else `_commit` of `.copier-answers.yml` of the repository, else the latest release tag of `github.template_repository` (`GET /repos/<template>/releases/latest`). The command runs `copier copy --vcs-ref <ref> --defaults --quiet --data <answer>=<value>... https://github.com/<template>.git <dir>` in a temporary folder. The rendered `github/repository.yaml` must match `templates/github-repository.schema.json` of the template at the same ref (`jsonschema`). The answers are `scopes` (`--scope`), `release_flow` (`--release-flow/--no-release-flow`, else true when the repository can have environments, D2) and `release_type` (`--release-type`). When `.copier-answers.yml` exists, its answers and its `_commit` win, and a flag that differs from the file is a usage error.
- **Row 0.** It reads the scopes of the token from `X-OAuth-Scopes` of `GET /user` and needs `repo` and `workflow`. It probes `GET /repos/<repo>/rulesets`: a 403 on a private repository is the limit of the Free plan (D2). It fails when the baseline or a repository secret names `SERVICE_APP_*` (#6771). With `--confirm`, a failed row 0 stops the run before any write.
- **Row 2.** The body of `repository` of the baseline, and `has_issues: true`, which the roadmap jobs need. A key of `security_and_analysis` that the live answer does not hold is not available on the plan of the repository, and the row leaves it out.
- **Row 3.** `vulnerability_alerts`, `private_vulnerability_reporting`, `immutable_releases`, `code_scanning_default_setup` and `actions_workflow_permissions`, each read and written at the endpoint that the template README names. A 403 or 404 of the default setup on a private Free repository is `not available`.
- **Row 4.** `GET /repos/<repo>/code-quality/setup`: 404 is `not available`, else the row sets `state: configured` when it differs.
- **Rows 5 and 6.** With the release flow only. Row 5 writes the environment, its branch policies and its variables. `RELEASE_APP_CLIENT_ID` comes from `github.release_app_client_id`. Row 6 checks each secret of the environment by name (`GET`), and writes a missing one, or each one with `--rotate-release-key`, with `sync_repository_secrets(..., environment=, value=)`. The value of `RELEASE_APP_PRIVATE_KEY` comes from `--release-key-file` or from the credential `github.release_app_private_key`, and it stays in memory: no output, log record, span, plan or error text holds it. A 403 of the environments API is a person step (D2).
- **Row 7.** For each App whose ID and key the configuration holds (`service.github_app`, `renovate`), the row reads `GET /repos/<repo>/installation` with the JWT of the App. 404 is a person step. The row sends no PUT: every GitHub App of the account is installed on all repositories (owner rule of 2026-11-21), which differs from design row 7.
- **Row 8.** The labels of the package and of `.github/labels.yml`: the file of the default branch when it exists, else the rendered file. The row creates each missing label and keeps a label that differs.
- **Row 9.** The rendered files, the agent files of `devops ai agents --template` (`AGENTS.md` and the pointer stubs), each only when the repository lacks it. A file of the template that the repository holds with other text is kept: after the render the repository owns its files, and Renovate's copier manager brings each new tag. The row writes the missing files to the branch `ci/repository-template` with the Git data API (one tree, one commit, one ref), opens the draft pull request `ci: add the files of the repository template` (AGENTS.md rule 6), and waits for its check runs with `core.clock` until they end or `_CHECKS_WAIT_SECONDS` pass. A failed check fails the row; an open wait is `waiting`.
- **Row 10.** The ruleset `main` of the baseline, with each required check of the live ruleset and each check that reported on the template pull request (D3). `POST` when no ruleset of that name exists, else `PUT` on a difference.
- **Row 11.** After the checks pass: `markPullRequestReadyForReview`, then `enablePullRequestAutoMerge` with `SQUASH` and the head that the checks ran on. When GitHub has nothing to wait for (`mergeStateStatus` `CLEAN`, `HAS_HOOKS` or `UNSTABLE`), the row merges with `mergePullRequest`, as `gh pr merge --auto` does, so the run of the person starts the merge (D3).
- **Row 12.** Until #4417. A hook with `service.webhook_url`, content type `json`, active, with each event of `CONST_ROADMAP_WEBHOOK_EVENTS` or `*` (#6662). A missing hook gets `POST`, a wrong hook or a hook with no secret in `service.webhook_secrets` gets `PATCH` with a new secret of `secrets.token_hex(32)`. The secret goes into the keyring map `service.webhook_secrets` and into no output.
- **Row 13 (D4).** With `--confirm`, the row adds the repository to `service.repos` and, unless `--no-deploy`, runs `devops k8s push-secrets --only devops/devops-cli --rotate` and `devops k8s deploy-stack --stack devops`, but only when the working directory is a clean checkout of `origin/main` of devops-cli (`git fetch origin main`, `git rev-parse HEAD origin/main`, `git status --porcelain`). Otherwise the row is `refused` with the reason and the run goes on. The row deploys only when this run changed `service.repos` or a webhook secret.
- **Row 14.** With `--service`, a person step: the services entry of the repository in the environment repository (dan-petty/infra `docs/service-repos.md`). Its values (the namespaces, the path) belong to the service repository, so the command does not write the entry.
- **Row 15.** The three RAG reads of `devops roadmap onboard` (#3771), and with `--confirm` the ingestion pass of the repository when `service.repos` holds it.
- **Person steps.** Each row that needs a person adds a step with its GitHub document. The output ends with the list.

## Rejected alternatives

- **Copier as a Python library**: rejected, because copier 9.19.1 requires `jinja2-ansible-filters`, which is GPL3 (PyPI metadata), and CONTRIBUTING.md refuses a strong-copyleft dependency.
- **A render from a tarball of the API** (`GET /repos/<template>/tarball/<ref>`): rejected, because Copier then records a local `_src_path` and no `_commit`, and Renovate's copier manager reads both.
- **`GET /user/installations` for row 7**: rejected, because GitHub answers 403 for the token of gh (run of 2026-11-22).
- **A `PUT /user/installations/<id>/repositories/<rid>` on a miss**: rejected by the owner rule of 2026-11-21: every App is installed on all repositories, so no step installs an App on a repository.
- **A homelab pull request for row 14**: rejected, because the services entry holds values of the service that the command cannot know, and only a person merges in the environment repository.
- **Overwrite of a template file that the repository changed**: rejected, because it would undo the changes of the repository at each run; `copier update` through Renovate merges a new tag.
- **The `clear-status` row**: not carried, because #4660 moves the work to the Service.
