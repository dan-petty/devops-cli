# Design

## Decisions

- **Register the row commands from a static tuple of 25 names, and generate a command for each name that the app does not already hold.**: `get_check_specs()` imports the type checker, the tools lock and the sandbox, and the `startup-imports` row measures the import of `devops`; the module therefore reads a `CheckSpec` with `get_check_spec(name)` only when a row runs.
- **The option callback checks the names and returns the value unchanged.**: Click calls a `multiple=True` callback once for each occurrence, so a callback that returned a list would give the group a tuple of lists; the value stays a string and `resolve_selected_specs` parses it as it does today.
- **`resolve_selected_specs` keeps its `typer.Exit(2)` for a wrong name.**: `resolve_step_rows` calls it on a command line that Click never parses, and the pre-push hook and the implement scoped check read that answer; the callback covers the CLI path and the function covers the programmatic path.
- **The generated row command runs `_run_all_checks_async(specs=[spec])` inside `_gate_slot(spec.heavy)`, then prints the failures and the summary and exits 1 on a failure.**: That is the path of a narrowed run of the `ci` group: the same telemetry, the same gate slot and the same request plan, with no second implementation to keep equal.
- **Each generated command declares `@dry_run_class("request-plan")` and the `--dry-run` option.**: `_collect_reachable_commands()` in `tests/invariants/test_dry_run_class_ratchet.py` walks every command of the app and refuses a command with no class or a `request-plan` command with no `--dry-run`.
- **The new row commands join no entry of `CONST_MCP_EXPOSURE_TABLE`.**: The table lists the commands that the MCP server publishes as tools, and the issue asks for a CLI form; a row command would add a tool with no caller and a second surface to keep.
- **No alias keeps `devops ci run`.**: `devops_cli_subcommand_duration_seconds` shows 0 runs of it in the 7 days to 2026-11-13, the `ci` group runs the same rows with a cache and a gate slot, and the project is pre-1.0 and keeps no superseded form.
- **The gate-slot description reads `Time a gate run waited for a free gate slot before its checks started`, and the requirement pins that exact text.**: The old text held the name of the removed command, so a description written as a run of that command could not satisfy the removal rule; the new text names no command at all, so the two rules cannot contradict each other and a test has one exact string to assert.
- **The change of the instrument description comes before the regeneration of the documents, and `docs/TELEMETRY.md` is regenerated and never hand-edited.**: ADR 0025 lists `docs/TELEMETRY.md` among the 7 generated reference pages, so the `docs` row refuses a hand edit and the file follows the description of the instrument.
- **The implement prompt table names only the three rows of `CONST_ROADMAP_IMPLEMENT_SCOPED_ROWS`.**: The implement job runs exactly those three rows in check mode, and a long row can use up the command limit of a step and stop it.
- **The case that asserts the gate-slot description goes to `tests/telemetry/test_telemetry_instruments.py`, the test module of `src/devops_cli/telemetry/instruments.py`, and the tracked-file search case goes to `tests/commands/test_ci_row_commands.py`.**: The implement job cannot edit a test file that the plan leaves out, so group 4 names the test module of the changed file in its `changes` and reads `tests/telemetry/test_consolidation_serialization.py` as well.
- **The search case holds the removed command name and the removal requirement leaves the searching module out of its list of files.**: The case must name the text to search for it, so the requirement covers `README.md`, `docs/`, `src/` and every other test module, and names the one file that holds the text on purpose.

## Rejected alternatives

- **One `devops ci row <name>` command for every row.**: The issue's transcripts count `ci openspec` 7 times and `ci test-tree` 5 times and no `ci row`; a second word is what the callers fail to find, and the group would keep the same lookup problem.
- **`click.Choice` with `multiple=True` for `--only` and `--skip`.**: `.pre-commit-config.yaml` runs `--only lint,format,domain` and `--only actionlint,zizmor`, and `click.Choice` refuses a value that holds a comma, so the pre-push hook would fail.
- **Build the subcommands from `get_check_specs()` while the module imports.**: `get_check_specs()` imports `devops_cli.ci.typecheck`, the tools lock and the sandbox, and the `startup-imports` row measures the import of `devops`, so every command would pay that cost.
- **Keep `typer.Exit(2)` for a wrong row name and print a hint with `write_stderr`.**: The command prints its own error, so no `cli_usage_error` record exists and the ledger cannot count it; `case BadParameter():` in `src/devops_cli/telemetry/usage_errors.py` is what writes one `bad_value` record.
- **Keep `devops ci run` as an alias of the `ci` group.**: `devops_cli_subcommand_duration_seconds` shows 0 runs of it in the 7 days to 2026-11-13, and `docs/adr/0001-github-is-the-roadmap-source.md` records the project policy of removing a superseded command rather than keeping it alongside the new one.
- **Describe the gate-slot histogram as the time a run of the `ci` group waited for a slot.**: The description line reads `src/devops_cli/telemetry/instruments.py:82:before its checks started` after the name of the removed command, and `search_code` for that name answered 10 lines in 8 files, so a description written that way would keep a name that the removal must delete.
