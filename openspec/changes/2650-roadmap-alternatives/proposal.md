# Proposal

## Why

Issue #2650, sub-issue of #2648. An open item names its "Existing Tool Considered" once, when it is written. Nothing checks later whether an open, maintained tool now covers the item. The evidence of such a check is never on the issue. AGENTS.md rule 3 says: use an open tool before you build.

## What Changes

- New command `devops roadmap alternatives [--repo] [--item N] [--limit N] [--dry-run | --plan | --confirm]`, in the shape of `devops roadmap refine`. It is a command a consumer observes, so the change carries a spec delta.
- New module `src/devops_cli/roadmap/alternatives.py`. It selects the items to check, runs one agent run for each item, validates the reply, and writes the result. The agent run uses `investigate` of `src/devops_cli/roadmap/refine_investigation.py`, which now takes any set of tools, and the Firecrawl search of that module, which both jobs share.
- The agent has three tools: `search_web` (Firecrawl, at most 3 searches of 5 results), `github_repository(owner/name)` and `pypi_package(name)`. At most 6 fact reads are allowed for each item. The two fact tools read license, last activity and release facts. The tools are the only sources. A reply that cites a URL that no tool returned is refused.
- The job sets `maintained` from the facts: a tool is maintained when its repository is not archived and its last push is within 12 months, or, for a PyPI package with no repository read, its latest upload is within 12 months. The model does not write `maintained`, the license, the date or the searches run.
- With `--confirm`, a check posts one comment with the marker `devops roadmap alternatives`, replaces the block `devops-roadmap-alternatives:start` to `:end` in the body, and records the job record keys `alternatives.checked_at`, `alternatives.body_hash`, `alternatives.verdict` and `alternatives.tool`. It changes no label and closes no issue.
- The store gains `repository_facts(owner/name)`, one REST read of a repository and one of its latest release, in the GitHub adapter and in the in-memory adapter.
- New setting `roadmap.alternatives.recheck_days` (default 30).
- New prompt `src/devops_cli/ai/tasks/roadmap_alternatives.md`, new constants, messages and help text, the term "Alternative" in `CONTEXT.md`, and the README, regenerated.
- The change fits one pull request. The Service row and the use of the verdict by refine are sub-issue 2 of #2648 and are not part of this change.

## Feasibility

Each part of the premise was checked against the real system on 2026-10-29.

- GitHub REST: `devops gh api repos/pydantic/pydantic-ai` returned `html_url`, `archived` (false), `pushed_at`, `stargazers_count` and `license.spdx_id` (`MIT`). `repos/pydantic/pydantic-ai/releases/latest` returned `tag_name` and `published_at`. `repos/example-nobody/none/releases/latest` returned HTTP 404, so a repository with no release is a 404 that the adapter reads as "no release".
- PyPI JSON: `https://pypi.org/pypi/pydantic-ai/json` returned `info.version`, `info.license_expression` (`MIT`; `info.license` was null), `info.package_url`, and `urls[].upload_time_iso_8601`. A package that does not exist returned HTTP 404.
- Firecrawl search: `firecrawl_search` (#2398) is in `src/devops_cli/ai/common_tools.py`. It counts each search in `devops_cli_firecrawl_searches_total`.
- Agent construction: `investigate` in `src/devops_cli/roadmap/refine_investigation.py` uses only `tools.tools()` of its `tools` argument, so any object that gives a list of pydantic-ai `Tool`s can be passed. It already sets `UsageLimits`, streams, maps errors to refine's classes, and writes one spend record under the stage `analysis`.
- The store: `RoadmapStore.set_marks`, `write_issue_body`, `comment` and `comments_on` give every write the job needs. The job record keys are the known keys of `decode_job_record`, so a new key enum must join `_JOB_RECORD_KEYS`.

The premise holds. No part needs code that compensates for a missing feature.

## Existing Tool Considered

- Firecrawl `/v2/search` through `firecrawl_search` is the search API the owner chose. The job adds no second search provider.
- pydantic-ai `Agent` with `Tool`s, `UsageLimits` and `PrepareTools` is the agent. The job uses `investigate`, which refine already uses.
- The GitHub REST API (through `gh`, as the store reads everything) and the PyPI JSON API give the maintenance facts. No new library is needed. The PyPI read uses `new_http_client` and `httpx2`, as `devops survey` does.
- pydantic-ai's `WebSearch` capability is rejected. It needs a provider's native search or DuckDuckGo, and the gateway's local models have no native search. The owner chose Firecrawl.
- Built, because no tool covers it: the selection, the prompt, the validation and the writes of the job. Estimated cost: about 900 lines of code and tests, around 250k tokens of agent work, one day of elapsed time, and upkeep when Firecrawl's reply shape changes.
