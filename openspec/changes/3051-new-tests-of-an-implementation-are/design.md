# Design

## Decisions

- **Reuse the `test-function-has-assertion` ast-grep rule for the assertion scan of the new test files.**: The rule already holds the definition of an assertion: an assert statement, a call of `raises` or `warns` and `self.assert*`. A second parser would define an assertion twice.
- **Run mutmut through `select_targets` and `tally` of `src/devops_cli/ci/mutate.py`, and build no mutation engine.**: Those functions map the changed functions to mutmut's names and read each survivor with its file, its line and its name, which is what the report needs.
- **Bound the mutation run at `roadmap.implement.command_timeout_seconds` and at `CONST_ROADMAP_IMPLEMENT_SCOPED_TEST_MODULES` changed source files.**: The setting bounds every command of a step, and 30 is the project's existing cap for a scoped check.
- **Treat a mutation run that reaches a bound as no failure, and name the bound in the report.**: The first mutmut run of a fresh checkout runs the whole suite serially, so a bound is the normal end of the run; a failure would stop every item.
- **Run the scoped test modules again with coverage in the strength check, instead of reading coverage data from the tests check.**: `devops ci test` builds `uv run pytest` with no coverage option, so it writes no data; the strength check passes `--cov=src --cov-report= --cov-fail-under=0`, the options of a shard, and then runs `coverage xml` and diff-cover.
- **Run diff-cover with `--fail-under 100` and keep its markdown report in the comment.**: A changed line that no scoped test covers must fail the check, and the report already names the file and the missing line numbers.
- **Run the strength check after the scoped checks, in `_scoped_run`, and keep its report in the run's comment.**: The strength check reads the changed paths and the test modules that `_scoped_run` already computes, and `_comment` already renders the scoped runs of the item.
- **Leave the changed files of a task group of kind `other` out of the check, and name the group as the reason.**: An `other` group writes no test, so a mutation finding or an uncovered line on its files has no work that a repair step can do.
- **Turn a failed strength report into a `ScopedResult` named `strength`, whose log is the report.**: The existing repair loop already takes a failed scoped result and gives its log to a repair step, bounded by `roadmap.implement.repair_rounds`.
- **Add the strength report to the capability as a new requirement `The comment shows the strength report` instead of lengthening the existing comment requirement.**: A requirement text holds at most 500 characters, and the existing requirement already states the table and the line of each scoped check.
- **Add no dependency to `pyproject.toml`: mutmut, diff-cover and pytest-cov are dev dependencies already, and the runner image installs them.**: `pyproject.toml:120:"mutmut==3.8.1",` and `pyproject.toml:110:"diff-cover==11.0.1",` are pinned there, so the strength check runs the pinned tools and the image gains no package.
- **Pass the changed test module paths as arguments of a fixed argv, and never through a shell.**: The plan text and the changed paths come from the agent, and a shell would run what a path holds; one argument per path keeps the check to the commands it names.
- **Name the registry test of the constant in group 2 and change no row of it.**: The bound is the existing `CONST_ROADMAP_IMPLEMENT_SCOPED_TEST_MODULES`, which `tests/roadmap/test_roadmap_limit_classes.py` registers under the `CONST_ROADMAP_` prefix, so no new item joins the registry.
- **Name a file that the commit holds in the task text of every group.**: The earlier reply named only files that the change creates, so the step of group 3 packed no file; each group now names a file of the commit that it reads or changes.

## Rejected alternatives

- **Read the coverage data that the scoped tests check writes.**: `src/devops_cli/commands/ci.py:1919:cmd = ["uv", "run", "pytest"]` in `_build_test_cmd` adds no coverage option, and `pyproject.toml:228:addopts = "-n logical --dist worksteal -p no:logfire -p no:pytest_logfire -p no:randomly --hypothesis-profile=ci"` holds no `--cov`, so the scoped tests check writes no data for `coverage xml` to read.
- **Add a `--cov` option to `devops ci test` so the tests check writes the data.**: It changes a `devops` command, and the base requirement `The job runs the scoped checks before it pushes` names `devops ci test`, so the change would reach a second capability and the file that two open pull requests change.
- **Build a mutation runner in the repository.**: `pyproject.toml:120:"mutmut==3.8.1",` is a dev dependency, and `devops ci mutate` already maps the changed functions and reads each survivor with its file, its line and its name.
- **Parse each new test file with `ast` for an assertion.**: The rule at `.ast-grep/rules/test-function-has-assertion.yml:6:message: Test function has no assert, no pytest.raises, and no assertion or double check.` already holds the definition of an assertion, and the `constructs` row runs it over `tests/**`.
- **Run mutmut without a time bound, on its own four-hour default.**: `devops ci mutate` bounds mutmut at its own default of four hours, which is above the time limit of the step, and the issue asks for a time bound.
- **Run the strength check inside each group's exit checks.**: The test modules of the change do not exist before the last group, and a group of kind `other` has no test.
- **Put the strength report in a check run of the pull request.**: The job writes its record in the comment of the pull request, at `src/devops_cli/roadmap/implement/implement_run.py:def _comment`, and the issue asks for the report there.
- **Skip the strength check only when every changed file belongs to a group of kind `other`.**: The issue asks the skip for the changed files of such a group, so the files of a behavior group in the same change still need the check.
- **Diff two coverage reports in the job instead of running diff-cover.**: diff-cover 11.0.1 is a dev dependency and `.github/workflows/ci.yml:292:uv run diff-cover .data/coverage.xml --compare-branch=` already maps the changed lines of a coverage XML report.
- **Lengthen the existing comment requirement with the strength report.**: The text of that requirement reached 567 characters with the strength report, above the limit of 500 that a requirement text holds.

## Security

The strength check runs code that the agent wrote, the test modules of the item, inside the runner pod and outside the agent shell, with no GitHub token, and with the pod settings `readOnlyRootFilesystem: true`, `runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `capabilities.drop: ALL` and `seccompProfile: RuntimeDefault`; it writes only `.data/` and `mutants/` in the worktree. The changed paths come from git and the group kind from the plan text, which the agent writes, and the check passes them as elements of a fixed argv, never through a shell. The change adds no dependency to `pyproject.toml`, so the runner image gains no package. A person must confirm that mutmut, diff-cover and pytest-cov stay at their pins, and that the mutation run and the coverage run reach no network and no cluster. The test `test_each_test_module_path_is_one_argument_of_the_coverage_run` in `tests/roadmap/implement/test_roadmap_implement_strength.py` fails if a changed path reaches a shell instead of one element of the argv.
