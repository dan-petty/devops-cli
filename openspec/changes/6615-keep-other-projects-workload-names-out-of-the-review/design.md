# Design

## Decisions

1. **A namespace matcher in the query, from a setting.** Each of the seven facts gets the matcher `namespace=~"{namespaces}"` in each selector whose metric has a `namespace` label, and keeps `namespace` and `pod` in its `by` and `on` clauses. Prometheus then gives no series of another project, so the dispatcher never reads a foreign name, and each fact keeps one row for each workload of the project. The selectors of node metrics (`kube_node_status_allocatable`, `kube_node_status_condition`) have no `namespace` label and do not change.
   - `prometheus.requests_over_allocatable` gets the matcher on `kube_pod_container_resource_requests` and `kube_pod_status_phase`. Its value becomes the requests of the running pods of the project namespaces over the allocatable resources of the Ready nodes. The project review measures the project, so the share of the project is the value that it reports. Its definition says so.
   - `prometheus.restarting_containers` says "of the project namespaces" in place of "of all namespaces". The other definitions name the project namespaces.
2. **The setting `roadmap.project_review.namespaces`.** One list of names serves all facts, and the config of each checkout can give its own list. The model is `RoadmapProjectReviewConfig` in `src/devops_cli/config/settings.py`, as the field `project_review` of `RoadmapConfig`. `roadmap.review` is the setting of the step review (#5969), so the project review gets its own name.
   - The default is `DEFAULT_ROADMAP_PROJECT_REVIEW_NAMESPACES` in `src/devops_cli/config/defaults.py`: the 14 namespaces of `k8s/namespaces.yaml` (`git grep -l "kind: Namespace" k8s/`). The `namespace:` of the kustomizations (`cloudflared`, `monitoring`) are already in that file. The comment above the constant names this source. These names are already public in `k8s/` of this repository, so AGENTS.md rule 10 holds.
   - An empty list is a config error, not "all namespaces": the field has `min_length=1`. Each name must match `CONST_K8S_LABEL_RE` (RFC 1123 label), so a name holds only `a-z`, `0-9` and `-`. Such a name cannot change the regular expression of the matcher or end its PromQL string.
3. **The placeholder `{namespaces}`.** `PLACEHOLDERS` of `catalog.py` and the placeholder pattern of `catalog.schema.json` get `namespaces`. `window_placeholders(window, repo, namespaces)` gives the names joined with `|`. `read_catalog` in `dispatch.py` passes `context.settings.roadmap.project_review.namespaces`. `_plan_values` in `review.py` fills the same value from `load_settings()`, so `--dry-run` prints the filled queries. A settings load reads files only, so the dry run still sends 0 requests and starts no program.
4. **The loader rule `unscoped_workload_metric`.** It sits beside `unscoped_service_metric` in `catalog.py`, and `_cross_checked` calls it for each fact of the shape `rows`. It returns the first label `namespace` or `pod` that a `by (…)` or `on (…)` clause of the query names when the query holds no positive namespace matcher (`namespace="…"` or `namespace=~"…"`), else None. The refusal message `review_catalog_unscoped_workload` names the fact, the field `query` and the label. The rule reads the query text, as `unscoped_service_metric` and the schema rule for `by (node)` do.
   - A negative matcher (`namespace!="…"`, `namespace!~"…"`) does not scope a query: it still reads every other namespace, so the rule refuses it.
   - A `scalar` fact is one number with no label, so it names no workload, and the rule does not apply to it.
   - The rule accepts a fixed positive matcher. `loki.error_lines_top` holds `namespace=~"devops|llm"`, two project namespaces, and does not change.
5. **The header rule of `catalog.yaml`.** It adds `{namespaces}` to the list of placeholders, and adds: a query gives no name of a workload outside the project namespaces, so a `rows` fact that groups or joins by `namespace` or `pod` holds the matcher `namespace=~"{namespaces}"`.
6. **The `base` metrics and the probe do not change.** The probe is `group(last_over_time(<base>[<range>]))` with no `by` clause, so its answer has no label and names no workload. It tells only that the metric has a series in the window. #6612 changes the base metrics, the probe, the runner pair, the path condition, `prometheus.oldest_pending_update` and `prometheus.stage_sli`, and this change does not touch them.
7. **The proof is offline.** The spec scenarios use fixture catalogs, the shipped catalog loaded by the loader, the settings model and the fakes of the dry run. The 7-day read-only review after the release is the live check, in the pull request body. No test reads live data.

## Rejected alternatives

- **Remove `namespace` and `pod` from the `by` clauses.** It hides the names, but each fact still counts the workloads of other projects, so the values stay wrong for the project. The refine design of #6615 rejected it for this reason.
- **Filter the rows after the read.** The dispatcher has already read the foreign names, and a fact with a threshold (`> 0.8`) has already compared foreign series. The leak and the wrong count stay.
- **Hard-code the namespaces in each fact.** Seven copies of one value, and a review of another repository gives the namespaces of devops-cli with no way to change them.
- **Read the namespaces from the manifests at review time.** The review then needs a checkout with `k8s/` and a manifest parser, and a repository with no manifests gives no value. The setting with a default from the manifests gives the same names with no read.
- **An empty list means all namespaces.** A setting that is empty by mistake would publish the names of other projects again. The load refuses it.
- **Require the placeholder `{namespaces}` itself.** `loki.error_lines_top` holds a fixed matcher of two project namespaces, and the change does not touch other facts. A positive matcher is enough for the rule; the review of the catalog checks the value of a fixed matcher.
- **A PromQL syntax tree (promql-parser 0.12.0).** Its package metadata states no license, and it cannot parse the LogQL query of `loki.error_lines_top`. The regular expression over the query text is the technique of the two existing rules of the loader and the schema.
- **cloudflare/pint.** It lints the `expr` of Prometheus rule files and is a Go program. It does not read the catalog form, and a run of pint at each catalog load adds a second runtime for one check.
