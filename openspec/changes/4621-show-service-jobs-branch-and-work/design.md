# Design

## Decisions

- **Hold the branch and the lane clone path in the two Job annotations, which the callers pass through the existing annotations mapping of the builder, and add no parameter to it.**: `src/devops_cli/k8s/cluster_job.py:def build_job` takes `annotations` and copies the mapping onto the Job and onto its pod template, so both values reach both objects with no new code path.
- **Take the branch from the target of the Job and the clone path from the round that submits it, which both rows already hold.**: `src/devops_cli/roadmap/stage/stage_submit.py:345:source: Path | str,` and `src/devops_cli/roadmap/implement/implement_submit.py:694:source: Path | str,` are the clones of the two rounds, and the branch is the property `branch` of the stage target and the field `branch` of the implement target.
- **Leave the kube-state-metrics values, the spec of the Roadmap Service and its generated dashboard to dan-petty/homelab.**: `tests/gate/k8s_checks/environment_freeze.py:26:_PRODUCT_FOLDERS: Final[tuple[PurePosixPath, ...]] = (` names `k8s/devops` and `k8s/overlays/homelab/devops` as the only folders of `k8s` in which a branch of this repository can change a file that is no Markdown file, and steps 11 and 12 of `docs/HOMELAB_REPO_SWITCH.md` say that Argo CD reads the environment from homelab. So dan-petty/homelab#263 sets the allowlists of the jobs resource, sets `jobs = true` and regenerates the JSON, and this change holds the Service code and the template.
- **Read the kube_job series that the chart keeps today, and add no keep entry.**: The file `charts/feature-cluster-metrics/default-allow-lists/kube-state-metrics.yaml` of the chart `k8s-monitoring` 4.6.1 holds `- kube_job.*`, and `k8s/devops/monitoring/slos/runner-jobs-duration.yaml` reads `kube_job_status_start_time` and `kube_job_status_completion_time` from Prometheus today. The Job series end with the Job, so the Service adds no exporter, no credential and no cardinality.
- **Put the Job panels in the SRE template behind a `jobs` field of the spec that defaults to false.**: The template builds both tables of `k8s/monitoring/dashboards/services.toml`, and the generic table selects one namespace and one workload, which has no Job of the Roadmap Service. With the default, the build of each committed spec stays the same, and homelab sets the field for the Roadmap Service only.
- **Give the two panels titles in the form `Signal: measure`, and put the words of the issue in the descriptions.**: `tests/grafana/test_service_dashboard.py:90:if ": " not in title or not _sentence_case(title):` reports a title with no `: ` or with a capital after the first word. The titles are `Service jobs: branch, worktree and state` and `Work log: lines of the selected job`, and the descriptions name the Service jobs table and the Work log panel.
- **Give each of the nine columns of the table one source.**: The table reads the Prometheus data source with instant queries on the namespace of `src/devops_cli/k8s/cluster_job.py:38:JOB_NAMESPACE = "devops"`, joined on `job_name`. job is `job_name`. row, repo and item are `label_app_kubernetes_io_component`, `label_roadmap_devops_cli_repo` and `label_roadmap_devops_cli_item` of `kube_job_labels`. branch and worktree are `annotation_roadmap_devops_cli_branch` and `annotation_roadmap_devops_cli_worktree` of `kube_job_annotations`. state is a number with a value mapping to a word: running when `kube_job_status_active` is above 0, else succeeded when `kube_job_status_succeeded` is above 0, else failed when `kube_job_status_failed` is above 0, else waiting. start time is `kube_job_status_start_time`. duration is `kube_job_status_completion_time` minus the start time, or `time()` minus the start time while `kube_job_status_active` is above 0. The Kubernetes API sets the completion time of a Job only when the Job succeeds, so a failed Job shows no duration. The links take the owner from `label_roadmap_devops_cli_owner`.
- **Set the job variable from a link of the job column.**: A Grafana table has no row selection that a second panel reads. A data link of the job column opens the same dashboard with `var-job=${__value.raw}` and `${__url_time_range}`, so one click on a row filters the Work log panel on that Job. `Template.safe_substitute` in `src/devops_cli/grafana/service_dashboard.py:def _fill_in` changes only `$namespace` and `$workload`, so the link and the variables `$repo`, `$item` and `$job` stay as they are in a spec without `variables`.
- **Filter the Work log panel on the `devops` namespace and the pod name after the stream selector.**: `src/devops_cli/k8s/cluster_job.py:38:JOB_NAMESPACE = "devops"` is the namespace of every Service Job, and `src/devops_cli/grafana/service_dashboard.py:def _logs` puts the pod in a label filter after the stream selector, because a pod log carries the pod name as structured metadata.
- **Check the keys of the Job panels in the dashboard test of the template, against the keys that the Service sets.**: `tests/grafana/test_service_dashboard.py:def _panel_problems` and its case `tests/grafana/test_service_dashboard.py:def test_the_panel_rules_report_a_title_case_title_a_missing_description_and_two_units` are the shape: a rule that gives one line for each fault, and a case with a panel that breaks it. The new rule reads each query with `src/devops_cli/prometheus/promql.py:def selectors` and `src/devops_cli/prometheus/promql.py:def grouping_labels`, and takes the keys from the constants of `src/devops_cli/k8s/cluster_job.py`. It accepts each family whose name starts with `kube_job`, because the chart keeps `kube_job.*`.
- **Read the label sets of the Service from the metrics registry, in a case that starts the Service manager, and not from the mapping of series names.**: `tests/telemetry/test_service_counter_series.py:def _series` reads the label set of each sample from `GLOBAL_METRICS.registry.collect()`, while `SERVICE_SERIES` at `tests/telemetry/test_telemetry_instruments.py:87:SERVICE_SERIES: dict[str, InstrumentKind] = {` holds a series name and a kind, of the class `src/devops_cli/telemetry/instruments.py:31:class InstrumentKind(StrEnum):`, and no label set.
- **Keep the item, branch and worktree values off the Service metric labels and off the Loki stream labels.**: They are unbounded values; they stay on the kube-state-metrics series of a live Job, which end with the Job, and in the pod log lines of Loki, and the 23 series of `SERVICE_SERIES` keep their label sets.
- **Defer the run history link to #7272, which waits for #4589 and #4586.**: The Service serves no run record and no `/runs/{run_id}` route today, so the table would link to a page that no code serves.
- **Defer the branch and worktree annotations of Argo Workflows to #7273.**: No roadmap job runs on Argo Workflows, so no Workflow carries them; the roadmap rows run as cluster Jobs.
- **Leave out the 4 gate panels and the 3 alerts of the comment of 2026-11-11 on #4621.**: They read the gate runs, the queue time, the fallbacks and the disagreements with GitHub of the gate run in the cluster that #4698 adds. `git grep -c -e "--remote" origin/main -- docs/commands/ci.md` printed no line, so the gate command has no option that starts such a run, and no series of it exists.

## Rejected alternatives

- **Change the copies of `k8s/monitoring` in this repository.**: `tests/gate/k8s_checks/environment_freeze.py:def is_environment_path` is true for `k8s/monitoring/k8s-monitoring-values.yaml`, `k8s/monitoring/dashboards/services.toml` and `k8s/monitoring/dashboards/devops-roadmap-service.json`, so the required `k8s` row fails for the branch, and Argo CD does not read those copies since step 11 of `docs/HOMELAB_REPO_SWITCH.md`.
- **Add the kube_job families to `includeMetrics`.**: The default allow list of the chart `k8s-monitoring` 4.6.1 holds `- kube_job.*`, the chart joins it with `includeMetrics`, and `k8s/monitoring/k8s-monitoring-values.yaml:112:useDefaultAllowList: false` turns the default off for the host metrics only. The 5 entries would repeat what the chart keeps.
- **Check the Job keys in the `k8s` row, against the monitoring values and the committed dashboard.**: Both files are environment paths of `tests/gate/k8s_checks/environment_freeze.py:def is_environment_path`, and step 17 of `docs/HOMELAB_REPO_SWITCH.md` deletes them from this repository, so the check would read copies that deploy nothing.
- **Name the panels Service jobs and Work log.**: `tests/grafana/test_service_dashboard.py:90:if ": " not in title or not _sentence_case(title):` reports each of the two titles, so `tests/grafana/test_service_dashboard.py:def _panel_problems` fails the dashboard of a spec that sets `jobs`.
- **A custom Prometheus exporter for the Job metadata.**: kube-state-metrics already serves the Job labels and annotations through its allowlists, and the chart's values run it since the first install (`k8s/monitoring/k8s-monitoring-values.yaml:275:metricLabelsAllowlist:`); an exporter would add code and a credential for data that the cluster already exports.
- **Let Grafana read the Kubernetes API for the Jobs.**: The panels read Prometheus and Loki only, as the Loki stream selector of `src/devops_cli/grafana/service_dashboard.py:def _logs` shows, and Grafana holds no cluster credential.
- **Put the item, branch or worktree on a Service metric or a Loki stream label.**: The Service sends the 23 series of `SERVICE_SERIES` at `tests/telemetry/test_telemetry_instruments.py:87:SERVICE_SERIES: dict[str, InstrumentKind] = {`, and an item label would multiply each of them by the number of items.
- **Select the Job's log lines with a stream selector on the pod name.**: `pod` is structured metadata, not a stream label, so a stream selector on it returns no line; `src/devops_cli/grafana/service_dashboard.py:def _logs` already filters it after the stream selector.
- **Give the Job panels to the generic service dashboard.**: The generic table of `k8s/monitoring/dashboards/services.toml` selects one namespace and one workload, so its Job panels would show the Jobs of the Roadmap Service under any other service.
- **Check the label sets of the Service instruments by walking the mapping of series names.**: `tests/telemetry/test_telemetry_instruments.py:87:SERVICE_SERIES: dict[str, InstrumentKind] = {` holds a name and a kind for each series and no label set, so such a case passes whatever the code does.

## Security

The Job annotations carry the repository owner and name, the item number, the branch and the lane clone path out of the cluster into the Prometheus series and the dashboard that the Grafana ingress serves. A person must confirm that the two annotation values hold no token, no internal host name and no private address: they are the branch name of the item and the clone path of the lane. The allowlists of dan-petty/homelab#263 name the jobs resource, the four labels and the two annotations only, so no other object gains a label series and no other annotation of a Job leaves the Kubernetes API. The dashboard rule fails if a Job panel reads a label or an annotation that the Service does not set, and the registry case fails if a Service series gains an item, branch or worktree label.
