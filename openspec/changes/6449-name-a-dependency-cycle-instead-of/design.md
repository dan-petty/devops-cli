# Design

## Decisions

- **Use `graphlib.TopologicalSorter` of the standard library for the cycle check.**: The sorter is in the standard library, and the repository already imports it at `src/devops_cli/core/import_graph.py:18:from graphlib import CycleError, TopologicalSorter`, so the change adds no dependency.
- **Put `DependencyGraph`, `cycle_text` and `_path_back` in `src/devops_cli/roadmap/refine/refine.py` beside `body_dependencies`.**: The parse of the Dependencies section that the graph reads lives in that module, and the shared read already imports it at `src/devops_cli/roadmap/dependencies.py:13:from devops_cli.roadmap.refine.refine import body_dependencies, title_dependencies`, so a graph in the shared read module would import the refine module back.
- **Take the edges of an item from its job record, its Dependencies section and its quoted titles, and keep only an open item as a node.**: The record at `src/devops_cli/roadmap/refine/refine.py:2194:recorded = item.job_record.get(RefineRecordKey.BLOCKED_BY) or ""` and the body are the declared dependencies of the item, so a cycle that only the record declares is found, as the group of #4692 shows, and a closed issue holds nothing back.
- **Build one graph for each round in `plan_refine` from the open items that the round already reads for the owner-question frames, and give it to the selection and to each refine.**: `src/devops_cli/roadmap/refine/refine.py:3587:frames = recorded_frames(store)` reads every open item at `src/devops_cli/roadmap/refine/refine.py:1559:for item in sorted(store.open_items(), key=lambda open_item: open_item.number):` before the selection, so the graph of that listing sends no request; the whole item listing is read only inside `refine_one_item` at `src/devops_cli/roadmap/refine/refine.py:3251:unmatched = title_dependencies(current_body, store.items()).unmatched`, after the selection.
- **Read the open items once in `plan_refine` and give the same sequence to `frames_of` and to `DependencyGraph.of`, which replaces the call of `recorded_frames(store)` there.**: Two calls of `store.open_items()` in one round would read the listing twice, and the frames and the graph need the same items.
- **Give `_select_round`, `_Selection`, `_still_waiting` and `refine_one_item` a `graph` keyword that defaults to None, and build the graph from `store.open_items()` only when the caller gives none.**: `src/devops_cli/roadmap/refine/refine.py:2809:selection = _Selection(store)` in `refine_left_out` gives no graph, and `devops roadmap explain` must give the answer that the round gives, so the wait helper reads the open items for itself only for an item whose record holds a blocked wait.
- **Gate the graph with one `TopologicalSorter(...).prepare()` and walk the edges back from each item that a dependency leads back to.**: Each item of a shared cycle gets its own path, so an edge that two cycles share hides no item, as the group of #4692 shows.
- **Drop an edge to an issue that the item sequence does not hold.**: The graph is a function of the sequence it is given, so no read of an issue adds a node, and the round reads no listing of its own; the test asserts the drop.
- **Put the cycle branch of `next_step_of` first, before the alternatives and ready branches.**: `src/devops_cli/roadmap/refine/refine.py:1520:if is_ready:` and `src/devops_cli/roadmap/refine/refine.py:1527:return NextStep.BLOCKED, tuple(f"#{dep}" for dep in blockers), blockers` would otherwise answer first for an item whose proposal is complete or whose open issue closes the cycle.
- **Give `check_ready` the required keyword `cycle` and make it false when the item is in a cycle.**: The round carries `is_ready` into the item record at `src/devops_cli/roadmap/refine/refine.py:3372:is_ready=is_ready,` and writes the Status from it, so a complete proposal in a cycle would be set Ready while its step is `person`, and the stage job would take an item that the cycle holds back.
- **End the recorded wait of an item whose record holds the step `blocked` when the graph holds that item in a cycle.**: The blocked branch at `src/devops_cli/roadmap/refine/refine.py:2586:case NextStep.BLOCKED:` keeps the wait while its blocker is open, so without this rule the items of the six live cycles would never be refined again and would keep their step.
- **Record the step `person`, with the cycle in the step detail and under the Suspected block heading of refine's section, through the `cycle` keyword of `render_proposal_section`.**: A cycle waits on no outside event, so `blocked` is wrong and a person must remove one edge, and the section at `src/devops_cli/roadmap/refine/refine.py:3316:rendered_section = render_proposal_section(` is where a person reads the cause of a wait.
- **Give the shared reason, the step detail and the section one message, `dependency_cycle`.**: One text states the rule, so a person reads the same sentence in the stage reason, the implement reason and the refine section.
- **Keep the open-issue reason first in `open_dependency` and build the graph only when the body or a quoted title names an open issue.**: `src/devops_cli/roadmap/dependencies.py:27:return MESSAGES.roadmap.stage_left_dependency.format(issues=", ".join(open_issues))` comes from the body and the quoted titles alone, so an item whose body names no open issue must get no reason at all; a cycle reason there would hold back an item that the stage and implement jobs have no reason to leave out.
- **Keep every existing call site of `open_dependency`, `next_step_of`, `render_proposal_section` and `refine_left_out` as it stands, and update only the matrix of `tests/roadmap/refine/test_roadmap_refine_proposal.py` with the new keyword of `check_ready`.**: The new keywords carry a default, so an item that is in no cycle gets the answer it gets today, and the recorded diffs of the golden set replay as they stand; only `check_ready` requires the keyword, and its one production caller is in the group that changes it.
- **State the shared graph and the shared reason in a new capability, and the person step, the Status rule and the wait rule in `roadmap-refine/waits`.**: The shared read serves the stage and implement jobs as well as refine, so its requirements do not belong to the refine capability, and the refine rules change the requirement that already holds the open-dependency rule.

## Rejected alternatives

- **networkx for the cycle check**: It adds a dependency for a check that the standard library gives, and the repository already imports the sorter at `src/devops_cli/core/import_graph.py:18:from graphlib import CycleError, TopologicalSorter`.
- **A hand-written topological sort**: It keeps a sort and a cycle check in the project that the standard library gives and tests.
- **A new module `src/devops_cli/roadmap/cycle.py`**: A second module for three functions, and the parse that the graph reads already lives in the refine module, which the shared read already imports at `src/devops_cli/roadmap/dependencies.py:13:from devops_cli.roadmap.refine.refine import body_dependencies, title_dependencies`.
- **The cycle check in the refine job only, with no change to the shared read**: The stage job and the implement job keep the old reason and name no cycle, which the second acceptance criterion of the issue refuses.
- **One `prepare()` and the first `CycleError` path**: It names one cycle for each round, so the items of the other cycles keep waiting.
- **Repeat `prepare()` with the closing edge removed**: An edge removed for one cycle breaks another cycle that shares it, so its items stay unnamed.
- **Build the graph from `store.items()` at the start of each round**: The round's whole item listing is read inside `refine_one_item` at `src/devops_cli/roadmap/refine/refine.py:3251:unmatched = title_dependencies(current_body, store.items()).unmatched`, after the selection, and the selection reads the milestone items and the backlog at `src/devops_cli/roadmap/refine/refine.py:2881:backlog_items = store.backlog()`, so a round with no candidate would send a listing that it never sends today.
- **Build the graph inside each call of `open_dependency` from a second listing read**: The stage and implement jobs already hold their listing in `self._items` at `src/devops_cli/roadmap/stage/stage.py:774:return open_dependency(item, self._store, self._items)`, and the round holds the open items at `src/devops_cli/roadmap/refine/refine.py:3587:frames = recorded_frames(store)`, so a second read would send a request that the caller does not need.
- **A required `graph` argument on the wait helper and on the selection**: `src/devops_cli/roadmap/refine/refine.py:2809:selection = _Selection(store)` in `refine_left_out` gives no graph, so a required argument breaks `devops roadmap explain`.
- **Let `refine_left_out` keep the blocked wait and give it no graph**: The docstring of `refine_left_out` says that `devops roadmap explain` and a round cannot differ (#3483), so explain must end the wait that the round ends.
- **Return `person` from `next_step_of` for a cycle and leave readiness as it stands**: The round carries `is_ready` into the item record at `src/devops_cli/roadmap/refine/refine.py:3372:is_ready=is_ready,`, so a complete proposal in a cycle would be set Ready while its step is `person`.
- **Place the cycle branch after the split and blocker branches**: `src/devops_cli/roadmap/refine/refine.py:1527:return NextStep.BLOCKED, tuple(f"#{dep}" for dep in blockers), blockers` answers `blocked` before any later branch, so a cycle whose open issue is a blocker would never reach the cycle branch.
- **Leave the wait of a blocked item as it stands and rely on newly refined items only**: The blocked branch at `src/devops_cli/roadmap/refine/refine.py:2586:case NextStep.BLOCKED:` keeps the wait of an item while its blocker is open, so the items of the live cycles would keep their step and no person step would name the cycle.
- **Replace the record edges of the refined item with the open dependencies of its proposal**: A cycle that only the record of the item declares then gives no path, and the item records `blocked` as before.
- **A test that counts the store calls of `DependencyGraph.of`**: The graph takes the item sequence and never the store, so such a count passes whatever the graph does; the test asserts a rule of the graph instead, the drop of an edge to an issue that the sequence does not hold.
- **A new step value for a cycle**: A new value in the step vocabulary for one case, and the `person` step already carries the detail that a person reads.
- **Keep the cycle in the step detail only, and claim that closing an issue of the cycle ends the wait**: The wait text of a person step is the detail, and a detail alone names no cycle in the section that a person reads at `src/devops_cli/roadmap/refine/refine.py:3316:rendered_section = render_proposal_section(`.

## Unchanged references

- `src/devops_cli/roadmap/stage/stage.py` (import): The stage job keeps its one call to `open_dependency` at line 774, which names the cycle from the listing that `_items` already holds.
- `src/devops_cli/roadmap/implement/implement.py` (import): The implement job keeps its one call to `open_dependency` at line 382, which names the cycle from the listing that `_items` already holds.
