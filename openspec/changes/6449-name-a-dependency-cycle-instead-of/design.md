# Design

## Decisions

- **Use `graphlib.TopologicalSorter` of the standard library for the cycle check.**: The sorter is in the standard library, and the repository already imports `CycleError` and `TopologicalSorter` for the import graph at `src/devops_cli/core/import_graph.py:18:from graphlib import CycleError, TopologicalSorter`, so the change adds no dependency.
- **Put `DependencyGraph`, `cycle_text` and `_path_back` in `src/devops_cli/roadmap/refine/refine.py` beside `body_dependencies`.**: The parse of the Dependencies section that the graph reads lives in that module, and the shared read module imports it, so a graph in the shared read module would import the refine module back.
- **Take the edges of an item from its job record, its Dependencies section and its quoted titles, and keep only open items.**: The record and the body are the declared dependencies of the item, so a cycle that only the record declares is found, as the group of #4692 shows, and a closed issue holds nothing back.
- **Build one graph for each refine round in `_select_round` from the milestone items and backlog items that the round already read.**: `_select_round` already reads every open item of the round at `src/devops_cli/roadmap/refine/refine.py:2880:milestone_items = [store.items(milestone=m.number) for m in open_milestones]` and `src/devops_cli/roadmap/refine/refine.py:2881:backlog_items = store.backlog()`, so one build costs no store or GitHub request.
- **Give `_still_waiting` the keyword `graph`, which defaults to None, and build the graph from `store.items()` in its `BLOCKED` branch when the caller gives none.**: `refine_left_out` builds `_Selection(store)` for `devops roadmap explain` and `select_candidates` builds it through `_select_round`, so a required graph would break both paths and explain would keep the wait that the round ends. A round passes its graph and reads no listing; explain reads one listing for the one item that it judges.
- **Take the cycle of one item in `refine_one_item` from the listing that the function already reads for `title_dependencies`.**: `src/devops_cli/roadmap/refine/refine.py:3251:unmatched = title_dependencies(current_body, store.items()).unmatched` already reads the item sequence of the item, so the graph reuses it and the round sends no second listing read.
- **Let `open_dependency` build the graph from the `items` that the caller already holds.**: The stage and implement call sites keep their call and name the cycle with no change, and each job reads its listing once through its cached `_items` property, so neither sends a request for the graph.
- **Gate the graph with one `TopologicalSorter(...).prepare()` and walk the edges back from each item.**: Each item of a shared cycle gets its own path, so an edge that two cycles share hides no item, as the group of #4692 shows.
- **Give `check_ready` the required keyword `cycle` and make it false when the item is in a cycle.**: `src/devops_cli/roadmap/refine/refine.py:3996:if r.is_ready:` writes the Status from `is_ready` alone, so a complete proposal in a cycle would be set Ready while its step is `person`. `check_ready` is the one place that decides readiness, as it already does for an open dependency, and a required keyword lets no caller forget it.
- **End the recorded wait of an item whose record says `blocked` when that item is in a cycle.**: The round leaves an unchanged blocked item waiting while its blocker is open, so without this rule the items of the six live cycles would never be refined and would keep their step.
- **Put the cycle branch of `next_step_of` after the alternatives branch and before the ready, open-question, split and blocker branches.**: The cycle is the cause that a person must remove, and the blocker branch would otherwise answer `blocked` for the open issue that closes the cycle.
- **Record the step `person`, with the cycle in the step detail and in the Suspected block part of refine's section.**: A cycle waits on no outside event, so `blocked` is wrong and a person must remove one edge. The Suspected block part is the part of a person wait that holds no open question, so the wait text names the cycle.
- **Give the shared reason and the refine detail one message, `dependency_cycle`.**: One text states the rule, so a person reads the same sentence in the stage reason, the implement reason and the refine section.
- **Keep every existing call site and test of `open_dependency` and `next_step_of` as it stands, and update only the `check_ready` cases of `tests/roadmap/refine/test_roadmap_refine_proposal.py` with `cycle=False`.**: The new keyword of `open_dependency` and of `next_step_of` carries a default, so an item that is in no cycle gets the answer it gets today, and the recorded diffs replay as they stand.
- **State the Ready rule and the wait rule in a second added requirement, and keep the person step, its detail and the Suspected block line in the first.**: One requirement that holds all of the rules is over the 500-character limit of a requirement text, so the Status rule and the wait rule move to a requirement of their own, each with the scenarios that a test asserts.

## Rejected alternatives

- **networkx for the cycle check**: It adds a dependency for a check that the standard library gives, and the repository already imports `graphlib`.
- **A hand-written topological sort**: It keeps a sort and a cycle check in the project that the standard library gives and tests.
- **A new module `src/devops_cli/roadmap/cycle.py`**: A second module for three functions, and the parse that the graph reads already lives in the refine module.
- **The cycle check in the refine job only, with no change to the shared read**: The stage job and the implement job keep the old reason and name no cycle.
- **One `prepare()` and the first `CycleError` path**: It names one cycle for each round, so the items of the other cycles keep waiting.
- **Repeat `prepare()` with the closing edge removed**: An edge removed for one cycle breaks another cycle that shares it, so its items stay unnamed.
- **A required `graph` argument on `_still_waiting` and `_Selection`**: `src/devops_cli/roadmap/refine/refine.py:2809:selection = _Selection(store)` in `refine_left_out` gives no graph, so a required argument breaks `devops roadmap explain`, and `src/devops_cli/roadmap/refine/refine.py:2785:waits = _still_waiting(self.store, item, self.comments_on, self.questions())` is the one call that would then fail for that path.
- **Let `refine_left_out` keep the blocked wait and give it no graph**: `src/devops_cli/roadmap/refine/refine.py:2803:cannot differ (#3483). The limit of a round is no rule of the item.` states that explain and a round give the same answer, so explain must end the wait that the round ends.
- **Return `person` from `next_step_of` for a cycle and leave `is_ready` as it stands**: `src/devops_cli/roadmap/refine/refine.py:3996:if r.is_ready:` writes the Status Ready from `is_ready` alone, so a complete proposal in a cycle would be set Ready while its step is `person`, and the stage job would take the item that the cycle holds back.
- **Place the cycle branch after the split branch, as an earlier plan did**: `src/devops_cli/roadmap/refine/refine.py:1527:return NextStep.BLOCKED, tuple(f"#{dep}" for dep in blockers), blockers` answers `blocked` before any later branch, so a cycle whose open issue is a blocker would never reach the cycle branch.
- **Leave the wait of a blocked item as it stands and rely on the refined items only**: `_still_waiting` keeps the wait of an item whose record says `blocked` while its blocker is open, so the items of the live cycles would keep their step and no person step would name the cycle.
- **Replace the record edges of the refined item with the open dependencies of its proposal**: A cycle that only the record of the item declares then gives no path, and the item records `blocked` as before.
- **Hand the cycle to `next_step_of` from a test alone**: Such a test never runs the round over the store, so a broken wiring from the record and the listing to the step stays unseen.
- **Keep the cycle in the step detail only, and claim that closing an issue of the cycle ends the wait**: The wait text is the open questions, the suspected block and the watched files of refine's section, so a detail alone ends no wait.
- **A new step value for a cycle**: A new value in the step vocabulary for one case, and the `person` step already carries the detail that a person reads.
- **One added requirement that holds the person step, the Status rule and the wait rule**: The text of that requirement is 576 characters, over the 500-character limit, so the Status rule and the wait rule go into a second added requirement with their own scenarios.

## Unchanged references

- `src/devops_cli/roadmap/stage/stage.py` (import): The stage job keeps its call to `open_dependency`, which now names the cycle from the listing the job already holds.
- `src/devops_cli/roadmap/implement/implement.py` (import): The implement job keeps its call to `open_dependency`, which now names the cycle from the listing the job already holds.
- `src/devops_cli/roadmap/explain.py` (import): It calls `refine_left_out`, which ends the wait of a blocked item in a cycle through `_still_waiting` and needs no change of its own.
- `tests/roadmap/refine/test_roadmap_refine_blocked.py` (quoted target): Its items are in no cycle, so the step `blocked` and the open-issue reason stay as they are.
- `tests/roadmap/refine/test_roadmap_refine_event_comment.py` (import): It calls `next_step_of` without the new keyword, whose default gives the same answer for an item that is in no cycle.
- `tests/roadmap/refine/test_roadmap_refine_job_result.py` (import): It calls `next_step_of` without the new keyword, whose default gives the same answer for an item that is in no cycle.
- `tests/roadmap/stage/test_roadmap_stage_plan_check.py` (quoted target): It names `open_dependency` and asserts no cycle reason, and the answer for an item in no cycle is the open-issue reason still.
