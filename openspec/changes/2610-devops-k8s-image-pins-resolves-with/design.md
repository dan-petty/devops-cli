# Design

## Decisions

- **Resolve with `tag_digest` of `src/devops_cli/docker/registry.py`, not with a pinned `crane`.** `tag_digest` sends a HEAD of the manifest and answers a 401 Bearer challenge with an anonymous token. It is tested in `tests/docker/test_registry_tag_digest.py` and used by `check_pins` of `devops argo cd apps status`. The run of 2026-11-01 (see "Feasibility" in the proposal) read three Docker Hub digests and left `ratelimit-remaining` at `98;w=3600`.
- **Map a Docker Hub name in the registry module.** `tag_digest` builds its URL from the registry host of the reference. `docker.io` answers `302` to `www.docker.com`, and the Docker Hub registry is `registry-1.docker.io`. `tagged_image` reads a name with no registry as `docker.io`, and reads `index.docker.io` as `docker.io`. `tag_digest` then sends `docker.io` to `registry-1.docker.io` and puts the prefix library before a repository of one component. The table of names stays in `registry.py`, the one module that reads it, as a private constant. No other module of the package writes the host `registry-1.docker.io`.
- **Read a digest reference in `tagged_image`.** `image@sha256:...` and `image:tag@sha256:...` are references that the old resolver accepted. `TaggedImage` gets a `digest` field with the default `None`, so the existing equality checks of the tests still hold. When a digest is present, the HEAD goes to the manifest of the digest. A reference with neither a tag nor a digest stays refused.
- **Move `image_reference` to `registry.py`, and build `tagged_image` on it.** The issue asks that `src/devops_cli/k8s/image_pins.py` keep no split of its own. `updater_repositories` reads a name with no tag (the `imageName` of an `ImageUpdater`), so `tagged_image` alone cannot replace it. One split stays, in `registry.py`. The Docker SDK parity test moves with it. #2603 replaces the body with the parser of docker-py later.
- **The client comes from `new_http_client(level=EgressLevel.PUBLIC)`, opened in the command.** This is how `_check_image_pins` of `src/devops_cli/commands/argo.py` opens it. The timeout is `DEFAULT_HTTP_TIMEOUT_SECONDS`. `resolve_image_pins` takes the client and keeps its pool of 8 workers. One client serves all workers.
- **A resolve error is a result, not an exception.** `resolve_image` catches `RegistryReadError`, `SSRFBlockedError` and `httpx2.HTTPError`, as `check_pins` does, and records the text in `PinResolution.error`. The command then exits 1 and names the image, its Applications, its registry and the text. No error is hidden.
- **A dry run resolves nothing in the command.** In a dry run the renders are planned and return no output, so no image is found. The command opens no client and calls no resolver when `--dry-run` is set. The `planned` field of `PinResolution`, and the "planned" text of the result column, are then never set, so they go.
- **The tests double the registry at the HTTP edge** with `stub_web.serve(RegistryFake(...))` of `tests/support/fakes/oci_registry.py`. A Docker Hub case uses `RegistryFake(..., host="registry-1.docker.io")`. This is the double of #1997, so no new fake and no new contract suite is written.

## Rejected alternatives

- **Pin `crane` in `tools.lock` and call `crane digest` as a process.** It sends a HEAD too. The design of #1997 (`openspec/changes/archive/2026-10-29-1997-argo-image-pin-drift/design.md`) rejected it for the same read: a new pin, an installer step, a process fake, recorded runs and a contract suite. `tag_digest` already exists and passes its tests.
- **Prepend the prefix docker.io and library to a name and call `tag_digest` as it is.** `curl -sI https://docker.io/v2/library/nginx/manifests/1.27` gives `302` to `www.docker.com`, so every Docker Hub pin would fail. The host map above replaces it.
- **Keep `ImagetoolsFake` and add a second fake for `tag_digest`.** The resolver starts no process, so a process fake has no use. `RegistryFake` already answers at the HTTP edge.
- **Keep `image_reference` in `src/devops_cli/k8s/image_pins.py` next to `tagged_image`.** Two splits of the grammar drift. The issue asks for one.
- **Use `docker.auth.resolve_repository_name` from docker-py now.** The package has no type hints, and its import adds a `type: ignore` above the ceiling of the project (note in the module docstring of `registry.py`). #2603 does this.
