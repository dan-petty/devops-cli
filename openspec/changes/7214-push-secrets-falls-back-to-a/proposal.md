# Proposal

## Why

Product code reads a test fixture (#7214). `src/devops_cli/k8s/cluster_secrets.py:498:env_file = _resolve_fixture_secrets_file()` reads `tests/fixtures/cluster-secrets.toml` when the environment tree holds no cluster-secrets.toml, and `src/devops_cli/k8s/environment.py:104:fixture = self.repo / "tests" / "fixtures" / _CLUSTER_SECRETS` names the same fixture from the tree. An installed release ships no fixture, so `devops k8s push-secrets` pushes the product rows only and skips the environment Secrets with no error. The product table also still holds the `devops/renovate` row after Renovate left the product (#6938), and the living spec of `renovate-service` still requires that row.

## What Changes

- The `cluster_secrets` property of the environment tree, at `src/devops_cli/k8s/environment.py:96:def cluster_secrets(self) -> Path:`, returns the tree's own cluster secrets path and reads no test fixture.
- `src/devops_cli/k8s/cluster_secrets.py:467:def load_cluster_secrets_table(` resolves the environment tree, reads its cluster secrets file, and raises `src/devops_cli/exceptions/config.py:10:class ConfigurationError(DevOpsCLIError, ValueError):` with the new message `cluster_secrets_file_not_found` when the tree holds no such file.
- `src/devops_cli/k8s/cluster_secrets.py:453:_FIXTURE_SECRETS_FILE = (`, `src/devops_cli/k8s/cluster_secrets.py:456:_FALLBACK_FIXTURE_SECRETS_FILE = Path("tests/fixtures/cluster-secrets.toml")` and `src/devops_cli/k8s/cluster_secrets.py:459:def _resolve_fixture_secrets_file() -> Path | None:` go away, so no module under `src/` reads a Secret table from a test fixture.
- The product table holds no `devops/renovate` row: `src/devops_cli/k8s/cluster_secrets.py:504:CLUSTER_SECRETS: tuple[ClusterSecret, ...] = (` and `src/devops_cli/k8s/cluster_secrets.py:762:OPTIONAL_FEATURE_SECRETS: Final[tuple[str, ...]] = (` lose the row and its name.
- The push, plan, key-ref and renderer tests pass the `FIXTURES` folder as the tree to every read of the table, and a new push test proves the error on an empty tree.
- `tests/support/k8s_tree.py` gains `copy_with_cluster_secrets`, which copies the repository tree and puts the fixture at its root, and every deploy-stack run of the command tests reads a tree that holds the environment Secret rows.
- The bootstrap command tests read a copy of the tree with `--dir`, and the Mattermost bootstrap test runs in a temporary repository whose tree holds the fixture, because both commands push Secrets from the tree of their run.
- The object store gate check and the invariant test pass the fixture folder as the tree to their table reads.
- The generate tests of `tests/commands/test_config_commands.py` run in a temporary repository whose tree holds a copy of the fixture, and each of the six tests that reach the generator read that tree.
- `docs/CLUSTER.md` and `k8s/README.md` say that dan-petty/homelab holds the Renovate Secret row and the product table holds none.
- The spec delta of `cluster-secrets-loader` drops the fixture fallback and names the missing-file error, and the delta of `renovate-service` moves the row to the environment tree.
- The change lands after step 17 of #5134, which deletes the environment tree of the devops-cli checkout.
- The change fits one pull request.
