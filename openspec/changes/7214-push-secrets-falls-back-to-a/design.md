# Design

## Decisions

- **Delete both fixture fallbacks and raise the error of `src/devops_cli/exceptions/config.py:10:class ConfigurationError(DevOpsCLIError, ValueError):` with a message of the language catalog that names the tree's cluster secrets file.**: `src/devops_cli/k8s/environment.py:104:fixture = self.repo / "tests" / "fixtures" / _CLUSTER_SECRETS` and `src/devops_cli/k8s/cluster_secrets.py:456:_FALLBACK_FIXTURE_SECRETS_FILE = Path("tests/fixtures/cluster-secrets.toml")` make product code read a test fixture, and an installed release ships no fixture, so the push skips the environment Secrets with no error.
- **Let the loader resolve the tree with `src/devops_cli/k8s/environment.py:118:def resolve_environment(` and let both errors stand, so the loader holds one rule and catches nothing.**: The resolver already raises the configuration error that names the option and the project file, and a caught error hides the missing configuration that the issue reports.
- **Keep the direct and the nested lookup of the tree's own cluster secrets file, and delete the fixture branch alone.**: `src/devops_cli/k8s/environment.py:101:nested = self.root / "k8s" / _CLUSTER_SECRETS` serves a tree root that holds a k8s subfolder, and the issue asks for the removal of the test-fixture read only.
- **Give the tree to the tests through the existing constant `tests/support/paths.py:22:FIXTURES: Final[Path] = TESTS_ROOT / "fixtures"` and pass it as the tree argument to each read of the table, including the reads through `secrets_by_ref`, `keyring_only_keys`, `generator_option_names` and `generator_for_option`, whose `table` argument takes the table loaded from that tree.**: `tests/k8s/test_cluster_secret_plan.py:80:TABLE_REFS = {secret.ref for secret in load_cluster_secrets_table()}`, `tests/k8s/test_cluster_secret_key_refs.py:89:table_list = tuple(load_cluster_secrets_table())` and `tests/k8s/test_grafana_renderer_optional.py:10:refs = {secret.ref for secret in load_cluster_secrets_table()}` pass no tree, and `src/devops_cli/k8s/cluster_secrets.py:852:def keyring_only_keys(table: Iterable[ClusterSecret] | None = None) -> frozenset[str]:` loads the table itself when its argument is None.
- **Add `copy_with_cluster_secrets` to `tests/support/k8s_tree.py`, which copies the tree at `tests/support/k8s_tree.py:14:K8S = REPO_ROOT / "k8s"` and puts the fixture at the root of the copy, and give that copy to every deploy-stack run of a command test that pushes Secrets, through the module's deploy helper where the module has one.**: `src/devops_cli/commands/k8s/stack_lifecycle.py:984:table = load_cluster_secrets_table(env=env)` loads the table of the tree of the run, so each run of a module needs the file, and `tests/commands/k8s/test_k8s_qdrant_security.py:117:return CliRunner().invoke(DEPLOY_COMMAND, ["--context", "test-ctx", "--no-wait", *args])` shows one helper that carries every run of its module.
- **Give `--dir` with a copy of the tree to the two bootstrap runs that reach the deploy, and put the fixture into the tree that `test_k8s_bootstrap_success` builds.**: `src/devops_cli/commands/k8s/bootstrap.py:69:stack_life.deploy_stack(k8s_dir=env.root, stack=stack)` pushes the Secrets of the tree that the run resolved, and `tests/commands/k8s/test_k8s_context.py:73:manifest_dir = tmp_path / "k8s"` builds a tree with no cluster secrets file, so both fail after group 2 without the file.
- **Run `test_bootstrap_mattermost_full_flow` in a temporary repository whose profile names a tree that holds the fixture, and leave the command and its options unchanged.**: `src/devops_cli/commands/k8s/mattermost_bootstrap.py:341:k8s_push_secrets(` gives no `k8s_dir`, so the push reads the tree of the current folder, and `tests/commands/test_k8s_bootstrap_mattermost.py:117:res = runner.invoke(app, ["k8s", "bootstrap-mattermost"])` reaches it; a new option on the command would change the command that the issue does not name.
- **Put the copy under the temporary folder in a folder named k8s and change into the temporary folder for a run that names the relative tree, so the expected relative paths of the output stay the same.**: `tests/commands/k8s/test_k8s_logging_stack.py:30:res = cli("k8s", "deploy-stack", "--stack", "logging", "--k8s-dir", "k8s", "--dry-run")` asserts paths relative to the tree root, and `src/devops_cli/k8s/environment.py:111:"""The environment tree whose root is `root`, kept as given, so a relative root gives relative` keeps the given root.
- **Give the default tree to the push helper `tests/k8s/test_cluster_secret_push.py:132:return runner.invoke(PUSH_COMMAND, ["--context", "test-ctx", *args])`, so each push test passes `--k8s-dir`, and let the new error test use its own empty folder and assert `result.exception`.**: `tests/k8s/test_cluster_secret_push.py:56:_push_app = typer.Typer()` reports no error line, so the raised error reaches the result and not the output; one default covers the module.
- **Replace the four fixture tests of `tests/k8s/test_cluster_secrets_file.py` and the fixture test of `tests/k8s/test_environment.py` in the groups that delete the code they exercise.**: A test that monkeypatches a deleted constant fails its own group's verify, and the group that deletes the constant is the place that replaces the test.
- **Run the generate tests of `tests/commands/test_config_commands.py` in a temporary repository whose project profile names the `k8s` tree and whose tree holds a copy of the fixture, and give that fixture to each of the six tests that reach the generator.**: `src/devops_cli/commands/config.py:273:table = load_cluster_secrets_table()` resolves the tree from the project profile of the current folder, and the same call reaches six tests of the module, so one of them alone leaves the module's verify failing.
- **Drop the `devops/renovate` row and its optional-feature entry from the product table, and restate the `renovate-service` requirement so the environment tree of dan-petty/homelab holds the row.**: #6938 moved self-hosted Renovate out of the product, and the base requirement of `renovate-service` still states that the cluster secret table holds the row, so the delta modifies it.
- **Keep one requirement of `cluster-secrets-loader` for the environment file, with the missing-file error and the fixture rule in its text, and add no second requirement for the fixture.**: One rule sits in one requirement, and the earlier added requirement repeated the last sentence of the modified one.
- **State the three optional keys of the Renovate row in the text of its requirement and name them in the `The push` scenario, and keep the requirement name because the text still holds the two IDs and the key under their variables.**: A requirement text holds at most 500 characters, and the earlier text of 515 characters failed that bound; the keys stay in the text in one clause and in full in the scenario that a test asserts.
- **Leave the three callers and the two docstrings unchanged, and leave `openspec/specs/` to `openspec archive`.**: `src/devops_cli/commands/k8s/cluster_secret_push.py:233:table = load_cluster_secrets_table(k8s_dir=k8s_dir)` already gives the tree, Secret `devops/renovate` still exists in the environment tree, so the docstring of `src/devops_cli/config/settings.py` stays true, and the archive writes the living specs from this delta.
- **Carry the chosen design of the refine block: wait for step 17 of #5134 and dan-petty/homelab#96, and write no interim workaround.**: Comment 2 of the issue reports 89 failing tests against the devops-cli tree before step 17, and `AGENTS.md` rule 2 forbids compensating code for a leaf item that cannot be built as written.

## Rejected alternatives

- **Keep the fixture fallback as a last resort when the tree has no cluster secrets file.**: `src/devops_cli/k8s/cluster_secrets.py:456:_FALLBACK_FIXTURE_SECRETS_FILE = Path("tests/fixtures/cluster-secrets.toml")` builds a path from the package location, so an installed release resolves a path that no file fills and the push skips the environment Secrets with no error.
- **Add an interim `--k8s-dir` option before step 17.**: `src/devops_cli/commands/k8s/cluster_secret_push.py:233:table = load_cluster_secrets_table(k8s_dir=k8s_dir)` shows that the option already exists, so a second option is a second fix on a fix.
- **Add a cluster secrets file to the product tree so a devops-cli checkout resolves the rows.**: The issue body says "the freeze check of step 12 refuses a change of an environment path", and `list_files k8s` showed no cluster secrets file at the staging commit.
- **Give the fixture folder alone as the tree to a deploy-stack test.**: `src/devops_cli/commands/k8s/stack_lifecycle.py:984:table = load_cluster_secrets_table(env=env)` reads the table of the same tree that holds the manifests, and the fixture folder holds no manifest.
- **Give the fixture folder alone as the tree to a bootstrap run.**: `src/devops_cli/commands/k8s/bootstrap.py:69:stack_life.deploy_stack(k8s_dir=env.root, stack=stack)` deploys the manifests of the same tree, and `tests/commands/k8s/test_k8s_bootstrap.py:231:res = runner.invoke(app, ["bootstrap", "--auto-start", "--stack", "infra"])` asserts the helm releases of that deploy.
- **Add a `--k8s-dir` option to `devops k8s bootstrap-mattermost` for its Secret push.**: `src/devops_cli/commands/k8s/mattermost_bootstrap.py:341:k8s_push_secrets(` is the one call of the push in the command, and the issue names no new option, so a new option is a change of the command beyond the fix and a second fix on a fix.
- **Give the copy of the tree to one deploy-stack test of `tests/commands/k8s/test_k8s_qdrant_security.py` instead of to its `_deploy` helper.**: `tests/commands/k8s/test_k8s_qdrant_security.py:117:return CliRunner().invoke(DEPLOY_COMMAND, ["--context", "test-ctx", "--no-wait", *args])` carries the five deploy-stack runs of the module, so a tree given to one test leaves the other four reading `k8s/`.
- **Give the repository fixture to two of the `--generate` tests of `tests/commands/test_config_commands.py`.**: `src/devops_cli/commands/config.py:273:table = load_cluster_secrets_table()` sits in the generator helper, which `tests/commands/test_config_commands.py:102:result = runner.invoke(config_app, ["set", "crawl4ai.api_token", "--generate"])` and five more tests of the module reach, so the module's verify fails without the tree in each of them.
- **Write the fixture into the committed tree at the start of a test session and delete it at the end.**: `tests/support/k8s_tree.py:14:K8S = REPO_ROOT / "k8s"` is the tree of the checkout, so a crashed run leaves a file that git does not hold and a person must remove.
- **Verify the invariant and command test modules with the k8s gate row.**: `tests/gate/k8s_checks/object_store.py:1045:refs = [secret.ref for secret in load_cluster_secrets_table()]` sits in a check function that the k8s row calls, so that row never runs `tests/invariants/test_k8s_manifests.py` or `tests/commands/k8s/test_k8s_qdrant_security.py`.
- **Assert the missing-file error in the output of the plain push app of the test module.**: `tests/k8s/test_cluster_secret_push.py:56:_push_app = typer.Typer()` wraps no exit seam, so the raised error reaches `result.exception` and no line of `result.output`.
- **Restate the installed-package scenario of `cluster-secrets-loader` as a search of the fixture path.**: `src/devops_cli/k8s/cluster_secrets.py:467:def load_cluster_secrets_table(` is the function that the scenario names, so the test of that function proves it and a second requirement repeats no rule.
- **Split the Renovate requirement in two, one for the environment tree row and one for the product table.**: `read_spec renovate-service` showed the base requirement with its two scenarios `The push` and `A workstation with no Renovate settings`, and a `modified` entry replaces the whole requirement, so one requirement of 394 characters holds both rules and its name.

## Security

The change moves a Secret row across a trust boundary: the GitHub App credentials of Renovate leave the product table and live in the cluster secrets file of the environment tree of dan-petty/homelab, so a person must confirm that the tree holds the row and that the three App settings stay in the workstation keyring before the product row goes. The loader also stops reading a test fixture as production data, so no path under `tests/` can supply a Secret row to a cluster, and a tree that holds no cluster secrets file stops the push with one error line instead of a silent skip. `test_the_product_table_holds_no_renovate_row` and `test_load_cluster_secrets_table_raises_when_the_tree_has_no_file` fail if either rule breaks.
