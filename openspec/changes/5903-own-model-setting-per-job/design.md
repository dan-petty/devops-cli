# Design

## Decisions
- **The name of a task is the name of its job.** The tasks `intake`, `retitle`, `refine`, `alternatives`, `consolidate`, `stage`, `fix_plan` and `implement` have the name of the row or the command of the job. A second model role of a job adds a suffix to the name of the job: `_review` for the model that reviews the work of the job (`refine_review`, `stage_review`, `fix_plan_review`), and `_split` for the call that splits the groups of the implement job (`implement_split`). A new step job adds one task with its own name.
- **A task has no parent.** `AIConfig.for_task` applies only `ai.tasks.<task>` over `ai`. A task that sets no model uses `ai.model`, and a task that sets no window uses `ai.context_window`.
- **The repair of `fix-plan` reads its own tasks.** `revise_plan` and `_planner_of` of `stage.py` take the task of the planner and the task of the review as keywords, with `stage` and `stage_review` as the defaults. `fix-plan` passes `fix_plan` and `fix_plan_review`. The `ToolboxClient` of a run gets the task of its window, so the error of a run whose window ends the tools too soon names `ai.tasks.<task>.context_window` of that run.
- **The eval command of a job reads the task of the job.** `devops roadmap eval intake` and `eval jev` read `intake`. `eval verify` and the screen and verify evals of the stage review read `stage_review`. `eval stage` keeps `stage`.
- **The old tasks stay valid.** `analysis`, `verification` and `triage` stay in `AITasksConfig`, because `devops review`, `devops ai agents` grouping and the review profile read `analysis` and `verification`, and a config file or a live ConfigMap that sets `triage` must still load. No roadmap job reads them.
- **Each new task has the variables of `stage`.** The provider, the model, the reasoning effort, the Ollama URLs, the window and the reply limit.
- **The template names each job.** `k8s/devops/configmap.example.yaml` names DeepSeek with `context_window` 256000 for each job task that had that window through its old slot, and `local/qwen3.8:27b` for `intake` and `retitle`. A job reaches `local/qwen3.8:27b` only after its grade reaches 80% (owner direction of 2026-11-16).

## Rejected alternatives
- **Settings under `roadmap.<job>.model`.** The client factory, the gateway address, the spend stage and `get_task_model` read `ai.tasks.<task>` (`ai/client/factory.py`, `ai/spend/stage.py`). A second place for a model needs a second resolver for each of them.
- **One task for each job, shared by its review.** The stage job has a review model apart from its planner since #3153, and the windows of the two runs differ (#3039). A shared task cannot try a model on the review alone.
- **Keep `triage` as the task of intake.** Retitle moves to its own task, and a task named after a role and not a job does not show which job it moves. The live ConfigMap gets the key `intake` after the rollout.
- **Remove `analysis`, `verification` and `triage`.** `devops review` (`ai/review/runner.py`, `commands/review.py`), the grouping of `devops ai agents audit` and `run_store.review_setup` read `analysis` and `verification`. The live ConfigMap holds `analysis` and `triage`, and `AITasksConfig` refuses an unknown key, so the new image would not start.
