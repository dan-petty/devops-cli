# Design

## Decisions

- **Build the collection command with `_collection_cmd`, which calls the existing `_build_test_cmd` and adds `--collect-only -q`.**: `src/devops_cli/commands/ci.py:def _build_test_cmd` already builds `uv run pytest` with the `-k` filter and the targets, and a second builder in another module would drift from the command the run starts.
- **Count the collected tests with the existing `collected_items` of `src/devops_cli/roadmap/implement/implement_test_form.py`, imported lazily in the count function.**: That function already counts the lines of a quiet collection that hold a test id and answers zero for a collection with no item, so a second counter would duplicate tested code.
- **Keep `collected_items` in its module and import it lazily, instead of moving it into the CI package.**: Its tests live beside it in `tests/roadmap/implement/test_roadmap_implement_test_form.py`, the implement step imports it from there, and a lazy import keeps the startup imports of `devops ci` unchanged.
- **Start the collection through `_run_in_own_session`, the runner the run itself uses.**: One edge starts both children, the process runner seam answers both in the tests, and `tests/support/session_spawns.py:def record_spawns` doubles the same start.
- **Give the collection-failure case 13 target files, more than `DEFAULT_CI_TEST_SERIAL_MAX_FILES`.**: `src/devops_cli/commands/ci.py:1940:if len(targets) <= DEFAULT_CI_TEST_SERIAL_MAX_FILES:` gives `-n 0` at 12 files or fewer, so a 7-file case cannot tell the file-count fallback from a count of zero; at 13 files the fallback gives `-n 4` and the test asserts the rule that ran.
- **Treat pytest's exit code 5 as a count of zero and as no collection failure.**: A `-k` filter that matches no test is no failure of the collection, so the command runs `-n 0` with no warning; the fallback scenario names exit code 3, so no test reads two answers from one exit code.
- **Skip a child that holds `--collect-only` in the test helpers that read the pytest run.**: `tests/commands/test_test_selection.py:70:def _pytest_runs(process_fake: ProcessFake) -> list[list[str]]:` and `tests/commands/test_ci.py:1947:runs = [call for call in process_fake.calls if "pytest" in call.argv]` take the first pytest child as the run, and the collection is now the first one.
- **Give `-n 2` to the tests that read the run's own child.**: A given `-n` makes no collection call, so the helpers `_run_recording_handlers` and `_devops_ci_test` and the timeout case keep the child they signal, time out and record.
- **Make no collection call in a dry run.**: A dry run renders the planned command and starts nothing, so a collection there would answer with a plan and no count.
- **Re-raise `asyncio.CancelledError` from the collection as `typer.Exit(CONST_EXIT_CANCELLED)`.**: A Ctrl-C, SIGTERM or SIGHUP during the collection must exit as cancelled, as `src/devops_cli/commands/ci.py:def _session_returncode` already does for the run.
- **Fall back to the file count when the collection fails or times out, with a warning that names the failure.**: The run still starts, and the rule of #1669 bounds the worker count of that fallback; a collection error hides no test result.
- **Set `DEFAULT_CI_TEST_SERIAL_MAX_TESTS` to 50 collected tests.**: The issue reports seven files and 399 tests, and the criteria keep a small selection serial; 50 keeps xdist start-up away from a tiny selection and puts that selection on the narrowed workers.
- **Keep `_narrowed_workers` in `src/devops_cli/commands/ci.py` and give it the collected count.**: The issue names that function, and the command module owns the worker choice that `src/devops_cli/commands/ci.py:def test` makes.
- **Leave the inline collection command of `src/devops_cli/roadmap/implement/implement_step.py` unchanged.**: It collects one named path for a test-form check under its own timeout, not for a worker decision, and only its counter is reused.
- **Regenerate the command pages with `uv run devops docs generate` and edit no generated file by hand.**: `src/devops_cli/commands/ci.py:def get_check_specs` gives that command as the fix of the `docs` row, which refuses a generated document that is not the output of its generator.
- **Leave the recorded stage fixtures unchanged: `tests/fixtures/roadmap/plan_heads/4917-ba8cc66fd2f4/4472-a-narrowed-ci-test-runs-many/proposal.md`, `tests/fixtures/roadmap/plan_heads/4917-ba8cc66fd2f4/4472-a-narrowed-ci-test-runs-many/design.md`, `tests/fixtures/roadmap/plan_heads/4917-ba8cc66fd2f4/4472-a-narrowed-ci-test-runs-many/tasks.md` and `tests/fixtures/roadmap_fix_plan/stage_comment_4472.txt`, and keep `src/devops_cli/roadmap/implement/implement_step.py` and `tests/roadmap/implement/test_roadmap_implement_test_form.py` as they are.**: The four fixtures record an earlier plan and an earlier review of this issue, which the stage evaluation replays as they are, and the two source files keep the counter this change reuses.
- **Keep `CHANGELOG.md` as it is.**: Its line records the released change of #1669 and release-please keeps released entries as history; this change adds its own entry at the next release.

## Rejected alternatives

- **Keep the number of test files as the only rule for the worker count.**: The issue reports 7 files holding 399 slow tests that ran serially past the 1800 s timeout, while `pytest -n 6` ran 264 of the other tests of the same selection in 114 s.
- **Read a duration cache of the collected tests and size the workers by their time.**: The issue's alternatives check records that no maintained duration cache exists in the project, so the command would have to build and keep one.
- **Always start `DEFAULT_CI_TEST_NARROWED_WORKERS` workers for every narrowed run.**: The comment above `src/devops_cli/config/defaults.py:494:DEFAULT_CI_TEST_SERIAL_MAX_FILES: Final[int] = 12` records one module at 6 s serial against 11 s on four workers, so a tiny selection pays xdist start-up for nothing (#1669).
- **Write a second counter over the collection output inside the CI package.**: `src/devops_cli/roadmap/implement/implement_test_form.py:85:def collected_items(output: str) -> int:` already counts the lines that hold a test id and returns zero for a collection with no item.
- **Count the test functions of the selected files with `ast`.**: `tests/roadmap/implement/test_roadmap_implement_test_form.py:108:def test_collected_items_counts_the_lines_that_hold_a_test_id() -> None:` shows pytest reports one item for each parametrized case, which an `ast` count of functions misses while counting functions that the run skips.
- **Add a second builder of the collection command in a new module.**: `src/devops_cli/commands/ci.py:def _build_test_cmd` already builds `uv run pytest` with the `-k` filter and the targets, so a second builder would let the collection and the run drift apart.
- **Start the collection with the synchronous `run_subprocess`.**: `tests/support/session_spawns.py:def record_spawns` doubles only `asyncio.create_subprocess_exec`, so the tests that drive the command through that edge would start a real `uv run pytest --collect-only`, which `refuse_nested_test_runs` fails.
- **Let the live driver of the signal tests make its collection call.**: Its `uv` is a fake on PATH that waits for a signal, as `tests/commands/test_ci.py:2626:def _devops_ci_test(` shows, so the collection would wait instead of the run that the test signals.
- **Keep the collection-failure case at 7 files.**: `src/devops_cli/commands/ci.py:1940:if len(targets) <= DEFAULT_CI_TEST_SERIAL_MAX_FILES:` gives `-n 0` at 7 files, which is also the answer of a count of zero, so no test can show that the command fell back to the file count.
- **Read a non-zero collection exit as a failure whatever its code.**: `_collected_test_count` answers 0 on exit 5, the exit pytest gives when no test matches the `-k` filter, so the spec scenario of the fallback names exit code 3 and no test reads two answers from one code.
