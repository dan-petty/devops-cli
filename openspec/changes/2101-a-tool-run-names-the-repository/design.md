# Design

## Decisions

- **Read the repository URI with `git config --local --get remote.origin.url` through the existing `_git` helper**: Exit code 1 means the key is not set, and the `git config` manual documents it. The command `git remote get-url origin` exits with 2 for a missing remote, and git does not document that code. The option `--local` keeps git from reading the global configuration, and it gives exit 128 outside a checkout. `_git` accepts exit codes 0 and 1, and an empty output gives None.
- **Guard the read as the commit read is guarded**: The repository read returns None when `nearest_checkout` finds no checkout, as `_read_tree_commit` does. A `_tree_repository_uri` helper turns a `SandboxError` into None unless `required` is true, as `_tree_commit` does, and `record_tool_run` passes `require_commit` as `required`. So a tree outside any repository, and a checkout that the direct executor cannot read, keep their record with no repository.
- **Strip the userinfo from the URL before storing it**: The issue requires no credential in the URI, and a SARIF consumer must not see a token. `urlsplit` splits the URL, and the host part of the netloc is the text after the last `@`.
- **Store the repository URI only when it is an absolute URI with a host**: The SARIF schema gives `repositoryUri` the format `uri`, and the specification calls it an absolute URI. A scp-style remote (`git@example.com:a/b.git`), a local path and a `file:` URL are not absolute URIs with a host. `urlsplit` gives them an empty scheme or an empty host, and `repository_uri` is None for them. A `ssh://` remote keeps its host and path, and loses its user name.
- **Write one `versionControlProvenance` entry for each distinct pair of repository URI and commit among the clean records of the tool**: `run.versionControlProvenance` is an array with unique items, and one tool can run more than once in a review at more than one commit. A record is clean when its commit is not None and does not end with `-dirty` (SARIF 2.1.0 section 3.23.4), and its repository_uri is not None. Each such record gives the pair `(repositoryUri, revisionId)`. The entries keep the order of the first record that gave each pair, and a pair never repeats. The code change is in `_run_for`, which builds the run from the records of the tool. `to_sarif` does not change.
- **Write no `versionControlProvenance` when no record is clean with a repository URI**: The schema requires `repositoryUri` in each entry, so a missing URI means the entry cannot be written. A `-dirty` commit identifies no revision of the scanned files.

## Rejected alternatives

- **Read the repository URI from an environment variable or config file**: The issue says read from git, and the existing _git helper is the established pattern for reading checkout metadata
- **Write versionControlProvenance for dirty commits with a note field**: SARIF 2.1.0 section 3.23.4 says revisionId must uniquely and permanently identify the revision of the scanned files; a -dirty commit does not, and the schema has no note field for this
- **Read the URI with `git remote get-url origin` and accept exit code 2**: On git 2.55.0 a missing remote gives exit 2, but the manual does not document it. The same code could stand for another failure, and `_git` would return None for it.
- **Read the URI with `git config --get remote.origin.url`**: Outside a checkout, git reads the global configuration and exits 0 with a URL that is not the URL of the tree (see Feasibility). `--local` removes this.
- **Keep one commit for the whole tool**: A review can run a tool more than once, and the records of one run can differ in their commit. `tests/security/test_sarif_emission.py` already puts a record with a commit and a record with no commit in one run. One entry would name a revision that some results did not scan.
- **Convert a scp-style remote to an `ssh://` URL**: It needs a hand-written parser for a form that `urlsplit` does not read. The remote stays out of the record, and the run has no `versionControlProvenance`.
