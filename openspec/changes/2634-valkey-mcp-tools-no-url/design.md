# Design

## Decisions

- **The MCP tools publish no URL.** `_PATH_PARAM_RESTRICTIONS` lets a command publish some of its options. Each of the six Valkey commands gets an entry with the options that stay. A model has no URL to give, so the defect has no input. A call that names `url` fails at the argument contract, before any command runs.
- **A list of allowed options, not a list of removed options.** The table that #2480 made lists the options that a tool publishes. A new option of a command is not published until a person adds it. This is the safe default for a tool that a model calls. The entries for `valkey_ping` and `valkey_stats` have an empty list.
- **The commands keep `--url`.** A person types `--url` at the command line. This keeps the rule of #2480: no model sits between the person and the option. The requirement "valkey.url names the address and the database" in `valkey-endpoint` keeps its words, because it is about commands and not about tools.
- **The password has no origin rule at the command line.** `_resolve_client` is the one place that joins a URL and the password. After this change no input of a model reaches it. `valkey keys`, `valkey backup` and `valkey cli` are not MCP tools, and no tool passes free arguments to a `devops` command. A person who types `--url` names the host on purpose.
- **The tests are in `tests/test_valkey.py`.** The file tests the client and the commands already. The new tests call the tools through a FastMCP `Client`, as the gateway tests of #2480 do. They bind a real listener on `127.0.0.1` with the shared `serving_valkey` and read the commands that arrive. The valkey domain is withheld from the tool listing, so the schema test hydrates it first.
- **`serving_valkey` returns at once when no client connects.** The accept loop waits in slices of one poll interval. After the block ends, it serves a connection that is pending, or it stops. The test of a refused call opens no connection, so it needs this. The old fake waited 30 seconds in that case.
- **`SECURITY.md` is not changed.** Principle 11 says that a tool publishes no option for a URL from a model. It holds no list of open exceptions. The list is in the design of #2480, which is archived and does not change.

## Rejected alternatives

- **Send the password only to the origin of `valkey.url`.** This is the second option that the issue names. It does not remove the defect of a write: `valkey_set` and `valkey_flush` would still write to any host that the model names, without a password. The tool needs no URL, because each tool reports or changes the configured server. The rule would also change the command for a person. `devops valkey ping --url` of another origin would send no `AUTH` and get a `NOAUTH` error from a server that needs a password. A second rule on a fix that already removes the input is what AGENTS.md rule 2 warns about.
- **Keep the option and dial at the public level.** The `EgressLevel.PUBLIC` docstring names this level for a URL that a model gives. It stops the loopback scan, but the password would still go to any public host that the model names. Valkey is an internal service by design (`SECURITY.md` principle 2), so a public level would also refuse the usual server.
- **An invariant test that no MCP tool publishes a URL option.** Other tools publish one, and each one is an open defect: #2635 for `k8s_logs`, #2637 for `ai_prewarm`, #2638 for `ai_benchmark` and #2639 for `vault_status`. An invariant needs an allow list of them, and an allow list is an escape. Each fix removes its own tool.
- **Close the connection of the fake after a timeout, or make the test wait 30 seconds.** A fixed wait makes each refusal test slow. A check that averages more than 5 minutes is a P0 bug, and a wait in each test adds to that. The accept loop with a stop flag costs 10 milliseconds.
