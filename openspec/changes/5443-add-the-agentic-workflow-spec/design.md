# Design

## Decisions

- **The form of `docs/DESIGN.md`.** The spec has a purpose, principles, a target table, measured tables with a caption above each, a method, a rules table with an ID for each rule, and an item table. The Mermaid figure follows the Mermaid row of `docs/DESIGN.md`: a flowchart, no `init` directive, 11 nodes and one direction.
- **One owner for each rule.** A rule that another document owns is a row with a link and a short name, and its rule text is `-`. The spec owns only the rules that no document held: the tuning loop and the trial (AW-T1 to AW-T6), the default of one branch run (AW-J5), the live proof (AW-J6), the line of a new job (AW-M2), the funnel (AW-M4), the context rules (AW-C1 to AW-C4), the tool rules (AW-U1 to AW-U4), the cost of a result (AW-O2), the agreement of the spend counters (AW-O3) and the eval rules AW-E2 to AW-E4.
- **Rule IDs with a prefix.** `docs/DESIGN.md` already uses T1 to T10 and C1 to C14, and the sibling specs add more IDs. So each rule ID of this spec starts with `AW-`.
- **A new term: branch run.** `CONTEXT.md` defines a candidate as an issue that intake has not placed. The parallel runs of one job on `<type>/<issue>-<slug>-<n>` need another word, so `CONTEXT.md` gets the term **Branch run**, with "candidate" in its `_Avoid_` line. Table 5-1 uses the terms Unit of work and Roadmap step of `CONTEXT.md`.
- **Measured numbers with their queries and their date.** Each table states its window and its source, and the section "Queries" gives each LogQL and PromQL query. The section is "The baseline of 2026-11-13", and only a pull request that states a new date changes it. The spend and token counters use the window of the lines (27 hours from the first line), so that a ratio of a counter to the lines compares the same hours. The comparison of the spend counters uses the `user_agent` label of the gateway, because nearly all gateway spend comes from devops-cli clients. The tables keep the defects of the measure in view (the `intake` skips, the copied `implement` line, the `fix_plan` lines outside the base query), because the grade `100` rule of `docs/roadmap/job-success.md` asks to check the measure first.
- **The approved plan as the target.** The pipeline split is approved but not built. Tracker #5474 holds it and is the public source of P3, Table 5-1, the funnel and the branch runs. The spec states the job model as the target and names what exists today (`run_due_jobs`, due marks, the modes of ADR 0021 section 8).
- **The sibling specs by issue.** The SRE service spec (#5445) and the Kubernetes performance spec (#5444) are not on `main`, so the spec names them by issue and not by path. A comment on each sibling issue asks its pull request to change these issue numbers to links when the files merge.
- **The tune-down rule.** "At least 25 % above the p90 of the successful attempts, and never below the largest one" keeps the room of each real success and leaves a margin for the tail, and the 3 daily checks of the 80 % rule decide the revert.
- **The trial.** A doubling or a change of one setting is one trial. It ends at 30 attempts with `infra=false`, after 7 days, or after one golden-set or replay run. Under 30 attempts, the Wilson upper bound under 0.80 starts a doubling, as in the 80 % rule. The SLOs of #4709 bound the time limits, so a doubling that burns the budget of the runner-Job SLO stops, and the loop goes to the next configuration or to a split.
- **Each gap has an issue.** Intake filed #5472 (G14), #5474 (G30, with G11 and G31), #5476 (G3) and #5479 (G12) as sub-issues; the tracker #5474 is a sub-issue of #4517, as the approved plan asks. G5 is part of #4724, with a comment that gives the same-window numbers. G28 is part of #3109.
- **The fix of `job-success.md`.** The sentence "The owner tunes the caps and the limits of a roadmap job only after the job holds 80% success" conflicts with the owner decision of 2026-11-13, so it changes in this pull request (AGENTS.md rule 8).

## Rejected alternatives

- **One spec for all three topics:** the owner asked for three specs, and the SLOs, the pod tuning and the agentic jobs have different owners and readers.
- **A row in `AGENTS.md`:** it has 4,222 of 4,500 characters, and the sibling specs can need the room. `docs/ROADMAP_WORKFLOW.md`, which `AGENTS.md` routes to, links the spec.
- **Copy the 80 % rule, the grade table and the failure classes into the spec:** a second copy drifts. The spec links `docs/roadmap/job-success.md` and `docs/ROADMAP_WORKFLOW.md`.
- **The grades from `devops roadmap eval grades`:** the command could not reach Loki from the workstation (#5481), and its base query leaves out the `fix_plan` lines of the Job stream (#5169). The Grafana datasource gave the same queries plus the Job stream.
- **"Candidate" for a parallel run of one job:** `CONTEXT.md` gives the word to an issue that intake has not placed. One word has one meaning (ASD-STE100).
