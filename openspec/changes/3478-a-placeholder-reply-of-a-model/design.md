# Design

## Decisions

- **Remove the `premise_failed` return path of the stage job.**: The key had one true use (#3251) and 33 filler uses. A typed form still trusts model text. A quote check cannot work: #3109 quotes a probe line and states that the premise holds. A premise that is false is a fact that the implement job and a person can find with evidence, and `devops roadmap return` stays for a person. A test holds the choice: a reply with the key fails the schema.
- **Make the keys of the plan required keys of `StageProposal`.**: With the return path gone, no reply may leave them out. A schema with the defaults and no check would accept `{}`. The required keys also show in the JSON schema that the model receives.
- **One type, `ReplyText`, applies `is_placeholder` as a pydantic `AfterValidator`.**: It lives in `pull_form.py` beside `is_placeholder`, so one word list holds the rule. It raises `PydanticCustomError("placeholder_text", ...)`, so the type of the error tells a placeholder from another violation. `is_placeholder` gains `y`, `probe` and the lead `Not yet:`. `__PROBE__` needs no entry: the edge characters include `_`.
- **Use `ReplyText` for the free-text fields of the refine reply, and keep the content gate for the stage reply.**: Every free-text field of the refine reply is `ReplyText`, except `suspected_block`: its value `none` is a valid answer that `CONST_ROADMAP_REFINE_NO_BLOCK_TEXTS` holds. In the stage reply, the key `premise_failed` was the one field whose filler changed the state of an item. Every other free-text field of the stage plan goes through `content_problems`, which calls the same `is_placeholder`, and a reply it refuses goes back to the model once. The design of #3394 records why that gate is the seam of the stage plan: the replay of the golden set and the job call it, and a schema error would stop the reply before the gate can name the problem. A second, schema-level check on the same fields would duplicate the gate and would rewrite the requirement "A plan text is no placeholder", which #3394 modifies.
- **Refine asks `chat_structured` for one retry (`max_retries=1`).**: `chat_structured` already sends the schema report back to the model. One retry matches the stage job (`_REPLY_RETURNS`) and the issue.
- **A placeholder failure is not item-caused, and it does not fail the round.**: `StructuredOutputValidationError.error_types` names the pydantic error types of the last reply. When all of them are `placeholder_text`, `RefineFailure.placeholder` is set. A placeholder failure is logged with the warning of every failed call and stays in `RefinePlan.failed_items`. It sets no mark on the item (the size guard of #1526 would settle the item as `edit` after two rounds), writes no comment, opens no question and sets no Status. `raise_for_failed_items` skips it, so the round succeeds and `FailureLedger` counts no failed round. A reply with a placeholder and another violation is a normal schema failure. The cost: the model sees the item again in the next round. A placeholder is a fault of the model and not of the item, so a new call may answer well.
- **The repair pass reads the same facts as `stop_clear`.**: An item is the Service's when it is open, holds Status New, the job record holds the same Status, no owner label of an agent or a person holds it, and no runner Job holds it. A person who changed the label or set an owner made the item theirs, and the pass leaves it.
- **A filler return is the newest comment of the item.**: The comment starts with the marker of the stage job and its `Evidence:` text is a placeholder by `is_placeholder`. A comment after it, from anyone, is a reply. The pass then leaves the item. The pass sets the Status Ready, because the stage job takes Ready items only.
- **A stub refine block is a refine section that holds a placeholder.**: The record names the next step `person`, the newest comment is a comment of refine, the section hash equals the recorded hash (no person edited it), and the problem statement or the existing-tool answer of the section is a placeholder. The pass writes the body without the section, then clears the refine block of the record: the hashes, the next step, the failed-body hash, the blockers, the paths and the split mark. The body goes first. A failure between the two writes leaves a body without a section, which refine reads as a new item. The other order would leave a section with no recorded hash, which refine reads as a person edit.
- **The pass follows the pattern of `devops roadmap inbox` and `return`.**: Without a flag it reads GitHub and lists the stalled items. `--confirm` writes. `--dry-run` makes no request and prints the requests of both modes, as the project rule asks (#412). The pass reads the open items once and the comments of each candidate that passes the cheap tests on the record. It does not call a model. Before it writes, it reads the item again and skips an item that changed.
- **The pass does not list the returns that say the premise holds (#3193, #3109, #3255).**: Only a text rule can find them, and no deterministic rule tells "the premise holds" from an evidence text. They are three items, and a person sets them back.

## Rejected alternatives

- **Gate `premise_failed` with a typed form that holds the false claim and a quote of a probe answer.**: #3109 quotes a probe line and states that the premise holds, so a quote check passes it. The form still trusts a claim of the model. `src/devops_cli/roadmap/stage_probe.py` already puts the probe answers in the plan context, so the plan can cite them in `feasibility`.
- **Keep the key and refuse only the filler words.**: #3193, #3109 and #3255 hold real sentences that state the opposite of a false premise. No word list finds them.
- **Apply `ReplyText` to every shared text type of the stage reply.**: The gate `content_problems` already refuses the same words with a retry, the replay of the golden set calls that gate, and #3394 extends it. Moving the check into the schema duplicates it and breaks the requirement that #3394 rewrites.
- **Let a placeholder reply settle the item as `edit`, like another schema failure.**: The item would wait for a body edit that its text does not need. That is the stall the repair pass clears.
- **Let the failed round count in `FailureLedger`.**: Three rounds with one placeholder item would suspend the whole refine row until its input changes.
- **Reset every New item.**: It would touch items that no filler stalled and items that a person set.
- **Read comments only.**: The record holds the Status that a job last set. Only the record tells a Status that a job set from a Status that a person set.
