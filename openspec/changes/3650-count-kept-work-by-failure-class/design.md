# Design

## Decisions

- **Reuse `devops_cli_service_implement_jobs_total` with the added label `class` and the results `continued`, `finished` and `blocked`.**: The counter of #3069 is in the tree at `docs/TELEMETRY.md:64`, and the issue forbids a second counter once that item has merged.
- **Keep the base increment of the counter for every reported runner Job, and narrow the kept-work requirement to the results `continued`, `finished` and `blocked`.**: The base requirement `Implement job outcome counter` reads `once for each runner Job that a round reports`, so the added requirement forbids the three kept-work results for an item with no kept work and leaves the base increment in force.
- **Keep the class of the stop in `implement.continued`, written by the clear rule of the Service.**: `src/devops_cli/roadmap/stop_clear.py:320:ImplementRecordKey.FAILURE: None,` removes the class at the clear, and the clear runs before the Job is created, so no later read of `implement.failure` can give the class of the continued stop.
- **Write `implement.continued` only when the record holds `implement.wip`, and write `none` there when the stop recorded no class.**: An item with no kept work must add none of the kept-work results, and the Service round holds no checkout to call `kept_commits`; `none` keeps a stop with no class countable.
- **Clear `implement.continued` in every report of a runner Job.**: The report is the last read of the run, so the next kept run counts its own continued Job and no report counts the same outcome twice.
- **Land the enum member, the row of `docs/ROADMAP_WORKFLOW.md` and the reader line of the record table in one group.**: `tests/invariants/test_roadmap_workflow_doc.py:158` and `tests/roadmap/implement/test_roadmap_implement_record_readers.py:72` each fail while the other side of the pair is missing.
- **Prime the class `none` and each failure class for the result `failed`, and `none` and each failure class for `continued`, `finished` and `blocked`.**: A reported Job that Failed without a stop counts `none`, and a stop counts its class, so both label sets exist before the first count.
- **Add the metric list as a new section at the end of `k8s/README.md`.**: `k8s/README.md:571:## Alerting` and the dashboards section are sliced by their headings in the tests, so a new trailing section changes no parsed text.
- **Name the Service counter in the module docstring of `src/devops_cli/telemetry/instruments.py`, in a group of its own, and change no other module.**: `tests/telemetry/test_telemetry_instruments.py:81` binds the `devops_cli_` prefix to that path, so the group that satisfies the registry rule edits the instruments module and nothing else.
- **Leave the fixed set of `class` values to the base requirement `The metric labels are classes of the taxonomy`, and keep the added requirement short.**: That base requirement already bounds the `class` values to the taxonomy, so the added requirement states the three results and the ban for an item with no kept work and stays under the length limit.

## Rejected alternatives

- **Read the class of the continued stop from `implement.failure` in `_create`, as the first plan did.**: `src/devops_cli/roadmap/stop_clear.py:320:ImplementRecordKey.FAILURE: None,` removes the class at the clear, and `src/devops_cli/roadmap/implement/implement_submit.py:573:stops = clear_stops(` runs before `src/devops_cli/roadmap/implement/implement_submit.py:604:created = _create(store, api, repo, plan.selected[0], label, size)`, so the record holds kept work and no class at `_create`.
- **Add a second counter `devops_cli_service_kept_work_total` as the refine block proposes.**: `docs/TELEMETRY.md:64` shows the counter of #3069 in the tree, so the condition of the issue for a fallback counter does not hold.
- **Forbid every increment of the jobs counter for an item with no kept work.**: `read_spec roadmap-implement-job/record` gave the base requirement, word for word: `The roadmap Service SHALL increment `devops_cli_service_implement_jobs_total` with the labels `repo`, `item_class` and `result` once for each runner Job that a round reports.` A ban on every increment for an item with no kept work contradicts that requirement.
- **Call `kept_commits` in the Service round to find the kept work on the item branch.**: `src/devops_cli/roadmap/implement/implement_submit.py:def _report` takes a store, a client of the cluster and the item, and the Service round runs no git command, so it holds no checkout of the item branch.
- **Count only the terminal outcomes `finished` and `blocked`.**: The first acceptance criterion asks for a test of `continued` when the next Job starts from kept work, so the counter has to hold that outcome.
- **Add the row of `implement.continued` to `docs/ROADMAP_WORKFLOW.md` in a later group, after the code.**: `tests/invariants/test_roadmap_workflow_doc.py:158:problems += [f"record key {key} is missing" for key in sorted(RECORD_KEYS - named_keys)]` fails while the enum holds a key that the page does not name, so the key and the row land in one group.
- **Leave `src/devops_cli/telemetry/instruments.py` untouched, because the Service series live in the config constants.**: `tests/telemetry/test_telemetry_instruments.py:81` binds the `devops_cli_` prefix to that path, and the archived gate rule reads `openspec/changes/archive/2026-11-07-3254-list-the-registry-and-ratchet-entries/specs/roadmap-stage/spec.md:4:MUST refuse a plan that adds a counted item and has no task whose text names the declared path.`

## Security

Nothing crosses a trust boundary: the change adds one label to a Service counter, adds one key to the job record and edits documents under `k8s/` and `docs/`. A person confirms that `k8s/README.md` and `docs/CLUSTER.md` list the counter with its label values and hold no secret, no internal host name and no private address, and that no label value holds an issue number. `uv run devops ci test tests/telemetry/test_service_counter_series.py` fails when a primed label value leaves the bounded set, `uv run devops ci test tests/roadmap/test_roadmap_stop_clear.py` fails when the clear stops keeping the class, and `uv run devops ci test tests/invariants/test_roadmap_workflow_doc.py` fails when the workflow page and the job record disagree.
