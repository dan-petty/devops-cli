# Proposal

## Why

The 2026-10-24 coverage audit of #2176 found 26 test files that cover no line of `src/` that another file does not also cover, and line coverage cannot show that such a file adds no check, because a file can assert something that no other file asserts. Mutation runs decide each file: a file that kills no mutant of its own adds no check. The table is the tree of b170358e, so the plan settles every row against this tree before it campaigns, and it keeps each test that no mutant can reach.

## What Changes

- Add a `## Mutation decisions` section to `docs/TESTING.md` with one row for each of the 26 table rows: the table path, the path now, one decision, the reason or the commit, the campaign command, the duration, the killed count and the keys of the own mutants.
- Add `tests/invariants/test_mutation_decisions.py` as the census of the 26 rows, list it in the invariant files of `docs/TESTING.md`, and let each campaign group add the check of its own rows.
- Point the mutation test selection of `pyproject.toml` at the modules of this tree, add `openspec` to its copy list, and check both in `tests/ci/test_ci_mutate.py`.
- Campaign the six AI client rows with the whole suite and again with each file left out, fill their rows, and remove the tests of each row with no own mutant.
- Campaign the toolsets row and the loopback row at the paths that hold their tests now, with all files of a row left out together.
- Campaign the three configuration rows, and move a case of `tests/commands/test_config.py` into `tests/config/test_config_key_removal.py` or `tests/config/test_config_file_that_is_not_yaml.py` only when the campaign gives that file no own mutant and no case of the target holds its rule.
- Campaign the four core, HTTP and Valkey rows and the three docs, benchmark and audit rows, settle each of them, and fill their rows.
- Keep the six rows and the four cases that no mutant can reach, and give each row the decision `unjudged`.
- Record the gate result, the total line coverage and the `fail_under` value in the record.
- Record the `Tests & Coverage` time of the pull request beside the mean of the job on `main`.
- The change fits one pull request.
