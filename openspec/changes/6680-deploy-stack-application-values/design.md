# Design

## Decisions
1. **The Application gives the values files.** `chart_sources(folders)` in `devops_cli.k8s.app_sources` gives, by the name of each Application, a `ChartSource`: the `targetRevision` of its chart source, the `helm.valueFiles` of that source in their order, and the sources of the Application with a `ref` (`ref_sources`). It replaces `chart_versions`, so the Applications are read once. An Application whose chart source pins no version has no entry, as before.
2. **The table holds no values file.** A row of `HELM_RELEASES_BY_STACK` gives the name, the chart and the namespace. `StackRelease.values` becomes `NotRequired`, as `version` is: `_release_at` sets both from the `ChartSource` of the release. A release with no entry stops the deploy with the error `chart_version_not_pinned`, as before.
3. **One `SourceTrees` for each deploy.** `deploy_stack` makes it after `_stack_roots`, in a `tempfile.TemporaryDirectory`, and holds the folder for the rest of the command. So a fetch happens in `_collect_deploy_targets`, before the deploy touches the cluster, and the fetched files stay until the Helm releases are installed. The origin is `repository_origin(env.repo)`, as in `collect_image_pins`. Issue #6681 can build the path sources with the same trees.
4. **A relative root gives relative values files.** `tree_at` keeps a relative root so a command prints relative paths. `EnvironmentTree.repo` is always resolved, so `SourceTrees` gets the checkout relative to the current folder when the root is relative (`os.path.relpath`). `--k8s-dir k8s` then gives `k8s/logging/loki-values.yaml`, as before.
5. **The dry run fetches nothing.** The root callback clears the dry-run state for the own `--dry-run` of a command. So `SourceTrees` gets the field `dry_run`, and `_fetch` only records its commands when the field or the state is on. `deploy_stack` gives it `dry_run or is_dry_run()`. The key `details.source_fetches` lists the recorded commands, so a person sees which repository and revision the real run fetches.
6. **A local read is no cluster call.** `repository_origin` starts `git config` with `local_read`, which the process runner runs also in a dry run. The tests that assert that a dry run, or a refusal before the cluster, starts no process leave out a local read: the stand-in `_Cluster` of `tests/commands/k8s/test_k8s.py` answers it with no record, the cluster fixture of `tests/commands/k8s/test_k8s_qdrant_security.py` answers a git local read itself, and the other tests filter `call.local_read`, as `tests/commands/test_global_dry_run.py` does.
7. **The product base gives no values file.** `--product-dir` names the manifests, the post-Helm files and the ConfigMap template of the product base. `_stack_roots` asks for the product base only for a stack with product manifests or post-Helm paths.
8. **Tests.** A new test of `tests/commands/k8s/test_k8s.py` writes a tree with the fixture Application `loki`: a chart source, an `infra` source at a tag and a `values` source of the origin. The test of the prometheus release gets an Application with two `$values` files. The tests of `tests/k8s/test_app_sources.py` test `chart_sources`. `release_values` of `tests/support/k8s_tree.py` reads the Application of a release, with a work folder of the caller.

## Rejected alternatives
- **Add the infra template to the table.** Rejected: the list of values files is then in two places, which is the problem of the issue.
- **Resolve the values files just before the Helm installs.** Rejected: a fetch failure would stop the deploy after the namespaces, the Secrets and the manifests are applied, and the dry run would read the sources at another step than the real run.
- **Read only the `values` ref with a string prefix.** Rejected: the `infra` ref names another repository, and `SourceTrees` already resolves any ref for `argocd_gate.py` and `image_pins.py`.
- **`helm --values <raw URL>`.** Rejected: a raw file URL fits only one forge, and a private repository needs a token in the URL.
- **A Click resource of the command context (`ctx.with_resource`).** Rejected: `devops k8s bootstrap` calls `deploy_stack` as a function (`src/devops_cli/commands/k8s/bootstrap.py:69`), with no Click context.
- **Set the dry-run state in `deploy_stack` (`set_dry_run`), as `devops k8s image-pins` does.** Rejected: the state stays on after the command returns. `test_llm_stack_applies_gateway_servicemonitor_after_helm_and_deletes_before_uninstall` calls the `k8s` group with no root callback, and its real deploy after a dry run then ran as a dry run and applied nothing.
- **Keep `--product-dir` for the values of the product base.** Rejected: Argo CD reads the second values file of `prometheus` from the `values` ref, and the issue asks for one place.
