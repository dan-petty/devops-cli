# Proposal

## Why

The project review works for one repository only: it reads one fixed tag ref, takes the functional change only from the OpenSpec facts, and asks lizard to read a Shell file that lizard cannot read. #4730 makes the review read the traits of each managed repository, record the reason of each skipped fact, take the functional change from a fallback source, and list the sections and the conditions of each repository of `service.repos` in a dry run.

## What Changes

- Read the review tag pattern from the review table of the roadmap file of the checkout, with the default `v*`, in `src/devops_cli/roadmap/project_profile.py`, and keep that default in a constant of `src/devops_cli/config/constants.py` beside `src/devops_cli/config/constants.py:3777:CONST_ROADMAP_IMPLEMENT_STEPS_FILE: Final[str] = ".devops/roadmap.toml"`.
- Accept the review table in the declaration of the roadmap file, so `resolve_profile` reads a repository file that holds it, in `src/devops_cli/roadmap/project_profile.py`.
- Give the tag read of `src/devops_cli/roadmap/project_review/git_read.py` and `src/devops_cli/roadmap/project_review/window.py` the pattern, and refuse a version window when no tag matches it, with a message that names `tag_pattern`.
- Name the pattern in the tag query of `src/devops_cli/roadmap/project_review/facts.py`, and pass it from `src/devops_cli/roadmap/project_review/review.py`.
- Add the functional change fact in `src/devops_cli/roadmap/project_review/functional.py`: the CHANGELOG sections first, then the feat and fix subjects, then the titles of the merged pull requests.
- Add the `listing.merged_titles` fact to `src/devops_cli/roadmap/project_review/catalog.yaml`, which gives those titles from the one listing read of the run.
- Record the functional change in `src/devops_cli/roadmap/project_review/review.py` after `lizard.complexity` and before the catalog facts, when the catalog result holds no ok fact whose id starts with `openspec.`.
- Skip the complexity rank in `src/devops_cli/roadmap/project_review/facts.py` when lizard reads no hot file, and keep the churn rank with the reason as the note.
- List each repository of `service.repos` in a dry run with no window, with the title of each section, the id of each fact, the reason of each fact whose setting is unset and the text of each other condition, from `src/devops_cli/roadmap/project_review/dispatch.py`.
- State the review tag pattern, the functional change fallback, the churn-only hotspots and the dry-run listing in `docs/ROADMAP_WORKFLOW.md`.
- The change fits one pull request.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `roadmap-project-review`: A version window needs a tag that matches the tag pattern, The functional change comes from the CHANGELOG without openspec, The functional change falls back to the commit subjects, The functional change falls back to the merged pull request titles, The complexity rank is skipped when lizard reads no hot file, The review writes the facts in a fixed order with the disagreements and the read counts, A dry run of the review starts no program
- `toolchain-preset`: The roadmap file holds a review table

## Existing Tool Considered

No open tool covers the need: git-cliff writes a changelog from commits and onefetch gives a repository summary, and neither gates a catalog condition on the traits of a repository, records a skipped reason, nor falls back from the CHANGELOG to the commit subjects and the merged pull request titles. Building it in the project review package costs about 80k tokens to build, keep and fix, and 1 day elapsed. It deletes no internal code.
