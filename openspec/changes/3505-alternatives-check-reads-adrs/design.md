# Design

## Decisions

- **Read the ADRs through the store, in `plan_alternatives`, once for a run and only when the run checks an item that is no skip class.**: `plan_alternatives(store, repo=...)` has no checkout, and the command `devops roadmap alternatives` takes no `--source`. The store already reads one file of the repository (`repository_file`), so a second method that lists one directory (`repository_files`) is the smallest addition. A run of skip-class items makes no model call, so it reads no ADR. The ADRs are the same for every item of a run, so one read serves up to `roadmap.alternatives.first_pass_limit` items: 1 listing and 17 file reads.
- **Send the title and the `Considered Options` section of each ADR, and nothing else.**: The rejection in the evidence ("Temporal and Hatchet: rejected.") is a bullet of that section, and every ADR of the project records its chosen and rejected tools there. The title states the decision in one line. The 17 ADRs hold about 64,000 tokens in all, and their options hold about 6,000.
- **Send the ADRs as one text under the key `decisions`, the highest number first, cut with `truncate_to_token_limit` to `CONST_ROADMAP_ALTERNATIVES_MAX_ADR_TOKENS` (8,192).**: A cut takes the end of the text, so the oldest ADRs go first. A newer ADR can supersede an older one. The key is left out when the repository has no ADR, so a repository with no `docs/adr/` sends the request of before this change.
- **Let the model name the ADR in the new reply key `adr`, and let the job confirm it.**: Whether a sentence rejects a tool is a judgment over free prose, and the model correlates better than a pattern does. The job then keeps the model honest: the number must be an ADR that the repository holds, and the title or the options of that ADR must name the tool. A reply that fails either test is refused, as a reply with a URL that no tool returned is refused, and the item is tried again after `roadmap.alternatives.retry_days`.
- **Add `rejected` and `in-use` to `Verdict`, and let only the job set them.**: The record, the counter `devops_cli_roadmap_alternatives_total` and the `alternatives` key of refine's request all carry the verdict, so two values reach each of them with no new field. The job refuses both from the model, as it refuses `not-applicable`.
- **Decide `in-use` with code: the last segment of the tool name (the name after `owner/` of a repository, or the PyPI package name) as a whole word in the title and the body of the item, with no case and with a space, `-`, `_` or `.` as one separator.**: This is the comparison that the issue asks for in `validate_reply`. A whole word keeps `pytest` from matching `pytest-cov`. The separator rule matches "Argo Workflows" to `argo-workflows`. The last segment alone is enough, because a URL or `owner/name` in a text holds it as a whole word too.
- **Read the text of the item outside the block of the check and outside the refine section.**: The block of the check names the tool of the earlier check, as the issue says. The refine section holds the open question "The alternatives check found that `<url>` covers this item", so it names the tool for the same reason. A rule that read it would turn each later `covers` check of an item into `in-use` and close a question that no person answered. `Item.body` holds no record block, so the record is no part of the text.
- **Give `rejected` priority over `in-use`, and apply both to `covers` and `partly`.**: An ADR is a fact about the project, and an item that names a rejected tool most likely names it to dismiss it. A `partly` verdict for a rejected tool, or a tool that the item uses, is as wrong for a person as a `covers` verdict, and it costs no branch: both go through `_TOOL_VERDICTS`.
- **Let a failed read of `docs/adr/` stop the run, and let a missing directory mean no ADR.**: A swallowed read error would bring back the unneeded questions with no sign. A missing directory is the normal state of a repository with no ADR, so `GitHubFileNotFoundError` is the one error the reader turns into an empty list. A rate-limit error already stops a run.
- **Write one line about the basis, in the comment and in the block: `Rejected by ADR 0008. A newer fact can change an ADR.` for `rejected`, and `The item already names this tool.` for `in-use`.**: The comment keeps the tool line with the URL, so a person can see the tool and the ADR number. The ADR number has four digits, as in the file name.
- **Change nothing in refine.**: `covers_question`, `_covering_tool` and `_needs_second_look` read the verdict `COVERS` only, so no question follows a `rejected` or `in-use` check. A test pins it. The prompt of refine names the two verdicts, so the model of refine reads them.

## Rejected alternatives

- **Decide `rejected` with code: a bullet of `Considered Options` that holds the tool name and the word "rejected".**: The ADRs word it in many ways ("rejected", "rejected for now", "not chosen", "rejected as above"), and a pattern over prose decides some of them wrongly. The job still checks the one fact that code can check, the tool name in the ADR.
- **Read the ADRs from a clone with `inspect_checkout` and `collect_context`, as refine does.**: The alternatives row has no clone and the command has no `--source`. Adding one turns the row into a clone job, which is a larger change than the issue names.
- **Send the full text of each ADR.**: The ADRs hold about 64,000 tokens, which is more than the window of a run.
- **Send the titles only.**: The title of ADR 0008 does not say that Temporal was rejected. The bullet does.
- **Let the model decide `in-use` too.**: The issue asks that code decide it where it can, and a model flag would still need the name test to be safe.
- **Match only a URL or `owner/name` in the text.**: The items of the evidence say "Grafana" and "notifications-engine's", and hold no URL, so none of the three cases would change.
- **Read the text outside the block of the check only, as `_request` does.**: It makes the refine question close itself (see the decision above).
- **Add a fuzzy-match library such as rapidfuzz.**: A fuzzy match would name a tool that the item does not name. A whole-word test needs `re` only.
- **Keep the ADRs in a cache between runs.**: The row runs about twice a day and the read costs 18 requests, so a cache adds an invalidation rule for no gain.

## Risks

- A tool whose name is also a common word (`just`, `task`) reads as in use when the item holds that word. The check still writes the tool, its facts and the line about the basis, so a person can see it. The test of the whole word and the exclusion of both blocks limit the cases to the words of a person's own text.
- The model may cite an ADR that does not reject the tool but names it, for example as the chosen one. The job confirms the name only, not the sense. The refused reply and the retry cover a wrong number. A wrong sense stays a model error that a person can see in the comment.
