# Design

## Decisions

- **The owner is a fifth field.** `ItemField.OWNER` has the values `Service`, `Agent` and `Human`. The label is the lower-case value after `owner/`, as for every field. So the store reads, writes and guards the family with the code that exists, and the job record names the last owner that a job set. A person who adds a label by hand with the label of another owner wins, because `field_values` gives a family with two labels the value that the record does not name. A person's claim in the web page of GitHub therefore works without the command.
- **One rule decides a claim.** `claim.py` has one check: a release is always allowed, a claim of a free item is allowed, a claim by the owner that holds the item changes nothing, and a `Human` claim takes an item that `Service` holds. Everything else is refused. `plan_claim` runs the check on the item as read, `apply_claim` reads the item again and runs it again, so a claim made between the two is refused and never reverted. A race between the read and the write is closed by `set_field`, which raises `RoadmapItemChangedError` when the owner changed.
- **Any actor may release.** A release clears the label whoever holds it. The tracker W7 and W10 show a stale claim, and a person decides. No job clears a claim of a person or an agent.
- **Both commands follow `roadmap return`.** They show a plan without `--confirm`, write with `--confirm`, and make no request with `--dry-run`. `claim` takes `--as agent|human` and has no `service` value: only the Service claims as the Service.
- **The command claims for the worktree, the function does not.** `add_worktree` is also called by the stage job and by the implement job. Only the command `worktrees add` claims, so a Job never claims an item as an agent. The claim runs after the worktree exists, so a refused claim never blocks work. Its result is two fields of `WorktreeAddReport`, `claimed` and `claim_error`, as the reclaim has `reclaim_error`. A warning prints in the table format only. A repository whose origin is not a GitHub repository, or whose issue is no item, gives a `claim_error` text.
- **The Service claims in the write that records the Job.** `_create` calls `set_field(OWNER, Service, marks={JOB: name, JOB_STATE: None})`, one request that already existed for the marks. If another owner holds the item then, or a person changes the owner between the read and the write, no Job is created and the round is not a failure. A failed create takes the claim and the record back in one write. `_report` takes `owner/service` off in the write that records `implement.job_state`. A release by the Service looks at the owner it reads now: a person's claim stays.
- **The job leaves a claimed item out in the judge.** The check is the second check of `implement` (after Status) and of `stage` (after the Status and split checks), because it reads the labels only. The reason is one message for both jobs: "It is claimed by agent." The `Service` owner never blocks: a Job whose item the Service claimed is the Service's own work, and a second Job for it cannot exist because the round waits for a running Job.
- **A Job ends at a group boundary.** `_ItemRun` reads the item before each unticked group and once after the last group, before the docs step and the push. If an agent or a person holds the item, it raises `_ClaimedError`. `_implement_item` catches it: it comments why, pushes nothing and opens no pull request, and leaves Status In Progress and the claim as they are. The passed groups stay in the local worktree, and the worktree is removed with the Job. The item is in the hands of its new owner, and a branch the job pushed earlier stays on `origin`. `ImplementApplied` gets `yielded` so that the output counts it.
- **`_report` does not stop a claimed item.** The Job leaves such an item In Progress, which `_settles_as_stop` reads as a stop that nobody wrote. With an owner other than the Service, the item is not a stop: the round comments the state of the Job and records it, and it sets no Status and no `implement.stopped`.
- **The labels file and its check.** The three labels go in the block "Roadmap Item Fields" after the Effort labels. A new test reads `.github/labels.yml` and asserts that it declares `field_label` of every value of every field. GitHub creates a label that a write names and the file does not declare, with a default color, so the test keeps the color and the description in step with the code.

## Rejected alternatives

- **GitHub assignees.** An assignee names a login. The three owners are kinds of actor, and the page "Assignees" of the REST documents describes assignees as people with push access. The Service acts as a GitHub App. It does not say that an App can be assigned. A label family is how ADR 0016 holds every other field, and the poll of ADR 0003 sees a label change.
- **A field in the job record only.** A person would have to run a command to claim, and the web page of GitHub could not claim. ADR 0016 keeps a field a person sets in a label.
- **A claim in `add_worktree`.** The stage and implement jobs call it, and they would claim items as agents.
- **A claim written by the stage job.** Stage runs in the Service in one round, changes a staging branch only and ends in minutes. The Job of the implement job is the long work that a person can meet, so only it claims.
- **Push the passed groups when a person claims the item.** The person now works on the branch. A push would put commits on it that the person did not ask for, and a new pull request would sit over their work. The issue says the Job opens no pull request over the work.
- **Set the item to Ready when the Job yields.** The Status of an item that a person works on is In Progress, and the Service takes no claimed item. A Ready status with a person's claim would send the item to the next round for nothing.
- **Fail the round when a claim races the Job creation.** A person's claim is the intended outcome, not a failure. A failed round counts toward the suspension of the row.
- **A refused claim by an agent of an item that a person holds, with a `--force`.** The owner decided one owner at a time. A person releases first.
