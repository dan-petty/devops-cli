# Design

## Decisions

- **Add row 16 `openspec` to `devops repos onboard`, after row 15.**: `src/devops_cli/github/onboard/run.py:62:ROW_NAMES: Final[dict[int, str]] = {` holds rows 0 to 15, and `src/devops_cli/github/onboard/run.py:246: run.put(15, lambda: rag_row(writer, ctx, settings))` is the last row, so row 16 is the next free number.
- **Add `MISSING` and `INVALID` to `src/devops_cli/github/onboard/model.py:class RowState` and count both as failing.**: `src/devops_cli/github/onboard/model.py:30:_FAILING_STATES: Final[frozenset[RowState]] = frozenset(` holds the states that make the command exit 1, so a repository without a valid OpenSpec setup needs its two states there.
- **Read the default branch only, and read `waiting` while the open template pull request holds the files.**: Criterion 1 of #3770 names the default branch, and `src/devops_cli/github/onboard/template_pr.py:216:def template_row(` records the head of the open pull request in `ctx.template_head`, so the row reports the merge that is pending and the command exits 0 in a confirm run.
- **Ship the project-neutral config as package data at `src/devops_cli/templates/openspec/config.yaml`.**: Criterion 3 names a template that devops-cli ships, and `src/devops_cli/templates/` is the home of the other templates of the package, so the file is reviewed as data and read at run time.
- **Merge the shipped OpenSpec files into the one template pull request of row 9.**: `src/devops_cli/github/onboard/template_pr.py:73:def _file_states(` adds only the files that the revision lacks, so the label rule of #3742 and the OpenSpec files share one pull request and no file is overwritten.
- **Read the config with `get_file_at` on `src/devops_cli/github/client.py:class GitHubClient`, not through the helper of #4629.**: `src/devops_cli/openspec/project.py:26:def uses_openspec(source: Path, ref: str, *, operation: str) -> bool:` takes a checkout of the repository and the onboard run has none, so the row reads `CONST_OPENSPEC_CONFIG_PATH` through the client and the helper stays the one switch of the stage and `devops pr create`.
- **Add `folder_entries_at` next to `src/devops_cli/github/client.py:677: def folder_names_at(self, repo: str, path: str, ref: str) -> tuple[str, ...]:` and answer a folder path in the fake repository.**: `src/devops_cli/github/client.py:650: def get_file_at(self, repo: str, path: str, ref: str) -> str | None:` gives None for a folder and `folder_names_at` lists folders only, so the specs path needs one read of all of its entries and the fake must answer it.
- **Prove the merged tree with a live test that runs the real pinned `openspec validate --specs --strict`.**: `tests/support/fakes/openspec.py:11:The record (`tests/fixtures/openspec_runs/recorded_runs.json`, made by` holds only the commands of the gate and of the archive, and a fixed answer would pass whatever the tree holds; `tests/openspec/test_openspec_contract.py:56:@pytest.mark.live("openspec")` lets the test start the pinned program.
- **Describe row 16 in `docs/repos/onboard.md`.**: `docs/repos/onboard.md:44:| Row | Name | What it does |` is the row table of the command, and the issue names `docs/roadmap/onboard.md`, which this tree does not hold.

## Rejected alternatives

- **Copy the OpenSpec config file of devops-cli into the target repository.**: `openspec/config.yaml:7:devops-cli is pre-1.0 alpha software` gives the planner of another repository the context of this project.
- **Write every OpenSpec file from devops-cli instead of the template pull request.**: `src/devops_cli/github/onboard/template_pr.py:73:def _file_states(` adds every missing template file in one commit and one pull request, so a second write path would open a second pull request.
- **Run `openspec init --tools <ids>` in a scratch checkout and copy the files that it writes.**: `src/devops_cli/github/onboard/template_pr.py:73:def _file_states(` already delivers the missing files in the one pull request, and a second copy of the init layout would drift from the pinned tool.
- **Replay the strict validation from the recorded runs of the OpenSpec fake.**: `tests/support/fakes/openspec.py:11:The record (`tests/fixtures/openspec_runs/recorded_runs.json`, made by` holds the commands of the gate and of the archive only, so a replay answers nothing about the merged tree.
- **Report `present` when the open template pull request holds the files.**: Criterion 1 of #3770 names the default branch, so the row would exit 0 while the default branch holds no config file.
- **Read the config only through the helper of #4629.**: `src/devops_cli/openspec/project.py:26:def uses_openspec(source: Path, ref: str, *, operation: str) -> bool:` takes a checkout of the repository, and the onboard command reads the GitHub API with no checkout.
- **Keep the generic template in the project kit of #3753 and ship nothing here.**: Criterion 3 of #3770 names a template that devops-cli ships, and #3753 is no dependency of the body, so the criterion would have no task.
