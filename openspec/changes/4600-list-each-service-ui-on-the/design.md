# Design

## Decisions

- **The `k8s` row of `devops ci` enforces the start page rule, and no test in `tests/invariants/` reads a manifest.**: `tests/invariants/test_k8s_manifests.py:5:and no test asserts a value of them (#6060).` reserves manifest-value assertions for the `k8s` row and kube-linter, and the rule needs the whole render of one application.
- **The rule is the pure function `start_page_problems` over documents in `src/devops_cli/k8s/start_page.py`, tested directly in `tests/k8s/test_start_page.py` and wired into `tests/gate/k8s_checks/start_page.py` with both product-base and negative-control checks.**: The product base holds no IngressRoute or Mattermost resource (`k8s/ingress/ingress-routes.yaml:488:kind: IngressRoute` sits in the frozen environment tree), so unit tests plus negative-control `check_*` functions (`tests/gate/k8s_checks/valkey_memory.py` precedent) prove failure modes in both `pytest` and `devops ci --check --only k8s`.
- **Each service UI carries the annotations on the object that routes its host: an Ingress, the Traefik IngressRoute, or the ingress block of the Mattermost resource.**: Homepage reads the annotations of the routing object, and `k8s/mattermost/mattermost.yaml:23:ingress:` shows that a Mattermost resource keeps its annotations under `spec.ingress` and not in `metadata.annotations`.
- **The five groups AI, Observability, Platform, Source Control and Collaboration are one closed constant.**: A free-form group lets a typo create a sixth group that hides the service, and the issue names the five groups; one constant makes group membership a single lookup.
- **The machine-endpoint list of this repository holds one member, the pair `(devops, roadmap-service)`.**: The product base holds one routing object, the webhook Ingress of `k8s/devops/roadmap-service/ingress.yaml:15:- host: hooks.example.com`, while the environment API and exporter routes belong to dan-petty/homelab.
- **A machine endpoint carries no `gethomepage.dev` annotation, and the check fails the object that carries one.**: The route of `devops/roadmap-service` is a webhook post on `k8s/devops/roadmap-service/ingress.yaml:18:- path: /webhooks/github`, so a tile would invite a person to a machine endpoint.
- **The rule counts each kind, namespace and name once and reads the first document of that key.**: `k8s/devops/kustomization.yaml:21:- roadmap-service` puts the roadmap Service Ingress in the homelab overlay render, and deploy-stack applies the same file (`k8s/devops/roadmap-service/ingress.yaml`), so a per-document count would report the same object twice.
- **The rule requires `{{HOMEPAGE_VAR_DOMAIN}}` in the `href` host and reads it as `example.com` before comparing against routed hosts.**: Committed manifests route `example.com` hosts (`k8s/mattermost/mattermost.yaml:25:host: mattermost.example.com`), while the live dashboard expands `{{HOMEPAGE_VAR_DOMAIN}}`; requiring the placeholder rejects hardcoded `example.com` or real hosts.
- **The contract goes into `k8s/README.md`, next to the description rule that already cites #4600.**: `k8s/README.md:649:A service with a Homepage UI takes its description from the` already states one annotation of this contract, and a Markdown file under `k8s` passes the freeze (`tests/gate/k8s_checks/environment_freeze.py:44:and file.suffix != _DOCUMENT_SUFFIX`).
- **The rule of the row is written as two added requirements, one for opt-in and machine endpoints and one for the group set, link host and deduplication.**: Combining all clauses in one requirement exceeded the 500-character limit; splitting across two added requirements keeps each well under 500 characters while preserving every scenario detail.
- **The 11 annotations, the environment API/exporter list entries, and checks over environment objects go to dan-petty/homelab, and the live tile check stays #7101.**: `tests/gate/k8s_checks/environment_freeze.py:73:in a pull request of dan-petty/homelab, and remove it from this branch. Step 17 deletes` and `docs/adr/0039-homepage-is-the-cluster-start-page.md:33:live in dan-petty/homelab, because environment manifests moved out of this repository.` place the start page deployment and environment manifests in dan-petty/homelab, and a live rendered tile needs a cluster sync and a running pod.

## Rejected alternatives

- **Reuse `_host_fields` in `src/devops_cli/k8s/argocd_overrides.py` instead of adding `start_page_routed_hosts`.**: `src/devops_cli/k8s/argocd_overrides.py:147:def _host_fields(doc: dict[str, Any]) -> list[tuple[str, str]]:` yields JSON-pointer pairs across `ConfigMap`, `Deployment`, `tls` and raw Traefik `match` expressions rather than parsed routed hostnames, and step 15 deletes that module (`docs/HOMELAB_REPO_SWITCH.md:254:delete the override path of #1290:`).
- **A pytest test in `tests/invariants/` that reads every Ingress, IngressRoute and Mattermost resource.**: `tests/invariants/test_k8s_manifests.py:5:and no test asserts a value of them (#6060).` reserves manifest-value assertions for the `k8s` row and kube-linter.
- **A kube-linter custom check.**: kube-linter inspects one manifest at a time, whereas comparing an `href` host to routed hosts across a render requires `tests/gate/k8s_render.py:83:def applied_documents(path: Path) -> list[dict[str, Any]]:`.
- **A central Homepage services file.**: It duplicates routing from `k8s/ingress/ingress-routes.yaml:488:kind: IngressRoute` and lets a new Ingress show without opting in, which is the problem of #4600.
- **A free-form group for each service.**: A typo creates a sixth group and hides the service; `k8s/README.md:649:A service with a Homepage UI takes its description from the` shows that this cluster documents the contract as one closed list.
- **Read the group list from the Homepage deployment layout.**: That layout lives in dan-petty/homelab (`tests/gate/k8s_checks/environment_freeze.py:67:is an environment path, and dan-petty/homelab holds the environment.`), so an offline check in this repository could not read it.
- **A default opt-out for every routing object.**: A new service UI would stay hidden and no check would catch it.
- **List the roadmap Service with the other services.**: Its only route is a webhook post on `k8s/devops/roadmap-service/ingress.yaml:18:- path: /webhooks/github`, so a tile would invite a person to a machine endpoint.
- **Treat each document as a separate object.**: `k8s/devops/kustomization.yaml:21:- roadmap-service` places the Ingress in the overlay render, and deploy-stack applies the same file (`k8s/devops/roadmap-service/ingress.yaml`), so a per-document count would fail on duplicates.
- **Compare the literal domain placeholder without requiring or normalizing it.**: Committed routes use `example.com` (`k8s/mattermost/mattermost.yaml:25:host: mattermost.example.com`), while unnormalized placeholders never match and unrequired placeholders allow hardcoded domains.
- **Require the live tile check in this item.**: A rendered tile needs a live cluster, a Homepage sync and a running pod, tracked in open issue #7101.
- **Add the 11 annotations to the manifests of this repository.**: `tests/gate/k8s_checks/environment_freeze.py:67:is an environment path, and dan-petty/homelab holds the environment.` fails the `k8s` row on any branch editing `k8s/ingress/ingress-routes.yaml` or `k8s/mattermost/mattermost.yaml`.
- **Run the rule only on committed product-base manifests in `tests/gate/k8s_checks/` with no unit tests or negative controls.**: The product base contains one machine-endpoint Ingress and no IngressRoute or Mattermost resource (`k8s/ingress/ingress-routes.yaml:488:kind: IngressRoute`), leaving every opt-in, group, host and Mattermost branch untested.
- **Keep the whole rule in one added requirement and drop details to fit 500 characters.**: Squeezing all clauses near the 500-character cap leaves no room for clarification; two added requirements keep each rule concise and unambiguous.

## Security

The change adds an enforcement rule for routing objects on the cluster start page and updates `k8s/README.md`. The trust boundary is the tile list shown to operators: a tile on the roadmap Service webhook Ingress would invite callers to a machine endpoint, and an unvalidated `href` or hardcoded real host would misdirect operators or leak environment hostnames. Reviewers must confirm that the webhook route remains excluded and that `href` examples and rules enforce `{{HOMEPAGE_VAR_DOMAIN}}`. `uv run devops ci --check --only k8s` fails if `devops/roadmap-service` opts in or if negative-control Ingress checks break, and `uv run devops ci test tests/k8s/test_start_page.py` fails if `start_page_problems` accepts an unlisted non-opted-in object, a machine endpoint opt-in, an unknown group, a non-placeholder `href` or an unrouted link host.
