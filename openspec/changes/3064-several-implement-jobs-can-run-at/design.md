# Design

## Decisions

- **The round counts the running Jobs of its repository against the new setting, as the stage row counts its own.**: `src/devops_cli/roadmap/stage/stage_submit.py:359` already subtracts running Jobs from a setting and plans with the difference, so the implement row follows a standard Service rule.
- **The limit is per repository, not global.**: `src/devops_cli/roadmap/run.py:820` runs the round for one repository and the Service runs one status-lane worker per repository. A global count would need a store and a clone for every repository in one round.
- **The conflict predicate includes capability specs and generated docs alongside `Changes:` paths.**: Implement Jobs run `devops docs generate` and `openspec archive`, which update generated docs and `openspec/specs/<capability>/spec.md`. Including these in the change set ensures parallel items never conflict at merge.
- **Filter running items before applying free slots.**: Planning with `limit=slots` can pick an In Progress item currently held by a running Job and then skip it, starving an available slot. The round plans with `limit`, discards items whose label matches a running Job, and then takes the first `slots` non-conflicting targets.
- **Enforce per-job request budget and model lane limits.**: Each runner Job sets `set_model_call_limit(1)` and installs a `RequestBudget` on its GitHub session. The round checks budget availability before creating Jobs.
- **Check cluster resources by requiring no running runner pod is Pending.**: The round inspects active Jobs: if any runner Job is `Pending` (`job.started is None`), or if the API server refuses creation, the round pauses new creates and leaves items for the next sweep.
- **The runner Job carries the item label beside the repository label.**: `src/devops_cli/k8s/cluster_job.py:40` gives the item label that the stage round reads, and ADR 0021 finds a unit of work by its labels.
- **`SubmitResult.created` holds a tuple of Job names.**: The round logs all created Job names in `src/devops_cli/roadmap/run.py`.
- **The merge proof runs real git through `git_for_real` in `tests/roadmap/implement/test_implement_parallel.py`.**: The implement test suite already answers git with `git_for_real`. Placing tests in the module that mirrors `implement_parallel.py` complies with `docs/TESTING.md:92`.
- **The generated settings documents get their own group.**: `docs/ENV_VARS.md` and `docs/CONFIGURATION.md` are regenerated by `uv run devops docs generate` after the setting field exists.

## Rejected alternatives

- **Disjoint `Changes:` paths alone without capability specs.**: Two items with disjoint code paths that touch the same capability spec will conflict during `openspec archive` on merge (#4622).
- **Plan with `limit=slots` before filtering held items.**: An In Progress item held by a running Job consumes a slot and gets skipped, leaving free slots unused.
- **Adopt Hatchet for the scheduler.**: Hatchet does not read plans, does not compute disjoint file sets, and has no native GitHub request budget or model lane semantics.
- **Keep the repository-wide single-Job lock and add the setting alone.**: `src/devops_cli/roadmap/implement/implement_submit.py:546` returns `waiting` while any Job of the repository runs, so a second slot would never fill.
- **Drop cluster resource checks without an owner decision.**: Dropping checks violates AGENTS.md rule 2. Bounding creation when pods are Pending provides an active cluster check.
- **Replay recorded git transcripts for the merge proof.**: `git_for_real` is simpler, reliable, and tests git behavior directly on actual paths.

## Security

Crossing: one round of the Service now asks the Kubernetes API for up to `roadmap.implement.max_parallel_jobs` runner Jobs in namespace `devops` instead of one. Each Job holds a GitHub installation token that names one repository. The Service adds no RBAC rule and reads no nodes. The runner pod keeps `readOnlyRootFilesystem: true`, `runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]` and `seccompProfile: RuntimeDefault`.
