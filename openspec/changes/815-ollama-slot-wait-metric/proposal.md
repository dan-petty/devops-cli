# Proposal

## Why

Issue #815: a call to Ollama waits in the process for a slot on one of its nodes. `acquire_ollama_slot` (`src/devops_cli/ai/client/network.py`) queues the calls by priority: a `high` call goes first, a `normal` call waits while a `high` call waits, and an `as_available` call waits while any other call waits and leaves one slot free. No metric records this wait. A slow call that queued in the process looks like a slow reply from the model, and nobody can see whether the priority order starves the `normal` and `as_available` calls.

The lease and queue counts are module state of one process (`active_ollama_requests`, `waiting_priority_requests`). Each `devops` command is a short-lived process, so a gauge of these counts would hold only the last process's value. The wait of each call is data of that call, and a histogram sends it as a delta that the collector adds up across processes.

## What Changes

- Add the histogram `devops_cli_ai_ollama_slot_wait_seconds` to `INSTRUMENTS` (`src/devops_cli/telemetry/instruments.py`), labelled by `priority` (`high`, `normal` or `as_available`) and `outcome` (`ok` or `timeout`).
- `acquire_ollama_slot` observes the wait of each call once, through `emit`: when it holds a slot, with outcome `ok`, and when its deadline passes with no slot, with outcome `timeout`. A call that finds a free slot observes a wait of about 0 s, so the quantiles cover all calls.
- Add the panel "Ollama Slot Wait by Priority (p95)" to `k8s/monitoring/dashboards/ai-spend.json`. It charts the p95 wait by priority, and the timeout share by priority.
- `docs/TELEMETRY.md` names the new histogram and says what its wait covers (generated by `devops docs generate --sync-readme`).
- The change carries a spec delta, because a metric and a dashboard panel are observable. It creates the capability `llm-slot-wait`.
- No panel shows lease counts or queue lengths. They are per-process state, and #815 keeps them out.
- This change fits in one pull request.

## Capabilities

### New Capabilities

- `llm-slot-wait`: the wait of an LLM call for an Ollama slot in the process, as a histogram by priority and outcome, and its dashboard panel.

### Modified Capabilities

None.

## Impact

- Code: `src/devops_cli/ai/client/network.py`, `src/devops_cli/telemetry/instruments.py`, `src/devops_cli/docs/generator.py`.
- Dashboard: `k8s/monitoring/dashboards/ai-spend.json`. Argo CD applies it after the merge.
- Tests: `tests/test_ollama_dynamic_leasing.py`, `tests/test_telemetry_instruments.py`.
- Docs: `docs/TELEMETRY.md`.
- Metric volume: one histogram point for each priority and outcome that occurs in a flush, so at most six series.

## Feasibility

Checked on 2026-10-28 against `origin/main` at bb46660c.

- `acquire_ollama_slot` and `_wait_for_slot` in `src/devops_cli/ai/client/network.py` queue the calls by `RequestPriority` (`high`, `normal`, `as_available`; `src/devops_cli/ai/client/models.py`). `OllamaClient._ollama_messages` and its stream variant (`src/devops_cli/ai/client/ollama.py`) take the slot for each attempt, and `track_ollama_url` takes it for a single URL.
- No metric records this wait. `grep -rn slot_wait src/` finds only `devops_cli_ai_gateway_slot_wait_seconds`, which `_wait_for_gateway_slot` sends for the gateway's `BoundedSemaphore`. That semaphore has no priority, so its histogram has no `priority` label.
- `get_ollama_active_leases` and `get_ollama_waiting_counts` have no caller in `src/` other than the exports of `devops_cli.ai.client`. The issue's statement holds.
- `emit` (`src/devops_cli/telemetry/instruments.py`) sends a histogram as an exponential delta, which Prometheus stores as a native histogram that `histogram_quantile` reads (#792). `tests/test_telemetry_instruments.py` checks every query of `ai-spend.json` against `INSTRUMENTS`.

## Existing Tool Considered

OpenTelemetry's histogram instrument, through the client that devops-cli already uses (`OTelTelemetryClient`), and Grafana's `histogram_quantile` over a Prometheus native histogram cover the need. The change adds one instrument entry, one observation in the slot code and one panel. It builds no tool and deletes no internal code.
