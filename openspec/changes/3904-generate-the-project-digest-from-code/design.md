# Design

## Decisions

- **Build the digest at run time as one JSON object with sections for commands, settings, pins, architecture and decisions, and expose it as a model tool and as a knowledge base index section.**: It keeps each owner authoritative and gives exact facts, where a committed Markdown file drifts and repeats typed facts.
- **Read the command list from `introspect_all_groups` of `src/devops_cli/docs/generator.py:418:def introspect_all_groups(self, force: bool = False) -> list[CommandGroupDoc]:` and project it with `command_facts`.**: The docs generator already returns each group and command with its help text, so the digest walks the Typer tree no second time.
- **Extract the traversal of the settings model out of `generate_configuration_docs` into `iter_settings_fields`, and let the digest project it into `settings_sections`.**: `src/devops_cli/docs/generator.py:812:section_val = getattr(settings, section_key, None)` shows that the Default column of the page is a value resolved from a live settings object, which is configuration and must not enter a model's context; the traversal of the model is shared and the resolution stays in the page.
- **Read each pin through `read_inventory` of `src/devops_cli/research/inventory.py`, and name the file that holds each pin.**: The inventory readers already parse the manifest, the uv lock and the tools lock, and the installed set can differ from the lock.
- **Take the module paths from `generate_repo_map`, the edges from `build_import_graph`, and each decision's title and status from `read_record_texts` and `adr_of`.**: Each of those owners exists already, and a hand-written architecture section drifts from the import graph.
- **Pass `max_files` equal to the count of the Python modules under `src/` when the digest calls `generate_repo_map`.**: `src/devops_cli/config/defaults.py:629:DEFAULT_REPOMAP_MAX_FILES: int = 100` is below the module count, so the default would leave modules out of the section.
- **Read the head commit with `run_subprocess` of `src/devops_cli/core/process.py`, and take the commit as an argument of `build_project_digest`.**: The project starts every process through that seam, and an argument keeps the hash test free of a repository and of a double.
- **Hold each settings field's name, its annotation, and the model's own default or the name of its default factory, never a resolved value.**: A default is code and a resolved value is configuration, so no runtime value enters the digest or a model's context; a field whose default comes from `default_factory` has no model default, so the entry names the factory instead.
- **Hold only the section names in the knowledge base index section, not the digest body, the hash or the commit.**: The docs check compares the committed page with its generator on each commit, so a page that holds a hash or a commit would fail that check on every change.
- **Keep the argv lines of `src/devops_cli/ai/knowledge_base/devops_cli/cli_command_reference.md` and remove its typed Purpose and Primary Flags columns.**: `tests/docs/test_docs_inventory.py:186:cli_reference_lines >= 60,` needs at least 60 argv lines, and `devops docs check` resolves only those lines; the Purpose and Flags text is typed and drifts, which is why the issue names the page.
- **Move each claim that no owner generates once into `AGENTS.md`, and list each move for the pull request comment.**: The claim keeps a single owner and never returns to the knowledge base as a typed fact.
- **Leave `src/devops_cli/ai/knowledge_base/README.md` unchanged.**: It lists the page names and the categories of the knowledge base only, and holds no fact that the digest owns.
- **Build and test the digest against fixed fixtures, independent of the retrieval gold set of the knowledge base.**: The digest build reads files and code, and the gold set measures retrieval quality after the digest exists.

## Rejected alternatives

- **A committed Markdown digest file that a person regenerates.**: It drifts and repeats typed facts: the audit of 2026-11-07 found the settings table short of the model and a coverage floor of 90 against 85.
- **A vector-only entry in the retrieval index with no tool and no exact record.**: It hides exact facts and the content hash, and the item requires both a content hash and the commit.
- **Parse the command reference for the command list.**: The command reference is generated from the command tree and is one of the pages that drift, so the tree is the owner.
- **Parse the settings table of the knowledge base for the settings list.**: The table covers a fraction of the settings model, so it cannot be the owner.
- **Read the installed packages instead of the lock files.**: The installed set can differ from the lock, and the item requires a digest version to equal the lock.
- **Reuse the Default column values that `generate_configuration_docs` resolves for the settings section of the digest.**: `src/devops_cli/docs/generator.py:812:section_val = getattr(settings, section_key, None)` and `src/devops_cli/docs/generator.py:840:getattr(section_val, field_name, None),` show that the column holds a live value, so the digest would carry a value of the machine it ran on and the plan's security rule forbids a resolved value in a model's context.
- **Write a second reader of the project manifest, the uv lock and the tools lock inside the digest module.**: `src/devops_cli/research/inventory.py:32:def read_inventory(root: Path) -> Inventory:` already joins the python pins and the tool pins, so a second reader repeats the parse that the inventory owns.
- **Derive each import edge in the digest from the imports of the mapped modules.**: `src/devops_cli/core/import_graph.py:146:def build_import_graph(` already builds the edges from the parsed trees, and a second derivation would disagree with it.
- **Walk the Typer tree inside the digest module, as the command matrix of the docs generator does.**: `src/devops_cli/docs/generator.py:418:def introspect_all_groups(self, force: bool = False) -> list[CommandGroupDoc]:` already returns each group and command.
- **Start git with a bare `subprocess.run` in `head_commit`.**: The project reads a process through `src/devops_cli/core/process.py:1153:def run_subprocess(`, and an invariant test refuses a module that starts git another way.
- **Strip the command table from the command reference page.**: `tests/docs/test_docs_inventory.py:186:cli_reference_lines >= 60,` requires the documented command lines of that page, so the plan keeps the argv column and removes the typed columns instead.
- **Keep the typed Purpose and Flags columns of the command reference page because a test reads the page.**: That test resolves only the argv lines, so the typed columns can drift; the issue names the page as one of the drifting files.
- **Put the digest body in `docs/KNOWLEDGE_BASE.md`.**: `src/devops_cli/docs/generator.py:1420:if actual_content != expected_content:` makes the docs check refuse a page that is not the output of its generator, and a body that holds the commit SHA would fail on the next commit.
- **Add a `devops docs` subcommand that prints the digest.**: The item asks that a model reads the digest in the index or through a tool, so the tool and the index section cover the need and no command is added.
- **Block the digest on the gold set of the knowledge base retrieval test.**: The digest build reads files and code and needs no retrieval score, so it stays workable and the gold set stays a later measure.

## Security

The digest crosses a trust boundary: it copies each settings field's name, annotation and model default or factory name, and each declared pin, into a model's context. A person must confirm that the settings section holds no resolved value and no credential, and that a pin entry holds only the name, the version and the file of a lock. The digest test fails when a settings entry carries a resolved value instead of the model's own default or its factory name, and when a pin names a file that no reader parsed.
