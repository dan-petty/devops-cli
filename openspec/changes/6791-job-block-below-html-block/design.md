# Design

## Decisions

- **A job block marker line in an HTML block that only a blank line ends ends that block for a read.**: CommonMark reads the lines of such a block as raw HTML. GitHub then shows the marker as a comment, as it shows a marker block of its own. So a person cannot quote a marker there as text that GitHub shows. A person makes this form with an edit that removes the blank line above a marker. A fence and an HTML block of kinds 1 to 5 end at an end text, and their marker lines stay quotes, as before (#6736).
- **The first such line after the first line of the block ends it, not only the last line.**: Each job writes text directly below its start marker. Refine writes the `checked-at` line and `## Proposed design`, and the alternatives job writes its result line. CommonMark keeps these lines in the HTML block up to the next blank line, so the start marker is a middle line of the block. A scratch script on `c7e40970d` tried the rule of the last line only, the form of a comment that the marker ends (#6720). For `</details>` and `<div>x</div>` above each job block, it found no block: it found only the end marker. A lone end marker that bounds stops the alternatives write.
- **The rule goes in `_parts`, so each reader uses it.**: `_parts` already starts a new part at a marker line that ends an open block (#6736). `_html_block_end` gives one more such line. `block_marker_spans`, `job_block_bounds`, `extract_section_and_outside` and `close_blocks_before_markers` read the parts, and `body_dependencies` and `closed_body` read the closed body. So no reader gets a second rule.
- **The part before the line keeps its tokens up to the HTML block only.**: The tokens of a part are the tokens of the text from its start to the end of the body. An open block runs to the end of the body, so it is the last token of its part. An HTML block of kind 6 or 7 ends before the end of the body, so the tokens after it are also tokens of the new part. Without the cut, `_spans` reads each later marker two times.
- **`block_marker_of` does not change.**: The new part starts at the marker line, so CommonMark parses the marker there as an HTML block of its own. A token test for a line in an HTML block of kind 6 or 7 would read the marker a second time in the part before.
- **Only a top-level HTML block ends at a marker line.**: The jobs write their blocks and the record at the top level. A new part starts at the start of a line, so a cut in a list item or a quote would break that container. `_open_block` also reads only the last top-level token (#6736).
- **A marker line in such a block bounds also with no partner.**: A marker block of its own with no partner bounds too, and stops the alternatives write (#6627). On 2026-11-23, no open issue body held a marker line in such a block.
- **The writers put a blank line before the marker line.**: `_closed` writes the close of each part that ends before a new part, then a blank line. `close_open_block` gives no close for these kinds, so only the blank line is new. CommonMark then ends the HTML block at the blank line. The text of the person keeps its rendered form, because an HTML block renders as its own text.
- **`ends_at_a_blank_line` tells the kinds by `_HTML_BLOCK_CLOSES`.**: The table holds the end text of kinds 1 to 5 by the start of their first line. Each other HTML block that the parser gives is of kind 6 or 7. So the function copies no list of the block tags of CommonMark.
- **The record line on the last line of such a block reads as the record.**: `split_record` already parsed the body, and the last top-level block is the HTML block that holds the record line. `ends_at_a_blank_line` of that block decides with no new parse. The probe of `close_open_block` runs only for the other kinds, as before (#6785). A body that does not hold the record opener is not parsed (#4445), and a body whose last block is the record gets one parse. On 2026-11-23, `split_record` over the 833 open issue bodies took 0.865 s on the base and 0.871 s with this change (least CPU time of 10 runs). A second run put `<details>` directly above each of the 831 records. The change read each record in 0.98 s, and the base read none in 2.81 s (median wall time of 10 runs).
- **The read keeps the line break before the record line.**: No separator of the writer is there to take out. The next write (`with_record`) adds a blank line, so the record is then an HTML block of its own. The next read then gives the same body, so the lost-edit checks of the GitHub store see no change (#6729).
- **A quote of the record with a JSON object in such a block reads as the record.**: GitHub shows the line as a comment, so a person sees no quote. A quote in an open block reads the same way (#6785).
- **The cap on the parts does not change.**: A new part starts at a marker line, and no block of that part holds its first line. So each marker line ends one block at most, and a body with one block for each job has five parts at most. A body with more marker lines in such blocks keeps the later lines in their blocks.
- **`CONST_ROADMAP_REFINE_RULES_SINCE` does not move.**: The change can change the blockers that `body_dependencies` reads. A live check read the 833 open issue bodies of 2026-11-23 with the base and with this change. It found no difference in the records, the refine sections, the alternatives blocks, the blockers and the body hashes. So no item gets another model round. A second run put `<div>x</div>` directly above the start marker of each of the 783 refine sections. The change found each section, and the base found none.

## Rejected alternatives

- **Bound a marker on the last line of such a block only, as on the last line of a comment.**: The start marker of each job is a middle line of the block, so the read finds no block. The scratch script above gave `job_block_bounds` None and only the end marker for each job block.
- **Read each marker line in such a block as a bound in `block_marker_of`, and make no new part.**: The read then finds the block, but `close_blocks_before_markers` writes no blank line. The lines of the job below the marker stay raw HTML, so GitHub shows `## Proposed design` as plain text, and the next read again needs the rule.
- **Write a list of the block tags of kinds 6 and 7.**: That list copies CommonMark (AGENTS.md rule 3). `_HTML_BLOCK_CLOSES` already tells the other kinds.
- **Put a blank line before each block in each writer, and keep the readers.**: Each writer already puts a blank line before its block. The defect is the edit of a person after the write, so only the read can find the block.
- **Read the record with `_parts` of `body_hash.py`.**: The record is no job block, and `_parts` parses each part again, so each body of a listing would cost more parses. #6785 rejected this for the same reason.
