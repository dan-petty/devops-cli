# Design

## Decisions

- **One module of orchestration, the node steps of the apply.** `infra/node_run.py` runs the operations with `Cluster` of `infra/nodes.py`, the same code as `devops infra apply`: the health gate, the drain check, the drain bound, the workloads that only the node can run, the drain, the uncordon and the waits. It adds no second drain.
- **The hosts come from the default branch at origin.** The commands read the inventory as `devops infra status` does (`default_branch_tree`), because there is no plan record whose commit they could use. The ad-hoc tasks run in the same export, so they get the `ansible.cfg` and the inventory of that commit. A host that is not in the inventory, or is in the group of hosts out of service, is refused before a node changes.
- **The levels.** `uncordon` needs `safe`; `drain`, `restart` and `reboot` need `full`, because each takes a host out of service. The description of `infra.repos[].agent_access` and SECURITY.md give these levels.
- **`--force` only from a person.** The issue says "no `--force` unless a person gives it". `kubectl drain --force` deletes a pod that no controller owns, and the pod does not come back. An agent that gives `--force` is refused before any process starts, so an agent drain stops at such a pod, and a person decides. `--force` goes to the drain check too, so the check gives the result of the drain.
- **The drain bound of the apply.** `Cluster.drain_bound`: `infra.drain_timeout_seconds`, or the longest grace period of a pod that the drain evicts and 60 s. A fixed bound stops a drain that goes as it should (the live apply of #5125 showed a pod with a grace period of 660 s).
- **The unit comes from Ansible.** `devops_infra_node_service` is a template in dan-petty/homelab. The command reads the raw value from `ansible-inventory --list`: a host with no value is refused at once, with no process of the cluster or the hosts. A plain value is the unit. A template is rendered with one ad-hoc `ansible.builtin.debug msg={{ devops_infra_node_service }}` task for all such hosts, before the first drain; `debug` runs on the controller and opens no SSH connection. A unit name that is not a systemd unit name (letters, digits and `:_.@-`) is refused, so the value cannot add a module argument.
- **The restart waits for the unit in its task.** `systemctl restart` returns when the unit started; the k3s units are `Type=notify`, so a unit that does not start fails the task. The kubelet of k3s posts Ready only while the unit runs, so the wait for Ready follows. A separate SSH read of the unit adds a connection and no fact; the apply of #5125 made the same decision.
- **The reboot waits for a new boot.** `ansible.builtin.reboot` returns when the host answers with a new boot time. The node can still give the status of before the reboot to the API server for some seconds, so the wait for Ready also needs a boot ID other than the one before the drain. The kernel before and after comes from `nodeInfo.kernelVersion` of the node reads, with no SSH read.
- **The GPUs.** The wait for Ready needs the allocatable GPU count of before (`Cluster.wait_ready`), as the apply does.
- **The health gate before each host, the health wait after.** Before the drain of each host, one read of the gate: every node in service is Ready with no pressure, and no critical alert fires when `prometheus.url` is set. After the uncordon (or the change of a cordoned node), the waits of the apply: the nodes, then the alerts. The issue puts the health gate after the uncordon. The wait for Ready of the node of the host comes before the uncordon, so the command does not uncordon a node that is not Ready.
- **Refused and stopped.** A guard before the hosts, the health gate before the first host and a drain check that fails before the first change give `refused`: no node changed. A step that fails after the first drain or uncordon gives `stopped`. The command prints the report and exits 1 for both. A guard that stops the run before the first host raises its error after the audit record.
- **Become for the tasks that change a host.** The restart and the reboot run with `--become`, because both need root; the debug task runs with `ansible_become=false`, as the ping does. The SSH key is the key of `devops ssh`, and host key checks stay on.
- **Bounds.** The restart task has `--task-timeout 300`, and the reboot task `reboot_timeout=600`. The process bound of each is its task bound and 120 s, so Ansible stops first and writes its result.
- **One audit record for each run.** The record names the operation, the caller and its tool, the level, the repo, the commit of the inventory, the given hosts, `--force` and the result, and for each host its node, unit, outcome, step, reason, cordon state and kernel before and after, and the workloads that were down while it was cordoned. The counter `devops_cli_infra_runs_total` gets the command `node <operation>`: the counter already divides runs by command, and a second counter doubles the dashboard and alert rules.
- **The runner artifacts go away.** The ad-hoc tasks write their artifacts to a private temporary folder that is removed after the read of the job events, as the ping does. The report and the audit record hold the reason of a failed task.
- **No question.** The commands ask no question, as `kubectl drain` asks none. The level stops an agent error, and a person runs the command to change the node.

## Rejected alternatives

- **All four at `full`.** It refuses an uncordon that an agent at `safe` may do; the setting description gives `safe` the uncordon.
- **All four at `safe`.** A drain takes a host out of service, and the owner decision gives that to `full`.
- **A generated playbook through `devops infra plan` and `apply`.** A plan records a check-mode run of a playbook of the infra repo. These commands change one unit or reboot one host, and one ad-hoc task needs no playbook in the repo.
- **ssh and systemctl from the CLI.** It bypasses the inventory, the `ansible.cfg` and the connection settings of the infra repo.
- **A fixed `--timeout 300s` for the drain, or no timeout.** A fixed bound differs from the apply and ignores the setting; with no bound, a PodDisruptionBudget can block a drain forever, and the first-failure stop never comes.
- **A `--force` that an agent may give.** It deletes the pods that no controller owns with no person in the loop; see the decision above.
- **The raw inventory value of `devops_infra_node_service`.** It is a template in dan-petty/homelab, so the raw value is not a unit name.
- **An SSH read of `uname -r` for the kernel.** It adds two connections. The kubelet gives the kernel of the boot in `nodeInfo.kernelVersion`, and the boot ID shows that the status is of the new boot.
- **A new counter `devops_cli_infra_node_runs_total`.** It doubles the dashboard and the alert rules for the same question.
- **A read of the health gate after the uncordon with no wait.** After a reboot, the alerts of the node can fire for some time; the waits of the apply read again until two reads are clear or the time ends.
