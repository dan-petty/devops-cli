# Task: roadmap-service exports its AI usage counters after every lane batch, under one series identity that survives a pod restart (#1629)

**Issue**: [#1629](https://github.com/dan-petty/devops-cli/issues/1629)
**Feasibility**: Confirmed on main 68f88304. `OTelTelemetryClient.flush()` was the only metrics export, and only `main._delegate` and the exit hook called it. `devops serve --service` runs the intake and refine jobs in its process, in one `_delegate` call, so their counters left the pod only at exit. The metrics resource set `service.instance.id` to the host name, which is the pod name. Prometheus holds 37 `target_info` instances of `job="roadmap-service"` in 30 days, one for each pod. The many samples of each pod's series are from v0.2.29 to v0.2.33, which sent each observation when it occurred; v0.2.36 (#792) changed to one export at flush, after the Service stopped (#1562). The SDK source (opentelemetry-sdk 1.45.1) shows that `Resource.create` merges `OTELResourceDetector` last, and also adds a random `service.instance.id` for each process. The collector's `deltatocumulative` source drops a delta whose time is not after the last delta of its stream (`ErrOutOfOrder`).

## Description

Each lane batch of the Service sends its OTLP metrics when it ends, also when its job raises. The metrics resource merges the standard `OTEL_RESOURCE_ATTRIBUTES` and `OTEL_SERVICE_NAME` through the SDK's own detector, and these values override the defaults. The Deployment sets `service.instance.id=roadmap-service`, so the series of a new pod continues the series of the pod before it. One flush runs at a time, so the collector gets the deltas of two lane workers in the order of collection. Cluster Jobs send under the service name `devops-cli-job`.
