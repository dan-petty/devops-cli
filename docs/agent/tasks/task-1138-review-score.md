**Issue**: [#1138](https://github.com/dan-petty/devops-cli/issues/1138)
**Status**: Done
**Milestone**: v0.2.30
**Priority**: priority/p1-high
**Scope**: type/feature, scope/review

## Description

Every review evaluation from S5 to S21 computed precision, recall and stability by hand, the baselines existed only as prose, and the loop study's labels sat in gitignored scratch files. `devops review score` scores saved sessions against a committed label file, offline, and the seed labels reproduce the published baselines.

- **The scorer** (`src/devops_cli/review/score.py`). A label file (pydantic, unknown fields refused) holds inputs and labels. An input has a name, a split (`tuning` or `held-out`), its page digests, the checkout its sessions stored absolute paths under, its known defects, its accepted recall loss and a row map: session id to the label key of each findings.json row. A label holds the identity (key, producer, rule, path, lines, object, origin page, `fingerprint_v2`), the label (valid-strict, valid-lenient, opinion or false), the defect id, the expected severity, a note, the labeller and the date. A session's findings.json is read with `ai/review/history.py`'s `HistoryPayload`, made public (`HistoryFinding` gains `location`, `severity` and `cited_code`), and a SESSION without a readable findings.json, or with a page that does not parse, is refused rather than scored as empty; findings.sarif is read through `security/sarif.read_sarif`, locations through `review_schema._parse_location` and `security/normalization.split_location`, and fixture pages through `path_classes.is_fixture_path`.
- **Identity.** A row of a mapped session takes its cluster from the row map. Any other row takes the findings.sarif result at its cited file and line (or its object): that result's `fingerprint_v2`, else its tool, rule, path and line or object, the key the loop study clustered tool findings on. Results at one place that differ in tool, rule or fingerprint (two kube-linter checks on one object, Bandit's B603 and B607 on one line) leave the row without an identity, so it is listed as unlabelled; identical duplicates, which sessions write for Bandit's B108, are one result. A model's row takes the one persona label of its path and origin page within five lines, and two such labels leave it unlabelled. Nothing is read from a title or a message. A stored absolute path is made relative to the input's checkout with `PurePosixPath.relative_to`, a row outside the session's `files/` pages counts as false without a lookup, and a row echoed from a fixture page is no recall.
- **Figures.** Each ratio (`Ratio`) carries its numerator and denominator in the table and in `--json`, and reads "not computable" while one of its rows has no label; the unlabelled rows are listed. Per session: lenient, strict and per-distinct-defect precision, the same three split by producer, VERIFIED and HIGH/CRITICAL precision, recall against the label file's recall set (per finding, the sessions whose report cites it) and against the input's known defects. Per input digest (a session that records none is a group of its own, not computable for stability): pooled precision, the mean pairwise Jaccard of the identities the sessions report, and Fleiss' κ of their statuses over the identities every session reported, by statsmodels' `fleiss_kappa` and `aggregate_raters`, imported only when κ is computed (owner decision 2026-10-09). `fleiss_kappa` needs equal ratings per subject, so the loop study's κ of 0.444 (126 clusters, 730 ratings) is not recomputed.
- **The command** (`commands/review.py`): `devops review score SESSION... --labels FILE [--json]` records a `review-score` run (`Mechanism.REVIEW_SCORE`) whose results hold the report plus `precision_lenient`, `precision_strict`, `recall`, `stability_jaccard`, `stability_kappa` and the median `llm_calls`, `prompt_tokens` and wall time, and `not_computable`, which names each of the first five the score could not compute and why. Stability is the mean over the inputs with two or more sessions, and not computable while one of them is. `--materialise-golden DIR` takes no sessions: it writes the golden input's files (`tests/golden/review_findings.json`) into DIR and makes one commit through `git/operations.commit_snapshot` (fixed author, committer and date, no email address, no hooks, no signing), the commit `git commit` makes of the same files, and lists the accepted recall loss. It refuses a DIR that is a file, a golden file outside DIR or under its `.git/`, before it writes anything.
- **Run checks** (`ai/run_store.py`, `commands/ai_runs.py`). `devops ai runs check` takes `--max-precision-drop`, `--max-stability-drop` and `--max-calls-increase`. A precision or stability figure either run recorded gets a verdict; one the baseline recorded and the current run could not compute fails, its reason "not computable (<the score's reason>)" and its current value shown as "not computable", so new unlabelled rows cannot pass the check. Model calls are judged when both runs recorded them. The drop limits come from one table in `run_store.py`, and the recall verdicts call `_evaluate_drop_verdict` directly. Cost is model calls: `cost_usd` is 0.0 in every recorded session, since the models are self-hosted.
- **Labels** (`tests/fixtures/review_labels/labels.json`). A one-off transcription, run outside the repository and not committed, read `.data/review-labels/clusters.json` (`per_session[*].findings_row`, `s11_label`, `prior_label_s10`, `rel_path`, `origin`, `line_span_e3`, `rule_id`, `rule_sub`, `loc_suffix`) and the precision report's section 1 lists. Its row map covers all 51 S11 rows and all 441 loop rows; 169 clusters are labelled (168 reported, plus C243, config.py:514, valid and never reported): valid-strict 12, valid-lenient 8, opinion 8, false 141. Defect ids follow the report's merges: kube-linter objects group per check and file, the recall-set echoes C091, C093 and C036 join C092, C094 and C039, and C246 and C247 are one defect. S11 and the loop are tuning inputs with the 9 known defects of the loop evaluation; the golden set is held out, with no digest until it is first scored, its 12 known defects and 12 defects no tool can express (missing-containment, missing-depth-limit, unchecked-status, unvalidated-dest, processed-timestamps, if-none-of, not-properly, api-need-to, cwe400-upload, missing-auth-header, miscounted-line and persona-self-dismissal). The labellers are the S11, S10 and loop evaluations' agent lenses, dated 2026-10-03.
- **Recorded slices** (`tests/fixtures/review_labels/sessions/`): S11, S12, S13 and S18, trimmed to the rows' location, status, severity, reportable and verified_by, the profile's call, token and time figures, and the `files/` pages the rows name, by `file_path` only. The expected figures are the loop evaluation's section 2 table, which the transcription reproduced for all 11 sessions from the raw findings.json rows (S20's HIGH cell reads 3/6, as the evaluation's skeptic corrected). The slices' stability was computed from clusters.json at transcription time: Jaccard over the three loop slices' row clusters is 0.3672 (3 pairs), and κ is 1.0 over the 19 clusters all three report, each with one status in all three.
- **Docs.** `docs/adr/0005-review-findings-come-from-tools-not-models.md` holds #1137's decision record byte for byte; `docs/VISION.md` item 8 is #1137's Evidence-First Code Reviews text; the knowledge base's `rag_context_indexing.md` states the two lookups a review makes (each page by file path and symbol names, up to three chunks; each finding the verifier checks by title and description, up to two) and that a review writes nothing to the index. `docs/SELF_IMPROVEMENT.md`'s recall protocol scores with `devops review score` in place of its inline `score_recall.py`, whose test cases moved to `tests/test_review_score.py`; the protocol now counts reported rows only, no longer the candidates before re-ranking and verification, and the doc and the changelog fragment say so. CONTEXT.md is not changed.
- **Tests** mirror the source tree: `tests/test_review_score.py`, and cases in `tests/test_run_comparison.py` and `tests/test_git_operations.py`. They read the committed fixtures and write sessions into `tmp_path`; the golden tests run local git with `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`.
