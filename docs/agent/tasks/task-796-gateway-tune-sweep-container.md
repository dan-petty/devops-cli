# Task: Gateway Tune Attaches One Sweep Container Per Run That Outlives the Run (#796)

**Issue**: [#796](https://github.com/dan-petty/devops-cli/issues/796)
**Scope**: scope/ai
**Feasibility**: Checked at release/v0.2.39 b40d48e3. `_ensure_sweep_container` looked up only the fixed name `gateway-tune-runner`, gave a terminated one a suffixed replacement, and created every container with `sleep 3600`. `tune_pool` calls `measure_in_gateway_pod` once per deployment, so each call after the first container exited attached another, and a run's exec budget (request timeout x rounds x (levels + 1) + 60 s per deployment, 2460 s at the defaults) outlasts the hour from the second deployment on. The new tests drive `tune_pool` over the two `devops-review` deployments with only `subprocess.run` faked as kubectl: at the base the run attaches `gateway-tune-runner` with `sleep 3600`, and a container that exits after the first sweep is replaced by a second one without an error. Kubernetes states that an ephemeral container cannot be changed or removed once it is added to a pod (kubernetes.io, Ephemeral Containers), so a run cannot remove its container; it sizes the container's `sleep` so that the container ends by itself after the run.

## Description

- [x] **Run container** (`ai/gateway_tune.py`): `tune_pool` names one container `gateway-tune-<6 hex>` for the run and passes it to every `measure_in_gateway_pod` call with a lifetime of the exec timeout times the number of deployments. `measure_in_gateway_pod` takes both as required arguments, and the default name `gateway-tune-runner` is gone.
- [x] **Attach** (`_ensure_sweep_container`): a running container is reused, an absent one is attached with `sleep <lifetime rounded up>`, and one that has exited raises `GatewayTuneError` naming it, since a second container would leave the run with more than one. The suffixed replacement is deleted.
- [x] **Earlier runs**: a container an earlier run left behind is never reused, because its remaining life is unknown and reusing it would bring back the mid-sweep expiry. Reuse within a run, which [#669](https://github.com/dan-petty/devops-cli/issues/669) added, stays. The pod keeps the run's container, exited, until the pod is replaced, as the module docstring says.
- [x] **Tests** (`tests/test_ai_gateway_tune.py`): `_FakeKubectl` holds the state of each ephemeral container on the pod and can end them after a number of sweeps. One test runs `tune_pool` over two deployments with a running container from an earlier run on the pod and checks for one `debug` call, a `gateway-tune-<6 hex>` name, the same name on both `exec` calls and a `sleep` of the rounded-up exec budget of both deployments; another ends the container after the first sweep and checks that the run fails naming it, with no second `debug` and no second `exec`. The tests of `measure_in_gateway_pod` pass the new arguments and check the `sleep` they are given.
- Pending a person: `devops ai gateway tune` against a live gateway with two or more deployments, then `kubectl get pod <gateway-pod> -n <namespace> -o jsonpath='{.spec.ephemeralContainers[*].name}'` lists exactly one new `gateway-tune-<hex>` container for the run.
