# Task: `web_fetch` Vetoes Every Redirect Hop Before It Is Sent (#860)

**Issue**: [#860](https://github.com/dan-petty/devops-cli/issues/860)
**Status**: Done
**Milestone**: v0.2.24
**Priority**: priority/p0-critical
**Scope**: scope/ai

## Description
`fetch_web_page` (`src/devops_cli/ai/common_tools.py`) validated the URL once, then let a fresh httpx2 client follow up to 20 redirects. `_validate_response_egress` checked only the final `resp.url`, after every hop had been sent. A public page that redirected to `169.254.169.254` and on to another public page therefore had the link-local hop requested, and the tool returned the final page.

This delivers PR1 of the issue, the per-hop egress veto, which is the P0. PR2 to PR4 (failure status, encoding, untrusted rendering) and PR5 are not in it.

- `fetch_web_page` sends through a client of its own from `HttpClientBroker.new_client()` on `get_broker()`, and closes it after the fetch. That client has the shared client's redirect limit and `request` event hook, but no shared connection pool or cookie jar, so a cookie one fetched site sets never reaches a later fetch or the shared client that `vault_broker` uses. httpx2 walks the redirects, and the hook runs before each hop is sent, the first included. The tool puts its policy, `_validate_fetch_hop`, in `request.extensions` under `CONST_HTTP_EGRESS_POLICY_EXTENSION`. The policy allows only http and https, applies `allowed_domains` and `blocked_domains`, and calls `validate_url_egress(allow_private=False)`, which ignores `DEVOPS_CLI_AI_ALLOW_PRIVATE_NETWORK`.
- `allowed_domains` and `blocked_domains` compare the host and each entry lowercased and without a trailing dot, so `https://blocked.com./` no longer gets past `blocked.com`, on the first URL or on a redirect hop.
- `HttpClientBroker._validate_request` holds a request that carries an egress policy to that policy first and then to the broker's own SSRF check, so a policy can narrow what the broker admits but never widen it. Other requests keep the broker's check alone. The veto is on each redirect request, not in a `response` hook.
- Both broker clients follow at most `DEFAULT_HTTP_MAX_REDIRECTS` (10) redirects, below httpx2's 20.
- `web_fetch` builds the request from its own headers through `client.build_request`, not through `HttpClientBroker.request`, whose `build_headers` adds the caller's `traceparent`.
- `_validate_response_egress` is deleted: the hook has already vetted the final URL before that hop was sent. `_is_private_or_loopback`, which only `_validate_response_egress` called, is deleted with its test; `devops_cli.core.validation.is_loopback_or_private_host` keeps that behaviour and its tests.
- `tests/web_fakes.py` adds `StubWeb`, canned pages served by httpx2's `MockTransport`. The `stub_web` fixture (`tests/conftest.py`) replaces `httpx2.Client` and `httpx2.AsyncClient` with subclasses that always use that transport, so every client keeps the broker's redirect limit and request hook, and code that subclasses them or checks `isinstance` still works. It gives the tests a fresh broker and resolves external names to a public address as `public_dns` does. The `web_fetch` tests that patched `new_http_client` with `MagicMock` responses now fetch through it.
- `test_web_fetch_tool_blocks_post_redirect_to_private_host` is replaced. It sent no redirect and accepted any string containing "error".

Two gaps that predate this change and lie outside #860 remain. `is_non_public_ip` classifies by `is_global`, which Python reports as true for the NAT64 prefix `64:ff9b::/96`, so `http://[64:ff9b::a9fe:a9fe]/` passes the hop veto; on a NAT64 network that reaches `169.254.169.254`. And the hook resolves a hop's hostname itself before httpcore resolves it again to connect, so a rebinding name that answers public and then private within that window is not bound to the vetted address.
