# Task: Project reconcile reads an unknown quota, fixes existing cards first, and says when it stopped early (#892)

**Issue**: [#892](https://github.com/dan-petty/devops-cli/issues/892)
**Status**: Done
**Milestone**: v0.2.29
**Priority**: priority/p1-high
**Scope**: type/bug, scope/github, priority/p1-high

## Description

`devops gh project reconcile` and `devops gh project sync` no longer add cards, read an unknown or expired GraphQL quota instead of treating it as spent, plan every change before making any, and say when and why a run stopped early. The item also carries #878 (sync's task-file parse and its invented counts) and #1010 (the template path relative to the working directory).

- Reconcile starts with the roadmap store's GraphQL budget query (`board_budget_args`, `require_budget`, #1125), whose reply reports GraphQL's own count. When the ledger holds no GraphQL entry, or one past its reset, `run_gh`'s `acquire` refreshes it from `gh api rate_limit` before sending the query, so the first run of an identity, or one an hour after the last, reconciles instead of printing `Would change 0 of 0`. A run that would leave fewer than `DEFAULT_GH_GRAPHQL_BUDGET_FLOOR` (250) points refuses before the first page, naming the points left and the reset, and exits 1.
- It evaluates only the cards already on the board, plans every change with `plan_item_changes` (unchanged, #703's rules), refuses before any write when a planned value is not among the board field's options, and makes the changes in order. Before each write it checks the mutation budget and the ledger's GraphQL entry; a failed `item-edit` stops the run. `ReconcileResult` holds the planned, applied and remaining changes and the stop reason, so the planned changes are the applied ones followed by the remaining ones.
- The CLI prints `Changed X of Y items on project #N (Z field changes).` and exits 0 when every planned change was made, or `Stopped early (<reason>): N planned changes remain.` and exits 1. A run that listed open issues says how many are not on the board (awaiting intake: devops roadmap intake).
- `--plan` reads and lists the changes; `--dry-run`, and the global dry run, make no request and print the requests a run makes, built by the same argument builders the run uses. MCP `gh_project_reconcile` takes `mode` (`dry-run`, `plan` by default, `write`), as the roadmap tools do.
- Sync finds or creates the board, links it, creates missing fields and reconciles; it adds nothing, prints reconcile's stop line and exits 1 when reconcile stops, and its dry run makes no request and prints no board number. `--task-file`, the task-file parser and `ProjectItem` are gone.
- Every `--template` option defaults to `.github/project-template.json` at the repository root (`find_repo_root`), and `reconcile -n` reads the board's own Status options instead of the template.

## Decisions and deviations

- **Quota source (amended 2026-10-08)**: #983 moved to the backlog, so the item's fallback applies. The start decision uses the GraphQL budget query's reply rather than `gh api rate_limit`, which #1125 measured reporting 4,899 GraphQL points while GraphQL said 17. The REST refresh still runs first when the ledger is unknown or expired, inside `run_gh`'s `acquire`; the unknown- and expired-ledger tests go through the real `run_gh` with gh's process and the refresh stubbed, so that path is exercised. `github/rate_limiter.py` is not edited.
- **One threshold**: `DEFAULT_GH_GRAPHQL_BUDGET_FLOOR` (250) replaces `DEFAULT_GH_GRAPHQL_SAFETY_THRESHOLD` (500), which is deleted with `_is_graphql_quota_exhausted`.
- **Between writes**: the ledger's GraphQL entry decides. An entry that is unknown or past its reset proceeds to the write, because `acquire` refreshes it first and a passed reset means the hourly window refilled; no extra GraphQL read is added.
- **Failed writes stop the run** at the first failure, which keeps planned = applied + remaining and avoids repeating a failing write up to the budget. The stop line names the field, the item and gh's error, printed as written (`safe=True`, as `exit_on_error` prints), since gh's error is remote text.
- **Values the board can't take are refused at plan time (review 2026-10-08)**: `plan_item_changes` forces Done, In Review and In Progress and defaults to New without checking the board's options, so a board lacking one would fail the same write on every run and, with the run stopping at the first failed write, block every later change. Reconcile reads every field's options and checks each planned change with the roadmap store's `require_option` before any write, in `--plan` and live runs alike, naming the value and the options. The whole run refuses rather than skipping the change, because a skipped change is a swallowed error and the board's options are a person's fix (`devops roadmap migrate` lists the edits). A failed write after that check is transient or needs its cause fixed, so the help says a rerun continues once that is done.
- **Dry run (#412)**: `--dry-run` lists the requests and makes none; `--plan` is the reading preview. Without `-n` the plan also lists the board lookup (`find_remote_project`'s reads, by title then short name), and with an `@me` owner the login read. MCP `gh_project_reconcile` follows the roadmap tools' `mode` convention with `plan` as the default, so a call with no arguments no longer writes.
- **Awaiting intake under `--state closed`**: open issues are not listed, so no count is printed rather than adding a listing.
- **Field options**: reconcile reads the board's own field options with `gh project field-list` in every mode, through the roadmap store's `field_list_args` and its reply model `FieldListingPayload` (made public, with an `options()` the store also uses), failing closed on a failed read, a listing short of its `totalCount`, or a board without Status options. Fields are matched by their exact names (`Status`, `Priority`), as `require_option` and the store match them. The template is no longer an input to reconcile; the CLI loads it only to find the board when `-n` is absent. The reset time in the quota stop is formatted by `board_read.utc_clock` (made public), not a copy.
- **Template root**: `find_repo_root()` (the nearest directory holding `.git` or `pyproject.toml`) gives `git rev-parse --show-toplevel`'s answer for a checkout, a linked worktree and a `repos/` clone without running git; `find_worktree_root()` would send a `repos/` clone to the outer workspace's template.
- **Writes by login**: `field-list` and `item-edit` pass the owner's login, as the roadmap store does, through its `field_list_args` and `item_edit_args`, instead of the `@me` mapping and its retry, so the request plan is exact.
- **No spend line**: the reading preview ends with the summary, not a GraphQL spend line; that would add a request the issue does not ask for.
- **Tests double only gh (review 2026-10-08)**: the new reconcile and sync tests stub `projects.run_gh`, or the real `run_gh`'s process, rate-limit refresh and pacing sleep, with `tests/project_reconcile_fake.py`, which also answers sync's scope check, board lookup, link and login read. None replaces a function of `projects.py` or `gh.py`; the sync tests drive `devops gh project sync` end to end, and the template-not-read check runs in a checkout with no template instead of spying on the loader. The CLI tests narrow `MutationBudget`'s limit, a run setting.
- **Duplicate test removed**: `tests/test_gh_issues_milestones.py::test_reconcile_never_writes_the_milestone_the_board_mirrors` called the deleted `_reconcile_single_item`; `test_the_milestone_the_board_mirrors_is_never_written` covers the same rule through `plan_item_changes`.
- **Overlaps**: #1034 edits `rate_limiter.py` pagination, which this item does not touch. #868 checks the MCP argv lists; the reconcile tool appends `--dry-run` and `--plan` as literal flags. #898 rewrites AGENTS.md:416, two lines below a line reworded here.
