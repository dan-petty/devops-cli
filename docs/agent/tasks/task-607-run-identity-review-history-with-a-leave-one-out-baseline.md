## 1. Description & Objectives

`ReviewSessionPayload` (src/devops_cli/ai/review_schema.py:1084) stores no target or commit, and pydantic silently drops the `target=`/`timestamp=` that the tests pass (tests/test_category_metrics.py:173-174). The baseline reader (src/devops_cli/ai/review/category_metrics.py:114-124), `devops review stats` (src/devops_cli/commands/review.py:1122) and the feedback export (src/devops_cli/ai/review/exporter.py:139-147) each sum every session dir. A re-review, or a `devops review benchmark` (3 runs by default, src/devops_cli/config/defaults.py:389), therefore counts one target several times. findings.json is written (src/devops_cli/ai/review/pipeline.py:3082) before the report is built (pipeline.py:3095), so the #434 "Historical Baseline FP Rate" includes the session it is compared with. An identity rule already exists: `RunRecord.subject_key` is `run_store.digest(subject)` (src/devops_cli/ai/run_store.py:53-92). Review sessions sit outside that store, though, and `load_runs` (run_store.py:200-210) does not collapse repeats either. vibes has the same defect: `_shard_name` names shards by timestamp plus a count of existing files, and repeats are summed.

- Deliverable*: PR1 measures. It records a `subject` on each session, keyed with `run_store.digest`: `pull.head.sha` for PRs (already fetched, src/devops_cli/ai/review/runner.py:1750), base and head SHAs for branches, and `_corpus_digest` (runner.py:1323) for paths, which is a content digest rather than a dirty flag. `devops review stats` then reports sessions per identity, repeats and unkeyed sessions before any figure changes. PR2 adds one session reader to replace the three globs. It takes `exclude_session_id` (the pipeline passes its own) and a window constant in config/defaults.py. The `total_sessions > 1` gate (category_metrics.py:148) must then count prior identities, or the baseline disappears on a first re-review. PR3 is the export merge described below. Fix the dropped test fields, and add a regression test that writes the current session before rendering. Add a correction note under #434 in docs/ROADMAP.md.
- Constraint*: Keeping only the newest session per identity would let a machine re-run replace `verified_by = "human"` labels (src/devops_cli/commands/review.py:970), which are the only trustworthy labels in the export. Merge findings within an identity using the existing matchers (`consolidate_duplicate_findings`, review_schema.py:1031; `_is_matching_finding`, src/devops_cli/ai/review/verification.py:1585), with human verdicts winning. Do not add a new match rule. Sessions with profile.json have a target but no commit (src/devops_cli/ai/review/profile.py:99-103), so report them as target-only. Report sessions without profile.json as unkeyed. Never derive a key from directory names, and never drop these sessions.
- Measured*: A scratch probe on a temp reviews dir (`uv run --no-sync python probe/l301_probe.py`): with only a prior VERIFIED session the cell reads `— (baseline established)`.
