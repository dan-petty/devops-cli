# Task: MCP Tools Refuse Coerced Arguments Before They Run, With Prescriptive Errors That Never Echo Values (#862)

**Issue**: [#862](https://github.com/dan-petty/devops-cli/issues/862)
**Status**: Done
**Milestone**: v0.2.24
**Priority**: priority/p0-critical
**Scope**: scope/mcp

## Description
FastMCP validates tool arguments with pydantic in lax mode, and the server does not set `strict_input_validation`. `review_pr` given `{"number": true, "post": true}` therefore built `devops review pr 1 --persona devsecops --post`, and `{"number": "1"}` and `{"number": 1.0}` also reviewed PR 1. `_validate_mcp_int_bound("number", ..., min_val=1)` passed, because `True == 1` after coercion. An undeclared parameter got pydantic's raw `Unexpected keyword argument` text, which quotes the value and lists nothing the call could have sent. FastMCP logged pydantic's error list with every rejected `input`, so a malformed `vault_set` wrote its `key_values` to the log and to the reply. The SDK's own strict check is no substitute. It sees only listed tools, while `DomainGateMiddleware` withholds most of them, including `sandbox_stop`, `tf_apply` and `pr_close`. It also quotes the value and answers before any middleware runs.

- `ArgumentContractMiddleware` (`src/devops_cli/ai/mcp/server.py`) sits beside `DomainGateMiddleware`. For `tools/call` it resolves the registered tool through `mcp.get_tool`, listed or withheld. It validates the arguments against the tool's published `tool.parameters` with `iter_errors` and raises `ToolError` with the envelope before the handler runs. The validator is `jsonschema`'s `Draft202012Validator` extended with one change to its type checker: `integer` accepts only a JSON integer, never `1.0` or a boolean. JSON Schema counts `1.0` as an integer, and lax pydantic then passed it to every integer parameter that is not a PR or issue number, so `sandbox_stop` given `{"timeout": 10.0}` ran `devops sandbox stop --timeout 10`. Pydantic still runs afterwards. Its `fastmcp.exceptions.ValidationError` is read through `__cause__.errors(include_url=False)` and answered with the same envelope, raised `from None` so the pydantic error is not chained. A tool name that resolves to nothing is left to FastMCP's own `Unknown tool` answer.
- `src/devops_cli/ai/mcp/argument_contract.py` turns both error sources into `ArgumentViolation`s from the error's location and the schema alone, never from jsonschema's `message` or pydantic's `input`, both of which quote the value. `describe_schema` states the expected type from the schema's keywords (`integer >= 1`, `string or null`, `array of string`, `one of "all", "test", ...`, `exactly "json"`). An `additionalProperties` error becomes one `HALLUCINATED_PARAM` per undeclared name, and a `required` error one `MISSING_PARAM` per absent name. Inside a union, a failed bound makes the kind `OUT_OF_RANGE` instead of `TYPE_MISMATCH`. An undeclared name is the caller's own text, so it is masked with `mask_secrets` and cut to 64 characters before it is echoed. A parameter that fails several keywords, such as `5` against `ci_run`'s string `enum`, keeps only its first violation, so it does not inflate the count or take another parameter's place among the five shown. The kind tables and the bound phrases are in `src/devops_cli/config/constants.py`, and a test holds them to every keyword the registry publishes.
- The renderer is in `src/devops_cli/ai/schema_reflection.py`, the Lossless Structured Error Reflection module, so it is shared with schema retries. `ArgumentRefusal.format_envelope` numbers up to `CONST_MAX_SCHEMA_REFLECTION_ERRORS` (five) violations, each with its parameter, kind, expected type and fix, and counts the rest. It then lists the sorted allowed parameters and ends with "Re-issue the call with every violation corrected." The existing reflection prompts are unchanged.
- `PullOrIssueNumber = Annotated[int, Field(ge=1, strict=True)]` types the 11 PR and issue numbers: `review_pr.number`, `issue_number` on `gh_issue_edit`, and `pr_number` on `pr_checks`, `pr_threads_list`, `pr_monitor`, `pr_ready`, `pr_check_readiness`, `pr_diff`, `pr_close`, `pr_update_branch` and `pr_edit`. Their schemas now publish `minimum: 1`. The schema check already refuses `true`, `"1"` and `1.0`, so the strict alias is defence in depth for a value that check lets through. The `_validate_mcp_int_bound` calls stay, because a direct Python call skips both the schema and pydantic. Deleting the three helpers is the issue's follow-up.
- Since fastmcp 4.0.11 (#1184), FastMCP logs a refused call's pydantic error count and types, never the input, so the filter this issue added on the `fastmcp.server.server` logger was removed in #899. `test_no_rejected_input_reaches_a_log_record` still holds FastMCP's log to no rejected input.
- `jsonschema==4.26.0` moves from the dev group to the runtime dependencies. It is the version already locked through `mcp`, so `uv.lock` changes only the declarations.

The sweep over the real registry checks 193 coerced values on 106 parameters of 66 of the 154 tools, `1.0` among them on all 41 integer parameters, and 11 of the 46 integer or number parameters publish a bound (the PR and issue numbers). The registry publishes only `type`, `anyOf`, `items`, `enum`, `minimum`, `required`, `additionalProperties`, `properties` and `default`. FastMCP's DEBUG log of each call's arguments in `fastmcp.server.mixins.mcp_operations` is redacted by #899.

## Acceptance Criteria
- [x] Through `fastmcp.Client(mcp)` with `_run_mcp_cmd` patched to raise, `review_pr` refuses `{"number": true, "post": true}`, `{"number": "1"}`, `{"number": 1.0}` and `{"number": 1, "post": "true"}` before the handler runs, and the patched runner records no call. `test_a_coerced_argument_is_refused_before_the_handler_runs` (`tests/test_fastmcp_contracts.py`) asserts `(is_error, call_count) == (True, 0)` for each. Against `release/v0.2.24` all nine of its cases reach the runner (`(True, 1)`). Two are integral floats on integers that are not PR numbers, `sandbox_stop`'s `{"timeout": 10.0}` and the advertised `ai_vllm_scale`'s `{"replicas": 2.0}`, and they reached it even past a published-schema check that read `integer` as JSON Schema does.
- [x] The same holds for the withheld `sandbox_stop`: `{"timeout": true}`, `{"timeout": "10"}`, `{"timeout": 10.0}` and `{"all_instances": "true"}` are refused with no runner call by the same test. `test_a_withheld_tool_refuses_with_the_same_envelope` checks its envelope.
- [x] The refusal names the parameter, the expected type and the allowed parameters, and never echoes the value. `test_a_refusal_names_the_parameter_its_type_and_the_allowed_parameters` sends `{"number": "4242", "verbose": true}` and finds an entry for `number` with `Expected: integer >= 1`, an entry for `verbose`, the sorted allowed parameters `number`, `persona` and `post`, and "Re-issue the call", but no `4242`. `test_each_violation_is_numbered_with_its_parameter_and_kind` classifies `MISSING_PARAM`, `OUT_OF_RANGE` (on a plain and an optional number), `HALLUCINATED_PARAM`, `TYPE_MISMATCH` (for `"7"` and `7.0`) and `INVALID_CHOICE`. `test_a_parameter_that_breaks_two_keywords_is_listed_once` sends `ci_run` `{"check": 5}` and finds one entry. `test_a_strict_refusal_is_rendered_like_a_schema_refusal` bypasses the schema check so the strict alias refuses `4242.0` in pydantic, and finds the value in neither the reply nor FastMCP's log. `test_a_refused_secret_never_reaches_the_reply` keeps a `vault_set` sentinel out of the reply. `test_an_undeclared_parameter_name_is_masked_and_bounded` masks a `ghp_` name and cuts a 500-character one to 64.
- [x] FastMCP's log keeps no rejected input. `test_no_rejected_input_reaches_a_log_record` calls `vault_set` past the middleware, as FastMCP does once middleware has run, so pydantic refuses and FastMCP logs "Invalid arguments for tool". The sentinel is not in the captured log.
- [x] Every published schema keeps `additionalProperties: false`, and `strict_input_validation` stays off. `test_every_published_schema_forbids_undeclared_parameters` hydrates every domain, lists through `fastmcp.Client(mcp)` and matches the registry's 154 tools. `test_strict_input_validation_stays_off` asserts the setting.
- [x] A sweep runs the validator, never a handler, over every integer, boolean and number parameter. `test_the_validator_refuses_every_coerced_value_without_running_a_handler` refuses bool-for-int, string-for-int, integral-float-for-int, bool-for-number, string-for-number and string-for-bool wherever the property does not also accept that JSON type. It records bound coverage as the `numeric_parameters_with_a_published_bound` property (11/46) without asserting it. `test_pr_and_issue_numbers_publish_a_positive_bound` finds `minimum: 1` on all 11 PR and issue numbers. `test_every_published_keyword_is_one_a_refusal_can_describe` fails on any published keyword the kind and bound tables do not cover, such as `pattern` or `multipleOf`, whose refusal would otherwise name only a type the value already has.
- [x] Tests never touch the network. `fastmcp.Client(mcp)` uses FastMCP's in-memory transport, and the session network guard stayed on.
- [x] `uv run devops ci` passes: all 13 checks, 132 s wall clock (pytest and coverage 2 min 8 s), while parallel agents' gates shared the machine.
