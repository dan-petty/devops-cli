# Task: Reviews Run Nothing From, and Take No Conventions From, the Tree Under Review (#946)

**Issue**: [#946](https://github.com/dan-petty/devops-cli/issues/946)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/review

## Description
A review must treat the tree it reviews as untrusted. Analysing review session `20261001-224227` found three paths that ran its code or followed its instructions. This change closes all three.

- **Type probe** (`_module_typechecks_clean`, `ai/review/verification.py`). The check that dismisses a claimed `None` dereference (`_check_none_dereference_hallucination`) ran `["uv", "run", "mypy", "--strict", <file>]` with no `cwd`, so in whatever directory the CLI was started from. Started inside a repository under review, `uv run` synced that project and ran its build backend, and mypy read that directory's config and plugins. As the issue proposed, the probe is isolated rather than skipped for files outside devops-cli. It now runs `[sys.executable, "-I", "-m", "mypy", "--strict", "--config-file", <probe mypy.ini>, "--cache-dir", <probe cache>, <absolute file>]` with `cwd` set to a fresh `tempfile.TemporaryDirectory`, which also holds the config.
  - `-I` (isolated mode) makes the interpreter ignore `PYTHON*` variables and keep the working directory off `sys.path`. `run_subprocess`'s allowlist passes `PYTHONPATH` and `PYTHONHOME` on, so a `PYTHONPATH` naming the target, as a devcontainer, direnv or an IDE sets for the project in hand, had the child import the target's `sitecustomize.py` and its `mypy` package in place of the real one. `run_subprocess` drops `MYPYPATH`, `PWD` and every other variable outside its allowlist.
  - The config is devops-cli's own, `CONST_TYPECHECK_PROBE_MYPY_CONFIG` (`config/constants.py`): `[mypy]` with `plugins = pydantic.mypy`, the one plugin devops-cli's `[tool.mypy]` loads. mypy imports a plugin named as a module from its own interpreter's `sys.path`, which `-I` and the empty `cwd` keep free of the target. The issue's argv named an empty config, but without the plugin, devops-cli modules that pass the project's `mypy --strict` failed the probe, so the guard was off for the code it was built for. `ai/review/pipeline.py` failed with four errors the plugin resolves; a review of this change counted 21 such modules.
  - mypy's cache is kept in devops-cli's cache directory, `<data dir>/cache/typecheck-probe/<digest of the interpreter and the config>` (`_typecheck_probe_cache_dir`, `CONST_TYPECHECK_PROBE_CACHE_DIR_NAME`), in place of the issue's `--no-incremental`. A cold pass over `pipeline.py`'s imports took 58 s at a load average of 3.5 and about three minutes at 14 on this machine, against the probe's 120 s timeout, and a timeout claims nothing. The cache is data mypy reads, never code it runs. It is under the same data directory as the review history, the hallucination catalog and the LLM response cache that reviews already trust. A module-level lock runs one probe at a time, so concurrent verification workers do not each make the same cold pass. mypy commits its cache module by module, so a probe that times out still leaves what it checked for the next.
  - A target whose imports devops-cli's interpreter cannot resolve fails the check, which leaves the finding to the model verifier.
- **Branch conventions** (`_prepare_branch_content`, `_execute_review_workflow`, `ReviewPipelineOrchestrator`). `devops review branch` gave the personas and the verifier the working tree's `AGENTS.md` and `.devops/review.md`, so a branch could add exemptions that suppress findings about itself. `BaseRevision` (`ai/analyze/symbols.py`) gains `revision`, the local git revision its `read` reads at. `_branch_base_revision` sets it to the merge base, or to `HEAD` for a working-tree review. `_execute_review_workflow` passes it to the orchestrator as `conventions_revision`, and `_read_target_conventions` reads both files there. `_prepare_branch_content` reads `agents_md`, the conventions of the fallback persona loop, at the same revision through `_load_agents_md(start, revision)`. Before, it ran `git show <base>:AGENTS.md`, which read only `AGENTS.md`, at the base branch's tip rather than the merge base, and fell back to the working tree when the base had none. A pull request's `BaseRevision` has no `revision`, so `devops review pr` keeps reading the base conventions `_materialize_pr_head` writes under its temporary head directory.
- **Branch base** (`_detect_base_branch`, `_detect_remote_default_branch`, `ai/review/runner.py`). With no local base branch, as in a CI checkout or a single-branch clone of a feature with no `origin/HEAD`, the base fell back to the checked-out branch. The review then took the "reviewing main directly" path: it diffed `<feature>~1...<feature>`, the last commit only, and read the conventions at `<feature>~1`, under an exemption an earlier commit of the branch had added. The detection now lists local branches and `origin`'s in one `for-each-ref`, and tries `preferred_base`, local or as `origin/<name>`, then a local main, master or trunk, then `origin/HEAD`'s branch, local or remote, then `origin/` main, master or trunk. It never falls back to the checked-out branch: with no base at all it returns `preferred_base`, and the diff against it fails. A review of the base branch itself, which the user names or which is main, master or trunk, still diffs against the latest tag or `<base>~1` and reads the conventions there, in the base branch's own history, outside the diff.
- **Lookup** (`ai/review/review_environment.py`). `nearest_conventions` and `nearest_review_conventions` take an optional `revision`. With one, each candidate file is read with git at that revision in the repository that holds the target. Without one, files are read on disk. `read_file_at_revision` (`git/operations.py`) now reads only a regular file. It finds the path's entry with `git --literal-pathspecs ls-tree -z --full-tree <rev> -- <path>` and reads the blob by its object id with `git cat-file blob`, in place of `git show <rev>:<path>`, which printed a directory's listing that a lookup at a revision would take for `.cursor/rules`. The re-export of `_read_candidate_conventions_file` from `runner.py` had no user and is deleted.
- **Paths at a revision** (`_is_safe_relpath`, `git/operations.py`). `read_file_at_revision` refused any path with a character outside `[a-zA-Z0-9_\-/.@+]`, so a subproject whose directory name held a space or a character outside ASCII lost its conventions in a branch review, which fell through to the repository root's. It now refuses only an empty path, an absolute one, one that starts with `-`, or one with a `..` part. The path reaches git as one argument, a literal pathspec after `--` that follows the validated revision. `CONST_SAFE_GIT_RELPATH_PATTERN` had no other user and is deleted. #593's symbol-delta readers (`_branch_base_revision` in `runner.py`, `_apply_symbol_delta_to_meta` in `commands/analyze.py`) pass the paths `git diff -z` printed through the same check, which still refuses every path that could leave the repository or read as an option, and their revisions are validated as before. A changed file with a space in its name now gets its symbol delta, and a linked one an unknown delta rather than one computed from the path it points to.
- **Links** (`_disk_reader`, `ai/review/review_environment.py`). On disk the lookup followed links, so a reviewed tree's `AGENTS.md` linked to a file outside it put that file's text into the persona and verifier prompts. It now reads a file as the chunker reads a reviewed one (`_is_reviewable_candidate_file`): a link is absent, and so is a file that resolves outside the repository root (outside the start directory when there is no repository), as one under a linked `.devops/` does. At a revision a committed link, mode `120000` in `ls-tree`, is absent too, where `cat-file` had returned the path it points to as the conventions. Of the two answers the review allowed, treating such a link as absent or resolving it within the same revision, this takes the first, for three reasons. A path review and a branch review of one tree then read the same files, whereas resolving at a revision would read conventions that a path review of the same tree skips, since the on-disk rule refuses every link, even one inside the repository. Resolving would also have to follow chains of links and linked directories through git's trees, for a layout few projects use for these files. And the common link loses nothing: in a project that links `CLAUDE.md` to `AGENTS.md`, `AGENTS.md` is read first. A project that keeps `.devops/review.md` as a link to its rules elsewhere has to make it a regular file. A file reached through a linked directory, such as `.devops -> tools/devops`, is refused on disk as well, because git stores the link and a branch review never sees its files: `test_a_linked_conventions_directory_is_absent_on_disk_and_at_a_revision` gives `('', '')`, and fails with the previous reader, which followed the in-tree directory link.
- **Corpus root**. The walk ends at a directory whose `manifest.json` loads as a `DefectCorpus` (`_is_corpus_root`). Many projects keep a `manifest.json`, so a file that is not a corpus manifest stops nothing. The manifest is read through the walk's own reader: at the conventions' revision for a branch review, so a manifest the branch adds cannot end the walk before its base's conventions, and on disk only when it is a regular file. `DefectCorpus.load` had read it unchecked, so a FIFO named `manifest.json` hung the lookup and a link to `/dev/zero` read until `MemoryError`. The on-disk reader also treats a file that is not UTF-8 as absent rather than raising. `generate_corpus` wrote placeholder `AGENTS.md` and `.devops/review.md` files only to stop the walk, and those are deleted. A corpus now carries the first source's conventions files where the source has them, and none otherwise.
- **Profile**. `ReviewProfile.conventions_digest` is the `run_store.digest` of the rendered conventions the session's prompts carried. `_read_target_conventions` records them on the active profiler (`ReviewProfiler.set_conventions`). It is empty when the prompts carried none, whether no stage read the conventions or the target has none, so a profile shows that without its reader knowing the digest of an empty text. A target with none had recorded `digest("")`, `12ae32cb1ec02d01`. `prompt_digest` covers only the prompts devops-cli ships.
- **Docs**. `docs/SELF_IMPROVEMENT.md` describes the isolated probe, where branch and PR reviews read their conventions, that a linked conventions file is skipped, the corpus root and `conventions_digest`. The CLI is unchanged.
- Out of scope: corpus scoring does not compare sessions' `conventions_digest`. A score still refuses only sessions whose `prompt_digest` differs.
- Out of scope, in #972: the review of this change found four more ways the tree under review reaches a review: devops-cli's project config and data directory, library contracts for contract grounding, the static scanners' config, and suppression comments that satisfy the type probe. #972 tracks them.
