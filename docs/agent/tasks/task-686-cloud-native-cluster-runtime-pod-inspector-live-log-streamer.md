## Description
The dashboard's Kubernetes tab already listed every pod, refreshed every five seconds and tailed a pod's logs on Enter. It got several things wrong, and this item fixes them and adds the inspection the tab lacked.

**One pod status everywhere.** The Status column showed the pod phase, so a container crashlooping in a pod whose phase was still Running read as Running. `PodInfo.from_pod` in `src/devops_cli/models/k8s.py` ports the STATUS, READY and RESTARTS logic of kubectl's `printPod`, split into helpers for the init containers, the app containers and the final adjustments: the pod's reason or phase; the first unfinished init container as `Init:<reason>`, `Init:Signal:<n>`, `Init:ExitCode:<n>` or `Init:<done>/<total>`, with a started sidecar counted toward READY; then the app containers last to first, where a waiting or terminated reason wins and a Completed container beside a running one gives Running or NotReady by the pod's Ready condition; and finally Terminating, or Unknown for a lost node, on a pod being deleted. READY counts ready containers over the spec's containers, sidecars included in both, so a pod creating its one container reads `0/1`. `unhealthy` is set for any status other than Running or Completed, and for a Running pod short of READY. The dashboard tab, `devops dashboard --summary`, `devops k8s pods` (with its status colour now by health) and `devops k8s pods --watch` all read this one port. Every reason name, the healthy set and the default-container annotation are declared in `src/devops_cli/config/constants.py`.

**Pod records carry their containers.** `PodInfo` gains `uid`, `containers` and `init_containers` (a new `ContainerInfo` with name, image, ready, restarts, state, reason, last termination reason and exit code, and restartable), `default_container` and `unhealthy`, all with defaults. `K8sSummary.pods` is `list[PodInfo]`.

**A dedicated `K8sPanel`** in `src/devops_cli/ui/widgets.py` keeps the `#panel-k8s` and `#k8s-table` ids; `DomainPanel` is unchanged. Its banner is `render_banner(snapshot)` plus "showing N of M" while a filter is on, and `k8s_banner` names the connection state, the context, Ready nodes out of the total, the pod count and the unhealthy count, or the context tried and the error when disconnected. Unhealthy rows are red. Nodes are listed on the same client as pods; a failed node list reads "nodes: unavailable (<reason>)" while the pods still render. Both list calls pass `_request_timeout=DEFAULT_K8S_CONNECT_TIMEOUT_SECONDS`, and errors are described in one line (`403 Forbidden` for an API error) and passed through `mask_secrets`. `node_is_ready` serves both the banner and `format_k8s_nodes_table`. The Minikube probe and the `minikube_active` and `services` fields are gone.

**Filters.** A namespace selector offers All namespaces, every namespace with pods and the chosen one, whose pods may all be gone; its options are replaced only when that set changes and the choice is put straight back. `/` focuses a text box matching namespace, name or status, ignoring case; Escape clears it and returns to the table. Both filters apply to every snapshot through the pure `filter_pods` in `src/devops_cli/ui/projections.py`, and rows keep #684's namespace/name keys, so the cursor stays on its pod or the nearest row.

**Focus follows the tab.** Activating a top-level tab focuses its widget, `#k8s-table` at startup and on `1`, the now focusable log pane on the Logs tab, and the first focusable widget elsewhere, so the table's and log pane's keys work without pressing Tab. Textual activates the tab holding any widget whose focus event it handles, so a focus still in flight for the tab just left, the table's at startup for instance, switched the dashboard back; the top-level `DashboardTabs` ignores focus landing in a tab no longer shown.

**Container-aware logs, one stream at a time.** Enter streams the pod's default container (the `kubectl.kubernetes.io/default-container` annotation when the pod has that container, otherwise the first), `pod_log_source` passes it to `read_pod_logs`, and `c` in the Logs tab restarts the stream on the next container, init containers included, from the record. The pane title reads `<namespace>/<pod> [<container>] (1 of 3 containers)`. Each stream has its own stop flag and queue; starting one stops the previous one, and a lock around the stop check and the buffer write keeps a stopped stream from writing another line.

**Pod inspector.** `e` opens `PodInspector` (`src/devops_cli/ui/pod_inspector.py`), a modal listing the pod's containers from the snapshot's record and its 20 most recent events, fetched on a worker thread with `list_namespaced_event` and the field selector `involvedObject.kind=Pod,involvedObject.name=<pod>,involvedObject.uid=<uid>`. `PodEventInfo.from_event` orders and ages an event by `last_timestamp`, then `event_time`, `first_timestamp` and `metadata.creation_timestamp`, and counts it by `count`, then `series.count`, then 1, so events written through events.k8s.io/v1 read correctly. A failed call is shown in the dialog; Escape closes it. Cluster text in its cells is escaped.

**Summary and help.** `devops dashboard --summary` lists unhealthy pods first, shows the Kubernetes banner, and says how many pods past `DEFAULT_DASHBOARD_SUMMARY_POD_ROWS` (10) it left out. The help screen lists `/`, `e`, Escape and `c`.

Out of scope, as the issue records: node capacity and GPU allocation (#807), the pod manifest view (#808), the workload restart (#809), the port-forward state-file defect (#810) and the port-forward and service URL view (#811). `devops k8s stream-logs` keeps its Stern-or-kubectl behaviour.
