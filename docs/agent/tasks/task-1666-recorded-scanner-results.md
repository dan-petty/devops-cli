# Task: The Suite's Slowest Tests Run on Recorded Scanner Results, and No Test Starts a Real gh or Scanner (#1666)

**Issue**: [#1666](https://github.com/dan-petty/devops-cli/issues/1666)
**Scope**: scope/ci
**Feasibility**: At release/v0.2.38 954914e a scratch pytest plugin that recorded every `subprocess.Popen` argv per test showed the real spawns: Semgrep (`--config p/default`) and Gitleaks in `test_a_branch_cannot_loosen_its_own_review`, `test_review_pipeline_admit_inline_suppression_added_by_change` and `test_pipeline_multi_scanner_aggregation`; Semgrep, Gitleaks and Bandit in the two `tests/test_gateway_review_stall.py` tests; Gitleaks in `test_routed_files_only_branch_diff_makes_no_model_calls`; `uv venv` and `uv pip sync --require-hashes` in `test_devcontainer_post_create_scaffolds_agent_instructions`; and `sudo chown -R None:1000` in `test_ensure_path_ownership_and_mount_edge_cases`. No test started gh. The installed Semgrep 1.179.0, Gitleaks 8.30.1 and Bandit 1.9.4 are the versions `tools.lock` pins, so the runs recorded from them stand for the locked tools. Gitleaks 8.30.1, run as `build_gitleaks_cmd` runs it, printed no JSON on stdout for a clean file (exit 0) or for one holding a token (exit 1): without `--report-path` it writes no report, the adapter defect #1434 already names. The `uv audit` row was fixed by #1697 (`test_ci_maintain_live` patches `_returncode`).

## Description

- **The refusal.** An autouse, session-wide fixture in `tests/conftest.py`, `refuse_real_programs`, sits on `subprocess.Popen`, beneath `run_subprocess`, `run_gh`, `subprocess.run` and asyncio's subprocesses, and fails any test that would start gh or the binary of any scanner the security scanner registry holds, by the name at any path or the first word of a command string, before anything starts. It fails the test with `pytest.fail`, a `BaseException`, because the scanner adapters report any `Exception` as a failed scan: an `AssertionError` would have turned a refused scan into a passing test. Its docstring says #1310's hermetic floor, which refuses processes in general, replaces it.
- **The names.** `refused_programs()` in `tests/support/refused_programs.py` reads them once, when the guard is installed: `CONST_GH_CLI` and each registered scanner's `binary_name`. A scanner added to the registry is refused with no list to edit, and no test-only list sits in product code. Building the registry once a worker has collected its tests took 0.02-0.08 s in narrowed runs, since the conftest has already loaded the modules it imports; in a fresh process it takes about 2 s. Ruff and mypy are `BaseSecurityScanner` subclasses outside the registry, and are not refused: the swallowed-failures ratchet runs ruff for real, offline, over the source tree.
- **The scanner fake.** `ScannerFake` in `tests/support/fakes/scanners.py`, behind the `scanner_fake` fixture, doubles `shutil.which` and `subprocess.run`, the stdlib objects themselves, since the process edge has no seam yet (#775). Semgrep, Gitleaks and Bandit are found under the test's own directory and answer with the runs recorded from the real tools on 2026-10-20, through their adapters as a review starts them, over one file holding `print("hello")`: their commands, exit codes, stdout and stderr, in `tests/fixtures/scanner_runs/recorded_runs.json`. Every other program is found and run for real.
- **The contract suite.** `tests/test_scanner_contract.py` starts each adapter as a review does over the fake and checks that it makes the recorded command and reads the recorded run as a clean scan, and that each recording's version is the one `tools.lock` pins. Changing a recorded flag or version in the recordings failed it.
- **The six tests.** The three Semgrep tests in `tests/test_review_security_tools.py` and `tests/test_review_project_conventions.py`, the two in `tests/test_gateway_review_stall.py` and the Gitleaks one in `tests/ai/review/test_runner.py` ask for `scanner_fake`. Their assertions are unchanged; the trivy, kube-linter, pluto and Bandit patches already in `tests/test_review_security_tools.py` stay.
- **Docs.** `docs/TESTING.md` says the floor refuses a real gh and every registered security scanner, by names read from the registry, and how a test gets a scanner's output instead. It marks sudo, and uv installing or syncing from PyPI, as the target, and says the gate's `uv audit`, `uv tree --outdated` and `uv check` are its intended network checks, which no test runs. It lists the refusal and the scanner fake with its contract suite as existing.

## Acceptance Criteria

- [x] Tests first, offline: the refusal fails a test that would start a scanner binary or gh. It sits on `subprocess.Popen` rather than wrapping `run_subprocess`, so it also covers `run_gh`, a direct `subprocess.run` and asyncio, and reads the names from the scanner registry rather than from every `BaseSecurityScanner` subclass, which would refuse the ruff the swallowed-failures ratchet runs. Before the refusal existed, every refusal case in `tests/test_suite_refuses_real_programs.py` failed (`FileNotFoundError` for each program named at `/usr/local/bin`, `DID NOT RAISE` for the shell command and the handler of every exception), and the git case passed. Under the refusal and before the fake, the six scanner tests failed, each naming the real Bandit or Gitleaks it started; with `scanner_fake` they pass. No test started gh. One full run under a stricter list that also named uv and sudo caught one other test, `tests/test_release.py::test_uv_lock_check_offline_passes_after_bump`, which runs `uv lock --check --offline` on purpose.
- [x] The refusal's docstring says #1310's hermetic floor replaces it.
- [x] Each changed test keeps its assertions and passes with no network: the six tests, the contract suite and the refusal's tests passed under `unshare -rn`.
- [x] The named tests, alone with `-n 0` beside other agents' work (load average 12-25 on 16 CPUs): `test_a_branch_cannot_loosen_its_own_review` 14.66 s to 2.15 s, `test_review_pipeline_admit_inline_suppression_added_by_change` 11.89 s to 0.74 s, `test_five_personas_with_one_transient_503_sees_exactly_six_calls` 7.42 s to 0.86 s, `test_pipeline_multi_scanner_aggregation` 7.34 s to 0.77 s, `test_transport_answers_400_once_fails_without_second_attempt_and_reports_status` 7.30 s to 0.59 s and `test_routed_files_only_branch_diff_makes_no_model_calls` 1.00 s to 0.06 s: 49.6 s to 5.2 s.
