# Task: Every HTTP Client Dials Only Addresses Its Egress Level Allows, Checked at the Connect (#898)

**Issue**: [#898](https://github.com/dan-petty/devops-cli/issues/898)
**Status**: Done
**Milestone**: v0.2.29
**Priority**: priority/p1-high
**Scope**: scope/security

## Description

Every outbound HTTP guard checked a host name or a URL string, and httpx2 then resolved the name again when it opened the socket, so the checked address was never the dialled one. Measured offline at `910b823`: `web_fetch` made three checking lookups on the first hop, and at k = 3 a stub resolver's private answer reached the dial, which received the hostname `example.com`.

This item delivers the issue's "PR A" scope and closes #898. The remaining raw clients, the pre-flight removals, the deletion of `_resolve_host_ips` and `_enforce_non_private_ssrf`, the documentation crawler (with #1112) and `github/client.py` (after #983) move to the follow-up issue #1381, because readiness requires a pull request to close exactly one issue and this task file reads Done in the delivering commit.

## Key Changes

- **Policy module** (`src/devops_cli/http/egress.py`, new). `EgressLevel` (public, loopback, private) and `configured_level`, which reads `ai.allow_private_network` from the given `AIConfig` or the loaded settings when a client is built. `vet_addresses` (sync, `socket.getaddrinfo`) and `avet_addresses` (async, `anyio.getaddrinfo` in a worker thread, bounded by the connect timeout) resolve once, classify every answer with #897's predicates (`is_non_public_ip`, pydantic-ai's `is_cloud_metadata_ip`, the metadata names through the new `core.validation.is_cloud_metadata_name`, which `is_cloud_metadata_host` now uses for its name test too), refuse them all with `SSRFBlockedError` when any is unsafe, refuse scoped IPv6, and re-raise a lookup's `OSError` as `httpcore2.ConnectError`. `VettingBackend` and `AsyncVettingBackend` implement httpcore2's public `NetworkBackend` and `AsyncNetworkBackend`: they dial each vetted IP literal in turn through `SyncBackend` or `AnyIOBackend` and raise the last failure.
- **Factory** (`src/devops_cli/http/client.py`). `new_http_client` and `new_async_http_client` take a required `level` and own `verify`, `http2` and `limits`. `egress_transport` and `async_egress_transport` build httpx2's transport and replace its `_pool` with an `httpcore2.ConnectionPool` or `AsyncConnectionPool` holding the vetting backend, with one SSL context shared by both. Retries are opt-in (`retries=`). Client options are a `ClientOptions` TypedDict, so `proxy`, `mounts` and `transport` cannot be passed past the check. `connection_limits` moved here from `http/pool.py`.
- **Broker** (`src/devops_cli/http/broker.py`). One shared sync and async client per level, built by the factory; `request`, `arequest`, `new_client`, `get_client` and `get_async_client` take the level. The environment parser, the `allow_private_networks` argument, `validate_url` and the per-request `allow_private_network` extension are gone. The hooks check only the request's egress policy and the scheme, so the async hook no longer blocks the loop. Vault's one request path, `vault_request` (`security/vault_http.py`), which the broker, logins, leases and Transit share, and the memory profiler use the private level; Vault's same-origin redirect policy stays the request's egress policy, which the hook applies to every hop.
- **Shared pool** (`src/devops_cli/http/pool.py`). `get_shared_client` and `get_shared_async_client` take a level, which joins the pool key, and build through the factory. The AI client base (`ai/client/base.py`) passes the configured level and its retry count; the `:64-65`, `:73-74` and `:96-97` fallbacks are deleted, so a client that cannot be built raises. `k8s/service_http.py` uses the private level for the API-server proxy (with its TLS context) and for direct URLs.
- **web_fetch** (`ai/common_tools.py`). The public-only broker client; `_validate_fetch_hop` keeps the scheme and domain-list checks and makes no lookup. DuckDuckGo, Tavily, the harness documentation fetch and the Statuspage fetch, the factory's existing callers, are public-only.
- **Hand-rolled copies replaced.** Jaeger (`telemetry/waterfall.py`) requests its configured hostname through a loopback-level client, its `timeout` passed as `httpx2.Timeout(timeout)` so it bounds the connect as well as the read, as the probe's HTTP and OpenAPI clients do; `_is_unsafe_ip`, `_resolve_safe_jaeger_target`, `_is_blocked_metadata_host`, the f-string netloc and the Host header are deleted. The sandbox probe (`sandbox/probe.py`) uses private-level clients for HTTP and OpenAPI discovery, and `probe_tcp` dials through `VettingBackend` at the private level; `_resolve_safe_socket_addr` and `_is_blocked_metadata_host` are deleted. Tool downloads (`commands/install_tools.py`) use a public-only client whose request hook refuses any hop that is not https, replacing the `startswith("https://")` test and `validate_service_url`.
- **Flag parsers removed.** `validate_url` (`core/validation.py`), `LLMClient._allow_private_network` (`ai/client/unified.py`) and the broker no longer read `DEVOPS_CLI_AI_ALLOW_PRIVATE_NETWORK`; `ALLOW_PRIVATE_NETWORK_ENV` (`ai/client/network.py`, `ai/client/__init__.py`) and `CONST_AI_ALLOW_PRIVATE_NETWORK_ENV` are deleted. `config/env.py` still maps the variable onto `ai.allow_private_network`, the one source. The refusal message (`lang/en/messages.py`) names the setting and says other URLs must be public.
- **Dependencies.** `httpcore2==2.13.1` and `anyio==4.15.1`, both already locked, are declared in `pyproject.toml`; `uv lock --offline` refreshed `uv.lock`.
- **Review guidance and docs.** `AGENTS.md` (the SSRF distinction), `.devops/review.md` and the `HALLUCINATION-INTERNAL-SERVICE-PRIVATE-NETWORK` catalog entry say which factory-built connector gets which level, that metadata is refused at every level, that the other clients are not checked at the connect yet (the service connectors among them validate their URL before the request), and that SSRF findings still apply to public-level callers. `README.md`, `ARCHITECTURE.md`, `docs/ROUTINE_TASKS.md` and the knowledge base's `libraries/httpx2.md` describe the connect-time check for the clients the factory builds.
- **Tests.** `tests/test_http_egress.py` is new. `tests/web_fakes.py` gains `ConnectRecorder` (stands in for httpcore2's dial and records each dial's address and connect timeout, the TLS names and the bytes written per connection, whose Host headers h11 parses) and `ScriptedResolver` (answers change between lookups); h11 also serialises the canned responses, and is declared in the dev group at the locked 0.16.0. The session guard passes any host `getaddrinfo(host, None, flags=AI_NUMERICHOST)` accepts, so `2852039166` resolves in tests as glibc resolves it. `stub_web` vets each request's host with `vet_addresses` at the level of the factory-built transport it replaces. Tests that relied on the environment variable widening a direct `AIConfig` now resolve `example.com` through `public_dns`.

## Decisions

- **Link-local (owner decision, a merge gate).** Implemented the proposed answer: public and loopback levels refuse every link-local address; the private level refuses cloud metadata (pydantic-ai's `is_cloud_metadata_ip` and the metadata names) and admits other link-local addresses, such as rootless Podman's 169.254.1.2 host gateway, so the `host.docker.internal` setups in `docs/DEVCONTAINER_USAGE.md` keep working. This partly reverses #897's refusal of all link-local at the private level, for the connect-time check only; the pre-flight checks the follow-up removes still refuse it. Scoped IPv6 is refused at every level. Pinned by `test_link_local_host_gateways_are_admitted_only_at_the_private_level`.
- **Proxies (owner decision, a merge gate).** Implemented the proposed answer: factory clients ignore `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` (httpx2 reads them only without `transport=`), because a proxy would be the vetted peer instead of the destination. Pinned by `test_environment_proxies_are_ignored_and_the_destination_dialled`.
- **Retries are opt-in.** The skeptic was right: `create_retry_transport` raises `HTTPStatusError` for every status of 400 or more and retries 429, 5xx and connect errors with backoff from 1 s. Wrapping every client would break Vault's status read (503 sealed, 429 standby) and 404-vs-403 handling, the probe's expected-status check and Jaeger's non-200 path. Only the AI clients pass `retries=`, as they wrapped before. Pinned by `test_a_client_without_retries_returns_error_statuses_and_dials_once`.
- **The flag parsers go, not just move.** `validate_url` reads no flag at all rather than reading the settings: a check made with `allow_private=False` stays public-only, and the configured callers already pass `ai.allow_private_network`. The only production caller that relied on the variable widening a hard-coded `False` is the documentation crawler, which becomes public-only now, as the issue's table puts it; an `AIConfig` built in code takes its own flag. The changelog names both. The conftest's autouse variable no longer widens tests, so 11 test files that built `AIConfig` or `Settings` for `example.com` URLs now resolve them through `public_dns`; `test_private_ip_allowed_when_env_set` and `test_private_api_base_can_be_enabled_via_env` became tests that the variable never widens a check by itself.
- **Explicit levels at the broker.** The broker reads no flag: every caller passes its level (web_fetch public, Vault and the memory profiler private), so there is no default level to get wrong.
- **One lookup per hop changes criterion 7's k.** With a single lookup, a rebound answer is refused at k = 0; at k = 3 that lookup answers the public address, which is what is dialled. `test_web_fetch_refusal_reaches_the_runner_error_result` asserts the runner's `error` result at k = 0, and the k = 0 to 4 rebinding rows assert the dial is the public address or nothing for every k.
- **Re-baselined premises.** Since #897, `validate_url(allow_private=True)` already refuses the integer, hex, dotted-hex and ideographic spellings and NAT64/6to4/Teredo forms, and `validate_url_egress(allow_private=True)` refuses metadata and link-local. The "old vs new" tests assert the connect-time result; what was still open was a name answering metadata under `validate_url(allow_private=True)` and every check running before a dial that received the hostname.
- **httpcore2 2.13.1, not 2.13.0.** httpx2 2.13.1 is locked and pins `httpcore2==2.13.1`. `anyio` is declared as well, because `egress.py` imports it directly.
- **The cluster-service direct URL keeps its pre-flight.** `k8s/service_http.py` still calls `validate_url_egress(allow_private=True)` before the private-level client; removing pre-flight checks is the follow-up's.
- **Caller timeouts bound every phase (review).** The factory reads a bare number as the read timeout and keeps a 1 s connect, so `devops sandbox probe --timeout N` and a Jaeger query would no longer have bounded the connect by N. The probe's HTTP and OpenAPI clients and Jaeger pass `httpx2.Timeout(timeout)`, which bounds every phase as `httpx2.Client(timeout=N)` did. The broker, Kubernetes, install-tools and search callers pass a per-request number, which overrides every phase, so they are unchanged; the Statuspage fetch already used the factory's read-only meaning. Pinned by `test_the_probe_timeout_bounds_every_connect` and `test_the_jaeger_timeout_bounds_the_connect`, which see a 1.0 s connect on the previous call sites.
- **The docs claim only what this item delivers (review).** The guidance and docs name the factory-built clients as the ones checked at the connect and say the others are not checked there yet; only the service connectors among them (Loki, Prometheus, Grafana, ArgoCD, the AI providers) are said to validate their URL before the request, because the OTLP exporter and the fixed GitHub, Cloudflare and OSV clients validate none. They carry no follow-up number: the follow-up updates them when it moves the rest.
- **Tests double only the edges (review).** The level table runs each caller twice with its host answering 127.0.0.1 and then 10.0.0.1 and reads the level from what reached the dial (public dials neither, loopback the first, private both), one test per caller and flag, instead of spying `vet_addresses`; it counts only dials to the answer, because the test configuration's telemetry exporter dials its collector from a background thread. The fail-closed test builds the client against a missing `SSL_CERT_FILE`, and the pool tests read the real client's httpcore2 pool. The memory profiler swaps its broker client's transport for an in-memory ASGI app, so its level is not observable; its test now asserts that the workload makes no lookup and no dial, and the private level it passes is not pinned.
- **Overlaps.** #709 merged first and routed every Vault request through `vault_request` (`security/vault_http.py`). That one call passes `level=EgressLevel.PRIVATE` and keeps #709's same-origin policy as the request's egress policy, so the broker's hook still refuses a hop off the Vault origin before the token or a login body is sent, and the connect refuses cloud metadata. `test_post_routes_through_the_egress_validated_broker` pins the level and the policy on the call, and the level table's Vault status and lease rows pin the private level at the dial. #1120 deletes the `import httpx` fallbacks in `http/broker.py` and `telemetry/memory_profiler.py`, which this item leaves in place.

- [x] **TLS stays on the hostname**: `start_tls` receives `server_hostname="example.com"`, the context has `check_hostname=True` and `CERT_REQUIRED`, Host is `example.com` and `response.url` is `https://example.com/` (`test_tls_and_the_host_header_keep_the_hostname`).

- [x] **Three levels**, metadata refused at every level, link-local per the proposed answer (`test_each_level_admits_only_its_address_classes`, `test_link_local_host_gateways_are_admitted_only_at_the_private_level`).
- [x] **Rebinding** (criterion 1): `web_fetch` without `stub_web`, k = 0 to 4 against 169.254.169.254, 127.0.0.1 and 10.0.0.1, with the environment flag set; the dial receives 93.184.215.14 or nothing, never a hostname (`test_web_fetch_never_dials_a_rebound_answer`).
- [x] **Redirect to a second hostname** (criterion 2) for every k (`test_web_fetch_never_dials_a_rebound_redirect_hop`), and **one hostname per connection** (criterion 3) with `start_tls` names `example.com` then `example.org` (`test_web_fetch_opens_one_connection_per_hostname_with_its_own_tls_name`).
- [x] **The environment does not widen web_fetch** (criterion 4): the rebinding and redirect rows run with `DEVOPS_CLI_AI_ALLOW_PRIVATE_NETWORK=true` and `ai.allow_private_network: true`.

- [x] **Isolation**: a private-level connection is never reused by a public-level request, through the broker and the pool keys.
