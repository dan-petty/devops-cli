## Description
Only INVALIDATED verdicts were checked against evidence. A model's MITIGATED verdict needed a mechanism and a perimeter to be named, never to exist, and `derive_recommendation` leaves MITIGATED findings out. Through `_apply_single_finding_verification`, a HIGH "Command injection via os.system" finding with the mechanism "shlex.quote wrapper in safe_exec", the perimeter `src/does/not/exist.py` and line 999 of a four-line file cited came out MITIGATED with `verified_by=llm`, no note and APPROVE, and a model VERIFIED verdict citing line 999 also passed. In review session `20261001-224227` all 28 MITIGATED findings were reported and counted as defects: 18 mechanisms name no code identifier, 5 describe the defect itself, 2 perimeters are `.devops/review.md`, and 11 carry `verified=True` because `_build_verdict_updates` made MITIGATED verified. `mitigations._normalize_path` used `.lstrip("./")`, which cut the dot off `.github/...` and `.devops/...` and the root off an absolute path.

The scope added on 2026-10-03 from review sessions `20261003-005122` (S7) and `20261003-012555` (S8) (`.data/review-evaluation-20261003-s7-s8.md`, D8): a confirmation or mitigation whose own reason refutes the claim was applied as given. In S8 qwen3-coder returned VERIFIED on `workspace.py:43` and `main.py:84` with reasons saying no untrusted input reaches the import (cache `llm_6818ef36`, `llm_f3d7fc26`), and #948's ranking put both among the report's top 8 rows. In S7 it returned 3 MITIGATED verdicts whose reasons argue the defect away (`llm_3ec3580c`, `llm_54a55488`, `llm_952922a2`) and a VERIFIED one (`llm_4617de34`) whose reason says "the test execution passes" while that criterion had failed with `No module named 'pytest'`. Replayed on this branch before the fix, `llm_6818ef36` gave `('VERIFIED', 'llm', None, True)`.

What the merged v0.2.25 items left: #846 made `_extract_citation_line` read explicit citation keys only, added the note kinds `compute_verdict_distributions` counts (`CONST_VERIFICATION_NOTE_KINDS`) and the `VERDICT_FIELDS` copy-back, which carries `verified` back onto the saved finding. #948 lists MITIGATED findings apart in the summary. #949 and #950 record a person's MITIGATED verdict in the ledger. None of them checked a mitigation's perimeter or mechanism, a confirmation's citation, or a confirmation's or mitigation's reason against the claim; #846's self-refutation guard (`_without_self_refutation`) checks only the reverse, an invalidation whose reason confirms. #790's placeholder set has not landed, so the existing `_is_placeholder` and `_NO_VALUES` stay. #789 (multi-page recompose drops UNVERIFIED findings) is open and untouched. #1021 and #1018 (refutation guards, removed-symbol refutations) are not part of this change.

## Key Changes
- **Mitigations** (`ai/review/verification.py`). `_unproven_mitigation_note` runs on every model MITIGATED verdict: `_mitigation_presence_gap` (reason, mechanism and perimeter named; it replaces `_determine_mitigated_degradation_note`), then `_mitigation_evidence_gap`. A mechanism matching `CONST_SELF_NEGATING_MECHANISM_PATTERN` (`but (does )?not|is expected to|intended to|too permissive`, `config/constants.py`) describes the defect. `_perimeter_gap` resolves each perimeter file with `_perimeter_file`: an absolute path is refused outright, and a relative one goes through `_file_in_reviewed_tree`, that is `safe_resolve_subpath(root, path, must_exist=True)` for the review's target and its repository (`_reviewed_tree_roots`; a pull request's head, written outside any repository, has only its own files), so a `../` escape, a symlink, a directory or a missing file is unresolved. A perimeter `classify_file_context` reads as documentation (`CONST_DOC_EXTENSIONS`, `CONST_DOC_FILENAMES`, documentation MIME types) is no perimeter. Then `_extract_code_symbols(mechanism)` must name an identifier that a perimeter file or the finding's own file holds as a whole word, read with the 50 MB cap (`DEFAULT_MAX_AST_FILE_SIZE_BYTES`). The finding's own file goes through `_file_in_reviewed_tree` directly, so a scanner's absolute location inside the tree is read (`safe_resolve_subpath` accepts an absolute path inside its base and refuses one outside). A failed check makes the verdict UNVERIFIED and reportable, without the line it cited, with the note `mitigation-unproven: <check>` (`CONST_MITIGATION_UNPROVEN`), which names the perimeter path or the identifiers. A verdict that claims a mitigation and is left UNVERIFIED for want of a part it never named gets the same kind.
- **Confirmations**. `_citation_outside_file` downgrades a model VERIFIED verdict whose `citation_line` is below 1, or past the end of the finding's file in the reviewed tree, to UNVERIFIED with `citation-out-of-range: line <n> of <file> (<lines> lines)` (`CONST_CITATION_OUT_OF_RANGE`) and drops the citation. The finding's file is read where its location points, absolute or relative. A verdict without a citation, or whose file is not in the tree, is left as it was.
- **Contradictions** (`ai/review/verification.py`). `_contradiction_note` runs first on every model VERIFIED and MITIGATED verdict. `_denial_of_the_claim` mirrors `_reason_confirms` on the same claim words (`_claim_words` of the verification criteria and the title) and the same `_NEGATION`, but reads where the negation points: a negation (not "without", which names a missing guard as a confirmation does, nor "already") followed, past fillers ("the", "any", "actual") and bridges ("derived from", "controlled by"), by at least two consecutive claim words that the claim does not negate itself (`_negated_in_claim`: up to five words after "no", "not", "missing" or "lacks", three before "missing" or "disabled"). `_claims_a_failed_criterion_passed` matches `CONST_CRITERION_PASSED_CLAIM_PATTERN` (a test, command, criterion or check that "passes" or "succeeds" with nothing after it, or exit status 0) when the finding has executable criteria runs and none passed. Either makes the verdict UNVERIFIED and reportable, without its citation, with `verifier-contradiction: the <status> verdict's reason denies the claim ('<words>')` or `... says a criterion passed ('<words>'), but its recorded run failed` (`CONST_VERIFIER_CONTRADICTION`). The plain mirror (any negation and 60% of the claim's words) was measured first and rejected: over 778 VERIFIED and MITIGATED verdicts in 529 cached verifier replies (`.data/cache/llm`, the claim read from the title each reply repeats) it set aside 318, mostly confirmations that negate a guard ("does not prevent path traversal", "without a default value"). This guard sets aside 13 of the 778; 12 argue their finding away ("no user input", "not derived from untrusted user input", "no hardcoded secret", "no ambiguous command reference"), and the 13th quotes a convention ("not overly complex") in a reason that also says the finding "cannot be fully verified".
- **Structure**. `_resolve_status_and_verification_note` dispatches to `_resolve_refutation` (the unchanged INVALIDATED path), the contradiction check, the mitigation note and the citation check, and `_mitigation_fields` passes the mechanism, perimeter and regression test only for MITIGATED; `_build_finding_verdict_kwargs` is gone. Both functions are back under the complexity cap (12 each before, by `devops scan complexity`). Each verdict is still resolved on its own in `_apply_bound_verdicts_to_findings`.
- **The flag** (`ai/review/verdicts.py`, `ai/review_schema.py`). `_build_verdict_updates` writes MITIGATED with `verified=False`, for every adjudicator, and `_merge_two_findings` does the same when the best status is MITIGATED.
- **Distributions**. `mitigation-unproven`, `citation-out-of-range` and `verifier-contradiction` join `CONST_VERIFICATION_NOTE_KINDS`, so `compute_verdict_distributions` counts them in `profile.json`'s `verdict_distributions.verification_note`.
- **Perimeter matching** (`ai/review/mitigations.py`). `_normalize_path` strips a leading `./` only and reads an absolute path inside the repository relative to its root; `find_perimeter_changes` takes that root as `repo_root`, the current repository's (`find_repo_root()`) by default, as `devops pr check-readiness` and branch and pull request reviews call it. A person's MITIGATED verdict on a scanner finding records the finding's absolute location as its perimeter (`record_mitigated_finding`), so without this the warning never fired for it. `_is_path_matching` matches an absolute path, now one outside the repository, only to itself; two relative paths still match when one ends in the other.
- **Prompt and docs**. `ai/tasks/verify_finding_system.md` tells the verifier a perimeter is a repository-relative path to code or configuration, not documentation, that the mechanism names an identifier in backticks which a perimeter file or the finding's file holds, and that a mechanism describing the defect is no mitigation. The review knowledge base (`ai/knowledge_base/devops_cli/tasks/ai_code_review.md`) describes the rules, the contradiction check included. The verifier prompt does not mention the contradiction check.
- **Tests**. `tests/test_verdict_writers.py` holds the new tests. `tests/golden/review_findings.json` gains `app/shell.py`, the real defect `shell-injection`, four `fabricated_verdicts`, which `tests/test_review_regression_harness.py::test_a_verdict_pointing_at_no_evidence_leaves_the_defect_reported` drives with the golden files as the reviewed tree, and six `contradicting_verdicts`, the six cached replies trimmed to the finding (from the session's `candidates.json`) and the verdict's status fields, reason, citation, mechanism and perimeter, which `test_a_verdict_its_own_reason_contradicts_is_not_applied` drives the same way. Five existing tests encoded a MITIGATED verdict on a perimeter that does not exist, a mechanism naming no identifier, or MITIGATED meaning verified, and now give a reviewed tree that holds the mechanism or expect `verified=False`: `test_mitigating_mechanism_annotation` and `test_review_verify_cli_command` (`tests/test_verdict_writers.py`), `test_apply_single_finding_verification` and `test_verdicts_are_read_as_the_model_meant_them` (`tests/test_review_verification.py`), and `test_a_mitigated_finding_is_reported_with_its_mitigation` (`tests/test_review_project_conventions.py`).
