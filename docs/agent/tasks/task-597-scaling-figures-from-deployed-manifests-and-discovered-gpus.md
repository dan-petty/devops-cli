## 1. Description & Objectives

`GatewayRouter.scale_vllm` and `scale_lightllm` (`src/devops_cli/ai/gateway.py:541-622`) multiply by a literal 24 GB per GPU and default tensor parallelism to literals. `--apply` only runs `kubectl scale --replicas` (`gateway.py:338`), yet both MCP tools claim to "Inspect or configure" (`ai/mcp/server.py:2764,2787`). The CLI drops `--tensor-parallel-size` for LightLLM and sends every other backend, `vllm-single` included, to the dual-GPU branch (`commands/ai_gateway.py:246-247`). vibes observation 20 §2c found the model id, TP=2 and 24 GB literals in the vLLM scaler. #457 has since moved vLLM identity into `DEFAULT_VLLM_*` (`config/defaults.py:86-90`), which is still a hand-written copy of the manifests. KV-cache discovery (`ai/gateway_bench.py:71`) and GPU discovery (`ai/gateway_tune.py:188-228`) already exist, but only `tune` uses them. The cluster runs no LightLLM or Portkey Deployment (`kubectl get deploy -n llm`).

- Deliverable*: PR1: remove `--tensor-parallel-size` from `scale` and both MCP tools. Reword the tool descriptions to "Inspect" and regenerate `docs/MCP_TOOLS.md` and the CLI reference. Reject an unknown `--backend`, add `vllm-single`, and report GPU memory from `deployment_gpus`, or "unknown", never 24. A fixture test asserts that the report changes when a manifest's model or TP changes. PR3 (optional): a fit column comparing `engine_info` `kv_cache_tokens` with max-model-len. Point #453's Remaining note here. Whether to retire or deploy LightLLM and Portkey is a separate decision.
- Constraint*: A hand-written registry is one more copy of each model name. LightLLM already has two: `gateway.py:88` routes it as `qwen2.5-coder:14b`, while its manifest serves Llama 3.3 70B. `DEFAULT_K8S_DIR` is relative to the working directory (`config/defaults.py:432`) and `k8s/` is not in the wheel, so files in the checkout do not show what is deployed. Do not gate on `estimate_hardware_requirements` (`security/aibom.py:73`). It puts the working 65536-token dual-GPU profile at 56.0 GB, against the 48 GB that `scale` reports, so a gate on either figure would reject a working deployment or pass a phantom one. Do not import vLLM's argument parser, which pulls in the whole engine. A weight estimate from safetensors headers would add `huggingface_hub`, which is absent from `uv.lock`, so it stays future work.

With `["scale", "--backend", "vllm", "--tensor-parallel-size", "4", "--format", "json"]` it returns `total_vram_gb` 96 and status `inspected`. `["scale", "--backend", "vllm-single", "--format", "json"]` returns the dual-GPU 32B model. `grep -cE '\b24\b' src/devops_cli/ai/gateway.py` returns 4.
