## 1. Description & Objectives

The review's static stage picks analyzers by file suffix in `_run_static_scanners` (`ai/review/pipeline.py:1165-1229`). Bandit runs on `.py`, Kube-linter and Pluto on YAML, Trivy on container files and lockfiles, and Gitleaks and Semgrep `p/default` on every file. `_STATIC_ANALYZERS` (`pipeline.py:849-856`) has no Go entry, and neither do the registry's 11 scanners (`security/registry.py:16-42`), so a `.go` file gets only generic rules. SARIF ingestion already exists (`security/sarif.py:311`, `security/normalization.py:308`). The review already reports a missing binary as not run (#516, `pipeline.py:860-872`). `.devops/review.md` already carries per-repo rules into persona prompts (`ai/review/review_environment.py:74`). vibes wrote its own pprof goroutine classifier. Its survey lists `uber-go/goleak` as the maintained alternative (`docs/landscape/SURVEY.md:36`), and its roadmap plans a golangci-lint integration (`docs/ROADMAP.md:63`).

- Deliverable*: Add a `GolangciLintScanner` to the registry. It requests SARIF output and converts it with `from_sarif` and `to_finding`, so no bespoke parser is needed. Default linters are errcheck, govet (with lostcancel) and staticcheck; contextcheck is opt-in. Add a `go` kind and a golangci-lint row to `_STATIC_ANALYZERS`. Add a `.go` branch in `_run_static_scanners` that runs once per nearest `go.mod` root and keeps only findings in reviewed files, using `_match_static_findings_to_files`. Add a golangci-lint entry in `commands/install_tools.py`. Keep the suffix dispatch and do not reroute the stage through the registry. Do not port the vibes classifier or `tools/cpp_lifetime_sentinel.py`. File two follow-ups separately. The first is a Go persona addendum that recommends goleak. It is blocked on Model-in-the-Loop Prompt Benchmarking and on a goroutine defect template, which `ai/review/defects.py` does not have. The second is clang-tidy with a `compile_commands.json`, only once the `fmt` sample shows a recall gap.
- Constraint*: golangci-lint loads packages through the Go toolchain. It needs `go` on PATH and module dependencies it can resolve, and it runs per module, not per file list. A missing `go`, a package-load or typecheck failure, and a missing binary must each record their own analyzer state, never zero findings. The registry path still returns `[]` for a missing binary (`security/base.py:93-97`), so `devops scan report` needs the same guard for this scanner. A first run on an existing tree floods the review. Branch reviews should use golangci-lint's own `--new-from-merge-base` rather than a hand-rolled baseline. Measure before claiming value: run `devops review samples validate --review` on the `go` category (cobra) before and after the change.
- Measured*: The vibes classifier reports CLEAN at 100.0 on a hand-built dump that has a `chan send` goroutine under `runtime.gopark` (`python3 -B probe/probe_leak.py`). One managed repository holds 359 non-vendored `.go` files (`find <repo> -name '*.go' -not -path '*/vendor/*' | wc -l`), and it tracks none of them (`git -C <repo> ls-files '*.go' | wc -l` gives 0). All 3 saved Go sample validations have `review: null` (`.data/reviews/sample-validations/*/go.json`), so Go review recall has never been measured.
