# Task: Polyglot Outlines Parse With Tree-Sitter, Token Estimates Match the Outline, and AST Queries Check Size First (#959)

**Issue**: [#959](https://github.com/dan-petty/devops-cli/issues/959)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p3-low
**Scope**: scope/ai

## Description
A triage of review session `20261001-224227` against `release/v0.2.25` (c279c18) upheld four low-severity defects in the AST engine and the inspection outlines. Each is fixed as its **Fix** line says, and each has a regression test that fails on the base revision (e3ff98c) and passes here.

- **Outlines use tree-sitter** (`ai/inspection.py`). `_build_polyglot_topology`, `_build_polyglot_structural` and `_find_symbol_or_lines_range` called `FallbackASTParser` directly, so every non-Python file was outlined by regexes, at all three levels. A Python file that does not compile went the same way. They now take a `PolyglotFileMap` from one helper, `_parse_polyglot`, which calls `TreeSitterEngine().parse_code(content, lang, str(path))`. The engine keeps its own fallback to the regex parser when a grammar finds nothing. Each call to `generate_semantic_outline` builds one level, so each call parses the file at most once. `inspection.py` no longer imports `FallbackASTParser`. The helper takes the language from `detect_language(path, content)`, which gains an optional `content` argument: given it, a `.h` header is C++ when its content uses C++ (the engine's `_header_language`) and C otherwise, as `parse_file` and `query_file` read it. The outline's `language` comes from the same call. Inspection had mapped every `.h` to C, so a C++ header's outline was labelled `c` and listed none of its classes, and once routed through tree-sitter it listed the header's namespace and class as functions.
- **Level 0 lists every method** (`ai/inspection.py`). `_build_polyglot_topology` listed a method only under a class named by its `parent_scope`, so a method with no owner, or an owner the file does not declare, was counted in `total_symbols` and shown nowhere. A method whose class the file declares is still listed under it. Any other is now listed among the functions: by `Owner.name` when it has an owner (a Go method on a type declared in another file of the package, `Server.Close`), and by its own name otherwise (a C++ out-of-class definition, `Widget::draw`, which tree-sitter already names by its qualified name). The C++ definition keeps no `parent_scope`, as `tests/test_ast_more_languages.py` pins for `fmt::basic_appender<char>::push_back`. The issue's base listed `Widget::draw` among the functions too.
- **Tree-sitter gives a Go method its type and signs a symbol with the line holding its name** (`ai/ast/engine.py`). `_extract_native_symbols` took a symbol's scope only from an enclosing class, interface or struct, so every Go `method_declaration` had no owner. The new `_go_receiver_type` reads the type its receiver names, through a pointer, type arguments or parentheses (`(l *List[T])` is `List`'s), as the regex fallback already did. Before inspection used tree-sitter, Level 0 put Go methods under their struct through the fallback, so without this they would have vanished. The engine also signed a symbol with the line its node starts on, which for a Java method under an annotation, a C# one under an attribute or a TypeScript class under a decorator is that annotation, `@Override`. It now signs with the row of the node's `name` field and uses the start row only for a node without one. A known gap is left: a C or C++ definition whose return type sits on its own line above the name, as GNU style writes it, is still signed with the return-type line. Its node has no `name` field, and taking the declarator's row instead would sign a multi-line `typedef struct {...} name;` with its closing line.
- **The fallback signs with the declaration line** (`ai/ast/fallback.py`). The fallback now signs every symbol with the line that declares its name (`line.strip()`), as `_extract_native_symbols` does. A new `_declared` helper builds each one-line symbol, which replaced 20 hand-built `PolyglotSymbol(...)` calls. For Python, `_py_declaration_line` takes the `def` or `class` line, after any decorators. It replaces the fallback's own `_extract_py_signature`, which rebuilt `(args) -> ret` and is deleted. Classes, structs, interfaces and Terraform blocks, which had no signature, now get theirs. In a TypeScript skeleton the line `  (x: string, y: number)` becomes `  export function a(x: string, y: number): Promise<void> {}`.
- **Fallback patterns harden as the issue says.** `RE_RS_FN` accepts `pub(...)` visibility, any of the qualifiers the Rust reference's grammar allows (`const`, `async`, `safe`, `unsafe`, `extern` with an optional ABI), and generics before the parameters. `RE_TS_FUNC` accepts an `export default` prefix and generics. Both use `<.*?>` instead of the issue's `<[^>]*>`, because `[^>]*` stops at the first `>` and so misses nested generics such as `<T: Into<String>>`. The parameter groups the patterns no longer need are dropped.
- **Topology tokens are measured** (`ai/inspection.py`). `_render_topology_markdown` now delegates to `_render_topology(top)`, and `_resolve_topology_level` sets `estimated_tokens = estimate_tokens(_render_topology(topology))` for both paths. `generate_semantic_outline` already reported that value as `outline_tokens`. The `text_repr` plus `total_syms * 6` guess in `_build_python_topology` and the `max(1, total_syms * 6)` guess in `_build_polyglot_topology` are deleted, and the builders leave the field at 0 for the caller to measure. The structural level is unchanged: it already counts the skeleton it emits. Its fenced block adds only the fence lines, and the issue made counting them optional. For `SAMPLE_HOTSPOT_PYTHON` the topology measures 149 tokens where the guess said 33. For `inspection.py` as it stands here, it measures 1351 tokens where the guess gives 291, so the guess claimed a reduction of 96.4% against a real 83.2%.
- **AST queries check size first** (`ai/ast/engine.py`, `commands/ai_ast.py`). The new `TreeSitterEngine.query_file(path, sexpr)` returns None for an unknown language, a file it cannot stat or read, or a file over `max_file_size_bytes`. It reads nothing until the size check passes, then runs `query_code`. It shares `_mtime_within_cap` (the stat and size guard) and `_read_source` (the read, and the language from `detect_language(path, content)`, which reads a `.h` header's from its content) with `parse_file`, which now uses both. `ast_parse_cmd --query` calls `query_file`. On None it prints the same "Unsupported language or file size exceeded" error as the parse branch, through one `_exit_unparsable` helper, and exits 1. One behaviour change follows: a file with an unknown extension used to be queried as Python and now exits 1, as a plain parse always did. The optional `_validate_inspect_path` step was not added. The issue left it optional, and it would apply inspection's own path and size policy to `ai ast`, a change of its own.
- **Docs.** The `--level` help (`lang/en/help.py`) and the `inspection.py` module docstring promised a Level 0 outline under 200 tokens. Only the guess supported that figure; `inspection.py`'s own topology measures 1351. Both now describe what the topology holds. `docs/CLI_REFERENCE.md` and `docs/commands/ai.md` are regenerated. `test_level_0_topology_outline` now bounds the sample's measured count from both sides (`100 < tokens < 200`), so the old guess of 33 fails it.
- **Left as they were, outside this issue.** `query_code`'s native branch calls `Language.query`, which tree-sitter 0.26 does not have, so every `--query` is answered by the keyword filter over parsed symbols (`_matches_sexpr_filter`) and never by real S-expression captures. `RE_JAVA_METHOD` takes `return new Foo();` for a method named `Foo`. Neither is changed here.

## Acceptance Criteria
- [x] Each defect is fixed as its **Fix** line describes. There are two differences, both explained above: the generics pattern is `<.*?>`, which also matches nested generics, and the optional `_validate_inspect_path` step was not added. The fallback signature change also covers Python, classes and the other one-line symbols. Both engines now sign a symbol with the line that holds its name, and the agreement test checks it for Python, TypeScript (with a decorated class), Go, Rust, Java (with annotations) and C# (with attributes). They do not find the same symbols everywhere: the fallback still scopes no TypeScript or Java method to its class, and the GNU-style C gap above remains.
- [x] Each defect has its regression test, offline and red on e3ff98c. For the red run, the base `src` was exported with `git archive` and put first on the path (`-o pythonpath=<base src>`). 19 cases failed; on this branch all 19 pass:
  - Signatures: `tests/test_ai_inspection.py::test_polyglot_structural_skeleton_keeps_names_and_return_types`. Red: `assert (False, False) == (True, True)`, because the skeleton was `  (x: string, y: number)`.
  - Rust: `tests/test_ai_inspection.py::test_rust_outline_finds_generic_const_unsafe_fns`. Red: `assert ({'plain'}, 1, False) == ({'plain', 'process', 'c', 'u'}, 2, True)`. The fallback-only test the issue asks for is `tests/test_treesitter_engine.py::test_fallback_finds_generic_and_qualified_rust_and_typescript_functions`, which also covers `pub(crate) unsafe extern "C" fn`, `pub async fn f<'a>`, `function identity<T>` and `export default function`. Red: `assert (['plain'], []) == ([...6 names], ['identity', 'main'])`.
  - Tokens: `tests/test_ai_inspection.py::test_topology_outline_tokens_match_rendered_markdown[python]` and `[polyglot]`, a TypeScript file through the polyglot path. Each asserts that `outline_tokens` and `topology.estimated_tokens` equal `estimate_tokens(_render_topology_markdown(outline))`, which is stricter than the issue's 10% tolerance. Red: `(33, 33) == (149, 149)` and `(36, 36) == (49, 49)`. The updated `test_level_0_topology_outline` is red too: `(False, True) == (True, True)`.
  - Size cap: `tests/test_ai_ast_cli.py::test_ast_parse_query_respects_size_cap`, with `TreeSitterEngine` patched to a 100-byte cap and a file of about 1 KB. Red: `(0, True, False, 0, True) == (1, False, True, 0, True)`, because the query exited 0 and printed the match for `f`. The same test checks that a file within the cap is still queried. `tests/test_treesitter_engine.py::test_query_file_checks_size_and_language_before_reading` pins `query_file` itself: matches for a small file, and None for a file over the cap, an unknown extension and a missing file. It also checks that a C++ `.h` header is queried as C++. Red: `AttributeError: ... no attribute 'query_file'`.
  - One meaning for a signature: `tests/test_treesitter_engine.py::test_fallback_signs_symbols_with_their_declaration_line_as_tree_sitter_does[python|typescript|go|rust|java|csharp]`. Each case asserts that the fallback and tree-sitter give the same `(name, signature)` pairs for a snippet. All 6 red, for example `('NewWorkerPool', '(workers int)')` against `('NewWorkerPool', 'func NewWorkerPool(workers int) *WorkerPool {')`, and for C# `('Get', 'public ActionResult<User> Get(int id)')` against tree-sitter's `('Get', '[HttpGet("{id}")]')`.
  - Tree-sitter wiring: `tests/test_ai_inspection.py::test_polyglot_outlines_come_from_tree_sitter` passes only when inspection parses through tree-sitter. Its TypeScript class must list `login` and `logout` at Level 0, and `--symbol validateEmail` must span lines 13-15. The regex fallback scopes no TypeScript method to a class and spans every symbol by one line. Red: `[('UserPayload', []), ('AuthService', [])]` and `(13, 13)`.
  - Methods at Level 0: `tests/test_ai_inspection.py::test_polyglot_topology_keeps_go_receiver_and_cpp_out_of_class_methods` asserts `WorkerPool [Start, Stop]` with `NewWorkerPool` and `Server.Close` among the functions, `Widget [width]` with `Widget::draw` and `helper`, and the breadcrumbs `WorkerPool > Start`. Red on e3ff98c because `Server.Close` was left out. `tests/test_treesitter_engine.py::test_go_methods_belong_to_their_receiver_type` pins the receiver forms. Red: `('Start', None) != ('Start', 'WorkerPool')`.
  - Annotated signatures: `tests/test_ai_inspection.py::test_polyglot_skeleton_signs_annotated_methods_with_their_declaration` asserts the Java and C# Level 1 skeleton lines. Red on e3ff98c: `['class OrderService', '  ()', '  (Cart cart)']`.
  - Headers: `tests/test_ai_inspection.py::test_polyglot_outline_reads_a_header_as_cpp_only_when_its_content_is` asserts that a C++ `.h` header is outlined as `cpp` with `writer [size]` and `--symbol size` at line 5 under `writer > size`, and that a C header stays `c` with `point`, `add` and `twice`. Red on e3ff98c: `('c', [], []) != ('cpp', [('writer', ['size'])], [])`. Before the fix on this branch it read `('c', [], ['fmt', 'writer'])`, and `--symbol size` fell back to lines 1-7.
  - The Go, C++, wiring and annotation tests and the `csharp` case came from a review of this change, which found that routing inspection through tree-sitter had dropped Go receiver methods and C++ out-of-class definitions from Level 0, and that annotated Java and C# methods were signed with their annotation.
