## 1. Description & Objectives

Ollama slot leases (`src/devops_cli/ai/client/network.py:169`) and pydantic-ai limiters (`src/devops_cli/ai/concurrency.py:31`) count per process; GitHub pacing is already cross-process (`src/devops_cli/github/rate_limiter.py:243`). `devops ai prewarm` sends `keep_alive: 1h` (`src/devops_cli/ai/client/ollama.py:60`). Chat and stream bodies omit it (`ollama.py:287`, `:463`), `devops ai chat` then calls through pydantic-ai (`src/devops_cli/commands/ai.py:1046`), and no manifest sets `OLLAMA_KEEP_ALIVE`. A request without it resets expiry to the server default, so the lease is probably cut short; unchecked on a live server. Each of the 2 Ollama pods is routed 3 named models against `OLLAMA_MAX_LOADED_MODELS` 2 (`k8s/llm/ollama.yaml:66-67`); the direct embedding task adds another (#481). No ms/token metric exists, only a tokens/s span attribute on direct non-streaming Ollama calls (`src/devops_cli/ai/client/unified.py:69`), and nothing reads `/api/ps`. vibes `observations/systems/06` reports 45 to over 2,500 ms/token under eviction cycles, with no method; its claim that prewarm pins VRAM is contradicted above.
