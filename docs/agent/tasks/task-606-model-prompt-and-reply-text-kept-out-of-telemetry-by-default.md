## 1. Description & Objectives

When `--logfire` or `telemetry.logfire: true` is set (commands/review.py:146-160), `LogfireBridge.configure` calls `logfire.instrument_pydantic()` and `instrument_pydantic_ai()` with no arguments and passes no `scrubbing` (telemetry/logfire.py:206-217); once a token resolves, spans go to Logfire (logfire.py:191-198). Review personas run through devops-cli's own `PydanticAgent` and `LLMClient`, not `pydantic_ai.Agent`, so today's leak is `instrument_pydantic` at its default `record='all'`: validation spans carry the prompt and reply held in `CachedLLMResponse` and `AgentResponse`. Separately, every native `ai.llm.dispatch` span carries `gen_ai.prompt_preview` (ai/client/unified.py:372), every successful one `gen_ai.response_preview` (:92), exported unmasked (telemetry/tracer.py:871-888) with native export on by default (config/settings.py:263). `redact_text` (security/sanitizer.py:177) has no private-host pattern. vibes documents collector-side scrubbing its shipped collector config never implements.
