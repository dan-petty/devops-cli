## 1. Description & Objectives

Two hand-rolled FSMs implement one think-block sanitizer: `ThinkingStreamProcessor` (`src/devops_cli/ai/thinking_stream.py:51`, used by chat at `commands/ai.py:881-884`) and `StreamingTokenProcessor` (`src/devops_cli/ai/client/streaming.py:23`, behind `sanitize=True` at `client/unified.py:793-796`, unused in `src/`). Both start only in EMITTING (`thinking_stream.py:74`, `streaming.py:58`), so a closing tag seen while emitting passes through as text (`_process_outside_think` seeks only the open tag, `thinking_stream.py:135-157`); `strip_think_blocks`/`extract_think_blocks` (`thinking_stream.py:15-40`), the review pipeline's path (`review/runner.py:457`, `client/structured.py:50,104`, `response_repair.py:53`), match only open…close pairs. Neither caps the thought buffer (`streaming.py:64-69` bounds only the whole stream) nor reports EOF inside a thought: `streaming.py:176-191` resets `in_think` and `tests/test_ai_streaming.py:128-137` asserts that erasure. vibes `docs/RETROSPECTIVE.md:173` records this design leaking a whole chain of thought when the template pre-opens it; `examples/streaming-reasoning-sanitizer/sanitizer.py` fixes it with `starts_thinking`, `unopened_close_tags`, `unclosed_stream` and a 65,536-character cap (line 18). Today's pool (`k8s/llm/gateway/configmap.yaml:17-96`) is safe only because adapters re-wrap out-of-band reasoning as complete blocks (`streaming.py:252,279,299`); the leak goes live with the first DeepSeek-R1/Qwen3-class model served by vLLM without `--reasoning-parser` (none at `k8s/llm/vllm/deployment.yaml:68`) or reached via the `ollama/*` pass-through (`configmap.yaml:103`). Neither #475 nor #479 plans such a model: a latent defect to close before any pool change.
