# Task: Delete the Unwired Harness Port and the Capability Clones Nothing Imports (#1836)

**Issue**: [#1836](https://github.com/dan-petty/devops-cli/issues/1836)
**Scope**: scope/ai
**Feasibility**: At the base, an AST import graph over `src/devops_cli` (entry points: every `commands/` and `server/` module and `main`) reaches only `ai/harness/slots.py`, `ai/harness/skills.py` and `ai/harness/constants.py`, through `commands/ai_harness.py`. The ten other modules under `ai/harness/` (5,186 lines) load only because `ai/harness/__init__.py` imports them. No `importlib`, `__import__`, entry point or registry names them or the classes in `ai/agents/capabilities.py`: `AgentSpec.capabilities` is an untyped list. A per-symbol scan of `ai/agents/capabilities.py` found importers outside the deleted code for `BaseCapability`, `HandleDeferredToolCalls`, `SystemReminders`, `_accepts_positional_arguments` and the `ToolCallPart`, `DeferredToolRequests`, `DeferredToolResults`, `ToolApproved` and `ToolDenied` re-exports only. The pinned pydantic-ai 2.54.0 already exports `Thinking`, `WebSearch`, `WebFetch`, `MCP`, `NativeTool`, `PrefixTools` and the other clone names from `pydantic_ai.capabilities`, so nothing is lost. After the deletion `ruff check`, `mypy --strict` and the whole collected suite (11,372 tests) import cleanly, and `devops ai harness status` still runs. A `git grep` over `src` found no caller of `is_private_ip_or_localhost`, `format_plan_reminder_as_xml` or `harness.skills.Skills` outside the deleted modules, their own exports and their own tests.

## Description
The harness package was a port of Pydantic AI Harness capabilities (shell, filesystem, memory, planning, compaction, sub-agents, docs, repo context, conversation search, a coder, a researcher, a Macroscope reviewer and a Playwright browser) that no command, server tool or other module used. `ai/agents/capabilities.py` held a second set of unused clones of capabilities that pydantic-ai ships itself. Both are deleted with their tests. No shim replaces them: if the capabilities are wanted later, they come from pydantic-ai or from pydantic-ai-harness, which pins pydantic-ai-slim 2.59.0 against our 2.54.0, so adopting it is a separate dependency decision.

- `ai/harness/` loses `agents.py`, `compaction.py`, `conversation.py`, `docs.py`, `filesystem.py`, `memory.py`, `planning.py`, `repo_context.py`, `shell.py` and `workflow.py`. `__init__.py` exports only what `skills.py` and `slots.py` define. `constants.py` is deleted: its seven prompt constants, command and pattern sets, `HarnessDeprecationWarning` and logger served the deleted modules, and `UNSUPPORTED_BEHAVIORAL_SKILL_FIELDS` served only the `Skills` capability. `skills.py` keeps `ParsedSkill` and `normalize_skill_name`, which `slots.py` uses, and loses the `Skills` capability (nothing in `src` built it), its frontmatter helpers and a second copy of `DEFAULT_PYAI_DOCS_TOPICS`.
- `ai/agents/capabilities.py` keeps `BaseCapability`, `HandleDeferredToolCalls`, `SystemReminders`, `_accepts_positional_arguments` and the five re-exports, and goes from 1,116 lines to 232. `BaseCapability.prefix_tools` and `BaseCapability.with_metadata` go with the clones they returned: `prefix_tools` falls back to the upstream method; `with_metadata` is removed with no replacement. The module docstring and `HandleDeferredToolCalls.handle_deferred` no longer name deleted classes.
- The seven task prompts only `harness/constants.py` loaded are deleted from `ai/tasks/`: `advisor_system`, `summarizing_compaction`, `coder_agent`, `researcher_agent`, `macroscope_guidance`, `planning_guidance` and `playwright_guidance`.
- `HarnessExecutionError` was raised only by `memory.py`. It is deleted with `MemoryOperationConflictError`, `CONST_ERROR_CODE_HARNESS_EXECUTION`, the `CONST_DOMAIN_EXCEPTION_MODULES` entry for the memory module and `CONST_SQLITE_PER_CONNECTION_DATABASES`. `docs/ERRORS.md` is regenerated and loses both rows.
- Sixteen `DEFAULT_*` constants used only by the clones leave `config/defaults.py` and `config/__init__.py`: the three thread-executor settings, the identifiers of the select-model, resolve-model, prepare-tools, prefix-tools, return-schema, tool-metadata, content-filter, reinject-prompt, process-history and process-event-stream clones, `DEFAULT_AGENT_STREAM_EVENT_KIND`, `DEFAULT_THINKING_EFFORT` and `DEFAULT_REASONING_FORMAT`. `DEFAULT_SHELL_BG_OUTPUT_LINES` and `DEFAULT_SHELL_DRAIN_TIMEOUT_SECONDS` go with the shell. `DEFAULT_PLAN_REMINDER_ID` and `DEFAULT_PLAN_REMINDER_CADENCE` stay: `agent.py` and `SystemReminders` use them.
- The shared lists follow the deletion: the harness keys in `tests/fixtures/swallowed_failures_ceilings.json`, the harness paths in the bare-exception list of `tests/test_architectural_invariants.py`, the compaction reset in `tests/conftest.py`, the memory-conflict row `tests/test_docs.py` pinned, and the `harness docs` rows of `tests/test_http_egress.py`. AGENTS.md now names `_terminate_process_group` in `src/devops_cli/sandbox/host.py` as the guarded process-group termination, in place of the deleted `Shell` method. The two bullets of the historical case-study section of `docs/SELF_IMPROVEMENT.md` that described fixes in deleted code are removed.
- Tests: `tests/test_harness.py` is deleted: it exercised the deleted modules and the `Skills` capability, and the `normalize_skill_name` check it held moves to `tests/test_harness_slots.py`, next to the skill slot that calls it. Tests that reached live code only through a clone are rewritten with a `BaseCapability` subclass or `SystemReminders`: the on-demand `load_capability` test in `tests/test_pydantic_agent.py`, the `BaseCapability` subclass test and a new `MCPToolset` test in `tests/test_ai_agent_capabilities.py`, the capability tests of `tests/test_pydantic_ai_native_capabilities.py`, and the `Thinking()` placeholders of `tests/test_ai_agent_deferred_tools.py`. `tests/test_validation.py` keeps the `k8s.domain` and `cloudflare.domain` validation as `test_settings_domain_validation`, the only test of that Settings validation, and drops the clone halves. It also gains `test_settings_domain_refuses_every_spelling_of_the_root_name`, which feeds `@` and the IDNA full stops to the validator branch that rejects the root name. The numbered section comments of the touched test modules are renumbered, and the docstring of `tests/test_subsystem_containment_and_redaction.py` no longer lists the two groups of tests deleted from it.
- Ceilings only go down: `DEFAULT_C901_SUPPRESSION_CEILING` falls from 47 to 28, `src type: ignore` from 89 to 71, `tests type: ignore` from 228 to 139 and `tests noqa: F401` from 4 to 3, the counts the suppression collector of `tests/test_architectural_invariants.py` measures on this tree.
- Orphans of the deletion: `common_tools.is_private_ip_or_localhost` (its only caller was `harness/agents.py`) and `format_prompt.format_plan_reminder_as_xml` (its only caller was `harness/planning.py`) are deleted with the two `DEFAULT_XML_PLAN_REMINDER_*` constants and the test of the formatter. `validate_configured_domain` in `core/dns_names.py` loses its IP-literal early return and its fall-through field label, which only the deleted capability domain lists reached; it now names `k8s.domain` or `cloudflare.domain` from the model title, as the two settings fields are its only users.
- Not done: `common_tools.web_fetch_tool` and `duckduckgo_search_tool` had their callers in the deleted code and are left with none in `src`. So do the other tool factories of `common_tools.py` (`exa_*`, `image_generation_tool`, `x_search_tool`, `tavily_search_tool`), which had none before this change. Deleting the module's tool family takes the untrusted-page renderer, its dependencies and the egress tests of `tests/test_common_tools.py`, `tests/test_native_common_tools.py` and `tests/test_http_egress.py` with it, which is a decision about the whole module, not a part of this deletion. It is [#1854](https://github.com/dan-petty/devops-cli/issues/1854), which reduces `common_tools.py` to `tavily_search`; the dead pydantic_ai facades are [#1852](https://github.com/dan-petty/devops-cli/issues/1852), and the unwired agent extras are part of [#1121](https://github.com/dan-petty/devops-cli/issues/1121).
