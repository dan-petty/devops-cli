# Task: Delete the Dynamic Workflow and Code Mode Capabilities, Whose Sandboxes Let Model-Written Code Reach os and Start Processes (#947)

**Issue**: [#947](https://github.com/dan-petty/devops-cli/issues/947)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/ai

## Description
Two harness capabilities ran model-written Python with `exec` in the CLI's own process. Each one's sandbox was an AST check plus a trimmed `__builtins__`, and each handed the script the `typing` and `asyncio` modules, which reach the rest of the process.

- The dynamic workflow capability (`src/devops_cli/ai/harness/workflow.py`) gave an orchestrator agent a tool that ran a script coordinating a catalog of sub-agents, each wrapped in an agent wrapper class. A probe on 2026-10-02 showed `typing.sys.modules['os'].getpid()` returning the pid and `await asyncio.create_subprocess_exec('true')` exiting 0.
- `CodeMode` (`src/devops_cli/ai/harness/os_access.py`) gave an agent a `run_code` tool that ran a script calling sandboxed tools, with REPL state kept between calls. Its AST validator also blocked a list of reflection attributes and identifiers, but not `sys` or `modules`. With the workflow capability already deleted, `run_code(code="typing.sys.modules['os'].getpid()")` returned the pid. The issue's scope was extended to cover it.

No CLI command built either capability. Only `tests/test_harness.py` and `tests/test_security_sandbox_and_protection.py` did, but `devops_cli.ai`, `devops_cli.ai.agents` and `devops_cli.ai.harness` all exported them, so any caller could. The issue decided to delete rather than repair: an in-process Python sandbox is not a boundary worth keeping, and model code that has to run belongs in the host sandbox (bwrap) that review criteria already use.

- `ai/harness/workflow.py` loses the dynamic workflow capability, its agent wrapper class and `_invoke_agent_callable`, the helper only the capability called. It also drops its `ast`, `asyncio`, `json` and `HarnessExecutionError` imports. The module stays: `SubAgent`, `SubAgents`, `AgentOverride`, `ModelOption`, `Advisor`, `clamp_effort` and `MINIMUM_EFFORT_FLOOR` are still exported, and `Advisor` still uses `_extract_response_data`.
- `ai/harness/os_access.py` loses `CodeMode` and the helpers only it used: `STANDARD_SANDBOX_MODULES`, `_FORBIDDEN_ATTRIBUTES`, `_FORBIDDEN_IDENTIFIERS`, `_ASTSecurityValidator`, `_extract_target_names` and `_collect_assigned_names`. It also drops its `ast`, `asyncio`, `json`, `math`, `SecurityError` and `HarnessExecutionError` imports, going from 642 lines to 225. `MountDir`, `OSAccess` and `ToolSearch` stay, and the docstrings of `MountDir` and `OSAccess` no longer name the deleted class.
- The three names leave `__all__` and the lazy `__getattr__` name sets of `devops_cli.ai` and `devops_cli.ai.agents`, and the imports and `__all__` of `devops_cli.ai.harness`. No alias or shim replaces them.
- Deleted tests: `test_dynamic_workflow_script_execution`, `test_dynamic_workflow_structured_outputs_and_prints`, `test_dynamic_workflow_budget_and_reveal`, `test_dynamic_workflow_edge_cases_and_syntax` and `test_code_mode_execution_and_tool_wrapping` from `tests/test_harness.py`. Also `test_os_access_codemode_blocks_dangerous_imports_and_builtins` from `tests/test_security_sandbox_and_protection.py`, along with that module's `asyncio` import and the docstring lines that described it.
- `test_no_module_runs_python_in_process` (`tests/test_architectural_invariants.py`) parses every module under `src/devops_cli/` and asserts that none calls the `exec` or `eval` builtin. Method calls such as `engine.exec(...)` and `client.eval(...)` are not counted.
- No doc, knowledge-base page or `AGENTS.md` section described either capability, so none needed a correction. `CHANGELOG.md` keeps its historical line about `_invoke_agent_callable`. `docs/ROADMAP.md` and the task files for #700 and #710 cite `ai/harness/workflow.py:280` for `delegate_task` and `:276` for `SubAgents.get_tools`. Those are now lines 266 and 262. They are left as they were, since this item edits neither the roadmap nor other items' task files.
- After the deletion, nothing uses `MountDir` or `OSAccess`. The harness `ToolSearch` is used only by its own test, `test_tool_search_discovery_and_strategies`. `devops_cli.ai.agents.ToolSearch` resolves to pydantic-ai's `ToolSearch`, which `ai/agents/pydantic_agent.py` re-exports, not to the harness class. Whether to keep these three is a separate decision; this item leaves them.
