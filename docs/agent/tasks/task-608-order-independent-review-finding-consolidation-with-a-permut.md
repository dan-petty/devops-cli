## 1. Description & Objectives

Follow-up to #512. `consolidate_duplicate_findings` (`src/devops_cli/ai/review_schema.py:1029`) is a greedy first-match fold over `_are_findings_duplicate` (`:866`), which is not transitive. `_merge_two_findings` (`:932`) keeps the first argument's title and location, joins personas and list fields in arrival order, takes the first non-empty `category` and `relocated_from`, and gives `description` and `fix` length ties to it. `sort_findings` (`:1048`) has no total tie-break. Worker completion order never reaches the fold (`ai/agents/pipeline.py:264`, `ai/review/pool.py:126`); model emission, persona and segment order do (`ai/review/pipeline.py:1838`, `:2405`; `ai/review/runner.py:457`; `ai/review/verification.py:1581` via `ReviewResult.merge`). Verification reads the folded list (`pipeline.py:2165`), so the kept anchor decides what gets checked. No test reorders the input. vibes' CRDT has the same blind spot: its one commutativity test swaps a single pair and passes.
