# Task: A review session store owns where review sessions live, how they are written and who reads them (#771)

**Issue**: [#771](https://github.com/dan-petty/devops-cli/issues/771)
**Scope**: scope/review
**Feasibility**: Verified against the code at `release/v0.2.39`. With `DEVOPS_CLI_DATA_DIR` unset, `data.dir` pointing at one directory and `DEVOPS_CLI_DATA_REVIEWS_DIR` at another, the review writer's resolver returned the second and the dashboard's returned none, so `list_review_sessions()` listed no session of a review that had just run. The two resolvers share every default, so one is a strict superset of the other. `tests/test_ui_dashboard.py::test_dashboard_lists_sessions_written_where_the_reviews_directory_setting_points` fails on that commit with `[]` and passes with one resolver. For part 2 the code at `release/v0.2.39` showed `ai/review/pipeline.py` writing findings, raised findings, SARIF and `review.md` with plain `write_text` and `runner.py` writing `profile.json` after the report, so `findings.json` could not mark a session complete; the routed-files-only review writes a report but never a profile; and `history`, the exporter and the corpus commands decide a session exists by listing `*/findings.json`, so a marker file they do not check would leave them reading a session that is still being written. A session is therefore written where such a listing does not reach, `<reviews>/.staging/<name>`, one level deeper, and made visible by one rename inside the same filesystem. `output/file_writer.write_file` with `atomic=True` renames a temporary file created with mode 0600 over its target, where `atomic=False` opens the file `0o644` under the user's umask, as `write_text` did, so staging being private is what replaces the per-file rename and the session files keep mode 0644 under the usual umask. A path validator decodes percent escapes in a path it is given, so a file named `a%00b.py` or `%2e%2e%2fx.py` was refused as a payload name once the payload went through `write_file`; `tests/test_review_pipeline.py::test_a_file_whose_name_holds_percent_escapes_is_reviewed` fails on the flattened name and passes on a digest.

## Description

A review session's files had no owner: two functions resolved where sessions live and disagreed, `findings.json` was treated as "complete" although it is written before the rest of the session, every file was written in place, and the file names were spelled out in ten modules. The item gives the session one owner in `src/devops_cli/review/session.py` and delivers it as several pull requests, each saying `Part of #771`, the last closing the issue. This file is the one record of all of them.

Writing a session creates the directory, as the orchestrator, the benchmark, the corpus and the sample validation already do with `mkdir(parents=True)`.

The dashboard now lists the sessions a review wrote under `data.reviews_dir`, and returns no sessions for a refused or missing directory or a settings value the schema refuses.
- [x] The dashboard no longer swallows a settings failure to fall back on `./.data`: `root()` lets it surface, and the dashboard answers a refused directory (a `DevOpsCLIError`), an unreadable one (an `OSError`) and a settings value the schema refuses (a `ValueError`, as `data.reviews_dir: [1, 2]` raises) with a warning and no sessions. The swallowed-failures ceiling for `src/devops_cli/ui/data_providers.py` falls from 12 to 11.
- [x] Point every caller at `ReviewSessionStore.root()`: `commands/review.py`, `ai/review/pipeline.py` (the session directory and the roots `_checked_session_dir` allows), `ai/review/exporter.py`, `ai/review/category_metrics.py` and `ai/review/runner.py`. The redundant `resolve()` calls on the root are gone, since it is resolved.
- [x] Add the `review_store` fixture to `tests/conftest.py`, built on `isolate_data_dir`, and replace the patches of `_get_reviews_base_dir` in `tests/test_review_defects.py`, `test_review_runner.py`, `test_run_store.py`, `test_review_profile.py`, `test_review_path.py`, `test_review_backend_activity.py` and `test_review_group_analysis.py`: a test that lists, searches or checks the store asks for `review_store`, and one that only lets a command write there needs no patch, since every test already has its own data directory. `test_review_pipeline.py`, `test_review_untrusted_tree.py` and `test_data_dir_worktrees.py` call `ReviewSessionStore.root()`, so `rg -n '_get_reviews_base_dir|_reviews_root' src tests` finds nothing.
- [x] Tests in `tests/test_review_session_store.py` and `tests/test_ui_dashboard.py`: the dashboard lists sessions written where `data.reviews_dir` points; `root()` follows `DEVOPS_CLI_DATA_DIR`, a relative value under the review data root, `DEVOPS_CLI_DATA_REVIEWS_DIR` and the config file; `root()` creates nothing; a traversal sequence or `/etc` raises a `SecurityError` with its exit code and error code, and the dashboard lists no session for either or for a `data.reviews_dir` that is not a path.

### PR 2: Staged sessions published by one rename (Part of #771)

- [x] Add `ReviewSession` in `src/devops_cli/review/session.py`, one session directory, obtained from `ReviewSessionStore.session(name)` or listed by the store. It writes `findings.json`, the raised findings (still `candidates.json` until the rename), `findings.sarif`, `review.md`, `profile.json`, `analysis.json` and the per-file payloads into `<reviews>/.staging/<name>` (`CONST_REVIEW_STAGING_DIRNAME`) through `output.file_writer.write_file` with `atomic=False` and the staging directory as `base_dir`. Staging is private until published, so a file needs no rename of its own, and each keeps the mode `write_text` gave it, 0644 under the usual umask. The file names `review.md` and `profile.json` are `CONST_REVIEW_REPORT_FILENAME` and `CONST_REVIEW_PROFILE_FILENAME` in `config/constants.py`.
- [x] `ReviewSession.create()` clears whatever a review of that name left in staging and makes `files/` there. `ReviewSession.publish()` renames the staging directory to the session directory in one `Path.rename`, and refuses a name that is already published with `ReviewSessionExistsError` (`REVIEW_SESSION_EXISTS`, in `exceptions/ai.py`), which names where the refused review's files stay. The run publishes right after `profile.json` is written (`_run_profiled_session`) and at the end of the routed-files-only review, which writes a report but no profile, and never in a dry run. A review run without its reporting stage (`--no-reporting`, `--pre-analysis-only`, `--static-scan-only`) writes no `findings.json`, which every reader of a session needs, so it keeps no session: `_close_session` discards its staging directory (`ReviewSession.discard()`, which `create()` also uses), no `profile.json` is written, and the run says so (`MESSAGES.review.session_not_kept`; the `--no-reporting` help says it too). A session on disk from before this part is a published session as it stands: there is no marker, no migration and no shim.
- [x] `ReviewSessionStore.sessions()` lists the published sessions newest first by name, and `latest()` is the first. A directory of the sessions directory is a session when it holds `findings.json`, which every published session does, since `benchmarks` and `corpora` are kept there too and `corpora` sorts after every timestamp; hidden entries such as staging are not sessions. The name is the review's timestamp, where the directory's modification time moves when a verdict is written into an old session. `ReviewSessionStore.in_flight()` lists `.staging`, which the dashboard shows as incomplete sessions beside the published ones, so a running review stays visible and the newest published session is the one displayed. `devops review findings` and `verify` without a session read `latest()` (`_find_session_dir`), and a session named by part of its name is looked up among the published ones.
- [x] `devops clean` judges each session in `.staging` by its own modification time, not the `.staging` directory, whose time moves with every review that starts or publishes: a review abandoned part-way is pruned after the retention period (`devops workspace clean --older-than`) while other reviews run.
- [x] The record of a file a review read is named by the SHA-256 of the file's path (`ReviewSession.write_payload(payload)` takes the payload and names it), and `_sanitize_filename` is deleted. The flattened name could not be written for a repository path a path validator reads as traversal after decoding it (`a%00b.py`, `%2e%2e%2fx.py`), which dropped the file from the review, and it gave `src/a_b.py` and `src/a/b.py` one file. A digest holds whatever a path does, in 64 characters, and the record holds `file_path`, which is what `review score` reads. Records of earlier sessions keep their names.
- [x] Rewire the pipeline onto the session: `_persist_session_artifacts`, the per-file payload write and the constructor use `orchestrator.session`, which replaces `session_dir` and `files_dir`. `run_group_analysis` returns the report and no longer writes `analysis.json`; the pipeline's group analysis stage writes it through the session. `ReviewProfile.write` and `PROFILE_FILENAME` are deleted for `ReviewSession.write_profile`; `ReviewProfile.load` stays until readers move onto the store.
- [x] A session being compared is not in the history it is compared to, since it is unpublished while its report is built, so the `exclude` argument of `load_review_history`, `collect_historical_category_metrics` and `format_category_baseline_markdown` is deleted with the pipeline's call.
- [x] Tests: a session is listed only once published, and a raw `*/findings.json` listing never sees one being written; publishing keeps every file the review wrote and leaves no staging directory; a same-name publish is refused with a typed error and leaves the first session as it was; `create()` clears what a failed review left; a review that fails part-way publishes nothing; the routed-files-only review publishes without a profile, and the profiled one with it; a session from before staging is listed and is the latest, and the benchmarks and corpora beside the sessions are neither; session files are mode 0644 under umask 022; the files of paths named with percent escapes or a backslash traversal are recorded, as are two paths that flatten alike; the dashboard lists a session in staging as incomplete; a review without its reporting stage publishes nothing and leaves no staging directory, both for a profiled review and for the routed-files-only one; `cleanup_data_tier` prunes an old staged session beside a fresh one and keeps the fresh one.
