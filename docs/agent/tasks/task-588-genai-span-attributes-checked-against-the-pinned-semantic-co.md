# Task: GenAI Span Attributes Checked Against the Pinned Semantic Conventions (#588)

**Issue**: [#588](https://github.com/dan-petty/devops-cli/issues/588)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/cli

## Description
`SpanHandle.record_llm_metrics` said it recorded "standard OpenTelemetry GenAI attributes", but it named no convention and nothing checked it. `src/` held 36 distinct `gen_ai.*` literals: 34 attribute keys and the span names `gen_ai.chat` and `gen_ai.stream`. Of the 34 keys, 8 were current, 3 had been renamed upstream and 23 were private keys in the conventions' namespace. `gen_ai.provider.name`, which the inference span requires, was never written. Old and new token keys were written together, `gen_ai.server.address` held the `backend_info` display string, `gen_ai.response.model` held `backend_info` or `"cache"` on the wrapper span, and every LLM span was INTERNAL. The GenAI conventions live in `open-telemetry/semantic-conventions-genai`, which has no tagged release, and the installed `opentelemetry-semantic-conventions` 0.65b0 marks every GenAI key it has as deprecated, so it is not the oracle.

One change pins the conventions, checks every `gen_ai.*` literal in `src/` against them inside the gate, and renames the emitters so the check passes.

- **Snapshot.** `src/devops_cli/telemetry/semconv_genai.json` holds `source` (`open-telemetry/semantic-conventions-genai`, commit `b31e9e8ea26ac1c086d3313d474e31d7c3f391ae`, weaver `0.26.1`), the 107 non-deprecated attribute keys of the resolved catalog (the `gen_ai.*` keys and the core keys its signals reference, such as `server.address` and `server.port`), the 22 non-deprecated metric names and the 13 span types with their kind and required attributes. Lists are sorted, and only this reduced table is committed. It was produced by `devops telemetry semconv refresh` with the official weaver v0.26.1 linux x86_64 release (archive checked against the release's published sha256), at the conventions' HEAD on 2026-10-02.
- **Refresh.** `devops telemetry semconv refresh --commit <sha>` (`telemetry/semconv.py`, `refresh_genai_snapshot`) runs `weaver --version`, then `weaver registry package --v2 -r https://github.com/open-telemetry/semantic-conventions-genai.git@<sha>[model] --resolved-registry-uri <same> --diagnostic-format json --diagnostic-stdout -o <tmp>/package` as an argument list with a 300 s timeout (`DEFAULT_SEMCONV_WEAVER_TIMEOUT_SECONDS`). weaver 0.26.1 refuses to package without `--resolved-registry-uri`, which lands only in the manifest the refresh never reads. weaver runs with its working directory and `HOME` in the throwaway directory, so its git cache and `.weaver.toml` discovery stay there. The refresh reads `resolved.yaml` with PyYAML, reduces it and writes the snapshot atomically as the last step. A weaver failure is reported by its JSON diagnostic messages, capped at 256 characters. weaver fetched the bare SHA through `.git@<sha>[model]`, so the archive-URL fallback the issue allowed was not needed. A person runs it; the gate never does.
- **Check.** `find_unknown_genai_literals` reads the raw text of every `src/devops_cli/**/*.py`, comments and docstrings included, and returns each quoted string starting with `gen_ai.` that is not a current attribute key or metric name in the snapshot, and each f-string or t-string that starts with it, as `file:line`. The pattern (`CONST_SEMCONV_GENAI_LITERAL_PATTERN`) has no allowlist or exemption; the string prefix is read backwards from the quote, because an optional-prefix group made the scan ten times slower.
- **Rename.** The issue's table is applied with no key written twice. `record_llm_metrics` is deleted. `_set_response_span_attributes` is the only writer of `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `gen_ai.response.model` (the provider's reported model, unset otherwise) and `gen_ai.response.finish_reasons`, and it runs only on `ai.llm.dispatch`. `_record_chat_telemetry` keeps `llm.cached`, `llm.wall_seconds` and `llm.processing_seconds` on the wrapper span, and a cache hit no longer writes a response model. Private keys moved under `llm.*`. The CHANGELOG lists every old key and its new name.
- **Inference spans.** `ai.llm.dispatch` and `ai.llm.stream` are CLIENT spans with `gen_ai.operation.name="chat"`, `gen_ai.provider.name` (`claude` becomes `anthropic` through `CONST_GENAI_PROVIDER_NAMES`, other ids unchanged) and `gen_ai.request.model`. `server.address` is the host of the one backend's netloc and `server.port` its port, split with `urllib.parse.urlsplit`; a comma-joined host list sets neither, and a netloc without a port sets no port. The stream span also sets `gen_ai.request.stream=true` and `gen_ai.response.time_to_first_chunk` in seconds. `ai.llm.chat`, `ai.client.chat_structured` and `pydantic_ai.direct.*` stay INTERNAL and set no operation name.
- **Docs.** `docs/TELEMETRY.md` is generated, so its new "LLM Span Attributes" section comes from `DocGenerator.generate_telemetry_docs`. It names the pinned commit, read from the snapshot so a refresh followed by `devops docs generate` keeps it current, the `llm.*` prefix for private keys and the refresh command. `docs/CLI_REFERENCE.md`, `docs/commands/telemetry.md` and `README.md` were regenerated for `devops telemetry semconv refresh`.
