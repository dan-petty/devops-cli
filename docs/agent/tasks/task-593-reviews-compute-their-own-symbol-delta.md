# Task: Branch and PR Reviews Compute Their Own Base-vs-Head Symbol Delta (#593)

**Issue**: [#593](https://github.com/dan-petty/devops-cli/issues/593)
**Status**: Done
**Priority**: priority/p1-high
**Scope**: scope/review

## Description
v0.2.23 records the symbols each file added, removed and kept on `FileAnalysisMeta`, and the construct validator exempts a finding that cites a removed symbol: it is labelled "cites removed symbol" and moved to the nearest diff hunk instead of being invalidated. Real reviews never got the removed set. Only `devops ai analyze branch` computed a delta. The review's pre-analysis kept whatever symbol lists the cache held, and verification loaded the newest `*-metadata.json`, whichever run wrote it. Its segments were the file's numbered source, which has no hunks. When the reviewed files had no delta, the summary added up every file in the newest cached analysis. Branch and PR reviews now compute the delta for the files they review, from their own base, and verification and the summary use only that delta. This ships in one PR.

- **Git helpers** (`git/operations.py`): `read_file_at_revision` and `resolve_merge_base` moved here from `commands/analyze.py` as public functions, keeping #787's fix. `list_changed_files` is new. It runs `git diff --name-status -z --find-renames` over a range and returns a `ChangedFile` (`models/git.py`) for each file, with its change type, its head path and, for a rename or copy, its old path. `devops ai analyze branch` and the review both use the three. `analyze branch` used to read `old.py<TAB>new.py` as one path that does not exist, so it recorded a renamed file as deleted. `CONST_GIT_NAME_STATUS_CHANGE_TYPES` maps every status letter git documents for `--diff-filter` to a change type, and `CONST_GITHUB_PR_FILE_CHANGE_TYPES` does the same for every file status GitHub documents for a pull request.
- **One delta rule** (`change_symbol_delta`, `ai/analyze/symbols.py`): an added file's symbols are all added, and its base is never read. A modified, renamed or deleted file is compared with its base text, read at its old path. When that read fails, the delta stays empty and a debug line is logged. `compute_symbol_delta(None, head)` would count every head symbol as added, which is the wrong number #787 produced. Any other change, and any file that is not Python, gets no delta. `analyze branch` resolves the merge base once and lists the changes from it. For a reused file it computes the delta again, because the cached one may be against an older merge base.
- **Branch reviews**: `_prepare_branch_content` also returns a `BaseRevision`, which holds the changed files, a reader for their base text and, for a branch, a reader for their head text. The base is the merge base of `effective_base` and the target, where `git diff base...target` starts. Without a merge base the review already falls back to a two-dot diff, and the base is `effective_base`. The head is read at the target's commit, where the diff ends. The checkout can be another branch, or carry uncommitted edits the diff leaves out. Read from disk, a symbol the base branch dropped after the branch point, or an uncommitted deletion, would count as removed by the reviewed branch, and a finding citing it would be exempted. A working-tree review reads its base at `HEAD` and its head from disk, as `git diff HEAD` does.
- **PR reviews**: `GitHubClient.get_merge_base` reads the merge base of `pull.base.sha` and `pull.head.sha` from the compare endpoint, asking for one commit per page. `_prepare_pr_content` lists the PR's files once, shares the list with `_materialize_pr_head`, and builds the `BaseRevision` from it. Base text is read from the base repository at the merge base, and a renamed file at its `previous_filename`. Reading at `pull.base.sha`, the base branch's tip, would count symbols added on the base since the branch point as removed. Without a merge base, nothing is read.
- **Pre-analysis** (`run_pre_analysis_refresh(base_revision=...)`) records the delta of each added, modified or renamed Python file before it saves the session metadata. It reads the head text through the `BaseRevision`'s head reader when it has one, and otherwise from the reviewed files on disk: the working tree, or the PR head written under its temporary directory. A failed head read leaves the delta empty too, since comparing with nothing would list every base symbol as removed. Every other file, including files reused from the cache, carries empty symbol lists. A path review has no base, so none of its files carries a delta.
- **Verification**: `execute_finding_verification` takes the session metadata and the per-file diff text that persona review gets (`diff_map`). Hunks come from the diff text, and the numbered source stays the verification context. `_validate_segment_findings` no longer loads the newest cached analysis when no metadata is passed.
- **Summary**: `_compute_symbol_delta_summary` counts the reviewed files only, and its fallback to the newest cached analysis is deleted. `removed_symbol_findings_count` counts only real exemptions now, so #607's run history can track it.
- `docs/ROADMAP.md` is still hand-edited, so this change ticks the #593 entry and rewrites it to the one-PR scope. Its matrix row no longer names lizard or v0.2.23. Per-function complexity before and after is now #873.
- Out of scope: the fallback persona loop (`_run_persona_loop`) still loads cached metadata. `_make_review_clients` always builds `LLMClient`, so reviews take the orchestrated path. Review pages name a renamed file by its old path (the `a/` side of `diff --git`), so its payload does not find the session metadata, which is keyed by the new path. #901 tracks that.

## Measurements
These are the `--durations` figures for the 15 new tests in the final `uv run pytest -p no:cacheprovider -q -n 6 tests --durations=0` run on the delivering tree. There are 14 test functions, and one of them runs twice, for a failed base read and a failed head read. The run passed 6779 tests and xfailed 8 in 197 s, on 16 cores shared with other sessions, at a one-minute load average of 14 to 15.
