# Task: PR Readiness Requires an Issue-Linked, Completed Task File (#704)

**Issue**: [#704](https://github.com/dan-petty/devops-cli/issues/704)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p2-medium
**Scope**: scope/github

## Description
AGENTS.md grounded every change in an issue and a task file, and asked for that file with every box ticked and "verification results recorded". Nothing checked either. Of the 41 PRs merged into `release/v0.2.24`, 8 closed no issue, 2 closed several and 3 closed one without changing its task file. 15 task files marked Done held unchecked boxes. The PR template asked authors to tick 15 quality-gate boxes no one could verify, and the release PR body ticked seven of its own without reading anything.

- **Readiness blocker.** `_evaluate_pr_blockers` (`commands/pr.py`) runs `_grounding_blockers` on every PR. The release PR is exempt: head `release/vX.Y.Z` (`CONST_RELEASE_BRANCH_RE`) from the same repository as the base, into the base repository's default branch, all read from the REST payload readiness already fetches. Otherwise one `run_gh` read, `gh api --silent repos/{owner}/{repo}/contents/docs/agent/tasks?ref=<base sha>`, decides whether the check applies. A 404 means the repository keeps no task files. Any other failure is a blocker that names it, and the check still applies. The checks are a table (`_GROUNDING_CHECKS`), so a later rule is one more entry. The body must close exactly one issue, as `extract_linked_issues(body, "<owner>/<repo>")` reads it. The changed files must have been read. They must include `docs/agent/tasks/task-<N>-*.md` for that issue with status `added`, `modified` or `renamed` (`CONST_AGENT_TASK_FILE_RE`, `CONST_PR_FILE_WRITTEN_STATUSES`), and the number is read as an integer. A check that needs what an earlier one found missing reports nothing, so each failure is one blocker that says what is missing. The messages are in `MESSAGES.pr`. The `check-readiness` docstring describes the check, and the generated docs are refreshed.
- **Changed-file reader.** `_fetch_pr_files` calls `gh api --paginate repos/{owner}/{repo}/pulls/{n}/files?per_page=100` through `run_gh` and returns each file as a `ChangedFile(filename, status)`. A non-zero exit, malformed JSON or a malformed entry raises `GitHubOperationError`. It replaces `_fetch_pr_changed_files`, which ran `gh pr diff --name-only` and returned `[]` on any failure. Readiness reads the list once (`_read_pr_files`). The grounding check and the perimeter warning both use it. Where the check does not apply, a failed read prints one warning.
- **Completed task file.** `tests/test_agent_task_files.py` fails on an unchecked task-list item (`-`, `*`, `+` or numbered, at any indent) outside fenced code blocks. It owns the rule and imports nothing from `github/projects.py`. 17 files failed it at this base: the 16 the issue lists, plus task-686, merged since. Lines that only described PR process (commit, open, monitor, merge) are deleted. task-557's moved criterion is a plain bullet naming #546. task-593's open parts start "Planned:". task-686, -692 and -693's person-run checks start "Pending a person". Every other unchecked line now starts "Not checked when merged:". No box was ticked.
- **Rule text.** `AGENTS.md` (the author-as-merged rules, topic-branch isolation and issue-only linking) and `docs/agent/tasks/README.md` (rules 1 and 3, the format template and Lifecycle States) now agree. A box is ticked only for done work. Unfinished work and person-run checks are plain bullets. Verification is the PR's passing checks, which readiness reads, with no typed pass counts or coverage figures. A PR that changes a rule every task file follows brings the existing files into line.
- **PR template.** `.github/pull_request_template.md` asks for a summary, the type of change, the base branch, `Closes #<issue>` and the task-file path. The quality-gate checklist and the commented example closing reference are gone, and no issue number appears in it.
- **Release PR body.** `_build_quality_checklist` and its call in `_build_release_pr_body` (`commands/release.py`) are deleted.
- `tests/test_docs.py::test_write_and_check_docs` syncs a README under `tmp_path`. It used to rewrite the repository's own `README.md`. The workspace tripwire then failed the test run whenever that README already differed from HEAD, as it does in this change, which regenerates the README's `check-readiness` row.
- `devops pr check-readiness` stays a local command that agents run. The MCP tool `pr_check_readiness` is unchanged, since no flag was added.
