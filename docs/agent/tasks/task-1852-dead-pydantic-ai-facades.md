# Task: Delete the Dead pydantic_ai Facades, the Legacy Provider Layer and the Unused Exception Mirrors (#1852)

**Issue**: [#1852](https://github.com/dan-petty/devops-cli/issues/1852)
**Scope**: scope/ai
**Feasibility**: At the base, an AST import graph over `src/devops_cli` (entry points: every `commands/` and `server/` module and `main`) reaches no importer of `ai/exceptions.py`, `ai/profiles`, `ai/result`, `ai/run` or `ai/ext_langchain.py`. `ai/direct.py` is imported only by the four `LLMClient.direct_*` methods, which nothing calls, and the five legacy provider modules (`base`, `anthropic`, `copilot`, `ollama`, `openai`) are imported only by `ai/providers/__init__.py`, whose `get_provider`, `register_provider` and `reset_providers` have no caller outside it and the test conftest. The only `importlib` and `__import__` uses in `src` load command modules by path and the `pydantic_ai.providers.*` table of `create_pydantic_ai_provider`, which stays; no entry point or registry names a deleted module. A per-symbol scan (every top-level definition, then every class method, with its references in `src`) of the ten helper modules found no `src` reference for the deleted helpers, and a scan repeated after each deletion found what the deletion orphaned: the token governor and cache-point helpers only the bridge helpers used, `core/clock.async_sleep` and `http/pool.aclose_expired_connections` only the async retry transport used, `LLMResponse.from_model_response` only `ai/direct.py` used, and `AgentResponse.from_run_result` only `ai/result` used. A scan of `src` for every raise and catch of the pydantic-ai exception wrappers found six in use (`ModelRetry`, `UnexpectedModelBehavior`, `ToolFailed`, `ApprovalRequired`, `CallDeferred` and the `SkipToolExecution` alias); `ContentFilterError`, `AgentRunError` and `UserError` have none either, although the issue counted them among those that stay. The pinned pydantic-ai 2.54.0 provides every replacement (`pydantic_ai.concurrency`, `pydantic_ai.models.concurrency`, `pydantic_ai.template`, `pydantic_ai.settings`, `pydantic_ai.direct`, `pydantic_ai.providers`), `ruff check`, `mypy` and `deptry` over `src` and an import check of every `from devops_cli... import` in `src` and `tests` pass afterwards, and `devops --help` and `devops ai --help` still run. The package is pre-1.0 and promises no import path to anything outside the repository.

## Description
The repository carried a second layer over pydantic-ai that nothing used: re-export modules for pydantic-ai's exceptions, profiles, result, run, concurrency, template and direct APIs, a hand-written provider stack beside `create_pydantic_ai_provider`, wrappers around single library calls, and exception subclasses of library exceptions that no code raised or caught. All of it is deleted with its tests; no shim replaces it. Code that needs one of these imports it from pydantic-ai, as `ai/agents/agent.py`, `ai/agents/pipeline.py` and `ai/pydantic_ai_bridge.py` now do for the concurrency limits and `TemplateStr`.

- Modules deleted: `ai/exceptions.py`, `ai/profiles`, `ai/result`, `ai/run`, `ai/ext_langchain.py`, `ai/direct.py`, `ai/concurrency.py` (its registry of shared limiters had no caller, which left five re-exports), `ai/template` (`render_template` and the other helpers had no caller, which left the `TemplateStr` re-export) and `ai/governance.py` (the token governor served only the bridge's workflow helpers). `ai/providers/` keeps `create_pydantic_ai_provider` and `is_pydantic_ai_provider`; the five legacy provider classes, the registry functions and the lazy `Native*Provider`, `Provider` and `infer_provider*` re-exports leave it.
- `LLMClient` loses `direct_request`, `direct_request_sync`, `direct_stream` and `direct_stream_sync`, and `devops_cli.ai.client` loses `model_request` and `model_request_sync`. `LLMResponse.from_model_response` and `AgentResponse.run_usage`, `to_final_result`, `from_run_result` and `from_model_response` go with the facades that were their only callers.
- `ai/pydantic_ai_bridge.py` keeps model resolution and the fallback cascade. `create_pydantic_ai_agent` (and its `PydanticAgent` fallback), `get_persona_pydantic_agent`, `DevOpsAgentContext`, `execute_structured_workflow`, `execute_structured_workflow_sync`, `inject_prompt_cache_points`, `create_cached_user_prompt` and `is_pydantic_ai_available` are deleted.
- The helper modules lose the wrappers around single library calls: `create_tool`, `is_native_tool`, `create_tool_definition`, `approve_all_requests`, `deny_all_requests` and `matches_tool_selector_sync` from `ai/tools`; `combine_toolsets`, `prefix_toolset`, `filter_toolset`, `rename_toolset`, `require_approval_toolset`, `defer_loading_toolset` and `is_toolset` from `ai/toolsets`; `normalize_thinking_level`, `normalize_service_tier`, `normalize_tool_choice`, `create_tool_or_output` and `resolve_runtime_model_settings` from `ai/settings`; `create_async_retry_transport`, `ExpiringAsyncConnectionTransport` and `normalize_agent_retries` from `ai/retries`; the five `format_*_as_xml` wrappers other than `format_prompt_data` from `ai/format_prompt`; `build_output_spec`, `resolve_output_mode`, `get_review_output_spec` and the three `REVIEW_RESULT_*` specs from `ai/output`. The pydantic-ai names those modules re-exported and nothing imported are dropped from their imports and `__all__`.
- Exceptions: `ModelAPIError`, `ModelHTTPError`, `UsageLimitExceeded`, `ConcurrencyLimitExceeded`, `RunCancelled`, `IncompleteToolCall` and `SuspendedResponseExpired` are deleted from `exceptions/ai_pydantic.py` and `exceptions/ai.py`, with `ContentFilterError`, `AgentRunError`, `UserError`, ten native aliases (`SkipModelRequest`, `SkipToolValidation`, `UndrainedPendingMessagesError`, `ToolRetryError`, `ToolFailedError`, `FallbackExceptionGroup` and four warnings) and the two taxonomy errors only `ai/exceptions.py` imported, `ContextBudgetExceededError` and `ModelUnavailableError`. `docs/ERRORS.md` is regenerated and loses twelve rows.
- Orphans of the deletion: the direct dependency `pydantic-graph` (its only importer in `src` and `tests` was `ai/run`; it stays installed as a dependency of `pydantic-ai`, and `pyproject.toml` and `uv.lock` no longer list it as a direct dependency, so `deptry` finds no unused dependency), the `pydantic_ai.run` override in `[tool.mypy]` that only `ai/run` needed, `is_ollama_cloud` and `get_recommended_output_mode` in `ai/models/ollama.py` with their `ai.models` exports and tests (the deleted `resolve_output_mode` was their last caller), `core/clock.async_sleep` and `ClockFake.async_sleep` with the contract cases that drove them (the clock seam keeps `sleep` and `monotonic`), `http/pool.aclose_expired_connections` with its helper, four `CONST_AI_PROMPT_CACHE_*` and cache-marker constants, and twenty-two `DEFAULT_*` constants: the token bucket, usage-limit, concurrency, context-budget, end-strategy and persona defaults, the legacy provider models, host and timeout defaults, and the eight `DEFAULT_XML_*` tags of the deleted wrappers. The `pydantic_ai.direct.*` span name leaves the wrapper-span sentence of `docs/TELEMETRY.md` (generated from `docs/generator.py`), the `pydantic_ai` knowledge base page describes the bridge as it is, and the calibration row about the deleted token governor leaves `docs/SELF_IMPROVEMENT.md`.
- The shared lists follow the deletion: the mock-provider fixture, the `ai.providers` and `ai.concurrency` reset entries and the re-registration in `tests/conftest.py`, `tests/mock_provider.py`, and the ceilings in `tests/fixtures/swallowed_failures_ceilings.json` (three keys for deleted files, `http/pool.py` from 7 to 5, `ai/agents/models.py` removed). Ceilings only go down: `DEFAULT_C901_SUPPRESSION_CEILING` falls from 28 to 25, `src type: ignore` from 71 to 67 and `src noqa: F401` from 22 to 21, `[[tool.mypy.overrides]]` from 2 to 1 and `tests type: ignore` from 139 to 138, the counts the suppression collector of `tests/test_architectural_invariants.py` measures on this tree.
- Tests: the files that exercised only deleted code are deleted (`test_pydantic_ai_result.py`, `test_pydantic_ai_run.py`, `test_pydantic_ai_direct.py`, `test_pydantic_ai_template.py`, `test_ext_langchain.py`, `test_providers.py`, `test_openai_auth.py`), and the other test modules lose the cases for deleted names and the re-export checks of pydantic-ai symbols. Tests that reached live code only through deleted code are rewritten with minimal live inputs: `tests/test_model_contract.py` feeds `ModelFake` to the native `model_request_sync` and `model_request_stream_sync`, `tests/test_pydantic_ai_concurrency.py` checks that the bridge wraps a model in the concurrency limit it is given, `tests/test_rag_loopback_policy.py` keeps the `LLMClient` loopback assertions, and the new `test_a_tool_is_called_and_executed_like_its_function` covers `Tool.__call__` and the async branch of `Tool.execute`, which only the deleted `matches_tool_selector_sync` test reached. No `src` module that remains loses a covered line against the base on the 8,600 tests that import the touched modules.
