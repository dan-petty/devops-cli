# Task: Passing Criteria Leave a Finding for the Verifier Instead of Verifying It, and Running the Cited Test Counts as Evidence (#1043)

**Issue**: [#1043](https://github.com/dan-petty/devops-cli/issues/1043)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/review

## Description
`_evaluate_criteria_verdict` returned VERIFIED by `criteria` once a passing verification command counted as evidence and every verification command had finished, and only an UNVERIFIED finding is shown to the verifier, so that verdict was final. #846's evidence rule answers whether a command runs the cited code and checks the outcome, not which side of the claim a pass supports, and #847's 30 s python limit and the reviewed project's `.venv` let scripts that import this project's code finish. In review session `20261003-012555` (S8), `src/devops_cli/ai/review/chunker.py:395` claimed `PurePosixPath` has no `full_match`, which is false on Python 3.13 and later; both of its verification criteria assert that `skips_persona_review` returns the right value, the opposite of the claim. An offline replay at da50329 ran both to exit 0 and the finding ended VERIFIED by criteria at confidence 1.0 without reaching the verifier. Since #948 the report ranks VERIFIED findings first.

- **Criteria verdict** (`ai/review/review_environment.py`). `_evaluate_criteria_verdict(matched_ver, matched_inv, refuting)` returns UNVERIFIED with `criteria-non-discriminating` when commands pass on both sides, INVALIDATED by `criteria` when a passing invalidation command counts, and None otherwise. The VERIFIED branch is gone with the parameters that only served it (`proving`, `verification_commands`, `exec_results` and the `completed` set). `_reconcile_finding_from_criteria` still records every result in `criteria_execution_results` and the counting commands in `verified_criteria_matched` and `invalidated_criteria_matched`; a finding with only counting verification commands stays UNVERIFIED with no note and no confidence, so `_awaits_verdict` shows it to the verifier, whose verdict applies with the commands kept as matched. The verifier prompt is unchanged: it does not see which criteria passed (`CONST_VERIFIER_FINDING_FIELDS`).
- **Evidence rule** (`ai/review/criteria_evidence.py`). `counts_as_evidence` also counts a `python -c` script that calls, as a top-level statement (`ast.Expr` in the script's own body), the test whose definition spans the cited lines, imported from the cited test module by `from <module> import <test> [as <name>]`. `_cited_test` reads the cited file only when pytest collects it by its default `python_files` patterns (`CONST_PYTEST_FILE_PATTERNS`: `test_*.py`, `*_test.py`), resolved inside the repository root, through `global_ast_cache` (size-capped); the test is a module-level `def` (not `async def`, whose bare call only creates a coroutine) named with pytest's default `python_functions` prefix (`CONST_PYTEST_FUNCTION_PREFIX`), whose span, decorators included, holds the cited start and end lines (`review_schema._parse_location`, as `judged_claims` reads it). A name the script binds again is no longer the test, and a call inside a `try` or handed to another function does not count. `is_tautological_criterion` treats a top-level call of a `test...` name imported from a module outside the standard library whose file pytest collects as a command that may count. The pytest patterns are a constant rather than `calibration.is_test_path`, whose import made a cycle in `ai/review` (`calibration` → `category_metrics` → `review_environment`); every file they match is a test path to calibration too.
- **Leftovers** (`ai/review_schema.py`, `ai/review/calibration.py`, `config/constants.py`). `_merge_two_findings` takes a VERIFIED result's adjudicator from a verified input and never falls back to `criteria`; a merge of verified inputs that named none keeps none, which the verdict invariants then report. `_is_hedged` replaces `_is_hedged_without_evidence`, so a hedged title is MEDIUM at most whoever verified it, and `CONST_REVIEW_EVIDENTIAL_ADJUDICATORS` is removed. `criteria` stays a `VerifiedBy` value for INVALIDATED verdicts.
- **Docs**. The docstrings of `criteria_evidence.py`, `_evaluate_criteria_verdict` and `calibration.py`, the hedge-word comment in `config/constants.py`, `docs/SDLC.md` (executive summary bullet) and the knowledge base's `devops_cli/tasks/ai_code_review.md` say that criteria refute but never confirm, and that nothing lifts the hedge cap.
- **Golden fixture**. `tests/golden/criteria_direction.json` holds three trimmed findings with the results their commands gave and the cited-file lines each needs, at their line numbers: S8's `chunker.py:395` (results from the da50329 replay, exit 0 in 15.6 s and 15.2 s; S8 itself recorded 5 s timeouts), S8's `tests/test_rag_multi_project_indexer.py:66` (exit 0 in 4.135 s), and `tests/test_pipeline_protocol.py:114` from `20260928-201857` (exit 0 in 3.515 s, VERIFIED by criteria in that session).
- **Changelog**. The entry is `changelog.d/1043.md`. Two fragments of this release described what this change removes, and the cut merges every fragment into one section, so they are brought into line: `changelog.d/847.md` says an asserting criterion counts as evidence, which settles INVALIDATED as an invalidation criterion and leaves the finding to the verifier as a verification criterion (it said such a criterion "settles the verdict"), and that the evidence rule also counts a direct call of the cited test; `changelog.d/948.md` drops "unless executed criteria verified it" from the hedge cap, and its replay of session `20261001-224227` now gives 165 HIGH, not 173. Replayed read-only over that session's 563 reported findings, f5fdf40's calibration gives 5 CRITICAL, 173 HIGH, 228 MEDIUM and 157 LOW (#948's figures) and this change's gives 5, 165, 236 and 157: the 8 that move are hedged HIGH titles VERIFIED by criteria, such as "Potential SSRF in ArgoCD API calls via unvalidated URL construction".
