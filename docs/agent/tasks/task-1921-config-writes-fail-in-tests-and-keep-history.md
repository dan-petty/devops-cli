# Task: A Test That Writes a Real Config File Fails at the Write, and Every Config Write Keeps a Copy and a Record (#1921)

**Issue**: [#1921](https://github.com/dan-petty/devops-cli/issues/1921)
**Scope**: scope/config
**Feasibility**: Confirmed on CPython 3.14.7 with a probe script under `$TMPDIR`: `Path.write_text`, `os.open` and the copy in `shutil.copy2` raise the audit event `open` with `(path, mode, flags)`; `os.replace` raises `os.rename` with `(src, dst, src_dir_fd, dst_dir_fd)`; `Path.unlink` raises `os.remove` with `(path, dir_fd)`; and an absent directory descriptor is `-1`, while `shutil.rmtree` removes by name relative to one. A hook that raises stops the operation before the system call. Typer 0.27.2 runs commands on the click it vendors (`typer._click`), so the running command comes from `typer._click.globals.get_current_context`, as `core/cli.py` already imports `typer._click.exceptions`. `devops_cli.core.audit.record_audit_event`, which writes `data.audit_log_path` (`.data/logs/audit.jsonl`), had no caller. A counting hook over 129 tests saw 435,121 audit events in 14.9 s, and the guard's check of an event that it does not watch costs about 50 ns in a loop, so the guard adds well under 1% to a run.

## Description
A person lost the setting `ssh.key_prefix` from the project `config.yaml` and reports that tests that did not isolate the environment wrote the real file. `save_settings` writes the whole file from the settings in memory and kept nothing, and the workspace tripwire found a change only when the session ended, without the name of the test.

The test process now has a config write guard, `tests/support/config_write_guard.py`, a PEP 578 audit hook beside the network block. It refuses an open for writing, a rename onto and a removal of a config file outside the run's temporary directory. A config file has the name of a project config candidate or of the user-level config (`config.yaml`, `.devops.yaml`), or that name, a dot and more text, such as the copy `config.yaml.bak-<stamp>` and the temporary file `config.yaml.tmp`. So `save_settings` stops at its first write, before it changes anything beside the real file. The refusal is `pytest.fail`, which an `except Exception` does not hide. It names the test from `PYTEST_CURRENT_TEST` and shows the stack, and the test also fails at teardown. Each run pushes its temporary directory (`run_temp_root` in `tests/support/bootstrap.py`, the xdist controller's basetemp for a worker) at `pytest_configure` and pops it at `pytest_unconfigure`, so a run that pytester starts in the same process holds its tests to its own directory. Product code holds no test detection.

`save_settings` now hands each write to `devops_cli.config.write_history`. Before a write that changes the file, `back_up` copies the file to `<name>.bak-<YYYYMMDD-HHMMSS>` beside it, with the time in UTC, and removes all but the newest ten copies (`CONST_CONFIG_BACKUPS_KEPT`). A file whose suffix is not such a stamp, such as a copy a person made, stays. A second write in the same second keeps the first copy, which holds the older state. After the write, `record_write` appends an audit record through `record_audit_event`: the time, the user, the command path (such as `devops config set`) and, in `details`, `action: config_write`, the file, the copy and the dotted names of the keys that changed. The record holds no value. The command path holds no argument, because an argument can be a credential (`devops config set ai.api_key <value>`). A save that changes no byte of the file writes nothing, keeps no copy and records nothing, so a repeated save does not push older copies out.

The issue proposed a new log, `<data_dir>/audit/config-writes.jsonl`. The record goes to the audit log that already exists, `data.audit_log_path`, which `devops config audit-stream` reads, so the project keeps one audit trail. The diff of keys is a walk of two mappings in 15 lines. `deepdiff` covers it too, but a new dependency costs more to keep than these lines.

## Acceptance Criteria
- [x] A test that writes a config file outside its run's temporary directory fails at the write and names itself, also when it catches the failure, and the file stays as it was. `test_a_config_write_outside_the_run_fails_at_the_write_naming_the_test` (`tests/invariants/test_hermetic_floor.py`) runs seven tests through pytester in the floor. An open for writing, a rename onto `.devops.yaml`, a removal, a caught write and `save_settings(load_settings())` from a checkout with `DEVOPS_CLI_CONFIG` unset each fail with `test_inner.py::<test> (call)` in the refusal. A config file under `tmp_path` and another file outside stay writable. The tree outside the inner run holds only the one file that the allowed write made.
- [x] Before each write that changes the file, a copy named `config.yaml.bak-<YYYYMMDD-HHMMSS>` holds the bytes it replaces, and only the newest ten copies stay. `test_a_config_write_keeps_a_copy_of_the_file_it_replaces_and_records_the_changed_keys`, `test_a_config_write_keeps_the_newest_ten_copies_and_no_file_a_person_made` and `test_a_second_write_in_the_same_second_keeps_the_copy_of_the_older_state` in `tests/test_config_write_history.py`, with the time from the shared `clock` fake.
- [x] Each write appends one audit record with the time, the command and the dotted names of the changed keys, and never a value. The first test above finds `changed_keys: ["ssh.key_prefix"]` for the write that drops the setting. `test_config_set_records_its_command_and_the_key_it_changed` finds `devops config set` and `["github.default_org"]`, and not the value. `test_the_first_write_of_a_config_file_records_every_key_and_keeps_no_copy` and `test_a_config_write_that_changes_no_byte_writes_nothing_and_records_nothing` cover a new file and a save that changes nothing.
- [x] `devops config set --from-file` (#1649) works as before. The tests of `tests/test_config_commands.py` pass unchanged.
- [x] On `origin/main` (`a752a14a`) with its own `tests/support`, the seven new tests fail and the eleven other floor tests pass. `devops ci fail-to-pass --base origin/main` overlays the whole new `tests/`, the guard included, so there the six tests of `tests/test_config_write_history.py` fail on base and the guard's probe passes. With the change, the 82 config, Kubernetes, gateway, telemetry, SSH, audit, tripwire and invariant test files that write settings pass: 1622 passed, 1 skipped.
