# Task: Sandbox Egress Port Scoping, Collector Lane & In-Container Trace Context (#702)

**Issue**: [#702](https://github.com/dan-petty/devops-cli/issues/702)
**Status**: Done
**Milestone**: v0.2.30
**Priority**: priority/p1-high
**Scope**: type/feature, scope/security, scope/telemetry

## Description

`devops sandbox network-policy` and MCP `sandbox_network_policy` print a Kubernetes NetworkPolicy for a sandbox pod. The whitelist modes put every resolved address into one egress rule with no `ports`, which opened every port and protocol to each address and dropped the port an entry named. A public whitelist CIDR was checked only at its ends and against Python's `is_global`, so `8.0.0.0/5`, which holds 10.0.0.0/8, was admitted. No rule reached the OTel collector, and sandbox containers and execs got no trace context, unlike subprocesses. The four parts land together:

- **Public CIDR range check** (`core/validation.py`). `is_non_public_ip` treats a range as non-public when it overlaps any of pydantic-ai's non-public blocks (`_PRIVATE_NETWORKS`) or the NAT64 (`64:ff9b::/96`) or IPv4-compatible (`::/96`) image of a private IPv4 block, built once with `ipaddress` from `CONST_IPV4_EMBEDDING_IPV6_PREFIXES`. For a single address this adds nothing to pydantic-ai's classifier, which decodes the same images, so it is not special-cased. Space only Python's `is_global` treats as non-global and pydantic-ai does not list, such as the documentation prefix `3fff::/20` (RFC 9637), is not looked for inside a wider range: `3ff0::/12` is admitted while `3fff::1` is refused. That prefix is never routed, and closing the gap would need the private `ipaddress._IPv6Constants`, so it is left to a follow-up if the owner wants it. An IPv4 range never overlaps an IPv6 block, and an ISATAP-style interface id, which occurs in every /64, is not taken to hide an IPv4 address in a range, so `2606:4700::/48` stays public.
- **Port scoping** (`sandbox/models.py`). `_parse_whitelist_entry` replaces `_extract_host_or_ip` and returns the host and one TCP port. An IP address or CIDR is read first with `ipaddress.ip_network` and opens 443; anything else goes through `urllib.parse.urlsplit`, taking the stated port, else the scheme's default from `CONST_SANDBOX_WHITELIST_DEFAULT_PORTS` (443 for no scheme and `https`, 80 for `http`). It refuses, naming the entry: no host, another scheme without a port, port 0, a port `urlsplit` cannot read (outside 0-65535 or not a number), and a path, query or fragment without a scheme, which is how `140.82.112.0/20:8443` would otherwise have become one address on 443. Both validators call it, so a bad entry fails when the model is built and the command exits 1. `_build_whitelist_egress(entries, resolve_host)` replaces the two builders: the kube-dns rule, then one rule per entry with its addresses and `ports: [{protocol: TCP, port}]`. The resolvers are unchanged. The `--public-whitelist` and `--local-whitelist` help states the forms, the defaults, and that names are resolved when the policy is generated.
- **Collector lane** (`sandbox/models.py`, `commands/sandbox.py`, `ai/mcp/server.py`). `to_k8s_network_policy(..., allow_collector=True)` appends one rule whose single peer has both `namespaceSelector` `kubernetes.io/metadata.name: otel` and `podSelector` on `CONST_OTEL_COLLECTOR_POD_LABELS` (`app.kubernetes.io/name: opentelemetry-collector`, `app.kubernetes.io/instance: otel-collector`), on TCP `CONST_OTEL_OTLP_GRPC_PORT` (4317) and `CONST_OTEL_OTLP_HTTP_PORT` (4318), with no `ipBlock`. It applies to the modes in `CONST_SANDBOX_COLLECTOR_LANE_MODES`; isolated and bridge raise an error naming them. `devops sandbox network-policy --allow-collector` and `sandbox_network_policy(allow_collector=True)` pass it through. No mode has a rule for 6379.
- **Container trace context** (`docker/engine.py`, `sandbox/engine.py`, `docker/sandbox.py`). `DockerEngineService.exec_in_container` takes `environment` and passes it to `exec_run`. `WorkloadSandboxEngine._build_create_kwargs` copies `config.env` and calls `get_tracer().inject_trace_env` on the copy, inside the `sandbox.deploy` span. `WorkloadSandboxEngine.exec` runs the command in a `sandbox.exec` span and passes that span's context, or no environment when tracing is off. `WorkloadSandboxRunner._build_create_kwargs` injects once into the environment `_network_create_kwargs` returns, inside `docker.workload_sandbox.run`. Proxy variables stay, and with tracing disabled the environment is exactly `config.env`.

## Acceptance Criteria

- [x] Each whitelist entry is its own egress rule with its own TCP port: `https://1.1.1.1:8443` and `1.1.1.1:8443` give `1.1.1.1/32` on 8443 only, `http://example.com` 80, `example.com` 443, `[2606:4700::1]:8443` `2606:4700::1/128` on 8443, and local `http://localhost:11434` `127.0.0.1/32` on 11434 (`tests/test_sandbox_networking.py::test_a_whitelist_entry_opens_only_its_own_port`, names through `public_dns`).
- [x] `example.com:8443,example.org`, each name stubbed to its own public address through a patched `socket.getaddrinfo`, gives two rules, and neither pairs one entry's addresses with the other's port (`test_two_entries_never_share_a_rule`).
- [x] `network-policy` exits 1 with the entry in its output for `ftp://example.com`, `example.com:0`, `example.com:70000` and `140.82.112.0/20:8443` (`test_network_policy_exits_1_naming_an_entry_it_cannot_scope_to_a_port`); the parser's forms and refusals are pinned by `test_a_whitelist_entry_parses_into_its_host_and_port`, `test_a_whitelist_entry_that_cannot_name_one_port_is_refused` and the IPv6 property test in `tests/test_sandbox_policy_properties.py`.
- [x] Every egress rule but the DNS rule names its ports, over one module-level list of every whitelist configuration the networking tests build (`test_every_whitelist_rule_but_the_dns_rule_names_its_ports`).
- [x] `is_non_public_ip` refuses `0.0.0.0/0`, `::/0`, `128.0.0.0/1`, `8.0.0.0/5`, `64:ff9b::/96`, `64:ff9b::800:0/101`, `::800:0/101` and `64::/16`, and admits `2606:4700::/48` and `140.82.112.0/20` (`tests/test_validation.py::test_a_range_is_non_public_when_any_of_its_addresses_is`). `test_is_non_public_ip`, which keeps `64:ff9b::808:0/112` public, and the #701 tests pass unchanged.

- [x] Two execs in one sandbox carry different parents, each its own `sandbox.exec` span and neither the deploy span; with tracing disabled an exec sends no environment; `exec_in_container` hands `environment` to `exec_run` (`test_each_exec_is_parented_to_its_own_exec_span`, `test_an_exec_with_tracing_off_sends_no_environment`, `tests/test_docker_engine.py::test_exec_in_container_hands_its_environment_to_the_exec`).
- [x] No test resolves a real name or opens a non-loopback socket. Generated docs are refreshed with `devops docs generate --sync-readme` and pass `devops docs check`; `docs/TELEMETRY.md`, written from `docs/generator.py`, names the sandbox containers and execs, and `changelog.d/702.md` carries the entry; `CHANGELOG.md` and `docs/ROADMAP.md` are not edited.
- Pending a person: on the cluster, in a test namespace, apply the policy from `devops sandbox network-policy --network-mode public_whitelist --public-whitelist 1.1.1.1:443 --name egress-check --namespace <test-namespace> | kubectl apply -f -`, run a pod labelled `app.kubernetes.io/name=egress-check` there (`kubectl -n <test-namespace> run egress-check --image=curlimages/curl --labels=app.kubernetes.io/name=egress-check --command -- sleep 3600`), and from it confirm `1.1.1.1:443` connects and `1.1.1.1:80` times out (`kubectl -n <test-namespace> exec egress-check -- curl -sS -m 5 -o /dev/null https://1.1.1.1` and `kubectl -n <test-namespace> exec egress-check -- curl -sS -m 5 -o /dev/null http://1.1.1.1`). If port 80 connects, the cluster does not enforce NetworkPolicy, and the owner decides what follows.
- Pending a person: apply a policy generated with `devops sandbox network-policy --network-mode sandbox_namespace --allow-collector --name egress-check --namespace <test-namespace>` the same way, and confirm an OTLP request from the pod reaches the collector (`kubectl -n <test-namespace> exec egress-check -- curl -sS -m 5 -o /dev/null -w '%{http_code}' -X POST -H 'Content-Type: application/json' -d '{}' http://otel-collector-opentelemetry-collector.otel:4318/v1/traces` prints a status rather than timing out).
- Pending a person: `kubectl -n otel get pods --show-labels` shows the collector pod with both `app.kubernetes.io/name=opentelemetry-collector` and `app.kubernetes.io/instance=otel-collector`.
