## Description
A triage of review session 20261001-224227 against `release/v0.2.25` (c279c18) confirmed six defects in the scanners and audits. Each is fixed as the issue's **Fix** line says, with the differences noted below, and each has a regression test that fails on c279c18 and passes here.

- **Dive.** `run_dive_analysis` (`security/dive.py`) no longer invents a result. `DiveAnalysisResult` has `status: Literal["ran", "unavailable", "failed"]` and `reason`, and only `ran` carries measurements (`efficiency_score` defaults to 0.0). A missing `dive`, or one that is a symlink, which is still refused, is `unavailable`. A non-zero exit, a timeout, an `OSError`, a missing export or an export that does not parse is `failed`, with dive's error capped at 256 characters. dive's `--json` names a file it writes (`cmd/dive/cli/internal/options/export.go`), never stdout, so dive now writes into a private `tempfile.TemporaryDirectory`, and the file is read by the keys of dive's `export.Export`: `image.efficiencyScore`, `image.inefficientBytes`, `image.sizeBytes`, and `layer[].index`, `digestId`, `sizeBytes` and `command`. The export has no per-layer wasted bytes, so `DiveLayerInfo.wasted_bytes` and the `Wasted (MB)` column are gone. `devops docker analyze-layers` prints `MESSAGES.docker.layer_analysis_not_run` as a warning and exits 1 unless the status is `ran`. With `--json` it prints the result, then exits 1. Under `--json` stdout carries only the JSON document: the `Analyzing container image layers ...` line is not printed, as `devops scan complexity` already does. Layer commands are the image's history, written by whoever built the image, so the layer table shows each one, and the image name in its title, through `escape_text`; `pip install uvicorn[standard]` no longer loses `[standard]`, and a `[link=...]` in a command is text. `docker_analyze_layers` answers `Dive not available: <reason>` or `Dive analysis failed: <reason>`. The `devops scan` adapter, `DiveScanner`, had the same `--json -` and `wastedBytes` mistakes. It now runs dive through `run_dive_analysis`, overriding `_run_scanner_command`, and its `parse_output` reads a `DiveAnalysisResult`.
- **RBAC audit.** `rbac_audit` (`commands/k8s/security_audit.py`) reads `kubectl get clusterrolebindings,rolebindings -o json` and `kubectl get clusterroles,roles -o json` through `runtime._run_cmd(..., check=False, capture=True)`. It passes `-n <namespace>` with `--namespace`, otherwise `--all-namespaces`, because without it kubectl returns only the current namespace's RoleBindings. `devops_cli.k8s.rbac` parses the lists into Pydantic models, reading `null` lists as empty since Kubernetes writes `"rules": null` for an empty aggregated ClusterRole. `audit_rbac` reports each subject that a binding grants the built-in `cluster-admin`, `admin` or `edit` ClusterRole, or a role with `*` in its verbs, resources or API groups. ServiceAccounts in `kube-system` and `system:` users and groups pass. One addition to the issue's rule: `system:anonymous`, `system:unauthenticated`, `system:authenticated` and `system:serviceaccounts` (`CONST_K8S_RBAC_BROAD_SUBJECTS`) do not pass. They stand for every client or every service account, and binding cluster-admin to them is the misconfiguration an RBAC audit exists to catch. A User named `system:serviceaccount:<ns>:<name>` is that ServiceAccount and a Group named `system:serviceaccounts:<ns>` is every ServiceAccount in `<ns>` (`CONST_K8S_SERVICE_ACCOUNT_SUBJECT_PREFIXES`), so either passes only when `<ns>` is `kube-system`; their `system:` prefix would otherwise excuse a ServiceAccount the issue says to flag. The control-plane identities that k3s and kubeadm bind to broad or wildcard roles on every cluster, without a `system:` prefix, pass as cluster components (`CONST_K8S_RBAC_DISTRIBUTION_SUBJECTS`, matched by kind and name): User `kube-apiserver` (k3s `manifests/rolebindings.yaml`, bound to the upstream `system:kubelet-api-admin`, which has `*` verbs on `nodes/proxy` and `nodes/log`), User `k3s-cloud-controller-manager` (k3s `manifests/ccm.yaml`, `*` verbs on nodes and daemonsets) and Group `kubeadm:cluster-admins` (kubeadm 1.29+, the admin.conf group that took over from `system:masters`). Without them every fresh k3s or kubeadm cluster fails the audit. Exempting roles labelled `kubernetes.io/bootstrapping: rbac-defaults` instead was rejected: upstream `cluster-admin`, `admin` and `edit` carry that label, so it would excuse a ServiceAccount bound to cluster-admin, and k3s's cloud controller role has no such label. Cluster names are escaped with `escape_text`. A violation prints a table (`format_k8s_rbac_table`, now Namespace, Binding, Role, Subject, Finding) and exits 1. A kubectl failure, a timeout or JSON that does not parse prints `ERRORS.k8s.resource_lookup_failed` and exits 1. A clean cluster prints `MESSAGES.k8s.rbac_audit_passed` with the binding count. The issue's alternative, deleting the command, was not taken, so README, the command docs, `docs/ROADMAP.md` and the release notes stay as they are and are now true. The `kubernetes` library manual no longer says the Python client powers `rbac-audit`. The hardcoded assertion in `tests/test_k8s.py` is gone, replaced by `tests/test_k8s_rbac_audit.py`.
- **Checkov fallback, Dockerfiles.** `_check_dockerfile_fallback` reads instructions as Docker does (`_dockerfile_instructions`). A line ending in the escape character continues on the next, with comment and blank lines inside skipped. The escape character is a backslash, or the backtick a leading `# escape=` parser directive sets (`CONST_DOCKERFILE_PARSER_DIRECTIVE_RE`). The instruction's location is its first line. After a RUN, COPY or ADD, or an `ONBUILD` of one, that opens BuildKit heredocs (`<<EOF`, `<<-EOF`, `<<'EOF'`, several on one line: `CONST_DOCKERFILE_HEREDOC_RE`), each body is skipped up to its terminator, which `<<-` lets be tab-indented, as in moby/buildkit's `frontend/dockerfile/parser`. So a Python `from x import y` in `RUN python3 - <<EOF` is not a FROM, and nginx's `user nginx;` in `COPY <<EOF /etc/nginx/nginx.conf` is not a USER. Each instruction is matched with `CONST_DOCKERFILE_FROM_RE` (`^FROM\s+(?:--\S+\s+)*(?P<image>\S+)(?:\s+AS\s+(?P<alias>\S+))?`, case-insensitive), and stage aliases are recorded. It skips `scratch` and earlier aliases, and flags an image with no digest whose tag, read from the last path component so a registry port is not a tag, is missing or `latest`. A `$VAR` or `${VAR}` (`CONST_DOCKERFILE_VARIABLE_RE`) skips an image only where it can hide the tag or digest: in the tag (`python:${TAG}`), or in the last component's name when there is no tag (`$BASE`, `${IMAGE:-docker.io/python}`). A variable registry or path hides neither. So `${REGISTRY}/library/python:latest`, which c279c18 flagged, and the untagged `${REGISTRY}/python` are flagged. `USER` is `CONST_DOCKERFILE_USER_RE`, case-insensitive.
- **Checkov fallback, Kubernetes.** The kind substring gate is gone. `_check_k8s_fallback` composes every document with `yaml.compose_all`, which keeps line marks, so no line-tracking loader is needed. It uses `yaml.CSafeLoader` when PyYAML is built with libyaml, as it is here, and `yaml.SafeLoader` otherwise. Both give the same nodes, tags and `start_mark.line`, and the line-number assertions run on the C loader. On a 1.1 MB file of 100 CRD-like documents, the fallback took 0.98 s with it and 6.75 s with `SafeLoader`, on the loaded devcontainer. The walk covers the document and each resource nested in a `List`'s `items` (what `kubectl get -o yaml` writes, which c279c18 caught by its `kind: Deployment` text) or an OpenShift Template's `objects` (`CONST_K8S_NESTED_RESOURCE_KEYS`). For each, it follows the pod spec paths (`CONST_K8S_POD_SPEC_PATHS`) and container lists (`CONST_K8S_POD_CONTAINER_KEYS`). It flags `securityContext.privileged` when it is a YAML boolean true by PyYAML's own `SafeConstructor.bool_values`. A file that does not parse, such as a Helm template, falls back to `CONST_K8S_PRIVILEGED_LINE_RE` (`^\s*privileged:\s*(?:true|yes|on)\b`, case-insensitive). So does a file nested deeper than the composer or the walk can recurse. Its `RecursionError` used to escape, so `devops scan iac` died with a traceback, and `devops scan` marked checkov failed and lost every IaC finding.
- **Complexity.** `_visit_with_depth` hands a `FunctionDef`, `AsyncFunctionDef` or `ClassDef` to `self.visit` before counting anything, so it is measured on its own, and the old child-only check is gone. `_handle_function` also zeroes `_class_depth` while it walks its body. Without that, a function nested in a method of a class defined in a function would report as a method.
- **Dead helpers.** `_execute_and_parse_semgrep` and `_execute_bandit_subprocess` are deleted with `json`, `subprocess` and `DEFAULT_SUBPROCESS_TIMEOUT_SECONDS` in `semgrep.py`, and `json` and `DEFAULT_SUBPROCESS_TIMEOUT_SECONDS` in `bandit.py`. Both modules' `logging` import and `logger` go too, since only the helpers used them. `semgrep.py` keeps its parenthesised `devops_cli.config.defaults` import and only drops the `DEFAULT_SUBPROCESS_TIMEOUT_SECONDS` line. #963 (6dbe7a7 on `release/v0.2.25`) adds `DEFAULT_SECURITY_SCANNER_TIMEOUT_SECONDS` inside the same block and a `CONST_SEMGREP_EXCLUDED_EXTENSIONS` import above it, and collapsing the block to one line made the two changes conflict. `run_subprocess  # noqa: F401` stays in both, as in `gitleaks.py`, because `BaseSecurityScanner._run_subprocess` honours a patched `run_subprocess` on the scanner's module. The hygiene test finds module-level private functions with a column-0 `def` regex instead of `ast`. A `def` in column 0 is module-level by Python's indentation grammar, the regex finds exactly what `ast` finds in `security/*.py` today, and parsing every module took 0.15 to 0.37 s on the loaded devcontainer. Only names that appear once in their own module are then searched for across `src/` and `tests/`.
