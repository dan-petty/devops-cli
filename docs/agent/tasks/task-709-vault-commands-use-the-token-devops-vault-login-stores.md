## 1. Description & Objectives

`devops vault login` stores the issued token in the OS keyring by default (`--store`, `commands/vault.py:298-301`), but nothing in `src/` reads it back. `VaultSecretBroker` takes its token only from the argument, `VAULT_TOKEN` or `DEVOPS_CLI_VAULT_TOKEN` (`security/vault_broker.py:90-91`), so after a successful login `status`, `get`, `set`, `sync` and `leases` all build a token-less broker (`commands/vault.py:74,129,176,227,327`). `get` skips Vault and silently returns the keyring fallback (`vault_broker.py:134-141`), `VaultProvider` in the shared secret chain resolves nothing (`security/secrets.py:212-247`), and `leases --revoke` hands the missing token to `LeaseRegistry` (`token: str | None`, `security/vault_lease.py:166`), whose `revoke` swallows the rejection (`:257-271`); the user sees only "Could not revoke lease" (`commands/vault.py:347`). vibes `observations/polyglot/01` argues an unauthenticated client should not expose authenticated operations; the optional token is that gap here.

- Deliverable*: `VaultSecretBroker` resolves its token from the argument, then the environment and keyring `vault_token` via the existing `get_keyring_secret`, in the order `build_default_resolver` documents (`security/secrets.py:334-338`), stated in its docstring. `LeaseRegistry.token` becomes a required `str`: `login_approle` and `login_kubernetes` already return `VaultAuthResult` (`vault_lease.py:97-112,130-151`), and `mypy --strict` in CI (`.github/workflows/ci.yml:57`) then forces `vault leases` to handle the missing case. Commands that need Vault auth exit non-zero naming `VAULT_TOKEN`, `DEVOPS_CLI_VAULT_TOKEN` and `devops vault login`, the message style #465 used for AI keys. Tests: env unset with the keyring mocked to hold `vault_token` yields an authenticated broker; no token anywhere makes `vault leases --revoke X` name the missing token. Replace `test_registry_headers_omit_absent_credentials` (`tests/test_secret_resolution.py:698-702`). No new dependency: `hvac` is not one, and adopting it would not read this project's keyring entry.
- Constraint*: Do not port Rust type-state or add an AGENTS.md lifecycle rule: Python cannot consume `self`, and the other wrappers already connect on first use (`valkey/client.py:194-195`, `http/broker.py:59-68`). Keep `get`'s keyring fallback only after every token source has been tried; a fallback that hides an unread token is the current bug. Out of scope, as separate entries: `LeaseRegistry` has no producer and is per-process (`commands/vault.py:27-41`), so listing and `--renew` do nothing in a one-shot CLI; and `SqliteStepStore` raises a bare `AssertionError` after `close()` (`ai/durable.py:134,153,177`), where a lazy reopen would silently return an empty `:memory:` store.
