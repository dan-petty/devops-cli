# Task: The OpenSpec Gate Drops the Cut-Only Code (#1846)

**Issue**: [#1846](https://github.com/dan-petty/devops-cli/issues/1846)
**Scope**: type/refactor
**Feasibility**: The owner decided on 2026-10-22 that the pull request which closes a change archives it. The same decision says that the gate does not rehearse `openspec archive`. I read the issue text that a person rewrote on that day. I ran OpenSpec 1.14.3, the version in `tools.lock`, in a scratch repository. A spec with a placeholder Purpose failed `openspec validate --all --strict` with exit 1, so check 1 needs no new run. I recorded the new gate with the real tool again and compared it with the trimmed record (see Checks). I ran the same tool again in a scratch repository to decide whether the overlap check stays (see The overlap check).

## Description

The first plan archived changes at the release cut. The owner replaced that plan: the pull request that closes a change archives it. The cut holds no OpenSpec code, so the code that #1868 merged for the cut has no caller. This part deletes that code and the text that describes it. It adds no readiness rule, because that rule is the last part of #1846.

- **Existing tool considered.** `openspec archive` is the tool, and the closing pull request runs it as shipped. This part builds nothing. It deletes 253 lines in `src` and 829 lines in `tests`, and it adds 28 and 44 lines there. Of the deleted lines, 396 are recorded runs. The cost of changing our own code to fit the tool is no reason to keep that code.
- **Checks.** The old recorded runs showed three cases. Archive exits 0 and writes a placeholder when the Purpose is missing. Archive refuses with exit 1 and changes no file for a `MODIFIED` of an absent spec. It does the same for a duplicate `ADDED`. These cases now show in the closing pull request.
- **Checks, recording.** The trimmed record and the new recording hold the same eight scenarios and the same 41 runs. The exit codes and the output are equal, apart from `lastModified` times and list order. I ran `uv run devops openspec check` on the tree with the real tool, and it passed. I searched `src`, `tests`, `docs`, `openspec` and `.github` for each deleted name. Only the deleted files and the files that this part edits used them. The deleted names now appear only in this task file.
- **The gate.** `src/devops_cli/openspec/archive.py` is deleted. `active_changes` moves to `src/devops_cli/openspec/tool.py` and returns the names of the active changes, because no code reads their status now. `gate.py` loses `GateCheck.REHEARSAL` and `_rehearsal_findings`. The gate still runs the validations, the skills comparison, the instructions probe and the overlap check. It archives nothing and reads no git history.
- **The overlap check.** The check stays. The owner decided on 2026-10-22 to follow the evidence below. ADR 0012 first called the check cut-time code that this part removes. That is wrong. The check reads `openspec show <change> --json --deltas-only` for each active change, archives nothing and reads no git history. OpenSpec 1.14.3 has no deterministic check for two changes on one requirement, and `openspec archive --help` lists no option for it. ADR 0010 deletes the check when OpenSpec ships its own (Revisit Conditions). That has not happened.
  - **How I reproduced it.** I used the pinned OpenSpec 1.14.3 from `src/devops_cli/tools_lock/tools.lock`, run by its path, with `DO_NOT_TRACK=1`, `OPENSPEC_TELEMETRY=0` and `OPENSPEC_NO_UPDATE_CHECK=1`. The scratch repository holds one spec with one requirement of three lines, and two active changes that each `MODIFY` that requirement. It is under `.data/agent/scratch/` and is not committed.
  - **One tree.** `openspec validate --all --strict` exits 0 with both changes active. `openspec archive <first> --yes` exits 0. `openspec archive <second> --yes` exits 0 and replaces the text of the first change. It prints no warning and does not refuse.
  - **Two branches, one line.** Each branch archives its own change. The first merge is clean. The second merge stops with a conflict in `openspec/specs/<capability>/spec.md`. Only this case is an ordinary git conflict.
  - **Two branches, different lines.** The first change edits line 1 of the requirement and the second edits line 3. Both merges are clean. The spec holds the lines of both changes, and nothing tells the author.
  - **Second branch rebased, then archived again.** `openspec archive` exits 0 and replaces the text of the first change. Only a changed line in the diff of the spec shows it.
  - **Result.** Git catches one of the four cases. The check reports all four while both changes are still active.
- **Deleted with it.** `OpenSpecArchiveError` and its row in `docs/ERRORS.md` go. `build_git_additions_log_cmd`, `CONST_OPENSPEC_CHANGE_METADATA_FILENAME` and `CONST_OPENSPEC_STATUS_COMPLETE` go. The messages `archive_refused` and `symlink_refused` go. The `static` job of `ci.yml` returns to the default shallow checkout, so `fetch-depth: 0` and its comment go.
- **Text.** The overlap message ends "so that the second waits until the first archives". The help of `devops openspec check` and the docstrings of `gate.py`, `overlap.py` and `skills.py` name no archive at the cut. The comments in `constants.py` follow. `docs/SDLC.md`, `RELEASE_CYCLE.md` and the generated `README.md`, `docs/CLI_REFERENCE.md` and `docs/commands/openspec.md` follow too.
- **Configuration.** `openspec/config.yaml` and its copy in ADR 0010 say two things. A change that modifies a requirement which another active change adds names that issue as a blocker and archives after it. The pull request that closes the issue archives its own change as its last commit, a `Part of` pull request archives nothing, and nobody runs `sync`.
- **ADR 0010.** Every passage that archived at the cut now describes the closing pull request. The passages are the Decision, Conflicts, Layout and names, Lifecycle and Specs start empty. They also include the old "Archive at the cut" bullet, One gate, Delivery, Readiness, Documents and routing, Tests and the sequence. The quoted AGENTS.md wording, Considered Options, Consequences, Revisit Conditions and Decisions Taken change too. The quoted AGENTS.md wording is 3 characters longer, so the ADR now gives 39,984 of 40,000 characters. Step 4 of the sequence now follows step 5, because readiness extends the folder reader of step 5.
- **Tests.** `tests/test_openspec_archive.py` is deleted. `tests/test_openspec_gate.py`, `test_openspec_tool.py` and `test_openspec_command.py` lose the rehearsal, order, symlink and archive-failure cases. The scenarios `merged-out-of-issue-order`, `missing-purpose`, `modified-spec-absent` and `duplicate-added` are gone. The `merged` field and the commits that `build_scenario` made are gone too. A scenario tree holds a `git init` and no commit, so a gate that reads git history fails every gate test.
- **New tests.** `test_the_gate_passes_changes_and_archives_none_of_them` runs the scenarios `pair` and `skip-specs-change`. It asserts no finding and no `archive` run. `test_the_static_job_installs_the_pinned_node_and_openspec_before_the_gate` now asserts that the checkout step has no `fetch-depth`.
- **Recorded runs.** I deleted four scenarios from `tests/fixtures/openspec_runs/recorded_runs.json`. I also deleted every `archive` run and every `validate --specs --strict` run. I edited no recorded text. `tests/test_openspec_contract.py` proves that the record holds only runs that the gate starts.
- **Other task text.** `docs/agent/tasks/task-1844-openspec-scaffold-and-gate.md` loses the archive-function bullet and the rehearsal. Its criterion for a change that would not archive now names the overlap check. `docs/agent/tasks/task-1753-openspec-adoption.md` and `changelog.d/1753.md` no longer say that the cut archives.
