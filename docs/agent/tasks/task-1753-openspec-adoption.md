## Description

ADR 0010 answers the issue's questions 1-5 with the sources and measurements above, records the trial of #1805 with its effort and friction, and records the owner's decision of 2026-10-22 to adopt OpenSpec as the spec and change-proposal layer, so that planning is consistent across Claude Code, Gemini CLI and Copilot, with the in-cluster roadmap jobs joining in the last two steps of the sequence. Each defect found is answered by a design decision tried in scratch: archive at the release cut, in merge order, because archive writes a shared spec file that conflicts between pull requests; a `## Purpose` in the delta that creates a capability; a gate that rehearses the archive and checks that no two active changes edit one requirement; `skip_specs: true` for a change that alters nothing a consumer observes; an npm lockfile in `tools.lock` with an `npm audit` command in the `audit` row; telemetry opt-outs set wherever the tool runs; and skills-only delivery of a four-workflow `custom` profile, with the conventions in `openspec/config.yaml` and the commands as the entry point for an agent with a single turn. The ADR lists every change adoption needs (AGENTS.md, readiness, the closing comment, the cut, the docs inventory, review routing and the tests), the ordered sequence of eight items, the transition rule, the two decisions it takes and the revisit conditions.
