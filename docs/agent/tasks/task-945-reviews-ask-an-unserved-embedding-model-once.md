# Task: Reviews Ask an Unserved Embedding Model Once, and a Failed Embedding Raises (#945)

**Issue**: [#945](https://github.com/dan-petty/devops-cli/issues/945)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/ai

## Description
The owner's gateway routes every backend to the review model `devops-review`, Ollama keeps one model loaded, and `ai.tasks.embedding` names `bge-m3:latest` on the gateway. A review asked for that embedding model on every RAG lookup: per finding in verification (`_collect_rag_verification_blocks`), per file in the payloads (`ai/review/pipeline.py`), in pre-analysis (`ai/analyze/outlines.py`) and per persona prompt (`ai/agents/agent.py`). Every request failed with HTTP 400 and logged `OpenAI embeddings failed ... Using fallback.`. On a node that loads one model, such a request can also evict the review model. The engine then turned the failure into a hash of the text (`_deterministic_fallback`), and retrieval searched Qdrant with it, so the verifier got context blocks picked by noise.

Two causes, two fixes:

- **No memory of the failure** (`ai/rag/investigator.py`). `investigate_rag_context` remembered results per query text only. Now the first `EmbeddingsError` raised while retrieving turns RAG off for the process (`_RAG_STOPPED`, a `threading.Event`, set under `_STOP_LOCK` so concurrent persona threads log one warning between them). `_stop_rag_for_run` logs one WARNING, `MESSAGES.rag.stopped_for_run`, naming the model, the error, and the fix: serve the model, point `ai.tasks.embedding` at a backend that serves it, or set `ai.rag.enabled: false`. It also records `ai.rag.investigation.stopped`. Later calls return `None` before loading settings, building a retriever or sending a request. Until the model has answered a lookup, lookups take turns: `_retrieve` runs the search under `_PROBE_LOCK` while `_RAG_SERVED` (a `threading.Event`) is unset, and `_search` checks `_RAG_STOPPED` before it embeds. Without that, the stop came only when the first failed reply returned, and every lookup that started before then sent its own request. Stage 3 of a review resolves each file's RAG context in parallel (`_resolve_rag_and_contract_context` on `ReviewWorkerPool`, `DEFAULT_GATEWAY_REVIEW_CONCURRENCY = 16` on a gateway), so the owner's setup sent up to 16 requests for `bge-m3:latest` at once. Now a waiting lookup finds RAG stopped and sends nothing. The first lookup the model answers sets `_RAG_SERVED`, and later lookups skip the lock and run in parallel. The lock is taken after the retriever is built, so an unreachable Qdrant does not make lookups wait for one another. If the model fails after it has answered once, only the lookups already past the stop check can send a request, and `_STOP_LOCK` still keeps the warning to one. `clear_investigation_cache()` lifts the stop and clears `_RAG_SERVED`. The function is split into `_retrieve`, `_search`, `_investigation_attributes` and `_recorded_results`, which brings its cyclomatic complexity from 14 to under 10, and its 2048-character query cap moves to `DEFAULT_RAG_INVESTIGATION_MAX_QUERY_CHARS` in `config/defaults.py`.
- **A failed embedding became a fake vector** (`ai/rag/embeddings.py`, `ai/rag/retriever.py`). `_deterministic_fallback`, `EmbeddingVector` and `EmbeddingList` are deleted, with every `is_fallback` path and no shim. Each failure now raises `EmbeddingsError`, whose message is `ERRORS.rag.embedding_failed`: the model, then each endpoint or node asked and what it gave. That is the HTTP status with the reply's body on one line, cut to `CONST_EMBEDDING_REPLY_EXCERPT_CHARS` (500), a reply with the wrong number of vectors, or the error's type and message. `details` carries the model, provider and failures. Each path:
  - The OpenAI-compatible path (`_embed_openai`) wraps the URL check, the request and the reply check. A refused URL or a transport error raises too, so a gateway that cannot be reached also stops RAG for the run.
  - The Ollama path checks each node's reply with `_reply_vectors`. `_try_query_candidate_nodes` collects every node's failure and raises. `_embed_batch_with_subdivision` halves a failed batch and raises once a single text fails on every node. Parallel batches cancel the queued ones on the first such failure.
  - `_dispatch_embed` raises `ERRORS.rag.embedding_no_provider` when no provider and no Ollama URLs are configured.
  - `_populate_fresh_embeddings` writes every vector to Valkey, since every vector now comes from a model.
  - `SemanticRetriever._embed_search_query` no longer swallows the error, so `search` and `retrieve_context` raise it.
- **Callers.**
  - `rag_search` (`ai/tools/builtin_tools.py`) returns `MESSAGES.rag.search_embedding_failed` (`RAG search unavailable: <error>. Fallback: use search_code.`), as it does for an unreachable Qdrant.
  - A new `exit_on_error(error_type)` context manager (`core/cli.py`) prints the error with markup escaped and exits with its status. `devops ai rag index`, `index-kb`, `query`/`search` and `drift --auto-sync`, and `devops ai ingest index-libraries` and `query-library`, run their embedding step inside it. They exit 1 with the message instead of a traceback. `WorkspaceIndexer` embeds each batch before it upserts it, and `LibraryVectorStore.index_contract` embeds before it upserts, so a text the model did not embed gets no vector in Qdrant.
  - Reviewed and unchanged. The embedding benchmark runner (`ai/benchmark/embedding_runner.py`) wraps each embed call in its own `except`, logs the failure, and scores a model it could not embed with no vectors: dimension 0 and zero recall. `ai/agents/embeddings.py` (`EngineEmbeddingModel`, `Embedder._get_engine`) calls the engine's `embed_query` and `embed_texts` and lets their errors through. Neither relied on the fallback.
- **Docs.**
  - `config.example.yaml` says what happens when the embedding model cannot embed, and how to fix it.
  - The knowledge base's RAG manual (`knowledge_base/devops_cli/tasks/rag_context_indexing.md`) gains a best-practice item on serving the model or turning RAG off.
  - The comments on `CONST_KNOWN_EMBEDDING_DIMENSIONS` and `DEFAULT_RAG_EMBEDDING_MIN_BATCH_SIZE` no longer describe a fallback. No other doc, knowledge-base page or `config.example.yaml` comment described it.
  - The changelog entry is `changelog.d/945.md`.

- [x] No fallback. `_deterministic_fallback`, `EmbeddingVector` and `EmbeddingList` are gone, and `git grep -n -E "_deterministic_fallback|EmbeddingVector|EmbeddingList|is_fallback|Using fallback"` finds nothing outside this file and the changelog fragment.
