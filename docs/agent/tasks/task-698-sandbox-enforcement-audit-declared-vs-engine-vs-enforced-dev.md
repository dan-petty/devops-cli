## 1. Description & Objectives

Both sandbox runners declare hardening as Docker SDK kwargs — `cap_drop ALL`, `no-new-privileges`, `pids_limit 256`, `network_mode none` (`src/devops_cli/sandbox/engine.py:227-239`, `src/devops_cli/docker/sandbox.py:260-273`); `read_only` and a `noexec` tmpfs exist only in the deploy engine (`engine.py:234-235`; the workload runner's `read_only` only sets the bind mode, `docker/sandbox.py:254,264`). Tests check those kwargs at three sites (`tests/test_sandbox_lifecycle.py:311-315`, `tests/test_workload_sandbox.py:78-80,167-179`), only against a mocked SDK. Nothing queries the engine: `DockerEngineService` (`src/devops_cli/docker/engine.py:197`) has no `SecurityOptions` accessor, and the two dry-run summaries disagree (`commands/sandbox.py:183-188`, `docker/sandbox.py:155-172`). vibes hit this failure: `CISPolicyAuditor` scored the policy 100.0/100, 8/8, while the engine enforced 0 of 8; the fix scored the engine about to run, named each unapplied control, and tested that the scores differ (`examples/ephemeral-container-sandbox/sandbox.py:104,222-262`, `test_sandbox.py:206-231`, `observations/systems/19-self-consistency-is-not-conformance.md:27,115,132`).

#### Key Deliverables:
- **Deliverable**: A `devops sandbox audit` command and `sandbox_audit` MCP tool beside `sandbox_deploy` (`src/devops_cli/ai/mcp/server.py:1289,1336`), with per-control columns DECLARED, ENGINE, ENFORCED. Three sequential PRs. PR1: DECLARED derives from the production `_build_create_kwargs` (`sandbox/engine.py:207`, `docker/sandbox.py:252-273`); both dry-runs read those kwargs, replacing the literal at `commands/sandbox.py:183-188`. ENGINE comes from a new `DockerEngineService.security_options()` calling `client.info()['SecurityOptions']` via the `docker` SDK (`pyproject.toml:24`); an unreachable daemon reports 0 enforced plus the reason. PR2: `--probe` runs the runner's identical kwargs on `DEFAULT_SANDBOX_IMAGE` (`config/defaults.py:641`), recording EPERM/ENOSYS/success for `io_uring_setup`, `unshare(CLONE_NEWUSER)`, `ptrace`, `mount`, non-loopback `connect`, writes outside `/tmp`/`/workspace`, forks past `pids_limit`; an unprobed control reads `not probed`, never enforced. A mocked daemon reporting `profile=unconfined` must lower ENFORCED with DECLARED constant. PR3: a `seccomp_profile` field on `SandboxDeployConfig` (`sandbox/models.py:360`) and `WorkloadSandboxConfig` (`docker/sandbox.py:46`) reading an OCI profile, rejecting a missing or `SCMP_ACT_ALLOW` `defaultAction`, passing `security_opt: ["seccomp=<profile JSON>"]`. Do not port vibes `tools/seccomp_synthesizer.py`: the engine's builtin profile is the maintained default-deny artifact (Measured); tighter profiles come from a maintained tracer (`oci-seccomp-bpf-hook`), audit-confirmed. The harness shell tool (`ai/harness/shell.py:272`, process-group isolation only) is listed enforcing no container control.
