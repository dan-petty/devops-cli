## Description
The model verifier marked 0 of 94 VERIFIED rows strictly valid, its confidence did not separate valid findings from false ones (0.950 against 0.958), it dropped 47 of 125 valid tool candidate-runs, and its keyword guards kept false rows more often than valid ones. ADR 0005 has tools originate findings and only tools and people change a finding's state, so the verifier, the hallucination catalog that fed it, the deterministic model-claim guards, the criteria runner, the calibration caps, location anchoring and the mitigations ledger are deleted with no flag and no re-export. No verdict path to a model remains: a person's verdict is a label on the session's files, and a known false positive is a reviewed `.devops/review.toml` suppression.

The calibration caps were the only cap on scanner findings in tests and documents, because `[severity_caps]` never reached `admit()`. This item carries #1301: the caps now apply at admission, and a secret scanner's finding is exempt.

## Key Changes
- **Deleted** (`src/devops_cli/ai/review/`): `verification.py`, `common_hallucinations.py` and `common_hallucinations.json`, `construct_validator.py`, `criteria_evidence.py`, `calibration.py`, `judged_claims.py`, `mitigations.py` and `mitigated_findings.json`, `stages/adversarial_debate.py`; the prompts `ai/tasks/verify_finding.md`, `verify_finding_system.md` and the two `negative_exemplars_*.md` the catalog loaded.
- **Pipeline** (`ai/review/pipeline.py`): the verification stage, `_anchor_page_findings`, the calibration loop, the removed-symbol count and report row, the Executable Criteria report section, `run_self_test` and `run_pipeline_self_test` are gone, with the `verification_client` parameter. The constructor reads `.devops/review.toml` once (`load_review_config`) for its suppressions and `[severity_caps]` (`load_severity_caps`), and both `_admit_scanner_findings` calls, head and base revision, pass the caps to `admit()`. A candidate a secret scanner reported, any Gitleaks rule or Trivy's `SECRET` results (`CONST_REVIEW_SECRET_SCANNER_RULES`, `_is_secret_scanner_result`), is admitted with no cap. Any other scanner's candidate is capped, even when its words make its category `secret_exposure`, as Bandit's B105 and Semgrep's credential-disclosure rule do.
- **Runner** (`ai/review/runner.py`): the legacy engine's Step 3 (`_execute_findings_validation`) is gone and its steps are renumbered. `_parse_reply` clears the status, adjudicator and confidence a segment or recompose reply wrote (`reset_verification_state`, as the orchestrator does), a recompose that lists no finding keeps the merged segment findings, and `_merge_segment_results` moved here; `ReviewClients` has no `verification` client and the orchestrated review has no verification stage.
- **Suppression perimeter** (`review/suppression.py`): `ReviewSuppression.covers(path)` is the path half of `matches`, and matches with `PurePosixPath.full_match` at any depth, so `tests/**` covers `tests/ai/review/test_runner.py` (`PurePosixPath.match` read `**` as one directory); `covering_suppressions` returns the unexpired suppressions whose path covers a changed file, and `format_covering_suppressions` words the warning from `lang/en/messages.py`, the review.toml text escaped (`escape_text`) so a reason holding `[/b]` or `list[str]` prints as written. `_check_and_warn_perimeter_changes` reads them at the base revision for branch and PR reviews, and `devops pr check-readiness` (`_check_pr_perimeter_changes`) at the working directory's repository root.
- **Verdicts** (`ai/review/adjudication.py`, `commands/review.py`): verdicts write the session files alone and every one records `verified_by="human"`. `devops review verify` loses `--adjudicator`, `--perimeter` and `--regression-test`; `devops review hallucinations` is gone; `--no-verification` and `--verification-only` are gone from `review path|branch|pr` and the `ai review` alias. `SavedFinding` loses `learned_catalog_ids` and `mitigation_ledger_ids`. `VerifiedBy` (`ai/review/verdicts.py`) names only the labels still written: `human`, `deterministic:vulnerable_dependency` and `deterministic:dry_run`; `Finding.verified_by` is plain text, so older sessions still read.
- **Cited code** (`ai/review/cited_code.py`): `record_cited_code` and `cited_code` moved out of the deleted `verification.py` and `judged_claims.py`. The orchestrator records the code each finding cites when it writes findings.json and candidates.json, read from the reviewed checkout through `_resolve_file_path`, at most `DEFAULT_CITED_EXCERPT_MAX_LINES` lines, with secrets masked; a `secret_exposure` finding records none. It is evidence about a location, not a verdict: `review score` places a row whose location is an absolute path into a review worktree by it, as the recall protocol (`docs/SELF_IMPROVEMENT.md` section 3) needs, and `review export-feedback` keeps its `cited_excerpt`. The deleted `_is_secret_path` name check is not carried over. The legacy engine records none (#995 deletes it).
- **MCP and agent tools**: the MCP `verify_finding` tool is gone, with its entries in the devsecops and qa agent tool lists.
- **Other callers**: `ai/prompt_eval.py` replays nothing and counts the recorded verdicts per labeller; `ai/review/classification.py` shows no exemplars; `ai/spend/stage.py` and `ai/run_store.py` name no verification stage; `review_environment.py` keeps the criteria allowlist validator (`validate_criteria_command`, with `python_invocation` moved beside it) and loses the executor.
- **Config**: `ai.tasks.verification` and its four `DEVOPS_CLI_AI_TASK_VERIFICATION_*` variables, and the constants and defaults left with no reader, are removed. The verifier's note kinds stay in `CONST_VERIFICATION_NOTE_KINDS`, which review statistics count in stored sessions, and `CONST_VERIFIED_BY_AGENT` stays, which review history reads.
- **Suppressions** (`.devops/review.toml`): the six Semgrep claims people had judged in the learned catalog are rule and path suppressions, each over its whole file, each with the person's recorded resolution as its reason and an expiry of 2027-04-09: `python-logger-credential-disclosure` on `security/secrets.py`, `config/settings.py`, `github/secrets.py` and `server/service.py`, and `non-literal-import` on `telemetry/memory_profiler.py` and `commands/release.py`. The seventh, on `security/vault_lease.py`, was already suppressed.
