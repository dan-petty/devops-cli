# Task: Every Application Pins Automated Sync Enabled in Git, So the devops Application Syncs Again and a UI Pause Is Reverted (#1626)

**Issue**: [#1626](https://github.com/dan-petty/devops-cli/issues/1626)
**Scope**: scope/k8s
**Feasibility**: Checked read-only on 2026-10-23 at `main` 6ec1cd43. Argo CD is v3.5.3 (`helm list -A`, image `quay.io/argoproj/argocd:v3.5.3`). The installed Application CRD has the boolean `spec.syncPolicy.automated.enabled`. The v3.5.3 `docs/user-guide/auto_sync.md` says that with `false` the controller skips automated sync, and that a null value counts as enabled. `kubectl -n argocd get applications.argoproj.io -o yaml` showed `devops` as the only one of 27 Applications with `enabled: false`. The manager `argocd-server` owned that field. `devops` was OutOfSync on Deployment, CronJob and Ingress `roadmap-service`. Its `last-applied-configuration` holds `automated: {prune, selfHeal}` with no `enabled`, so `cluster` showed `devops` as Synced. `cluster` and `bootstrap` use client-side apply and the default diff: neither sets `ServerSideApply`, and `argocd-cmd-params-cm` sets no server-side diff. Prometheus showed `ArgoCdAutoSyncDisabled` firing for `devops`. For the amendment of 2026-10-18: ImageUpdater `devops` (controller v1.3.0) was Ready with `imagesManaged: 0` and `lastUpdatedAt` 2026-10-10, and Application `devops` had no `status.summary.images`. In the v1.3.0 source, `GetImagesFromApplication` (`pkg/argocd/argocd.go`) adds an image that no pod runs only when it sets `ForceUpdate`. `UpdateApplication` (`pkg/argocd/update.go`) skips an image that is not in that list, and writes nothing when the spec already names the new image. The installed ImageUpdater CRD has `forceUpdate` under `images[].commonUpdateSettings`, with the default `false`.

## Description

- [x] **Pin** (`k8s/argocd/apps/*.yaml`, `k8s/argocd/bootstrap/{bootstrap,cluster}.yaml`): each of the 27 Applications sets `enabled: true` under `spec.syncPolicy.automated`. The value goes into the parent's last-applied configuration. The parent's three-way diff then shows a pause from the UI as OutOfSync, and its self-heal reverts the pause. The edit is one line in each Application.
- [x] **Test** (`tests/test_k8s_argocd_apps.py`): `test_automated_sync_policies` asserts `automated.enabled is True` for each Application, `bootstrap` and `cluster` included. It failed before the change, first on `bootstrap`.
- [x] **Docs** (`k8s/README.md`, GitOps): the new "Pausing an Application" subsection says to pause an Application in git, never in the UI or the API. For an emergency stop, it says to pause from the top down, and how `bootstrap` restores the others. The "Replaced Hand Steps" table names `automated.enabled: true`.
- [x] **Image Updater** (the amendment of 2026-10-18): `k8s/argocd/image-updater-values.yaml` sets `forceUpdate: true` on the service image, and its header gives the reason. No pod in the Application's tree runs the image: CronJob `devops-cli` is a suspended template, and `roadmap-service` is at 0 replicas. `test_image_updater_keeps_only_application_devops_on_the_digest_of_service_latest` compares the whole values file and failed before the change. `k8s/README.md` "Service Image Updates" says why the setting is necessary.
- [x] **Alert**: `ArgoCdAutoSyncDisabled` (#551, `k8s/monitoring/prometheus-values.yaml`) already fires on a paused Application. This change does not change it.
- [x] **#1562**: the merge does the last step of `task-1562-suspend-roadmap-service.md`, which turns the `devops` sync on again. Git has held `replicas: 0` for `roadmap-service` since that change, so the sync starts no pod.
- The amendment's executable release check is not in this change. That check compares the `devops` Application's digest with the digest of `service:latest` and reports a mismatch as an error. Follow-up issue: #1997.
- Pending a person: before the merge, restore the host overrides of the `devops` Application, which the manual sync of 2026-10-21 dropped (#1817). Run `devops k8s deploy-stack --stack devops --no-push-secrets --no-wait --no-configure-urls`. Without this step, the first sync after the merge gives Ingress `roadmap-service` the placeholder host.
- Pending a person: after the merge, `kubectl -n argocd get application devops -o jsonpath='{.spec.syncPolicy.automated}'` shows `"enabled":true`. `devops argo cd apps status devops` is Synced and Healthy, and `kubectl -n devops get deploy roadmap-service` still shows `0/0`.
- Pending a person: within one poll (2 minutes) after the merge, `kubectl -n argocd get imageupdater devops -o jsonpath='{.status.imagesManaged}'` prints `1`. `kubectl -n argocd get application devops -o jsonpath='{.spec.source.kustomize.images}'` names the digest that `service:latest` points at, and CronJob `devops-cli` runs it.
- Pending a person: pause `devops` in the Argo CD UI. `cluster` shows it OutOfSync and turns its automated sync on again at its next self-heal.
