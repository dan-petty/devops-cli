# Task: Ollama Clients Name Services That Select Serving Tiers (#1637)

**Issue**: [#1637](https://github.com/dan-petty/devops-cli/issues/1637)
**Scope**: scope/k8s
**Feasibility**: Checked read-only against the live cluster on 2026-10-23. The DaemonSets `ollama-16gib`, `ollama-48gib`, `ollama-48gib-slow` and `ollama-64gib` each have one ready pod. `ollama-24gib`, `ollama-32gib`, `ollama-72gib`, `ollama-96gib` and `ollama-128gib` desire none, and their EndpointSlices hold no endpoint. Prometheus `kube_daemonset_status_number_ready` shows `ollama-24gib` at 0 since about 2026-10-04, and `ollama-16gib` at 0 from about 2026-10-12 until its pod started again on 2026-10-23. The 48 GiB and 64 GiB tiers served through the whole period. The live Open WebUI StatefulSet sets `OLLAMA_BASE_URLS` to `ollama-24gib` and `ollama-64gib`, and sets no RAG Ollama URL. Open WebUI v0.11.4's `config.py` then defaults `RAG_OLLAMA_BASE_URL` to `http://localhost:11434`, where its pod runs no Ollama, and defaults `RAG_OPENAI_API_BASE_URL` to `https://api.openai.com/v1` with no key. `helm template` of chart open-webui 16.6.0 with the new values renders `OLLAMA_BASE_URLS` with the two speed Services and the three RAG variables, the key as a `secretKeyRef`. Qdrant holds no Open WebUI collection, so a new embedding model needs no new index.

## Description
Several clients of Ollama named VRAM tiers whose host was offline. Open WebUI's first Ollama connection named `ollama-24gib`, which has had no pod since early October, and its RAG embeddings went to `localhost`. The ollama ingress, the CLI's default Service and the CLI's direct-Ollama failover routes named `ollama-16gib`, which had no pod for eleven days. Each name was a VRAM size, so each host change broke the clients without a sign.

Clients of Ollama's native API now name the speed Services `ollama-fast` and `ollama-standard`, which select the 48 GiB and 64 GiB tiers. A host change now changes one selector in `k8s/llm/profiles/services.yaml`. Open WebUI sends its RAG embeddings to the gateway, which serves `qwen3-embedding:0.6b` from the background tier. That tier keeps the embedding model loaded beside `qwen3.8:27b`, so Open WebUI adds no third model there (#1064, #1221). The GPU placement table of `k8s/README.md` records which tiers serve, and a test holds every client to a Service that selects a serving tier.

## Key Changes
- `k8s/ingress/ingress-routes.yaml`: the `ollama-ingress` backend is `ollama-fast`.
- `src/devops_cli/config/defaults.py`: `DEFAULT_OLLAMA_CLUSTER_SERVICE` is `ollama-fast`. `devops k8s port-forward --stack llm`, `devops k8s configure-urls` and the failover routes in `ai/gateway.py` follow it through `DEFAULT_OLLAMA_CLUSTER_URL`.
- `k8s/llm/values-open-webui.yaml`: `ollamaUrls` names `ollama-fast` and `ollama-standard`. `RAG_EMBEDDING_ENGINE` is `openai`, `RAG_OPENAI_API_BASE_URL` is the gateway, `RAG_OPENAI_API_KEY` comes from `llm-gateway-secrets/master-key`, and `RAG_EMBEDDING_MODEL` is `qwen3-embedding:0.6b`. The stale comments about a 16 GiB and a 24 GiB embedding node are gone.
- `k8s/README.md`: the GPU placement table has a Serves column, and the text says which clients use the speed Services and how the column and the test work together. The port-forward example names `ollama-fast`. The `devops-review` line names the three tiers the ConfigMap routes to, with `least-busy` routing and no weights. The Open WebUI paragraph tells a person what to change in an existing installation.
- `k8s/llm/profiles/README.md`: section 2 describes the speed Services and points at the record of serving tiers. The gateway excerpt loses the `weight` fields that the ConfigMap no longer has, and its 16 GiB window is 48000.
- `tests/test_k8s_llm_gateway.py`: `test_the_gpu_placement_table_says_for_each_tier_whether_it_serves`, `test_every_ollama_consumer_names_a_service_that_selects_a_serving_tier` and the negative control `test_a_tier_that_stops_serving_names_each_consumer_that_reaches_it_alone`. The clients are the CLI defaults and failover routes, the review slots, the ingress, Open WebUI, the gateway ConfigMap and the devcontainer. Each URL on an Ollama port in the `llm` namespace counts, so a new client setting is found with no edit. `test_open_webui_values_connect_to_gateway` checks the RAG settings, and the embedding registry test reads Open WebUI's RAG model.
- `tests/support/markdown_examples.py`: `tables()` reads the tables of a Markdown document with markdown-it-py's table rule.
