## Description
The documentation of the review and self-improvement loop described mechanisms the code does not have: `performance` and `sre` personas and an ensemble by default, a five-phase protocol, `devops review verify` as automated verification, an export that grounds RAG and refines prompts, reviewers that cross-reference the catalog, five metrics nothing sends, and `review_output_instruction.md` as a prompt the review sends. It lands after the review-loop items of this release (#846, #948, #949, #950, #951, #1043, #1044, #946, #972), and describes the code they left.

- **`docs/SELF_IMPROVEMENT.md` section 1** is now *The Loop as It Runs*: the six stages of a review (the persona's system prompt ending in `ai/tasks/guardrails_isolation.md`, and re-ranking marking each file that has a reportable finding without changing one), the verdicts `devops review verify` records, what a person's verdict teaches (the learned catalog, the mitigations ledger, review history), the feedback dataset and its one reader, `devops ai prompt-eval`, where each kind of review data lives and how `DEVOPS_CLI_DATA_DIR` moves it, and what the loop does not do. Every statement names its file and line as `path:line`, with paths under `src/devops_cli/` written from there. One sentence points to the ADR a later release adds for the evidence-first redesign and says the personas and verifier described are what runs until it lands. The *Closed-Loop Feedback Inversion* steps file an issue instead of adding to `docs/ROADMAP.md`.
- **Section 2** follows the four steps of `tasks/review.md` (ground, inspect, falsify, formulate) instead of five phases; step 3 says a persona is shown up to eight catalog entries and does not look the catalog up. A dated calibration record for session `20261001-224227` gives the session's counts, the hand triage, the nine failure signatures the prompt A/B counts, and the mechanism each failure now has.
- **Section 3** reads findings with `devops review findings`, records an agent's verdict with `--adjudicator agent`, says that only a person's verdict teaches the loop, and exports with `--status ALL` to the dataset `devops ai prompt-eval` reads.
- **Section 4** lists the two metrics a review sends, `devops_cli_review_duration_seconds` and `devops_cli_findings_total`, with their labels, when they are sent, that the `persona` label is the review's `--persona` or `devsecops`, and the review's trace spans. **Section 5.6** says where each calibration signal is read, and that no command computes the first four. Section 5.1 no longer counts `review_output_instruction.md` as a prompt a model reads.
- **AGENTS.md** (`:125`, `:127`, `:129`, `:131`, `:132`, `:204`, `:302`, `:405`, `:406`, `:411`, `:414`, `:415`, `:423`): friction, an interface inconsistency, a bad pattern and a suggestion are each filed as a candidate issue, so the roadmap block no longer tells agents to add to `docs/ROADMAP.md` (ADR 0001); verdicts are an agent's, and the export feeds `devops ai prompt-eval` only; the default review runs the DevSecOps persona alone; RAG chunks are untrusted context and verdicts never reach the index; what a review enforces about CVE citations, and that nothing checks one an agent writes; and that a review gives its models the opening 3,000 characters of AGENTS.md as conventions and all of `.devops/review.md`. `generate_agents_md` carries the same issue rules in its devops-cli roadmap block (`ai/instruction_generator.py:209`, `:211`, `:213`, `:215`, `:216`), and `tests/test_instruction_generator.py` now expects them and no rule that adds to `docs/ROADMAP.md`. AGENTS.md is edited in place: `devops ai agents` renders the short template of `ai/instruction_generator.py` or an LLM's text, either of which would replace the curated file (#840 adds the guard).
- **Knowledge base**: `tasks/ai_code_review.md` and `topics/agentic_ai_and_code_reviews.md` describe the stages (re-ranking changes no finding; the persona prompt includes the isolation guardrails), the personas (challenger included), verification, the rule filter, confidence, the learned catalog and the dataset as they run, and `Finding`/`SavedFinding` instead of a `ReviewFinding` that does not exist. The `devops review` examples that did not parse are fixed in `libraries/pygithub.md` (`--post`), `tools/ollama.md` and `tasks/ai_code_review.md` (`DEVOPS_CLI_AI_TASK_ANALYSIS_*` instead of `--provider`/`--model`), and removed from `tasks/ai_code_review.md` (`devops ai review patch`) and `topics/model_governance_routing_and_curation.md` (`--orchestration-shape`). `devops review findings --session latest`, which matches no session, is now `devops review findings --details`.
- **`CONTEXT.md`**: a mitigated verdict is a defect a named guard in named files limits, as the verifier defines it, and unverified is a verdict; a verdict records who gave it.
- **Help and generated docs**: `--persona`, `--all`, `--summary` ("Has no effect", with no history), `findings --invalidated` and the `export-feedback` docstring say what happens, and the hallucinations group names what the catalog holds. `devops docs generate --sync-readme` regenerated `docs/commands/review.md`, `docs/commands/ai.md`, `docs/CLI_REFERENCE.md` and the README matrix.
- **Tests** (`tests/test_docs_review_loop.py`, with the Markdown reader in `tests/markdown_examples.py`): markdown-it-py's CommonMark parser finds shell fences and code spans, the standard library's shell lexer (`shlex.shlex` with `punctuation_chars`) splits each line into words and operators, a `devops` command ends at the first operator whether spaced or attached (`stats;`, `stats|head`), and `resolve_devops_argv` parses it on the Typer app, each distinct command once, with `<name>`, `$VAR`, `[OPTIONS]`, `...` and upper-case metavariables as placeholders. markdown-it-py, already installed through Rich, is declared as a development dependency. tree-sitter-markdown's inline grammar was tried first and crashed the interpreter (SIGSEGV) on several of the repository's pages. The lexer splits `;`, `&`, `|`, `(` and `)` from the words they touch but leaves `<` and `>` inside a word, because the documents write `<session>` for a value the reader fills in and splitting it would end the command at `<`; a spaced redirection still ends a command, and an attached one (`stats>out.txt`) is read as one word and reported.
