# Task: The Review Report Ranks, Counts and Headlines What Was Verified (#948)

**Issue**: [#948](https://github.com/dan-petty/devops-cli/issues/948)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/review

## Description
Review session `20261001-224227` reported "563 reportable findings (21 Critical, 263 High)" and headlined CVE-2021-44228 (Log4Shell) against a Python CLI. A triage of all 563 found 46 real defects, none above MEDIUM. The failures were in code: `sort_findings` ranked by model confidence before verification status; the headline named the first reference or title of the first-sorted findings; Key Bad Patterns had 280 bullets, 257 of them for one finding; the analyzer line was a literal; the counts mixed every status; nothing compared a cited advisory with the session's dependency scan; 148 free-text category strings could not be grouped; the verifier could raise a severity, and tests and docs findings were CRITICAL or HIGH. The two scope additions extend the path routing to branch and pull request reviews, keep routed files in the secret scan, stop an all-routed diff from reaching the model, and make the executive summary count an analyzer as executed only when it ran.

## Key Changes
- **Ranking** (`ai/review_schema.py`). `sort_findings` orders by (not reportable, status VERIFIED < UNVERIFIED < MITIGATED < INVALIDATED, severity, file and first line, title). `_STATUS_RANK` serves it and `_merge_two_findings`, whose own copy it replaces.
- **Executive summary** (`ai/review/stages/reporting.py`, rewritten). `format_status_counts` and `status_counts` count VERIFIED and UNVERIFIED findings, each with its severities, and list apart the UNVERIFIED findings whose `verification_note` starts with `verification-unavailable` and the MITIGATED ones. `verified_themes` groups VERIFIED findings by defect class, drops classes seen once and `other`, and ranks by (most severe, most findings). The headline names the first `DEFAULT_REVIEW_HEADLINE_THEMES` (3) and counts the rest, and Key Bad Patterns gives one line per recurring class with a representative location. `_derive_finding_theme` and its title and reference parsing are gone. `review.md`'s summary section adds a `By status:` line, and the terminal's Review Summary a `By Status` row (`_status_rows` in `pipeline.py`).
- **Analyzer line** (`ai/review/pipeline.py`). `_static_analysis_line` builds the line from `static_analyzers` and from `static_severities`, the severities of the scan's own findings that `_run_static_scanners` now records: the analyzers that ran, the critical findings reported, then those on built-in patterns only, failed or not installed. It is no longer a Key Good Pattern.
- **Taxonomy** (`ai/review_schema.py`, `config/constants.py`). `DefectClass` is a closed `StrEnum` of 27 classes. `Finding._assign_category` runs `assign_category`: a CWE in the category or the references becomes `CWE-<n>`; otherwise `defect_class` maps the category's words, or with no category the title's, through `CONST_REVIEW_DEFECT_KEYWORDS`, and the original stays in `category_raw`. `CONST_REVIEW_CWE_DEFECT_CLASSES` maps CWE ids to classes. `resolve_finding_category` (`ai/review/category_metrics.py`) is the one theme function: the report, the category baseline table and `devops review stats` call it. `HistoryFinding` reads `category_raw` and `references` and assigns its category the same way, so history's slim parse and a full parse agree, and drops `description` and `invalidation_reason`, which only the hallucination-category inference read.
- **Severity calibration** (`ai/review/calibration.py`, new). `calibrate_severity` caps a severity by each rule that applies and never raises one: not VERIFIED caps at HIGH, a title with a word from `CONST_REVIEW_HEDGE_WORDS` caps at MEDIUM unless VERIFIED by `criteria` (`CONST_REVIEW_EVIDENTIAL_ADJUDICATORS`), and a finding in a test (`is_test_path`) or a document (`classify_file_context`) caps at LOW unless it is a VERIFIED `secret_exposure` or a secret scanner's match that was not INVALIDATED (`_is_secret_scan_match`: a title starting with one of `CONST_REVIEW_SECRET_SCAN_TITLE_PREFIXES`, `[GITLEAKS` or `[SECRET]`). The cited path is read relative to the repository `root` the caller passes, and an absolute path outside it by its name alone, because scanners cite absolute paths (#788). The first severity stays in `severity_raw`. `generate_consolidated_report` calibrates every payload, with `find_repo_root(target_dir)` as the root, before candidates.json, findings.json and the report are written, and `_save_findings_json` does the same on the persona-loop path. Calibration runs once, at the report: a person's verdict through `devops review verify` comes later and leaves severities as they are, so `human` is not an evidential adjudicator. `less_severe` lets `_resolve_finding_attributes` take a verifier's severity only when it is lower, and `_verify_single_file_payload` now copies the verified severity, `severity_raw`, references and `reference_note` back to the payload.
- **Advisories** (`ai/review/verification.py`). `_strip_unbacked_advisories` runs on every UNVERIFIED finding after the early checks. It removes each reference naming a CVE or GHSA id that no `DependencySpec.vulnerabilities` record of the session carries by `id` or `aliases`, and writes `reference_note`; a finding left with no reference is INVALIDATED as `deterministic:unbacked_advisory`. `VulnerabilityRecord.aliases` is new, filled from OSV's `aliases`. `_is_placeholder_advisory` adds runs of ascending digits from 0 or 1 (`CVE-2023-1234`) to the `x`, `n` and `?` runs, and `_check_placeholder_advisory_hallucination` spares an id a record of the session's dependencies carries: sequential ids are published ones too (CVE-2016-1234, glibc; CVE-2023-1234, Chrome). `_run_static_scanners` records the advisories the static analyzers looked up, Trivy's `[CVE-...]` findings, as `DependencySpec` records (`_scanner_advisories`, `scanner_advisories`), and `execute_finding_verification` passes them with `_session_dependencies(file_payloads)` to each `_verify_single_file_payload`, so Trivy's own finding of CVE-2020-11111 stands, a persona reference to an advisory Trivy found is backed, and a package Trivy found vulnerable is not scanned clean. `strip_model_set_state` (renamed from `_strip_model_set_verification_state`) clears a reply's `external_dependencies`, `network_references`, `severity_raw` and `reference_note`, whether `parse_review_response` parsed it or the agent framework did (`_resolve_step_parsed_data`).
- **Path routing** (`ai/review/chunker.py`, `ai/review/runner.py`, `commands/review.py`). `skips_persona_review` decides for all three targets: a lockfile by name (`CONST_REVIEW_GENERATED_FILES`) or a path matching `CONST_REVIEW_ROUTED_PATH_PATTERNS` (`CHANGELOG.md`, `changelog.d/**`, `docs/ROADMAP.md`, `docs/agent/tasks/**`, `docs/adr/**`, `docs/commands/*.md`, `docs/CLI_REFERENCE.md`) through `PurePath.full_match`. It replaces `_is_generated_diff_block` in the branch and PR page builder (`diff_stream_chunks`) and the lockfile check in `_is_candidate_file_included`. A path review partitions its candidates once (`_partition_candidate_files`) and `_prepare_path_content` returns the routed files as a fourth value; a file named as the target is reviewed as asked.
- **Routed files reach the secret scan** (`ai/review/pipeline.py`, `ai/review/runner.py`). `_execute_review_workflow` hands `ReviewPipelineOrchestrator(secret_scan_files=...)` the path review's routed files and, for a branch or PR, the non-deleted changes in `base_revision` that `skips_persona_review` matches (`_routed_changes`). `_scan_gitleaks_and_semgrep` split into `_scan_secrets`, which reads reviewed and routed files, and `_scan_semgrep`, which reads reviewed files; Gitleaks' file kind is now `secrets`. A routed file with a finding gets a payload of its own, which `execute_multi_persona_review` skips, and whose verifier `_verification_context` sends only the numbered lines around what each finding cites (`_cited_lines`): its line, or for a Trivy location such as `uv.lock:requests` the line declaring the package, else the first naming it, with `DEFAULT_LOCATION_CONTEXT_LINES` either side. It was sent the whole file, 558 kB for this repository's uv.lock.
- **An all-routed change calls no model** (`ai/review/chunker.py`, `ai/review/runner.py`). `diff_stream_chunks` yields no page when every file is skipped. `_execute_review_workflow` sends a review with no page to `_review_routed_files_only`, which prints `MESSAGES.review.nothing_for_personas` (or `nothing_for_personas_unscanned` with the static scan off), runs `ReviewPipelineOrchestrator.scan_routed_files` (static scanners only) and writes the report, before the pre-analysis, the LLM client check and `_run_persona_loop`. `generate_consolidated_report` keeps an explicit empty `personas` list, so that report's findings.json names no persona.
- **Docs.** `docs/SDLC.md` and the knowledge base's `tasks/ai_code_review.md` describe the routing, the taxonomy, the caps, the advisory rule and the new summary.
