# Task: Addresses Are Classified With ipaddress, and the Sandbox Local Whitelist Refuses host.docker.internal (#1174)

**Issue**: [#1174](https://github.com/dan-petty/devops-cli/issues/1174)
**Scope**: scope/security
**Feasibility**: Measured on Python 3.14.7 at 3dd7fa6. `ipaddress` reads 224.0.0.1, ff02::1, 64:ff9b::a00:1, 4000::1 and 5f00::1 as global, and the last three also as reserved, so `is_global` alone is not "public". It reads every documentation and benchmarking block (192.0.2.0/24, 198.18.0.0/15, 2001:db8::/32, 2001:2::/48, 3fff::/20) as private and not global, so no library tells them from RFC 1918 space, and it reads 192.88.99.0/24 as global although IANA's IPv4 special-purpose registry lists 192.88.99.2/32 (RFC 6751) as not globally reachable. It reads site-local `fec0::1` as global and not reserved (`is_reserved` stops at fe00::/9), although RFC 3879 deprecated fec0::/10 and IANA's IPv6 address space registry lists it as reserved by the IETF. Its `is_global` follows an IPv4-mapped address to the IPv4 address it carries, but membership in an IPv4 network does not, so `::ffff:192.88.99.2` passed both constants until `_parse_ip` normalised it. With the RFC tables, 224.0.0.1 was in no class and `check_threat_intel` sent it to Cloudflare Radar (`test_check_threat_intel_asks_no_service_about_a_local_address` failed on the base with one request). Classifying the raw string let prose punctuation through: `check_threat_intel("100.64.0.1.")`, `"224.0.0.1,"`, `"10.0.0.1."` and `"2130706433"` each sent a GET to Radar's domain lookup with `httpx2.Client.get` patched, since `ipaddress` parses none of them and only `is_example_or_invalid_network_target` stripped the punctuation. `socket.inet_aton` reads `2130706433`, `127.1` and `0x7f.0.0.1` as 127.0.0.1, as a resolver dials them, but glibc's also reads `1 555 0100` as 0.0.0.1 because it stops at whitespace, so a target holding whitespace names no address. `dns.name.from_text` equality ignores case and a trailing dot, as `is_cloud_metadata_name` already relies on.

## Description

`security/reference_extractor.py` dropped its hand-kept RFC 6890 tables. Every specified address is now in exactly one of three classes. It is a documented example when it lies in `CONST_DOCUMENTATION_IP_NETWORKS` (RFC 5737, RFC 3849, RFC 9637, RFC 2544, RFC 5180). It is public when it is global, not reserved and not multicast, and outside both that constant and `CONST_NON_GLOBAL_NETWORKS_STDLIB_READS_GLOBAL` (192.88.99.0/24 and site-local fec0::/10). Otherwise it is local. An IPv4-mapped IPv6 address is classed as the IPv4 address it carries. Both constants hold `ipaddress` networks in `config/constants.py`, with their RFCs cited. `is_example_or_reserved_ip` is removed and its callers use `is_example_ip`.

Every class reads the address a target names, `network_target_address`: without the punctuation prose leaves after it (`CONST_PROSE_TRAILING_PUNCTUATION`), the host of a URL or `host:port` without its trailing dot, and the legacy numeric spellings `inet_aton` reads, through `core.validation.parse_numeric_ip`, with no lookup. `classify_network_target` puts a target in one `NetworkTargetClass`: a public, documentation, unspecified or local address, a fictional phone number, or an example, local or other domain. `is_example_or_invalid_network_target` is its example classes, `is_public_ip`, `is_example_ip` and `is_private_or_local_ip` are its address classes, and Shodan InternetDB, Cloudflare Radar and `check_threat_intel` all dispatch on it. Shodan is asked only about a public address, in its canonical spelling. Radar answers every class but a public address and any other domain from a static record whose summary names what the target is, so no documentation, unspecified or local address reaches its domain lookup in any spelling, and its batch path does the same. `check_threat_intel` names everything `is_example_or_invalid_network_target` excludes, the unspecified addresses (RFC 1122, RFC 4291) and fictional phone numbers included, answers a local address itself with a reply that says no service was asked, and sends a public address to Shodan as the address it names.

In the sandbox local whitelist, `host.docker.internal` is refused at `SandboxNetworkConfig` validation with a `SandboxValidationError`, ahead of the private-host check, with a message asking for the IP address or CIDR the cluster reaches the host on. On the workstation the name is the container runtime's gateway (169.254.1.2 under rootless Podman), which a cluster pod cannot reach; it used to become a `127.0.0.1/32` ipBlock. A loopback entry (`localhost`, a loopback address or a loopback network such as `127.0.0.0/8`) resolves to no address, and `_build_whitelist_egress` adds no rule for an entry that resolves to none, so no generated rule has an empty `to`, which would allow every destination on its port. No DNS lookup was added to the policy builder. #887 landed first and its private-host check admits `host.docker.internal`, since `internal` is not on the Public Suffix List, so the refusal sits ahead of that check.

## Acceptance Criteria
- [x] `security/reference_extractor.py` holds no RFC tables; `CONST_DOCUMENTATION_IP_NETWORKS` and `CONST_NON_GLOBAL_NETWORKS_STDLIB_READS_GLOBAL` are the only address constants the classification reads (`test_every_specified_address_is_in_exactly_one_class`).
- [x] `is_public_ip` is `is_global and not is_reserved and not is_multicast`, outside 192.88.99.0/24, fec0::/10 and the documentation constant; `test_the_stdlib_still_reads_each_non_global_network_as_global` reports when CPython follows IANA and a network of the second constant can go. `::ffff:192.88.99.2` is local and `::ffff:192.0.2.1` a documented example (`test_every_specified_address_is_in_exactly_one_class`).
- [x] Multicast, 100.64.0.0/10, 192.88.99.0/24 and fec0::/10 are local and reach neither Shodan nor Cloudflare Radar, and Radar answers `0.0.0.0`, `::` and `http://0.0.0.0:8000` without a request (`test_check_threat_intel_asks_no_service_about_a_local_address`, `test_shodan_answers_a_documentation_or_local_address_without_a_request`, `test_cloudflare_radar_answers_a_documentation_or_local_address_without_a_request`).
- [x] `3fff::1` is reported as "Documented Example" (`test_a_report_tags_documentation_space_as_an_example_and_reserved_space_as_local`), and `is_example_or_reserved_ip` no longer exists in `src` or `tests`.
- [x] `check_threat_intel`'s reply names RFC 2606, 6761, 5737, 3849, 9637, 2544, 5180, 1122 and 4291 and fictional phone numbers, and not RFC 6890, for `3fff::1`, `555-0100`, `0.0.0.0`, `::`, `http://0.0.0.0:8000` and `3221225985` (192.0.2.1) alike (`test_check_threat_intel_names_the_rfcs_of_every_target_it_excludes`).
- [x] An address is classed without trailing prose punctuation, and a URL, `host:port` or `inet_aton` spelling names the address a resolver dials, with no lookup (`test_an_address_is_classed_without_the_punctuation_prose_leaves_after_it`, `test_a_network_target_names_the_address_a_resolver_would_dial`).
- [x] `100.64.0.1.`, `224.0.0.1,`, `10.0.0.1.`, `2130706433` and `http://100.64.0.1./v1` reach neither Shodan nor Radar, by `check_threat_intel`, `CloudflareRadarClient.check_domain` or its batch path; `check_threat_intel` replies that the target is a local address and no service was asked, and a public address with a trailing mark goes to Shodan as the bare address (`test_check_threat_intel_asks_no_service_about_a_local_address`, `test_check_threat_intel_asks_shodan_about_the_address_the_target_names`, `test_cloudflare_radar_answers_a_documentation_or_local_address_without_a_request`, `test_cloudflare_radar_batch_sends_no_local_address`).

- [x] `host.docker.internal`, in any case and with or without a trailing dot, is refused at validation with a `SandboxValidationError` and no `getaddrinfo` call, even when the private-host check would admit it (`test_the_host_gateway_name_is_refused_in_the_local_whitelist_without_a_lookup`).
- [x] Loopback entries produce no egress rule, no rule has an empty or missing `to`, and neither name maps to `127.0.0.1/32` (`test_a_loopback_entry_opens_no_egress_rule`, `test_a_loopback_host_or_network_resolves_to_no_address`, `test_an_entry_that_resolves_to_no_address_adds_no_rule`, `test_every_whitelist_rule_names_a_destination`).
