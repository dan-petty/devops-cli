## 1. Description & Objectives

No provider reads a finish reason, and the span hardcodes `gen_ai.response.finish_reasons` to `["stop"]` (`ai/client/unified.py:91`). A persona-review reply cut at its cap (`ai/review/runner.py:713`) is silently repaired, keeps its partial last finding, passes the validator and is cached (`unified.py:579`); failed validation resends the identical prompt (`unified.py:605-609`). Streaming: every provider reads `iter_lines()` (`ai/client/streaming.py:330`), the Ollama extractor never reports done (`:306-308`) and the Claude extractor handles only `content_block_delta` (`:269`). An early EOF or error frame is stored by `devops ai chat` (`commands/ai.py:954`) and billed as complete (`unified.py:816`). Repair enters through three functions (`ai/response_repair.py:51`, `ai/client/structured.py:57`, `core/serialization.py:23`); only `chat_structured`, which nothing calls, counts repairs (`structured.py:197,255`). vibes observation 15 shows retrying into the same token ceiling fails; vibes' RESP decoder returns `(None, 0)` until a whole frame arrives, tested over a frame-splitting socket.
