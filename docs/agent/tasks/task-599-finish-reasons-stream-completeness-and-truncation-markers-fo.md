# Task: Finish Reasons and Stream Completeness for Model Replies (#599)

**Issue**: [#599](https://github.com/dan-petty/devops-cli/issues/599)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/ai

## Description
No provider client read why a model stopped. The non-streamed parsers ignored `finish_reason`, `stop_reason` and `done_reason`, `LLMResponse` had no field for the reason, and the dispatch span hard-coded `gen_ai.response.finish_reasons` to `["stop"]`. A persona reply cut at its 8,192-token cap was repaired by json-repair, passed the validator and was cached for 7 days, and neither the spend ledger nor `profile.json` could say how often that happened. Every stream read `response.iter_lines()`, whose decoder splits on U+2028, so a delta holding a raw U+2028 was cut in two and dropped. The Ollama extractor never reported done, and the Claude extractor stopped on `[DONE]`, which Anthropic never sends. An OpenAI stream with no end marker, an Ollama stream cut mid-line, an Ollama error line and an Anthropic `event: error` each returned their partial text as a whole reply, and `chat_messages_stream` billed them as complete.

Every reply now carries the reason it ended, and a stream ends only on its provider's final frame.

- **Finish reason** (`ai/client/models.py`, `config/constants.py`): `LLMResponse.finish_reason` is pydantic-ai 2.35.0's `FinishReason`. `CONST_OPENAI_FINISH_REASONS`, `CONST_ANTHROPIC_STOP_REASONS` and `CONST_OLLAMA_DONE_REASONS` copy pydantic-ai's private OpenAI and Anthropic maps, including `pause_turn` to `None` and `compaction` to `stop`; Ollama's `stop` and `length` map directly and `load` and `unload` to `None`. `provider_finish_reason(table, value)` returns `None` for an absent, unmapped or non-string value. `_parse_compat_response`, `_claude_messages` and `_ollama_request` fill the field, `to_model_response` passes it to `ModelResponse.finish_reason`, and `from_model_response` reads it back.
- **Spans** (`ai/client/unified.py`): `_set_finish_reason_attribute` sets `gen_ai.response.finish_reasons` to `[reason]`, or nothing when the reason is unknown, on `ai.llm.dispatch` (from `_set_response_span_attributes`) and on `ai.llm.stream` (from `chat_messages_stream`). `ai.llm.chat` never carries it. The `["stop"]` literal is gone, and the event payload moved to `_response_event_payload`, so `_set_response_span_attributes` is no longer over the complexity cap.
- **Ledger** (`ai/spend/ledger.py`, `ai/spend/models.py`): the table gains `finish_reason TEXT`. Older ledgers gain it in place through `_ADDED_COLUMNS`, which now drives `served_by`, `stage` and `finish_reason` through one `_add_column`. `record_request`, `SpendRecord` and `track_request_spend` take `finish_reason`, and the call dict observers receive carries it. `_record_response_telemetry_and_spend` passes `res.finish_reason`, `_record_stream_spend` the stream's reason, and both pydantic-ai direct calls `resp.finish_reason`.
- **Profile** (`ai/review/profile.py`, `ai/review/runner.py`): `StageProfile.finish_reasons` counts a stage's replies by reason, `unknown` for `None`, and `StageProfile.truncated` counts `length` replies by `served_by`, keyed like `backends`. Cached calls stay counted apart and are in neither. `ReviewProfile.truncated_replies` sums the stages' `length` replies, and `_write_review_profile` adds `, N hit the reply cap` to its summary line when N is not zero.
- **Cache**: `_handle_successful_chat_dispatch` stores no reply whose reason is in `CONST_UNCACHED_FINISH_REASONS` (`length`, `content_filter`, `error`) and still returns it. Validation and retries are unchanged.
- **Stream framing** (`ai/client/streaming.py`): `_read_event_stream` reads OpenAI-compatible and Anthropic streams with `httpx2.EventSource(response, max_event_size=...)`, and `_read_ndjson_stream` reads Ollama's `iter_bytes()`, splits on `\n` only and decodes each whole line as UTF-8, refusing an unterminated line past its limit. Both limits default to `DEFAULT_AI_STREAM_MAX_EVENT_BYTES` (1 MiB, httpx2's `DEFAULT_MAX_EVENT_SIZE_BYTES`). Both feed `_read_frames`, which counts each frame towards `MAX_STREAM_BYTES` before parsing it and yields each chunk as it arrives. One `StreamFrame` parser per provider (`_openai_stream_frame`, `_claude_stream_frame`, `_ollama_stream_frame`) says what a frame carries: text, whether the stream is complete, whether reading stops, the reason, or the provider's error.
- **Completeness**: OpenAI-compatible streams are complete on a chunk with a non-null `finish_reason` or on `[DONE]`; reading goes on after the reason to `[DONE]` or EOF, so a usage chunk after it is read (#591). Anthropic streams are complete on `message_stop`, with the reason from `message_delta`; `[DONE]` is not an end. Ollama streams are complete on `done: true`, with the reason from `done_reason`. An Ollama `{"error": ...}` line, an Anthropic `error` event and an OpenAI-compatible `data:` object with an `error` raise `AIClientError` with the provider's message, masked with `mask_secrets` and then cut to 256 characters. A stream that ends before its final frame raises `AIClientError`, and so does an event stream whose content type is not `text/event-stream`, naming the type. `_read_failures` raises httpx2's `SSEError` and every other `RequestError` as `AIClientError`: a `TransportError` or a `DecodingError` escaping mid-output would be replayed on the next host by the Ollama loop, which catches both.
- **Stream reason and spend**: `_read_frames` sets `network.stream_finish_reason` once the stream is complete, and `chat_messages_stream` resets it beside `stream_served_by` as each stream starts. A stream that fails after yielding a chunk records its spend with reason `error` and re-raises. One that fails before its first chunk (connection error, HTTP status error, rejected credentials or an error frame first) records nothing.
- **Removed**: `_consume_streaming_lines`, `_read_response_lines`, `_extract_claude_stream_chunk`, `_extract_openai_stream_chunk`, `_extract_ollama_stream_chunk`, `_extract_ollama_stream_tuple` and the unused `_extract_stream_chunk`, with their re-exports from `devops_cli.ai.client`. No alias is left.
- **Tests**: every whole-line `iter_lines` stub in `tests/test_ai_streaming.py`, `tests/test_ai_client_providers_and_embeddings.py` and `tests/test_ai_spend_dispatch.py` is replaced by an httpx2 `MockTransport`, through `tests/llm_stream_fakes.py` (canned SSE and NDJSON frames, a body that records how far it was read, and `route_client`, which sends an `LLMClient`'s requests to a handler), as `tests/web_fakes.py` does for web pages. The tests that called the extractors with whole `data:` lines, there and in `tests/test_thinking_providers.py`, call the frame parsers with `httpx2.ServerSentEvent`s or NDJSON lines. `tests/test_ai_served_by.py`'s streamed gateway reply gains `content-type: text/event-stream`.
- **Docs**: `DocGenerator._llm_span_attribute_lines` says both inference spans carry the finish reason, and `docs/TELEMETRY.md` is regenerated. `docs/SELF_IMPROVEMENT.md` describes the profile's new counts. The changelog entry is `changelog.d/599.md`.
- Out of scope, as the issue decided: acting on cut persona replies (#876), one JSON repair seam (#875), streamed `devops ai chat` turns that send the user's message (#874), Ollama streams that send the configured options (the issue's fourth split-off), a finish-reason label on `devops_cli_ai_requests_total`, and purging cut replies already cached, which expire within 7 days or go with `devops ai cache clear`.

## Notes
- In `devops ai chat` with streaming and no tools, a cut stream now raises instead of storing its partial text. The chat loop's handler (`commands/ai.py:1106-1110`) then pops the last memory entry, which is the previous reply, because the streamed turn never adds the user's message. #874 fixes that turn.
- Anthropic's `message_delta` usage and the OpenAI-compatible usage chunk are read and ignored; #591 reads provider-reported usage from the same final frames.
- An event stream's size counts each event's data. Comment lines carry none, and the per-event limit still bounds one left unterminated. An NDJSON stream's size counts each line.
- An error frame is the server's answer, so it does not fail over to the next Ollama host; only connection failures before any output do, as before. The Ollama stream's errors now name `Ollama` instead of `LLM`.
