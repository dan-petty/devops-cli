## 1. Description & Objectives

#430 added AIMD recovery to the embedding batch size, marked delivered in the "Capability-Gated Model Failover & AIMD Batch Recovery" item, but three one-way transitions remain. First, `_embed_ollama` fixes `chunk_batch_size` once per call (`src/devops_cli/ai/rag/embeddings.py:697`), and every slow batch in that call halves again (`:640`, `:653`) although none was sent at the reduced size. The increase fires on any batch at or under 2.0 s, with none of the cooldown or 0.5x margin vibes proposes (`embeddings.py:331-336`). Second, one Valkey error nulls the L2 client for the rest of the run (`embeddings.py:359,374`; `security/vulnerability_lookup.py:451,467`), pinned by `tests/test_security_threat_intel.py:228`, while `cache/tiered.py:202-222` retries and reconnects on every call during an outage (`valkey/pool.py:118-144`). Third, `trigger_failover` persists a `failover:*` route (`ai/gateway.py:487-526`) with no failback, and a healthy probe clears the breaker flag but keeps the route (`gateway.py:418`). #430 also left a backwards-compatible `_halve_batch_size` alias (`embeddings.py:327`).

- Deliverable*: Three small PRs. PR1 (before the v0.2.23 tag): pass the sent size into `_record_batch_latency` and the timeout path, skip a decrease when the sent size exceeds the current one, add a cooldown and a margin below the threshold before any increase, delete the alias, and migrate `tests/test_rag_embeddings.py:399-407`. Test it through `_embed_ollama` with a stubbed endpoint and two workers. PR2: adopt pybreaker behind one seam at the Valkey L2 boundary, route the engine, the threat-intel client and `TieredCache` through it, delete every `self._valkey = None`, and rewrite the pinning test to cover open, cooldown, half-open and closed. The v0.3.4 "Proportional API Rate Budgeting & GraphQL Circuit Breaker Guard" should reuse it. PR3: the route file feeds only `devops ai gateway status`/`routes`, while live fallback belongs to LiteLLM's `fallbacks` (`k8s/llm/gateway/configmap.yaml:118-137`). Make `status` report failover while any route is `failover:*`, and add `failover --reset` to restore default routes. List each knob, its trip, reset and test in the task file.
- Constraint*: A naive recovery is worse than the ratchet. Increasing on every healthy batch without a margin can climb straight back to the size that breached, and uncoalesced decreases then undo it in one call. Retrying Valkey on every call makes each call pay a connection attempt during an outage, which the disable avoids, so the breaker needs a real open state. Failback stays explicit: flipping routes on one healthy probe would call the local routes healthy regardless of LiteLLM, which owns traffic. A deliberate trip is recorded as one, not forced to recover.
- Measured*: `PYTHONPATH=src uv run --no-sync python probe/round_probe.py`: one `_embed_ollama` call with default parallelism and every batch slow drives the size from 32 to 1. `PYTHONPATH=src uv run --no-sync python probe/recovery_probe.py`: 32 healthy batches climb from 1 back to 32. `PYTHONPATH=src uv run --no-sync python probe/l2_probe.py`: after one transient Valkey read error, 0 of the next 100 reads reach L2.
