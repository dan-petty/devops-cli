## 1. Description & Objectives

#430 added parameter-count floors (reasoning >=30B, coding >=7B) in `src/devops_cli/ai/capability.py`. They are inferred from the model name, and a name it cannot parse passes (`capability.py:105`). The gate runs in `GatewayRouter.trigger_failover` (`src/devops_cli/ai/gateway.py:509`) and in `ConstellationManager.failover`. `trigger_failover` is a manual CLI path that no live request uses. Live failover is LiteLLM's static `fallbacks` (`k8s/llm/gateway/configmap.yaml:136-138`). There, `devops-reasoning` (32B AWQ) falls to `devops-coder` (14B AWQ), the edge the 30B floor forbids. `devops-coder` falls to the 32B model, then to `devops-chat` (7B). Only the `chat` task uses these fallbacks. Reviews use `devops-review`, which has no fallback but shuffles across three models. `probe_backend` (`gateway.py:624`) checks health only. `gateway tune` measures capacity and cost only. vibes' 0%-vs-85%+ figures describe a 70B tier that is not deployed here, and they have not been measured.
