# Task: devops-cli Dashboards Chart the Metrics the CLI Sends and the Grafana Sidecar Provisions Them (#692)

**Priority**: priority/p2-medium
**Scope**: scope/cli

## Description
devops-cli sends eight delta counters and histograms (`INSTRUMENTS`, `src/devops_cli/telemetry/instruments.py`), and the collector adds each series' deltas up before Prometheus stores them. Its two dashboards charted little of that: command latency, the `status` label on `devops_cli_command_total`, the `severity` label on `devops_cli_findings_total` and review volume by `target_type` were sent and never charted, review and RAG time showed only means, and seven "lifetime" panels summed a raw counter, which shows the count since the collector last reset an idle series. Only the four Kubernetes views were packaged for the Grafana sidecar, in hand-copied ConfigMaps that nothing applied, so `devops-cli.json` and `ai-spend.json` reached Grafana only through `devops grafana dashboards sync`. `sync` exited 0 when every file failed, and `lint` neither caught a uid two files share nor failed with `--json`.

The requested four new dashboards (`ai-constellation`, `ai-review`, `github-agentic`, `loki-incident-triage`) are not built: nothing sends most of their data as a counter or histogram a dashboard may query (slot leases, TTFT, vector-cache hits, GitHub quota and logs). The parts that have data became panels in the two existing dashboards.
