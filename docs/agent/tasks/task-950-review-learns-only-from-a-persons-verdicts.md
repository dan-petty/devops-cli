# Task: The Review Learns Only From a Person's Verdicts, and Every Reader of the Feedback Dataset Is Honest (#950)

**Issue**: [#950](https://github.com/dan-petty/devops-cli/issues/950)
**Status**: Done
**Milestone**: v0.2.25
**Priority**: priority/p1-high
**Scope**: scope/review

## Description
`docs/SELF_IMPROVEMENT.md` described a review that learns from its verdicts, but nothing a verdict produced changed a later review, and the datasets built from verdicts were read by broken or circular tools. All 35 entries of this repository's learned catalog were `general` entries the deterministic checks had taught, with signatures pairing common words (`exception`+`handling`), inert only because `_verify_general_ground_truth` dispatched on id substrings; the ledger's read-modify-write ran unlocked from verification threads. The persona exemplars were the shipped entries ranked by a count that never changed. The benchmark suite sent empty prompts, prompt-eval scored the deterministic layer against labels it wrote, and the exporter overwrote its output from findings.json alone. Review session `20261002-214641` added the scope line: 21 of its 24 reported entries repeated `20261002-205520`'s wording, and the `exec` finding at a test's line 439 changed from Semgrep's title to Bandit's B102.

- **Judged claims** (`ai/review/judged_claims.py`, new). `JudgedClaim(project, file, line, code_sha256, claim)` is one claim, and two findings make the same claim when every field agrees: the project (`main_worktree_root(...).name`), the file relative to its checkout, the first line the location cites, the SHA-256 of the cited lines each stripped of surrounding whitespace, and the code names of those lines (`[^\W\d]\w*`, matched ignoring case) that the title names, or the description when the title names none. Python's `keyword.kwlist` and `softkwlist` and `CONST_JUDGED_CLAIM_STOP_WORDS` (common English words, and keywords of other languages that are words) are no code names, and in a file whose suffix is in `CONST_DOC_EXTENSIONS` or `CONST_CONFIG_EXTENSIONS` (Markdown, YAML, JSON, ...) only a name with an underscore or a camelCase hump is. `cited_code(location, file_path, checkout)` reads at most `DEFAULT_CITED_EXCERPT_MAX_LINES` (40) lines of a file inside the checkout, with `mask_secrets` applied and the 50 MB file cap, into `CitedCode(project, file, line, excerpt)` (`ai/review_schema.py`); `judged_claim(finding, cited)` returns None when the finding names no code name of it.
- **The learned catalog** (`ai/review/common_hallucinations.py`). A learned entry is a `CommonHallucinationEntry` with `source="person"` and a `judged` claim; `record_judged_claim` builds one with a deterministic `JUDGED-<digest>` id, so another verdict on the same claim counts once more. `register_common_hallucination` refuses any other entry. `update_learned` does every read-modify-write under an `fcntl` lock on `common_hallucinations.json.lock`, and `save_common_hallucinations`, `remove_learned_hallucinations` and #949's withdraw and restore go through it. Loading purges every entry that is not a judged claim, under the lock, with one warning; a ledger that cannot be read or a record that does not validate warns. `find_similar_hallucinations` matches the builtin catalog only, and `find_judged_entry` matches a finding's claim exactly, field for field. `auto_record_invalidated_finding`, `catalog_learning_disabled` and the signature synthesis are deleted.
- **Verification** (`ai/review/verification.py`). The deterministic checks no longer call the catalog. `_check_judged_claim` runs first in `_run_file_level_deterministic_checks` and again after the construct check moves a finding, invalidating with `deterministic:person_verdict`; `consult_judged=False` leaves it out for prompt-eval's replay. `record_cited_code` stamps `SavedFinding.cited_code` from a non-secret file inside the reviewed checkout when the pipeline and the runner save a session, and `_check_judged_claim` builds a finding's claim in the checkout of the directory under review.
- **Verdicts** (`ai/review/adjudication.py`). A person's INVALIDATED verdict records the claim keyed on the session's `cited_code` only; with none, or no code name, it records nothing and warns (`MESSAGES.review.verdict_teaches_nothing`). `EntryIds.take(finding, status)` releases the learned-catalog ids of every verdict but INVALIDATED and the ledger ids of every verdict but MITIGATED, on the finding and on its mirror in the other session file, for `settle` to withdraw once the files are written; #949 released them only on a reset to UNVERIFIED.
- **Pull request reviews** (`commands/review.py`). The PR head is written to `<tempdir>/<project_of(cwd)>`, so `project_of` and `find_worktree_root` resolve the head to the checkout the review runs in, for the exemplars and for suppression.
- **Exemplars** (`render_negative_exemplars(target)`, `_persona_system_prompt(..., target)`). The judged claims of the target's project (`main_worktree_root(...).name`), ranked by `occurrence_count` then `last_seen`, under `negative_exemplars_judged.md`, which says "reported against this codebase"; with none, the builtin entries under `negative_exemplars_shipped.md`. Lines are masked and their boundary tags escaped. The pipeline passes its `target_dir`.
- **Exporter** (`ai/review/exporter.py`). `export_invalidated_feedback` reads findings.json then candidates.json, appends only records whose `feedback_fingerprint` (session, first persona, location, title, status, adjudicator) the file does not hold, writes nothing when there is nothing new, and records `subject`, `category`, `references` and `cited_excerpt` (the excerpt of `cited_code`).
- **prompt-eval** (`ai/prompt_eval.py`, `devops ai prompt-eval`). `by_labeller` and `excluded_labels`; `deterministic:*` labels are excluded unless `--include-deterministic`.
- **Suite removal**. `ai/benchmark/suite.py`, `--suite`, `--dataset`, `--type suite`, the MCP `benchmark_suite` tool, the suite models, `format_benchmark_suite_table` and their messages are deleted, and `--type` refuses any value but `CONST_BENCHMARK_TYPES` (`auto`, `chat`, `embedding`) with a `ValidationError`. The literal-prompt test also found `planning_guidance.md` and `playwright_guidance.md` missing; both are now prompt files that `ai/harness/constants.py`, `planning.py` and `agents.py` all read.
- **Docs**. `docs/SELF_IMPROVEMENT.md` (new section 5.7, sections 1, 3, 4 and 5.3), `docs/SDLC.md`, `docs/ROUTINE_TASKS.md`, `docs/cheatsheets/ai_and_rag.md`, `AGENTS.md` and the knowledge base name the one dataset path and the judged-claim model; the CLI and MCP references are regenerated.
