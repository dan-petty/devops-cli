## 1. Description & Objectives

`k8s/llm/lightllm/deployment.yaml:27` and `k8s/llm/portkey/deployment.yaml:32` run `:latest` with `imagePullPolicy: IfNotPresent`, so each node keeps whichever build it pulled first. `k8s/llm/valkey.yaml:40-47` starts the shared Valkey with no `--maxmemory` and no eviction policy under a 2048Mi limit. LiteLLM (`gateway/deployment.yaml:60`), Portkey (`portkey/deployment.yaml:46`) and Open WebUI websockets (`values-open-webui.yaml:47`) all write to it. The bundled knowledge base says to always set both (`valkey.md:132`), and `k8s/llm/valkey-runs.yaml:80-81` already does (`512mb`, `noeviction`). No test asserts either manifest. No CI step runs Checkov or kube-linter. The native fallback checks only Dockerfile `FROM` tags (`security/checkov.py:53`), and `devops k8s lint` prints "passed" when kube-linter is absent (`commands/k8s/security_audit.py:92`).

- Deliverable*: One PR. Pin both images to explicit version tags. In `k8s/llm/valkey.yaml`, add `--maxmemory` below the 2048Mi limit and `--maxmemory-policy volatile-lru`, mirroring `valkey-runs.yaml`. Assert the flag pair for both manifests in `tests/test_k8s_valkey_stack.py`. Commit `k8s/.checkov.yaml` (`framework: kubernetes`, `check: CKV_K8S_14`, `skip-path: coredns/deployment-patch.yaml`) and add one CI step that runs a pinned Checkov over `k8s/`. Checkov finds the file itself and exits non-zero on failure. No wrapper change is needed. `devops scan report --scanner checkov --fail-on` already exits 1 for local use (`commands/scan.py:851-852`), and `devops valkey info --section memory` already prints the memory fields.
- Constraint*: Routing CI through the devops wrapper would fail open. When the binary is missing, the wrapper silently runs the native fallback (`security/base.py:93-97`), which has no k8s tag check. That fix belongs with the delivered #516 analyzer states (`ai/review/pipeline.py:845`) and the *Gate Integrity* draft, not here. The coredns patch has no image and no kustomization renders it, so it is skipped by path. `allkeys-lru` could evict Open WebUI's websocket state. `volatile-lru` evicts only keys with a TTL and refuses writes when none remain, which is better than an OOM kill. Digest pinning (`CKV_K8S_43`) fails on every workload, and Dependabot covers only `github-actions` and `pip`. Digests therefore wait for *Finding Baseline for Incremental Scan Gate Adoption* and a Kubernetes-aware updater such as Renovate. A 0.0.0.0 rule is wrong here, because in-pod servers must listen on all interfaces. Host exposure comes from one `hostPort` (`k8s/llm/ollama.yaml:95`) plus `NodePort` services, most documented as local-minikube choices. Compose `${VAR:?}` and loopback checks have no target in devops-cli.
- Measured*: `uvx --from checkov==3.3.19 checkov -d k8s --framework kubernetes --check CKV_K8S_14,CKV_K8S_43 -o json`: `CKV_K8S_14` fails in 3 files (lightllm, portkey, coredns patch). `CKV_K8S_43` fails in 13, with none passing.
