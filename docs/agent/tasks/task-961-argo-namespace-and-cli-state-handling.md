## Description
The path review of the whole repository in session `20261001-224227` raised 563 findings. Triage against `release/v0.2.25` (c279c18) upheld seven defects, each with a fix and a regression test. This delivers all seven in one PR, the argo namespace fix (MEDIUM) first. Every regression test was run against a scratch copy whose `src/` was put back to `HEAD` with `git show HEAD:<path>`, where it failed, and against this tree, where it passes. The tests stub kubectl through the runtime's `_run_cmd` or `run_subprocess`, `gh` through `run_gh`, the Kubernetes API, sockets and `subprocess.Popen`, and keep every file under `tmp_path`.

- **Argo** (`commands/argo.py`): `_crd(namespace)` built the custom resource service with the namespace as its kubeconfig context, so outside a pod `-n argo` looked up a context named `argo`. `_crd` is deleted. `workflows list`, `submit`, `logs`, `rollouts list` and `rollouts status` call `get_argo_crd_service()` with no context, and `submit` builds the service once and hands the same one to `_await_workflow`. No `--context` option was added, so the CLI reference is unchanged.
- **Workspace** (`commands/workspace.py`): `_load` returns empty defaults only when the file does not exist. A file over the size limit, not UTF-8, not plain JSON, or without a `folders` list stops `add` and `remove` with exit 1 before `_save` can run. `ERRORS.workspace.{file_too_large,malformed,corrupted}` no longer say "Using defaults"; they say the file was left unchanged and point at `devops workspace generate`. JSONC was not accepted: a rewrite would still drop the comments, and `json-repair` guesses at broken input rather than parsing a grammar.
- **Git daemon** (`commands/devcontainer.py`): `_is_git_daemon_running` is the 127.0.0.1:9418 connect probe alone. `git daemon` still writes its pid file, where a person can find the pid, but nothing reads it.
- **Port-forward state** (`k8s/port_forward_daemon.py`, `commands/k8s/networking.py`): `PortForwardDaemonManager.locked()` holds `fcntl.flock(LOCK_EX)` on `port_forwards.lock` beside the state file, opened with `O_NOFOLLOW`. `list_forwards` (read and prune), `stop_forwards`, and all of `_launch_port_forwards` from its read through every `Popen` to its save run under it. `load_forwards` and `save_forwards` are the unlocked steps a caller runs under `locked()`. `save_forwards` writes through `write_json_file(..., atomic=True)`, a temporary file moved into place with `os.replace`, behind the existing symlink guard. `PortForwardInfo.start_ticks` holds field 22 of `/proc/<pid>/stat`, read by `process_start_ticks` at launch. Where `/proc` can be read, `is_alive` holds only while the pid still has that start time, so a reused pid is neither listed nor signalled. Without `/proc` it falls back to `os.kill(pid, 0)`. The field is required, so a state file written before this change no longer parses: it reads as no forwards, with a debug log, and the next start saves over it.
- **TLS secrets** (`commands/k8s/tls_management.py`): `_apply_tls_secret` renders the secret with `kubectl create secret tls ... --dry-run=client -o yaml` and, only once that succeeds, pipes it to `kubectl apply -f - -n <ns>` through `runtime._run_cmd(..., input=...)`. `create-tls-secret` and `enable-tls --overwrite` use it, and neither runs `kubectl delete secret` any more. A failure reports kubectl's stderr, bounded to `CONST_MAX_ERROR_DETAIL_LENGTH`. `enable-tls` without `--overwrite` still runs a plain create. `_deploy_tls_secret` holds that choice, keeping `enable_tls_stack` below the complexity cap. `create-tls-secret` now says `Applied TLS secret`.
- **Drift report** (`ai/library/drift_auditor.py`, `commands/ai.py`): a failed save logs `Could not write drift report to <path>: <error>` at WARNING and sets `DriftReport.save_error`; it does not raise, since the printed or JSON result is still valid. `DriftReport.save` removes the previous report before writing, so a failed write cannot leave the old one to pass as current. `audit-library-usage` prints the failure as a warning, on stderr with `--json`, and otherwise prints where it saved the report.
- **Labels** (`github/labels.py`, `github/client.py`, `commands/gh.py`): `LabelClient` is a Protocol with `get_labels`, `create_label` and `edit_label`, all taking the repository first, and `sync_repository_labels` calls them directly. `_apply_label_mutation`, its `getattr`/`callable` check and both `except TypeError` fallbacks are deleted, and so is `_extract_labels_from_raw`, because both clients return dicts and `diff_labels` already skips anything else. `GhCliClient` raises `GitHubOperationError` when a `gh label list`, `create` or `edit` exits non-zero or the list is not JSON. `gh label list` gets `--limit DEFAULT_GH_LABEL_LIST_LIMIT` (1000) in `GhCliClient.get_labels` and in `_get_repo_labels`. `labels sync` prints the error and exits 1, and prints `Label sync complete` only after every call succeeded. The PyGithub client already raised on failure and is unchanged.
- Beyond what the issue asks:
  - `devops tls enable-k8s` (`commands/tls.py`) had the same delete-then-create for every namespace, unconditionally. It now renders and applies the same way.
  - `test_k8s_helpers_and_error_branches` (`tests/test_k8s.py`) ran `devops k8s port-forward` with `Popen` mocked and no manager patched. It wrote pid-1 records into `.data/k8s/port_forwards.json` under whichever directory the suite ran from, and would now leave the lock file there too. It now records under `tmp_path`.

- [x] 2.
