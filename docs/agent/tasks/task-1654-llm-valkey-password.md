# Task: The llm Valkey Cache Requires a Password and Admits Only Its Clients, Like valkey-runs (#1654)

**Issue**: [#1654](https://github.com/dan-petty/devops-cli/issues/1654)
**Scope**: scope/k8s
**Feasibility**: Read-only checks on 2026-10-23. The live `llm/valkey` ran `valkey-server` with no `requirepass`, and `valkey-cli CLIENT LIST` showed three Open WebUI connections and the local exporter only. Portkey 1.15.0 reads a cache only from `REDIS_CONNECTION_STRING` (source at tag `v1.15.0` and the running build), so `CACHE_STORE` and `REDIS_URL` had no effect, and its log shows no Redis backend. The LiteLLM v1.103.0 package in the running gateway reads no `LITELLM_REDIS_HOST` or `LITELLM_REDIS_PORT`, and the gateway config turns on no cache. The open-webui chart 16.6.0 renders `REDIS_URL` and `WEBSOCKET_REDIS_URL` before `extraEnvVars`, so a `$(VAR)` from `extraEnvVars` does not expand there. The kubelet adds `envFrom` variables before it expands `env` (`pkg/kubelet/kubelet_pods.go`), and the chart has `extraEnvFrom`. `helm template` of the chart with the new values gives both URLs with `$(VALKEY_PASSWORD)` and the `envFrom` entry. `devops k8s push-secrets --only llm/valkey-auth --plan` says `would generate`.

## Description

- [x] **Secret** (`src/devops_cli/k8s/cluster_secrets.py`): row `llm/valkey-auth`, key `VALKEY_PASSWORD`, from keyring `valkey_password`. That is the keyring entry of the workstation setting `valkey.password`, which a workstation sends through `devops k8s port-forward`. A missing value is adopted from the live Secret, else 64 hex characters are generated. A change restarts `deployment/valkey` and `statefulset/open-webui`. deploy-stack pushes the row before it applies the llm manifests.
- [x] **Valkey** (`k8s/llm/valkey.yaml`): the valkey container reads `VALKEY_PASSWORD` from the Secret and writes `requirepass` into `/run/valkey/auth.conf` on a memory emptyDir with umask 077, as `valkey-runs.yaml` does. The password is never on the command line. The `redis-exporter` sidecar sends it as `REDIS_PASSWORD`.
- [x] **Open WebUI** (`k8s/llm/values-open-webui.yaml`): `extraEnvFrom` loads the Secret, and `websocket.url` is `redis://:$(VALKEY_PASSWORD)@valkey.llm.svc.cluster.local:6379/0`. The Secret key is the variable name, because `envFrom` names each variable after its key.
- [x] **Network** (`k8s/llm/valkey.yaml`, `k8s/llm/networkpolicy.yaml`): `valkey-perimeter` admits pods `app.kubernetes.io/name: open-webui` on TCP 6379 and the `monitoring` namespace on the exporter port 9121, and allows no egress. `llm-default-perimeter` leaves `valkey` out, because policies add up.
- [x] **Unused cache settings removed**: `LITELLM_REDIS_HOST` and `LITELLM_REDIS_PORT` (`k8s/llm/gateway/deployment.yaml`), `CACHE_STORE` and `REDIS_URL` (`k8s/llm/portkey/deployment.yaml`), and the Valkey egress rules of `llm-gateway-perimeter` and `portkey-perimeter`. Neither workload connected to Valkey. Portkey was not moved to `REDIS_CONNECTION_STRING`: Portkey 1.15.0 logs that URL at info level, and the password would then go to Loki.
- [x] **Argo CD** (`k8s/argocd/apps/projects.yaml`): `valkey-auth` is in the `orphanedResources` ignore list with the other pushed Secrets.
- [x] **Docs**: `k8s/README.md` has the Cluster Secrets row, a `valkey-cli ping` that authenticates, the `valkey-perimeter` paragraph and the gateway egress without Valkey. A typed password must use only letters, digits, `-`, `.`, `_` and `~`, because Open WebUI sends it in a URL and Valkey reads it from a quoted config line. The knowledge base article `it_domains/tools/valkey.md` authenticates its `valkey-cli` commands and selects the pod by `app.kubernetes.io/name`.
- [x] **Tests** (`tests/test_k8s_valkey_stack.py`): `test_the_cache_valkey_takes_its_password_from_its_secret_as_the_run_index_does`, `test_the_cache_valkey_exporter_scrapes_with_the_password`, `test_open_webui_sends_the_password_from_the_secret_in_both_redis_urls`, `test_only_open_webui_and_the_metrics_scrapers_reach_the_cache_valkey` and `test_open_webui_is_the_only_workload_that_names_the_cache_valkey`. The table, push, deploy-order, gateway, Portkey and default-perimeter tests in `tests/test_k8s_push_secrets.py`, `tests/test_k8s_qdrant_security.py`, `tests/test_k8s_llm_gateway.py` and `tests/test_ai_gateway_portkey.py` hold the new row and policies.
