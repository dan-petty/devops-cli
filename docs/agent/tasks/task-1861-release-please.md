# Task: release-please Makes Every Release From `main` (#1861)

**Issue**: [#1861](https://github.com/dan-petty/devops-cli/issues/1861)
**Scope**: scope/release, scope/ci, scope/github, scope/roadmap
**Feasibility**: On 2026-10-23 the inputs and outputs of each pinned action were read from its `action.yml` at the pinned commit. `googleapis/release-please-action` v5.0.0 (`45996ed1`, release-please 17.6.0) takes `token`, `config-file` and `manifest-file`, and writes `release_created` and `tag_name` for the path `.`. `actions/create-github-app-token` v3.3.0 (`64ab729a`) takes `client-id` and the `permission-*` inputs. `amannn/action-semantic-pull-request` v6.1.1 (`48f25628`) checks the title of a pull request. release-please 17.6.0 accepts every key of `release-please-config.json`, and its TOML updater matches the `uv.lock` JSONPath. `actionlint` and `zizmor` report nothing on `release.yml` and `pr-title.yml`. The owner decided on 2026-10-23 that Argo CD keeps tracking `main`, that the roadmap planner is deleted, and that nothing predicts a version ([ADR 0013](../../adr/0013-releases-use-release-please-as-it-ships-and-agents-stay-out.md)).

## Description

- [x] **Release workflow** (`.github/workflows/release.yml`): on each push to `main`, a job mints the release App token and runs release-please, which opens or updates one release pull request. The token has contents, issues and pull requests write only. When release-please creates a release, later jobs upload the wheel, the sdist and `SHA256SUMS.txt`, and build, smoke-test, attest and tag the two images with the release tag and `latest`. Each of these jobs checks out the commit that the release tags, and a re-run of the upload replaces the assets that it uploaded before.
- [x] **Configuration**: `release-please-config.json` uses the `python` release type with `v<version>` tags and no component in the tag, `bump-minor-pre-major` and `always-update`. Its changelog sections show `feat`, `fix`, `perf`, `refactor` and `revert`. An extra file updates the version in `uv.lock`. `.release-please-manifest.json` holds the last release of the old pipeline.
- [x] **Pull request titles** (`.github/workflows/pr-title.yml`): the `Semantic PR title` check runs on each pull request into `main`.
- [x] **Triggers**: `ci.yml`, `codeql.yml` and `fail-to-pass.yml` run for pull requests into `main` only. The devcontainer and service image jobs of `ci.yml` run on pull requests and on a dispatch. `changed-tests` runs on every pull request. The `no-commit-to-branch` hook protects `main` only.
- [x] **DevContainer build time**: the devcontainer image builds for `linux/amd64` only, with no QEMU, as it did up to v0.2.34. Since #1570 it also built `linux/arm64` under emulation, and with the features that #1895 restored, every pull request check took about 25 minutes ([#1951](https://github.com/dan-petty/devops-cli/issues/1951)). The smoke test still starts the image as `vscode` and finds a command from each feature.
- [x] **Gate**: `devops ci build` runs `uv build` after the lock check, and the toolchain action runs `uv sync --locked`.
- [x] **Release code deleted**: `devops release` and all of its commands, the release package (cut, changelog fragments, notes compaction), the release notes sync, `devops docs compact`, the Argo CD diff at the cut, `devops devcontainer validate --oci-labels` and `--expected-source`, the MCP release resource and tool, and the release exceptions, models, constants and strings.
- [x] **Planner deleted**: `devops roadmap reprioritize`, `close`, `render` and `migrate`, the document writer and `docs/ROADMAP.md`. Intake puts each new item in the backlog and keeps a milestone that a person set. The agent quota counts over a rolling window of `quota_window_days` (default 7). Refine records `checked-at: sha=` with no branch, and it treats every open milestone the same. The service lane `release` is now `status` and runs the metrics only. A milestone is found by its exact title or by its number, and milestones are ordered by due date, then by number. No code reads a milestone title as a version.
- [x] **Pull request tooling**: `devops pr create` always opens a draft against the default branch, and `devops pr ready` is the only path to ready. `devops pr create` and `devops pr monitor` tell the author to run `devops pr ready` when the checks pass. `devops pr update --all` updates only the pull requests of the current account. Readiness requires the default branch as the base, exactly one closed issue from `closingIssuesReferences`, an open issue of the same repository on the roadmap board, and a change to its task file. `devops pr copilot-pass`, `devops gh pr copilot-pass` and `devops pr threads file-issues` are deleted.
- [x] **Renovate**: a base image update of the root `Dockerfile` is a `fix(deps):` pull request, and its body says that fail-to-pass does not apply.
- [x] **Labels, board and metrics**: the `release` label is replaced by `autorelease: pending` and `autorelease: tagged`. The board template and the label descriptions name no release parent or release milestone. The two release telemetry instruments and the "Release growth" dashboard row are deleted.
- [x] **Documents**: `AGENTS.md` section 3, `RELEASE_CYCLE.md`, `CONTRIBUTING.md`, `SECURITY.md`, `ARCHITECTURE.md`, `docs/SDLC.md`, `docs/ROUTINE_TASKS.md`, `CONTEXT.md`, `k8s/README.md`, the knowledge base, `openspec/config.yaml` and the instruction generator describe trunk releases by release-please. `changelog.d/`, `docs/RELEASE_NOTES.md` and two knowledge base articles are deleted. ADR 0013 supersedes ADR 0012.
- [x] **Tests**: `tests/test_workflow_contracts.py` holds the release workflow, its gates, the asset upload and the title check, and fails when a workflow targets a release branch or runs release tooling. A test holds the changelog table of `CONTRIBUTING.md` equal to `release-please-config.json`. Sample milestones and branches in the tests are planning buckets and topic branches. The `tests type: ignore` ceiling is 79, the count after the deleted tests.
- Pending a person: the release App, the `release` environment, the squash settings and the required checks of [#1864](https://github.com/dan-petty/devops-cli/issues/1864) are in place before this pull request merges. `devops gh api repos/dan-petty/devops-cli/environments/release` shows the environment.
- Pending a person: after the merge, the first `Release` run on `main` opens a release pull request from `release-please--branches--main` ([#1865](https://github.com/dan-petty/devops-cli/issues/1865)).
