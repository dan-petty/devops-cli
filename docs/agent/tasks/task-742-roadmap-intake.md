# Task: Single-Entry Item Intake with Duplicate Detection, Placement and the Agent Filing Quota (#742)

**Issue**: [#742](https://github.com/dan-petty/devops-cli/issues/742)
**Status**: Done

## Description
`devops roadmap intake` is the one way new work becomes an item. It takes every open issue not on the board, every board item intake left without a Priority, or one candidate that is not an issue yet (`--title` with `--body-file`, or the Python entry point `intake_candidate`). Each candidate is embedded with the comparison set (every board item and every issue closed as not planned) and judged by the model against its five nearest items; a duplicate is closed as a duplicate of the original, or, for a new candidate, not filed. The model's structured proposal (type, Priority P1-P3, Value, Effort, optional evidence, each with a reason) is checked by code. P0 needs evidence that appears in the text or was attached by the caller, that GitHub confirms, from a trusted source. A critical fix goes where #740's table admits it; everything else goes to the backlog. Writes come in a fixed order with Priority last, so a run that stops is finished by the next one. Intake also enforces the agent filing quota from #1153. It follows the dry-run rule (#412's amendment, 2026-10-04): `--dry-run` makes no request and prints the requests a run makes; `--plan`, which intake with no mode flag runs after a one-line note, reads GitHub and calls the model, writes nothing and reports its spend; `--confirm` writes.

## Follow-ups
Found outside this item and left for the owner; no issues were filed.
- The dry-run rule reaches `roadmap intake` only: `roadmap migrate`, `render` and `reprioritize` `--dry-run` still read GitHub, and an exported `DEVOPS_CLI_DRY_RUN` still stops at the lazy group proxy, which prints the command line instead of intake's request plan (#412).
- The Python entry point `intake_candidate` has plan and confirm only; a caller that wants no request uses `dry_run_intake`.
- `--plan` reports no GraphQL points: the store's queries ask for no `rateLimit { cost }`, a `gh project` command counts once though it may page, and `run_gh`'s retries are not counted. A proposal call counts once though the LLM client retries an answer that does not fit the schema, and an embedding call once though the embedder may batch it or answer from its cache.
- The MCP mirror's subprocess fallback runs `uv run devops`, which may sync the environment.
- Without `--repo`, the dry run resolves the repository with `git remote get-url origin`, and #767 pins `GH_TOKEN` into every `git` child, so `gh auth token` runs first: no network, but a read of gh's stored login, which may sit in the keyring. Exempting local `git` commands from the pin is #767's to decide.
- The dry run gives the exact `gh` command only where it is known without a read: the `.github/roadmap.toml` and `.github/labels.yml` reads, the milestone and issue listings (per page) and the open-issue count. The board, GraphQL and the other searches stay a method and a target; exact argv for every store operation is #1125 Part B's work, since it rewrites the store's reads.
- `AGENTS.md`'s release-start population rule and "Roadmap-Driven Milestone Linking" still say every issue links the active release milestone; the issue leaves both to #739 and #740, but they contradict a backlog item having no milestone.
- `audit_issues_triage` still reads `priority/*` labels, not the board's Priority, and `get_repository_issues(..., limit=100)` caps it at 100 open issues while the repository has about 280.
- A shipped release whose milestone is still open has no row for a joining fix in #740's table; intake reads it as cut.
- `comments_on` returns bodies without authors, so anyone who posts a comment carrying intake's marker suppresses intake's reason comment on that issue; reading the comment author would close that.
- `gh_issue_create` (FastMCP) and `devops gh issues create` still file issues outside intake, without `source/agent`, so the quota never counts them and, filed under the owner's login, they read as trusted for P0. `AGENTS.md` now names `roadmap_intake` for new work; routing or labelling those commands is left to the owner.
- Two intake runs at once (or back to back, as REST search lags new filings) can both open within one allowance slot.
- A regression commit is confirmed to exist in the repository, not to be reachable from the default branch.
- With `--durations=0` the module's per-test calls total about 1 s, but the shared session fixtures' setup (about 5 s on this workspace) lands on its first test.
