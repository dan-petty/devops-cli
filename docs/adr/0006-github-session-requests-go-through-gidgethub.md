# The GitHub session sends its requests through gidgethub

The process's GitHub session (#767) sends its own REST requests through gidgethub 6.0.0, by subclassing its httpx2 adapter, `gidgethub.httpx.GitHubAPI` (#983). gidgethub builds each request, decodes each answer, reads each page's `Link: rel="next"` and keeps conditional-request caches; the project keeps only what is its own. That is pacing and charging on the identity's quota ledger, the retry rules, the origin check and the mapping onto its error classes.

- **Client.** The adapter runs over one `httpx2.AsyncClient` per session, built by the egress-checked factory (`new_async_http_client` at the public level, #898), which has no other way in. An async client is bound to the event loop it first runs on, and every caller is synchronous, so the session owns one anyio blocking portal and each request runs on its loop.
- **Lifecycle.** The transport is closed exactly once: by `close()`, by `reset_github_session()`, by `get_github_session()` when a token change replaces the session, when the transport is garbage-collected, or at interpreter exit. A `weakref.finalize` over its resources does the last two while the portal's daemon thread still runs. Nothing may leave the close to the portal context's own exit at shutdown: that exit calls into a thread that no longer runs, and the process hangs. Closing closes the client on the loop, then stops the portal with `cancel_remaining=True`, so a request waiting out a retry or a pacing pause is cancelled, and it fails as `GitHubUnreadError`. A session used after a close opens a new transport, with its own finalizer.
- **Origin.** The client follows redirects and carries one request hook, which compares `request.url.origin` with the origin of `CONST_URL_GITHUB_API_BASE` before the first request and before every hop. A request to any other origin is refused before it is sent, so the token never leaves GitHub's API, not even for github.com.
- **Pacing and ledger.** Each attempt waits its turn on the `GitHubRateLimiter` of the session's own identity, as `run_gh` waits for `gh api <path>`, and a write waits as a write. Each answer's `x-ratelimit-*` headers, read with `gidgethub.sansio.RateLimit.from_http`, update the quota of the resource `x-ratelimit-resource` names. One limiter per identity (`identity_rate_limiter`) paces gh and the session alike. Every use of it runs in a worker thread, never on the portal's loop, since its lock may be held through another thread's quota refresh. gidgethub's own `rate_limit` attribute is not read.
- **Retries.** gidgethub's `handle_rate_limit_error` hook retries a rate limit (a 403 with no quota left, a 429, or a 403 with `retry-after`) up to `DEFAULT_GH_MAX_RETRIES` times, waiting what `run_gh` would: the Retry-After, else until the quota resets, else jittered backoff from the secondary-limit floor. A 5xx is retried only for a read, from `DEFAULT_GH_SERVER_ERROR_RETRY_FLOOR_SECONDS`, since GitHub may have applied a write it failed to answer. A refused connect and a refused origin are not retried.
- **Errors.** `github/error_classifier.py` maps gidgethub's exceptions by type, status and headers, never by message text, onto `GitHubUnauthenticatedError` (401), `GitHubScopeError` (a 403 whose `x-accepted-oauth-scopes` the token holds none of), `GitHubRateLimitError`, `GitHubNotFoundError` (404) and `GitHubUnreadError` (no readable answer, an answer that does not decode, or a request a close stopped). Anything else is a plain `GitHubOperationError`. Each carries the status, as an int, and the request path. Only a `DevOpsCLIError` leaves `rest()`: one of these, or one raised on the way, such as the egress check's `SSRFBlockedError`, unchanged.
- **Pagination.** `paginate(path, *, iterable_key=None)` reads a REST listing one page per portal call, as its consumer asks for items, and follows the `rel="next"` link gidgethub reads from each page's `Link` header, whether it names a page number or a cursor. Every page passes through the same pacing, retries, origin hook and error classes as `rest()`. It does not use gidgethub's `getiter`, which iterates whatever a page decodes to: a string's characters, or an object's keys when its key is missing. A page must be a JSON array, or an object holding one under `iterable_key`. Anything else raises `GitHubUnreadError` naming the endpoint and the page, so a listing never ends short without saying so (#1034's rule). An empty array, or a page without a next link, ends the listing. A listing still linking a next page after `DEFAULT_GH_MAX_PAGINATED_PAGES` pages, the cap every other paginated reader keeps, raises `GitHubUnreadError` naming the endpoint and the cap.
- **Identity.** The requests carry `CONST_GITHUB_USER_AGENT` and `CONST_GITHUB_API_VERSION`. They never carry the login or an email.

## Considered Options

- **A hand-written subclass of `gidgethub.abc.GitHubAPI`** (the owner's 2026-10-08 decision): superseded. It was chosen because gidgethub's httpx adapter took an `httpx.AsyncClient`. Since 6.0.0 (2026-09-25) the adapter imports `httpx2` first, so it takes the factory's client unchanged, and subclassing it leaves `_request` as a thin wrapper rather than a transport of our own.
- **PyGithub**: rejected as the transport. It talks to GitHub over `requests`, outside the egress-checked factory and the ledger, its pagination and retries are its own, and #891 removes it.
- **githubkit**: rejected. It generates models and methods for the whole API, far more than the session reads, and its own retry and rate-limit handling would compete with the ledger that already paces `gh`.
- **httpx2 alone, with our own `Link` parser, retry loop and ETag store**: rejected. That is the hand-written code this decision removes, and #1034 showed how such a page loop goes wrong.
- **Everything through the `gh` CLI**: rejected for the session's own requests. Each call is a process, and its errors arrive as text that can only be matched by phrase. Board commands, review threads and other GraphQL calls stay on gh until an item moves them.

## Consequences

- `gidgethub` and its one new dependency, `uritemplate`, are pinned in `pyproject.toml` and `uv.lock`. `PyJWT[crypto]` was already locked.
- gidgethub is async only. Every synchronous caller goes through the session's portal, and no caller creates an event loop of its own.
- `GitHubClient.get_pr_diff` and SSH signing-key registration are session requests. Neither builds its own client or reads a `Location` header. A redirect to github.com, which the old diff code followed with the token copied onto it, is now refused.
- Tests fake the session through the repository's existing httpx2 client seam, the one `stub_web` uses. The `github_api` fixture puts `tests/github_session_fakes.py`, a fake GitHub API on `httpx2.MockTransport`, in place of the transport the factory built. The factory, its timeouts, the redirect handling and the origin hook stay real, and every request is still vetted at the egress level the factory was asked for. The plan gave the session constructor a `transport=` argument instead. That was dropped: it needed a path around egress vetting in product code, used only by tests.
- `run_gh` no longer pages. The project's own listings (a pull request's files, reviews, timeline and check runs, and the reconcile listings) read through `paginate()`. `devops gh api --paginate` is the only `--paginate` left, and `run_gh` hands gh that flag with `--slurp`, `--jq` and `--template` as given, since gh follows `Link` itself. gh walks the pages in one process, so the whole walk runs under one timeout (`DEFAULT_GH_API_PAGINATE_TIMEOUT_SECONDS`), and a rate-limited walk is retried from page 1. `run_gh_async` and its `aiolimiter` limiter are gone.
- A failed gh command is classified in the same module, `classify_gh_failure`, from gh's exit status (4 is "requires authentication") and the gh-output table in `config/constants.py`, the one place gh's text is matched. Its errors carry the status gh names as an int, like an HTTP failure's. The ETag cache follows in a later pull request of #983, and `graphql()` waits for the first item that moves a GraphQL call off gh.
