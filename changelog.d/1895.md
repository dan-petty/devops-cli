### Fixed
- The published devcontainer image `ghcr.io/dan-petty/devops-cli/devcontainer` holds its Dev Container Features and the user `vscode` again, so a repository that names only the image with `"remoteUser": "vscode"` opens. Since v0.2.35 the release built the Dockerfile alone, and the Dev Containers CLI stopped with `unable to find user vscode`. A shared action, `.github/actions/devcontainer-image`, now builds `.devcontainer/devcontainer.json` with the Dev Containers CLI 0.89.0 from `tools.lock` for `linux/amd64` and `linux/arm64`. It pushes the image by digest and starts it as `vscode` before the release attests and tags it. The pull request check runs the same action against a registry on the runner and publishes nothing. `devops install-tools` and post-create install the CLI as `devcontainer` ([#1895](https://github.com/dan-petty/devops-cli/issues/1895)).
